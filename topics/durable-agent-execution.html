내구성 있는 에이전트 실행: Temporal + OpenAI Agents SDK

Temporal 개발자 애드보케이트 Cornelia Davis가 AI Engineer 2026-01-12에서 발표한 내용. OpenAI Agents SDK와 Temporal을 결합해 프로덕션 수준의 내구성 있는(durable) AI 에이전트를 구축하는 방법을 두 개의 라이브 데모로 설명한다.

핵심 개념

에이전트의 정의

  • Gen AI 애플리케이션과 에이전트의 구분은 LLM이 애플리케이션 흐름을 스스로 결정하는 자율성(agency)을 부여받았는가에 있다
  • 에이전틱 루프(Agentic Loop): while True 구조로 LLM 호출 → 툴 실행 → 결과를 대화 히스토리에 추가를 반복

Temporal의 두 핵심 추상화

추상화역할특징
Activity외부 호출·재시도 가능한 작업 단위실패 가능성 있는 작업, 멱등성은 개발자 책임
WorkflowActivity들을 오케스트레이션하는 비즈니스 로직이벤트 소싱 기반 상태 저장, 재시작 후 재생 가능
  • 두 추상화를 결합하면 재시도·큐·상태 저장이 자동으로 제공된다
  • Temporal은 Uber에서 만든 Cadence의 포크로 5~6년 된 오픈소스. Snapchat·Airbnb·Pizza Hut·Taco Bell·OpenAI Codex·OpenAI 이미지 생성·Lovable 등이 프로덕션 사용 중

두 가지 구현 패턴

1. 수작업 에이전틱 루프 (데모 1)

  • OpenAI 순수 API + Temporal activity/workflow를 수작업으로 조합
  • tools/__init__.py의 get_handler(tool_name) 함수가 if-elif 체인으로 툴 이름을 실제 핸들러에 매핑
  • Temporal UI에서 이벤트 히스토리(create→get_weather_alerts→create) 타임라인으로 실행 흐름 시각화

2. OpenAI Agents SDK 통합 (데모 2)

  • activity_as_tool() 함수로 activity를 감싸면 JSON 스키마 직렬화가 자동 처리
  • 데모 1 대비 코드량이 크게 감소
  • Agents SDK 커밋 히스토리에서 ‘runner 클래스를 abstract로 만든’ 변경이 통합을 가능케 함

Durability 실증

  • 워커 프로세스를 강제로 죽였다가 재시작해도 워크플로우가 이벤트 히스토리를 재생해 중단 지점부터 그대로 이어진다
  • OpenAI Agents SDK만 단독으로 쓰면 단일 Python 프로세스라 크래시 시 상태가 모두 소실되고 수평 확장도 불가
  • Temporal workflow 안에 Agent를 넣으면 동일한 코드로 durability와 멀티 워커 확장성 확보

마이크로에이전트 오케스트레이션

두 가지 방식:

  1. 코드로 직접 연결: runner.run 체이닝으로 여러 에이전트를 순차 실행
  2. SDK의 handoffs 기능: 동일한 에이전틱 루프 내에서 컨텍스트만 전환 (별도 루프 아님)
  • handoff는 별도 루프가 아니라 동일한 에이전틱 루프의 컨텍스트만 바뀌는 것

아키텍처 구조

Temporal Client
  → Temporal Service (start the agentic flow)
      ↑↓ picking up work
  Temporal Worker
      ├── Activity (외부 호출 단위)
      └── Workflow (오케스트레이션 로직)
          → OpenAI Platform (sending telemetry)
  • Temporal Client는 에이전트 구현과 느슨하게 결합
  • 워커는 자유롭게 오갈 수 있어 수평 확장 가능

주요 제약 및 트레이드오프

항목내용
activity 왕복 지연수십 밀리초(tens of ms) — 장시간 실행 에이전트에는 감내 가능
멱등성Temporal이 강제하지 않음, 개발자 책임
human-in-the-loop대기 중 워크플로우는 메모리→캐시→디스크로 단계적 내려감, 며칠~몇 주 대기 가능
스트리밍 지원아직 네이티브 미지원, 최우선 개발 항목
대용량 페이로드참조 전달 방식 미지원, 개발 중

전략적 시사점

  • 프로덕션 에이전트의 핵심 요구사항: 크래시 복구·상태 저장·수평 확장을 개발자가 직접 구현하지 않으려면 Temporal 같은 분산 실행 백킹 서비스가 필수
  • SDK 추상화 계층: OpenAI Agents SDK → Temporal Runner 교체만으로 동일한 비즈니스 로직에 durability 추가 가능 — 추상화 계층 설계의 중요성
  • Human-in-the-loop 패턴: 승인 대기 시 리소스를 거의 소비하지 않는 Temporal의 수면 패턴은 에이전트 감독(oversight) 워크플로우에 이상적
