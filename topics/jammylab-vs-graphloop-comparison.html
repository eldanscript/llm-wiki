rainny-jammylab vs rainny-graphloop — 멀티 에이전트 개발 환경 비교

한 줄 정의

두 저장소 모두 “코딩 에이전트에게 개발을 맡기고 사람 개입을 줄인다”는 같은 문제를 다루지만, jammylab은 **“어떤 하네스(벤더)로 돌릴지와 격리·안전”**을, graphloop은 **“한 번 맡긴 작업이 실패했을 때 사람 없이 어떻게 재시도·교정할지”**를 다룬다.

핵심 내용

각자 푸는 문제

rainny-jammylabrainny-graphloop
핵심 질문이 작업엔 어떤 하네스·모델을 쓸까? 벤더마다 안전하게 격리할 수 있나?한 노드가 실패하면 사람 없이 어떻게 다시 돌릴까? 언제 재시도를 멈추고 사람을 부를까?
축넓이 — Claude Code·Codex CLI·Antigravity CLI 여러 벤더를 나란히 놓고 비교·격리깊이 — 노드 하나의 재시도·되먹임·중단 규칙을 정밀하게 설계
시작 동기여러 하네스를 함께 쓰는 실험 환경이 필요해서 (2026-08-16 시작)rainny-gcpcoach 16단계를 사람이 매 회차 붙어 돌린 뒤, 사람이 정확히 무엇을 잡았는지 세어보니 자동화할 자리가 보여서

아키텍처

jammylab — 4층 구조

층맡는 일실체
실행·격리·통신하네스를 띄우고 워크트리로 격리, 메시지로 조율ORCA(외부 도구)
편성 판정요청마다 어떤 하네스·모델·패턴을 쓸지 판정ranma-one-half
측정하네스별 결과물 품질·비용agent-eval
지식(RAG)조사 결과 축적·검색미착수

대표 에이전트 jammy가 사용자와 자연어로 소통하고 전체를 관장 — 사용자는 “지시서 확인과 병합만” 결정한다.

graphloop — 그래프 + 루프 2기둥 + 엔진

  • Graph Engineering: 노드마다 입력/출력(계약)을 선언 — 돌리기 전에 validate로 순환·고아 산출물·존재하지 않는 소비를 미리 잡는다.
  • Loop Engineering: 노드 실패 시 실패 내용을 다음 시도 입력으로 되먹인다. 멈추는 조건은 규칙으로 명시: 예산 소진, 같은 실패 반복, 되먹여도 안 듣는 실패(모순·설계 문제)는 재시도하지 않고 즉시 위로 올림.
  • Python 엔진(engine/)이 validate·plan·run·status CLI를 제공. 코드 산출물은 git 커밋으로, 판단(리뷰 결과 등)은 별도 IO 층(engine/artifacts.py)으로 나른다.

안전장치·격리 방식

jammylabgraphloop
격리 단위워크트리(하네스별)노드별 작업 폴더
하네스의 쓰기 권한하네스는 커밋하지 않는다 — verify-and-commit.sh로만 커밋노드가 통과 판정을 스스로 못 낸다 — 엔진이 결정
경계 사고 사례antigravity 격리 실패(2026-08-29): --sandbox 인자가 파일 쓰기는 원본 저장소 기준으로 잡아버림 → antigravity를 읽기 전용으로 강등해당 사례 없음
사후 감지repo-snapshot.sh/repo-diff.sh로 워크트리 밖 저장소 변경 여부 대조노드 계약(입력/출력 선언)이 사전 검사 대상

테스트는 51개→90개로 늘었고 매 회차 통과했지만 결함을 하나도 먼저 잡지 못했다는 게 graphloop 설계의 출발점.

사람에게 남기는 자리

  • jammylab: 사용자는 “지시서 확인과 병합만” 결정.
  • graphloop: 사람에게 셋만 남긴다 — ① 무엇을 만들지 정한다(명세·계획), ② 위로 올라온 것을 판단한다(막힘·되먹임 실패·같은 자리 3회 지적), ③ 밖으로 내보내는 것을 승인한다(배포·공개). “계획을 고치는 것”은 기계에게 넘기지 않는다.

계층 관계 — 서로 배타적이지 않다

jammylab은 “어떤 도구로 돌릴지”, graphloop은 **“그 도구가 만든 결과를 어떻게 재시도·검증할지”**를 다룬다. graphloop의 run <plan> --runner <run-task.sh>가 호출하는 실행기 자리에 jammylab의 하네스 하나를 꽂는 것도 구조적으로 가능해 보인다 — 다만 두 저장소가 실제로 연결된 기록은 아직 없다(확인 안 됨).

jammylabgraphloop
검증 방식실험 기록 축적형 (docs/experiments/)테스트 스위트형 (34개 테스트 통과)
실제 하네스로 돌린 이력2026-08-16~08-29 Claude/Codex/Antigravity/Gemini 각각 실측2026-08-31 첫 진짜 하네스 실행, 2026-09-01 노드가 서로 물린 계획까지 실행
정직하게 밝힌 한계antigravity 격리 실패로 읽기 전용 강등동시 실행은 흉내(순차 실행) — 문서 스스로 “병렬보다 실패 제거가 세 배 값어치”로 명시

확인 안 된 것

  • 두 저장소가 실제로 서로 연동해 쓰인 사례는 확인하지 못했다.
  • ranma-one-half(jammylab의 편성 판정 층)의 구체적 판정 로직은 이번 조사에서 열어보지 않았다.
