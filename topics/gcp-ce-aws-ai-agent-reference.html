AWS AI 에이전트 구축·활용 사례 레퍼런스 (GCP CE 준비용)

GCP Customer Engineer 업무 준비 목적의 경쟁사(AWS) 동향 조사. AWS 기술 블로그의 AI 에이전트 관련 글과 실제 코드를 확인해, GCP 대안(Vertex AI Agent Builder, Agent Engine 등)을 고객에게 설명할 때 쓸 비교 참고 자료.

AWS AI 에이전트 사례 요약

1. KCC — Amazon Bedrock Tool Use 기반 Multi Agent 플랫폼

  • 시스템: 건자재 제조사 KCC가 구축한 전사 통합형 Agentic AI. 손익(Profit)·재무(Card)·HR(People+)·생산(Product) 4개 도메인 에이전트 구성
  • AWS 스택: Amazon Bedrock(Claude 3.5 Sonnet, Amazon Nova Pro) + Lambda + API Gateway(웹소켓) + DynamoDB + PostgreSQL
  • 핵심 패턴: Bedrock Converse API의 toolSpec으로 Lambda를 도구화 → Claude가 tool 배열 반환 → 순차 실행
  • 처리 흐름: 사용자 질문 → API Gateway(웹소켓) → CustomGuardrailForPrompt Lambda(유해성 검사) → IntentAndInfoExtractor Lambda(의도·키워드 추출) → Claude Tool Dispatcher → 선택된 Lambda Tool들(text2sql_function, chart_function, answer_function, related_function) 실행 → 응답 반환
  • 정량 성과: 프롬프트 캐싱으로 토큰 비용 90%+ 절감 (원문 명시 유일한 수치)
  • Text2SQL 패턴: Chain-of-Thought 프롬프트 + 도메인 용어사전 + MS SQL 문법 전문가 역할 부여
  • GCP 대응: toolSpec 정의 패턴 = Gemini function calling + Cloud Functions/Cloud Run. 라우팅·오케스트레이션은 Vertex AI Agent Engine이 관리형으로 대체 가능. Gemini 컨텍스트 캐싱으로 비용 절감 비교 설명 소재

2. LangGraph + Amazon Bedrock 멀티 에이전트

  • 시스템: 여행 계획 도우미 예제 — Supervisor Agent가 Destination·Flight·Hotel 3개 하위 에이전트 조정
  • AWS 스택: Amazon Bedrock(Claude 3/3.5 Sonnet) + LangGraph(오픈소스 오케스트레이션) + boto3 + langchain-aws(ChatBedrockConverse)
  • 핵심 패턴: 상태(State, 공유 데이터 스냅샷)/노드(Nodes, Python 함수)/엣지(Edges, 다음 노드 결정 함수) 3요소 그래프. langgraph.json에 의존성·그래프 경로 선언. 스레드 기반 체크포인트로 대화 이력 유지. human-in-the-loop 지점 내장
  • 특징: Bedrock은 LLM 추론 엔진만 담당, 오케스트레이션은 LangGraph(서드파티)에 전적으로 의존 — AWS 네이티브 멀티 에이전트 오케스트레이션 서비스 아님
  • GCP 대응: 오픈소스 프레임워크 레벨에서는 AWS·GCP 차별화 없음(동일하게 LangGraph + Vertex AI 조합 가능). 관리형 배포·관측·거버넌스 지점(체크포인트 저장소·human-in-the-loop 승인·세션 격리)에서 Vertex AI Agent Engine의 관리형 세션/메모리 기능이 운영 부담 절감

3. Amazon Bedrock AgentCore Runtime

  • 시스템: 로컬 프로토타입 에이전트를 프로덕션으로 옮기는 서버리스 에이전트 실행 런타임 (“프로토타입 트랩” 해소 목적)
  • 핵심 특징:
    • BedrockAgentCoreApp() + @app.entrypoint 데코레이터로 로컬 Python 함수를 HTTP 서비스로 변환
    • CLI 3단계: agentcore configure → agentcore launch → CodeBuild 빌드·ECR 푸시·CloudWatch 자동 구성
    • Firecracker 기반 microVM: 사용자 세션별 전용 CPU/메모리/파일시스템 격리
    • HTTP / MCP(8000/mcp) / A2A(9000/) 3가지 프로토콜 지원
    • AgentCore Identity 통합: OAuth 2.0, SigV4, Okta, Microsoft Entra ID, Amazon Cognito 연동
    • 프레임워크 독립적: Strands/LangGraph/CrewAI/LlamaIndex 어느 것이든, 모델도 Bedrock/Claude/GPT/Gemini 무엇이든 동일 방식 서비스화
  • 공개 스펙: 200ms 콜드스타트, 8시간 장기 실행, 100MB 페이로드, 5분 유휴 후 세션 일시중단(상태 보존), 소비 기반 과금
  • GCP 대응: Vertex AI Agent Engine과 가장 정면으로 겹치는 서비스. 비교 포인트:
    • 세션 격리 단위(Firecracker microVM)를 Agent Engine 격리 모델과 구체적으로 맞비교 준비 필요
    • 200ms 콜드스타트·8시간 장기 실행·100MB 페이로드 수치는 고객이 AWS 자료로 들고 올 가능성이 높으므로 Agent Engine 대응 스펙 미리 정리 필요

4. Amazon Bedrock AgentCore Identity

  • 시스템: 에이전트 전용 인증·권한 관리 계층. 에이전트마다 고유 식별자 부여, “에이전트+호출 사용자” 조합 단위 자격증명 격리·저장
  • 지원 흐름: OAuth 2LO(client credentials grant, 서비스 대 서비스) + 3LO(authorization code grant, 도구 실행 시점 사용자 인가 동적 요청)
  • 연동 서비스: AgentCore Runtime + Gateway + Secrets Manager + Cognito + CloudTrail
  • 핵심 패턴: 자격증명 공급자 등록 → Runtime JWT authorizer 설정 → 3LO 데코레이터(@requires_access_token)로 사용자 인가 요청 → complete_resource_token_auth로 세션 바인딩 (4단계)
  • GCP 대응: GCP 쪽은 서비스 계정 + 워크로드 아이덴티티 연동 + OAuth 동의 화면 3LO 조합으로 설명. AWS는 이를 에이전트 전용 Identity 계층으로 패키징해 데코레이터 한 줄로 노출 — “에이전트×사용자” 조합 단위 전용 관리 서비스 GCP 대응 여부는 후속 확인 필요

5. Amazon Bedrock AgentCore Memory

  • 시스템: 대화 이력·사용자 선호·절차적 지식을 세션을 넘어 장기 기억하는 관리형 메모리 서비스
  • 메모리 유형: 시맨틱(의미 기반 요약) / 에피소딕(사건 순서 기억) / 절차적(행동 패턴·선호 학습)
  • GCP 대응: Vertex AI Agent Engine의 Memory Bank(GCP-CE-Gemini-Enterprise-Agent-Case-Studies Payhawk 사례 50% 시간 단축)와 직접 비교 가능. 메모리 유형별 세분화 비교로 설명
