에이전트 컨텍스트 엔지니어링: 공간·시간 두 축의 제약과 해법

Nx 창업자 Victor Savkin이 AI Engineer 2026(2026-06-26)에서 제시한 프레임워크. AI 코딩 에이전트의 근본적 제약을 ‘공간(저장소 하나만 봄)‘과 ‘시간(세션 간 기억 없음)’ 두 축으로 분석하고, 이를 해결하는 에이전트-비특정 메타 하네스 Polygraph를 소개한다.

핵심 문제: 천재이지만 기억상실인 에이전트

  • 공간 제약: 에이전트는 한 번에 저장소(repository) 하나만 볼 수 있다. 크로스 레포 변경에서 다운스트림 영향을 자체 검증 불가
  • 시간 제약(기억상실): 세션마다 기억이 초기화된다. 이전 대화·의사결정·맥락이 새 에이전트에게는 존재하지 않는다
  • 정량화된 낭비: UI-Module1-Module2-Platform 4개 저장소를 넘나드는 단일 변경 하나에 사람이 동일 맥락을 7번 재설명해야 한다 (초기 설명 1회 + 레포 이동마다 재설명 + 1주 후 프로덕션 버그 대응)
  • 사람이 메모리 역할을 대신: 에이전트가 CI 실패를 놓치거나 다운스트림 영향을 검증하지 못하면, 사람이 연구자·조율자·메모리 역할을 전부 대신해야 한다

해법: Polygraph — 에이전트-비특정 메타 하네스

핵심 데이터 모델: 두 그래프의 결합

그래프구성 요소역할
세션 그래프Session A/B/C (보라색 노드)대화·의사결정·인텐트 이력
저장소 그래프Repo1/2/3/4/5 (청록색 노드)코드 산출물·PR·의존성
연결세션 → 저장소 점선 화살표특정 세션이 어느 저장소에 영향을 미쳤는지 추적
  • 두 그래프가 서로 연결되어 **전체 이력(인텐트 + 코드 산출물)**을 재구성 가능
  • 다른 머신·다른 개발자·다른 에이전트(Claude→Cortex 등)로 완전한 상태(state) 그대로 세션 전송 가능

합성 모노레포(Synthetic Monorepo)

  • 코드를 물리적으로 이동하지 않고 여러 저장소를 하나의 통합 의존성 그래프로 연결
  • GitHub 접근 가능한 저장소(소유 저장소 ~300개 + 오픈소스 의존성 수천 개) 전체를 분석
  • 각 저장소가 무엇을 생산(produce)·소비(consume)하는지 메타데이터화
  • SEPARATE ↔ SYNTHETIC 토글로 물리 모노레포와 동일한 에이전트 경험 제공

크로스 레포 CI 처리

  • 멀티 레포 변경에서 발생하는 여러 PR·CI를 ‘하나의 벡터’로 취급
  • 한 레포의 CI 실패가 소비 레포 패치 책임인지 원인 레포 수정 책임인지 자체 판단·처리
  • 병렬 서브에이전트가 프론트엔드/백엔드를 동시에 조사 (Cogitated for 21s, 16 tool uses, 20.5k tokens)

에피소드 기억 해결

  • 인텐트·관련 저장소·PR·에이전트 트레이스를 모두 캡처해 서로 연결
  • ## What / ## How / ## Tests / ## Related 형식의 구조화된 인수인계 문서 자동 생성
  • 세션을 이어받은 개발자·에이전트가 전체 맥락을 재설명 없이 즉시 파악

자연어 기반 저장소·세션 탐색

  • 수동으로 저장소 선택 불필요 — 자연어 질의로 관련 저장소 자동 탐색
    • 예: ‘이 라이브러리 특정 버전에 의존하는 모든 저장소를 찾아 업데이트해줘’
  • 유사 과거 세션 검색으로 베스트 프랙티스 재사용
  • 진행 중인 에이전트 세션 내에서 ‘이 저장소도 추가해줘’ → 즉석 편입

실증 데모 결과

시나리오결과
백엔드 GET /api/app-info 엔드포인트 추가 + 프론트엔드 소비한 번의 설명으로 2개 레포에 PR 동시 생성
동료 핸드오프세션 참조만으로 즉시 재개, 인수인계 문서 자동 제공
프로덕션 버그 수정1주 전 세션 참조 → 원인 레포·변경 이력 자동 탐색
테스트 통과npm run lint/build/test 18/18 passed 자동 확인

활용 패턴

# CLI로 세션 시작
polygraph start "add GET /api/app-info endpoint"

# 진행 중 세션에서 저장소 추가
"이 저장소도 포함해줘: poly-frontend"

# 세션 핸드오프
polygraph resume <session-id>  # 다른 머신·에이전트에서

전략적 시사점

  • 멀티 레포 조직의 에이전트 도입 핵심 과제: 모노레포가 아닌 조직에서 에이전트 효과를 내려면 ‘합성 모노레포’ 수준의 컨텍스트 통합이 필수
  • 메타 하네스 계층의 부상: 에이전트 자체(Claude, Copilot 등)보다 그 위에 앉는 하네스 계층이 실질적 생산성을 결정 → Agent-Harness-Design 비교
  • 에피소드 기억 = 조직 지식: 세션 그래프는 단순 기술 도구가 아닌 팀의 의사결정 아카이브
  • 재현성 문제와의 교차: 세션 이력 캡처는 Agent-Reproducibility-Debugging에서 다루는 재현성 문제 해결과 직결
