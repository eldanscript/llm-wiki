CHAPTER 4~7: TODO 앱 (칸반 보드)

요건 정의 프로세스

  • PRD → TRD → REQUIREMENTS → DATA_MODEL → API_SPEC → COMPONENT_SPEC → TEST_CASES 순서로 7개 명세 문서 작성
  • CLAUDE.md가 “구현 전 명세 문서 필수 확인” 게이트로 7개 문서를 강제
  • FR-001~008: 티켓 생성/조회/수정/완료/삭제/드래그앤드롭/오버듀 판정

핵심 설계 결정

  • Done 이동: POST /api/tickets/:id/complete (24시간 후 보드에서 제외)
  • 그 외 이동: POST /api/tickets/reorder
  • 아키텍처 경계: src/server(DB·서비스·Route) / src/client(컴포넌트·Hook) / src/shared(공통 타입)
  • app/page.tsx만 src/server/에 직접 접근 가능

TDD 구현 결과

  • 백엔드: 7 API 엔드포인트, 서비스 통합 테스트(실DB + --runInBand)
  • 프런트: 16 컴포넌트 (Phase 1~5: UI → Board → Ticket → Data → Container)
  • 총 26 suites · 169 tests
  • 프런트 컴포넌트 계층: ui(Button·Badge·Modal·ConfirmDialog) → board(TicketCard·Column·Board) → ticket(TicketForm·TicketModal·TicketDetailView) → BoardContainer·FilterBar·BoardHeader

SDD(Spec Kit) 확장 — tika

  • .specify/memory/constitution.md — 프로젝트 헌법 6원칙
  • specs/<feature>/{spec,plan,tasks}.md — 피처별 명세 삼총사
  • Constitution Check 게이트: plan.md 생성 시 헌법 위반 자동 검증
  • 멀티테넌트 SaaS로 확장: NextAuth v5 + RBAC + Gemini + Vercel Blob

CHAPTER 8~12: AI 챗봇 (AWS Bedrock)

시스템 아키텍처

React(Vite) ─── POST /api/chat ──► Express 5 ──► AWS Bedrock
                SSE 스트리밍  ◄───────────────────────────────
  • 프런트는 Express에만 요청 (Bedrock 키 클라이언트 노출 방지)
  • 세션: 인메모리 (user-assistant 쌍 단위 히스토리 트리밍으로 토큰 폭증 방지)
  • Scope 외 명시: 인증/인가·DB·파일 업로드·멀티모달·RAG

AWS Bedrock Converse API

  • Converse API: 모델 공통 인터페이스, Tool Use 네이티브 지원
  • ConverseStream: 토큰 단위 SSE 스트리밍
  • 운영 모델: Claude Sonnet 4.6 / 개발 비용 절감: Haiku 4.5
  • SSE 이벤트 6종: text / tool_start / tool_delta / tool_result / done(토큰사용량) / error

Tool Use 구현 3종

도구파일특징
현재 시간 조회tools/getCurrentTime.ts타임존별 시간 반환
계산기tools/calculator.ts사칙연산·거듭제곱·제곱근
날씨 조회tools/getWeather.tsOpen-Meteo API (키 불필요), Fetcher 주입 구조로 테스트 용이
  • 도구 오케스트레이터: Map 등록, getToolDefinitions() 일괄 노출, 병렬 실행
  • 유틸리티: validation(JsonSchema·MAX_STRING_LENGTH=10000), timeout(executeWithTimeout), fallback(retry/default/skip/error), retry(지수 백오프), permission(executeWithPermissionCheck)

챗봇 프런트엔드

  • shadcn/ui 기반 컴포넌트 시스템
  • hooks/useChat.ts — 스트리밍 상태·메시지 누적 관리
  • hooks/useSession.ts — 세션 상태 통합
  • services/sse.ts — SSE 클라이언트, AbortController 취소 지원
  • MarkdownRenderer — XSS 방지 sanitize 유틸 포함
  • ToolResult 컴포넌트 — tool_start/tool_result 이벤트를 UI로 표시

시스템 프롬프트 설계

  • config/systemPrompt.ts: DEFAULT_SYSTEM_PROMPT(역할·행동지침·제약, 한국어 응답)
  • PERSONAS 맵으로 페르소나 교체 가능
  • 에러: 사용자 응답은 한국어, 로깅은 영어로 분리

공통 적용 원칙

  1. 테스트 코드 = 명세: 테스트 파일이 구현의 SSOT 역할
  2. 명세 우선: 구현 전 반드시 명세(문서 또는 테스트) 확정
  3. 경계 분리: 서버/클라이언트/공유 영역의 명확한 경계
  4. 환경 분리: .env.local(개발) / .env.test(테스트) / 운영
  5. 커스텀 에러클래스: BedrockServiceError 등 도메인 에러 타입화
  6. TypeScript strict + Zod: 컴파일 타임·런타임 이중 타입 안전
