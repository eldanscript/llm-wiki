백로그 트리아지 상태 머신

Matt-Pocock이 설계한 mattpocock/skills의 /triage 스킬. GitHub Issues·Jira 등 백로그를 상태 머신 기반 라벨로 분류하여 AFK 에이전트가 자동으로 집어갈 수 있는 실행 가능한 작업으로 변환하는 방법론.

1. 핵심 개념: 상태 머신 라벨 체계

각 이슈는 카테고리 롤 1개 + 상태 롤 1개를 반드시 동시에 보유해야 한다 (상태 머신 제약).

카테고리 롤 (2종)

라벨의미
bug무언가 고장남
enhancement신규 기능 또는 개선 사항

상태 롤 (5종)

라벨의미
needs-triage관리자 평가 필요 — 라벨 없는 이슈의 기본 진입 상태
needs-info제보자 추가 정보 대기 중 (응답 시 다시 needs-triage로 복귀)
ready-for-agent완전히 명세된 상태, AFK 에이전트가 자동 픽업 가능
ready-for-human사람의 직접 구현이 필요한 작업
wontfix조치하지 않음

상태 전이 흐름

[신규 이슈] → needs-triage
                   ↓
         ┌─────────┴─────────┐
    needs-info         ┌─────┴──────┐
         ↓             ↓            ↓
   (제보자 응답)  ready-for-agent  ready-for-human
         ↓                          |
    needs-triage               (사람 구현)
                               wontfix

2. out-of-scope 디렉터리 연동

  • .out-of-scope/ 디렉터리에 ADR(아키텍처 결정 기록) 형식으로 ‘하지 않기로 결정한 기능’ 문서를 저장
  • 에이전트가 enhancement 이슈 트리아지 시 이 디렉터리를 참조해 범위 밖 요청을 자율적으로 wontfix 처리
  • SKILL.md에 OUT-OF-SCOPE.md 참조 문서 링크 포함

3. ready-for-agent 전환 조건

  • 필수 조건: 에이전트 브리프(agent brief 템플릿) 작성 완료
  • SKILL.md에 AGENT-BRIEF.md 참조 문서 링크 포함
  • 브리프가 완성되어야만 AFK 에이전트(예: Sandcastle의 plan 프롬프트)가 이슈를 자동 픽업
  • PRD에서 파생된 티켓도 동일하게 ready-for-agent로 표시해 에이전트가 집어가도록 연결 가능

4. 진단 스킬(diagnose) 연계 — TDD 피드백 루프

  • triage 후 버그 이슈는 /diagnose 스킬로 이어짐
  • 진단 흐름: 재현 → 회귀 테스트(피드백 루프) 먼저 작성 → 수정
  • 실제 시연 사례 (이슈 #477, Sandcastle 저장소):
    • 원인: InitService.ts의 BACKLOG_MANAGER_REGISTRY에서 VIEW_TASK_COMMAND/CLOSE_TASK_COMMAND 값에 리터럴 {{TASK_ID}}가 포함되어, substitutePromptArgs가 매칭 값 없음 에러를 던짐
    • 수정: {{TASK_ID}}를 <ID>(non-{{}} 플레이스홀더)로 교체 (단, parallel-planner*/implement-prompt.md는 런타임 TASK_ID를 실제로 사용하므로 예외 처리)
    • 변경 파일: src/InitService.ts, src/InitService.test.ts (회귀 테스트 추가), .changeset/fix-task-id-leak.md
    • 검증: 146개 테스트 전체 통과, 타입체크 클린, 소요 시간 3분 49초

5. 운영 원칙

  • AI 생성 표시: triage 중 생성된 모든 코멘트·이슈에 *This was generated by AI during triage.* 디스클레이머 필수
  • 롤 이름 매핑: canonical 롤 이름과 실제 이슈 트래커 라벨 문자열은 다를 수 있으며, /setup-matt-pocock-skills 실행 시 매핑 확정
  • 큐 관리 철학: AI 에이전트 관리의 핵심은 ‘큐 관리’이며, triage는 사람이 만든 티켓과 AI 구현 사이의 번역 계층 역할
  • 팀 협업 필수: 솔로 개발자용 스킬 설정만으로는 부족한 팀 환경에서 특히 효과적
  • 백로그 시스템 무관: GitHub Issues, Jira, Linear 등 모든 백로그 시스템에 연결 가능

6. 7단계 개발 프로세스와의 연결

/triage 스킬은 AI-Driven-Development-7-Phases의 Kanban Board 단계와 직접 연결된다:

  • 타인이 제출한 이슈·아이디어를 triage → ready-for-agent 상태로 전환
  • AFK 에이전트가 Execution 루프에서 자동 픽업
  • 완성된 작업은 QA 단계 거쳐 루프 종료
