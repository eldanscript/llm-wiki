코드 없이 16분 만에 웹 + 모바일 앱 동시 제작 (Riley Brown)

Riley Brown이 vibecode.dev에서 Instagram 클론 웹앱과 이를 동일 백엔드·데이터베이스로 연동하는 뷰 전용 모바일 앱을 16분 만에 제작한 과정 기록 (2026-01-28).

제작한 앱 구성

웹앱: Momento (Instagram 클론)

  • 플랫폼: vibecode.dev (Claude Opus 4.5)
  • 인증: 이메일 OTP 방식 (Better Auth Email OTP 플러그인)
  • 주요 기능: 포스팅·좋아요·댓글·프로필·AI 이미지 생성(GPT Image 1.5)
  • 디자인: 다크모드, 보라색 절대 사용 금지 명시
  • 실제 사진 업로드: 표준 파일 업로드 엔드포인트로 통합 (base64 → File 객체 리팩터링)

모바일 앱: GramView (뷰 전용 컴패니언)

  • 연동 방식: 웹앱의 백엔드 /docs 페이지 텍스트를 새 프로젝트 프롬프트에 그대로 복사 붙여넣기
  • 기능: 뷰 전용(인증 없음), 피드·포스트 상세·유저 프로필 탭
  • 특징: 폰의 다크모드 설정 자동 추종, 네이티브 UI 버튼 자동 활용

에이전트 동작 메커니즘

  • 매 인터벌마다 포스트/좋아요/댓글 확률로 ‘주사위를 굴려’ 행동 결정
  • 포스트 생성 순서: GPT로 이미지 아이디어 생성 → GPT Image 1.5로 이미지 생성 → 캡션 작성
  • Time Scale 슬라이더: 1x~8x 배속 조절 (8x 배속 시 5분 인터벌 에이전트가 약 37초마다 행동)

백엔드 공유 아키텍처

웹앱 (Momento)
    └── 동일 백엔드·DB
모바일 앱 (GramView)

연동 방법: 웹앱의 /docs 엔드포인트에 노출된 API 스펙 전문을 복사해 새 프로젝트 프롬프트에 붙여넣기

인증 API 스펙 (Better Auth)

  • POST /api/auth/email-otp/send-verification-otp — OTP 이메일 발송
  • POST /api/auth/sign-in-email-otp — OTP 검증 후 로그인
  • GET /api/auth/get-session — 로그인 상태 확인
  • POST /api/auth/sign-out — 로그아웃
  • 쿠키 기반 세션 (fetch 시 credentials: "include" 필요)

핵심 교훈

  • 프롬프트 구체성: ‘보라색은 절대 쓰지 말라’처럼 구체적 제약이 결과물 품질에 직접 영향
  • 단순 시작: AI가 인증·백엔드부터 만들면 토큰 소모가 크므로 단순한 프롬프트로 시작 권장
  • 점진적 기능 추가: 뷰 전용으로 시작 → 이후 단계적으로 인증·기능 추가
  • 데이터베이스 이해: 바이브 코더에게 가장 중요한 핵심 역량
  • 미래 전망: 같은 DB에 연결된 여러 소규모 앱들이 늘어나는 방향으로 발전 예상
