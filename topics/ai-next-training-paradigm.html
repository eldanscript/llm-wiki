다음 AI 훈련 패러다임은 무엇인가?

Dwarkesh Patel의 2026-06-26 비디오 에세이. 모든 AI 랩이 걸고 있는 다음 훈련 패러다임 베팅(RLVR → AGI)을 분석하고, 그 한계와 가능한 해법(연속 학습·OPSD·드리밍)을 제시한다.

랩들의 핵심 베팅

수백만 개의 검증 가능한 태스크와 수천 개의 다양한 RL 환경에서 훈련시키면, 오류·모호함 속에서도 몇 주씩 열린 문제를 풀어가는 범용 문제해결 에이전트(AGI)가 만들어진다.

  • 낙관론: 데이터 비효율성·연속 학습 부재 같은 결함은 스케일을 더 키우면 해소될 것 (자연어처리 분야의 LLM 돌파 유추)
  • in-context 학습 낙관론: 컨텍스트 윈도우가 무한히 커지면 6개월치 온보딩 경험을 컨텍스트에 넣을 수 있어 가중치 갱신 불필요

Verifiable ≠ Grindable: 컴퓨터 사용의 역설

  • 컴퓨터 사용은 검증 가능(verifiable): 세금 납부 여부, 이벤트 장소 예약 여부 등 명확히 판단 가능
  • 그런데도 코딩·수학보다 훨씬 느리게 발전: 이유는 ‘grindable’하지 않기 때문
  • Grindable의 조건: 동일 시작점에서 결정론적·재현 가능한 시뮬레이터로 대량 병렬 롤아웃 실행 가능
  • Amazon 예시: 봇 1000개로 체크아웃 플로우를 훈련시킬 수 없음 → Andy Jassy가 차단
  • 함의: RLVR의 일반화 가능성에 근본적 한계가 있음

RLVR의 일반화 한계

  • Dario 발언 인용: 짧은 컨텍스트로 훈련하면 긴 컨텍스트에서 성능 저하 → 훈련 분포 밖으로 무한정 일반화 불가
  • 실세계 스킬의 문제: 사업 구축·정치·소송처럼 리셋 불가능·비정상(non-stationary)한 환경 → 데이터센터 내 재현 불가
  • 현재 컴퓨트 낭비: 랩 컴퓨트 30~50%가 추론(inference)에 쓰이나 모델 개선에 전혀 기여 못함

연속 학습(Continual Learning)의 필요성

  • 정의: 배포 중 얻는 실세계 경험을 가중치로 되돌리는 능력
  • 인간의 연속 학습: 모든 관찰을 그대로 기억하는 게 아니라 핵심 통찰만 가중치로 압축·통합
  • 표본 효율성과의 관계: 연속 학습 문제 = 표본 효율성 문제 (동일한 근본 문제)

유력한 해법 후보들

OPSD (On-Policy Self-Distillation)

  • 외부 검증 보상 불필요
  • per-token 확률 격차로 RLVR보다 조밀한 지도 신호 제공
  • RL처럼 스파스한 업데이트로 기존 지식 보존 → SFT보다 우월

드리밍(Dreaming)

  • AI가 스스로 시뮬레이션을 만들어 리허설
  • pretraining·RL·inference-time compute에 이은 네 번째 스케일링 축 후보 (투기적 아이디어)

Cursor Tab 모델 (현재 유일한 성공 사례)

  • 하루 4억 건 요청, ‘에딧 수용 여부’라는 동일 objective로 online-learn
  • 단, 사용자별로 상이한 것을 학습하는 단계에는 미도달

2027~2028 시나리오

  1. RLVR로 훈련된 에이전트 실전 배치
  2. 몇 주간 경험 축적 + 사람의 승인(thumbs up/down) 수신
  3. OPSD·드리밍을 통해 베이스 모델 가중치에 증류
  4. 모델 발전의 주된 동력이 사전훈련 → 배포 후 누적 경험으로 전환
