LLM 가드레일 PoC 검토: TypeSafe AI Jev vs GCP Model Armor × jammylab 적용 방안

한 줄 정의

2026-09-21 작성 PoC 기술 검토서 — TypeSafe AI Jev(System 1 판단 모델)와 GCP Model Armor(sanitizeUserPrompt API)를 DAN 탈옥 공격 하나에 돌려 판정 성능·속도·비용을 비교하고, rainny-jammylab(멀티 에이전트 개발랩) 적용 방안을 도출.

핵심 내용

검증 배경

  • 가드레일 정의: LLM 입출력을 실행 전 검사해 탈옥·유해 콘텐츠·정책 위반을 걸러내는 장치
  • 테스트 케이스: DAN(Do Anything Now) 탈옥 프롬프트 단일 케이스
  • 실행 환경: GCP 프로젝트 duper-project-1(us-central1) — Qwiklabs류 임시 샌드박스 가능성. 운영 도입 전 실제 프로젝트 재검증 필요

판정 성능 비교

  • 두 서비스 모두 DAN 탈옥 정확 탐지
  • Model Armor: 5개 사전 정의 필터(pi_and_jailbreak 등) 이진 적중 여부 반환
  • Jev: 정책 6개 조항별 위반 확률 분해 출력
    • 0번 조항(지시 무시 금지) 위반 89%
    • 1번 조항(능력 정직) 위반 11%
    • 실질 위해도(severity) 3점 만점 1.71 — 탈옥 시도이나 최종 질문 무해(‘지금 몇 시야?’) 반영
  • 설명 해상도: Jev가 정책 조항 단위·위해도 분리 수치 제공 → 우위

응답 속도

  • Jev 순수 서버 처리: 101ms
  • Model Armor 추정 서버 처리: 200~250ms (한국↔미국 네트워크 왕복 포함 측정값)
  • 서버 처리 속도만 비교 시 Jev 약 2배 빠름

기능 커버리지 요약

| 기능 | Model Armor | Jev | 비고 | |---|:---:|:---:| | 프롬프트 인젝션/탈옥 탐지 | ✅ | ✅ | Jev 확률값으로 임계값 서비스별 조정 | | 기본 유해성 | ✅ | ✅ | 대체 가능 | | 도메인 맞춤 정책 | ❌ | ✅ | Jev 단독 강점 | | 세부 라우팅(review/block/support 분기) | ❌ | ✅ | 확률 기반 단계적 분기 | | PII 마스킹·카드번호 탐지 | ✅ | ⚠️(의미 탐지만) | Model Armor 우위 | | 악성 URL·CSAM 해시 필터 | ✅ | ❌ | Model Armor 우위 |

비용 손익분기점

  • Jev: 100만 토큰당 $0.042 (입력만), 요청마다 정책 오버헤드 ~690토큰 고정
  • Model Armor: 100만 요청당 $0.10
  • 손익분기: 검사 대상 텍스트 500토큰(영문 약 2,000자, 한글 약 1,0001,200자) 초과 시 Jev가 저렴
  • 단문(180토큰): Model Armor 50% 저렴 / 장문(1,500토큰+): Jev 38~51% 저렴

PoC 권장 구성

  1. 1단계: 정규식/Cloud DLP로 PII 마스킹 + URL 형식 검사
  2. 2단계: 마스킹된 텍스트를 Jev에 전달 → ~100ms 단일 호출로 탈옥·유해성·정책 위반·위해도 평가
  3. 분기: jailbreak > 0.50 또는 severity >= 2.0 → BLOCK / jailbreak > 0.25 또는 severity >= 1.0 → REVIEW / 그 외 → ALLOW

출시 일정 및 배경

  • 출시일: 2026-09-15 얼리 액세스 — PoC 작성일(2026-09-21)은 출시 6일 뒤. 검증 선례 부족한 신생 제품
  • 창립자: Diogo Almeida (OpenAI instruction-following 연구·ChatGPT 기반 연구 참여)
  • 투자: DCVC 주도 약 4천만 달러 펀딩, 스텔스 탈출
  • System One 모델 범주: Kahneman ‘System 1’(빠른 직관 판단)에서 착안 — 텍스트 생성 없이 확률·점수만 반환하는 판단 전용 모델
  • 학습 방식: RLCD(Reinforcement Learning for Calibrated Decisions) — 보정된 확률 수치 자체를 목표로 학습
  • 공개 주장 성능: 프론티어 LLM 대비 40200배 빠름, 40400배 저렴, 종단간 70~500ms

공식 스키마 패턴

  • GitHub aquental/jev-guardrail 레퍼런스 구현이 PoC의 assistant_policy + Choice/Noul/Score 패턴과 정확히 일치
  • Noul(0~1): 탈옥 여부 → jailbreak / Choice: 6개 정책 중 위반 항목 → policy_violation / Score(0~3): 위해도 → severity
  • 정책을 state.json 배열로 정의, `assistant_policy[0]` 형식 동적 참조
  • 공식 권장 임계값: jailbreak > 0.50 OR severity >= 2.0 → BLOCK

코딩 에이전트 파이프라인 적용 선례

  • randilt/jev-guardrail — WSO2 API Gateway 계층에서 Jev 호출
  • jimbobbennett/typesafe-guardrails — OpenAI Agents SDK에 System One 가드레일 부착, Arize AX 트레이싱
  • jms-dcksn/jev-pii-guardrail — UiPath 코딩 에이전트에 LangChain awrap_model_call 미들웨어로 Jev PII 탐지 삽입
  • 공통 패턴: Jev를 파이프라인 ‘본체’가 아닌 기존 미들웨어 훅에 얇게 얹는 보조 계층으로 활용

jammylab 적용 권장안

구조 개요

rainny-jammylab: 오케스트레이터 “jammy”가 Claude·Codex 등 여러 코딩 에이전트를 조율하는 멀티 에이전트 개발랩

가드레일 삽입 지점

  • 사용자 입력 → jammy 오케스트레이터: Jev로 탈옥·정책 위반 선별. 단문 위주라면 Model Armor 우선 검토(비용)
  • jammy → 코딩 에이전트 디스패치: 장문 코드 컨텍스트 포함 → 500토큰 초과 지점 → Jev가 비용 효율
  • LLM 출력 검사: 민감 코드·데이터 포함 시 Model Armor PII 필터 선행, 이후 Jev 정책 검사
  • MCP/A2A 인터페이스: API 게이트웨이 계층에서 randilt/jev-guardrail 패턴 적용 가능

적용 우선순위

  1. 즉시: 사용자 입력 → jammy 진입 지점에 Jev 미들웨어 훅 삽입 (출시 6일 신제품이므로 베타 주의 플래그 유지)
  2. 단기: 코딩 에이전트 출력의 장문 검사에 Jev 도입 (손익분기 500토큰 확인 후)
  3. 보완 유지: PII 마스킹·URL 필터는 Model Armor 또는 Cloud DLP 계속 사용
