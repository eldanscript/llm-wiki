GPT-2(124M) 완전 재현 — Andrej Karpathy 2024

Andrej Karpathy가 OpenAI GPT-2(124M)를 PyTorch로 처음부터 재현하는 4시간 1분 라이브 코딩 강의(2024-06-09). HuggingFace 가중치 로드 → 아키텍처 직접 구현 → 단계적 최적화 → 8×A100 분산학습 → FineWeb-Edu 사전학습 → HellaSwag 벤치마크까지 전 과정.

핵심 내용

GPT-2 아키텍처 특징 (원조 Transformer 대비)

  • 디코더 전용: 인코더·cross-attention 없음
  • Pre-norm: LayerNorm이 sub-block 앞으로 이동
  • 추가 LayerNorm: 최종 self-attention block 뒤에 추가
  • Weight Tying: 토큰 임베딩(wte)과 분류기(lm_head) 가중치 공유 → 파라미터 약 30% 절약(40M/124M), 성능도 개선
  • Residual 초기화: 레이어 수 제곱근으로 스케일 다운(1/√(2×n_layer)) → residual stream 분산 폭주 방지

단계적 최적화 (약 11배 가속)

최적화 기법효과
TF32 활성화FP32 19.5→TF32 156 TFLOPS (8배)
BF16 autocast추가 2배
torch.compilekernel fusion으로 메모리 이동 감소
FlashAttentionattention 행렬 HBM 물리화 없음, 실측 ~27% 추가 가속
vocab_size 패딩50,257→50,304 (2의 거듭제곱 배수) → CUDA block tile 정렬
전체~1,000ms/step → ~90ms/step

FlashAttention 원리

  • attention 행렬(T×T)을 HBM에 아예 쓰지 않는 online-softmax 기반 kernel fusion
  • SRAM/HBM 타일링 구조로 메모리 이동 최소화
  • flops는 더 많지만 메모리 병목 해소 → 실측 가속
  • F.scaled_dot_product_attention 한 줄로 적용 가능

분산학습 & 데이터

  • DDP(DistributedDataParallel): 8×A100, torchrun 실행
  • gradient accumulation: grad_accum_steps로 나눠 loss 정규화 필수 (그렇지 않으면 gradient 과대)
  • 배치 크기: GPT-3 스타일 0.5M 토큰
  • 데이터셋: FineWeb-Edu 10B 샘플 (1억 토큰/shard × 100 shard, np.uint16 저장)

벤치마크 결과

  • HellaSwag 평가 방식: 4지선다를 token completion으로 취급, 평균 loss 최소 옵션 선택
  • 10B 토큰 학습: GPT-2(124M) 공식 체크포인트 초과
  • 40B 토큰(4 epoch): GPT-3(124M) HellaSwag에 근접
  • GPT-2(124M) HellaSwag acc_norm ~29.55%(random 25%에 가까움), GPT-2-XL(1.5B) ~49%

학습 비용 변화

  • 2019년 GPT-2(1.6B) 재현: ~$40,000
  • 2024년 기준 8×H100 24시간: ~672(2.99/GPU/hr)
  • $100 수준도 가능

인사이트

  • vocab_size ugly number 역설: 50,257(홀수)→50,304(nice number)로 패딩하면 계산량이 늘어도 CUDA 정렬 덕분에 오히려 빠름 → 하드웨어 친화적 설계의 중요성
  • FlashAttention의 핵심: 정확도 손실 없이 메모리 접근 패턴만 바꿔 대폭 가속 → “알고리즘보다 메모리 계층이 병목” 실증
  • llm.c: 순수 C/CUDA 재구현체로 PyTorch(185K tok/s) 대비 추가 가속(223K tok/s). 교육·연구 목적 경량 참조 구현
  • FineWeb-Edu 같은 고품질 필터링 데이터셋의 중요성: 동일 규모에서 데이터 품질이 성능을 좌우
