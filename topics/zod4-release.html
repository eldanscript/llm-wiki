Zod 4 릴리즈 — 주요 변경 사항

Zod 3.0(2021-05 출시, 24번의 마이너 버전) 이후 최초의 메이저 버전. 런타임 성능·TypeScript 컴파일 성능·번들 크기·API 설계 전반을 새로운 내부 아키텍처로 재작성.

1. 성능 개선

  • 런타임 파싱 속도: 문자열 2.6배, 배열 3배, 객체 7배 향상 (multi validation library benchmark 기준)
  • TypeScript 컴파일 속도: extend() 반복 사용 시 타입 인스턴스화 25,000개 → 약 1,000개, 컴파일 시간 4,000ms → 400ms(10배 개선)
  • tsgo 시너지: 차세대 TypeScript Go 컴파일러와 결합 시 훨씬 큰 스키마·코드베이스로 확장 가능
  • 주간 다운로드: 2025-03-30 기준 24,510,308회 (2021년 출시 당시 600k에서 성장)

2. 번들 크기 최적화

  • 프런트엔드 번들 제약 환경에서 Zod를 현실적 선택지로 만드는 핵심 변화

3. 신규 API

z.toJSONSchema — 1급 JSON Schema 변환

  • AI 구조화 출력(Structured Output) 및 Tool Calling에 직접 활용 가능
  • 기존 서드파티 변환 라이브러리 불필요

z.interface — 정밀한 옵셔널 타입 구분

  • 키 옵셔널(key-optional): {"name?": z.string()} → {name?: string} (속성 자체가 없을 수 있음)
  • 값 옵셔널(value-optional): {name: z.string().optional()} → {name: string | undefined} (속성은 있지만 값이 undefined)
  • 진짜 재귀 타입: getter 문법으로 z.lazy() + 수동 타입 어노테이션 없이 재귀 스키마 정의 가능
  • TypeScript의 exactOptionalPropertyTypes와 대응하는 정확한 구분 표현

메타데이터 Registry

  • 메타데이터를 스키마 자체가 아닌 별도 Registry에 저장: z.registry<{title: string; description: string}>()
  • .describe() 유지, .meta({description: ...}) 사용 권장
  • z.globalRegistry.add(z.string(), {id, title, description, examples}) 형태로 전역 등록

기타 신규 API

  • z.file(): 파일 유효성 검사 (.min(), .max(), .type("image/png"))
  • z.config(z.core.locales.en()): 로케일 설정 API (현재 영어만 지원)
  • z.prettifyError: 사람이 읽기 쉬운 에러 포맷
  • 최상위 문자열 포맷 함수: z.email(), z.uuidv4(), z.uuidv7(), z.ipv4(), z.ipv6() 등 (기존 메서드 방식 deprecated, Zod 5에서 제거 예정)
  • z.templateLiteral: 템플릿 리터럴 타입 스키마 (z.templateLiteral([z.number(), cssUnits]))
  • z.stringBool(): 문자열 형태 boolean 파싱 ("true"/"1"/"yes"/"on" → true, "false"/"0"/"no"/"off" → false)

4. 설계 철학 변화

  • Zod 3는 메서드 체이닝 중심 → Zod 4는 내부 아키텍처 재설계로 성능·번들 크기 동시 해결
  • Zod Mini는 Standard Schema(Valibot 협업) 철학을 공유하며 래퍼 함수 기반 API로 분기
  • 메타데이터 Registry 분리 이유는 설계자도 명확히 설명하지 못한 상태 — 커뮤니티 피드백 수렴 중
  • AI 생태계(구조화 출력, Tool Calling)에서 스키마 검증 라이브러리로서 제2의 성장 동력 확보
