AICodeKing: Codex·Claude Code·GLM 구독 요금제 수학적 비교 (2026-09-09)

AICodeKing이 Codex·Claude Code·GLM 세 코딩 에이전트 구독의 API 환산 가치를 실측 기반으로 계산해 비교한 분석 영상 요약.

핵심 내용

  • 검증(Verification)이 에이전트 루프의 핵심: Boris Cherny(Claude Code 제작자) 인용 — Trigger→Goal→Work→Memory→Verification 5단계 루프에서 ‘아직 안 됐다’고 말할 수 있는 유일한 단계가 Verification이며, 모델 성능보다 이 피드백 게이트가 실제 결과 신뢰성을 좌우한다.
  • 에이전트 자기검증의 함정: 2일간 돌린 에이전트 루프가 매 반복마다 테스트를 통과했지만, 실은 자체 mock 대상 유닛테스트였을 뿐 실제 체크아웃 버튼은 비작동 상태였음 — 에이전트 자신의 기기에서 나온 green 결과는 실사용자 검증 대체 불가.
  • TestSprite CLI: 검증 도구로 오픈소스 TestSprite CLI 사용 — mock이 아닌 배포된 실제 앱을 실사용자처럼 조작하고, 실패 시 문제 화면 스크린샷 반환.
  • **Codex 200요금제API환산가치∗∗:43분실측샘플(주간미터34,900 상당 (가정적 추정, 샘플이 매우 작고 미터 귀속 불확실).
  • **Claude Code 200요금제API환산가치∗∗:주간allowance42,013 상당. 다만 모델(Astra vs Sonnet)과 측정 스케줄(주간 vs 가정된 일일)이 달라 두 수치를 직접 배수 비교할 수 없음.
  • 캐싱 비교: Codex 계열(Astra) 입력 94% 캐시 재사용 vs Claude(Sonnet) 79% 재사용. 가상 98% 재사용 시나리오에서 Codex는 처리 가능 토큰 25% 증가, Claude는 9.3%만 증가 — Claude 샘플의 캐싱 할인 미적용 output 비중이 커서.
  • 요금제 배수 구조: 100(5x사용량/5x가격)은달러당사용량동일,200(20x 사용량/10x 가격)은 달러당 사용량 2배.
  • Claude Code 구독 약점: Pro에서 Fable 5.1은 별도 유료 크레딧 필요, Max에서도 주간 allowance 최대 50%까지만 Fable에 사용 가능 → 소모 빠름.
  • GLM $18 요금제: API 환산 달러 수치 미산정이나 실사용 여유와 브라우저 자동화 기능을 근거로 예산이 빠듯한 사용자에게 추천.
  • 최종 추천: 대부분의 사용자 → Codex, Fable 5.1·터미널(CLI) 경험 중시 → Claude Code Max, 예산 절감 → GLM $18.

측정 한계 및 주의사항

  • 실측 샘플이 매우 작음 (Codex 43분/3%, Claude 4%)
  • 주간 미터 표시가 변하지 않아 재현 검증 불가 사례 존재
  • 저가 요금제 수치는 광고된 배수를 그대로 적용한 가정, 직접 측정 아님
  • Codex 정책·프로모션이 자주 바뀌어 예측 가능성 낮음
  • 두 플랫폼의 모델·스케줄 구조가 달라 단순 배수 비교 부적절
