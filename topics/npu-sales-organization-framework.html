NPU·AI 반도체 영업 조직 프레임워크

AI 반도체(NPU) 및 추론 서버 어플라이언스 영업 조직의 역할 정의, Pre/Sales/Post 프로세스, Vertical·Horizontal 전략을 통합한 운영 표준안. FuriosaAI 류 엔터프라이즈·공공 인프라 세일즈에 특화된 범용 프레임워크.

1. 3대 영업 역할 구분

세 역할은 “무엇에 책임지는가(accountable for)” 로 갈린다.

역할책임 대상핵심 질문성공 지표
Sales (AE/BD)매출·계약”이 딜을 언제, 얼마에 닫는가?”수주액, 파이프라인, win rate
Tech Sales (SE/기술영업)기술 검증·신뢰”이 제품이 고객 요구를 실제로 충족하는가?”PoC 성공률, 기술 win, 데모 전환
SA (Solutions Architect)아키텍처·설계 정합성”고객 환경에 어떻게 끼워 넣어야 동작·확장하는가?”레퍼런스 아키텍처, 도입 후 안정성

역할별 핵심 내용

  • Sales(AE/BD): 리드 발굴 → 자격검증 → 제안·협상 → 클로징 → 계정 확장(land & expand). 딜 규모 수십~수백억, 사이클이 길고 공공은 국책과제 프로세스 별도 트랙
  • Tech Sales(SE): 개발팀과 고객 사이의 기술 커뮤니케이션 허브. 제품 데모, PoC 설계·실행, 벤치마크 수치 제시, SDK·런타임 피드백 환류. “칩 스펙” 이 아닌 “고객 워크로드에서의 실측 성능/TCO” 를 증명
  • SA: 고객 환경(온프렘/하이브리드/에어갭) 기준 배포 아키텍처 설계, 레퍼런스 아키텍처 자산화, 확장성·가용성·보안·기존 시스템 연동 설계. 클라우드 SA 출신이 자연스럽게 전환되는 역할
  • 스타트업 현실: 초기 단계에서는 한 사람이 2~3개 역할 겸직이 일반적. 딜마다 “누가 매출 A, 누가 기술검증 R, 누가 설계 A” 를 명시적 합의로 운영

2. Pre-Sales / Sales / Post-Sales 3단계 프로세스

AI 반도체 어플라이언스 도메인의 특성상 Pre-Sales(특히 PoC)가 전체 딜의 무게중심이다.

단계세부 활동주담당핵심 산출물
Pre-Sales ① Discovery고객 워크로드 파악(모델 사이즈, RPS, GPU 비용 구조), 페인포인트 정의Sales + Tech SalesDiscovery 노트, 자격검증 체크
Pre-Sales ② Solutioning배포 옵션 설계(온프렘/하이브리드/에어갭), 후보 아키텍처SA레퍼런스 아키텍처 초안
Pre-Sales ③ PoC/벤치마크vLLM 드롭인 교체 등 최소 변경 PoC, GPU vs NPU 실측 비교Tech Sales + 개발팀벤치마크 리포트, TCO 계산서
Sales ④ 제안ROI·TCO 기반 의사결정자 프레젠테이션, 가격·구성 제안Sales제안서, 가격표, SOW
Sales ⑤ 협상·계약조달·법무·보안 검토 대응, 계약 조건 협상Sales계약서, 납품 일정
Post-Sales ⑥ 배포설치·통합·튜닝, 기존 시스템 연동, 보안 적합성SA + Tech Sales배포 완료 보고, 운영 런북
Post-Sales ⑦ 운영·확장SLA 지원, 업셀(서버 증설/구독 전환), 레퍼런스화Sales(CSM) + Tech Sales레퍼런스 케이스, 갱신·확장 계약

PoC → 레퍼런스 전환 공식 (도메인 핵심)

1) Discovery (≈2주)  : 워크로드 유형·RPS·현 GPU 비용 구조 파악
2) PoC 설계 (≈1주)   : 기존 코드 변경 최소화(드롭인), 비교 조건 합의
3) PoC 실행 (2~4주)  : 지원팀 동행, 현장 이슈 즉시 대응
4) 클로징            : TCO 계산서 + 의사결정자 ROI 프레젠테이션

핵심 인사이트: 기술 승리 ≠ 딜 승리

  • PoC 단계의 게이트는 tech_win (Tech Sales 책임)
  • 제안 단계의 게이트는 econ_buyer_yes (Sales 책임)
  • Pre-Sales 단계부터 경제적 결정권자(Economic Buyer) 를 끌어들이는 것이 핵심 리스크 관리 포인트

3. Vertical vs Horizontal 영업 전략

정의

전략개념핵심 메시지
Vertical (수직)한 산업을 깊게 파고든다”금융 전용 AI 어플라이언스”
Horizontal (수평)공통 역량을 여러 산업에 넓게 판다”추론 워크로드면 어디든 RNGD”

Vertical 전략 — 산업별 번들

3레이어 구조: HW는 공통(불변), SW 스택·파트너·컴플라이언스가 산업마다 달라지는 조합

  • L3: 버티컬 SW (모델+플랫폼+인증) — 산업마다 가장 많이 바뀜
  • L2: 파트너 생태계 (통신/SI/ISV) — 산업마다 다른 파트너
  • L1: NPU 하드웨어 — 공통, 불변

Vertical 진입 절차: 레퍼런스 1건 확보 → 딜의 [유즈케이스 + 아키텍처 + TCO 계산서]를 산업 표준 패키지로 자산화 → 도메인 파트너 확보 → 2·3번째 고객에 복제 → 컴플라이언스를 파트너와 묶어 진입장벽화

산업별 차별화 포인트

버티컬핵심 유즈케이스NPU 강점 소구점결정적 컴플라이언스
금융사기탐지, 챗봇, 문서요약저지연, 전력효율망분리, 금융보안원
통신상담 AI, 망 이상탐지24/7 가용성, 온프렘—
공공/국방문서분류, 보안 AI데이터 주권, 에어갭CC인증, 국정원 검토
의료영상판독, EMR 요약온프렘 격리, 저전력비식별화, ISMS-P

Horizontal 전략 — 워크로드 횡단

  • 포지셔닝: “GPU = 학습, NPU = 추론” 표준 메시지
  • 무기: vLLM 드롭인 호환, OpenAI API 호환 SDK — 전환비용(switching cost) 최소화
  • 채널: 클라우드 마켓플레이스(AWS/GCP/Azure 어그노스틱), SI 리셀러
  • 효과: 영업 인력 없이도 파이프라인이 흐르는 개발자 셀프서브 구조

전략 선택 가이드

상황권장 전략이유
레퍼런스 0~소수, 신뢰 미확보Vertical 우선깊은 1건이 “검증됨” 내러티브를 만듦
SDK·호환성 성숙, 개발자 풀 큼Horizontal 가속셀프서브로 파이프라인 자가증식
규제 강한 산업(금융/공공/의료)Vertical 필수컴플라이언스가 곧 진입장벽
가격경쟁 회피, 정책·안보 논리Vertical (Sovereign)데이터 주권으로 판매, 장기계약화
글로벌 빠른 확장Horizontal + 채널직접영업 한계를 파트너로 보완

경쟁 구도 함의

  • NVIDIA: Horizontal 지배 — CUDA/TensorRT-LLM/NIM 생태계로 모든 산업 횡단. 해자는 칩이 아닌 소프트웨어 생태계
  • AMD(ROCm): Horizontal 추격, 생태계 격차가 약점
  • 하이퍼스케일러: Trainium/Inferentia·TPU·Maia = 자사 클라우드 내부 Vertical(자가소비)
  • NPU 챌린저 표준 해법: Horizontal로 전환비용을 낮추고, Vertical로 NVIDIA가 약한 규제·주권 영역에 깊이 박는 양면 전략

4. 펀넬 × 조직 RACI

R=실행, A=최종책임, C=자문, I=공유

단계Sales/AETech Sales/SESABD(공공/파트너)파트너(ISV/SI)개발팀
DiscoveryA/RRCCII
SolutioningCCA/RICC
PoC/벤치마크IA/RCICR
제안A/RCCCII
협상·계약A/RIIC(공공조달)II
배포ICA/RIRC
운영·확장A/RRCICI

핵심 원칙: 단계마다 A(최종책임)는 반드시 한 명. PoC는 Tech Sales A, 계약은 Sales A, 배포는 SA A.
