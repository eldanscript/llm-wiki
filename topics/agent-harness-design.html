에이전트 하네스 설계: 모델보다 하네스가 중요하다면?

Etsy 스태프 엔지니어 Aditya Bhargava가 AI Engineer World’s Fair 2026(2026-07-07)에서 발표한 연구. 에이전트 성능이 모델 선택보다 하네스(Harness) 설계에 더 크게 좌우된다는 주장을 Harness Bench 벤치마크 데이터와 7단계 점진적 개선 시연으로 증명하며, 에이전트 구축 전용 언어 ‘Agency’를 소개한다.

발표 개요

  • 발표자: Aditya Bhargava (Etsy 스태프 엔지니어, IC 이니셔티브 리드 for Agent of Commerce, 『Grokking Algorithms』 저자)
  • 행사: AI Engineer World’s Fair 2026 (2026-07-07)
  • 원본 영상: https://www.youtube.com/watch?v=2e9ANoOEn28

핵심 주장

하네스가 모델보다 중요한 이유

  • 통념 반박: “모델이 너무 좋아서 하네스는 단순하게 유지하면 된다” → 이 통념은 독점적 클로즈드 모델에 대한 의존을 심화시킨다
  • 대안 방향: 하네스가 충분히 좋다면, 로컬 오픈소스 모델로도 최첨단 모델과 동등한 성능을 낼 수 있다
  • 약한 모델일수록 하네스의 영향이 크다: 소수 기업의 독점 모델에 의존하지 않아도 되는 가능성

Harness Bench 벤치마크 결과

  • 106개 태스크, 동일 모델·동일 태스크, 하네스만 변경
  • 점수 범위: 52.4% ~ 76.2% — 하네스만 바꿨을 때 20점 이상 차이 발생
  • 결론: 하네스가 모델만큼, 혹은 그 이상 성능을 결정한다

용어 정의

  • 에이전트 = 모델 + 하네스
  • Claude Code 예시: Opus = 모델 / 나머지 전부 = 하네스
  • Agency 언어는 하네스 구축에 특화된 언어 수준(language-level) 솔루션

7단계 점진적 하네스 개선

통제 변인: 동일 모델, 동일 태스크 (median() 버그 수정) median(numbers): 짝수 길이 배열에서 ordered[middle] 반환 → AssertionError: median() returned 3, expected 2.5

단계별 요약

단계이름특징한계
01도구 없음모델만 사용실제 파일 접근 불가
02도구 추가read/write 도구 부여안전하지 않음 (무제한 파일 접근)
03핸들러(Handlers)handle/with 블록으로 사람 승인안전하지만 느림
04부분 함수 적용(PFA)디렉터리 인자 고정으로 자동 안전화안전+빠름
05피드백 루프/Reasoningreact 패턴: 테스트 실행→실패 확인→수정 반복자기 검증 가능
06서브에이전트관련 도구 그룹화, 컨텍스트 오염 방지컨텍스트 분리
07자기 최적화(Self-optimization)Japa 옵티마이저로 프롬프트 체계적 개선목표 기반 최적화

Agency 언어 핵심 기능

1. 부분 함수 적용 (Partial Function Application)

  • read/write 도구의 디렉터리 인자를 고정 → 허가된 경로 외 접근 구조적 차단
  • 사람 승인 없이도 안전하게 자율 동작 가능
  • 능력(capability)과 안전성(safety)을 동시에 확보하는 핵심 메커니즘

2. True Pause/Resume

  • interrupt를 통해 실행 중 任意 지점에서 일시 정지
  • 사람 입력 후 정확히 같은 지점에서 재개 (for loop 내부, tool call 내부, 서브에이전트 내부 포함)
  • handle { ... } with (data) { ... } 블록 구조로 승인 로직 구현

3. 자동 도구 변환

  • Agency의 모든 함수는 자동으로 도구(tool)로 사용 가능
  • docstring이 곧 도구 설명 → 툴 정의 최소화

4. react 패턴 지원

  • reason → act → observe 사이클을 하네스 수준에서 구현
  • 테스트 실행 → 실패 확인 → 코드 수정 → 재확인 반복 → 에이전트 자기 검증

5. 자기 최적화 (Self-optimization with Japa)

  • trial-and-error가 아닌 목표(goal) 기반으로 프롬프트 체계적 측정·개선
  • 에이전트가 자신의 하네스 설정을 스스로 최적화

서브에이전트 설계 원칙

  • 컨텍스트 오염 방지: 관련 없는 도구가 많으면 모델이 올바른 도구를 선택하기 어려워짐
  • 도구 그룹화: 서브에이전트별로 담당 도구를 분리해 선택 정확도 향상
  • 능력 확장: 메인 에이전트의 컨텍스트를 오염시키지 않고 기능 확장

Handlers 코드 예시

→ 안전하지만 매 도구 호출마다 사람 개입 필요 (3단계의 한계)

전략적 시사점

  • 오픈소스 모델 경쟁력 향상: 좋은 하네스가 약한 모델의 성능을 보완 → 독점 모델 의존 탈피 가능성
  • 에이전트 안전성의 구조화: 안전은 모니터링이 아닌 구조적 제약(PFA, 디렉터리 고정)으로 달성
  • 언어 수준 해법의 필요성: 프레임워크로는 부족하고, 언어 수준 지원이 있어야 하네스 설계가 자유로워진다
  • Evals ↔ 자기 최적화: 하네스 자체가 자신의 성능을 측정하고 개선하는 루프 구현 가능
