FuriosaAI

한국의 AI 반도체 스타트업. AI 컴퓨팅의 에너지 효율성을 극대화하는 NPU(신경처리장치)를 개발·양산하며, 누구나 강력한 AI를 경제적으로 사용할 수 있는 생태계 구축을 목표로 한다.

핵심 내용

  • 설립 배경: 알파고 쇼크 이후 AI 컴퓨팅 초기 단계(약 9년 전)부터 AI 전용 반도체 개발에 착수, AI 컴퓨팅 비용 절감을 핵심 사명으로 삼는다
  • 핵심 기술: Tensor-Contraction-Processor (TCP) — 텐서 컨트랙션을 하드웨어 기본 요소로 사용. 메모리 이동 최소화, 에너지 효율성 극대화
  • 주력 제품: RNGD(RENEGADE) — 200W TDP 제약 내에서 512 TFLOPS(FP16 AP) 달성, HBM3 메모리, 400억 트랜지스터 집적
  • 아키텍처 특징: 효율성·범용성·생산준비성 세 축으로 설계. 시간·공간 축 병렬성, 온칩 데이터 재사용, 컴파일러 기반 자동 최적화
  • 양산 현황: 2021년 설계 착수 → 2024년 샘플 출시 → 2025년 1월 양산 시작. 2025년 약 2만 개 RENEGADE 카드 공급
  • 성능 비교: NVIDIA RTX Pro 6000(600W)과 동등 처리량을 180W TDP로 달성 — 와트당 처리량 약 3배 우위
  • 생태계 파트너: TSMC(파운드리), SK하이닉스(HBM3), Supermicro(서버 어플라이언스), LG AI·LG U+, 삼성 SDS, Upstage, 메가존 클라우드

소프트웨어 스택

  • PyTorch 모델 → 자체 컴파일러 → 최적화 바이너리 → 서빙 시스템
  • OpenAI API 호환, Kubernetes(DRA/LMD) 지원, VLM 호환
  • FP8, BF16, MX FP4, MVFP4 등 다양한 데이터 타입을 소프트웨어 업데이트만으로 지원

RENEGADE 2026 Summit 발표 (2026-05-31)

  • 양산 완료 선언: 2025년 1월부터 양산. 현재 고객 공급 중
  • 성능 벤치마크 공개: X41.032B 모델 기준 배치 512, 처리량 12,000 토큰/초 달성
  • 엔터프라이즈 배포 사례: LG AI ExaOne 모델 최적화 완료, LG U+ B2C 서비스(콜 에이전트·IPTV) 적용
  • 클라우드 파트너십: 삼성 SDS — 2025년 7월 구독형 NPU-as-a-Service(Azure) 국내 최초 출시 예정
  • 글로벌 확장: 메가존 클라우드 주도 중동(사우디) 수출 프로젝트, 향후 5년간 약 3,000억 원 규모
  • 로드맵: RENEGADE S(PC/워크스테이션용) 2025년 말~2026년 초, 3세대 칩 2028년 예정

TCP 아키텍처 하이라이트

설계 철학

  • 도메인 특화: GPU의 범용 메모리 명령어 대신, 딥러닝 핵심 연산(텐서 컨트랙션)을 하드웨어 기본 요소로 채용
  • 선언적 → 저수준 변환: 아인슈타인 표기법 → 저수준 ISA로 자동 컴파일. 메모리 레이아웃·스케줄링 명시화
  • 슬라이스 구조: SRAM + Compute Unit 한 쌍. 다양한 텐서 형태에 유연하게 대응

성능 최적화 축

  1. 메모리 효율: 온칩 데이터 재사용, SRAM 대역폭 극대화
  2. 시간 파이프라이닝: 연속 사이클 동안 입력 데이터 재사용. Compute unit 지속 활용
  3. 공간 분산: 여러 SRAM·compute unit에 병렬 실행. 멀티캐스트 네트워크
  4. 컴파일러 자동화: 전술 공간 탐색으로 최적 레이아웃·스케줄링 선택

엔터프라이즈 지원

  • VLM 호환: Vision-Language Model 서포트
  • 동적 형태: 배치 크기, 시퀀스 길이 런타임 변화 대응
  • 클라우드 네이티브: Kubernetes DRA/LMD, OpenAI API 호환

에너지 효율성의 근원

  1. 아키텍처 단순화: 텐서 컨트랙션 기본 요소화로 불필요한 범용 회로 제거
  2. 메모리 이동 최소화: 데이터 지역성(locality) 극대화. DRAM 접근 빈도 감소
  3. 시간·공간 병렬성 통합: 단일 기본 요소로 시간·공간 축 동시 가속화. 회로 활용도 증가
  4. 소프트웨어 최적화: 모델 레벨 메모리 레이아웃 최적화. 연산자 간 불필요한 데이터 이동 제거

GTM(Go-To-Market) 전략 프레임워크

상세 내용: NPU-Sales-Organization-Framework

영업 조직 3대 역할

  • Sales(AE/BD): 매출·계약 책임. 수십~수백억 딜, 긴 사이클, B2G 별도 트랙
  • Tech Sales(SE/기술영업): 기술 검증·신뢰 책임. PoC 설계·실행, GPU vs NPU 실측 TCO 증명
  • SA(Solutions Architect): 아키텍처·설계 정합성 책임. 온프렘/하이브리드/에어갭 배포 설계

도메인 핵심 프로세스 포인트

  • Pre-Sales(특히 PoC)가 전체 딜의 무게중심 — PoC → 레퍼런스 전환이 성장 공식
  • 기술 승리(Tech Win) ≠ 딜 승리 — 경제적 결정권자(Economic Buyer)를 초기부터 확보 필수
  • vLLM 드롭인 호환, OpenAI API 호환 SDK로 전환비용 최소화 → Horizontal 확산 기반

Vertical vs Horizontal 양면 전략

  • Vertical(수직) 우선: 규제 강한 산업(금융/공공/의료)에서 레퍼런스 1건 확보 → 패키지화 → 반복 복제
  • Horizontal(수평) 병행: “GPU=학습, NPU=추론” 포지셔닝으로 산업 무관 추론 워크로드 공략
  • Sovereign AI: 데이터 주권·에어갭 요구 고객(공공/국방/중동 수출)은 단가 경쟁 탈피, 장기계약화
