Claude Code

Anthropic이 개발한 터미널 네이티브 AI 코딩 CLI. 자율적 계획→실행→검증 에이전트 워크플로우, CLAUDE.md 기반 프로젝트 메모리, Hook·MCP·Plugin·Skill 확장 시스템을 갖춘 개발 보조 도구.

핵심 내용

모델 계열 (2026-06 기준)

  • Opus 4.8 (5/25/1M token) — 일상적 에이전트 워크플로우용 플래그십. 1M 컨텍스트 윈도우
  • Sonnet 4.6 (3/15/1M token) — 능력·속도·비용 균형. 구 Opus 수준 코딩 지능
  • Haiku 4.5 (1/5/1M token) — 최고 속도·저비용. 개발 단계 비용 절감용
  • SWE-bench — 실제 소프트웨어 문제 기반 LLM 평가 벤치마크
  • OSWorld — 실제 컴퓨터 환경 멀티모달 에이전트 벤치마크

인터페이스 & 모드

  • Normal(Edit) 모드 — 파일 수정·명령어 실행 시 승인 요청 (기본)
  • Auto-Accept 모드 — 자동 승인, [Shift+Tab]으로 전환
  • Plan 모드 — 읽기 전용 코드베이스 분석 후 계획만 수립. 복잡한 리팩터링·아키텍처 검토에 활용
  • Extended Thinking 모드 — [Option+T]로 토글. Advanced Thinking은 작업 복잡도에 따라 추론 깊이 동적 결정

핵심 슬래시 명령어

  • /init — CLAUDE.md 생성 (프로젝트 구조 분석·기술 스택·컨벤션 자동 생성)
  • /compact — 컨텍스트 압축
  • /context — 세션 토큰 사용량·대화 요소 시각화
  • /memory — CLAUDE.md 메모리 파일 편집
  • /rewind — 코드 변경 되돌리기
  • /resume [session] — 이전 세션 이름·ID로 재개
  • 커스텀 슬래시 명령어 — .claude/commands/*.md 파일로 정의

CLAUDE.md — 프로젝트 메모리 시스템

  • Project Memory Scope — [project]/CLAUDE.md, [project]/.claude/CLAUDE.md: 팀 공유 프로젝트 설정
  • User Memory Scope — ~/.claude/CLAUDE.md: 개인 전역 설정 (코딩 스타일·선호 도구)
  • Project Local — [project]/CLAUDE.local.md: 개인 프로젝트별 설정
  • 효과적인 작성 요소: 프로젝트 개요·기술 스택·핵심 명령어·디렉토리 구조·코딩 규칙·금지 사항
  • 파일 확장 시 @import, .claude/rules/ 디렉토리, Glob 패턴 활용
  • AGENTS.md — 멀티 에이전트 생태계 오픈 표준 (Google·OpenAI·Factory·Cursor 등 공동, 2025-07 공식화). CLAUDE.md에서 참조하거나 심볼릭 링크로 연동

Agent Skill 시스템

  • 클로드 능력을 확장하는 모듈화된 지식·지침 패키지
  • SKILL.md + 선택적 지원 파일(스크립트·템플릿)로 구성
  • 대화 맥락 분석 → 자동 로드 또는 @멘션으로 즉시 로드
  • Front Matter: name(슬래시 호출명), description(자동 로드 판단 기준), allowed-tools
  • 마켓플레이스: skill.sh(Vercel 운영), awesome-claude-skills(Composio), SkillsMP
  • Anthropic 공식 Skills 저장소

Hook — 워크플로우 자동화

  • 특정 이벤트 발생 시 자동으로 실행되는 사용자 정의 쉘 명령어
  • 결정론적 제어 추가: ‘언제’ ‘항상’ 실행 보장
  • 이벤트 타입: PreToolUse, PostToolUse, PermissionRequest, UserPromptSubmit, Notification, Stop
  • RTK(토큰 최적화 도구)는 PreToolUse 훅으로 평균 63% 토큰 절약 구현

MCP & Plugin

  • MCP — 외부 도구 연동 (Obsidian REST API 등)
  • Plugin — 팀 고유 워크로드 패키징·공유

TDD + SDD 개발 방법론 통합

  • TDD(todo-app): docs/*.md 명세 → Red-Green-Refactor 사이클. 26 suites·169 tests
  • SDD(tika): Spec Kit 워크플로 constitution→specify→plan→tasks→implement. 자연어 명세를 SSOT로
  • 결합형: 명세(SDD) 후 테스트 우선(TDD). CLAUDE.md에 “테스트 코드가 명세 역할” 명시
  • Constitution 6원칙: ①SDD ②타입안전+Zod ③보안우선 ④데이터안전 ⑤YAGNI ⑥Constitution Check 게이트
  • FORBIDDEN 규칙: as any 금지, raw SQL 금지, schema.ts 무단수정 금지

실전 스택 (Claude Code 마스터 실습 기준)

  • TODO 앱(TDD): Next.js 15 App Router · React 19 · TypeScript strict · Tailwind 4 · Drizzle ORM · PostgreSQL · Zod · Jest+RTL · Vercel
  • TODO 앱(SDD, tika): 동일 + NextAuth v5 · RBAC · Gemini · Vercel Blob
  • 챗봇 앱: React(Vite) · Express 5 · AWS Bedrock Converse API · SSE 스트리밍 · Tool Use · shadcn/ui · Vitest

AWS Bedrock Tool Use 패턴

  • Converse API + ConverseStream — 모델 공통 인터페이스, 토큰 스트리밍, Tool Use 네이티브 지원
  • SSE 이벤트 6종: text / tool_start / tool_delta / tool_result / done / error
  • 도구 오케스트레이터: Map으로 등록, 병렬 도구 호출, 미등록 도구는 error 결과 반환
  • 유틸리티: validation.ts(JsonSchema), timeout.ts(executeWithTimeout), fallback.ts(retry/default/skip/error), retry.ts(지수 백오프)
  • 운영은 Sonnet 4.6, 개발 비용 절감은 Haiku 4.5로 분리
