DBMS의 탄생과 발전, 그리고 역사

오늘날 대부분의 기업에서 사용되고 있는 DBMS는 컴퓨터가 발명된 이후 오랫동안 기업들의 필수 애플리케이션으로 자리해 왔다. 현재는 오라클이 전 세계적으로 DBMS 분야에서 명성을 날리고 있지만, 그 밑바탕에는 여러 사람들이 일궈낸 결과물들이 자리 잡고 있다. DBMS가 어떻게 발전해왔는지 그 역사를 조명해본다.

현재 데이터베이스 기술

데이터베이스 기초 이론

  • Table 설계

  • 정규화 이론

  • 인덱스

    • Target record를 빠르게 찾아 내기 위해 사용하는 것

  • SQL (Structured Query Language)

RDBMS 제품

MySQL

  • Open source RDBMS 중 가장 많이 보급

  • PHP/Perl/Ruby 등의 LL(Lightweight Language)에서 조작이 빠르고 ( DB 접속이 Process 단위가 아닌 thread 단위로 overhead가 낮음) 웹 개발에 주로 사용

  • 1995년 첫 버전 발표 (MySQLAB) → 2000년 오픈 소스 (GPL) → 2008년 MySQLAB 인수 한 Sun에 귀속 → 2010년 Sun 인수한 Oracle에 귀속 된 후 이중 License 화 (GPL, 상용 License) → MySQL 오픈 소스를 모태로 MariaDB 개발

  • 1995년 ACID를 지원하는 InnoDB 발표 (Innobase Oy) → 2000년 MySQL과 협력 → 2001년 MySQL 4.0에서 MySQL/InnoDB 출시 → 2005년 Oracle에 인수 → 2010년 MySQL 5.5에서 InnoDB를 기본 Storage 엔진으로 채택

PostgreSQL

  • Oracle과 호환성이 높아 Oracle에서 PostgreSQL로 이식 등이 있었음

  • 1974년 버클리 Ingres 프로젝트에서 시작 → 1985년 Post-Ingres 프로젝트 시작 → 1995년 Postgre95 개발 (SQL 해석기 추가) → 1996년 SQL query가 추가 되었음을 의미하는 PostgreSQL로 이름 변경

  • Optimizer 기능이 MySQL 보다 우수 → 복잡한 Query 실행이 많은 경우 PostgreSQL이 사용이 쉬움

NoSQL Database

  • 한대의 서버로 다 처리할 수 없다 → Web 서비스에서의 RDBMS의 성능 문제

    • 데이터 양 증가 → 액세스 범위, 빈도가 증가 → 느린 디스크 I/O 처리 횟수 증가 → 단일 서버 성능으로 허용 가능 범위 초과

  • 성능 문제 해결을 위해 데이터를 복수 서버로 분할 (Scale out) → RDBMS에서는 scale out 구성을 사용할 수 있는 구조를 기본적으로 가지지 않음 → 애플리케이션에서 분할 로직을 만들어 처리

    • Amazon RDS에서는 어떻게 scale out을 처리 하는가? : https://aws.amazon.com/blogs/database/scaling-your-amazon-rds-instance-vertically-and-horizontally/

      • Instance와 Storage가 decouple 되어 있음

      • Scale out의 경우 Read replica를 생성하여 확대 (MySQL, PostgreSQL, MraiaDB, Oracle, SQL Server : 5 replicas, Aurora : 15 replica)

      • RDS의 Storage size : max 64 TiB (MySQL, PostgreSQL, MariaDB, Oracle), max 16 TiB (SQL Server), max 128 TiB (Aurora Cluster)

특수한 데이터 구조를 사용

  • 용도에 따른 특수한 데이터형이 필요

    • 소셜 게임의 실시간 랭킹의 경우 모든 사용자의 점수를 계산하지 않고 순위를 계산하는 방법이 필요 → Redis의 Sorted Set

RDBMS에서 NoSQL과 Hadoop 분산 처리

Column Store DBMS

  • 1969년 TAXIR 시스템에서 시도 → 1993년 KDB에서 상업 버전으로 구현 → 1995년 사이베이스(Sybase) IQ에서 널리 사용 → 분석용 시장 석권

  • 1990년대 중반 이후 메인프레임이 유닉스 서버로 다운사이징 되면서 RDBMS가 데이터 저장 플랫폼을 대표 → 웹 아키텍쳐 발달 및 SNS 유행, 빅 데이터 등장으로 RDBMS에 challenge 발생

NoSQL (Not Only SQL) 등장

  • 1998년 RDBMS의 복잡한 트랙잭션 기능을 뺀 단순화된 DBMS 개발 → NoSQL로 명명

  • 2000년 이후 SNS 서비스 발전 이후 다양한 형태의 저장 플랫폼 확대

    • Document type

    • Wide Column Store type

    • Graph type

    • Key-Value type

  • 2009년 오픈소스 분산 데이터베이스 MeetUp 행사에서 위의 데이터베이스 흐름을 NoSQL로 명명 → ACID 트랜잭션 기능을 제공하지 않는 비 관계형, 분산 데이터 저장 플랫폼을 지칭하는 용어로 사용

분산 처리와 Hadoop

  • 메인프레임 시절의 대량 배치 작업을 100분할 이상으로 나눠 작업 후 결과를 합쳐 작업 수행 → Google이 분할 작업을 위한 프레임워크를 개발하여 사용하고 논문으로 공개

  • 구글 논문을 바탕으로 HDFS 분산 처리용 데이터 저장 플랫폼과 분할 처리 프레임워크 MapReduce를 Hadoop으로 공개 (더그 커팅)

  • 이후 빅데이터 처리를 위한 기본 플랫폼으로 각광 받고 다양한 기능의 오픈소스 모듈이 추가되며 Hadoop eco system을 형성
