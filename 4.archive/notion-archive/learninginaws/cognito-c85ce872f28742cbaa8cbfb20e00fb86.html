  1. GetId

  2. GetOpenIdToken

  3. AssumeRoleWithWebIdentity

GetId

Unauthenticated Access

  • Identity pool에서 guest access를 허용

  • 사용자는 GetId API를 사용하여 새로운 identity ID를 요청할 수 있게 한다

Authenticated Access

  • Public login provider (Facebook, Google, Amazon)를 사용할 경우 user는 provider에서 식별하는 token (OAuth 또는 OpenID Connect)을 제공할 수 있게 됨

  • GetId 호출을 사용하면 Cognito는 새로 인증된 identity 또는 이미 login과 연결되어 있는 identity를 전달

  • Cognito는 provider와 함께 token 유효성을 검증하여 identity 처리

    • token 유효성과 만료 여부 확인

    • Provider에서 생성한 application identifier와 token 일치 여부

    • User identifier와의 token 일치 여부

GetOpenIdToken

  • identify ID 형성 이후 GetOpenIdToken API 호출

Unauthenticated Access

  • 인증되지 않은 Identity가 있는 경우 해당 ID에 대한 토큰을 얻는 데 필요한 것은 ID 자체 입니다.

  • ID가 인증 된 경우 (또는 비활성화), 해당 ID에 대한 인증되지 않은 토큰을 얻을 수 없습니다.

Authenticated Access

  • 인증된 identity가 있다면 이미 login에 연동된 최소 한개 이상의 유효한 token을 전달해야 함

  • GetOpenIdToken 응답은 identity ID를 포함하고 있음

  • Linking Logins

    • 어떤 identity와도 연동되지 않은 login token을 전달할 경우

    • public provider 당 오직 한개의 login만 link 해야 함 → 한개 이상일 경우 ResourceConflictException

  • Merged Identities

    • 주어진 identity와 현재 link 되지 않았지만 다른 identity와 link 된 login token을 전달하면, 이 두개의 identity를 merge 함

    • Merge 된 후 한개는 parent/owner identity가 되고 나머지는 사용하지 않음

    • Return되는 token은 parent/owner identity

AssumeRoleWithWebIdentity

  • OpenID connect token을 가지게 된 후 이것을 AWS 임시 자격 증명과 교환

  • STS의 AssumeRoleWithWebIdentity API 호출을 통해 수행

  • Cognito token을 전달하게 되는 과정이며 public provider에게 token을 받는 것과 동일한 과정

  • 인증된 identity와 인증되지 않은 identity를 위한 2개의 다른 role을 생성

  • 2개의 role은 동일한 access policy를 가짐 → Amazon Cognito Sync service에 access를 허용

Summary

  • Cognito는 SRP 기반 인증 사용

  • SRP : Secure Remote Password

    • 안전한 (secure) augmented password-authenticated key agreement (PAKE) protocol

    • Zero-knowledge proof protocol

    • 하나 이상의 사용자가 암호를 알고 암호키 설정을 위해 암호 인증키를 사용하는 방식

    • iOS, Android, JavaScript 기반 SDK에서 지원

  • Token

    • RefreshToken, AccessToken, IdToken

    • OIDC 표준의 JWT (JSON Web Token)

    • IdToken

      • 사용자 신원(Name, Email, Phone #)에 대한 Request로 구성

    • AccessToken

      • 리소스에 대한 접근 권한을 부여하는데 사용

    • RefreshToken

      • AccessToken, IdToken을 얻는 데 사용

Client Authentication

  • UserName과 Password 기반 인증

  • Client app에서 password 대신 SRP를 사용할 수 있음
