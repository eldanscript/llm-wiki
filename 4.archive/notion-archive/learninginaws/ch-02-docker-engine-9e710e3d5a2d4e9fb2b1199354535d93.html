Docker Volume

Container data를 Persistent data로 처리

Host Volume Share

  • -v option : [host directory]:[container directory]

    • home directory는 존재하지 않으면 새로 생성

Volume Container

  • —volumes-from [container name]

    • -v option으로 host directory를 mount한 container (volume_override)의 mount volume을 volumes_from_container에서 다시 공유

Docker Network

Structure

  • Docker는 container에 내부 IP를 순차적으로 할당

  • Container 재 시작할 때마다 변경 될 수 있음

  • 내부 IP는 Docker가 설치된 host 에서만 쓸 수 있는 IP로 외부와 연결이 필요

    • Container를 시작할 때마다 host에 network interface (veth)를 생성하여 연결

  • 아래와 같이 한개의 container가 생성 되어 있을 때

  • 한개의 veth와 docker0 network interface가 존재함을 확인할 수 있다

    • docker0는 bridge network

Feature

  • Docker Network Driver Type

    • bridge

      • 172.17.0.x IP 대역을 container에 순차적으로 할당

      • Container를 생성할 때 자동으로 연결

    • host

    • none

    • container

    • overlay

  • Third party plug-in

    • Weave

    • Flannel

    • Openvswitch

Bridge Network

  • 신규 bridge type network 생성

  • Container에서 사용하도록 설정

    • —net option
    • bridge 연결 / 분리

Host Network

  • Host network를 그대로 사용
  • Container에서 ifconfig를 실행해 보면 host와 동일하게 나오는 것을 확인할 수 있음

None

  • 외부와 연결이 단절

Container Network

  • 다른 container의 network namesapce 환경을 공유

  • 내부 IP, network interface의 MAC address 공유

Brdige Network & —net-alias

  • 특정 host name으로 여러 개 container에 접근

  • 다른 container에서 alicek106 이라는 host name으로 3개의 container에 접근 가능

  • Test

  • alicek106 alias의 IP는 round-robin 방식으로 결정한다

    • Docker engine의 DNS가 alicek106 hostname을 alicek106으로 설정된 container의 IP로 resolve 함

MacVLAN Network

  • Host NIC를 가상화하여 물리 network 환경을 container에 동일하게 제공

    • 물리 network상에 가상의 MAC 주소를 생성

    • 물리 network에 연결된 다른 장치와 통신 가능

  • Container는 기본 IP 대역 (172.17.x.x)가 아닌 network 장비의 IP 대역을 할당 받는다

fluentd

💡

Log를 수집, 저장하는 기능을 제공하는 open source tool. Data format으로 JSON을 사용하여 쉽게 사용 가능하고 S3, HDFS, MongoDB 등 다양한 저장소에 저장 가능

  • Example

    • Log client → fluentd server → MongoDB server

    • Log client : 172.17.0.5

    • fluentd server : 172.17.0.4

    • MongoDB server : 172.17.0.3

  • MongoDB container 생성

  • fluent.conf file 작성 - mongoDB 설정

    • mongoDB IP는 ‘docker inspect mongoDB’로 조회

  • fluentd conf file을 사용하여 fluentd container 생성

    • alicek106 repository의 fluentd image는 fluentd에 mongoDB plug-in이 설치되어 있음

    • fluentd IP는 ‘docker inspect mongoDB’로 조회

  • lgo client를 생성

    • nginx container를 fluentd 설정과 함께 구동

    • nginx IP는 ‘docker inspect mongoDB’로 조회

  • Log 확인

    • mongoDB container 접속
    • mongoDB data 확인

Resource Constraints

Usage status

  • run ‘docker inspect’

Set constraints

  • docker run with options

Memory constraints

  • —memory

CPU constraints

  • —cpu—shares

    • 상대적인 값 : ratio

    • cpu-share 1024, cpu-share 512를 가진 container가 2개 실행 된다면 CPU 사용률은 66%, 33%가 될 것임

  • —cpuset-cpu

    • 특정 CPU만 사용

  • —cpu-period

    • CFS (Completely Fair Scheduler) 주기를 변경 : default 100ms

    • 100000 → 100ms

  • —cpu-quota

    • cpu period에 설정된 시간 중 얼마나 할당할 것인지 설정

    • 25000 → cpu-period의 1/4을 할당 받음

  • —cpus

    • CPU 개수 지정

    • 1이하 가능 : cpu-period가 조정 됨

Image Creation

  • option

    • -a : Image author

    • -m : commit message

  • Image structure

    • layers
  • Image Layer 확인

  • Commit image 삭제

    • 상위 layer image가 존재한다면 삭제할 수 없다. 상위 image를 삭제한 후 삭제 하여야 함
