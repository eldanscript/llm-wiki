  • Retrieval-Augmented Generation for Large Language Models: A Survey

    2312.10997v5-RAG Survey.pdf

    • Summary - RAG 기술의 발전 과정과 핵심 기술

      1. RAG 개요

      • RAG는 Large Language Model(LLM)의 한계를 극복하기 위해 등장한 기술로, LLM의 내부 지식과 외부 데이터베이스의 정보를 융합하여 활용합니다.

      • RAG 기술은 크게 Naive RAG, Advanced RAG, Modular RAG 등 3단계로 발전해왔습니다.

      1. RAG의 핵심 기술

      • 정보 검색(Retrieval): 데이터 인덱싱, 쿼리 최적화, 임베딩 모델 등이 포함됩니다.

      • 응답 생성(Generation): 검색 결과 리랭킹, 컨텍스트 압축 등을 통해 LLM의 입력 정보를 최적화합니다.

      • 증강(Augmentation): 반복적 검색, 재귀적 검색, 적응형 검색 등의 기법으로 검색 과정을 개선합니다.

      1. RAG 평가 및 적용 사례

      • QA, 대화 생성, 정보 추출 등 다양한 NLP 태스크에 적용되고 있습니다.

      • 맥락 관련성, 응답 충실성, 응답 관련성 등의 지표로 RAG 성능을 평가합니다.

      1. 향후 과제

      • LLM의 긴 문맥 처리 능력 향상, 로버스트니스 개선, 하이브리드 기법 활용 등이 중요한 과제로 제시됩니다.

      • RAG 기술 스택의 발전과 실용화를 위한 노력이 필요합니다.

    • RAG process

      그림에서 보이는 RAG 프로세스는 다음의 3단계로 구성됩니다:

      1. 인덱싱(Indexing):

      • 원문 문서를 전처리하여 토큰 단위로 분할합니다.

      • 분할된 텍스트 청크를 임베딩하여 벡터 데이터베이스에 저장합니다.

      • 이 과정을 통해 원문 데이터를 효율적으로 검색할 수 있는 인프라를 구축합니다.

      1. 검색(Retrieval):

      • 사용자의 질문을 동일한 임베딩 모델을 사용하여 벡터로 변환합니다.

      • 질문 벡터와 문서 청크 벡터들 간의 유사도를 계산하여, 가장 관련성이 높은 상위 k개의 청크를 선별합니다.

      • 이렇게 검색된 관련 문서 청크들이 LLM의 입력 컨텍스트로 활용됩니다.

      1. 생성(Generation):

      • 사용자 질문과 검색된 관련 문서 청크들을 LLM의 입력으로 제공합니다.

      • LLM은 이 입력 정보를 바탕으로 최종 답변을 생성합니다.

      • 생성 과정에서 LLM의 내부 지식과 외부 데이터가 융합됩니다.

    • RAG paradigm

      1. Naive RAG

      • 가장 초기의 RAG 연구 단계로, 전통적인 정보 검색 및 응답 생성 과정을 따릅니다.

      • 문서 인덱싱, 질의 기반 검색, 그리고 LLM을 이용한 응답 생성의 3단계로 구성됩니다.

      • 단순한 구조로 구현이 쉽지만, 정확도 및 신뢰성 측면에서 한계가 있습니다.

      1. Advanced RAG

      • Naive RAG의 한계를 극복하기 위해 제안된 접근법입니다.

      • 검색 전(pre-retrieval) 및 검색 후(post-retrieval) 과정을 강화합니다.

      • 인덱싱 최적화, 질의 변환, 검색 결과 재순위화 등의 기법을 도입합니다.

      • 정보 검색 성능과 정확도가 향상되었지만, 여전히 고정된 프로세스 구조를 가지고 있습니다.

      1. Modular RAG

      • Advanced RAG를 더 발전시킨 모델로, 보다 유연하고 적응성 있는 아키텍처를 가집니다.

      • 검색, 생성, 증강 등의 다양한 기능 모듈을 도입하여 상황에 맞게 구성할 수 있습니다.

      • 질의 라우팅, 메모리 활용, 예측 모듈 등 새로운 기능 모듈을 포함합니다.

      • 모듈 간 상호작용을 최적화하여 유기적인 검색-생성 프로세스를 구현합니다.

      • 유연성과 확장성이 높아 다양한 태스크와 도메인에 적용 가능합니다.

    • RAG generation

      1. Pre-training 단계

      • CoG: 질문-답변 쌍을 활용하여 검색과 생성 과정을 반복적으로 학습, 질문에 효과적으로 답변할 수 있는 모델을 사전 학습

      • TIGER: 개별 항목(item) 단위로 검색-생성 모듈을 사전 학습, 추천 시스템 등 항목 기반 응용에 효과적

      • Atlas, RAVEN, RETRO++, INSTRUCTRETRO: 사전 학습 데이터셋에서 문서 검색 기능을 사전 학습, LLM의 검색 성능 향상

      1. Fine-tuning 단계

      • EAR, UPRISE, RAST, Self-Mem: 특정 데이터셋에 맞춰 검색 모델을 추가 학습, 도메인 적응력 향상

      • FLARE, Self-RAG: 검색 필요 여부를 스스로 판단하는 적응형 검색 기법, 상황에 맞는 유연한 검색 수행

      • RRR, RA-e2e, PROMPTAGATOR, AAR, RA-DIT: 다양한 방식으로 검색-생성 모듈 간 파인튜닝, 모델 간 선호도 정렬

      • RAG-Robust, RA-Long-Form, CoN: 장문 문서 처리 및 노이즈 데이터에 강건한 RAG 모델 학습

      1. Inference 단계

      • DenseX: 문장 단위의 세부적인 검색 기법, 정확성 향상

      • PGRA, FILCO, RADA, Filter-rerank: 검색 결과 재순위화와 압축을 통해 LLM 입력을 최적화

      • R-GQA, LLM-R: 문장 쌍 단위의 검색 기법, 질문-답변 관계 강화

      • BGM, CoQ, Token-Elimination: LLM 내부에서 검색 기능을 수행하거나 토큰 제거 등으로 최적화

      • PaperQA, NoiseRAG, IAG, NoMIRACL: 특정 도메인(논문, 의료 등) 또는 노이즈 데이터에 적합한 RAG 기법

      • ToC, SKR, ITRG, RAG-LongContext, ITER-RETGEN, IRCoT: 반복적/재귀적 검색-생성 과정으로 복잡한 문제 해결

      • RAPTOR: 재귀적 요약을 통해 계층적 문서 표현을 구축, 다층 검색-생성 수행

      • RECITE, ICRALM: LLM 자체 메모리나 생성 출력을 활용한 새로운 검색 기법

    • RAG augmentation

      1. 반복적 검색(Iterative Retrieval):

      • 초기 검색 결과와 생성된 내용을 바탕으로 지속적으로 검색을 반복하는 방식입니다.

      • 이를 통해 점진적으로 문맥 정보를 보완하고 최종 답변의 정확성을 높일 수 있습니다.

      • ITER-RETGEN (Iterative Retrieval-Enhanced Generation) 과 같이 검색-생성 간 상호 강화 기법이 활용됩니다.

      1. 재귀적 검색(Recursive Retrieval):

      • 질문을 세부 하위 질문으로 분해하고, 각 단계에서 검색-생성을 반복하는 방식입니다.

      • IRCoT (Interleaving Retrieval with Chain-of-Thought), ToC (Tree of Clarifications) 등에서 볼 수 있듯이, 점진적 질문 최적화와 계층적 검색을 통해 복잡한 문제를 해결합니다.

      • 이를 통해 상위-하위 수준의 정보를 균형 있게 활용할 수 있습니다.

      1. 적응형 검색(Adaptive Retrieval):

      • 검색 필요성 및 시기를 LLM 자체적으로 판단하고 결정하는 방식입니다.

      • Flare와 Self-RAG에서와 같이, 생성 결과의 confidence나 특수 토큰을 이용해 검색 개시 시점을 유동적으로 조절합니다.

      • 이를 통해 불필요한 검색을 방지하고, 상황에 맞는 최적의 검색-생성 프로세스를 구현할 수 있습니다.

    • RAG echosystem

      1. RAG 기술의 발전 과정:

      • 초기에는 단순한 retrieve-read 프로세스로 시작했지만,

      • 이후 advanced RAG, modular RAG로 진화하면서 검색, 생성, 증강 등 각 단계별 최적화 기법이 발달했습니다.

      • 이를 통해 RAG의 성능과 활용도가 지속적으로 향상되었습니다.

      1. RAG와 다른 최적화 기법의 비교:

      • 프롬프트 엔지니어링, 파인튜닝 등 다른 LLM 최적화 기법과 RAG를 비교하여 특징을 설명하고 있습니다.

      • RAG는 외부 지식 활용과 모델 수정이 적은 편이며, 파인튜닝은 모델 내부 구조 수정에 초점을 맞춥니다.

      1. RAG 생태계의 발전:

      • RAG 연구와 함께 LangChain, LlamaIndex 등의 RAG 관련 툴킷이 등장했습니다.

      • 이러한 툴킷들은 RAG 구축을 위한 API와 프레임워크를 제공하며, RAG 기술의 발전을 뒷받침하고 있습니다.

      • 또한 Weaviate, Amazon Kendra 등 RAG 기반의 상용 서비스도 등장하고 있습니다.

      1. RAG 생태계의 향후 발전 방향:

      • RAG 기술은 계속해서 진화하며, 사용자 맞춤화, 간소화, 특화 등의 방향으로 나아가고 있습니다.

      • 다양한 도메인과 과제에 적용되면서 생태계가 지속적으로 확장되고 있습니다.

  • RAPTOR: RECURSIVE ABSTRACTIVE PROCESSING FOR TREE-ORGANIZED RETRIEVAL

    2401.18059v1-RAPTOR RAG.pdf

    • Summary

      개요:

      • RAPTOR는 ==텍스트를 재귀적으로 임베딩, 클러스터링, 요약하여 트리 구조로 표현==하는 새로운 retrieval-augmented 언어 모델입니다.

      • 이를 통해 RAPTOR는 주제 수준부터 세부 내용 수준까지 다양한 수준에서 정보를 검색할 수 있어, ==복잡한 다단계 질문에 더 효과적으로 답변==할 수 있습니다.

      주요 기술:

      • 텍스트를 짧은 연속 chunks로 분할하고 SBERT로 임베딩합니다.

      • 이 chunks를 GMM 클러스터링과 UMAP 차원 축소를 통해 묶습니다.

      • 클러스터링된 chunks를 GPT-3.5-turbo로 요약하고, 이 과정을 재귀적으로 반복하여 트리 구조를 구축합니다.

      • 검색 시 tree traversal 방식과 collapsed tree 방식 중 collapsed tree 방식이 더 좋은 성능을 보입니다.

      실험 결과:

      • NarrativeQA, QASPER, QuALITY 3개 QA 데이터셋에서 UnifiedQA, SBERT, GPT 모델과 함께 RAPTOR가 BM25, DPR 등 전통적인 방법보다 우수한 성능을 보입니다.

      • RAPTOR + GPT-4가 QASPER와 QuALITY에서 새로운 최고 성능을 달성했습니다.

      핵심 발견사항:

      • RAPTOR의 다층 트리 구조가 중요한데, 상당 부분의 검색 노드가 리프 노드가 아닌 상위 층에서 나오기 때문입니다.

      • 질적 분석 결과 RAPTOR가 DPR 대비 더 포괄적이고 관련성 높은 정보를 검색할 수 있어, 복잡한 다단계 질문에 대한 언어 모델의 성능을 높일 수 있습니다.

      요약하면, RAPTOR의 핵심 혁신은 재귀적 요약을 통해 텍스트의 계층적 표현을 구축하여, 더 효과적인 검색과 지식 집약적 QA 태스크의 성능 향상을 달성한 것입니다.

    • GMN clustering

      동작 원리 및 방식:

      • GMM (Gaussian Mixture Model)은 데이터 포인트가 다수의 가우시안 분포의 혼합으로부터 생성된다고 가정하는 확률 모델입니다.

      • RAPTOR에서는 텍스트 chunks를 d-차원 밀집 벡터 임베딩으로 나타내고, 이 임베딩 벡터들이 GMM 모델의 데이터 포인트가 됩니다.

      • GMM 모델은 각 가우시안 분포의 평균, 공분산, 혼합 가중치를 학습하여 클러스터를 식별합니다.

      • UMAP을 사용하여 고차원 임베딩 벡터를 저차원으로 차원 축소하는데, 이는 고차원 공간에서의 거리 측정 문제를 해결합니다.

      • 계층적 클러스터링을 위해 UMAP의 이웃 수 hyperparameter를 조절하여 먼저 전역 클러스터를 찾고 이후 지역 클러스터를 식별합니다.

      • BIC (Bayesian Information Criterion)를 사용하여 최적의 클러스터 개수를 선정합니다.

      장점:

      • 확률 모델 기반으로 클러스터의 소속 확률을 제공하므로, 하나의 chunk가 여러 클러스터에 속할 수 있는 soft clustering이 가능합니다.

      • UMAP을 통한 차원 축소로 고차원 임베딩 벡터의 특성을 잘 보존할 수 있습니다.

      • 계층적 클러스터링으로 전역-지역 관계를 모두 잘 포착할 수 있습니다.

      단점:

      • 가우시안 분포 가정이 텍스트 데이터의 실제 분포와 완벽히 부합하지 않을 수 있습니다.

      • 클러스터링 결과가 초기화와 하이퍼파라미터 설정에 민감할 수 있습니다.

      결론적으로 GMM 클러스터링은 soft clustering, 고차원 벡터 처리, 계층적 구조 구축 등의 장점으로 RAPTOR의 효과적인 텍스트 표현 학습에 기여했습니다. 다만 텍스트 데이터의 특성을 완벽히 반영하지 못하는 한계가 있어, 이에 대한 추가 연구가 필요할 것으로 보입니다.

      • UMAP 차원 축소

        UMAP(Uniform Manifold Approximation and Projection)의 동작 원리:

        • UMAP은 고차원 데이터를 저차원 공간에 투영하는 비지도 학습 기반 차원 축소 알고리즘입니다.

        • 고차원 데이터가 저차원 측정 공간에 매립되어 있다는 가정 하에, 원 데이터의 국소적/전역적 구조를 최대한 보존하면서 저차원 표현을 학습합니다.

        • 이를 위해 UMAP은 다음과 같은 과정을 거칩니다:

          1. 각 데이터 포인트의 k개 최근접 이웃을 찾습니다.

          2. 포인트 간 지역적 거리를 측정하고, 이를 바탕으로 저차원 표현 간 거리를 최적화합니다.

          3. 전역적 구조 보존을 위해 저차원 표현 간 Kullback-Leibler divergence를 최소화합니다.

        RAPTOR에서의 활용:

        • RAPTOR에서는 SBERT로 임베딩된 텍스트 chunks를 UMAP으로 차원 축소합니다.

        • 이를 통해 고차원 텍스트 임베딩의 국소적/전역적 구조를 효과적으로 보존하면서 GMM 클러스터링을 수행할 수 있습니다.

        • UMAP의 이웃 수 hyperparameter를 조절하여 전역 클러스터와 지역 클러스터를 계층적으로 식별합니다.

        장점:

        • 비지도 학습 기반으로 별도의 레이블링 없이 데이터의 고유한 구조를 잡아낼 수 있습니다.

        • 국소적/전역적 구조 보존으로 차원 축소 후에도 원 데이터의 주요 특성을 잘 유지합니다.

        • 간단한 구현과 빠른 계산 속도로 대용량 데이터에도 효과적으로 적용할 수 있습니다.

        RAPTOR에서 UMAP은 고차원 텍스트 임베딩을 효과적으로 저차원화하여 GMM 클러스터링의 성능을 높이는 데 기여했습니다. 이를 통해 RAPTOR는 텍스트의 의미적 구조를 보다 잘 반영할 수 있게 되었습니다.

    • BIC cluster numbering optimization

      BIC(Bayesian Information Criterion)는 RAPTOR에서 최적의 클러스터 개수를 선택하는 데 사용된 모델 선택 기법입니다.

      BIC의 동작 원리:

      • BIC는 모델의 복잡도와 모델의 적합도를 함께 고려하는 지표입니다.

      • 주어진 데이터에 대해 특정 모델을 적합시켰을 때, BIC 값이 가장 낮은 모델이 가장 적합한 것으로 판단됩니다.

      • BIC 값은 다음과 같이 계산됩니다:
        BIC = ln(N) * k - 2 * ln(L̂)

        • N은 데이터 포인트 수

        • k는 모델 파라미터 수

        • L̂은 최대화된 로그-우도 함수 값

      RAPTOR에서의 활용:

      • RAPTOR에서는 GMM 모델을 적용하여 텍스트 chunks를 클러스터링합니다.

      • GMM 모델의 클러스터 개수 k는 모델 복잡도에 영향을 미치는 중요한 hyperparameter입니다.

      • RAPTOR는 BIC 값을 계산하여 최적의 클러스터 개수 k를 선택합니다.

      장점:

      • BIC는 모델 복잡도와 적합도 간 균형을 달성하는 합리적인 기준을 제공합니다.

      • 별도의 cross-validation 없이도 데이터 자체의 통계적 특성을 활용하여 최적 모델을 선택할 수 있습니다.

      • 계산이 비교적 단순하여 대용량 데이터에도 효율적으로 적용할 수 있습니다.

      RAPTOR에서 BIC는 GMM 클러스터링의 최적 클러스터 개수를 자동으로 선택하는 데 기여했습니다. 이를 통해 RAPTOR는 텍스트 chunks를 의미적으로 효과적으로 분할할 수 있었습니다.

    • 검색 방식 비교 : Tree traversal vs Collapsed tree

      RAPTOR에서 사용된 두 가지 검색 방식, 트리 트래버설(tree traversal)과 콜랩스드 트리(collapsed tree)의 동작 메커니즘과 장단점을 비교

      트리 트래버설(Tree Traversal):

      • 동작 메커니즘:

        1. 루트 노드 레이어에서 가장 관련성 높은 top-k 개 노드를 선택

        2. 선택된 노드의 자식 노드 레이어로 내려가 다시 top-k 노드 선택

        3. 이를 사용자가 지정한 깊이까지 반복

        4. 선택된 모든 노드의 텍스트를 취합하여 결과 반환

      • 장점:

        • 질문의 특성에 따라 검색 깊이를 조절할 수 있어 유연성이 높음

        • 상위 레이어와 하위 레이어의 정보를 적절히 균형 잡을 수 있음 : 쿼리에 필요한 정보가 여러 레이어에 걸쳐 있는 경우에도 종합적으로 좋은 결과를 얻을 가능성

      • 단점:

        • 각 레이어마다 top-k 노드를 고르는 비용이 누적되어 계산 복잡도가 높음

      콜랩스드 트리(Collapsed Tree):

      • 동작 메커니즘:

        1. 트리 전체를 단일 레이어로 펼침

        2. 질문 벡터와 각 노드 벡터 간 유사도 계산

        3. 유사도 상위 k개 노드를 선택하고 토큰 수 제한까지 추가 선택

      • 장점:

        • 모든 노드를 한꺼번에 비교할 수 있어 유연성이 높음

        • 질문에 가장 적합한 수준의 정보를 선택할 수 있음

      • 단점:

        • 모든 노드에 대한 유사도 계산이 필요해 계산 비용이 높음 : FAISS와 같은 고속 k-nearest neighbor 라이브러리를 활용하는 방법

      실험 결과, 콜랩스드 트리 방식이 트리 트래버설 방식보다 전반적으로 더 좋은 성능을 보였습니다. 이는 콜랩스드 트리가 질문 맥락에 맞는 적절한 수준의 정보를 선택할 수 있는 유연성이 더 높기 때문인 것으로 분석됩니다.

    • Collapsed tree

      트리 구조를 flatten하거나 압축한다는 의미로 트리의 계층적 구조를 “collapse”시켜 평면화한다는 개념

      모든 노드 간 유사도를 계산하고 비교할 수 있게 되므로, 질문에 가장 적절한 수준의 정보를 유연하게 선택
