Satisfying and Optimizing metrics

  • If there are multiple things you care about

    • there’s one as the optimizing metric that you want to do as well as possible on

    • one or more as satisficing metrics were you’ll be satisfice

  • Almost it does better than some threshold you can now have an almost automatic way of quickly looking at multiple core size and picking the, quote, best one

Training/Dev/Test Sets

  • Adding data to the training set will change the training set distribution.

  • However, it is not a problem to have different training and dev distribution.

  • On the contrary, it would be very problematic to have different dev and test set distributions

When to Change Dev/Test Sets and Metric

  • Having an evaluation metric and the dev set allows you to much more quickly make decisions about is Algorithm A or Algorithm B better

  • It really speeds up how quickly you and your team can iterate

  • Even if you can’t define the perfect evaluation metric and dev set, just set something up quickly and use that to drive the speed of your team iterating

  • If later down the line you find out that it wasn’t a good one, you have better idea, change it at that time

Human-level performance

  • Humans tend to be very good in natural perception task.

  • So it is possible, but it’s just a bit harder for computers to surpass human-level performance on natural perception task.

    • Speech recognition systems that can surpass human-level performance.

    • There are also some computer vision, some image recognition tasks, where computers have surpassed human-level performance

  • A learning algorithms performance can be better human-level performance but it can never be better than Bayes error

  • Over time, as you keep training the algorithm, maybe bigger and bigger models on more and more data, the performance approaches but never surpasses some theoretical limit, which is called the Bayes optimal error.

  • So Bayes optimal error, think of this as the best possible error.

Bias and Variance

Error Analysis

  • First, get about, say 100 mislabeled dev set examples, then examine them manually

  • 5% of dev set examples are pictures of dogs

    • If only 5% of your errors are dog pictures, then the best you could easily hope to do is that your error might go down from 10% error, down to 9.5% error

    • Ceiling on performance → What’s in the best case? How well could working on the problem help you?

  • 50% of them are dog pictures

    • Focus on reducing the problem of mislabeled dogs

    • Could be much more optimistic about spending time on the dog problem. In this case, if you actually solve the dog problem, your error would go down from this 10%, down to potentially 5% error

  • Estimate how worthwhile it might be to work on each of these different categories of errors

  • Look at the mislabeled examples for False Positives and False Negatives

  • Count up the # of errors and fall into various different categories

Clean Up Incorrectly labeled Data

  • How about incorrectly labeled examples in your dev set or test set?

  • Add one extra column so that you can also count up the number of examples where the label Y was incorrect

  • If it makes a significant difference to your ability to evaluate algorithms on your dev set, then go ahead and spend the time to fix incorrect labels

  • There is more of feeding data in algorithm and just training it and doing less hand engineering and using less human insight.

  • But in building practical systems, often there’s also more manual error analysis and more human insight that goes into the systems than sometimes deep learning researchers like to acknowledge

  • Maybe it’s not the most interesting thing to do, to sit down and look at a 100 or a couple hundred examples to counter the number of errors

Build First System Quickly, then Iterate

Training and Testing on Different Distribution

  • The advantage

    • Training, dev and test sets come from the same distribution

    • Easier to manage

  • The disadvantage

    • If look at dev set, a lot of it will come from the web page images rather than what actually care about, mobile app distribution

    • Spend most of the time optimizing for the web page distribution, which is really not what want

  • Split up data into train, dev & test

    • Training set have all 200K images from the web

    • Add in 5K images from the mobile app

    • Dev set will be 2.5K images from the mobile app

    • Test set will be 2.5K images from the mobile app

    • Get better performance over the long term

Bias and Variance with mismatched data distribution

  • Prioritize what to work on next

  • Training error 1% and Dev error 10%

  • If same distribution

    • Have a large variance problem that algorithm’s just not generalizing well from the training set

  • If different distribution

    • Maybe there isn’t a variance problem

    • Just reflects that dev set contains images that are much more difficult to classify accurately

  • Two things changed at a time

    • Algorithm saw data in the training set but not in the dev set

    • The distribution of data in the dev set is different

  • Randomly shuffle the training set and then carve out just a piece of the training set to be the training-dev set

    • When go to the training-dev, now have a pretty low variance problem

Addressing Data mismatch

  • If have a data mismatch problem,

    • Do error analysis

    • Look at the training set

    • Look at the dev set to try this figure out to try to gain insight into how these two distributions of data might differ

  • See if can find some ways to get more training data that looks a bit more like dev set

    • Artificial data synthesis

    • In speech recognition, artificial data synthesis significantly boost the performance

  • Just be cautious and bear in mind whether or not you might be accidentally simulating data only from a tiny subset of the space of all possible examples

Transfer Learning

  • Take knowledge the neural network has learned from one task and apply that knowledge to a separate task

  • If trying to learn from some Task A and transfer some of the knowledge to some Task B

    • then transfer learning makes sense

    • when Task A and B have the same input X

    • It has to make sense when you have a lot more data for Task A than for Task B.

    • Tend to make more sense if suspect that low level features from Task A could be helpful for learning Task B

  • maybe learning image recognition images to have a radiology diagnosis

  • maybe learning speech recognition teaches about human speech to help with trigger word or wake word detection

  • most useful if you’re trying to do well on some Task B, usually a problem where you have relatively little data.

Multi-task learning

  • Simultaneously, trying to have one neural network do several things at the same time

End-to-end Learning

  • Take all those multiple stages and replace it usually with just a single neural network

    • Speech recognition
