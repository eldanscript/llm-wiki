Proxy

💡

Web Proxy는 서비스 중개자이다.

Web Proxy Server

  • Client 입장에서 transaction을 수행하는 중개인

  • Web Server이자 Web Client

Web Proxy vs Gateway

  • Proxy는 동일 protocol을 사용하는 둘 이상의 application을 연결

  • Gateway는 서로 다른 protocol을 사용하는 둘 이상의 application을 연결

Use Case

  • 성능 향상 / 보안 개선 / 비용 절약

  • Usage Filter

  • 접근 제어

  • 보안 방화벽

  • Web Cache

  • 대리 Proxy (Surrogate)

    • 서버 가속기

    • 공용 컨텐츠에 대한 느린 web server의 성능 개선에 사용

  • Contents Router

    • Request를 traffic 조건과 컨텐츠 종류에 따라 특정 web server로 유도

  • Transcoder

    • 컨텐츠를 포맷 수정

  • Anonymizer

    • HTTP message에 신원을 식별할 수 있는 특성을 제거 : IP address, cookie, Refer header, From header, URI session id

    • 개인 정보 보호와 익명성 보장

    • User-Agent header에서 user computer와 OS 종류 제거

    • From header 제거 : 사용자 email 주소 보호

    • Referer header 제거 : 어떤 사이트를 거쳐 방문했지는 숨김

    • Cookie 제거 : profile과 신원 정보 제거

Proxy Arrangement

Egress Proxy (출구)

  • local network의 출구에 위치

  • 외부의 해킹을 막는 방화벽

  • 요금 절약, 트랙픽 성능 개선

  • Forward proxy

Ingress Proxy (접근, 입구)

  • ISP 접근 지점에 위치

  • Download 속도 개선, 대역폭 비용 감소를 위해 Cache proxy로 사용

Reverse Proxy (대리)

  • Web server 바로 앞에 위치하여 web server에 대한 요청을 처리하고 필요할 때만 web server에 자원을 요청

  • Web server에 보안 기능 추가 혹은 빠른 web server cache로 성능 개선

Network Interchange proxy

  • Internet peering 교환 지점에 위치

  • Traffic 혼잡 완화 및 흐름 감시

HAProxy

  • High Availability를 위해 Load를 분산시키는 소프트웨어

  • L4/L7 Hardware switch를 대체

Traffic Handle

Request to proxy

  • Client 수정

    • Client에 proxy 사용하도록 설정 : Browser에서 수동 혹은 자동 proxy 설정

    • PAC (Proxy auto-configuration)

    • WPAD (Web Proxy Auto Discovery) Protocol : PAC 파일을 자동으로 찾아주는 알고리즘

    • Proxy URI는 완전한 URI 형태 : GET http://ww.marys-antiques.com/index.html

  • Network 수정

    • Network infra에서 web traffic을 hooking : Intercept proxy

      • Via header : 1.1 proxy-62.irenes-isp.net, 1.0 cache.joes-hardware.com

    • Switching 및 routing 장치 필요

  • DNS namespace 수정

    • DNS name table을 수동으로 편집 혹은 동적 DNS server 이용 조정

  • Web server 수정

    • HTTP redirection 명령 response → proxy로 redirection

Gateway

💡

서로 다른 protocol과 application 간의 HTTP interface

  • Web의 복잡한 리소스를 처리하기 위해서는 단일 application으로 어려움

  • Interpreter와 같이 리소스를 받기 위한 경로를 안내하는 역할

  • 동적인 컨텐츠를 생성하거나 DB query 생성

  • Client protocol과 server protocol을 ’/’ 로 구분 : HTTP/NNTP

Prtocol Gateway

Server side web gateway

  • HTTP/*

Server side security gateway

  • HTTP/HTTPS

Client side security acceleration gateway

  • HTTPS/HTTP

Resource Gateway

CGI (Common Gateway Interface)

  • HTTP 요청에 따라 program을 실행하고, 결과를 수집하여 HTTP response로 전달

Web Service와 Application Interface

  • HTTP를 application을 연결하는 도구로 활용

  • SOAP (Simple Object Access Protocol)

    • HTTP message에 XML data를 담는 방식에 대한 표준

Web Tunnel

💡

HTTP connection을 통해 HTTP가 아닌 traffic을 전송하는 데 사용

Connect로 HTTP tunnel connection

  • CONNECT method 사용

  • CONNECT Request

  • CONNECT Response

Data Tunneling

SSL Tunneling

  • 방화벽을 통해 암호화된 SSL traffic을 전달하기 위해 개발

  • SSL과 같은 암호화된 프로토콜은 legacy proxy에서는 처리되지 못 함

  • Tunnel을 사용하여 SSL traffic을 HTTP connection으로 전송

Relay

💡

HTTP 명세를 완전히 준수하지 않는 간단한 HTTP proxy

HTTP/2.0

Background

  • HTTP/1.1 : 메시지 구현의 단순성과 접근성에 중점을 두고 최적화

  • HTTP/2.0 : Web을 빠르게 하기 위해 HTTP 속도 개선을 위한 기능을 추가

Frame

  • Header size : 8byte + Payload : ~ 16Kbyte

Stream & Multiplexing

  • Single connection에 multi stream 가능 : 하나의 connection에 여러 개의 request 동시 전송 가능

Header Compression

  • Header 압축 → 대역폭 절약

Server Push

  • Single connection에 여러 개의 리소스를 전송

  • Server에서 client에 Push할 리소스를 PUSH_PROMISE frame으로 사전 안내
