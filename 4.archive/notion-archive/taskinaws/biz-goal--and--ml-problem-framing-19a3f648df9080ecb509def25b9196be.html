Biz Goal & ML Problem Framing

Machine Learning on AWS

Categories of ML Algorithm

Supervised Learning algorithm

  • Classification : assign data to one or more classes

    • Binary classification

    • Multi-class classification

  • Regression : map to a continuous value

Unsupervised Learning Algorithm

  • Dimension Reduction

    • 차원 축소는 고차원 데이터셋을 더 관리하기 쉬운 크기로 줄이면서 원래 데이터의 가장 중요한 특성을 보존하는 기술입니다.

    • 차원 축소는 특성 수가 늘어날수록 모델 성능이 저하되는 차원의 저주 문제를 완화합니다.

    • 낮은 차원성은 더 빠른 학습 시간, 낮은 비용, 잠재적으로 더 정확한 예측으로 이어질 수 있습니다.

    • 예를 들어, 색상 차원이 기름 소비량 예측에 유의미하지 않다는 것을 학습을 통해 알아낼 수 있습니다. 이 경우 색상 특성은 최종 모델에 포함되지 않습니다.

  • Density Estimation

    • 데이터 분포 추정은 ML의 근본적인 문제입니다. 데이터 집합의 기저 확률 분포를 추정하는 것이 목표입니다.

    • 이 추정은 데이터 분포를 모델링하고 새로운 관측 데이터에 대한 예측을 하는 데 사용됩니다.

    • 밀도 추정은 이상 탐지, 데이터 생성, 모델 성능 향상에 유용할 수 있습니다.

    • 예를 들어, 사용자 선호도를 기반으로 사용자가 제품을 좋아할 확률을 추정할 수 있습니다. 이를 통해 추천 정확도를 높일 수 있습니다.

    • 밀도 추정에 대한 리뷰를 마치고 다음 탭으로 넘어가 군집 분석에 대해 학습하세요.

  • Cluster Analysis

    • 군집 분석은 데이터를 유사한 특징을 기반으로 군집화하여 데이터의 속성을 더 잘 이해하게 해주는 기술입니다.

    • 이 기술은 데이터셋 내에서 이산적인 그룹을 찾아내는 것을 목표로 합니다.

    • 이러한 그룹 내에서 구성원들은 서로 최대한 유사하고, 다른 그룹의 구성원들과는 최대한 다르게 됩니다.

    • 군집 분석은 패턴 인식, 이미지 분석, 고객 분석, 시장 세분화 등 다양한 분야에 응용됩니다.

    • 예를 들어, 필기체 숫자를 인식하는 모델을 만들 때, 10개의 군집(0, 1, …, 9)을 생성하고 입력 이미지를 이 군집에 분류하는 것이 모델 학습의 일부가 될 수 있습니다.

  • Anomaly Detection

    • 이상치 탐지(Anomaly detection)는 데이터셋에서 드문 항목, 이벤트 또는 관찰치를 식별하는 데 사용됩니다.

    • 이러한 이벤트들은 데이터의 나머지 부분과 크게 다르기 때문에 의심스러운 것으로 간주됩니다.

    • 이 기술은 사기, 시스템 고장 또는 기타 비정상적인 이벤트를 탐지하는 데 유용합니다.

    • 예를 들어, 이상치 탐지는 고속 모니터링 카메라의 잠재적인 하드웨어 고장을 감지하기 위해 데이터에서 이상치를 검색하는 데 사용될 수 있습니다.

Difference between Supervised and Unsupervised Learning

https://aws.amazon.com/compare/the-difference-between-machine-learning-supervised-and-unsupervised/

지도 학습 vs 비지도 학습의 차이

  • 지도 학습: 입력 데이터와 정답 데이터가 쌍으로 주어져 모델을 학습시킴

  • 비지도 학습: 레이블된 출력 데이터 없이 입력 데이터만 가지고 패턴을 찾아냄

  1. 지도 학습 기법

    • 로지스틱 회귀, 선형 회귀, 의사결정나무, 신경망 등

  2. 비지도 학습 기법

    • 군집화, 연관 규칙 학습, 확률 밀도 추정, 차원 축소 등

  3. 각각의 학습 방식을 사용하는 경우

    • 지도 학습: 알려진 결과가 있고 레이블된 데이터가 있는 경우

    • 비지도 학습: 데이터가 레이블되어 있지 않고 패턴 발견이 목적인 경우

  4. 지도 학습과 비지도 학습의 혼합 사용

    • 반지도 학습: 레이블된 데이터와 레이블되지 않은 데이터를 함께 사용 (semi-supervised learning)

  5. AWS에서의 지도/비지도 학습 지원

    • Amazon SageMaker를 통해 다양한 지도/비지도 학습 기법 활용 가능

Reinforcement Learning Algorithm

  • interacts with its environment and learns to take actions that will maximize rewards. Incorrect actions are penalized.

Next Generation ML

Deep Learning

  • Computer vision

  • Speech recognition

  • Natural language processing

  • Recommendation engines

Generative AI

  • powered by very large machine learning models that are pre-trained on vast collections of unlabeled data. (foundation model)

  • Conversations / Stories / Images / Videos / Music

  • Large Language Models

    • a popular type of foundation model

    • Copywriting: LLMs can write original copy or improve the style and voice of existing sentences.

    • Knowledge base answering: LLMs can answer specific questions related to knowledge bases.

    • Text classification: LLMs can classify text with similar meanings or sentiments, such as measuring customer sentiment.

    • Code generation: LLMs are proficient in code generation from natural language prompts. For example, Amazon Q Developer can generate code in multiple languages, such as Python, TypeScript, and Java.

    • Text generation: LLMs can generate new text. Examples include finishing incomplete sentences, creating product documentation, and writing stories.

What is LLM?

https://aws.amazon.com/what-is/large-language-model/

  1. LLM(Large Language Model)이란?

    • 매우 큰 규모의 딥러닝 모델로, 방대한 양의 데이터로 사전 학습된 모델

    • 트랜스포머 기반의 인코더-디코더 구조로, 병렬 처리가 가능

    • 수백억 개의 매개변수를 가지는 대규모 모델

  2. LLM의 중요성

    • 범용적인 유연성: 질문 답변, 문서 요약, 언어 번역 등 다양한 태스크 수행 가능

    • 예측 성능 우수: 적은 수의 프롬프트로도 높은 품질의 출력 가능

    • 인공 지능 기술 발전에 기여: 내용 생성, 검색 엔진, 가상 비서 등에 활용

  3. LLM의 작동 원리

    • 단어 임베딩을 통해 단어 간 관계 표현

    • 인코더-디코더 구조로 입력 텍스트 이해 및 출력 생성

  4. LLM의 활용 사례

    • 콘텐츠 생성: 광고 카피, 기사 작성 등

    • 지식베이스 문답: 문서 내 정보로 질문 답변

    • 텍스트 분류: 감성 분석, 문서 관계성 파악 등

    • 코드 생성: 프로그래밍 언어 코드 자동 생성

  5. LLM의 학습 방식

    • 대규모 데이터로 사전 학습 후 미세 조정(fine-tuning)

    • 제로샷 러닝, 소수 샷 러닝, 파인튜닝 등의 기법 활용

  6. LLM의 발전 방향

    • 성능 향상, 오디오/비주얼 입력 학습, 업무 자동화 등

  7. AWS의 LLM 지원

    • Amazon Bedrock, SageMaker JumpStart 등을 통한 LLM 활용 지원

Using AI/ML Responsibly

Fairness

  • Consider the impacts on different groups of people involved.

Explainability

  • Evaluate and understand how the system arrived at its outputs.

Privacy and Security

  • Properly obtain, use, and protect data and models.

Safety

  • Prevent harmful system outputs and mitigate the potential for misuse.

Controllability

  • Implement mechanisms to monitor and steer the behavior of AI systems, making human oversight and intervention possible when necessary.

Robustness (견고성) and Veracity (진실성)

  • Develop techniques to ensure that the system produces correct outputs, even when faced with unexpected or adversarial inputs. This makes the system reliable and trustworthy.

  • 견고성 : 예상치 못한 또는 악의적인 입력에도 오류 없이 정확한 출력을 내는 기술 개발

  • 진실성 : 시스템이 사실에 기반한 정확한 출력을 내도록 보장

Governance

  • Establish processes to define, implement, and enforce responsible AI practices in your organization.

Transparency

  • Communicate clear and understandable information about an AI system to stakeholders. This helps them make informed decisions about using the system.

Formulating Business Problems

  1. 문제 정의

    • 해결하고자 하는 구체적인 문제를 명확하게 정의

    • 프로젝트의 목표와 성공 기준을 명확히 설정

  2. 데이터 조사

    • 사용 가능한 데이터 원천 파악

    • 데이터의 특성, 품질, 구조 등 면밀히 조사

    • 데이터의 양, 범위, 형태가 문제 해결에 적절한지 확인

  3. 문제 유형 선정

    • 지도 학습, 비지도 학습, 강화 학습 등 적절한 문제 유형 선택

    • 회귀, 분류, 군집화, 이상치 탐지 등 구체적인 기계 학습 태스크 정의

  4. 성능 평가 지표 선정

    • 정확도, 정밀도, 재현율, F1-score 등 적절한 평가 지표 선택

    • 문제 유형과 도메인 특성에 맞는 평가 지표 사용

  5. 프로젝트 범위 설정

    • 프로젝트의 시간적, 기술적, 예산적 제약 사항 고려

    • 현실적으로 달성 가능한 목표와 범위 설정

  6. 데이터 준비 및 전처리 계획

    • 데이터 전처리, 피처 엔지니어링 등 필요 작업 식별

    • 이를 위한 시간 및 자원 배분 계획

Choose your data

  • Labeled Data

    • 머신러닝 모델은 특징(features)과 레이블(labels)로 구성된 데이터에 의존

    • 특징은 패턴을 감지하고 예측을 하는 데 사용되는 속성이나 변수

    • 레이블은 각 데이터 포인트에 대한 정답을 제공

    • 적절하게 레이블링된 데이터를 통해 모델은 특징과 레이블 간의 관계를 학습

    • 이를 바탕으로 새로운 레이블되지 않은 데이터에 대한 정확한 예측 가능

    • 모델은 특징의 패턴을 이용하여 훈련에 기반한 올바른 레이블을 할당

    • 예를 들어, 신용카드 사기 탐지 모델에서 거래일, 판매처, 거래 금액 등이 특징이 될 수 있음

    • 각 거래에 대한 레이블은 사기 거래 여부(합법/사기)로 표시됨

  • Data Quality and Relevance

    • 모델링에 사용되는 데이터는 연구 중인 현상에 대한 관련 신호를 포함해야 함

    • 예를 들어, 도매업체가 제품 수요를 예측할 때는 이전 판매 실적과 품절 시기를 추적해야 함

    • 수요를 예측하려면 품절 시 고객 수요가 있었음에도 판매가 이루어지지 않았다는 점을 알아야 함

    • 따라서 수요 모델링 시 품절 이벤트를 입력 특징에 포함해야, 오해를 불러일으킬 수 있는 모델 학습을 피할 수 있음

    • 다음 표에서와 같이 품절 이벤트가 입력 특징으로 포함되어 있음

  • Additional Data

    • 적절하게 레이블링된 데이터를 확보하는 것은 ML 모델 학습의 큰 과제 중 하나

    • 예를 들어, 자율 주행 자동차의 경우 도로, 표지판, 다른 차량 등 모든 객체와의 정확한 상대 위치가 레이블링된 이미지 데이터가 필요

    • 이처럼 복잡한 데이터의 수동 레이블링은 극히 어렵고 시간이 많이 소요

    • 충분한 레이블 데이터가 없다면 모델 정확도가 저하되어, 자율 주행과 같은 안전 중요 애플리케이션에 심각한 결과를 초래할 수 있음

Identify your ML success criteria

  • clearly define which metrics will determine whether the model is performing well

  • Predicting sales values

  • Determining whether to carry stock

  • Predicting sales months

이 문제에서 가장 적절한 성공 기준은 3번 “모델이 추천한 제품의 수익이나 매출 증가”입니다. 그 이유는 다음과 같습니다:

  1. 정확한 판매량 예측은 중요하지만, 제품 선정의 실질적인 목적은 수익 증대이므로 매출/수익 지표가 더 적절합니다.

  2. 분류 정확도도 중요하지만, 이는 수익 증대로 이어지는지가 관건입니다. 단순한 분류 성능만으로는 충분하지 않습니다.

  3. 모델이 추천한 제품의 실제 수익 또는 매출 증가는 모델의 실질적인 성과를 보여줄 수 있는 가장 적합한 지표입니다. 이는 모델의 최종 목적에 부합합니다.

  4. 훈련 데이터에 대한 낮은 오류율은 과적합을 방지하기 위한 지표일 뿐, 실제 운영 시 성과와는 직접적인 연관이 없습니다.

따라서 제품 선정 모델의 성공 기준으로는 모델이 추천한 제품의 매출 또는 수익 증대가 가장 적절한 지표라고 볼 수 있습니다.
