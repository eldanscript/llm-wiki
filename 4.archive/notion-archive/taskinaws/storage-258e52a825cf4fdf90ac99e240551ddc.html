Storage Type

https://qumulo.com/blog/block-storage-vs-object-storage-vs-file-storage/

Block storage

  • 데이터를 고정된 크기의 ‘chunk’ 혹은 ‘block’ 시퀀스로 처리

  • SAN (Storage Area Network)에 적용

cons

  • 고비용

pros

  • 빠른 데이터 접근 가능 : Journaling 이라는 데이터 추적 방식으로 구조화된 데이터에 적합

  • 파일이나 오브젝트를 여러 블락에 분산 저장 가능 → 다른 OS로 분산 저장도 가능

File storage

  • 가장 일반적인 저장소 유형으로 파일을 폴더와 하위 폴더의 계층 구조로 체계화

  • 폴더, 파일 경로를 사용해 접근 가능 → 파일 위치에 대한 메타데이터 (카탈로그와 같은 역활)

  • HDD, SSD, NAS (Network Attached Storage)에 적용

Object storage

  • 오브젝트 단위로 저장 → 데이터 고유 식별자를 통해 접근

  • Flat한 저장 구조로 접근이 빠르고 쉬움 → 오브젝트 API를 이용한 접근

cons

  • 파일 수정이 불가능

pros

  • 공간 효율적 이어서 비용이 저렴

  • 구조화 되지 않은 데이터의 규모 확장에 유리

Services

IOPS vs Throughput

  • IOPS : 초당 발생하는 IO 처리건 수

  • Throughput (처리량) : 지정 시간 동안 전송된 유효한 정보량

  • Latency : IO 요청을 처리하는 시간으로 응답 시간과 동일 의미

Block storage

  • Amazon EBS

File storage

  • Amazon EFS

  • Amazon FSx : feature-rich and highly-performant file systems

  • Amazon FSx for Windows

    • Windows Server에 구축된 완전관리형 공유 스토리지를 제공

    • SMB protocol을 통한 데이터 액세스

  • Amazon FSx for Lustre

    • Lustre 파일 시스템의 확장성과 성능을 가진 완전관리형 공유 스토리지

    • Lustre : applications that require fast storage

    • 고속 처리를 필요로 하는 HPC, 비디오 프로세싱, 금융 모델링, 유전자 sequencing, EDA (Electronic Design Automation) 등에 사용

  • Amazon FSx for ONTAP

    • 완전 관리형 공유 파일 스토리지 서비스인 ONTAP 파일 시스템 시작 및 실행

    • ONTAP : NetApp의 파일 시스템 기술로, 광범위하게 채택되는 일련의 데이터 액세스 및 데이터 관리 기능을 제공

    • NFS, SMB 및 iSCSI 프로토콜을 통한 데이터 액세스, 복제 등의 기능 제공

    • AWS와 온프레미스 간의 하이브리드 워크플로를 지원

  • Amazon FSx for OpenZFS

    • ZFS (Zettabyte File System) : Sun에서 개발한 파일 시스템으로 Solaris에 탑재 (Oracle)

    • OpenZFS : Linux, FreeBSD 지원

    • 고급 읽기 cache로 storage system 중단 시간을 줄일 수 있음, Inline 압축 제공, 특정 시점 스냅샷 및 인 플레이스 데이터 복제

    • AWS Graviton 프로세서 제품군 기반의 NFS 프로토콜(v3, v4, v4.1, v4.2)을 통해 액세스

    • 가장 대기 시간이 짧은 파일 스토리지 : 수백 마이크로초 latency, 12.5 GB/s througput, 1M IOPS

    • 대규모 사용자 또는 애플리케이션에 대해 공유된 고성능 파일 스토리지를 제공 및 병렬 연결을 지원 :

Object storage

  • Amazon S3

Backup storage

  • AWS Backup

    • AWS 서비스 전체에 대해 중앙에서 백업을 관리, 자동화 하여 데이터 보호 및 compliance를 지원

    • EC2, EBS volume, S3 bucket, RDS database, DynamoDB table, Neptune, DocumentDB, EFS, FSx file system, Storage Gateway volume

    • On-prem 및 VMWare workload 백업

Data Migration

  • AWS Storage Gateway

    • On-prem SW appliance를 클라우드 기반 storage에 연결하는 기능

    • File 기반 Gateway (S3, FSx), Volume 기반 (Cache, 저장), Tape 기반 Storage 솔루션

  • AWS DataSync

    • On-prem storage 시스템과의 데이터 이동을 단순화, 자동화, 가속화 하는 온라인 데이터 전송 서비스

    • Data Migration, Cold data archiving, Data 보호, Hybrid 클라우드 워크플로우

    • NFS 서버, SMB 서버, HDFS, On-prem object storage, Snowcone device, S3 bucket, EFS, Fsx for Windows/Lustre/OpenZFS

  • AWS Transfer Family

    • 파일 보안 전송 서비스

    • S3, EFS

    • SFTP, FTPS, FTP 프로토콜 사용

  • AWS Snowmobile

    • 초대용량 데이터를 AWS로 이전하데 사용하는 exa-byte 규모의 데이터 전송 서비스

    • 세미 트레일러 트럭으로 견인되는 운반 컨테이너 1대 강 최대 100PB 전송 가능 : DC migration, 비디오, 이미지 repository migration

  • AWS Snowball

    • 로컬 스토리지 및 대규모 데이터 전송

    • 스토리리 최적화 디바이스 (40 vCPU 및 객체 스토리지) : Edge computing, Data Migration, Edge Storage

    • 컴퓨팅 최적화 디바이스 (52 vCPU 및 객체 스토리지, 1 GPU) : 고급 ML 및 Full motion video analysis

  • AWS Snowcone

https://aws.amazon.com/ko/blogs/korea/introducing-aws-snowcone-small-lightweight-edge-storage-and-processing/

  • 8TB 스토리지 포함하여 DC, 데스크톱, 차량 및 드론 등과 함께 다양한 환경에서 사용 가능

  • Data migration, 콘텐츠 배포, 전략적 edge computing, 의료/산업 IoT, 운송, 물류, 자율 주행 차량 등에 사용

Amazon EBS

Feature

  • EC2 instance에서 사용할 수 있는 block storage service

  • 단일 instance에 여러개의 EBS volume 연결 가능

  • 단일 EBS volume을 여러개의 instance로 연결 (다중 연결) 가능 : 동일 AZ에서 최대 16개 Nitro system 기반 Linux instance

  • Block size & Volume Size

    • 4 KiB, 8 KiB, 16 KiB, 32 KiB, 64 KiB : 16 TiB, 32 TiB, 64 TiB, 128 TiB, 256 TiB

    • Block 개수 : 4 GiB (2 ^ 32)

Volume Type

https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ebs-volume-types.html

https://docs.aws.amazon.com/ko_kr/AWSEC2/latest/UserGuide/ebs-volume-types.html#EBSVolumeTypes_gp2

GP SSD

  • gp3 (2020년)

    • 3,000 IOPS 및 125Mib/s의 일관된 기준 속도를 제공

    • 추가 비용으로 추가 IOPS (~ 16000) 및 처리량 ( ~ 1000 MB/s) 프로비저닝

  • gp2 (2014년)

    • 시간을 연장할 경우 3000 IOPS 버스트 기능까지 지원 → 수 msec latency

    • 100 IOPS ( 33.33 GiB 이하) ~ 16000 IOPS (5334 GiB 이상)

    • baseline : GiB당 3 IOPS씩 비례해서 증가

    • Volume 크기는 1 ~ 16 TiB : volume이 클수록 기준 성능 수준이 크고 I/O 크레딧이 빨리 누적

    • I/O 크레딧 : 기준 성능 이상이 필요한 경우 대규모 I/O를 버스트 할 수 있도록 gp2 볼륨이 사용할 수 있는 가용 대역

Provisioned IOPS SSD

  • 성능과 일관성에 민감한 I/O 집약적 워크로드를 위해 설계

  • io2

    • Boot Volume, Virtual Desktop, Low latency interactive application

    • R5b, X2idn, X2idend 인스턴스의 io2 volume은 EBS Block Express에서 실행

    • EBS Block Express : 차세대 EBS 스토리지 아키텍쳐 (https://docs.aws.amazon.com/ko_kr/AWSEC2/latest/UserGuide/ebs-volume-types.html#io2-block-express)

    • 500 IOPS / GiB : 최대 50000 IOPS

  • io1

    • 대용량 Data base

    • 50 IOPS / GiB : 최대 5000 IOPS

Througput-optimized HDD

  • 자주 액세스하는 처리량 집약적 워크로드에 적합 : EMR, Big Data, Analytic 애플리케이션, 로그 처리

  • st1

    • 125 GiB ~ 16 TiB

    • 500 IOPS, 500 MiB/s

Cold HDD

  • 자주 액세스 하지 않는 데이터를 위한 스토리지

  • sc1

    • 125 GiB ~ 16 TiB

    • 250 IOPS, 250 MiB/s

Backup

Snapshot

  • Snapshot Archive (21.12) : https://aws.amazon.com/ko/blogs/korea/new-amazon-ebs-snapshots-archive/

  • If you make periodic snapshots of a volume, the snapshots are incremental—the new snapshot saves only the blocks that have changed since your last snapshot

  • Can create a point-in-time snapshot of an EBS volume and use it as a baseline for new volumes or for data backup

S3

Features

  • Durable (지속 가능하고), Highly Available (고 가용성을 가지고), Infinitely Scalable (무한 확장 가능한) Data Storage Infrastructure

  • Very Low Cost

  • Simply Key-based object store : Key는 문자열 이며 계층형 특성과 유사하게 구축할 수 도 있음

  • Object size : ~ 5TB

  • 단일 PUT method로 upload 할 수 있는 최대 object size는 5GB → 100MB 이상의 object는 Multipart Upload 기능을 이용

  • S3 data 구성 : Key(name), Value(data), Version ID, Metadata, ACL(Access Control List)

  • Scale : bucket의 prefix 당 최소 3500 PUT/POST/DELETE, 5500 GET rps

Use Case

  • Backup & Storage

  • Application / Media Hosting

  • Software Delivery

  • Statci Website

CORS (Cross Origin Resource Sharing)

  • Main origin에 연결 했을 때 다른 origin으로 요청을 허용

    • 요청이 GET 요청을 제출하도록 승인된 도메인에서 전송된 경우 해당 서버의 CORS 구성에 따라 cross-origin 서버는 요청된 리소스를 반환하여 응답

  • Acess-Control-Allow-Origin과 같은 CORS header가 allow 되어 있어야 함

https://aws.amazon.com/ko/premiumsupport/knowledge-center/s3-configure-cors/

Bucket

  • A flat container of objects

  • 100 buckets per account (default)

  • Universal namespace → must be unique globally

Replication

Same Region Replication (SRR)

  • 동일 리전 내에서 동일한 storage class의 S3 object 사본을 생성

  • 테스트 환경과 개발 환경 간에 실시간 복제를 구성

  • 데이터 주권 및 규정 준수 요구 사항을 충족하기 위해 동일 리전에 사용 필요 시

Cross Region Replication (CRR)

  • 동일 계정 혹은 다른 계정의

Multi Destination Replication

https://aws.amazon.com/ko/blogs/aws/new-amazon-s3-replication-adds-support-for-multiple-destination-buckets/

  • 다른 storage class, 다른 encryption type, 다른 account로 여러 복제를 생성할 수 있음

  • Source와 Destination bucket의 versioning이 활성화 되어 있어야 함

Pre-Signed URL

  • Query string authentication : 제한된 시간 동안에만 유효한 S3 object의 URL (Pre-Signed URL)

  • 모든 객체는 기본적으로 비공개이며, 객체 소유자만 이러한 객체에 액세스할 수 있음

  • 객체 소유자가 필요할 경우 자신의 보안 자격 증명을 사용하여 일정 기간 동안 객체 다운로드를 허가하는 미리 서명된 URL을 만들어 다른 사용자와 객체를 공유할 수 있음

  • 유효한 보안 자격 증명을 가진 사용자는 누구나 미리 서명된 URL을 만들 수 있습니다

  • GetObject 권한 : object view

  • PutObject 권한 : upload object
