2.2 Train Models

Overview

  1. 모델 학습은 모델의 매개변수(가중치)를 최적화하여 모델의 예측과 실제 출력값의 차이를 최소화하는 과정입니다.

  2. 학습 과정은 반복적으로 이루어지며, 알고리즘은 이전 예측에 대한 피드백을 바탕으로 가중치를 조정하여 점차 최적의 값에 가까워집니다. 마치 양궁에서 과녁의 중심을 맞추기 위해 화살의 방향을 조정하는 것과 유사합니다.

  3. 특징(feature)은 모델이 예측을 내리는 데 사용하는 정보 조각들로, 화살의 다양한 부품들(화살촉, 화살대, 꼬리 깃털)과 유사합니다.

  4. 모델 학습의 목표는 손실 함수(loss function)를 최소화하는 것입니다. 손실 함수는 모델의 예측 정확도를 측정하는 척도로, 예측값과 실제값의 차이를 나타냅니다. 이를 통해 모델의 예측을 실제 정답에 최대한 가까워지게 만듭니다.

  5. 효과적인 모델 학습을 위해서는 손실 함수와 최적화 기법이 필요합니다. 대표적인 최적화 기법인 gradient descent는 손실 함수의 기울기를 계산하여 가중치를 조정함으로써 최적의 값을 찾아갑니다.

  6. 그래디언트 디센트는 현재 가중치 값에서의 손실 함수 기울기를 계산하고, 이 기울기의 반대 방향으로 작은 스텝을 움직여 가중치를 업데이트합니다. 이 과정을 반복하면서 점차 전역 최소값에 수렴하게 됩니다.

  7. 학습률(learning rate), 배치 크기(batch size), 에폭(epoch) 수 등의 하이퍼파라미터를 적절히 설정하는 것이 모델의 학습 성공에 중요합니다. 예를 들어, 학습률이 너무 크면 최적값을 지나치게 되고, 너무 작으면 수렴이 느립니다.

  8. 하이퍼파라미터 튜닝은 모델의 일반화 성능을 높이는 데 필수적입니다.

  9. 이러한 모델 학습 핵심 개념과 기법은 많은 머신러닝 알고리즘, including Amazon SageMaker에서 사용됩니다.

Loss function

로그-우도 손실 함수(Log-Likelihood Loss)에 대한 설명:

  • 로그-우도 손실 함수는 **이진 분류 문제**에서 사용되는 손실 함수의 한 종류입니다.

  • 우도(Likelihood)는 모델이 관측 데이터를 얼마나 잘 설명할 수 있는지를 나타냅니다

  • 이 함수는 각 클래스에 대한 **예측 확률의 로그값**을 사용하여 손실을 계산합니다.

  • 수식은 다음과 같습니다: -log(p), 여기서 p는 모델이 예측한 해당 클래스에 대한 확률입니다.

  • y는 관측치의 실제 클래스를 나타내는 0 또는 1의 이진 지표입니다.

평균 제곱근 오차(RMSE)에 대한 설명:

  • RMSE는 **회귀 문제**에서 가장 기본적으로 사용되는 손실 함수입니다.

  • RMSE는 true output과 predicted output의 차이를 제곱하여 평균을 낸 것의 제곱근입니다.

  • 수식은 다음과 같습니다: √(Σ(Ytarget - Ypred)^2 / n), 여기서 Ytarget은 실제 출력값, Ypred는 예측 출력값, n은 데이터 포인트 수입니다.

  • RMSE는 예측 값과 실제 값 사이의 평균 편차를 나타내는 지표입니다.

Optimization techniques

  1. 일반적인 경사 하강법 (Gradient descent)

    • 전체 데이터셋을 한 번에 사용하여 가중치를 업데이트

    • 최소값 도달까지 **가장 느리지만**, 최소값 도달을 위한 **단계 수가 가장 적음**

  2. 확률적 경사 하강법(SGD - Stochastic Gradient descent)

    • 데이터셋의 각 **레코드별로 가중치를 업데이트**

    • 최소값에 **더 빠르게 도달**할 수 있지만, **다양한 방향으로 진동**할 수 있음

  3. 미니 배치 경사 하강법 (Mini-batch Gradient descent)

    • 전체 데이터셋이 아닌 **일부 데이터 배치(batch)를 사용하여 가중치 업데이트**

    • SGD보다는 **덜 진동**하면서, **경사 하강법보다는 더 빠르게** 최소값에 도달할 수 있음

    • 배치 크기 조절을 통해 **메모리 사용량을 조절**할 수 있음

Compute Environment Selection

Compute Environment Selection

When to consider GPUs

  • Large Datasets

  • Deep Learning Models

    • 많은 수의 파라미터를 가진 큰 규모의 딥 러닝 모델을 학습할 때

    • 고해상도 이미지, 방대한 텍스트 말뭉치 등 대용량 데이터셋을 다룰 때

    • 모델 개발 및 실험을 위해 빠른 학습 속도와 높은 처리량이 필요할 때

    • 사전 학습된 모델 또는 GPU 최적화 프레임워크를 활용할 때

    • 합성곱 신경망(CNN) 또는 순환 신경망(RNN) 같은 딥 러닝 모델을 학습할 때

    • 수백만 건 이상의 이미지나 문서로 구성된 대규모 데이터셋을 사용할 때

    • 모델 아키텍처와 하이퍼파라미터를 빠르게 시험해봐야 할 때

    • 지연 시간이 중요한 애플리케이션을 개발할 때

AWS Container Services

사전 빌트인 컨테이너 이미지 사용:

  • SageMaker에서 제공하는 일반적인 ML 프레임워크 기반의 사전 빌트인 컨테이너 이미지를 사용

  • 이미 포함된 학습 알고리즘 활용 가능

  • 사전 설정된 ML 프레임워크, 라이브러리, 의존성 사용 가능

사용자 정의 컨테이너 이미지 사용:

  • 사전 빌트인 컨테이너 이미지로 요구사항을 충족할 수 없는 경우

  • **추가적인 의존성이나 라이브러리가 필요한 경우** 사전 빌트인 이미지를 확장하여 사용

  • 알고리즘, 프레임워크, 의존성, 설정 등을 완전히 제어해야 하는 경우 BYOC(Bring Your Own Container) 방식으로 직접 컨테이너를 빌드

  • 규제 및 감사 요구사항을 충족하기 위해 BYOC 또는 BYOM(Bring Your Own Model) 방식 사용

AWS Marketplace에서 제공하는 컨테이너 이미지 활용:

  • 일반적인 프레임워크 기반의 최적화된 이미지 구독 가능

  • 성능과 확장성이 우수

Train A Model

Using a SageMaker Console

  1. SageMaker 학습 인스턴스 설정하기:

    • 왼쪽 메뉴에서 “Training” 선택 > “Training jobs” 선택

    • “Create training job” 버튼 클릭

  2. 트레이닝 작업 생성하기:

    • 이름: “training-job-demo”

    • IAM 역할: 기본 실행 역할 선택

    • 알고리즘 소스: XGBoost 알고리즘 선택

    • 입력 모드: Pipe 모드 선택

  3. 알고리즘 매트릭 및 리소스 구성:

    • 알고리즘 메트릭: 자동으로 표시됨

    • 리소스 구성: ml.m4.xlarge 인스턴스 유형, 단일 인스턴스 사용

  4. 하이퍼파라미터 설정:

    • 목표 함수: binary:logistic

  5. 입력 데이터 구성:

    • 학습 데이터 채널: 이름 “train”, 입력 모드 “Pipe”, 컨텐츠 유형 “text/csv”

    • S3 URI 입력

    • 검증 데이터 채널: 이름 “Validation”, 입력 모드 “Pipe”, 컨텐츠 유형 “text/csv”

    • S3 URI 입력

  6. 출력 구성:

    • S3 URI 설정

  7. 태그 추가:

    • 키-값 쌍의 태그 추가

  8. “Create training job” 버튼 클릭

  9. 학습 작업 모니터링:

    • 상태 변화 확인

    • 세부 내역 및 히스토리 확인

    • CloudWatch 지표 및 로그 확인

  10. 학습된 모델 아티팩트 확인:

    • S3에 저장된 모델 아티팩트 확인 (model.tar.gz)

    • 추가 테스트 및 배포를 위해 활용 가능

SageMaker Algorithm Options

  1. SageMaker 내장 알고리즘:

    • SageMaker는 다양한 사전 구성된 내장 알고리즘을 제공합니다.

    • 이러한 알고리즘은 회귀, 분류, 군집화 등 다양한 ML 작업에 최적화되어 있습니다.

    • 내장 알고리즘을 사용하면 ML 모델 개발에 소요되는 시간과 노력을 줄일 수 있습니다.

  2. 사용자 정의 알고리즘:

    • SageMaker는 사용자 정의 알고리즘을 사용할 수 있는 유연성을 제공합니다.

    • 사용자 고유의 알고리즘을 개발하여 학습에 사용할 수 있습니다.

    • 이를 통해 특정 비즈니스 문제에 최적화된 모델을 개발할 수 있습니다.

  3. 사전 학습된 모델:

    • SageMaker는 사전 학습된 모델을 활용할 수 있는 기능을 제공합니다.

    • 이를 통해 새로운 데이터셋에 대한 전이학습(transfer learning)이 가능합니다.

    • 기존에 학습된 모델을 사용하면 모델 학습 시간을 단축할 수 있습니다.

  4. 하이퍼파라미터 튜닝:

    • SageMaker는 하이퍼파라미터 최적화를 위한 도구를 제공합니다.

    • 모델 성능 향상을 위해 다양한 하이퍼파라미터 조합을 자동으로 탐색할 수 있습니다.

    • 이를 통해 최적의 하이퍼파라미터 설정을 찾을 수 있습니다.

  5. 사전 구축된 SageMaker 컨테이너 이미지를 사용할 수 없는 경우, 다음과 같은 옵션이 있습니다:

    • 자체 스크립트 또는 알고리즘을 패키징하여 SageMaker에서 사용

  6. SageMaker 내장 알고리즘의 장점:

    • 간편한 사용, 확장성, 성능, 다른 SageMaker 구성 요소와의 긴밀한 통합

    • 관리형 인프라를 제공하여 실험 수행 시 오버헤드 감소

  7. SageMaker 내장 알고리즘 사용 시:

    • 데이터, 하이퍼파라미터, 컴퓨팅 리소스만 제공하면 됨

    • 실험 수행 속도가 빨라지고, 결과 및 코드 변경 추적이 용이

    • 자동으로 다중 컴퓨팅 인스턴스와 GPU 지원 제공

  8. 내장 알고리즘의 한계:

    • 모든 비즈니스 문제와 데이터에 적합하지 않을 수 있음

    • 대용량 데이터에는 대부분 잘 확장될 수 있음

  9. 기타 옵션:

    • 자체 Docker 이미지 사용

    • AWS Marketplace에서 타사 모델 및 서비스 구매

Training Job

Component

  1. 학습 데이터:

    • 모델 학습을 위한 데이터는 Amazon S3에 저장되어 있어야 합니다.

    • SageMaker는 이 데이터를 사용하여 모델을 학습합니다.

  2. 하이퍼파라미터:

    • 모델 학습을 위해 선택하는 설정 값들입니다.

    • 알고리즘에 따라 다양한 하이퍼파라미터 옵션이 제공됩니다.

    • 이 값들을 적절히 선택하면 모델 성능을 높일 수 있습니다.

  3. 컴퓨팅 리소스:

    • 모델 학습을 위해 사용할 Amazon EC2 인스턴스 유형과 개수를 지정해야 합니다.

    • SageMaker는 다양한 최적화된 인스턴스 유형을 제공합니다.

핵심은 이 3가지 구성 요소만 적절히 설정하면 SageMaker의 내장 알고리즘을 사용하여 모델 학습을 수행할 수 있다는 것입니다. 이를 통해 실험 수행과 결과 추적을 위한 오버헤드를 크게 줄일 수 있습니다.

  1. SageMaker에서 사용할 수 있는 컨테이너 옵션:

    • 사전 구축된 알고리즘 컨테이너

    • 프레임워크 컨테이너

    • 사용자 정의 컨테이너

  2. 학습 데이터와 코드 입력 소스:

    • Amazon S3, Amazon EFS, Amazon FSx for Lustre

  3. 학습 과정:

    • 학습 코드와 데이터가 ML 컴퓨팅 인스턴스(Amazon EC2)로 전달됨

    • 인스턴스는 일시적으로 생성되어 학습 완료 후 자동 종료됨

    • SageMaker가 인스턴스 프로비저닝, 스케일링, 데이터/코드 배포를 관리

  4. 학습된 모델 아티팩트:

    • 사용자가 지정한 Amazon S3 버킷에 저장됨

  5. 비용 청구:

    • 학습 작업 실행 시간 동안 사용한 ML 컴퓨팅 인스턴스에 대해 과금됨

    • 인스턴스 유형과 개수에 따라 비용이 달라짐

Training Options

  1. SageMaker 콘솔 사용:

    • 콘솔 UI를 통해 모델 학습 작업을 생성할 수 있습니다.

  2. AWS SDK 사용:

    • 고수준 SageMaker Python SDK

    • 저수준 SageMaker API (Boto3 SDK for Python, AWS CLI)

Programmatic Access to training jobs

  1. SageMaker Python SDK와 Boto3 SDK를 사용하면 프로그래밍 방식으로 SageMaker 학습 작업에 접근할 수 있습니다.

  2. Estimator 클래스를 사용하여 고수준 인터페이스로 모델 학습을 구성할 수 있습니다.

    • set_hyperparameters() 메서드로 하이퍼파라미터를 설정할 수 있습니다.

    • fit() 메서드를 호출하여 실제 학습 작업을 시작할 수 있습니다.

  3. fit() 메서드 내부적으로 SageMaker의 CreateTrainingJob API를 호출합니다.

    • 제공된 구성과 입력 데이터를 기반으로 학습 작업을 시작합니다.

    • 학습 작업 완료 시 관련 인프라가 자동으로 종료되며, 사용한 리소스에 대해서만 과금됩니다.

  4. Estimator 클래스를 사용하면 프로그래밍 방식으로 학습 작업을 구성하고 실행할 수 있습니다.

    • 다양한 구성과 하이퍼파라미터를 효율적으로 실험할 수 있습니다.

    • ML 파이프라인에 통합하여 지속적인 통합 및 배포 워크플로를 구현할 수 있습니다.

Training data sources and data ingestion modes

Amazon SageMaker에서 효율적인 학습 작업을 설정할 때, 입력 데이터 액세스 방식을 고려하는 것이 중요합니다.

SageMaker는 Amazon S3, Amazon EFS, Amazon FSx for Lustre 등 세 가지 주요 데이터 소스를 지원합니다. 이 중 Amazon S3는 확장성, 내구성, 비용 효율성이 높아 교육 데이터 저장에 널리 사용됩니다.

데이터 Ingestion 모드

  1. Pipe 모드:

    • 알고리즘이 Pipe 모드를 지원하는 경우 사용

    • Amazon **S3에서 데이터를 직접 스트리밍**하여 **ML 스토리지 볼륨에 다운로드하지 않음**

    • 데이터 **다운로드 시간 감소로 학습 성능 향상**

  2. File 모드:

    • 알고리즘이 File 모드를 지원하는 경우 사용

    • Amazon **S3의 데이터를 ML 스토리지 볼륨에 다운로드**한 후 **컨테이너로 마운트**

    • ML 스토리지 **볼륨 용량이 데이터 크기를 수용**할 수 있어야 함

  3. Fast File 모드:

    • 알고리즘이 지원하는 경우 사용

    • Amazon **S3에서 데이터를 직접 스트리밍**하되, **파일 시스템 접근이 가능**

    • **순차적 데이터 액세스**에 적합

    • 버킷의 파일 수가 적을수록 시작 시간이 빨라짐

    1. 개요

      • Fast File 모드는 Amazon S3에 저장된 데이터를 마치 로컬 파일 시스템에서 액세스하는 것처럼 사용할 수 있게 해줍니다.

      • 코드 변경 없이도 데이터를 스트리밍 방식으로 사용할 수 있습니다.

    2. 사용 사례

      • 순차적으로 데이터를 읽는 알고리즘에 적합합니다.

      • 예를 들어 이미지, 텍스트, 오디오 데이터 등을 처리하는 모델 학습에 유용합니다.

    3. 장점

      • 데이터를 로컬에 다운로드할 필요가 없어 학습 시작 시간이 빠릅니다.

      • 데이터 전송 속도가 빨라 학습 성능을 높일 수 있습니다.

      • 코드 변경 없이 기존 파일 시스템 접근 방식을 그대로 사용할 수 있습니다.

    4. 제한사항

      • 증강된 매니페스트 파일은 지원되지 않습니다.

      • S3 버킷에 포함된 파일 수가 많을수록 시작 시간이 느려질 수 있습니다.

      • 무작위 액세스 패턴에는 적합하지 않습니다.

    5. 사용 방법

      • 학습 작업 생성 시 입력 모드를 “Pipe”로 지정하면 Fast File 모드가 자동으로 활성화됩니다.

      • 알고리즘이 Fast File 모드를 지원하는지 확인해야 합니다.

    요약하자면, Fast File 모드는 순차적 데이터 액세스 패턴을 가진 모델 학습에 적합한 옵션이며, 성능 및 개발 편의성 측면에서 장점이 있습니다.

    Fast File 모드를 사용할 때 SageMaker는 다음과 같은 서비스를 활용합니다:

    1. Amazon S3:

      • Fast File 모드에서는 Amazon S3에 저장된 데이터를 직접 액세스합니다.

      • S3에 저장된 데이터를 마치 로컬 파일 시스템에서 액세스하는 것처럼 사용할 수 있습니다.

    2. Amazon FSx for Lustre:

      • Fast File 모드에서는 Amazon FSx for Lustre 파일 시스템을 사용하여 데이터에 대한 파일 시스템 액세스를 제공합니다.

      • FSx for Lustre는 고성능 병렬 파일 시스템으로, 빠른 데이터 처리 속도를 제공합니다.

    3. AWS Managed Services:

      • SageMaker는 Fast File 모드를 위해 FSx for Lustre를 자동으로 프로비저닝하고 관리합니다.

      • 사용자는 이 파일 시스템을 직접 관리할 필요 없이 데이터 액세스만 구현하면 됩니다.

    이처럼 Fast File 모드를 사용하면 SageMaker가 Amazon S3와 FSx for Lustre를 활용하여 데이터에 대한 고성능 스트리밍 액세스를 제공합니다. 이를 통해 별도의 인프라 관리 없이도 데이터 집약적인 학습 작업을 수행할 수 있습니다.

데이터 Ingestion 모드 선택 시 고려사항

  • 데이터 크기: **대용량 데이터일 경우 Pipe 또는 Fast File 모드**가 효율적

  • 데이터 액세스 패턴: **순차적 액세스의 경우 Fast File** 모드, **무작위 액세스의 경우 File** 모드

  • 알고리즘 지원: 알고리즘에서 지원하는 모드 확인 필요

  • 성능 요구사항: 모드별 성능 특성 비교하여 선택

Anatomy of an ML model training script

SageMaker의 script mode에서 ML 모델 훈련 스크립트의 구성 요소는 다음과 같습니다:

  1. 라이브러리 및 의존성:

    • ML 프레임워크, 데이터 처리, 기타 유틸리티에 필요한 라이브러리와 의존성을 가져옵니다.

  2. 데이터 전처리:

    • 훈련 및 검증 데이터를 전처리하는 함수나 클래스를 정의합니다.

    • 데이터 정제, 특성 엔지니어링, 정규화 등의 작업을 수행합니다.

  3. 모델 정의:

    • 선택한 프레임워크(예: Apache MXNet, TensorFlow, PyTorch)를 사용하여 ML 모델을 정의합니다.

  4. 훈련 함수:

    • 훈련 루프를 구현하여 훈련 데이터를 반복적으로 처리하고, 손실을 계산하며, 모델 매개변수를 업데이트합니다.

    • 검증 데이터로 모델을 평가합니다.

    이때 엔트리포인트는 SageMaker에서 코드를 실행하는 방법을 알려주는 스크립트나 명령어입니다.

    script mode에서 엔트리포인트는 다음과 같은 구조를 따르는 Python 스크립트입니다:

    훈련 스크립트(train.py)

    • input_fn: 훈련 데이터를 로드하고 전처리

    • model_fn: 모델 아키텍처를 정의하고 모델 인스턴스 반환

    • train_fn: 훈련 루프를 정의하고 모델을 최적화

  5. 하드웨어 리소스 할당

    • 모델 훈련에 필요한 하드웨어 리소스(인스턴스 유형, GPU 개수 등)를 지정합니다.

    • 작업 특성과 요구사항에 맞는 적절한 리소스를 할당해야 합니다.

  6. 하이퍼파라미터 튜닝:

    • 모델 성능을 최적화하기 위해 하이퍼파라미터 튜닝 전략을 정의할 수 있습니다.

    • 다양한 하이퍼파라미터 조합을 탐색하여 최적의 값을 찾습니다.

  7. 로깅 및 모니터링:

    • 모델 훈련 진행 상황, 성능 지표, 잠재적 문제 등을 추적하기 위한 로깅 및 모니터링 메커니즘을 구현합니다.

    • CloudWatch 등 모니터링 도구를 활용하여 훈련 과정을 관찰할 수 있습니다.

이처럼 script mode를 활용하면 사용자 정의 코드와 SageMaker의 관리형 서비스를 유기적으로 결합할 수 있습니다.

Steps using script mode

SageMaker의 script mode를 사용하여 ML 모델을 학습하는 일반적인 단계는 다음과 같습니다:

  1. 로컬 환경 준비:

    • 개인 노트북이나 데스크톱에 SageMaker Python SDK를 설치합니다.

    • CPU나 GPU 등 다양한 인스턴스 유형을 사용할 수 있습니다.

    • SageMaker 관리형 노트북 인스턴스를 사용할 필요는 없습니다.

  2. 훈련 스크립트 작성:

    • 이전에 살펴본 구조를 따라 훈련 스크립트를 작성합니다.

  3. SageMaker estimator 객체 생성:

    • 훈련 스크립트, 인스턴스 유형, 기타 구성 정보를 지정하여 estimator 객체를 생성합니다.

  4. 추정기 객체의 fit 메서드 호출:

    • 훈련 데이터 채널과 검증 데이터 채널을 전달하여 fit 메서드를 호출합니다.

  5. SageMaker 처리:

    • SageMaker가 Amazon ECR에서 이미지를 가져와 관리형 인프라에 로드합니다.

  6. 모델 모니터링 및 아티팩트 검색:

    • 훈련 작업 진행 상황을 모니터링하고, 작업이 완료되면 학습된 모델 아티팩트를 가져옵니다.

이와 같은 단계를 거쳐 SageMaker의 script mode를 활용하여 ML 모델을 학습할 수 있습니다. 이 과정에서 사용자는 자신만의 맞춤형 코드와 SageMaker의 관리형 서비스를 효과적으로 결합할 수 있습니다.

SageMaker의 script mode에서 사용되는 관리형 사전 구축 컨테이너:

  • 사용자 정의 코드는 SageMaker 내장 알고리즘과 유사한 방식으로 사전 구축된 컨테이너 내에서 실행됩니다.

  • 이 컨테이너는 AWS에서 관리하며, Amazon ECR에 사전 구축되어 있습니다.

  • SageMaker 사전 구축 컨테이너에는 SageMaker Training Toolkit이 포함되어 있습니다.

    • 이 도구 키트는 Amazon SageMaker에서 학습 및 추론 작업을 관리하는 데 필요한 정보를 정의합니다.

    • 코드 및 기타 리소스 저장 위치, 컨테이너의 진입점 등이 포함됩니다.

  • 프레임워크별 도구 키트:

    • TensorFlow, MXNet, PyTorch, Chainer 등 주요 ML 프레임워크를 위한 프레임워크별 도구 키트가 제공됩니다.

    • 이 도구 키트는 사용자 정의 코드와 해당 프레임워크의 라이브러리 및 의존성을 원활하게 통합할 수 있도록 설계되었습니다.

이러한 사전 구축 컨테이너와 도구 키트를 사용하면 script mode에서 일관되고 원활한 경험을 제공할 수 있습니다.
사용자는 필요한 알고리즘, 라이브러리, 의존성을 가져올 수 있지만, 최적화된 환경 내에서 코드를 실행할 수 있습니다.

  4. fit() 메서드를 호출하여 학습 작업을 시작합니다.

학습 스크립트(example-script.py)에는 모든 의존성이 포함되어 있습니다.

SageMaker는 제공된 스크립트와 의존성을 가져와 AWS 관리형 컨테이너에 로드합니다. 그리고 요청된 리소스를 프로비저닝하여 학습 작업을 실행합니다.

데이터셋은 Amazon S3에 저장되며, SageMaker는 Amazon S3 파이프 모드, Amazon FSx for Lustre, Amazon EFS 등을 사용하여 데이터를 스트리밍할 수 있습니다. 이를 통해 대용량 데이터셋을 효율적으로 처리할 수 있습니다.

이처럼 SageMaker script mode를 활용하면 사용자 정의 TensorFlow 코드를 쉽게 확장 및 배포할 수 있습니다.

Methods to Reduce Training Time

모델 학습 시간을 단축해야 하는 주요 이유는 다음과 같습니다:

  1. 복잡성 및 데이터 집약성 증가:

    • ML 모델이 점점 더 복잡해지고 대용량 데이터를 처리해야 하므로, 학습 시간이 길어지고 있습니다.

  2. 모델 개발 주기 가속화:

    • 학습 시간이 단축되면 모델 개발 및 실험을 더욱 신속하게 수행할 수 있습니다.

    • 이를 통해 모델 성능 향상을 위한 반복 작업이 용이해집니다.

  3. 리소스 효율성 향상:

    • 학습 시간을 단축하면 비용과 컴퓨팅 리소스 사용을 줄일 수 있습니다.

    • 이는 ML 모델 개발 프로세스의 전반적인 효율성을 높입니다.

  4. 모델 성능 저하 방지:

    • 학습 시간 단축 기법을 적용하더라도 모델 성능이 저하되지 않도록 주의해야 합니다.

이러한 이유로 인해 SageMaker는 조기 중단(early stopping) 및 분산 학습 등의 기능을 제공하여 학습 시간을 단축할 수 있도록 지원합니다. 이를 통해 ML 엔지니어들은 보다 효율적으로 모델을 개발할 수 있습니다.

Early Stopping

조기 중단(Early Stopping)의 개념:

  • 모델이 검증 데이터셋에서 **더 이상 성능 향상이 없을 때 학습을 중단**하는 정규화 기법

  • 과적합(Overfitting) 문제를 방지하고 모델의 일반화 성능을 높이는 것이 목적

SageMaker의 조기 중단 기능:

  1. 각 epoch/iteration마다 지정된 목표 지표 평가

  2. 이전 작업들의 지표 평균 및 중앙값 계산

  3. 현재 작업의 지표가 이전 작업들의 중앙값보다 악화되면 자동으로 작업 중단

지원되는 알고리즘:

  • LightGBM, CatBoost, AutoGluon-Tabular, TabTransformer 등

  • 선형 학습기, XGBoost, 이미지 분류/객체 탐지, 시퀀스-시퀀스, IP Insights 등

구성 방법:

  • Boto3 SDK, SageMaker Python SDK, SageMaker 콘솔에서 설정 가능

조기 중단을 활용하면 ML 모델 학습 시간과 리소스 사용을 크게 줄일 수 있어, 모델 개발 효율성이 향상됩니다.

Distributed Training

분산 학습(Distributed Training)의 개념:

  • 여러 대의 컴퓨팅 리소스(GPU, 인스턴스 등)를 활용하여 딥러닝 모델 학습을 확장하는 기법

  • 모델 규모와 데이터셋 크기가 커짐에 따라 단일 머신으로는 학습이 어려워지는 문제 해결

  • **데이터 병렬(Data Parallel) 및 모델 병렬(Model Parallel) 방식**으로 구현

분산 학습의 장점:

  • 계산 리소스 확장을 통한 학습 시간 단축

  • GPU 활용도 극대화로 비용 효율성 향상

  • 매우 큰 모델 학습 가능

  • 대용량 배치 사용으로 모델 정확도 향상

분산 학습 라이브러리:

  • PyTorch, TensorFlow 등의 딥러닝 프레임워크를 위한 고수준 API 제공

  • 하부 인프라 관리 없이 학습 작업을 분산 실행할 수 있게 해줌

  • Amazon SageMaker에서도 이러한 분산 학습 라이브러리를 활용할 수 있음

요약하면, 분산 학습은 모델과 데이터셋 규모가 크거나 학습 속도 향상이 필요할 때 활용할 수 있는 중요한 기법입니다. SageMaker는 이를 위한 편리한 기능을 제공합니다.

Data Parallelism

  1. 데이터 병렬(Data Parallelism):

    • 학습 데이터셋을 **더 작은 배치로 나누어 여러 GPU 또는 인스턴스에 분산**

    • 각 디바이스에 **모델 복사본이 할당**되며, **자신의 데이터 배치에 대해 순전파와 역전파를 계산**

    • 배치 완료 후 디바이스 간 **계산된 기울기를 집계하고 평균하여 모델 가중치 업데이트 (AllReduce)**

  2. Key component

    • Global batch size: The total batch size used, equal to the sum of per-replica batch sizes

    • Per-replica batch size: The batch size assigned to each model replica

    • AllReduce: The collective operation to aggregate and average gradients from all devices

    • AllGather

      AllGather는 분산 데이터 병렬 학습에서 사용되는 또 다른 핵심 연산입니다.

      AllGather의 개념은 다음과 같습니다:

      1. 데이터 쪼개기(Sharding):

        • 학습 데이터셋을 여러 개의 조각(shard)으로 분할합니다.

        • 각 조각은 다른 GPU/인스턴스에 할당됩니다.

      2. 데이터 병렬화:

        • 각 GPU/인스턴스는 자신의 데이터 조각으로만 모델을 학습합니다.

      3. AllGather 연산:

        • 학습이 완료된 후, 각 디바이스의 모델 가중치 업데이트를 모든 디바이스에 모아 모은다.

        • 이를 통해 각 디바이스가 전체 데이터셋에 대한 모델 업데이트 정보를 얻을 수 있습니다.

      이 과정을 통해 메모리 사용을 최소화하면서도 전체 데이터셋에 대한 모델 학습이 가능해집니다. 이를 “쪼갠 데이터 병렬 학습(Sharded Data Parallel)“이라고 합니다.

  3. SageMaker 분산 데이터 병렬(SMDDP) 라이브러리:

    • SageMaker의 분산 학습 기능을 확장하는 라이브러리

    • AWS 네트워크 인프라와 SageMaker ML 인스턴스 토폴로지에 최적화된 분산 학습 기능 제공

    • AllReduce, AllGather와 같은 통신 연산을 AWS 인프라에 맞게 최적화

SageMaker의 SMDDP 라이브러리는 이러한 AllGather 연산을 AWS 인프라에 맞게 최적화하여 제공합니다. 이를 활용하면 메모리 효율적인 분산 학습을 수행할 수 있습니다.

데이터 병렬 방식은 대용량 데이터셋으로 학습할 때 유용합니다. 메모리 부족 문제가 발생하면 모델 병렬 방식이나 하이브리드 방식을 시도할 수 있습니다.

SMDDP 라이브러리는 SageMaker에서 분산 데이터 병렬 학습을 편리하게 수행할 수 있도록 지원합니다. 이를 통해 AWS 인프라의 장점을 활용하여 대규모 딥러닝 모델 학습을 가속화할 수 있습니다.

Model parallelism

모델 병렬(Model Parallelism)은 데이터 병렬과 달리 모델 자체를 여러 디바이스에 걸쳐 분산시키는 기법입니다.

모델 병렬이 필요한 경우:

  • **모델 크기가 너무 커서** 단일 디바이스의 메모리에 하나의 샘플도 담을 수 없는 경우

모델 병렬의 개념:

  • **모델 파라미터/가중치를 여러 디바이스에 분산 할당**

  • **입력 데이터를 디바이스 간 분산 처리**

  • 텐서 병렬(Tensor Parallelism)과 같은 기법으로 계층 내 큰 행렬 곱셈을 분산 처리

예시:

  • 4개 계층으로 구성된 모델을 2개의 GPU에 분산

  • 각 GPU에 모델의 절반씩 할당하여 처리

  • 데이터 병렬과 함께 사용하여 (병렬 정도: 데이터 8개, 모델 2개)

모델 병렬은 데이터 병렬에 비해 복잡합니다.
SageMaker 모델 병렬 라이브러리와 같은 프레임워크를 사용하면 구현을 간소화할 수 있습니다.

요약하면, 모델 병렬은 모델 크기가 매우 큰 경우 메모리 한계를 극복하기 위해 사용되며, 데이터 병렬과 함께 활용하면 더욱 효과적인 분산 학습이 가능합니다.

Model Parallelism library

SageMaker의 모델 병렬 라이브러리 v2 (SMP v2)에 대해 정리하면 다음과 같습니다:

  1. Hybrid Sharded Data Parallelism

    • 데이터 병렬과 모델 병렬을 결합하여 대형 모델을 다중 가속기에서 학습할 수 있게 해줌

  2. Tensor Parallelism

    • 모델 병렬의 한 형태로, 단일 텐서(가중치 행렬 등)를 여러 디바이스에 분산 처리

    • 단일 디바이스에 저장할 수 없는 매우 큰 텐서 연산을 가능하게 함

  3. Activation Checkpointing

    • 큰 신경망 학습 시 메모리 절약을 위해 순방향 계산 결과를 저장하지 않고 역방향 계산 시 재 계산

    • 활성화 체크포인팅은 대용량 신경망 모델을 학습할 때 메모리 사용량을 줄이기 위한 기법입니다.

    동작 원리:

    1. 순방향 계산 중 중간 활성화 값을 저장하지 않습니다.

    2. 대신 역전파 계산이 필요할 때마다 순방향 계산을 다시 수행하여 활성화 값을 재생성합니다.

    이렇게 하면 순방향 계산 중에는 활성화 값을 저장할 필요가 없어지므로, GPU 메모리 사용량이 크게 줄어듭니다.

    장점:

    • 메모리 사용량 감소: 순방향 계산 결과를 저장하지 않아도 되므로, GPU 메모리 사용량이 크게 줄어듭니다.

    • 모델 크기 확장 가능: 메모리 제약을 완화하여 보다 큰 모델을 학습할 수 있습니다.

    단점:

    • 계산 시간 증가: 역전파 시마다 순방향 계산을 반복해야 하므로, 전체 학습 시간이 길어질 수 있습니다.

    활성화 체크포인팅은 SageMaker의 모델 병렬 라이브러리 v2(SMP v2)에서 지원되는 핵심 기능 중 하나입니다. 이를 통해 대규모 신경망 모델 학습을 보다 효율적으로 수행할 수 있습니다.

  4. Activation Offloading

    • 큰 신경망 학습 시 GPU 메모리에서 CPU 메모리나 디스크로 활성화를 오프로딩하여 메모리 절약

SMP v2는 PyTorch의 완전 쪼갠 데이터 병렬(FSDP)과도 호환되어, 간단한 코드 변경으로 성능 최적화 혜택을 누릴 수 있습니다.

데이터 병렬 vs 모델 병렬 선택 가이드

  • 모델이 단일 GPU에 들어가지만 데이터셋이 크다면 데이터 병렬 추천

  • 모델이 단일 GPU에 들어가지 않는다면 모델 병렬이 필요

  • 극대형 모델 및 데이터셋인 경우 데이터 병렬과 모델 병렬을 혼용하는 것이 유리

이처럼 SageMaker의 SMP v2는 대규모 모델 및 데이터셋 학습을 위한 다양한 분산 학습 기술을 제공합니다.

External Models

Bring Your Own Model to SageMaker

SageMaker에 자신만의 모델을 가져오려면 모델 패키지를 구축해야 합니다. 이 패키지는 다음을 포함하는 배포 가능한 Docker 컨테이너를 정의합니다:

  1. 모델 실행에 필요한 프레임워크

  2. 모델 아티팩트의 위치

  3. 모델 추론 수행을 위한 코드

  4. 기타 라이브러리 및 종속성

  5. 배포 옵션

SageMaker에 모델을 배포하는 방법은 다음과 같습니다:

  1. 사전 구축된 컨테이너 사용:

    • SageMaker는 PyTorch, TensorFlow 등 다양한 ML 프레임워크를 위한 사전 구축 컨테이너를 제공합니다.

    • 이러한 컨테이너를 학습, 호스팅, 데이터 처리에 활용할 수 있습니다.

  2. 사용자 정의 컨테이너 생성:

    • 사전 구축 컨테이너로 요구 사항을 충족할 수 없는 경우

    • SageMaker 도구 키트 중 하나를 사용하여 자체 컨테이너를 구축할 수 있습니다.

SageMaker 도구 키트 목록은 “Adapting Your Own Docker Container to Work with SageMaker” 문서에서 확인할 수 있습니다.

모델 패키지 구축 방법에 대한 자세한 내용은 추가 정보를 확인하세요.

요약하면, SageMaker에 자신만의 모델을 배포하려면 Docker 컨테이너 기반의 모델 패키지를 구축해야 하며, 사전 구축 컨테이너나 사용자 정의 컨테이너를 사용할 수 있습니다.
