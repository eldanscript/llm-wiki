Amazon Bedrock AgentCore 소개

실험적인 AI 프로젝트에서 프로덕션 배포로 전환하면서, 조직은 AI 에이전트의 확장, 보안, 관리에 있어 중요한 과제에 직면합니다. Amazon Bedrock AgentCore는 **엔터프라이즈급 AI 에이전트 배포**에 필요한 기본 구성 요소를 제공하여 이러한 과제를 해결합니다.

Amazon Bedrock AgentCore란?

Amazon Bedrock AgentCore는 대규모로 안전한 AI 에이전트를 구축, 배포 및 운영하기 위한 AWS의 완전 관리형 서비스입니다.

핵심 목적

엔터프라이즈급 AI 에이전트 배포:

  • 실험에서 프로덕션으로의 전환 지원

  • **확장 가능한 인프라** 제공

  • **보안 및 관리 기능** 내장

Amazon Bedrock 생태계의 일부:

  • Bedrock의 기초 모델과 통합

  • 엔터프라이즈 AI 플랫폼의 핵심 구성 요소

  • 다른 AWS 서비스와 원활한 연동

프로덕션 배포의 주요 과제

조직이 직면하는 과제들:

1. 확장성 (Scaling)

  • 소규모 실험에서 대규모 배포로 전환

  • 증가하는 부하 처리

  • 성능 유지

2. 보안 (Security)

  • 엔터프라이즈급 보안 요구사항

  • 데이터 보호 및 규정 준수

  • 접근 제어 및 인증

3. 관리 (Management)

  • 여러 에이전트의 효율적 관리

  • 모니터링 및 유지보수

  • 버전 관리 및 업데이트

AgentCore의 핵심 기둥 (Core Pillars)

영상에서 다루는 AgentCore의 핵심 요소들이 어떻게 함께 작동하여 프로덕션 준비 AI 에이전트를 가능하게 하는지 살펴봅니다:

완전 관리형 서비스:

  • 인프라 관리 부담 감소

  • 자동 확장 및 최적화

  • 운영 복잡성 최소화

보안 및 규정 준수:

  • 내장된 보안 기능

  • 엔터프라이즈 표준 준수

  • 감사 및 로깅

확장 가능한 아키텍처:

  • 대규모 배포 지원

  • 고가용성 보장

  • 성능 최적화

AgentCore Seven Pillars

Amazon Bedrock AgentCore는 안전하고 확장 가능한 에이전트 배포를 가능하게 하기 위해 함께 작동하는 7개의 기본 기둥으로 구성됩니다.

7가지 핵심 기둥

각 기둥은 프로덕션급 AI 에이전트 시스템의 특정 측면을 담당합니다:

1. 런타임 (Runtime)

에이전트 배포 및 확장을 위한 안전한 서버리스 런타임

  • 서버리스 아키텍처: 인프라 관리 불필요

  • 자동 확장: 부하에 따라 자동으로 리소스 조정

  • 보안 실행 환경: 격리된 안전한 실행 공간

  • 고가용성: 안정적인 에이전트 운영 보장

역할: 에이전트가 실행되는 기반 환경을 제공합니다.

2. 메모리 (Memory)

단기 및 장기 메모리 관리

  • 단기 메모리: 현재 대화 및 작업 컨텍스트 유지

  • 장기 메모리: 과거 상호작용 및 학습 내용 저장

  • 효율적인 검색: 필요한 정보를 빠르게 찾기

  • 컨텍스트 유지: 일관된 에이전트 행동 보장

역할: 에이전트가 과거를 기억하고 학습할 수 있게 합니다.

3. 아이덴티티 (Identity)

안전한 중앙 집중식 액세스 관리

  • 인증 및 권한 부여: 누가 무엇에 액세스할 수 있는지 제어

  • 중앙 집중식 관리: 일관된 보안 정책 적용

  • 역할 기반 액세스: 세밀한 권한 제어

  • 감사 추적: 모든 액세스 기록 유지

역할: 에이전트와 사용자의 보안을 보장합니다.

4. 게이트웨이 (Gateway)

외부 시스템 및 도구와의 연결

  • API 통합: 외부 서비스와 연결

  • 프로토콜 지원: MCP 등 표준 프로토콜 구현

  • 데이터 변환: 다양한 형식 간 변환

  • 연결 관리: 안정적인 외부 통신

역할: 에이전트가 외부 세계와 상호작용할 수 있게 합니다.

5. 코드 인터프리터 (Code Interpreter)

안전한 코드 실행 환경

  • 샌드박스 실행: 격리된 환경에서 코드 실행

  • 다양한 언어 지원: Python 등 주요 언어 지원

  • 보안 제약: 안전하지 않은 작업 차단

  • 결과 검증: 실행 결과 확인 및 검증

역할: 에이전트가 동적으로 코드를 실행하고 계산을 수행할 수 있게 합니다.

6. 브라우저 도구 (Browser Tool)

웹 상호작용을 위한 클라우드 기반 브라우저

  • 웹 페이지 액세스: 실시간 웹 콘텐츠 접근

  • 자동화된 상호작용: 웹 양식 작성, 클릭 등

  • 스크린샷 및 데이터 추출: 웹 정보 수집

  • 안전한 브라우징: 격리된 환경에서 실행

역할: 에이전트가 웹과 상호작용하고 정보를 수집할 수 있게 합니다.

7. 관찰 가능성 (Observability)

포괄적인 모니터링 및 디버깅

  • 실시간 모니터링: 에이전트 동작 추적

  • 상세한 로깅: 모든 작업 기록

  • 성능 메트릭: 처리 시간, 성공률 등 측정

  • 디버깅 도구: 문제 진단 및 해결

역할: 에이전트의 동작을 이해하고 최적화할 수 있게 합니다.

에이전트 배포 흐름 (Agent Deployment Flow)

배포 프로세스를 이해하는 것은 AgentCore Runtime을 성공적으로 구현하는 데 필수적입니다. 다음은 에이전트 배포의 5가지 주요 단계를 안내하며, 초기 개발부터 프로덕션 엔드포인트 생성까지의 과정을 보여줍니다. 각 단계는 이전 단계를 기반으로 구축되며, AgentCore Runtime이 전통적으로 복잡한 배포 프로세스를 어떻게 자동화하고 단순화하는지 보여줍니다.

5단계 배포 프로세스

1단계: 로컬 에이전트 개발 (Local Agent Development)

개발 환경 구축:

  • 원하는 프레임워크를 사용하여 에이전트 구축 (LangGraph, CrewAI, Strands 등)

  • 선택한 모델로 로컬에서 기능 테스트

  • 필요한 종속성 및 요구사항 준비

  • 에이전트 동작이 기대치를 충족하는지 검증

핵심 활동:

  • 비즈니스 로직 구현

  • 로컬 테스트 및 디버깅

  • 성능 검증

  • 종속성 문서화

2단계: 런타임 구성 (Runtime Configuration)

배포 설정:

  • 진입점(entry point) 및 IAM 역할 구성

  • 필요한 라이브러리 및 종속성 지정

  • 환경 변수 설정

  • 리전 및 에이전트 이름 정의

  • 인증 설정 구성 (필요시 OAuth)

구성 요소:

  • 실행 권한 정의

  • 리소스 요구사항 명시

  • 보안 설정 구성

  • 네트워크 및 액세스 정책

3단계: 컨테이너 생성 (Container Creation)

자동화된 컨테이너화:

  • AgentCore가 자동으로 Dockerfile 생성

  • 종속성이 컨테이너 이미지로 패키징

  • 에이전트 코드에 런타임 데코레이터 추가

  • 관찰 가능성 구성 통합

  • 보안 제어 구현

자동 처리 항목:

  • 컨테이너 이미지 빌드

  • 보안 강화

  • 모니터링 설정

  • 최적화 적용

4단계: ECR 리포지토리 배포 (ECR Repository Deployment)

이미지 관리:

  • 컨테이너 이미지가 자동으로 빌드됨

  • 이미지가 Amazon ECR로 푸시됨

  • 버전 관리 유지

  • 보안 스캔 수행

  • 배포를 위한 이미지 검증

품질 보증:

  • 자동 보안 검사

  • 취약점 스캔

  • 버전 태깅

  • 배포 준비 확인

5단계: 런타임 엔드포인트 생성 (Runtime Endpoint Generation)

프로덕션 준비:

  • 안전한 엔드포인트 생성

  • 자동 확장 구성

  • 헬스 체크 구현

  • 모니터링 활성화

  • 호출 준비 완료된 엔드포인트

운영 기능:

  • 자동 스케일링

  • 로드 밸런싱

  • 장애 복구

  • 성능 모니터링

배포 흐름의 핵심 특징

자동화의 힘

개발자가 하는 일:

  1. 에이전트 코드 작성

  2. 런타임 구성 설정

  3. 배포 명령 실행

AgentCore가 자동으로 처리:

  • Dockerfile 생성

  • 컨테이너 빌드

  • 이미지 푸시

  • 보안 스캔

  • 엔드포인트 생성

  • 모니터링 설정

전통적 배포 vs AgentCore 배포

전통적 방식:

코드 작성 → Dockerfile 작성 → 이미지 빌드 →
레지스트리 설정 → 푸시 → 오케스트레이션 구성 →
보안 설정 → 모니터링 설정 → 배포
(수일~수주 소요)

AgentCore 방식:

코드 작성 → 런타임 구성 → 배포 명령
(수분~수시간 소요)

4단계 (ECR 배포):

5단계 (엔드포인트 생성):

아이덴티티 관리 (Identity Management)

AgentCore Identity는 에이전트를 위한 안전한 액세스 관리를 가능하게 하며, AWS 리소스 및 타사 서비스와의 원활한 통합을 제공합니다.

아이덴티티 관리 구성 요소

아이덴티티 관리의 각 측면을 살펴보겠습니다:

1. 인증 (Authentication)

  • Support for multiple identity providers

  • Token management

  • Session control

다양한 아이덴티티 제공자 지원:

  • AWS Cognito 통합

  • OAuth 2.0/2.1 프로토콜

  • 타사 아이덴티티 제공자 연동

  • 표준 인증 프로토콜 지원

토큰 관리:

  • 액세스 토큰 자동 생성 및 갱신

  • 안전한 토큰 저장 및 관리

  • 토큰 만료 및 갱신 처리

  • API 키 관리

세션 제어:

  • 세션 생명주기 관리

  • 동시 세션 제어

  • 세션 타임아웃 설정

  • 안전한 세션 종료

2. 권한 부여 (Authorization)

  • Fine-grained access control

  • Permission delegation

  • Resource policies

세밀한 액세스 제어:

  • 역할 기반 액세스 제어 (RBAC)

  • 리소스별 권한 설정

  • 최소 권한 원칙 적용

  • 동적 권한 평가

중앙 집중식 관리:

  • 모든 에이전트의 권한을 한 곳에서 관리

  • 일관된 정책 적용

  • 권한 변경의 즉시 반영

  • 감사 및 규정 준수 지원

3. 통합 (Integration)

  • AWS service connections

  • Third-party tool access

  • OAuth support

AWS 리소스 통합:

  • S3, DynamoDB, Lambda 등 AWS 서비스 액세스

  • IAM 역할 및 정책 통합

  • AWS 서비스 간 원활한 인증

타사 서비스 통합:

  • 외부 API 인증

  • OAuth 기반 서비스 연동

  • 커스텀 인증 시스템 지원

완전한 에이전트 능력:

Gateway의 역할:

  • 외부 도구 및 서비스 액세스

  • 실시간 데이터 수집

Memory의 역할:

  • 경험 저장 및 학습

  • 컨텍스트 유지

  • 개인화

함께 작동:

1. Gateway를 통해 날씨 API 호출
2. Memory에 사용자가 자주 확인하는 지역 저장
3. 다음번에 자동으로 해당 지역 날씨 제공
4. 시간대별 선호도 학습 (아침에 날씨 확인)
5. 점점 더 개인화되고 효율적인 서비스

  • Memory가 있으면 학습하고 개선하는 에이전트

  • 진정한 개인화 및 적응 가능

  • 안전한 격리 저장

  • 확장 가능한 아키텍처

사용자 경험:

  • 반복 없는 자연스러운 대화

  • 개인화된 상호작용

  • 시간이 지남에 따라 향상

단기 메모리 vs 장기 메모리

AgentCore Memory의 실제 작동 방식을 살펴보았으니, 이제 이 시스템을 강력하게 만드는 두 가지 구별되는 메모리 유형을 살펴보겠습니다. 단기 메모리와 장기 메모리의 차이를 이해하는 것은 즉각적인 컨텍스트와 가치 있는 장기 통찰을 모두 유지할 수 있는 에이전트를 설계하는 데 필수적입니다.

단기 메모리 (Short-Term Memory)

즉각적인 컨텍스트 관리:

세션 관리 (Session Management)

  • 현재 대화 세션의 상태 추적

  • 활성 작업 및 진행 상황 유지

  • 세션 시작부터 종료까지의 흐름 관리

  • 세션 간 경계 명확히 구분

원시 이벤트 저장 (Raw Event Storage)

  • 모든 상호작용을 있는 그대로 기록

  • 사용자 입력 및 에이전트 응답 저장

  • 타임스탬프 및 메타데이터 포함

  • 상세한 대화 이력 유지

대화 분기 지원 (Conversation Branching Support)

  • 대화 주제 전환 추적

  • 여러 병렬 대화 스레드 관리

  • 이전 주제로 돌아가기 지원

  • 복잡한 대화 구조 처리

즉각적인 컨텍스트 유지 (Immediate Context Retention)

  • “그것”, “저것” 등의 참조 해석

  • 이전 질문과 답변 연결

  • 대화 흐름의 자연스러운 연속성

  • 실시간 컨텍스트 업데이트

장기 메모리 (Long-Term Memory)

영구적인 학습 및 개인화:

사용자 선호도 추출 (User Preference Extraction)

  • 반복되는 패턴에서 선호도 학습

  • 명시적 및 암묵적 선호도 파악

  • 사용자 스타일 및 습관 이해

  • 개인화된 경험 제공

시맨틱 사실 저장 (Semantic Fact Storage)

  • 중요한 정보를 의미론적으로 저장

  • 관련 사실들을 연결하여 저장

  • 지식 그래프 형태로 구조화

  • 효율적인 검색 및 추론 지원

세션 간 지속성 (Cross-Session Persistence)

  • 세션이 종료되어도 정보 유지

  • 며칠, 몇 주 후에도 기억

  • 장기적인 관계 구축

  • 누적된 지식 활용

자동 지식 통합 (Automated Knowledge Consolidation)

  • 유사한 정보 자동 병합

  • 중복 제거 및 최적화

  • 패턴 인식 및 일반화

  • 지식 베이스 자동 정리

  • 최대 8시간 워크로드 지원

3. 보안 및 격리

  • VM 수준 세션 격리

  • 각 에이전트 실행의 독립성 보장

  • 멀티테넌트 환경 보안

  • 100MB 페이로드 지원

4. 통합 플랫폼

  • 다른 모든 기둥(Identity, Gateway, Memory 등)과 통합

  • 에이전트가 작동하는 전체 환경

  • 프레임워크 독립적 (Strands, LangGraph, CrewAI 등)

비유

Runtime은 건물의 기초와 구조와 같습니다:

  • 모든 것이 그 위에서 작동

  • 안정성과 보안 제공

  • 항상 필요한 필수 요소

Code Interpreter (코드 인터프리터)

기본 역할: 에이전트가 사용하는 특수 도구

주요 기능

1. 코드 실행 능력

  • Python, JavaScript, TypeScript 코드 작성 및 실행

  • 샌드박스 환경에서 안전한 실행

  • 사전 설치된 라이브러리 (pandas, numpy 등)

  • 기본 15분, 최대 8시간 실행

2. 데이터 처리

  • CSV, Excel, JSON 등 구조화된 데이터 처리

  • 대규모 데이터셋 분석 (S3 통합)

  • 수학적 계산 및 통계 분석

  • 데이터 시각화 생성

3. 문제 해결 확장

  • 추론만으로 해결하기 어려운 계산 문제

  • 복잡한 알고리즘 실행

  • 정밀한 수치 계산

  • 반복적 데이터 처리

4. Gateway를 통한 도구 통합

  • Gateway에 등록된 하나의 도구

  • 필요시 에이전트가 선택적으로 사용

  • 다른 도구들(Browser Tool 등)과 조합 가능

비유

Code Interpreter는 건물 안의 특수 작업실과 같습니다:

  • 특정 작업(코드 실행)을 위한 공간

  • 필요할 때만 사용

  • 다른 도구들과 함께 사용 가능

관계 및 상호작용

계층 구조

Core Runtime (기반 플랫폼)
    ├── Identity (보안)
    ├── Gateway (도구 통합)
    │   ├── Code Interpreter (코드 실행 도구)
    │   ├── Browser Tool (웹 상호작용 도구)
    │   └── 기타 도구들
    └── Memory (컨텍스트 유지)

작동 흐름

Runtime이 제공하는 환경에서:

1. Runtime: 에이전트 시작 및 실행 환경 제공
2. Identity: 권한 확인
3. Gateway: 사용 가능한 도구 제공
4. 에이전트: 필요시 Code Interpreter 선택
5. Code Interpreter: 샌드박스에서 코드 실행
6. Runtime: 전체 프로세스 관리 및 모니터링

Observability 기능의 분류

Observability 기능을 주요 목적에 따라 분류하면 다양한 모니터링 요구사항에 어떤 도구를 사용해야 하는지 이해하는 데 도움이 됩니다.

1. 모니터링 (Monitoring)

실시간 성능 추적:

  • 메트릭 수집: 응답 시간, 처리량, 성공률 등

  • 대시보드: 실시간 시각화 및 KPI 추적

  • 알림: 임계값 초과 시 자동 알림

  • 상태 확인: 에이전트 헬스 체크

주요 메트릭:

  • 요청 수 및 처리 시간

  • 오류율 및 성공률

  • 리소스 사용량 (CPU, 메모리)

  • 도구 호출 빈도 및 성능

2. 로깅 (Logging)

상세한 활동 기록:

  • 이벤트 로그: 모든 에이전트 활동 기록

  • 대화 로그: 사용자 상호작용 추적

  • 도구 호출 로그: Gateway를 통한 모든 도구 사용 기록

  • 오류 로그: 예외 및 실패 상세 정보

로그 수준:

  • DEBUG: 상세한 디버깅 정보

  • INFO: 일반 작업 정보

  • WARNING: 잠재적 문제

  • ERROR: 오류 및 예외

3. 추적 (Tracing)

요청 흐름 추적:

  • 분산 추적: 전체 요청 경로 시각화

  • 스팬(Span) 분석: 각 단계의 소요 시간

  • 의존성 맵: 서비스 간 관계 파악

  • 병목 지점 식별: 성능 저하 원인 찾기

추적 정보:

  • 에이전트 루프 (인식-추론-행동) 각 단계

  • 도구 호출 체인

  • Memory 액세스 패턴

  • 외부 API 호출

4. 디버깅 (Debugging)

문제 진단 및 해결:

  • 상세 실행 로그: 단계별 실행 내역

  • 변수 검사: 중간 상태 확인

  • 오류 스택 추적: 오류 발생 지점 파악

  • 재현 도구: 문제 상황 재현

디버깅 기능:

  • 브레이크포인트 설정

  • 단계별 실행

  • 변수 값 검사

  • 실행 흐름 시각화

5. 분석 (Analytics)

패턴 및 통찰 발견:

  • 사용 패턴 분석: 에이전트 사용 트렌드

  • 성능 분석: 시간에 따른 성능 변화

  • 비용 분석: 리소스 사용 및 비용 추적

  • 사용자 행동 분석: 상호작용 패턴

분석 도구:

  • 시계열 분석

  • 집계 및 통계

  • 이상 탐지

  • 예측 분석

  5. ✓ Browser Tool: 웹 상호작용 기능

  6. ✓ Code Interpreter: 안전한 코드 실행
