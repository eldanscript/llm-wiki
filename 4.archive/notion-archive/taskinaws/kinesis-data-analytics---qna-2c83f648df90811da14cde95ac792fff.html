Kinesis Data Analytics - QnA

1. Amazon ElasticSearch Service에서 ElasticStack의 Watcher 대체 가능 여부

  • Watcher와 유사한 기능으로 Amazon Elasticsearch에서는 Alerting 을 지원 합니다. Amazon Elasticsearch version 6.2 부터 지원되고 있습니다. (최신 Elasticsearch version은 7.7 입니다)

  • Alerting 기능에 대한 상세한 내용은 Open Distro 에서 확인할 수 있습니다.

💡

https://opendistro.github.io/for-elasticsearch-docs/docs/alerting/

  • Alerting은 Elasticsearch에서 수집된 document의 index가 지정된 조건을 만족하면 notification message를 발생시키는 기능으로 다음의 항목들로 구성됩니다.

    • **Trigger** : Alert를 발생시키는 조건을 정의합니다.

    • **Monitor** : Trigger 여부를 확인하기 위하여 schedule 된 query 작업을 정의합니다.

    • **Action** : Trigger가 발생된 후 수행되는 작업을 정의합니다.

    • **Destination** : Action에서 message를 전달하기 위한 대상을 정의합니다.

  • 지원되는 Destination은 다음과 같습니다.

    • Amazon SNS : E-mail, SMS, AWS Lambda, Amazon SQS 와 Webhook으로 사용될 수 있는 HTTP(S) endpoint 가 있습니다.

    • Slack 및 Amazon Chime 에 채팅 메시지로 전달할 수 있습니다.

    • Custom Webhook을 통해 이벤트로 전달할 수 있습니다.

5. Anomaly Detection에 대해 WebHook으로 notification을 전달하는 방법

  • Amazon SNS에서 HTTP(S) endpoint를 통해 Webhook으로 Topic을 전달할 수 있습니다. 상세한 사용 방법은 다음의 링크에서 확인할 수 있습니다.

💡

https://docs.aws.amazon.com/sns/latest/dg/sns-http-https-endpoint-as-subscriber.html

  • Lambda 함수를 사용하여 Webhook URL로 message를 전송할 수 있으며 기본 구조는 다음과 같습니다. 다음 링크를 통해 구성 및 시험 방법을 확인해 보시기 바랍니다.

💡

https://aws.amazon.com/premiumsupport/knowledge-center/sns-lambda-webhooks-chime-slack-teams/

4. Kinesis Stream에서 Security를 관리하는 방법

  • Data Stream에 대한 접근 권한은 AWS IAM 정책을 통해 사용자 및 사용자 그룹에 개별적으로 권한을 부여하여 관리합니다.

  • Kinesis의 Data Stream은 region 별로 구분되어 관리되며 VPC 기반의 Kinesis를 관리할 수 있는 NACL이나 Security Rule이 존재하지는 않습니다. HTTPS 프로토콜의 SSL endpoint를 통해 데이터 송/수신을 보호합니다.

  • 추가 적인 보안을 위해 Server-side encryption 기능을 지원하고 있습니다. Server-side encryption은 AWS KMS에서 관리되는 키를 사용하여 Data Stream 내에 저장된 데이터를 암호화하는 방식이며 Data Stream의 생산자 및 소비자는 KMS의 키를 사용하여 데이터를 암호화 하게 됩니다. 세부적인 내용은 다음의 링크에서 확인할 수 있습니다.

💡

https://docs.aws.amazon.com/ko_kr/streams/latest/dev/server-side-encryption.html

  • VPC와 Kinesis Data Stream간에 Traffic에 대해 VPC endpoint를 사용하여 비공개로 액세스를 할 수 있습니다. VPC endpoint를 사용하게 되면 Internet gateway나 NAT gateway, VPN 연결의 필요 없이 AWS 네트워크에서 VPC와 Kinesis Data Stream 간에 Private Link를 통해 데이터를 송수신 하여 보안을 더 강화 시킬 수 있습니다. 다음의 링크를 통해 내용을 확인할 수 있습니다.

💡

https://docs.aws.amazon.com/ko_kr/streams/latest/dev/vpc.html

7. DemoSet에서 Analytic Score값에 대한 lambda 함수 내 적용 방식

  • DemoSet으로 전달 된 Lambda 함수의 data 값을 잘 못 사용한 부분이 있어 수정 내용을 전달 드립니다. Anomaly Score는 실수값을 그대로 사용하면 됩니다.

  • Anomaly Score는 Random Cut Forest (RCF) 알고리즘을 통해 계산되는데 이 값은 간단하게 얘기하면 record간의 거리 값으로 생각하면 됩니다. 다음 그림과 같이 Anomaly Score가 가장 높은 10개의 붉은색 사각형이 3개의 cluster 군에서 멀리 분포되어 있는 것을 확인할 수 있습니다. Anomaly Score가 높게 나오는 것은 현재의 record가 이전의 어떤 데이터 군집 분포와는 다른 패턴을 가지는 것을 의미 합니다.

2. Metric 이상 감지에서 주기적인 batch job 실행으로 대량의 load가 발생하는데 실제는 이상 패턴이 아님. 이런 패턴들을 실제 이상 패턴과 구분할 수 있는지에 대한 여부

  • Anomaly Score의 산정 방식으로 판단해 볼 수 있는 부분은 이전 데이터의 군집 분포에 따라 이상 정도가 달라진다는 것입니다. 만일 일주일 단위로 발생하는 batch job으로 인한 load 변화값이 누적되어 간다면 최초에는 이상 패턴으로 감지가 되는 큰 Anomaly Score를 가지겠지만 점차 일정 패턴으로 군집 분포를 만들기 때문에 Anomaly Score 값이 점차 감소하게 될 것입니다. 운영 기간이 길어지면 자연스럽게 규칙적인 패턴으로 인식되어 갈 수 있게 될 것이고 과거의 batch job에서 발생한 load의 패턴가 좀 다른 양상을 보인다면 Anomaly Score 값이 증가하여 이상으로 감지될 수 있습니다.
