Udemy - Amazon SageMaker

Linear Learner

강사: 이제 SageMaker가 제공하는 다양한 내장된 알고리즘들을 파헤쳐 보겠습니다.
이러한 것들에 대해 잘 알고 있어야 하고, 각각의 특징과 독특한 점들을 이해해야 합니다. 집중하시고 메모하세요. 모두 중요합니다.

먼저 linear learner부터 시작하겠습니다. 선형 회귀는 기계 학습의 기본 개념이라고 할 수 있죠.
선형 학습기는 단순히 훈련 데이터에 선형 함수를 맞추는 것 이상의 기능을 제공합니다.
선형 함수로 적절하지 않은 데이터 세트도 있다는 점을 기억해야 합니다.
때로는 곡선이 더 적합할 수 있습니다.

그렇지만 선형 학습기는 회귀와 분류 두 가지 모두 처리할 수 있습니다.
이는 조금 직관적이지 않은데, 보통 회귀는 숫자 문제, 분류는 범주 문제로 생각하지만
선형 학습기는 선형 임계함수를 사용해 이 둘을 모두 처리할 수 있습니다.
즉, 이진 분류와 다중 클래스 분류 문제를 다룰 수 있습니다.

선형 학습기의 입력 형식으로는 RecordIO wrapped protobuf 파일 형식의 Float32 데이터를 선호합니다. 이것이 가장 높은 성능을 제공합니다.
하지만 raw CSV 데이터도 입력으로 사용할 수 있는데, 이 경우 첫 번째 열이 레이블, 나머지가 특징 데이터라고 가정합니다.
입력 모드로는 파일 모드와 파이프 모드 두 가지가 있습니다.
파일 모드는 한 번에 전체 훈련 데이터를 복사하지만,
파이프 모드는 S3에서 필요할 때마다 데이터를 스트리밍합니다.
대용량 데이터의 경우 파이프 모드가 더 효율적입니다.

선형 학습기에 대한 다른 주요 사항들도 있습니다.
훈련 데이터를 정규화해야 하는데, 직접 하거나 알고리즘에 맡길 수 있습니다.
또한 입력 데이터가 잘 섞여 있어야 합니다.

선형 학습기의 내부 구현을 보면,
SGD(Stochastic Gradient Descent)를 사용하고,
Adam, AdaGrad 등 다양한 최적화 알고리즘을 선택할 수 있습니다.
그리고 여러 모델을 병렬로 훈련시키고 검증 단계에서 최적의 모델을 선택합니다.
L1, L2 정규화도 지원합니다.

튜닝 시 중요한 하이퍼파라미터에는
다중 클래스 균형 가중치, 학습률, 배치 크기, L1/L2 정규화 강도 등이 있습니다.
또한 타겟 정밀도와 타겟 재현율을 설정할 수 있는데,
이를 통해 정밀도 또는 재현율을 특정 목표값으로 유지하면서 다른 지표를 최대화할 수 있습니다.

선형 학습기에 적합한 인스턴스 유형은 single 또는 multi CPU/GPU 입니다.
GPU를 여러 개 사용하는 것은 도움이 되지 않습니다.

선형 학습기는 단순한 선형 회귀 이상의 기능을 제공합니다.
예를 들어 MNIST 데이터셋을 사용한 손글씨 인식 분류 문제에도 적용할 수 있습니다.
이는 신경망과 유사한 방식으로 작동하기 때문입니다.

이상으로 선형 학습기에 대해 살펴보았고, 이어서 다른 SageMaker 알고리즘들에 대해 설명하겠습니다.

주요 내용 정리:

  • 선형 학습기는 선형 회귀 이상의 기능 제공

  • 회귀와 분류 모두 지원 (선형 임계함수 활용)

  • 입력 데이터 형식 및 모드(파일/파이프) 이해 필요

  • 데이터 정규화, 섞기 등 전처리 중요

  • 내부적으로 SGD, 다양한 최적화 알고리즘 및 정규화 기법 사용

  • 하이퍼파라미터 튜닝 시 고려사항(균형 가중치, 학습률, 정규화 등)

  • 적절한 CPU/GPU 인스턴스 유형 선택

XGBoost

XGBoost에 대한 설명

  • XGBoost는 최근 가장 주목 받는 알고리즘 중 하나입니다. 부스팅 기반의 앙상블 모델로, 일련의 의사결정 나무 모델들을 연결하여 만듭니다.

  • 새로운 트리를 추가할 때마다 이전 트리의 오류를 보정하는 방식으로 점차 성능을 높여나가며, 이를 위해 gradient descent 기법을 사용합니다.

  • XGBoost는 분류 문제뿐만 아니라 회귀 문제에도 적용할 수 있으며, 회귀 문제에는 회귀 트리를 사용합니다.

  • XGBoost는 오픈소스 프레임워크이며, AWS에서는 이를 SageMaker에 통합하여 제공하고 있습니다.

  • SageMaker에서 XGBoost를 사용하면 CSV, LIBSVM, RecordIO-protobuf, Parquet 등 다양한 입력 데이터 형식을 지원합니다.

XGBoost 하이퍼파라미터 튜닝

  • XGBoost는 많은 하이퍼파라미터를 가지고 있어, 이를 잘 조정하는 것이 중요합니다.

  • 과적합을 방지하기 위해 subsample, eta(학습률) 하이퍼파라미터를 조정할 수 있습니다.

  • gamma, alpha, lambda 등의 하이퍼파라미터로 정규화 효과를 조절할 수 있습니다.

  • eval_metric으로 최적화할 평가 지표를 선택할 수 있고, scale_pos_weight로 불균형 데이터를 다룰 수 있습니다.

  • max_depth는 의사결정 트리의 최대 깊이를 제한하여 과적합을 방지할 수 있습니다.

XGBoost 구현 방식

  • XGBoost는 CPU 기반으로 메모리 중심적으로 동작하므로, M5 인스턴스 등이 적합합니다.

  • 버전 1.2 부터는 GPU 기반 단일 인스턴스 학습도 가능해졌습니다.

  • 더 나아가 1.5 버전부터는 GPU 클러스터 기반 분산 학습도 지원합니다.

요약:

  • XGBoost는 최신 핫한 부스팅 앙상블 기반 알고리즘

  • SageMaker에 통합되어 다양한 입력 데이터 형식을 지원함

  • 많은 하이퍼파라미터가 있어 튜닝이 중요

  • CPU 기반 메모리 중심 동작이 기본이지만, 최근 GPU 기반 단일/분산 학습도 지원

Seq2Seq

다음은 원문 transcript를 한글로 상세히 표현한 내용입니다:

다음으로 우리는 SageMaker의 seq2seq 알고리즘에 대해 이야기할 것입니다. seq2seq는 시퀀스 투 시퀀스를 의미합니다. 이는 RNN(recurrent neural network)에 대해 이야기했을 때 들어보셨을 수 있습니다. 이는 토큰 시퀀스를 입력받아 또 다른 토큰 시퀀스를 출력하는 것입니다.

문장은 단어들의 시퀀스로 볼 수 있으므로, 이를 활용하면 기계 번역과 같은 작업을 할 수 있습니다. 문서의 요약도 이와 유사한 방식으로 처리할 수 있습니다. 음성 인식 또한 오디오 신호를 토큰화하고 텍스트 토큰으로 변환하는 것이라고 할 수 있겠습니다.

내부적으로는 RNN 또는 어텐션 메커니즘을 활용한 CNN이 사용될 수 있습니다. 즉, 순차적 데이터가 RNN에 적합하다고 여겨지지만, CNN도 이를 처리할 수 있습니다.

입력 데이터로는 RecordIO-Protobuf 형식의 토큰화된 정수 데이터를 사용합니다. 대부분의 SageMaker 알고리즘이 부동 소수점 데이터를 사용하는데 반해, 토큰화된 텍스트 데이터는 정수로 표현되기 때문입니다. 따라서 입력 데이터로는 토큰화된 텍스트 파일과 함께 단어-정수 매핑 정보를 담은 어휘 파일이 필요합니다.

기계 번역 모델 학습은 상당한 시간이 소요되므로, SageMaker에서는 사전 학습된 모델을 제공하고 있습니다. 실제 모델 학습을 위해서는 대규모의 병렬 GPU 처리가 필요하지만, 단일 기계에서 다중 GPU를 활용할 수 있습니다.

주요 내용 요약:

  • seq2seq는 시퀀스 입력을 다른 시퀀스로 출력하는 알고리즘

  • 기계 번역, 문서 요약, 음성 인식 등에 활용

  • RNN 또는 어텐션 메커니즘을 활용한 CNN 사용

  • RecordIO-Protobuf 형식의 토큰화된 정수 데이터 입력 필요

  • 대규모 병렬 GPU 처리가 필요하지만 단일 기계에서 다중 GPU 사용 가능

  • SageMaker에서 사전 학습된 모델 제공

DeepAR

DeepAR은 시계열 데이터 예측에 사용됩니다. 즉, 시간에 따른 1차원 데이터 시퀀스를 보고 미래의 시퀀스를 예측하는 것이 주된 용도입니다. 예를 들어 주식 가격 데이터를 보고 미래의 주식 가격을 예측하는 것 등입니다.

기존의 단순한 RNN과 다른 점은 DeepAR은 여러 관련 시계열 데이터를 동시에 학습할 수 있다는 것입니다. 즉, 하나의 시계열이 아닌 상호 의존적인 여러 시계열 데이터를 학습하여 개별 시계열에 대한 더 나은 예측 모델을 만들 수 있습니다.

DeepAR은 주기성과 계절성을 학습할 수 있기 때문에, 단순한 선형 회귀 모델보다 우수한 성능을 보일 수 있습니다. 시간의 흐름에 따른 데이터의 특성을 잘 파악하여 미래 예측에 활용할 수 있습니다.

DeepAR의 입력 데이터 형식은 다양합니다. JSON 라인 포맷, Gzipped 또는 Parquet 포맷 등을 사용할 수 있는데, 각 레코드에는 시작 시간 정보와 시계열 값 목록이 포함되어야 합니다. 또한 선택적으로 카테고리별 특성이나 동적 특성 데이터를 포함할 수 있습니다.

DeepAR의 사용 방법에는 몇 가지 특이점이 있습니다. 먼저 학습, 평가, 추론 시에 전체 시계열 데이터를 사용해야 합니다. 단순히 마지막 일부만 떼어내어 사용하면 안 됩니다. 이는 RNN 기반 모델의 일반적인 특성입니다.

또한 예측 구간을 400 데이터 포인트 이상으로 늘리는 것은 피해야 합니다. 그 이상으로 가면 모델의 성능이 저하될 수 있습니다.

관련된 여러 시계열 데이터를 함께 학습하는 것이 DeepAR의 강점을 극대화할 수 있습니다.

DeepAR의 주요 하이퍼파라미터로는 에폭 수, 배치 크기, 학습률, 셀 수 등 일반적인 신경망 하이퍼파라미터 외에도 컨텍스트 길이가 있습니다.
컨텍스트 길이는 예측을 위해 모델이 참고하는 과거 데이터의 길이를 의미합니다. 이 길이가 계절성 주기보다 작아도 괜찮습니다.
모델이 최소 1년 정도의 과거 데이터를 보고 계절성을 학습할 수 있기 때문입니다.

DeepAR의 최신 인스턴스 유형 가이드라인은 다음과 같습니다. CPU 인스턴스나 GPU 인스턴스 모두 사용 가능하며, 단일 시스템 또는 다중 시스템 환경에 배포할 수 있습니다.
그러나 AWS 공식 권장사항은 먼저 CPU 인스턴스인 ml.c4.2xlarge나 ml.c4.4xlarge를 사용하고, 대규모 모델이나 큰 미니배치 크기가 필요한 경우에만 GPU 인스턴스를 고려하라고 합니다.
추론 단계에서는 CPU 인스턴스만 지원됩니다.
모델 튜닝 단계에서는 더 강력한 인스턴스가 필요할 수 있습니다.

주요 내용 요약:

  • DeepAR은 시계열 데이터 예측에 사용되는 SageMaker 구성요소

  • 여러 관련 시계열을 동시에 학습하여 개별 시계열 예측 성능 향상

  • 계절성, 주기성 등을 학습하여 선형 회귀 모델보다 우수한 성능

  • 다양한 입력 데이터 포맷 지원(JSON, Gzipped, Parquet)

  • 전체 시계열 데이터를 학습/평가/추론에 활용해야 함

  • 400 데이터 포인트 이상의 장기 예측은 피해야 함

  • 관련된 여러 시계열 데이터를 함께 학습하는 것이 중요

  • 일반적인 신경망 하이퍼파라미터 외에 컨텍스트 길이 중요

  • CPU 인스턴스 사용을 권장, 대규모 모델/미니배치 시 GPU 인스턴스 고려

  • 모델 튜닝 단계에서는 더 강력한 인스턴스가 필요할 수 있음

BlazingText

BlazingText 알고리즘 소개

  • 이름과 달리 BlazingText는 매우 제한적인 기능만을 가지고 있습니다.

  • 크게 두 가지 기능을 가지고 있습니다:

    1. 문장 분류(Text Classification): 기존 문장과 레이블을 이용해 문장에 대한 레이블을 예측할 수 있습니다. 검색, 정보 검색 등에 활용할 수 있습니다.

    2. Word2Vec: 단어 간 유사도를 나타내는 벡터 표현을 생성합니다. 기계 번역, 감성 분석 등의 응용 분야에 활용할 수 있습니다.

  • Word2Vec은 문장 전체나 문서 전체에 대해서는 작동하지 않고, 단어 단위로만 동작합니다.

BlazingText의 입력 데이터 형식

  • 문장 분류를 위해서는 문장 앞에 “label” 문자열과 레이블을 붙여서 입력해야 합니다.

  • Word2Vec을 위해서는 문장 단위로 입력해야 합니다.

  • 입력 데이터는 전처리가 필요합니다. 단어 토큰화, 소문자화 등의 전처리가 선행되어야 합니다.

BlazingText의 학습 모드

  • 문장 분류를 위해서는 Continuous Bag of Words(CBOW), Skip-gram, Batch Skip-gram 모드를 선택할 수 있습니다.

  • CBOW는 단어 순서를 무시하고 가방 속 단어들의 관계만을 학습합니다.

  • Skip-gram은 단어 순서를 고려하여 학습합니다.

  • Batch Skip-gram은 단어 순서를 고려하면서 분산 처리도 가능합니다.

BlazingText의 주요 하이퍼파라미터

  • 문장 분류를 위해서는 Epoch, 학습률, n-gram 개수, 벡터 차원 등이 중요합니다.

  • Word2Vec을 위해서는 학습 모드, 학습률, 윈도우 크기, 벡터 차원, 부정적 샘플 개수 등이 중요합니다.

BlazingText의 하드웨어 요구사항

  • Word2Vec의 경우 P3 인스턴스를 사용하는 것이 좋습니다. GPU를 활용할 수 있습니다.

  • Batch Skip-gram은 CPU 기반 분산 처리를 지원합니다.

  • 문장 분류의 경우 C5 인스턴스를 사용하면 되고, 데이터 크기가 크면 P2.Xlarge나 P3.2Xlarge를 사용할 수 있습니다.

주요 내용 요약:

  • BlazingText는 문장 분류와 Word2Vec 기능 제공

  • 문장 분류는 문장 앞에 레이블 정보 필요, Word2Vec은 문장 단위 입력

  • CBOW, Skip-gram, Batch Skip-gram 등 다양한 학습 모드 제공

  • 문장 분류와 Word2Vec에 필요한 주요 하이퍼파라미터 정리

  • Word2Vec은 GPU 기반 P3 인스턴스 추천, Batch Skip-gram은 CPU 기반 분산 처리 지원

Object2Vec

Object2Vec 소개

  • Word2Vec이 개별 단어 간의 관계를 찾아내는 것과 달리, Object2Vec은 보다 일반적인 객체 간의 관계를 찾아내는 기능을 제공합니다.

  • Word2Vec이 단어 수준에서 동작한다면, Object2Vec은 문서 전체나 다른 형태의 객체에도 적용할 수 있습니다.

  • Object2Vec은 고차원의 객체 속성과 특징을 저차원의 밀집 벡터 표현으로 변환합니다.

  • 이를 통해 객체 간의 유사도를 계산하고, 군집화하거나 시각화할 수 있습니다.

  • 또한 추천 시스템에서 유사 항목이나 유사 사용자를 찾는데 활용할 수 있습니다.

Object2Vec의 입력 데이터

  • Object2Vec은 정수로 토큰화된 데이터를 입력으로 받습니다.

  • 입력 데이터는 객체 쌍(pairs)의 형태로 구성됩니다.

    • 예: 문장 쌍, 레이블-문장 쌍, 고객-상품 쌍, 사용자-아이템 쌍 등

  • 이러한 객체 쌍을 통해 객체 간의 관계를 학습합니다.

Object2Vec의 모델 구조

  • Object2Vec 모델은 2개의 입력 채널을 병렬로 가집니다.

  • 각 입력 채널은 자신만의 인코더 네트워크를 가집니다.

    • 평균 풀링 임베딩, CNN, 양방향 LSTM 등의 인코더를 선택할 수 있습니다.

  • 두 입력 채널의 출력은 비교기(Comparator)에 입력되어 최종 출력을 생성합니다.

  • 비교기 뒤에는 완전 연결 신경망이 추가됩니다.

Object2Vec의 하이퍼파라미터

  • 일반적인 딥러닝 모델 최적화에 필요한 하이퍼파라미터들이 중요합니다.

    • Dropout, Early Stopping, Epoch 수, 학습률, 배치 크기, 레이어 수, 활성화 함수, 최적화 알고리즘, 가중치 감쇠 등

  • 각 입력 채널의 인코더 유형(평균 풀링, CNN, LSTM 등)도 중요한 하이퍼파라미터입니다.

Object2Vec의 하드웨어 요구사항

  • 단일 머신에서만 학습이 가능합니다.

  • CPU 인스턴스(ml.m5.2xlarge)나 GPU 인스턴스(p2.xlarge)를 사용할 수 있습니다.

  • 대규모 작업의 경우 CPU는 m5.4xlarge, m5.12xlarge, GPU는 p2, p3, g4dn, g5 인스턴스를 사용할 수 있습니다.

  • 추론 시에는 ml.p3.2xlarge 인스턴스 사용을 권장합니다.

  • INFERENCE_PREFERRED_MODE 환경 변수를 설정하여 인코더 임베딩 최적화를 할 수 있습니다.

주요 내용 요약:

  • Object2Vec은 단어가 아닌 일반 객체 간의 관계를 학습하는 기술

  • 입력 데이터는 객체 쌍(pairs)의 형태로 구성

  • 2개의 입력 채널, 각 채널의 인코더 네트워크, 비교기, 완전 연결 신경망으로 구성

  • 일반적인 딥러닝 하이퍼파라미터 튜닝이 필요

  • 단일 머신(CPU 또는 GPU)에서 학습 가능, 대규모 작업 시 고성능 인스턴스 사용 권장

  • 추론 시 ml.p3.2xlarge 인스턴스 및 INFERENCE_PREFERRED_MODE 환경 변수 활용 권장

Obejct Detection

객체 탐지의 개념은 이미지 안에 있는 모든 객체를 찾아내고 그 위치를 경계상자로 표시하는 것입니다. 예를 들어 이 이미지에서는 와인 병, 와인 잔, 의자, 노트북, 그릇 등이 탐지되어 표시되어 있습니다.

이렇게 딥 신경망 모델을 사용하여 이미지 속 객체를 탐지하고 분류하며, 각 객체에 대한 신뢰도 점수도 제공합니다.

이러한 객체 탐지 기능은 SageMaker에서 두 가지 알고리즘으로 제공됩니다. 하나는 MXNet 기반의 객체 탐지이고, 다른 하나는 TensorFlow 기반의 객체 탐지입니다.

MXNet 객체 탐지는 Single Shot multiBox Decoder(SSD) 알고리즘을 사용하며, VGG-16 또는 ResNet-50과 같은 CNN 모델을 백본(backbone)으로 사용합니다. 전이학습 및 점진적 학습을 지원합니다. 입력 데이터로는 RecordIO 형식 또는 JPG/PNG 이미지와 함께 JSON 형식의 라벨 데이터를 사용합니다.

TensorFlow 객체 탐지는 TensorFlow Model Garden에 포함된 다양한 모델(ResNet, EfficientNet, MobileNet 등)을 선택할 수 있습니다. 사용하는 모델에 따라 입력 데이터 형식과 하이퍼파라미터가 달라집니다.

객체 탐지 모델 학습 시 중요한 하이퍼파라미터는 배치 크기, 학습률, 최적화 알고리즘 등입니다. 학습을 위해서는 GPU 인스턴스가 필요하며, p2.xlarge, p3.2xlarge 등의 인스턴스를 추천합니다.

추론 단계에서는 CPU나 GPU 인스턴스를 사용할 수 있으며, M5 인스턴스 또는 P2, P3, G4dn, G5 인스턴스 등을 활용할 수 있습니다.

주요 내용 요약:

  • SageMaker의 객체 탐지 기능

    • MXNet 기반과 TensorFlow 기반의 두 가지 알고리즘 제공

    • 이미지 속 객체 탐지 및 분류, 경계상자 표시

    • 각 객체에 대한 신뢰도 점수 제공

  • MXNet 객체 탐지

    • SSD 알고리즘 사용, VGG-16 또는 ResNet-50 모델 활용

    • RecordIO 또는 이미지 파일 + JSON 라벨 데이터 입력

  • TensorFlow 객체 탐지

    • TensorFlow Model Garden의 다양한 모델 선택 가능

    • 사용 모델에 따라 입력 데이터 형식과 하이퍼파라미터 다름

  • 객체 탐지 모델 학습을 위해 GPU 인스턴스 필요

    • p2.xlarge, p3.2xlarge 등 추천

  • 추론 단계에서는 CPU/GPU 인스턴스 모두 사용 가능

Image Classification

객체 탐지 알고리즘과 밀접한 관계가 있는 이미지 분류 알고리즘에 대해 설명합니다. 객체 탐지가 이미지 내 물체의 위치를 알려주는 것과 달리, 이미지 분류는 이미지 내 어떤 물체가 존재하는지만 알려줍니다. 예를 들어 고양이 사진을 보여주면 그냥 “고양이다”라고 말해줄 뿐 고양이의 위치는 알려주지 않습니다.

MXNet과 TensorFlow 버전의 이미지 분류 알고리즘이 각각 다르게 다루어집니다. MXNet은 무작위 초깃값으로 전체 네트워크를 처음부터 훈련하는 full training 모드와 사전 학습된 가중치로 초기화하고 상위 계층만 새로 훈련하는 transfer learning 모드가 있습니다. TensorFlow는 사용하는 구체적인 모델(MobileNet, Inception, ResNet, EfficientNet 등)에 따라 다른 특성을 가집니다.

이미지 크기, 배치 크기, 학습률, 최적화기 등의 하이퍼파라미터 조정이 중요하며, GPU 인스턴스를 사용하는 것이 학습 성능 향상에 도움이 됩니다. 추론 시에는 CPU 인스턴스도 활용 가능합니다.

주요 내용 정리:

  • 객체 탐지와 이미지 분류의 차이: 위치 vs. 존재 여부 정보 제공

  • MXNet과 TensorFlow의 이미지 분류 알고리즘 차이

  • MXNet의 full training과 transfer learning 모드

  • TensorFlow의 다양한 사전 학습 모델 활용

  • 이미지 크기, 배치 크기, 학습률 등 하이퍼파라미터 중요성

  • GPU 인스턴스 활용으로 학습 성능 향상

  • CPU 인스턴스로도 추론 가능

Semantic Segmentation

컴퓨터 비전 관련 내용을 계속 다루면서, 이제 의미론적 분할(semantic segmentation)에 대해 이야기해 보겠습니다. 여러분이 기억하시는 바와 같이, 이미지 분류는 이미지 내 객체가 무엇인지만 탐지할 뿐이었고, 객체 탐지는 그 객체의 경계 상자(bounding box)까지 알려줍니다. 의미론적 분할은 이를 한 단계 더 발전시켜, 픽셀 단위의 객체 분류를 수행합니다.

결과적으로 마스크 형태의 출력을 얻게 되는데, 이 마스크는 이미지 내 각 픽셀이 어떤 객체에 속하는지 보여줍니다. 예를 들면, 이 이미지에서는 플러시 동물, 장미, 양동이 등이 어느 픽셀에 해당하는지 알려줍니다. 이는 자율 주행 자동차 등에서 매우 중요한데, 상세한 객체 위치 정보가 필요하기 때문입니다.

의미론적 분할은 의료 영상 진단, 로봇 센싱 등 다양한 분야에 활용될 수 있습니다. 학습 시에는 JPG나 PNG 파일과 라벨링된 annotation 데이터가 필요하며, 훈련 데이터와 검증 데이터가 모두 준비되어야 합니다. 또한 라벨 매핑 정보도 필요합니다. 추론 시에는 JPG 이미지를 입력으로 받아 픽셀 단위 분류 결과를 출력합니다.

내부적으로는 Gluon, Gluon CV, Apache MXNet 등 다양한 기술이 활용되며, 3가지 알고리즘(fully convolutional network, pyramid scene parsing, DeepLabV3)을 선택할 수 있습니다. 백본 아키텍처로는 ResNet50 또는 ResNet101을 활용할 수 있습니다.

의미론적 분할 모델 학습 시 고려해야 할 하이퍼파라미터로는 epochs, learning rate, batch size, optimizer 등이 있습니다. 또한 선택한 알고리즘과 백본 아키텍처도 중요한 튜닝 대상입니다.

학습에는 GPU 인스턴스(P2, P3, G4dn, G5)만 지원되며, 단일 머신에서만 수행할 수 있습니다. 추론에는 CPU 인스턴스(C5, M5)나 GPU 인스턴스(P3, G4dn)를 사용할 수 있습니다.

주요 내용 정리:

  • 의미론적 분할: 이미지 내 각 픽셀을 객체별로 분류하는 기술

  • 자율 주행, 의료 영상 등 다양한 분야에 활용

  • 학습 시 JPG/PNG 파일과 annotation 데이터 필요, 3가지 알고리즘 선택 가능

  • 하이퍼파라미터 튜닝 시 epochs, learning rate, 알고리즘, 백본 아키텍처 등 고려

  • GPU 인스턴스로만 학습 가능, 추론 시 CPU/GPU 인스턴스 사용 가능

Random Cut Forest

다음으로는 Amazon의 비정상 탐지 알고리즘인 Random Cut Forest에 대해 다루겠습니다. 이 알고리즘은 지도학습이 아닌 비지도 학습 방식으로 동작합니다. 즉, 데이터 시계열을 분석하여 정상에서 벗어나는 이상치를 찾아내는 것이 목적입니다.

데이터가 정상 흐름에서 벗어나는 경우, 의사결정 트리에 새로운 분기가 많이 생길 것이므로, 이를 이용해 이상치를 탐지하는 것이 이 알고리즘의 핵심 원리입니다. 데이터를 무작위로 샘플링하여 다수의 의사결정 트리를 만들고, 각 데이터 포인트가 트리에 추가될 때의 복잡도 변화를 측정하여 이상치 점수를 부여합니다.

입력 데이터는 CSV 또는 RecordIO-protobuf 형식을 사용할 수 있으며, 학습용 데이터 외에 정답이 있는 테스트 데이터를 별도로 제공할 수 있습니다. 또한 이 알고리즘은 배치 처리뿐만 아니라 스트리밍 데이터에도 적용할 수 있습니다.

주요 하이퍼파라미터로는 의사결정 트리의 개수와 각 트리의 샘플 수가 있습니다. 정상 대 이상치 데이터의 비율을 고려하여 적절한 샘플 수를 설정하면 더 효과적인 탐지가 가능합니다. GPU는 사용하지 않고 CPU만으로 학습과 추론을 수행합니다.

주요 내용 요약 (Bullet point):

  • Amazon의 비정상 탐지 알고리즘 Random Cut Forest

  • 비지도 학습 방식으로 동작, 데이터 시계열에서 정상에서 벗어나는 이상치 탐지

  • 의사결정 트리의 복잡도 변화를 이용해 이상치 점수 산출

  • CSV 또는 RecordIO-protobuf 형식 지원, 테스트 데이터 제공 가능

  • 배치 처리 및 스트리밍 데이터에 적용 가능

  • 트리 개수, 샘플 수 등의 하이퍼파라미터 조정이 중요

  • GPU 사용 없이 CPU로 학습 및 추론 수행

Neural Topic Model

이번에는 토픽 모델링(topic modeling)에 대해 살펴보겠습니다. 토픽 모델링은 문서의 주제를 높은 수준에서 파악하는 비지도 학습 방법입니다. 문서들을 입력하면 알고리즘이 자동으로 문서들을 주제별로 그룹화해 줍니다.

SageMaker가 제공하는 토픽 모델링 알고리즘 중 하나는 신경망 토픽 모델(neural topic model)입니다. 이 알고리즘은 문서들을 의미 있는 주제로 자동 분류해줍니다. 예를 들어 “자전거”, “자동차”, “기차”, “주행거리”, “속도” 등의 단어가 함께 나오는 문서들은 “교통수단” 이라는 주제로 그룹화될 수 있습니다.

이 알고리즘은 어떤 주제인지 직접 명명하지는 않고, 단어들의 상관관계를 바탕으로 주제를 자동 생성합니다. 사용자가 직접 원하는 주제 수를 지정하면 그에 맞게 문서들이 주제별로 분류됩니다.

신경망 토픽 모델의 학습 과정은 비지도 학습 방식이므로 “학습”이라는 용어 대신 “학습 패스(training pass)“라고 표현합니다. 문서들을 토큰화하여 정수로 변환하고 어휘 파일을 추가 입력 데이터로 제공해야 합니다.

신경망 토픽 모델의 주요 하이퍼파라미터는 생성할 토픽 수로, 이 값이 클수록 더 세부적인 주제로 문서들이 분류됩니다. 또한 배치 크기, 학습률과 같은 신경망 모델의 일반적인 하이퍼파라미터들도 조정이 필요합니다.

학습에는 GPU를 활용하는 것이 좋지만, 추론에는 CPU로도 충분할 수 있습니다.

주요 내용 요약:

  • 토픽 모델링은 문서를 주제별로 자동 분류하는 비지도 학습 기법

  • SageMaker의 신경망 토픽 모델 알고리즘은 문서 내 단어들의 상관관계를 이용해 주제를 생성

  • 주제 수, 배치 크기, 학습률 등의 하이퍼파라미터 조정이 필요

  • 학습 시에는 GPU, 추론 시에는 CPU 사용이 효과적

Latent Dirichlet Allocation (LDA)

아마존 SageMaker의 다른 토픽 모델링 알고리즘인 LDA(Latent Dirichlet Allocation)에 대한 내용을 상세히 정리하겠습니다.

LDA는 신경망 기반이 아닌 또 다른 토픽 모델링 알고리즘입니다. 이것 역시 비지도 학습 방식으로 작동합니다. 사용 방식은 신경망 기반 토픽 모델과 비슷합니다.

토픽 자체는 레이블이 없는 상태로, 문서들이 공통적으로 가지고 있는 단어들을 기반으로 문서들을 그룹화한 것입니다. 이 알고리즘은 단어 데이터 외에도 고객의 구매 내역이나 음악 분석 등 다양한 분야에 활용할 수 있습니다.

입력 데이터는 recordIO-protobuf 또는 CSV 형식이며, 먼저 토큰화 과정을 거쳐야 합니다. 각 문서는 전체 어휘에 대한 단어 출현 횟수 리스트로 표현됩니다.

LDA 모델 학습 시에는 num_topics 매개변수로 원하는 토픽 수를 지정할 수 있습니다. 이 값을 조정하여 토픽의 세부 수준을 조절할 수 있습니다. 또한 Alpha0 매개변수 튜닝을 통해 토픽 분포의 희박성을 조절할 수 있습니다.

LDA는 CPU 기반으로 동작하므로 GPU 인스턴스가 필요하지 않아 비용 효율적일 수 있습니다. 다만 병렬 처리가 지원되지 않아 단일 CPU 노드에서 학습을 진행해야 합니다.

주요 내용 정리:

  • LDA(Latent Dirichlet Allocation)는 SageMaker의 또 다른 토픽 모델링 알고리즘

  • 신경망 기반이 아닌 CPU 기반 알고리즘으로, 비지도 학습 방식 사용

  • 문서의 공통 단어를 기반으로 문서를 그룹화하여 토픽을 도출

  • 단어 데이터 외에도 다양한 데이터에 활용 가능

  • num_topics 매개변수로 토픽 수를, Alpha0 매개변수로 토픽 분포의 희박성을 조절

  • CPU 기반으로 GPU 인스턴스가 필요하지 않지만 병렬 처리 지원 X

K-Nearest-Neighbors (KNN)

KNN은 아마도 세계에서 가장 간단한 기계 학습 알고리즘입니다. KNN은 데이터 포인트를 특징 공간에 플롯하고, 주어진 새로운 포인트에 대해 가장 가까운 K개의 이웃을 찾아 그 이웃들의 가장 일반적인 라벨을 반환합니다. 이는 분류에 사용될 수 있습니다. 또한 회귀에도 사용될 수 있는데, 이 경우 가장 가까운 K개 이웃의 평균값을 반환합니다.

SageMaker는 KNN을 더욱 발전시켰습니다. 먼저 데이터가 너무 많은 경우 샘플링을 수행합니다. 그 다음 차원 축소를 수행하여 계산을 효율적으로 합니다. 이 과정에서 정확도가 약간 떨어질 수 있습니다. SageMaker는 “sign” 또는 “fjlt” 옵션을 사용하여 차원 축소를 수행합니다.

그 다음 SageMaker는 이웃을 빠르게 찾을 수 있도록 인덱스를 생성합니다. 그리고 모델을 직렬화하여 사용자가 원하는 K값을 입력하면 해당 이웃들의 평균값이나 가장 일반적인 라벨을 반환합니다.

KNN에서 가장 중요한 하이퍼파라미터는 K값입니다. K값을 어떻게 설정하느냐에 따라 성능이 달라지므로 실험을 통해 최적의 K값을 찾아야 합니다. 또한 샘플 크기도 중요한 하이퍼파라미터입니다.

SageMaker는 KNN을 CPU 또는 GPU 인스턴스에서 학습할 수 있게 지원합니다. 추론 시에는 CPU가 지연 시간이 낮고 GPU가 처리량이 높습니다.

주요 내용 정리:

  • KNN은 가장 단순한 기계 학습 알고리즘 중 하나

  • SageMaker는 KNN을 더욱 발전시켰음

    • 데이터 샘플링 및 차원 축소 기능 제공

    • 빠른 이웃 탐색을 위한 인덱스 생성

    • 모델 직렬화로 간편한 사용 지원

  • K값과 샘플 크기가 KNN 성능의 핵심 하이퍼파라미터

  • CPU 또는 GPU 인스턴스를 선택할 수 있음

    • CPU는 지연 시간 낮고, GPU는 처리량 높음

  • Sign & FJIT option

    SageMaker에서 KNN 알고리즘을 사용할 때 데이터의 차원 축소를 위해 “sign” 또는 “fjlt” 옵션을 사용한다고 설명되어 있습니다.

    “sign” 옵션은 Sign Random Projection이라는 기법을 사용하여 데이터의 차원을 축소합니다. 이는 원래 데이터의 특성을 유지하면서 차원을 낮출 수 있는 방법입니다.

    “fjlt” 옵션은 Fast Johnson-Lindenstrauss Transform이라는 기법을 사용하여 차원 축소를 수행합니다. 이 방법 역시 원래 데이터의 구조를 최대한 보존하면서 차원을 낮출 수 있습니다.

    이렇게 차원 축소를 수행하면 KNN 알고리즘의 계산 효율이 높아져 대용량 데이터에도 효과적으로 적용할 수 있습니다. 다만 이 과정에서 약간의 정확도 저하가 발생할 수 있다고 설명되어 있습니다.

K-Means Clustering

K-means는 또 다른 널리 사용되는 기계 학습 알고리즘으로, SageMaker에서도 이를 제공하고 있습니다. SageMaker의 K-means는 더욱 발전된 형태를 가지고 있습니다.

K-means는 무감독 학습 기반 클러스터링 기법입니다. KNN(K-Nearest Neighbors)과 달리 KNN은 레이블이 있는 학습 데이터를 통해 학습하는 지도 학습 기법인 반면, K-means는 레이블이 없는 데이터를 입력받아 자동으로 클러스터를 형성하는 무감독 학습 기법입니다.

K-means는 데이터를 K개의 그룹으로 나누며, 각 그룹의 구성원들이 서로 최대한 유사하도록 최적화됩니다. 이를 위해 유사도를 측정하는 기준을 정의해야 하는데, 일반적으로 정규화된 특징 공간에서의 유클리디안 거리를 사용합니다.

SageMaker의 K-means는 대규모 데이터에 대한 고성능 클러스터링을 제공합니다. 대규모 데이터에 대한 클러스터링은 많은 데이터 포인트를 처리해야 하므로 도전적인 과제입니다. SageMaker는 이를 효과적으로 해결하기 위해 다음과 같은 방법을 제공합니다:

  • 훈련 시 ShardedByS3Key 옵션을 사용하여 S3 키 단위로 데이터를 분할하여 병렬 처리

  • 테스트 시 FullyReplicated 옵션을 사용하여 전체 데이터를 각 노드에 복제

  • RecordIO-protobuf 또는 CSV 형식의 데이터 입력 지원

  • 파일 모드와 파이프 모드 지원

SageMaker의 K-means 알고리즘은 다음과 같이 작동합니다:

  1. 모든 관측치를 특징의 개수 n 차원 공간에 매핑합니다.

  2. k개의 초기 클러스터 중심을 설정합니다. SageMaker는 k-means++ 알고리즘을 사용하여 이 초기 중심점을 최대한 멀리 배치합니다.

  3. 관측치를 가장 가까운 클러스터 중심에 할당합니다.

  4. 각 클러스터의 새로운 중심점을 계산합니다.

  5. 3-4단계를 반복하여 클러스터 중심점을 최적화합니다.

  6. 처음에는 k*x개의 클러스터 중심을 사용하고, 점진적으로 k개의 최종 클러스터로 수렴합니다.

주요 하이퍼파라미터는 다음과 같습니다:

  • k: 최종 클러스터 수

  • mini_batch_size: 미니 배치 크기

  • extra_center_factor: x, 초기 클러스터 중심 개수 조절

  • init_method: 초기 중심 초기화 방식 (랜덤 또는 k-means++)

SageMaker는 CPU 인스턴스를 훈련에 권장하지만, GPU 인스턴스(ml.g4dn.xlarge)를 사용할 수도 있습니다.

요약:

  • K-means는 무감독 학습 기반 클러스터링 기법

  • SageMaker는 대규모 데이터에 최적화된 K-means 기능 제공

  • 데이터 분할, 초기 중심 설정 등의 개선 기능 포함

  • 주요 하이퍼파라미터: k, mini_batch_size, extra_center_factor, init_method

  • CPU 인스턴스 권장, GPU 인스턴스(ml.g4dn.xlarge) 사용 가능

Principal Component Analysit (PCA)

PCA(Principal Component Analysis)는 차원 축소 기법입니다. 높은 차원의 데이터를 더 낮은 차원으로 줄여서 작업하기 쉽게 만듭니다. 예를 들어 여러 가지 특성(feature)을 가진 데이터를 2차원 공간에 투영하는 것입니다. 이때 주요한 정보의 손실을 최소화하려고 합니다.

PCA는 데이터의 공분산 행렬을 만들고, 특이값 분해(SVD) 알고리즘을 사용하여 주성분(principal component)을 찾아냅니다. 첫 번째 주성분은 데이터의 가장 큰 분산을 설명하고, 다음 주성분들은 그 다음으로 큰 분산을 설명합니다.

SageMaker에서는 PCA 모델을 두 가지 모드로 실행할 수 있습니다. 일반 모드는 희소 데이터나 관측치/특성이 중간 규모인 경우에 적합하고, 무작위 모드는 데이터 규모가 큰 경우에 근사 알고리즘을 사용하여 더 잘 확장됩니다. 또한 데이터 평균 제거 여부를 결정하는 하이퍼파라미터도 있습니다.

PCA의 주요 특징은 다음과 같습니다:

  • 높은 차원의 데이터를 낮은 차원으로 축소

  • 데이터의 주요 변동성을 잘 설명하는 새로운 축(주성분)을 찾아냄

  • 비지도 학습 기법이므로 레이블 없이 사용 가능

  • 입력 데이터로 record-IO, Protobuf 또는 CSV 파일 사용 가능

Factorization Machines

다음으로 우리가 살펴볼 알고리즘은 요인분해 머신(Factorization Machines)입니다.

요인분해 머신은 어떤 것일까요? 요인분해 머신은 희소 데이터(sparse data)에 대한 분류 또는 회귀 작업에 특화된 알고리즘입니다.

여기서 말하는 희소 데이터란 무엇일까요? 추천 시스템이 대표적인 예라고 할 수 있습니다. 추천 시스템에서는 사용자가 거대한 제품 목록 중 극히 일부만 상호작용하게 됩니다. 즉, 사용자가 특정 제품을 좋아했다/싫어했다는 식의 정보가 극히 일부만 존재하는 것이죠. 이처럼 대부분의 데이터가 비어있는 상태를 희소 데이터라고 합니다.

클릭 예측(click prediction)도 이와 유사한 예라고 할 수 있습니다. 개별 사용자나 세션에서 인터넷의 거대한 페이지 목록 중 일부만 클릭하게 됩니다. 하지만 우리가 알고 있는 일부 페이지 정보를 바탕으로 다음에 클릭할 페이지를 예측해야 합니다.

요인분해 머신은 이처럼 희소 데이터에 대한 분류 및 회귀 작업을 수행하는 지도 학습 방식의 알고리즘입니다. 예를 들어 사용자가 특정 제품을 좋아할지 여부를 예측하거나, 특정 제품에 대한 평점을 예측할 수 있습니다.

요인분해 머신은 쌍(pair-wise) 상호작용만을 다룹니다. 즉, 사용자와 아이템 간의 2차원 행렬 분해를 수행하게 됩니다.

요인분해 머신의 학습 데이터 형식은 RecordIO-protobuf 형식의 Float32 입니다. CSV 형식은 적합하지 않은데, 대부분의 셀이 비어있는 희소 데이터 특성상 CSV로는 너무 복잡해지기 때문입니다.

요인분해 머신의 작동 원리를 살펴보면, 사용자-아이템 행렬을 모델링하고 이 행렬의 요인(factor)을 찾아내 사용자가 경험하지 않은 아이템에 대한 평점을 예측하는 것입니다. 이는 주로 추천 시스템 분야에서 활용됩니다.

요인분해 머신의 중요한 하이퍼파라미터로는 편향 요인(bias factor)과 선형 항(linear term)의 초기화 방식이 있습니다. 균등 분포, 정규 분포, 상수 등 다양한 초기화 방법이 존재합니다.

요인분해 머신은 CPU나 GPU를 활용할 수 있지만, 일반적으로 CPU를 사용하는 것이 권장됩니다. GPU는 희소 데이터보다는 밀집 데이터에 효과적이기 때문입니다.

요약하면, 요인분해 머신은 희소 데이터에 대한 분류 및 회귀 작업에 특화된 알고리즘으로, 주로 추천 시스템 분야에서 활용됩니다.

주요 내용 요약:

  • 요인분해 머신: 희소 데이터에 특화된 분류/회귀 알고리즘

  • 주로 추천 시스템 등에서 활용

  • 사용자-아이템 행렬의 요인(factor)을 찾아 예측 수행

  • 주요 하이퍼파라미터: 편향 요인/선형 항 초기화 방식

  • CPU 사용을 권장, GPU는 밀집 데이터에 효과적

IP Insights

  • 엔티티와 IP 주소는 해싱 및 임베딩 처리됩니다.

  • 적절한 해시 크기가 중요한 하이퍼파라미터입니다.

  • 학습 중 랜덤하게 엔티티와 IP 주소를 쌍으로 생성하여 이상 샘플을 만듭니다.

  • 주요 하이퍼파라미터: 엔티티 벡터 수, 해시 크기, 임베딩 벡터 크기, 학습률, 배치 크기, 에폭 수 등

  • p3.2xlarge 이상의 GPU 인스턴스를 사용하는 것이 좋습니다.

  • CPU 인스턴스 크기는 선택한 하이퍼파라미터에 따라 달라집니다.

주요 요약 사항

  • IP Insights는 IP 주소의 이상 행동을 신경망 기반으로 탐지하는 기능

  • 엔티티와 IP 주소의 잠재 벡터 표현을 학습하여 이상 행동을 식별

  • 해싱, 임베딩, 랜덤 샘플링 등의 기법을 사용

  • CPU 또는 GPU 인스턴스로 실행 가능하며, GPU가 더 효과적

Reinforcement Learning

SageMaker에서의 강화학습 소개

강화학습은 일반적인 SageMaker의 다른 알고리즘과는 다른 접근법을 가지고 있습니다. 모델을 학습하고 배포하여 분류나 회귀 작업을 수행하는 것이 아니라, 어떤 가상의 환경을 탐험하면서 그 환경 내에서 최적의 방식으로 움직이는 법을 학습하는 것입니다.

예를 들어 AI 기반의 팩맨 게임을 생각해볼 수 있습니다. 팩맨이라는 에이전트가 게임 보드 환경을 탐험하면서 각 상태(예: 벽, 파워필, 유령 등)에 따른 보상을 학습합니다. 왼쪽으로 가면 벽에 부딪혀 큰 페널티를, 오른쪽으로 가면 파워필을 먹어 보상을 받는 등의 경험을 통해 최적의 행동을 학습하게 됩니다.

이렇게 학습된 Q값(상태-행동 쌍의 가치)을 바탕으로 새로운 환경에서도 빠르게 최적의 행동을 선택할 수 있습니다. 이는 공급망 관리, HVAC 시스템, 산업용 로봇, 대화형 시스템, 자율 주행차 등의 실제 문제에도 적용될 수 있습니다.

Q-learning이라는 강화학습의 구체적인 구현 방식에 대해 살펴보면 다음과 같습니다:

  • 상태(s): 에이전트(팩맨)의 주변 상황

  • 행동(a): 에이전트가 취할 수 있는 동작(상, 하, 좌, 우)

  • Q값(Q(s,a)): 각 상태-행동 쌍의 가치

초기에는 모든 Q값을 0으로 시작하고, 에이전트가 환경을 탐험하면서 보상과 페널티에 따라 Q값을 업데이트합니다. 이때 완전히 탐욕적으로 최고의 Q값 행동만 선택하면 효율적이지 않으므로, 임의의 확률로 무작위 행동을 선택하는 epsilon-greedy 방식을 사용합니다.

또한 현재 상태의 Q값에 미래 상태의 보상을 일정 비율로 반영하는 방식으로 Q값을 업데이트하면 좀 더 지혜로운 선택을 할 수 있습니다.

이러한 개념은 수학적으로는 마르코프 의사결정 과정(Markov Decision Process)이나 이산 시간 확률적 최적제어 과정(Discrete Time Stochastic Control Process)으로 표현될 수 있습니다.

SageMaker에서는 TensorFlow, MXNet 등의 딥러닝 프레임워크를 활용한 강화학습을 제공하고 있으며, 분산 처리 기능도 지원합니다. 하이퍼파라미터 튜닝을 통해 강화학습 모델을 최적화할 수 있으며, GPU 인스턴스 사용이 도움이 될 수 있습니다.

요약:

  • 강화학습은 환경을 탐험하며 최적의 행동을 학습하는 방식

  • Q-learning은 상태-행동 쌍의 보상을 학습하는 강화학습 알고리즘

  • 임의 탐험을 통해 효과적인 학습이 가능

  • 수학적으로 마르코프 의사결정 과정 등으로 표현 가능

  • SageMaker에서 분산 처리, 하이퍼파라미터 튜닝 등을 지원

Automatic Model Tuning

이제 SageMaker의 자동 모델 튜닝이라는 매우 흥미로운 기능에 대해 이야기해 보겠습니다.

하이퍼파라미터 튜닝은 기계 학습 분야에서 매우 큰 문제입니다. 우리가 지금까지 다뤄온 다양한 알고리즘들은 많은 하이퍼파라미터를 가지고 있습니다. 이런 파라미터들의 최적값을 찾는 것은 쉽지 않습니다.

우리는 학습률, 배치 크기, 모델 깊이 등 일부 하이퍼파라미터의 영향에 대해 알고 있습니다. 예를 들어 잘못된 학습률을 사용하면 지역 최소값에 빠질 수 있고, 과도한 모델 깊이는 과적합을 일으킬 수 있습니다. 하지만 이런 파라미터들의 최적값을 찾는 것은 여전히 어려운 문제입니다.

결국 우리가 할 수 있는 최선은 다양한 값들을 시험해 보고, 그 중에서 가장 좋은 성능을 보이는 조합을 찾는 것입니다. 하지만 하이퍼파라미터가 많아지면 이런 접근법은 기하급수적으로 복잡해집니다. 예를 들어 학습률 10개, 배치 크기 10개, 모델 깊이 10개를 시험한다면 총 1,000번의 모델 학습이 필요합니다.

이 문제를 해결하기 위해 SageMaker의 자동 모델 튜닝 기능이 도입되었습니다. 이 기능을 사용하면 튜닝할 하이퍼파라미터와 그 범위를 지정하면, SageMaker가 자동으로 다양한 조합을 시도하고 최적의 하이퍼파라미터를 찾아줍니다.

이 과정에서 SageMaker는 학습을 거듭하면서 어떤 방향으로 나아가는 것이 좋은지 학습합니다. 따라서 모든 조합을 다 시도하지 않고도 효율적으로 최적의 하이퍼파라미터를 찾을 수 있습니다.

이 기능을 사용할 때는 몇 가지 best practice를 따라야 합니다:

  • 튜닝할 하이퍼파라미터 수를 너무 많이 늘리지 말 것

  • 가능한 작은 범위의 값들을 사용할 것

  • 로그 스케일을 사용할 것

  • 너무 많은 training 작업을 동시에 실행하지 말 것

  • 다중 인스턴스에서 실행되는 training 작업의 objective metric을 정확히 보고할 것

이런 접근법을 따르면 SageMaker의 자동 모델 튜닝 기능을 효과적으로 활용할 수 있습니다.

<요약>

  • 하이퍼파라미터 튜닝은 기계 학습에서 큰 문제이며, SageMaker의 자동 모델 튜닝 기능이 이를 해결할 수 있음

  • 자동 모델 튜닝 기능은 튜닝할 하이퍼파라미터와 범위를 지정하면 최적의 하이퍼파라미터를 자동으로 찾아줌

  • 이 기능은 학습을 통해 점진적으로 최적 하이퍼파라미터를 찾아가므로 효율적임

  • 사용 시 하이퍼파라미터 수, 범위, 스케일, 병렬 작업 수 등을 적절히 조절해야 함

Apache Spark with SageMaker

SageMaker와 Apache Spark의 연계

  • Apache Spark는 데이터 전처리와 강력한 MLlib 라이브러리를 제공하는 매우 인기 있는 프레임워크임

  • Spark는 SageMaker가 제공하는 것과 유사한 기능을 많이 제공하지만, 데이터 전처리 능력이 더 뛰어남

  • Spark에서는 데이터 프레임 형태로 데이터를 로드하고, 클러스터에 분산 처리하여 데이터를 조작할 수 있음

  • AWS에서는 SageMaker-Spark 라이브러리를 제공하여 SageMaker와 Spark를 연계해서 사용할 수 있게 함

  • Spark에서 데이터 전처리를 수행하고, SageMaker의 알고리즘(K-Means, PCA, XGBoost 등)을 활용해 모델링을 할 수 있음

  • 이를 통해 Spark의 대규모 데이터 처리 능력과 SageMaker의 다양한 ML 기능을 결합할 수 있음

  • SageMaker 노트북을 Spark 클러스터(EMR 등)와 연결하여 통합된 워크플로우를 구현할 수 있음

  • Spark에서 전처리한 데이터는 feature 컬럼(double vector)과 label 컬럼(double)의 형태로 SageMaker 모델에 입력됨

  • SageMaker 모델은 Spark 파이프라인과도 통합될 수 있음

주요 내용 요약:

  • SageMaker와 Apache Spark의 연계를 통해 데이터 전처리와 모델링의 장점을 결합할 수 있음

  • Spark의 대규모 데이터 처리 능력과 SageMaker의 다양한 ML 알고리즘을 함께 활용할 수 있음

  • SageMaker 노트북과 Spark 클러스터를 연결하여 통합된 워크플로우를 구현할 수 있음

  • Spark에서 전처리한 데이터를 SageMaker 모델에 입력하고, SageMaker 모델을 Spark 파이프라인에 통합할 수 있음

SageMaker Studio, and SageMaker Experiments

SageMaker는 IDE 환경인 SageMaker Studio로 강력하게 이동했습니다. 그리고 이 Studio 환경 아래에서 점점 더 많은 기능들을 개발하고 있습니다. 이를 통해 사용자들이 코드를 직접 작성하지 않고도 웹 브라우저 안에서 모든 작업을 수행할 수 있게 되었습니다. 그리고 2021년에 새로 도입된 몇 가지 최신 기능들도 간단히 살펴보도록 하겠습니다. 이 기능들은 아직 시험에 나오진 않지만 점차 부각되고 있습니다.

가장 핵심적인 것은 SageMaker가 SageMaker Studio라는 것을 출시했다는 것입니다. SageMaker는 이를 머신러닝을 위한 시각적 IDE 또는 통합 개발 환경으로 positioning하고 있습니다. 즉, SageMaker를 사용하는 개발자의 경험을 개선하고자 기존 AWS 콘솔 기반 환경에서 실제 개발 환경과 더 유사한 형태로 발전시키고자 하는 것입니다.

그리고 SageMaker Studio는 현재 별도의 사용자 인터페이스로 제공되고 있지만, 향후에는 기존 SageMaker UI를 완전히 대체할 가능성도 있습니다.

이 새로운 노트북 인터페이스가 SageMaker Studio에서 어떤 모습인지 보여드리겠습니다. 여기서는 Jupyter 노트북을 SageMaker Studio와 통합하여, 개발자 경험을 개선하고자 하고 있습니다. 물론 근본적으로는 여전히 Jupyter 노트북 자체이지만, 새로운 look and feel을 제공하고 있습니다.

특히 이 SageMaker Studio를 통해 노트북을 다른 팀원들과 공유할 수 있게 되었다는 점이 인상적입니다. 또한 SageMaker가 관리하는 하드웨어 구성을 자유롭게 변경할 수 있습니다.

SageMaker Studio의 또 다른 구성 요소로는 SageMaker Experiments가 있습니다. 이는 그동안 SageMaker를 사용하면서 생성했던 모든 ML 작업들을 한 곳에 모아서 구조화하고 비교/검색할 수 있게 해줍니다. 그동안 수많은 노트북과 작업을 만들어왔는데, SageMaker Experiments를 통해 이를 체계적으로 관리하고 어떤 모델이 가장 잘 수행되었는지 파악할 수 있게 되었습니다.

요약하면, SageMaker는 SageMaker Studio와 SageMaker Experiments를 통해 사용자 경험을 크게 개선했다고 볼 수 있습니다.

주요 내용 정리:

  • SageMaker Studio: 시각적 IDE/통합 개발 환경 제공, Jupyter 노트북과 통합, 노트북 공유 및 하드웨어 구성 변경 지원

  • SageMaker Experiments: ML 작업 이력 관리, 모델 성능 비교 및 검색 기능 제공

  • SageMaker의 사용자 경험 개선을 위한 노력

SageMaker Debugger

강사: 저는 SageMaker Model Monitor에 대해서도 좀 더 자세히 다루겠습니다. 이 기능의 아이디어는 배포된 모델의 품질 이탈에 대해 자동으로 경보를 받는 것입니다. 모델을 한번 배포하고 나면 영원히 내버려 둘 수는 없습니다. 시간이 지나면서 데이터의 특성이 변하거나 편향이 생길 수 있어서 모델의 품질이 떨어질 수 있기 때문입니다.

Model Monitor는 CloudWatch와 연동되어 있어서 변화가 감지되면 자동으로 알림을 보내줍니다. 이를 통해 즉각적인 조치를 취할 수 있습니다. Model Monitor를 통해 데이터 드리프트를 시각화할 수 있습니다. 예를 들어 대출 모델에서 입력 데이터의 변화로 인해 사람들에게 더 많은 신용을 주기 시작한다거나 하는 상황을 포착할 수 있습니다.

Deployment Guardrails and Shadow Tests

SageMaker의 새로운 기능 중 배포 안전장치와 그림자 테스트에 대해 설명하고 있습니다.

배포 안전장치(Deployment Guardrails)는 새로운 모델을 배포할 때 위험을 관리하는 기능입니다. 이를 통해 점진적으로 트래픽을 새 모델로 이전하고 문제 발생 시 자동으로 이전 모델로 롤백할 수 있습니다. 다음과 같은 3가지 모드가 있습니다:

  • All At Once: 모든 트래픽을 새 모델로 한 번에 전환하고 모니터링

  • Canary: 일부 트래픽만 새 모델로 전환하고 모니터링

  • Linear: 단계적으로 트래픽을 천천히 이전

그림자 테스트(Shadow Tests)는 새 모델의 성능을 기존 프로덕션 모델과 비교하는 기능입니다. 새 모델이 일부 트래픽을 처리하며 수동으로 성능을 모니터링할 수 있습니다.

이를 통해 새 모델을 안전하게 점진적으로 배포하고 검증할 수 있습니다.

주요 내용 요약:

  • 배포 안전장치: 새 모델 배포 시 점진적 트래픽 전환, 자동 롤백 지원

  • 그림자 테스트: 새 모델과 기존 프로덕션 모델 성능 비교

  • 이를 통해 새 모델을 안전하게 배포하고 검증 가능

Bias Measures in SageMaker Clarify

SageMaker와 Clarify에는 다양한 편향 지표들이 있으며, 이것들은 현재 AWS 인증 시험에 출제되고 있습니다. 따라서 이 부분에 대해 잘 이해해야 합니다.

편향은 최근 기계 학습 분야에서 매우 중요한 이슈로 대두되고 있습니다.

훈련 데이터의 편향이 모델의 편향을 야기할 수 있기 때문입니다.

대출 승인, 대학 입학, 채용 등과 같이 삶에 큰 영향을 미치는 의사결정에서는 특정 인구통계학적 집단에 대한 불공정한 차별이 발생하지 않도록 주의해야 합니다.

이를 위해 사용할 수 있는 다양한 편향 지표들이 있습니다:

  • 클래스 불균형(**Class Imbalance**): 특정 인구통계학적 그룹에 대한 데이터가 부족하거나 과다한 것을 측정합니다.

  • 레이블 비율 차이(**Difference in Proportions of Labels, DPL**): 인구통계학적 그룹별 레이블 값의 비율 차이를 측정합니다.

  • Kullback-Leibler Divergence(KL), Jensen-Shannon Divergence(JS): 인구통계학적 그룹별 결과 분포의 차이를 측정합니다.

  • Lp-norm: 인구통계학적 그룹별 결과 분포 간 Lp-norm 차이를 측정합니다.

  • Total Variation Distance(TVD): 인구통계학적 그룹별 결과 분포 간 L1-norm 차이를 측정합니다.

  • Kolmogorov-Smirnov(KS): 인구통계학적 그룹별 결과 분포 간 최대 차이를 측정합니다.

  • 조건부 인구통계학적 격차(Conditional Demographic Disparity, CDD): 전체 그룹과 하위 그룹별 결과 격차를 측정합니다.

이러한 편향 지표들을 이해하고 적절한 것을 선택할 수 있어야 합니다. 시험에서는 이 개념들을 정확히 알고 있어야 합니다.

주요 내용 요약:

  • SageMaker와 Clarify의 편향 지표 중요성 강조

  • 편향에 대한 정의와 중요성 설명

  • 다양한 편향 지표들의 개념과 활용 방법 상세 소개

  • 편향 지표 이해와 선택이 시험에 중요하다고 강조

SageMaker Training Compiler

2022년에 소개된 SageMaker 트레이닝 컴파일러에 대해 설명하겠습니다. 이것은 마치 애플리케이션 코드를 컴파일할 때 최적화를 하듯이, 모델 트레이닝 단계에서 모델을 최적화하는 역할을 합니다.

AWS 딥러닝 컨테이너(DLC)에 통합되어 있어, 자체 컨테이너를 가져올 수는 없고 AWS DLC를 사용해야 합니다. 트레이닝 작업을 컴파일하고 최적화하는 역할을 하며, 특히 GPU 인스턴스에서 GPU 기능을 최대한 활용하여 트레이닝을 최대 50%까지 가속화할 수 있습니다.

그러나 파라미터를 잘못 설정하면 오히려 도움이 되지 않을 수 있습니다. 따라서 단순히 켜기만 하는 것이 아니라 내부 동작 원리를 이해하고 적절하게 사용해야 합니다. 모델을 하드웨어 최적화된 명령어로 변환하여 GPU 인스턴스에서 최대한 효율적으로 실행되도록 합니다.

Hugging Face 트랜스포머 라이브러리와 호환되며, 다른 사용자 정의 모델에서도 사용 가능하지만 결과를 보장하지는 않습니다. SageMaker 분산 트레이닝 라이브러리와는 호환되지 않는다는 점이 유일한 제한사항입니다.

몇 가지 사용시 주의사항이 있습니다:

  • GPU 인스턴스(ml.p3 or ml.p4) 사용 필수

  • PyTorch 모델 사용시 PyTorch/XLA의 모델 저장 함수 사용 필요

  • 디버깅을 위해서는 compiler_config 파라미터에서 debug 플래그 활성화 필요

종합하면, SageMaker 트레이닝 컴파일러는 GPU 인스턴스에서 AWS DLC 사용시 모델 트레이닝을 최대 50%까지 가속화할 수 있는 기능입니다. 단, 사용자가 적절한 설정을 해야 효과를 볼 수 있습니다.

주요 내용 정리:

  • 2022년 소개된 SageMaker 트레이닝 컴파일러

  • 모델 트레이닝 단계에서 모델 최적화

  • AWS DLC에 통합, GPU 인스턴스에서 최대 50% 가속화

  • 하지만 부적절한 설정시 오히려 도움이 되지 않을 수 있음

  • Hugging Face 라이브러리 호환, 사용자 정의 모델도 가능

  • SageMaker 분산 트레이닝 라이브러리와 호환 제한

  • GPU 인스턴스, PyTorch/XLA 모델 저장 함수, 디버깅 설정 등 주의사항 존재

SageMaker Feature Store

SageMaker Feature Store에 대한 설명

SageMaker Feature Store는 기계 학습 모델 학습을 위한 특징(feature) 데이터를 관리하는 기능입니다.

특징이란 기계 학습 모델이 학습할 때 사용하는 속성이나 데이터를 말합니다. 예를 들어 정치적 성향을 예측하는 모델의 경우, 주소, 소득, 연령 등이 특징이 될 수 있습니다.

기계 학습 모델은 이러한 특징 데이터에 빠르고 안전하게 접근할 필요가 있습니다. 대량의 데이터를 매우 빨리 불러와야 하고, 이 데이터가 민감한 정보인 경우 데이터 보안도 중요합니다. 또한 이 데이터를 여러 모델에서 공유할 수 있도록 체계적으로 관리해야 합니다.

SageMaker Feature Store는 이러한 요구사항을 해결하기 위해 고안된 기능입니다. 다양한 소스(Kinesis, Kafka, EMR, Glue 등)에서 들어온 특징 데이터를 조직화하고 관리합니다.

데이터는 실시간 스트리밍으로 들어오거나 일괄 처리로 S3에 저장될 수 있습니다. 온라인 리포지토리와 오프라인 S3 리포지토리를 모두 제공하여 유연한 데이터 액세스가 가능합니다.

보안 측면에서는 데이터 암호화, IAM 기반 접근 제어, AWS PrivateLink 등의 기능을 제공합니다.

주요 내용 요약:

  • 기계 학습 모델의 특징 데이터를 관리하는 SageMaker 기능

  • 다양한 소스에서 들어온 데이터를 체계적으로 조직화 및 공유

  • 실시간 스트리밍과 일괄 처리 방식의 데이터 액세스 지원

  • 데이터 암호화, IAM 기반 접근 제어, AWS PrivateLink 등의 보안 기능 제공

SageMaker ML Lineage Tracking

강사: 아, 데이터 엔지니어링 기본 섹션에서 이야기했던 계보 추적이 생각나네요. 그게 얼마나 오래된 일인지 모르겠어요.

SageMaker에는 SageMaker ML 계보 추적이라는 기능이 있어서 이런 작업들을 자동화해줍니다. 우리의 기계학습 워크플로우를 자동으로 생성하고 저장해줍니다. 이를 더 넓은 의미에서 ML 운영, 즉 기계학습 파이프라인과 프로세스를 관리하는 분야라고 합니다.

SageMaker ML 계보 추적은 모델의 변경 내역을 자동으로 기록하고 관리해줘서 감사와 규정 준수 목적으로 활용할 수 있습니다. 또한 수동으로도 계보 추적 엔티티를 생성할 수 있습니다. 그리고 계정 간 계보 추적도 가능한데, AWS 리소스 액세스 관리자를 사용하면 됩니다.

그럼 SageMaker ML 계보 추적의 실제 예시를 한번 살펴보죠. 여기 보시면 데이터가 들어오고 있고, 데이터셋 아티팩트와 스트리밍 입력 아티팩트가 있습니다. 이 데이터들이 처리 작업 시험 구성요소에 들어가고, 거기서 학습 작업으로 이어집니다.

학습 작업에는 입력 데이터셋, 추가 입력 데이터, 알고리즘 사양, 그리고 실행 코드가 포함되어 있습니다. 학습이 끝나면 모델 아티팩트, 체크포인트 아티팩트, 출력 데이터 구성 아티팩트가 생성됩니다. 그리고 이 모델 아티팩트들이 엔드포인트에 투입되어 외부 세계로 결과가 전달됩니다. 코드 스냅샷도 이 과정에서 생성됩니다.

이렇게 다양한 엔티티들이 추적됩니다. 시험 구성요소에는 처리 작업, 학습 작업, 변환 작업 등이 포함됩니다. 시험 구성요소를 조합해서 시험을 구성할 수 있고, 시험들을 다시 실험이라는 논리적 그룹으로 묶을 수 있습니다.

또한 컨텍스트, 액션, 아티팩트, 엔티티 간 연관관계 등도 모두 추적 대상이 됩니다. 이런 계보 추적 정보는 LineageQuery API를 통해 조회할 수 있습니다. 예를 들어 특정 아티팩트에 의존하는 모든 모델이나 엔드포인트를 찾을 수 있습니다. 이를 통해 아티팩트 변경이 미치는 영향을 파악할 수 있습니다.

SageMaker는 계보 추적 정보를 시각화할 수 있는 기능도 제공하지만, 외부 Visualizer 도구를 사용해야 합니다. SageMaker 자체에는 이런 시각화 기능이 내장되어 있지 않습니다.

주요 내용 정리:

  • SageMaker ML 계보 추적 기능을 통해 기계학습 워크플로우 전반을 자동으로 기록 및 관리

  • 모델 변경 이력 추적, 감사 및 규정 준수 지원

  • 시험 구성요소, 시험, 실험, 컨텍스트, 액션, 아티팩트 등 다양한 엔티티 추적

  • LineageQuery API로 의존 관계 조회 가능

  • 시각화는 외부 Visualizer 도구 필요

SageMaker Data Wrangler

SageMaker Data Wrangler는 SageMaker 내에서 사용할 수 있는 ETL 파이프라인 도구입니다. 데이터 준비 및 전처리를 위해 설계되었으며, 머신러닝 모델 학습을 위한 데이터 정제 및 변환에 특화되어 있습니다.

Data Wrangler를 통해 **다양한 소스(S3, Athena, Redshift 등)**에서 데이터를 가져올 수 있습니다. 가져온 데이터를 시각화하여 데이터의 분포와 이상치를 확인할 수 있습니다. 300가지 이상의 데이터 변환 기능을 제공하며, Pandas, PySpark, PySpark SQL 등을 이용한 사용자 정의 변환도 가능합니다.

또한 Quick Model 기능을 통해 데이터 변환이 모델 성능에 어떤 영향을 미치는지 실험해볼 수 있습니다. 이를 통해 데이터 전처리 과정을 최적화할 수 있습니다.

변환된 데이터는 Jupyter Notebook 코드로 출력되며, 이 코드를 실제 머신러닝 파이프라인에 통합할 수 있습니다. Data Wrangler는 단순히 코드를 생성하는 역할을 하며, 직접 데이터 처리 작업을 수행하지는 않습니다.

Data Wrangler 사용 시 주의사항은 다음과 같습니다:

  • SageMaker Studio 사용자에게 적절한 IAM 권한이 부여되어 있어야 합니다.

  • 데이터 소스에도 SageMaker에 대한 액세스 권한이 있어야 합니다.

  • 리소스 할당량이 부족한 경우 할당량 증가를 요청해야 합니다.

주요 내용 요약:

  • SageMaker Data Wrangler: SageMaker 내 ETL 파이프라인 도구

  • 머신러닝 모델 학습을 위한 데이터 준비 및 전처리에 특화

  • 다양한 데이터 소스 지원, 데이터 시각화 및 변환 기능 제공

  • Quick Model 기능으로 데이터 전처리 과정 최적화 가능

  • 변환된 데이터를 Jupyter Notebook 코드로 출력

  • IAM 권한, 데이터 소스 권한, 리소스 할당량 등 주의사항 존재
