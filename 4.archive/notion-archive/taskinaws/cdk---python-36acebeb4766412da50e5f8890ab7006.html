Project Structure

  • Open project in VSCode

    • code command가 shell command path에 설정되어 있어야 함

  • Project Structure Details

    • .env - The python virtual environment information

    • cdk_python_workshop - A Python module directory.

      • cdk_python_workshop.egg-info - Folder that contains build information relevant for the packaging on the project

      • cdk_python_workshop_stack.py - A custom CDK stack construct for use in your CDK application.

    • tests - Contains all tests.

      • unit - Contains unit tests.

        • test_cdk_python_workshop_stack.py - A trivial test of the custom CDK stack created
          in the cdk-python-workshop package. This is mainly to demonstrate how tests can be hooked up to the project.

    • app.py — The “main” for this sample application.

    • cdk.json — A configuration file for CDK that defines what executable CDK should run to generate the CDK construct tree.

    • README.md — The introductory README for this project.

    • requirements.txt—This file is used by pip to install all of the dependencies for your application. In this case, it contains only -e. This tells pip to install the requirements specified in setup.py. It
      also tells pip to run python setup.py develop to install the code in the cdk-python-workshop module so that it can be edited in place.

    • setup.py — Defines how this Python package would be constructed and what the dependencies are.

Constructor (생성자)

  • Basic building block of CDK apps

  • Represent abstract ‘cloud components’

  • Cloud components can be composed together into higher level abstractions via scope

  • Scopes can include constructors, which in turn can include other constructors

  • Constructs are always created in the scope of another construct

  • Must always have an identifier which must be unique within the scope it’s created

  • Construct initializers (constructors) will always have the following signature

    • scope

      • scope in which this construct is created

      • defining constructs within the scope of current construct

      • usually just want to pass self for the first argument

    • id

      • local identity of the construct

      • has to be unique amongst construct within the same scope

      • CDK uses this identity to calculate the CloudFormation Logical ID for each resource defined within this scope

    • kwargs

      • always a set of initialization arguments

      • specific to each construct
