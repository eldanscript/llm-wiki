https://w.amazon.com/bin/view/SystemsManager/InternalUse/Wiki/Patching_Solutions/Onboard_Account_To_Compliance_Reporting_And_Patching#HConsoleInstructions

  1. AWS System Manager에서 Quick Setup 메뉴에서 Configurations을 하나 생성합니다.

  • 이때 Configuration type은 Host Management로 선택하고 옵션은 기본설정, 타겟은 EC2를 사용한 범위를 지정합니다.

  • 이 설정이 완료되면, IAM Role*이 생깁니다.

    • **AmazonSSMRoleForInstancesQuickSetup**

IAM Role - AmazonSSMRoleForInstanceQuickSetup

  1. EC2 Instance의 SG에서 inbound 443 port allow

  2. EC2에 SSM 에이전트 설치

  • 다음 페이지에 따라 EC에 SSM 에이전트를 설치 합니다.

https://docs.aws.amazon.com/systems-manager/latest/userguide/ssm-agent.html

  • Amazon Linux2 AMI는 default로 설치가 됨. 설치 여부는 다음 명령어로 확인
  1. EC2에 ‘1’에서 생성된 IAM Role을 연결 합니다. **AmazonSSMRoleForInstancesQuickSetup**

  1. 조치 방법 위키 에 있는 CloudFormation 파일을 deploy 합니다.

AutomationRolesAndDocument-WIKI.json

  • AWS-SystemManager-AutomationAdministrationRole과 AWS-SystemManager-AutomationExecutionRole 생성

  • 한번 설치가 된 이후는 추가 설치 필요 없음

  • 이 파일은 EC2의 컴플라이언스 준수 여부를 보고하는 스크립트와 이 때 필요한 IAM Role 등을 배포 합니다.

  • 이때 주의하실 점은 최초 실행시에는 위키페이지의 AutomationRolesAndDocument 파일을 사용하고 us-west2(oregon) 리전을 선택합니다.

  • 이 Stack은 Role을 생성하는 것으로 us-west-2 설치 후 다른 region에서 설치는 불필요

  1. SystemManager Automation을 위한 CloudFormation 실행

  • Isengard 계정의 Oregon(US-WEST-2)에서 Cloudformation 실행 및 적용

    • aws cli로 적용 (아래 UI로 수행하지 않을 경우)
    • S3 URL : https://compliance-automation-roles.s3-us-west-2.amazonaws.com/AutomationRolesAndDocument.json → Access Denied
  1. ‘6’ 완료 후 AWS System Manager에서 Automations을 실행 합니다.
  • 상세 내용은 위키 페이지의 9~15 단계를 따릅니다.

  1. ‘5’까지 완료 후 24시간 내외에 시큐리티 대시보드에서 업데이트된 내역을 확인 합니다.
