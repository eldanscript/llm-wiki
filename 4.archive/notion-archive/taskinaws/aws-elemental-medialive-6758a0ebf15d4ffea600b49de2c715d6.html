💡

**converts video inputs** (live and prerecorded) into live outputs for broadcast and multiscreen video delivery over the internet

Video Encoding Service

Video workflow

  • glass-to-glass (from the glass of the camera lens to the glass of the viewer’s device)

Ingest

  • source content needs to be transported into the system to be processed

Process

  • Compress : contents needs to be compressed to be efficiently streamed to viewer devices

  • Packaging :

    • multiple bitrate versions of a source file are created and then broken into contiguous segments as internet bandwidth fluctuates and cannot be controlled

    • Breaking video streams into contiguous segments and listing the names and locations of the video segments in a manifest file

Store

  • segmented streams are cached or buffered for short periods of time, then served up when requested by a viewer

Deliver

  • managed in order to support millions of simultaneous veiewers

  • The main function of MediaLive is **compression**. Source content is typically too high in bandwidth to be efficiently streamed to viewer devices. The content needs to be compressed into lower resolution and lower bitrate versions

  1. Source : the content that is encoded and compressed so that it can eventually be viewed. source might be the live stream, pre-recorded files, or a combination of the two.

  2. Contribution Encoding : source content usually isn’t fed directly into the cloud. the direct output of camera and video switchers needs to be encoded (packetized) so that it can be moved in a computer network. source content is usually too high in resolution and bitrate and needs to be compressed. the contribution encoder modifies the source content to contribute to the downstream workflow. (AWS Elemental Live)

  3. Dedicated network connection : High value live video content needs to be moved into the cloud reliably, rapidly and securly. Content can be moved securely over the public internet, but high-bandwidth dedicated networks such as AWS Direct Connect can add reliability and reduce latency.

  4. Media transport : The need for real-time transactions, along with the high cost of production, make transporting live video stream more challenging than other type of network data. MediaConnect adds reliability, security, and speed for transporting live video streams into the AWS Cloud between AWS regions, and out of the AWS Cloud.

  5. Live video compression : High-resolution, high bitrate source content is compressed into multiple lower resolution/bitrate versions, suitable for use by viewer devices. Video compression is the main function of Elemental MediaLive.

  6. Packaging and origination : packaging is the process of taking compressed streams and breaking them into contiguous segments which are each several seconds long. The segmentation points allow a player to switch between bitrates, depending on the network bandwidth of the connection. this is referred to as ABR streaming. The video segments are cached for a short duration. When the user makes a request to play, the video segments originate from this location. Elemental MediaPackage is a packaging and origination service.

  7. Content Delivery Network : spreads content out through large networks to get the content physically closer to the consumer. A CDN is a network which supports servers which make it possible to serve video to hundreds, thousands, or millions of simultaneous viewers.

  8. Viewers : the final step in content delivery and include a wide array of devices such as connected TVs, PCs, laptops, tablets, and mobile devices. Viewers request and display content from the CDN.

MediaLive components

Inputs

  • 처리할 컨텐츠 타입 : live stream or pre-recorded content

  • 한번에 한 개의 채널에 연결 (attach)

  • 단일 채널에는 여러 개의 input이 연결 될 수 있지만 switching을 하게 됨

Pull input

  • MediaLive가 외부 위치 (external location)에 연결 하여 컨텐츠를 가지고 옴

  • source URL을 지정하고 필요시 접근 자격 증명을 제공

Push input

  • 외부 소스에서 직접 MediaLive 인스턴스로 컨텐츠를 전송 (1 대 1 연결)

  • AWS Cloud로 입력되는 traffic은 명시적으로 허용되기 전까지는 차단됨 → 명시적인 권한 (permission) 필요

Channels

  • 압축 및 다른 처리 작업이 발생하는 instance를 의미

  • Input은 한번에 하나의 channel 에만 연결 될 수 있으며 하나의 channel은 여러개의 input을 가질 수 있음

Output groups

  • 사용될 packaging format을 결정 : HLS, UDP, RTMP, MediaPackage, …

Output settings

  • video, audio 인코딩 명령어를 지정 : codec, resolution, frame rate, bitrate, video quality, …

Output destinations

  • 인코딩된 스트림을 전송할 대상 위치 : Network locations, S3 buckets, upstream systems, …

Input type

AWS CDI

  • Cloud Digital Interface

  • Uncompressed or light compressed source streams

  • Extremely low latency

  • Push input

  • Upstream source : VPC

  • Creating : https://docs.aws.amazon.com/medialive/latest/ug/input-create-cdi-push.html

RTP

  • Real-time Transport Protocol

  • Low latency

  • Push input

  • Upstream source : RTP server, VPC ovefr RTP

  • Creating : https://docs.aws.amazon.com/ko_kr/medialive/latest/ug/input-create-rtp-push.html

RTMP (push)

  • Real-time Messaging Protocol

  • Relatively low latency

  • Push Input : connection oriented single point-to-point connection (sender → MediaLive instance)

  • Upstream source : RTMP server

  • Creating : https://docs.aws.amazon.com/medialive/latest/ug/input-create-rtmp-push.html

RTMP (pull)

  • Pull Input : MediaLive connects to source location and pulls content to itself

  • Upstream source : RTMP server

  • Creating : https://docs.aws.amazon.com/medialive/latest/ug/input-create-rtmp-pull.html

HLS

  • HTTP-based Live Streaming

  • Adaptive bitrate streaming protocol

  • MediaLive selects one of multiple bitrate stream

  • Upstream source : HTTP(S) server, Elemental MediaStore, S3

  • Creating : https://docs.aws.amazon.com/medialive/latest/ug/input-create-hls-pull.html

MP4

  • MPEG-4 Part 10 Advancded Video Coding (AVC) / H.264

  • Single continuous file

  • Pull input

  • Upstream source : HTTP(S) server, S3

  • Creating : https://docs.aws.amazon.com/medialive/latest/ug/mp4-pull-input.html

TS

  • MPEG Transport Stream files

  • Upstream source : HTTP(S) server

MediaConnect

  • Transport live video into (within, out of) the AWS Cloud - Higher reliability compared to public internet

  • Push input

  • Upstream source : Elmental MediaConnect flow

  • Creating : https://docs.aws.amazon.com/medialive/latest/ug/input-create-push-mediaconnect.html

Elemental Link

  • Physical device used to send SDI and HDMI feeds to MediaLive

  • Push input

  • Upstream source : Elemental Link on-prem device

  • Creating : https://docs.aws.amazon.com/medialive/latest/ug/input-create-link-device.html

Output Types

HLS

  • HTTP Live Streaming

  • Adaptive bitrate streaming format

  • Highly accurate - may introduce latency

  • MPEG-TS or fMP4 container

  • Downstream system (protocol) : HTTP(S) server, CDN over HTTP(S), Elemental MediaPackage over HTTPS, S3, Elemental MediaStore

  • Creating : https://docs.aws.amazon.com/medialive/latest/ug/hls-create-procedure.html

Archive

  • Single continuous file sent to S3 bucket

  • Downstream system (protocol) : S3

  • Creating : https://docs.aws.amazon.com/medialive/latest/ug/archive-create-procedure.html

MS Smooth

  • Legacy adaptive bitrate streaming format - Native on Xbox

  • Downstream system (protocol) : CDN over HTTP(S)

  • Creating : https://docs.aws.amazon.com/medialive/latest/ug/smooth-create-procedure.html

UDP

  • Very low latency

  • Connectionless - receiver cannot request re-sends of packets

  • Downstream system (protocol) : UDP server

  • Creating : https://docs.aws.amazon.com/medialive/latest/ug/udp-create-procedure.html

RTMP

  • Real-time Messaging Protocol

  • Connection oriented - receiver may request re-sends, improve accuracy

  • Downstream system (protocol) : RTMP server

  • Creating : https://docs.aws.amazon.com/medialive/latest/ug/rtmp-create-procedure.html

RTMPS

  • Real-time Messaging Protocol Secure

  • Downstream system (protocol) : RTMP server

  • Creating : https://docs.aws.amazon.com/medialive/latest/ug/rtmp-create-procedure.html

Frame Capture

  • JPG still images sent to a S3 bucket

  • Downstream system (protocol) : S3

  • Creating : https://docs.aws.amazon.com/medialive/latest/ug/framecapture-create-procedure.html

MediaPackage

  • JIT packaging, Segment origination, Encryption

  • Downstream system (protocol) : Elemental MediaPackage over HTTPS WebDAV

  • Creating : https://docs.aws.amazon.com/medialive/latest/ug/emp-create-procedure.html

Multiplex

  • Combine Single Program Transport Stream (SPTS) into a Multiple Program Transport Stream (MPTS) - cable or satellite delivery

  • Creating : https://docs.aws.amazon.com/medialive/latest/ug/feature-multiplex.html

MediaLive Workflow Wizard

Input Type

  • AWS Elemental MediaConnect flow

  • AWS Elemental Link device

  • RTMP push

  • MP4 file on Amazon S3 of from HTTP server

Output Type

  • MediaPackage channel

  • MediaStore container

  • Facebook

  • Twitch

  • YouTube

Features

  • The Workflow Wizard offers a streamlined set of the most commonly used input and output types.

  • SDI streams can be ingested by using the on-premises AWS Elemental Link device.

  • Channels created through the Workflow Wizard can be deleted or modified, and they must also have proper IAM permissions assigned.

  • Channel templates are not used in the Workflow Wizard.

  • The Workflow Wizard offers the same range of input types that the Input panel offers.

Channel Edit

  • Input types cannot be edited, for example you cannot change an RTMP input to an HLS input.

  • Other attributes that can be edited include input name, source URL, tags, input security groups, among others.

  • A channel always has to have at least one input attached to it, and an input can only be attached to one channel at time. When a channel is cloned, the input remains attached to the original channel. Inputs themselves are not cloned.

  • A channel must have at least one input attached, so the existing input needs to be replaced with another one before attempting to update the channel

  • A channel can be cloned while it is running. A different input will need to be attached to the new channel. Editing or deleting a channel require that the channel is in the Idle state

  • Inputs are not specified in channel templates because they are the mostly likely to change from event to event, and because inputs can only be attached to one channel at a time.

Monitor MediaLive

CloudWatch Logs

  • As-run logs—start and stop times of the channel. MediaLive always produces these logs.

  • Channel encoder logs—detailed sequential description of activity that occurs in a channel. You must enable these logs for MediaLive to produce them.

Health Tab Metric

Fill milliseconds

  • This metric is the number of consecutive milliseconds of “fill” frames (for example - repeated frames, black frames, and/or slate) inserted by MediaLive due to the input not being present. Once the input returns, this value will go back to zero.

UDP input loss

  • When attached to an RTP input, this graph displays the cumulative number of seconds of loss of input. When connection to the RTP input is reestablished, the value resets to zero.

SVQ times (Speed vs Quality)

  • This metric defines the percentage of time, averaged over the last 10 seconds, the encoder has had to reduce quality optimizations to speed up the encode process in order to keep the MediaLive running in real time.

  • A drop in quality could be caused by imperfections in the source which require extra corrective work by the encoder.
