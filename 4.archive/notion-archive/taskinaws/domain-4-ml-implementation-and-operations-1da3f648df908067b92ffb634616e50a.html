Domain 4: ML Implementation and Operations

Objectives

  • Building ML solutions for performance, availability, scalability, resiliency, and fault tolerance

  • Recommending and implementing the appropriate ML services and features for a given problem

  • Applying basic AWS security practices to ML solutions

  • Deploying and operationalizing ML solutions

Domain 4.1: Build ML solutions for performance, availability, scalability, resiliency, and fault tolerance

이 도메인의 일부는 ML 솔루션을 운영 환경에 배포하는 것에 초점이 맞춰져 있습니다. 하지만 모델 배포 단계에 들어가기 전에, 운영 중 장애에 효과적으로 대응할 수 있도록 솔루션을 설계해야 합니다. 이 하위 도메인에서는 기계 학습 분야에서 이를 실천하는 모범 사례에 대해 다룹니다.

  • 고가용성과 장애 허용력

    • 고가용성 솔루션은 아키텍처의 어느 구성 요소가 작동을 중지해도 시스템이 계속 기능할 수 있습니다.

    • 장애 허용력은 고가용성의 핵심 부분으로, 아키텍처의 어느 구성 요소가 완전히 실패해도 애플리케이션이 성능 저하 없이 계속 작동하도록 보장합니다.

  • 느슨한 결합을 통한 고가용성과 장애 허용력 달성

    • 느슨하게 결합된 분산 시스템에서는 한 구성 요소의 장애를 애플리케이션 계층 사이에서 관리할 수 있어, 장애가 확산되지 않습니다.

    • 애플리케이션 구성 요소의 독립성을 보장하여 느슨한 결합을 달성할 수 있습니다.

    • 예를 들어 저장 계층과 컴퓨팅 계층을 분리하면, 훈련 작업에만 필요한 컴퓨팅 리소스를 필요 시에만 사용할 수 있습니다.

  • 큐를 사용한 구성 요소 간 느슨한 결합

    • Amazon SQS와 같은 큐 서비스 또는 AWS Step Functions와 같은 워크플로 서비스를 사용하여 구성 요소 간 메시지 전달을 구현할 수 있습니다.

  • Amazon CloudWatch를 통한 시스템 모니터링

    • Amazon CloudWatch는 모델 학습 및 테스트 코드와 별도로 로그와 운영 지표를 저장하여 시스템을 모니터링할 수 있습니다.

    • Amazon SageMaker는 Amazon CloudWatch와 기본 통합되어 훈련 작업 인스턴스의 CPU, 메모리, GPU 활용도 등의 지표를 실시간으로 수집할 수 있습니다.

  • AWS CloudTrail을 통한 API 호출 및 이벤트 캡처

    • AWS CloudTrail은 AWS 계정에서 발생한 API 호출 및 관련 이벤트를 캡처하여 Amazon S3 버킷에 저장합니다.

    • 이를 통해 어떤 사용자 및 계정이 AWS를 호출했는지, 호출 시간 및 IP 주소 등의 정보를 확인할 수 있습니다.

design for failure of any individual component

  1. ETL 프로세스와 ML 파이프라인 분리하기

    • ETL 프로세스와 ML 훈련에 필요한 컴퓨팅 파워가 다름

    • ETL 프로세스는 다양한 형식의 파일을 읽고, 변환한 뒤 저장소에 쓰는 작업이 필요함

    • 이를 위해서는 메모리와 디스크 I/O가 많이 필요한데, Apache Spark와 같은 프레임워크를 사용하면 효과적

    • 반면 모델 훈련에는 GPU가 더 적합하므로, 훈련과 ETL을 분리하면 리소스를 효율적으로 사용할 수 있음

    • AWS Glue나 Amazon EMR과 같은 ETL 서비스와 Amazon SageMaker를 함께 사용하면 이러한 분리가 가능

  2. 고가용성 ML 서빙 엔드포인트 구축하기

    • Amazon SageMaker 엔드포인트를 다중 가용영역에 배포하여 고가용성 확보

    • Amazon SageMaker는 모델 훈련과 추론을 위한 컨테이너화를 지원

    • 이를 통해 느슨하게 결합된 분산 서비스로 구성된 ML 모델을 만들 수 있음

    • 다양한 플랫폼이나 데이터 근처에 배포할 수 있음

  3. AWS Auto Scaling을 통한 탄력적 솔루션 구축

    • AWS Auto Scaling을 사용하여 Amazon SageMaker 엔드포인트의 자동 스케일링 구현

    • 트래픽 변화에 따라 필요한 컴퓨팅 파워를 자동으로 추가하고 제거

    • 가용성 중심, 비용 중심, 혹은 두 가지의 균형을 위한 스케일링 전략 선택 가능

    • 자동 스케일링을 통해 예측 처리량을 높이고 가용성을 보장

  4. 자동 스케일링 정책 테스트 및 구현

    • 엔드포인트가 지탱할 수 있는 로드(RPS) 테스트

    • 자동 스케일링 구현 후 지연 시간 감소, 오류 감소 등 기대 동작 관찰

    • 최소 2개의 인스턴스를 사용하여 가용성과 개별 장애 내구성 확보

이와 같이 ETL 프로세스와 ML 파이프라인의 분리, 고가용성 엔드포인트 구축, AWS Auto Scaling을 통한 탄력적 솔루션 구현 등의 기법을 활용하면, ML 솔루션을 안정적이고 확장 가능한 운영 환경에 배포할 수 있습니다.

Designing highly available and fault-tolerant ML architectures

고가용성 및 장애 허용 ML 아키텍처 설계

이전에 설명한 바와 같이, Amazon SageMaker로 생성한 모델을 Amazon SageMaker 엔드포인트에 배포할 수 있습니다. 엔드포인트가 생성되면 Amazon SageMaker 노트북 인스턴스 외부에서 적절한 입력(모델 시그니처)으로 엔드포인트를 호출해야 합니다. 이러한 입력 파라미터는 CSV, LIBSVM 등의 파일 형식뿐만 아니라 오디오, 이미지, 동영상 파일 형식도 가능합니다.

이를 위해 AWS Lambda와 Amazon API Gateway를 사용하여 입력 요청을 형식화하고 엔드포인트를 호출할 수 있습니다. 이 경우의 인프라 아키텍처는 다음과 같습니다:

  • Amazon SageMaker 엔드포인트

    • 배포된 ML 모델을 호스팅

    • 다중 가용 영역에 걸쳐 고가용성 보장

  • AWS Lambda

    • 입력 데이터 형식화

    • Amazon SageMaker 엔드포인트 호출

  • Amazon API Gateway

    • 웹/모바일 애플리케이션에서 Lambda 함수를 호출할 수 있는 API 제공

    • 인증, 요청 변환 등의 기능 제공

  • Amazon S3

    • 입력 데이터(CSV, 이미지 등) 저장

  • Amazon CloudWatch

    • 엔드포인트 모니터링 및 로깅

    • 성능 지표 수집 및 대시보드 제공

이러한 아키텍처를 통해 고가용성과 장애 허용력을 갖춘 ML 솔루션을 구축할 수 있습니다. 각 구성 요소가 느슨하게 결합되어 있어 독립적으로 확장이 가능하고, 자동 스케일링을 활용하여 트래픽 변화에 유연하게 대응할 수 있습니다.

  • libsvm file format : Library for Support Vector Machines

    LIBSVM은 머신러닝에서 널리 사용되는 데이터 파일 형식 중 하나입니다.

    LIBSVM 파일 형식의 특징은 다음과 같습니다:

    1. 희소 벡터 표현

      • 데이터 포인트는 희소 벡터로 표현됩니다.

      • 실제 값이 0인 피처는 명시하지 않고 생략합니다.

    2. 공백으로 구분된 형식

      • 각 라인은 다음과 같은 형식으로 구성됩니다:

      • 레이블 특징1:값1 특징2:값2 …

    예를 들어 다음과 같은 LIBSVM 파일 형식을 볼 수 있습니다:

    1 1:3.4 3:0.2 5:1.0
    -1 2:1.2 4:0.7 6:0.5
    0 1:2.1 3:0.9 5:0.3 7:1.2

    이 파일에는 3개의 데이터 포인트가 있습니다. 각 라인의 첫 번째 값은 레이블이고, 그 뒤에는 특징-값 쌍이 나열됩니다.

    이러한 희소 벡터 표현 방식은 대용량 데이터 처리에 효율적이며, 다양한 머신러닝 라이브러리에서 지원됩니다. 따라서 LIBSVM 형식은 ML 모델 입력 데이터로 널리 사용됩니다.

Domain 4.2: Recommend and implement the appropriate ML services and features for a given problem

이 문제 도메인은 ML 파이프라인의 각 단계와 관련된 AWS 서비스에 대해 다루었습니다. 예를 들어 데이터 수집 및 변환을 위해 AWS Glue, Amazon EMR, Amazon Kinesis를 다루었고, 모델 빌딩, 훈련, 튜닝, 평가를 위해 Amazon SageMaker를 다루었습니다.

그러나 이번 하위 도메인은 ML 파이프라인에서 벗어나, AWS ML 서비스 전반과 그 활용 사례에 초점을 맞추고 있습니다.

Amazon 기계 학습 스택은 3개의 계층으로 구성됩니다:

ML 프레임워크 + 인프라 계층

  • 이 계층은 ML 프레임워크 수준에서 작업하는 전문가 ML 실무자를 위한 것입니다.

  • 여기에서는 직접 ML 모델을 빌드, 훈련, 튜닝, 배포하는 것에 중점을 둡니다.

  • AWS 생태계와 더 폭넓게 연결될 수 있도록 지원하는 데 초점을 맞추고 있습니다.

  • 예를 들어 AWS IoT Greengrass의 IoT 데이터 활용, P3 인스턴스의 최신 칩 사용, 탄력적 추론 활용 등이 포함됩니다.

ML 서비스 계층

  • 이 계층은 전문 ML 실무자가 많지 않다는 현실을 반영하여 만들어졌습니다.

  • 이 계층의 핵심은 Amazon SageMaker로, 데이터 준비, 모델 훈련, 배포 등의 복잡한 작업을 간소화합니다.

  • 데이터 수집, 정제, 포맷팅, 모델 훈련, 운영 환경 관리 등의 어려움을 해결하는 것이 목표입니다.

AI 서비스 계층

  • 이 계층은 ML 모델 자체를 구축하고 싶어 하지 않는 고객을 위한 것입니다.

  • 컴퓨터 비전, 자연어 처리, 시계열 예측 등 다양한 도메인의 공통적인 ML 문제를 해결하는 서비스를 제공합니다.

  • 모델 구축에 대한 복잡성을 완전히 추상화하여 제공합니다.

이와 같이 Amazon의 ML 서비스 스택은 전문 ML 실무자부터 ML 활용에 관심 있는 일반 고객까지 다양한 요구사항을 충족하고자 설계되었습니다.

Domain 4.3: Apply Basic AWS security practices to ML solutions

클라우드에 구축되는 ML 솔루션의 보안 실천사항에 대해 다루고 있습니다. 이를 위해 Amazon SageMaker의 보안 기능을 중심으로 설명하겠습니다.

Amazon SageMaker의 내재적 보안 기능

  • 훈련 데이터는 Amazon S3에서 가져와 훈련 작업 환경으로 전달되며, 생성된 모델도 다시 Amazon S3에 저장됩니다.

  • 이 모든 과정은 고객의 계정 내에서 이루어지며, Amazon SageMaker 관리 계정에 저장되지 않습니다.

  • 배포 시에는 추론 엔드포인트에 모델이 로드됩니다.

IAM 역할 기반 액세스 제어

  • Amazon S3의 아티팩트에 대한 액세스를 IAM 역할 기반으로 제어할 수 있습니다.

  • 예를 들어 데이터 과학자는 원본 데이터의 PII 정보에 접근할 수 있지만, DevOps 엔지니어는 훈련된 모델에만 접근할 수 있도록 할 수 있습니다.

  • 노트북 실행 역할과 훈련 작업 실행 역할을 분리하여 최소 권한 원칙을 적용할 수 있습니다.

  1. 고객 관리 VPC에서 Amazon SageMaker 인스턴스 실행

    • Amazon SageMaker 노트북 인스턴스를 고객의 VPC에서 실행할 수 있습니다.

    • 이 경우 직접 인터넷 액세스 옵션을 선택할 수 있습니다.

    • 모델을 생성할 때 VPC 구성, 서브넷, 보안 그룹을 지정할 수 있습니다.

  2. 데이터 암호화

    • Amazon SageMaker는 저장 데이터와 전송 데이터를 암호화합니다.

    • 저장 데이터는 AWS KMS 키 또는 임시 키로 암호화됩니다.

    • 전송 데이터는 TLS 1.2 암호화를 사용합니다.

    • 노트북 인스턴스 액세스 시 AWS SigV4 인증을 사용합니다.

  3. 암호화된 Amazon S3 버킷 사용

    • 모델 아티팩트와 데이터를 암호화된 Amazon S3 버킷에 저장할 수 있습니다.

    • AWS KMS 키를 사용하여 연결된 ML 스토리지 볼륨을 암호화할 수 있습니다.

    • AWS KMS를 통해 데이터 암호화 키에 대한 중앙 집중식 제어가 가능합니다.

  4. 보안 기능 요약

    • 인증: IAM 연동

    • 권한 제어: IAM 정책 및 조건 키

    • 감사: AWS CloudTrail API 로깅(InvokeEndpoint 제외)

    • 저장 데이터 보호: AWS KMS 암호화

    • 전송 데이터 보호: HTTPS 암호화

    • 규제 준수: PCI DSS, HIPAA, ISO 등

이와 같이 Amazon SageMaker는 ML 솔루션의 보안을 위한 다양한 기능을 제공합니다.

Domain 4.4: Deploy and operationalize ML solutions

개발한 ML 모델은 보다 큰 소프트웨어 생태계의 한 구성 요소입니다. 따라서 보안, 로깅, 모니터링, 작업 관리, API 버전 관리 등 일반적인 소프트웨어 엔지니어링 및 관리 실적이 적용되어야 합니다. 이 생태계는 클라우드 및 소프트웨어 엔지니어링 모범 사례를 활용하여 관리되어야 합니다.

이러한 모범 사례에는 다음과 같은 것들이 포함됩니다:

  1. 종단간 테스트 및 A/B 테스트

  2. API 버전 관리(여러 버전의 모델이 사용되는 경우)

  3. 안정성 및 장애 조치

  4. 지속적인 유지보수

  5. 지속적 통합/지속적 배포(CI/CD) 등의 클라우드 인프라 모범 사례

Amazon SageMaker 호스팅 서비스를 사용하여 모델을 배포하는 프로세스는 3단계로 구성됩니다:

  1. Amazon SageMaker에서 모델 생성

    • 모델 아티팩트가 저장된 Amazon S3 경로

    • 추론 코드가 포함된 Docker 레지스트리 경로

    • 후속 배포 단계에서 사용할 이름

  2. HTTPS 엔드포인트를 위한 엔드포인트 구성 생성

    • 프로덕션 버전의 모델 이름

    • 모델을 호스팅할 ML 컴퓨팅 인스턴스

    • 자동 스케일링을 위한 인스턴스 수 설정

  3. HTTPS 엔드포인트 생성

    • 엔드포인트 구성을 Amazon SageMaker에 제공

    • Amazon SageMaker가 ML 컴퓨팅 인스턴스를 배포하고 모델을 배포

프로덕션 환경에 ML 모델을 제공할 때 주목해야 할 점:

  1. 소프트웨어 엔지니어링 규율 적용

    • 오류 복구 코드 추가, 예기치 않은 데이터 입력에 대한 테스트 수행

    • 단위 테스트, 품질 보증, 사용자 승인 테스트 수행

  2. 데이터 소스 변화 추적 및 관리

    • 데이터 유형 변경이 전체 파이프라인에 영향을 줄 수 있음

  3. 지속적인 모니터링 및 결과 평가

    • 오류율, 오류 유형 변화 확인

    • 모델 drift 발생 여부 점검

  4. 추론 데이터를 활용한 미래 모델 개선

Amazon SageMaker는 프로덕션 버전에 대한 자동 스케일링을 지원합니다.

  1. Amazon CloudWatch 지표 기반 스케일링 정책 정의 및 적용

  2. 실제 워크로드에 따라 인스턴스 수를 자동으로 조정

  3. 프로덕션 트래픽 관리를 위해 자동 스케일링 구성을 반드시 로드 테스트

이와 같은 방식으로 ML 모델을 안정적인 프로덕션 환경에 배포할 수 있습니다.

  • SageMaker Elastic Inference

    Amazon SageMaker의 Elastic Inference는 GPU 가속 추론을 제공하는 기능입니다.

    Elastic Inference의 주요 특징은 다음과 같습니다:

    1. GPU 가속 추론 지원

      • CPU 기반 인스턴스에 GPU 추론 기능을 추가할 수 있습니다.

      • 고성능 GPU 없이도 CPU 인스턴스에서 GPU 가속 추론을 사용할 수 있습니다.

    2. 필요한 만큼의 추론 용량 확보

      • 요구되는 추론 워크로드에 맞추어 필요한 만큼의 GPU 용량을 동적으로 할당할 수 있습니다.

      • 추론 트래픽 변화에 따라 용량을 자동으로 조정합니다.

    3. 비용 효율성 향상

      • 완전 관리형 서비스이므로 GPU 하드웨어 관리 부담이 없습니다.

      • 필요한 만큼만 GPU 리소스를 사용하므로 비용 효율성이 높습니다.

    4. Amazon SageMaker 통합

      • Amazon SageMaker와 원활하게 통합되어 사용할 수 있습니다.

      • SageMaker 노트북, 트레이닝 작업, 호스팅 엔드포인트에서 Elastic Inference를 사용할 수 있습니다.

    이처럼 Elastic Inference를 통해 CPU 인스턴스에서도 GPU 가속 추론을 활용할 수 있으며, 필요한 만큼의 용량만 동적으로 확보할 수 있어 비용 효율적입니다. SageMaker와의 원활한 통합을 통해 ML 워크로드에 GPU 가속을 적용할 수 있습니다.

이 문제의 주요 키워드는 “ensemble of models”, “behind a single endpoint”, “minimal management”입니다.

정답:
Create an AWS Lambda function with Amazon API Gateway that preprocesses the incoming data. The function then creates the prediction from all the ensemble models. And finally, it returns the prediction.

이 선택지가 정답인 이유:

  • AWS Lambda와 Amazon API Gateway를 사용하여 서버리스 컴퓨팅 환경을 구축할 수 있습니다.

  • 이를 통해 ensemble 모델의 예측을 통합하고 단일 엔드포인트로 제공할 수 있습니다.

  • 또한 이 구성은 최소한의 관리만으로도 운영이 가능합니다.

오답 분석:

  1. Create an AWS Deep Learning container that preprocesses the incoming data. The container then creates the prediction from all the ensemble models. And finally, it returns the prediction.

    • 이 방식은 모델 앙상블을 제공할 수 있지만, 최소한의 관리라는 요구사항에 부합하지 않습니다.

  2. Create an Amazon EC2 instance with the AWS Deep Learning AMI that preprocesses the incoming data. The instance then creates the prediction from all the ensemble models. And finally, it returns the prediction.

    • 이 방식 역시 모델 앙상블을 제공할 수 있지만, 최소한의 관리라는 요구사항에 부합하지 않습니다.

  3. Create an Amazon SageMaker endpoint that preprocesses the incoming data. The endpoint then creates the prediction from all the ensemble models. And finally, it returns the prediction.

    • Amazon SageMaker 엔드포인트는 단일 모델만을 지원하므로, 이 문제에서 요구하는 모델 앙상블을 제공할 수 없습니다.

따라서 이 문제의 정답은 AWS Lambda와 Amazon API Gateway를 활용하는 첫 번째 선택지입니다.
