Streaming

Producer API (PutMedia)

  • Media data (sends a stream of media fragments) → KVS (assigns a unique fragment number in increasing order)

  • Fragments : self-contained **sequence of frames**

Consumer API (GetMedia)

  • KVS → Video processing applications (packed into a structured format)

  • Archived in the data store / Available in real time

Chunk

  • Copy of media metadata

  • A fragment

  • KVS specific metadata : producer-side, server-side timestamps for each fragment

Streaming Protocol

HLS (HTTP Live Streaming)

  • HTTP-based media streaming communication protocol

  • For live playback or To view archived video

  • Latency : 3 ~ 5 sec (typically) → can be 1 ~ 10 sec (depend on the use case and network conditions)

  • Codec : AVC

MPEG-DASH (Dynamic Adaptive Streaming over HTTP)

  • Adaptive bitrate streaming protocol → Hight quality streaming of media content over the internet

  • For live playback

  • Latency : 3 ~ 5 sec (typically) → can be 1 ~ 10 sec (depend on the use case and network conditions)

  • Codec : AVC or HVEC

Media Codec

Video

  • H.264 (AVC - Advanced Video Coding)

  • H.265 (HVEC - High Efficiency Video Coding)

Audio

  • AAC (Advanced Audio Coding)

  • G.711

Container

  • Contains various media codecs

  • KVS Stream uses

    • MKV (Matroska, 마트료시카) : .mkv

      • Open Standard Free container format

      • Video + Audio + Image + Subtitle → one file

    • MPEG-4

      • fMP4 (fragmented MP4) : .mp4

      • CMAF (Common Media Application Format) : .mp4

    • MPEG-2

      • TS (Transport Stream) chunks : .ts

Transcoding vs Transmuxing

Transcoding

  • Convert from 1 codec to another

  • Analog to analog / digital to digital

  • KVS does not transcode

Transmuxing

  • Convert from 1 **container** to another

  • Re-packaging, Transpackaging

  • preserve original content

Transrating

  • YouTube

  • Create different version of video : different bitrate

BitRate

  • 3 Levers

    • Compression

    • Resolution

    • Framerate

  • Codec

    • H.264 : 720@30FPS → 2Mbps

    • H.265 : 720@30FPS → 1Mbps

Alexa Integration

  • KVS WebRTC provides simple HTTP APIs to integrate with Alexa Smart Home Skills.

  • Using these APIs, the developer sends the SDP offer received from Alexa to KVS Master (device) and receives the resulting SDP answer from KVS Master, which they can use to respond back to Alexa.

  • KVS WebRTC provides ultra-low latency live stream and 2-way-audio as the video/audio feed is directly ingested from the camera to Alexa.

  • Also state the WWA (Works with Alexa) requirement for devices which support 2-way audio

  • Engage customers with headless devices, with WebRTC full duplex 2-way-audio

Reference Architecture

  1. 카메라 ODM

    1. Kinesis 비디오 스트림과 AWS IoT와 파트너가 실내, 실외, LTE 및 초인종 카메라 제품을 위한 다양한 입증 된 카메라 참조 디자인을 제공합니다.

    2. 이러한 참조 설계는 이미 AWS IoT 및 Kinesis 비디오 스트림과 통합되어 있습니다.

    3. 고객 제품 사양에 맞게 사용자 정의 할 수 있으며 해결책을 발사하기 위해 시장에 대한 위험 및 시간을 더욱 줄일 수 있습니다.

    4. 대만과 중국의 IoT Lab 팀은 고객을 대신하여 이러한 카메라 ODM과 직접 일하고 있습니다.

    5. 우리가 배웠던 것에 의해 우리는 고객이 오늘날 우리와 함께 일하고 있는 다른 카메라 ODM과 신속하게 참여할 수도 있습니다.

    6. 거의 모든 대상 고객은 카메라 ODM에서 작동합니다. 아무도 자신의 장치와 펌웨어를 스스로 개발하고 있지 않으며 항상 카메라 ODM에 항상 참여할 것입니다.

    7. 또한 카메라 ODM 파트너에게 카메라 장치를 처음 사용하는 고객에게 추천 해 드리겠습니다.

  2. IoT 및 비디오 플랫폼 파트너

    1. 모든 고객이 필요할 수있는 것은 아닙니다. 많은 스마트 홈 회사는 자신의 엔지니어링 자원을 가지고 있으며 처음부터 비디오 제품을 구축합니다.

    2. 그러나 기존 엔지니어링이 없고 너무 크고 너무 느리지 않은 Telcos와 같은 새로운 유형의 고객은 이러한 파트너와 협력하고 싶습니다.

    3. Sercomm (ADT, Comcast, ATT Life)은 IoT Core, KVS, KVS WebRTC 및 Alexa를 기반으로 한 클라우드 플랫폼을 구축했습니다.

    4. SmartCom은 아이들을 위한 Telcos 용 IoT 플랫폼을 만들었고 KVS WebRTC로 비디오에 대한 기능을 확장했습니다.

    5. Celstream은 IoT 핵심 및 KV에서 고객을위한 플랫폼을 구축하고있는 인도 기반 SI입니다.
