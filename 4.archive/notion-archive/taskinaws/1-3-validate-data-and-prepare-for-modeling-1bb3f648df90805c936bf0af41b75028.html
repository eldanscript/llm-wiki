1.3 Validate Data and Prepare for Modeling

Validate Data

Fundamentals of Data Validation

  • 데이터 무결성(Data Integrity): 데이터의 **정확성, 완전성, 신뢰성, 일관성 및 보안**을 의미

  • 데이터 검증: 데이터 준비 단계에서 수행하는 주요 작업

    • 데이터 편향(Bias) 해결: 데이터 편향으로 인한 **모델의 편파적 결과 방지**

    • 클래스 불균형(Class Imbalance) 모니터링: **편향된 데이터셋 식별 및 완화**

    • 데이터 보안 확인: 데이터 암호화 및 규제 요구사항 준수

  • 데이터 무결성 검증: 모델 학습 전 필수적인 단계

    • 편향 해결 및 보안 강화를 통해 **신뢰할 수 있는 데이터셋 구축**

    • 이후 **데이터 분할, 셔플링, 증강** 등의 데이터 **구성 준비 작업** 수행

Data Integrity (무결성)

  1. 정확성(Accuracy)

    • 데이터가 **실제 세계 프로세스를 정확하게 반영**해야 합니다.

    • 부정확한 데이터는 편향되고 부정확한 모델 예측을 초래할 수 있습니다.

  2. 완전성(Completeness)

    • 기계 **학습 작업에 필요한 모든 관련 정보가 데이터셋에 포함**되어야 합니다.

    • 누락되거나 불완전한 데이터는 편향된 모델 학습을 초래하여 최적의 성능을 발휘하지 못할 수 있습니다.

  3. 일관성(Consistency)

    • 데이터는 다양한 **소스, 시간 범위 및 특성 간에 일관성**이 있어야 합니다.

    • 일관성 없는 데이터는 모델에 노이즈를 도입하여 의미있는 패턴 학습을 어렵게 만들 수 있습니다.

  4. 신뢰성(Reliability)

    • 데이터는 **일관되고 재현 가능한 결과를 생산**할 수 있어야 합니다.

    • 신뢰할 수 있는 데이터를 사용하면 모델의 성능이 **다양한 환경에서 일관**될 것입니다.

  5. 보안(Security)

    • 데이터는 **무단 접근, 수정 또는 손상으로부터 보호**되어야 합니다.

    • **암호화, 접근 제어, 데이터 마스킹** 등의 보안 조치가 데이터 무결성 유지에 중요합니다.

https://docs.aws.amazon.com/sagemaker/latest/dg/clarify-measure-data-bias.html

  • 모델 편향 예방을 위한 데이터 검증의 중요성

    • 훈련 데이터 내 편향으로 인한 모델 편향 및 편향 재현 문제

  • 모델 학습 전 데이터 편향 측정 지표

    • 다양한 지표 활용 가능 (**데이터 불균형, 레이블 불균형** 등)

    • 검증 목적에 맞는 적절한 지표 선택 필요

  • 데이터 준비 단계에서의 편향 지표 모니터링

    • 모델 **학습 전 편향 식별 및 완화**

    • 이 과정에서는 클래스 불균형(CI)에 초점

  • 클래스 불균형(Class Imbalance, CI)

    • **한 클래스의 데이터가 다른 클래스에 비해 크게 부족**한 경우

    • 모델의 전반적인 성능 및 **일반화 능력 향상**을 위한 해결 과제

  • Class Imbalance (CI)는 데이터셋 내 각 클래스(연령 그룹)의 불균형 정도를 측정하는 지표

  • CI 분석을 통해 특정 연령 그룹이 과도하게 대표되어 있는지 확인할 수 있습니다.

Addressing Class Imbalance

Best practices for addressing class imbalance

원본 데이터 이해하기

  • 클래스 불균형의 영향을 인식하려면 **원본 데이터와 그 목적을 이해**해야 함

  • ML 모델은 예측 시 확률을 사용하므로 일부 확률은 자연스럽고 필요함

  • 데이터의 목적을 이해해야 부정적 불균형이 있는지 판단할 수 있음

깨끗한 데이터로 작업하기

  • 데이터 준비 단계에서 데이터 정제를 하지 않으면 **이상치, 형식 오류, 누락값 등으로 인해 데이터셋이 왜곡**될 수 있음

  • 클래스 불균형 검증 전에 **데이터를 철저히 정제**해야 함

프라이버시 우선하기

  • 데이터 무결성을 위해 **데이터 보안과 규제 요건 준수가 항상 최우선**임

  • 데이터 검증 시 **프라이버시와 규제 사항을 보장**해야 함

적절한 기법 선택하기

  • 다양한 데이터 검증 전략이 있으며, 각각 다른 결과를 도출함

  • 다음 섹션에서 데이터셋에 맞는 적절한 검증 기법을 선택하는 방법을 알아볼 것임

Types of data validation strategies

데이터 리샘플링(Resampling)

  • 특정 클래스에 편향된 데이터인 경우 **오버샘플링 또는 언더샘플링을 통해 클래스 분포 조정**

  • 오버샘플링: 소수 클래스 샘플 **복제 또는 합성 샘플 생성으로 개수 증가**

  • 언더샘플링: 다수 클래스 **샘플 삭제로 개수 감소**

  • 목적: 보다 균형 잡힌 클래스 분포를 만들어 **다수 클래스에 과적합되지 않도록 함**

합성 데이터 생성(Synthetic Data Generation)

  • 실제 데이터 수집 대신 **알고리즘으로 새로운 인공 데이터 생성**

  • 과소 표현된 클래스에 대해 합성 데이터를 생성하여 클래스 불균형 해결

  • 균형 잡힌 데이터셋으로 모델 학습하여 다수 클래스 편향 감소

  • **SMOTE(Synthetic Minority Oversampling Technique)**: 소수 클래스 예시 사이에서 **보간하여 합성 데이터 생성**

데이터 증강(Data Augmentation)

  • 기존 데이터에 회전, 스케일링, 크롭(cropping), 반전(flipping), 노이즈 추가 등의 변형을 가해 새로운 데이터 생성

    1. 회전(Rotation):

      • 이미지 데이터의 경우 특정 각도로 회전시켜 새로운 이미지 생성

      • 예를 들어 45도, 90도, 180도 등으로 회전하여 추가 데이터 확보

    2. 스케일링(Scaling):

      • 이미지의 크기를 확대 또는 축소하여 새로운 이미지 생성

      • 예를 들어 원본 이미지를 75%, 125% 크기로 변환

    3. 크롭(Cropping):

      • 이미지의 일부분을 잘라내어 새로운 이미지 생성

      • 예를 들어 원본 이미지의 중앙 50% 영역을 잘라내어 새 이미지 생성

    4. 반전(Flipping):

      • 이미지를 수평 또는 수직으로 뒤집어 새로운 이미지 생성

      • 예를 들어 원본 이미지를 좌우 대칭, 상하 대칭으로 변환

    5. 노이즈 추가(Adding Noise):

      • 이미지에 랜덤 노이즈를 추가하여 새로운 이미지 생성

      • 예를 들어 가우시안 노이즈, 솔트-페퍼 노이즈 등을 적용

    6. 텍스트 데이터:

      • 단어 치환: 유사한 의미의 단어로 랜덤 치환

      • 문장 shuffling: 문장 내 단어 순서 랜덤 변경

      • 문장 추가: 유사한 의미의 문장을 추가

    7. 시계열 데이터:

      • 시간 이동: 시계열 데이터를 앞뒤로 이동

      • 노이즈 추가: 시계열 데이터에 랜덤 노이즈 추가

      • 스케일링: 시계열 데이터의 값을 스케일링

    8. 오디오 데이터:

      • 볼륨 조절: 오디오 신호의 볼륨을 랜덤하게 증감

      • 속도 변경: 오디오 재생 속도를 변경

      • 주파수 필터링: 특정 주파수 대역을 제거

    이처럼 데이터의 유형에 따라 다양한 데이터 증강 기법을 적용할 수 있습니다. 이를 통해 클래스 불균형 문제를 해결하고 모델의 성능을 향상시킬 수 있습니다.

    이러한 변형 기법을 적용하면 기존 데이터를 증강하여 클래스 불균형 문제를 해결할 수 있습니다. 모델 성능 향상을 위해 다양한 변형 기법을 실험해 볼 수 있습니다.

  • 합성 데이터 생성과 달리 **실제 데이터를 기반으로 변형**

  • GAN(Generative Adversarial Network - 생성적 적대 신경망): **생성기와 판별기 간 적대적 경쟁을 통해 점점 더 실제와 유사한 합성 데이터 생성**

  • 확산 모델(Diffusion Model)도 데이터 증강에 활용 가능

데이터 증강과 합성 기법 장단점 비교

데이터 증강(Data Augmentation):

  • 장점:

    • 실제 데이터를 기반으로 하므로 보다 현실적인 데이터 생성 가능

    • **기존 데이터에 대한 이해를 높일 수 있음**

  • 단점:

    • 증강 기법의 한계로 인해 **데이터 다양성이 제한**될 수 있음

    • **과도한 증강은 오히려 모델 성능을 저하**시킬 수 있음

합성 데이터 생성(Synthetic Data Generation):

  • 장점:

    • 데이터의 **다양성과 희소 클래스에 대한 표현력 향상** 가능

    • 클래스 불균형 문제를 효과적으로 해결할 수 있음

  • 단점:

    • **실제 데이터와의 차이**로 인한 모델 성능 저하 우려

    • 데이터 생성을 위한 **추가적인 모델 훈련 필요**

Strategies to address class imbalance in different types of data

숫자 데이터:

  • 과소대표 클래스(소수 클래스) 오버샘플링

    • SMOTE 기법 활용하여 소수 클래스 데이터 증폭 (make up the minority class)

  • 과다대표 클래스(다수 클래스) 언더샘플링

    • 임의 삭제로 다수 클래스 데이터 축소

  • 주의: 실제 데이터 삭제는 정보 손실 우려

텍스트 데이터:

  • 오버샘플링/언더샘플링

    • 소수 클래스(스팸 메일) 데이터 증폭

    • 다수 클래스(정상 메일) 데이터 축소

  • 합성 데이터 생성

    • 소수 클래스 데이터와 유사한 합성 텍스트 데이터 생성

이미지 데이터:

  • GAN(Generative Adversarial Network) 활용

    • 소수 클래스(희귀 병변) 이미지 데이터 합성

    • 균형잡힌 이미지 데이터셋 구축

정답은 Text-based data augmentation 입니다.

이유:

  • 이 문제에서 홈 데코 업체가 보유한 텍스트 기반 제품 리뷰 데이터셋은 클래스 불균형이 존재합니다.

  • 긍정 리뷰는 60,000개, 부정 리뷰는 35,000개, 중립 리뷰는 5,000개로 불균형이 심각합니다.

  • 이런 경우 SMOTE와 같은 오버샘플링 기법은 적절하지 않습니다. **중립 리뷰 데이터를 인위적으로 늘리면 오히려 모델 성능이 저하될 수 있습니다.**

  • 언더샘플링으로 중립 리뷰를 줄이는 것도 바람직하지 않습니다. **실제 데이터를 손실하면 모델 성능 저하로 이어질 수 있습니다.**

  • 따라서 이 문제에서는 텍스트 기반 데이터 증강(Text-based data augmentation)이 가장 효과적인 전략입니다.

  • 이를 통해 소수 클래스(중립 리뷰)의 데이터를 합성적으로 생성하여 클래스 불균형을 해결할 수 있습니다.

AWS Tools and Services for Data Validation and Bias Mitigation

AWS Glue Data Quality

  • 데이터 품질 연속 모니터링 및 개선을 위한 관리형 서비스

  • 기업 전체의 데이터 품질 통합 확인 가능

데이터 품질 검증 사례:

  • **데이터 품질 규칙 정의**: 비즈니스 요구사항에 맞는 **사용자 정의 SQL 규칙**

  • 자동 스케줄링: **정기적인 데이터 품질 검사** 예약

  • 데이터 품질 대시보드: 데이터 **품질 지표 및 추세 시각화**

AWS Glue DataBrew

  • 코딩 없이 데이터 탐색, 정제, 변환을 위한 시각적 도구

데이터 품질 검증 사례:

  • **데이터 프로파일링**: 결측값, 이상치, 데이터 편향 등 자동 파악

  • 기본 변환: 결측값 채우기, 중복 제거, 데이터 포맷 변경 등 350개 이상의 변환 기능

  • 사용자 정의 변환: 복잡한 데이터 품질 요구사항을 위한 Python 기반 사용자 정의 변환

Amazon Comprehend:

  • 비정형 텍스트 데이터에서 인사이트 및 정보를 추출하는 NLP 서비스

  • **텍스트 데이터 품질 검증**에 활용 가능

데이터 품질 검증 사례:

  • 개체 인식: 사람, 기관, 장소, 사건 등의 개체 식별 및 추출

  • 언어 감지: 다국어 데이터셋의 언어 자동 감지

  • 토픽 모델링: 텍스트 데이터의 핵심 주제 및 테마 식별

AWS services and tools for detecting and mitigating bias - Amazon SageMaker Clarify

  • 편향 분석(Bias Analysis)

    • 성별, 인종, 소득 수준 등 **다양한 유형의 편향 시각화**

    • 데이터 및 모델 예측의 편향 문제 손쉽게 파악

  • 이상치 탐지(Outlier Detection)

    • 통계적 **이상치 자동 감지**

    • 모델 학습 전 데이터 정제 필요성 확인

  • 설명 가능성(Explainability)

    • 특성 중요도 및 SHAP (Shapley Additive Explanations) 분석을 통한 **모델 예측 요인 설명**

      1. 특성 중요도 분석:

        • SHAP 값은 각 특성이 모델 예측에 미치는 기여도를 나타냅니다.

        • 이를 통해 모델이 어떤 특성을 중요하게 활용했는지 확인할 수 있습니다.

      2. 국지적 설명력:

        • SHAP 값은 개별 데이터 포인트 단위로 계산됩니다.

        • 이를 통해 모델의 특정 예측에 대한 설명을 제공할 수 있습니다.

      3. 전역적 설명력:

        • SHAP 값을 모아 시각화하면 전체 모델의 특성 중요도 패턴을 파악할 수 있습니다.

        • 이를 통해 모델의 전반적인 동작 방식을 이해할 수 있습니다.

      SHAP 분석은 모델의 작동 원리를 투명하게 보여줌으로써 데이터 과학자가 모델을 더 잘 이해하고 개선할 수 있도록 돕습니다. 이는 모델의 품질과 신뢰성을 높이는 데 기여합니다.

    • 모델이 예상한 특성을 사용하고 있는지 검증

  • 데이터 통찰(Data Insights)

    • 데이터 분포, 결측값, 오류 등에 대한 **통계와 시각화**

    • 데이터 품질 이슈 신속하게 파악

정답은 Data validation rules입니다.

이유:

  • 이 시나리오에서 팀은 고품질 데이터가 필요한 새로운 ML 모델을 구현하고 있습니다.

  • 모델 학습에 앞서 AWS Glue Data Quality를 활용하여 데이터 품질을 평가하고자 합니다.

  • 이 경우 가장 도움이 되는 Glue Data Quality의 기능은 데이터 품질 검증 규칙(Data validation rules)입니다.

  • 데이터 품질 검증 규칙을 통해 비즈니스 요구사항에 맞는 사용자 정의 SQL 규칙을 정의할 수 있습니다.

  • 이를 통해 데이터의 정확성, 완전성, 일관성 등을 사전에 검증하고 문제를 식별할 수 있습니다.

  • 데이터 품질 모니터링, 경고, 보고 기능은 이후 단계에서 활용할 수 있는 기능이지만, 이 시나리오에서는 데이터 검증 규칙이 가장 중요합니다.

따라서 이 상황에서 가장 유용한 Glue Data Quality 기능은 데이터 검증 규칙(Data validation rules)입니다.

Identifying and Mitigating Bias with Amazon SageMaker Clarify

  1. 데이터 편향 보고서 생성하기:

    • 모델 학습 전(pre-training)과 학습 후(post-training) 편향 분석을 위한 설정 구성

  2. 데이터 편향 보고서 평가하기:

    • **클래스 불균형(Class Imbalance, CI)** 확인

    • **레이블 비율 차이(Difference in Proportion of Labels, DPL)** 분석

  • 클래스 불균형(CI):

    • 데이터셋 내 각 클래스(예: 성별, 연령)의 샘플 수 편차 확인

    • 편향된 클래스 분포는 모델 성능에 부정적 영향을 줄 수 있음

  • 레이블 비율 차이(DPL):

    • **실제 레이블 분포와 모델 예측 레이블 분포의 차이** 확인

    • 특정 그룹에 대한 편향된 예측은 모델의 공정성 문제 야기

정답: The CI measure is negative, which indicates the advantaged group is relatively underrepresented in this dataset.

이유:

  • 클래스 불균형(CI) 측정값이 -0.33인 경우,

  • CI 값이 음수(-)라는 것은 “유리한” 그룹(advantaged group)이 상대적으로 과소 대표되어 있다는 의미입니다.

  • CI 값이 양수(+)라면 “불리한” 그룹(disadvantaged group)이 상대적으로 과소 대표되어 있다고 볼 수 있습니다.

따라서 이 데이터셋에서는 유리한 그룹(예: 특정 성별 또는 연령대)이 상대적으로 부족한 것으로 볼 수 있습니다. 이는 모델 성능에 부정적인 영향을 줄 수 있으므로, 이 문제를 해결하기 위한 대책이 필요할 것입니다.

클래스 불균형(CI) 지표는 다음과 같이 계산됩니다:

CI = (na - nd)/(na + nd)

na는 다수 클래스(advantaged group)의 샘플 수

nd는 소수 클래스(disadvantaged group)의 샘플 수

  • CI 값이 음수(-)이면 다수 클래스(advantaged group)가 상대적으로 적다는 의미입니다.

    na < nd

  • CI 값이 양수(+)이면 소수 클래스(disadvantaged group)가 상대적으로 적다는 의미입니다.

    na > nd

따라서 이 문제에서 CI가 -0.33이라는 것은, 데이터셋에서 advantaged group이 상대적으로 과소 대표되어 있다는 것을 의미합니다.

CI 값의 범위는 [-1, 1] 사이입니다.

  • CI = 1 이면, nd = 0이므로 데이터셋에 disadvantaged group(소수 클래스)이 전혀 없는 것을 의미합니다.

  • CI = -1 이면, na = 0이므로 데이터셋에 advantaged group(다수 클래스)이 전혀 없는 것을 의미합니다.

따라서 CI 값이 1에 가까울수록 특정 클래스의 데이터가 압도적으로 많아 클래스 불균형이 심각한 상황이라고 볼 수 있습니다.

반대로 CI 값이 0에 가까울수록 각 클래스의 데이터가 균형을 이루고 있다고 해석할 수 있습니다.

개인식별정보(PII)

  • 영향:

    • 개인 프라이버시 보호와 규제 준수를 위해 PII 데이터 취급 주의 필요

  • 컴플라이언스 요구사항:

    • **개인의 명시적 동의 필수**

    • **암호화, 편집, 마스킹, 접근 제어 등 데이터 보안 조치 이행**

    • **개인정보 처리 방침 제공 및 개인의 권리 보장**

    • **개인 의료 정보 보호**로 의료 서비스에 대한 신뢰 유지 필수

  • 컴플라이언스 요구사항:

    • 개인의 명시적 동의 필수

    • 접근 제어, 편집, 마스킹, 감사 추적, 안전한 데이터 관리 등 보안 조치

    • **개인정보 보호 책임자 지정 및 직원 교육**

  • 영향:

    • **데이터 보관 및 처리 위치에 대한 지역별 규제** 존재(GDPR 등)

    • 데이터 **로컬라이제이션**, **국경 간 데이터 이전** 등 법적 문제 가능

  • 컴플라이언스 요구사항:

    • **사업장 소재지 및 규제 준수 파악**

    • 클라우드, 데이터 센터 등을 통한 적절한 데이터 거주지 보장

    • 변화하는 규제에 맞춰 정책 및 절차 지속 업데이트

Dividing data to reduce bias

데이터 분할: **학습, 테스트, 검증의 3분할 접근**법

학습 데이터셋(Training dataset)

  • 모델 개발의 근간

  • 데이터 내 패턴과 관계 학습

  • 모델 학습을 위한 대다수의 데이터 포함

테스트 데이터셋(Testing dataset)

  • 모델의 **일반화 능력** 평가

  • 학습에 사용되지 않은 **새로운 데이터로 성능 측정**

  • 모델이 미지의 데이터에서도 정확한 예측을 하는지 확인

검증 데이터셋(Validation dataset)

  • 테스트 데이터셋으로 인한 편향 없이 모델 파라미터 조정

  • 최적의 모델 성능 달성을 위해 **반복적인 모델 구성 조정**

Dataset Splitting, Shuffling and Augmentation

Data-splitting techniques

데이터 분할 기법

  • 간단한 홀드아웃(Simple hold-out)

    • 장점:

      • 구현이 간단

      • **빠른 모델 성능 추정** 가능

    • 단점:

      • 특정 테스트 데이터에 종속적, 성능 추정에 편차 발생 가능

      • **소규모 데이터셋에는 적합하지 않아 과적합 또는 과소적합 문제 발생**

  • 교차 검증(Cross-validation)

    • 장점:

      • 전체 데이터셋을 학습과 테스트에 모두 활용, **데이터 활용도 최대화**

      • 여러 반복을 통해 성능 추정의 편차 감소

    • 단점:

      • 계산 비용이 많이 소요, 특히 대용량 데이터셋의 경우

      • **클래스 불균형에 민감**할 수 있어 적절한 층화가 필요

  • 모델 학습 단계에서 더욱 복잡해지는 분할 기법

  • K-fold 교차 검증

    • 데이터셋을 k개의 동일한 부분집합으로 나눠 k번의 학습과 평가를 반복

    • 한 번씩 각 부분집합이 테스트셋으로 사용되고, 나머지 k-1개가 학습셋

    • 예) k=5인 경우, 5개 부분집합 중 1개는 테스트셋, 나머지 4개는 학습셋으로 사용되며 이를 5회 반복

Dataset shuffling

데이터 셔플링의 중요성

  • 데이터 **고유 구조에서 발생할 수 있는 편향 해결**

  • 다양한 데이터 예시에 모델 노출을 위해 **무작위성 도입**

데이터 셔플링 기법:

  1. **무작위 순열**(Random permutation)

    • 데이터 포인트 위치를 무작위로 교환하여 셔플

  1. **Epoch 기반 셔플링**(Epoch-based shuffling)

    • 데이터셋을 Epoch(완전 순회)단위로 나눠 각 Epoch 간 셔플

  1. **미니배치 셔플링**(Mini-batch shuffling)

    • 미니배치 내에서 데이터 포인트 무작위 셔플

랜덤화의 이점

  • 데이터 **순서에 대한 모델의 암기 방지**

  • **인접 데이터 간 종속성/상관관계 차단**

  • 데이터 **배열에 따른 학습 편향 제거**

  • 학습과 테스트에 서로 다른 무작위화 데이터 사용

데이터 셔플링을 통한 순서 편향 완화:

  • 순서 편향 해결

    • 무작위 순서로 데이터 제공하여 특정 데이터 순서에 종속적인 패턴 학습 방지

    • 다양한 상황에 적용 가능한 불변 특성을 학습하도록 장려

  • 모델 강건성 향상

    • 다양한 데이터 예시에 노출되어 실제 데이터의 변동성과 이상치 처리 능력 향상

    • 학습 데이터의 특정 패턴에 과적합되는 것을 감소시켜 미지의 데이터에 대한 성능 향상

  • 탐색 촉진

    • 전체 데이터 공간을 효과적으로 탐색하여 포괄적인 학습 가능

    • 특정 데이터 하위집합에 편향되지 않고 전체 분포에서 학습

데이터 증강(Data Augmentation)

  • 개요

    • 한정된 학습 데이터의 편향 해결을 위해 인위적으로 데이터 확장

    • 데이터에 다양한 변형을 가해 실제와 유사한 새로운 샘플 생성

  • 효과

    • 과적합 위험 감소 및 미지의 데이터에 대한 일반화 성능 향상

  • 구현

    • 사전에 증강 데이터 생성 및 저장하지 않고, 실시간 증강 적용

    • 메모리 효율적이며 무한한 데이터 변형 가능

  • 기법

    • 이미지 증강:

      • 뒤집기, 회전, 크기 조절, 기울이기

      • 노이즈 추가, 색상 변화

      • 이미지 혼합 및 블렌딩

    • 텍스트 증강:

      • 단어 교체, 삽입/삭제/교체

      • 문장 바꾸기, 언어 변환

    • 시계열 증강:

      • 시간 축 변형, 노이즈 추가

      • 시계열 데이터 혼합 및 연결

      • 생성 모델로 새로운 시계열 생성

CSV 포맷

  • 일반적인 텍스트 기반 데이터 포맷

  • 데이터를 행(샘플)과 열(특성)로 구성된 표 형식으로 저장

  • SageMaker 내장 알고리즘 입력으로 사용 가능(XGBoost, 선형 학습기, DeepAR 등)

  • 레이블은 가장 왼쪽 열, 특성은 그 오른쪽에 위치

RecordIO-protobuf 포맷

  • SageMaker의 효율적인 **데이터 저장 및 전송을 위한 이진 데이터 포맷**

  • **대용량 데이터셋 처리, 자동 데이터 변환에 유용**

  • 각 레코드는 protobuf 메시지로 인코딩된 이진 데이터로 구성

  • 주로 **이미지 데이터에 사용**되며, 각 레코드는 이미지와 메타데이터를 포함

  1. Amazon S3를 통한 데이터 업로드:

  • S3 버킷 생성

  • 데이터 파일을 S3 버킷에 업로드

    • 적절한 폴더 구조 및 파일 이름 관례 준수

  • S3 버킷 액세스 권한 구성

    • ML 리소스의 읽기/쓰기 권한 설정

  1. Amazon EFS 또는 Amazon FSx 마운트:

    • Amazon EFS

      • 확장 가능한 파일 시스템, ML 워크로드에 활용

      • EFS 파일 시스템 생성 후 보안 그룹, 네트워크 설정 구성

    • Amazon FSx

      • Windows File Server, Lustre 등 파일 시스템 지원

      • Amazon FSx 파일 시스템 생성 후 적절한 프로토콜 구성

  2. Amazon S3에서 EFS/FSx로 데이터 복사:

    • AWS 데이터 전송 유틸리티 또는 사용자 스크립트 사용

    • 파일 시스템의 충분한 저장 공간 확보

    • 전송 완료 후 파일 크기, 체크섬 확인으로 무결성 검증

  3. ML 학습 리소스에 데이터 로드:

    • EFS/FSx 마운트 경로에서 데이터 로드

    • 공유 파일 저장소로 다수의 EC2 인스턴스 동시 접근 가능

  4. 모니터링, 최적화, 자동화, 보안 강화:

    • 데이터 수명주기 관리, 워크플로우 자동화

    • CI/CD 도입으로 모델 업데이트 및 배포 효율화

    • 암호화, 액세스 제어 등 보안 조치 구현 및 지속 관리
