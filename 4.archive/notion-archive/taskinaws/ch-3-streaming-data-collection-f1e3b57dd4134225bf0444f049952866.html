Ch.3 Streaming Data Collection

Concept

Static Data

  • Data that’s not changing

  • Most of the in-house datasets collected and stored in a data warehouse, or a data lake, is considered static data

Streaming Data

  • Constantly being updated, or continuously being added onto during the data collection process

Kinesis Data Streams

  • Use Kinesis streams to transfer, or load, or stream that data into AWS

Data Producer

  • Different devices or applications that produce streaming data : 스트리밍 데이터를 생성하는 디바이스나 애플리케이션을 지칭

  • Typically have some type of JSON data as the payload : 데이터 페이로드로 JSON을 사용하거나

  • Use any type of data that they can fit into a data blob : 데이터 블랍 (Binary Large Object)에 맞는 데이터를 사용

  • Application log files or social media streams, clickstream data or user interaction for an online website or application

  • Real time user interaction from video games, IoT devices or manufacturing devices in a factory

Shard

  • Kinesis streams carries that data using these things called shards

  • Data is contained within a shard

  • Container that holds the data that we want to send into AWS : 샤드는 AWS로 전송하는 데이터를 담고 있는 컨테이너

Data Consumer

  • Process or analyze that data

    • EC2 Instances

    • Lambda functions where do real time ETL processes)

    • Kinesis Data Analytics to run real time SQL queries on streaming data

    • Send to an EMR cluster and process it using Apache Spark

  • Have multiple consumers consume the data stream, or consume those shards and perform different processes

    • Process the data

    • Further analyze the data

    • Send it off to a data store within AWS : S3, DynamoDB, RedShift

Shard Details

  • Wrapper or the container that contains all of the streaming data that we want to load into AWS

  • Made up of a couple of different parts

    • Unique partition key for each shard

    • Each payload creates a sequence which is associated with a shard

  • The more requests, and the larger payload gets, determine how many shards use

    • of shards : 1 ~ 500 (default) → can request increases to unlimited shards

  • Parts of Shards

    • A partition key (a train id)

    • A sequence number (train car)

    • A data (passenger)

  • Shard consists of a sequence of data records

    • Data records is the unit of data captured : Data reocrd는 데이터 캡쳐 단위 임

    • Data records can be ingested at 1K records per second

  • Data record

    • sequence number

    • partition key

    • data blob (payload) : ~ to 1MB

  • Transient Data Store : 일시적인 데이터 저장소

    • retention period : 24 hours ~ 7 days

Interacting with Kinesis Data Streams

  • Kinesis Producer Library (KPL)

    • Library allows to write to a Kinesis Data Stream

    • Provide a layer of abstraction specifically for ingesting data

    • Optimal stream with retry mechanisms, optimizing throughput and aggregating records together

      • Automatic and configurable retry mechanism

      • Additional processing delay can occur for higer packing efficiencies and better performance

    • Java wrapper → Implement using **Java**

    • The KPL performs the following primary tasks

      1. Writes to one or more Kinesis streams with an automatic and configurable retry mechanism

      2. Collects records and uses PutRecords to write multiple records to multiple shards per request

      3. Aggregates user records to increase payload size and improve throughput

      4. Integrates seamlessly with the Amazon Kinesis Client Library (KCL) to de-aggregate batched records on the consumer

      5. Submits Amazon CloudWatch metrics on your behalf to provide visibility into producer performance

  • Kinesis Client Library (KCL)

    • Install the KPL on EC2 Instances or integrate it directly into Java applications

    • Integrated directly with KPL for consumer applications

  • Kinesis API (AWS SDK)

    • Perform all of the same actions with KPL or KCL

    • Used for more of low-level API operatios and more manual configuration

    • Low level API operations to send records to a Kinesis Data Stream

      • PutRecords

      • GetRecords

    • Stream creation, reshadring, putting and getting records are manually handled

    • No delays in processing

      • Need data stream immediately available within milliseconds, it may be better to use the Kinesis API

    • Use any of AWS SDKs → C#, JavaScript, …

Use Case

  • Needs to be processed by consumers

  • Real time analytics

  • Feed into other serivces in real time

  • Some action needs to occur on data

  • Storing data is optional

  • Data retention is important

  • Case

    • Analyze system and application logs continuously and process within secodns

    • Run real time data analytics on click stream data and process it within seconds

Kinesis Firehose

  • Delivery service for streaming data

  • Output data onto, or deliver data onto like RedShift, S3, Splunk, and Amazon Elastic Search

  • Data Producers → Processing Tools (Lambda, like ETL service) → Storage (S3, RedShift, ElasticSearch, Splunk)

Data Stream vs Firehose

  • Data Stream has shards and data retention

    • If there’s some failure in processing tools, then Data Streams holds onto that data to be able to re-process it

  • Firehose don’t have to worry about shards

    • Mainly used for streaming data directly into some storage or data repository

Use Case

  • Easily collect streaming data

  • Processing is optional

  • Final destination is S3

  • Data retention is not important

  • Case

    • Stream and store data from devices : Capturing importatn data from IoT devices, embedded systems, consumer applications and storing into a data lake

    • Create ETL jobs on streaming data : Running ETL josb on streaming data before data is stored into a data warehousing solution

Kinesis Video Streams

  • Allow to stream video into the AWS cloud

  • Data Producers (Video or Audio) → Data Consumers (Continuous Consumer or Batch Consumer) → Storage (S3)

Use Case

  • Needs to process real-time streaming video data (audio, images, radar)

  • Batch processing and store streaming video

  • Feed streaming data into other AWS services

Kinesis Data Analytics

  • Allows to continuously read and process streaming data in real time

  • Using SQL queries to process the incoming streaming data and produce some output data from that

  • Streaming Input (Data Streams, Data Firehose) → Data Analytics (Run real-time SQL queris) → Storage and Visuals (S3, RedShift, BI tools)

  • Run complex SQL queries like transform date times or change data types possibly change column names

  • Can do complex joins and do all of this on streaming data in a real time and then stored off into S3

Use Case

  • Run SQL queries on streaming data

    • Use SQL or Apache Flink

  • Construct applications that provide insight on data

  • Create metrics, dashboards, monitoring, notifications and alarms

  • Output query results into S3 or other AWS datasources

  • Responsive real time analytics : Send real time alarms or notifications when certain metrics reach predefined threshold

  • Stream ETL jobs : Stream raw sensor data then, clean, enrich, organize, and transform it before it lands into data warehouse or data lake
