Build & Deploy MicroService using Fargate

Architecture

  • 종종 단일 데이터베이스에 직접 통신하는 다양한 서비스가 있는 경우가 많음 (하나의 응용 프로그램으로 인덱스 추가 및 데이터 마이그레이션을 수행)

  • 주어진 자원의 모든 로직을 별도의 서비스로 분리하는 대신 “processing” 비즈니스 로직만 별도의 서비스로 이동하고 모노리스 앱을 데이터베이스 앞의 facade로 계속 사용하는 것으로 mircoservice 구축을 시작

  • 이런 방식을 때때로 Strangler Application 패턴이라고 하며, 우리는 그림(아키텍쳐 그림을 의미 하지 않을까?)에서 모놀리스를 교살(strangling)하고 완전히 교체할 수 있을 때까지 가장 꺼내기 힘든 부분에만 계속 사용합니다.

  • Microservice로 아키텍쳐를 재 설계 하는 과정에서 모든 것을 무리하게 분리하는 것이 아니라 Strangler pattern 등을 이용하여 일부는 monolith를 유지하면서 점진적으로 변경해 갈 수 있다. (my opinion)

  • Green box : monolith, Yellow box : microservice
