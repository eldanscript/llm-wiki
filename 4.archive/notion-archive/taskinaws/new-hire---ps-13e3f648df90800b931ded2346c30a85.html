데이터베이스 구성 및 캐시 시스템

Q) MSA에서의 DB 구성과 캐시 시스템에 대해 설명해 주세요.

A) 광고주 사이드에서는 단일 MySQL 서버를 사용하여 입찰 데이터를 관리합니다. 누적된 데이터는 광고 타입에 따라 적절한 데이터 스토리지를 사용합니다. 로컬 메모리와 Redis Pub/Sub 구조를 활용하여 확장성을 확보했습니다. 랭킹을 위한 퀄리티 스코어는 Solr 검색을 통해 실시간 처리합니다. 광고 관련 로그는 통합하여 Hadoop 기반의 HIVE로 처리합니다.

Redis에서 MongoDB로 일부 캐시 시스템을 전환했는데, 이는 대량의 후보군을 실시간으로 랭킹하고 광고 정책에 따라 유연하게 수정할 수 있도록 하기 위함입니다. MongoDB를 사용함으로써 스트림의 원자성을 유지하면서 성능을 개선할 수 있었습니다.

고가용성 및 로그 분석

Q) VM 서버의 고가용성 유지와 로그 분석 데이터 파이프라인에 대해 설명해 주세요.

A) VM 서버의 고가용성을 위해 경량화된 VM을 여러 개 연결하고 예비 풀을 유지합니다. 시뮬레이션으로 설정한 메트릭을 통해 예비 풀을 활용하여 버스트 트래픽에 대응합니다.

로그 분석 데이터 파이프라인은 다음과 같이 구성했습니다:

  1. 레거시 로그를 통합하여 신규 플랫폼에 적용

  2. 과금 관련 로그는 Kafka 스트림으로 전송 후 HIVE로 저장

  3. 실시간 데이터 인덱싱을 위해 Druid 사용

  4. 로그 표준화는 커스텀 필드를 활용하여 수행

Druid를 선택한 이유는 지표성 데이터를 SQL 기반으로 지원하고 숫자성 aggregation에 적합하기 때문입니다.

데이터 관리 및 보안

Q) 데이터 규모 증가 대응, 가용성 유지, 보안 유지 방법에 대해 설명해 주세요.

A) 데이터 규모 증가에 대응하기 위해 데이터 retention 주기 설정과 Pre-aggregation을 활용합니다. Druid의 indexing range를 활용하여 확장되는 로그 데이터에 대응합니다.

데이터 가용성 유지를 위해 Hadoop은 레플리카를 설정하고, 중요 데이터는 히스토리 조회로 row 단위 재처리가 가능하도록 합니다. Redis의 경우 AOF를 실행하여 원본 데이터 복구가 가능하도록 합니다.

데이터 보안을 위해 리포트 서버를 통해 인증된 사용자만 접근할 수 있도록 하며, aggregation 서버를 통해 데이터를 제공합니다. 개인정보 보호를 위해 비실명 식별자를 사용합니다.

향후 기술 도입 계획

Q) 향후 도입을 검토 중인 기술이 있다면 말씀해 주세요.

A) 현재 AI 기술을 활용하여 셀러들의 상품 이미지 관리를 개선하는 방안을 검토 중입니다. 구체적으로는 object detection을 통한 상품 이미지 분리(누끼) 기능과 LLM을 활용한 손상된 이미지 복원 기능을 연구하고 있습니다. TensorFlow에 공개된 모델을 기반으로 리서치를 진행 중입니다.

    • 몽고디비의 경우 대량의 후보군을 가져와서 실시간 랭킹을 세우게 될 때, DA나 스케줄 등의 실시간으로 수정이 필요한데 광고 정책에 따라 일부 수정이 필요하게 될 경우 키에 여러 가지 데이트를 묶어서 사용하게 되면 일부 데이터가 영향을 미칠 수 있기 때문에 스트림의 원자성을 유지하면서 성능을 유지하기 위해 사용하게 되었음

  • Q) VM 서버의 경우 고가용성 유지를 위해 작업한 내용은?

    • 경량화된 VM을 여러 개를 연결하고 예비 풀을 유지하면서 시뮬레이션으로 설정한 메트릭을 통해 예비 풀을 사용

  • Q) 로그 분석 데이터 파이프라인 어떻게 설계 하였는가?

    • 레거시 플랫폼에서 파편화 된 로그들을 수동으로 수정하여 적용하였음

    • 신규 플랫폼에서는 미디에이션 서버를 통해 효율이 좋은 광고를 중개해주게 되는데 상품의 우선 순위를 한번에 조회하기 위해 통합된 로그로 변환

    • 과금 성 로그는 Kafka 스트림으로 전송 → 해당 토픽의 내용을 HIVE로 insert

    • 실시간 성 데이터 인덱싱을 위해 Druid를 사용하여 히스토리 및 CTR, 매출 등에 대한 지표를 빠르게 응답할 수 있게 사용

    • ElasticSearch 등과 비교해 보면 → Druid 특성이 지표성 데이터를 SQL 기반으로 지원하기 때문에 사용성이 높음, 숫자성 aggregation에 좀더 적합

    • 로그 표준화 작업은 어떤 단계에서 수행이 되었는가? → 커스텀 필드를 활용하여 수용이 가능하다고 판단하여 활용

  • Q) 로그 데이터의 규모 증가에 대해 어떻게 대응 했는지?

    • 물리적 데이터가 늘어나는 경우에 대해서는 데이터 retention 주기 설정을 통해 관리 → Pre-aggregation을 사용하여 저장 공간을 보장

    • Druit의 indexing range을 활용하여 확장되는 로그 데이터에 대해 대응

  • Q) 데이터 가용성을 유지하기 위해 사용한 방법은?

    • Hadoop은 레플리카를 통해 설정

    • 중요 데이터의 경우 (과금 결과 데이터) 히스토리 조회로 row 단위로 재 처리 할 수 있도록

    • 레디스 AOF를 실행하여 원래 데이터를 찾아가도록 함

  • Q) 데이터 보안 유지는 어떻게 ?

    • 개인정보에 대해서는 비 실명 식별자를 사용

  • Redis에서 MongoDB로 캐시 시스템을 전환한 이유에 대해 설명해 주세요. 어떤 문제를 해결하기 위해 전환하게 되었는지 MongoDB의 어떤 특성이 이 문제를 해결해 주었나요?

    1. “Redis에서 MongoDB로 캐시 시스템을 전환한 주요 이유는 데이터의 복잡성 증가와 쿼리 요구사항의 변화 때문입니다. Redis 스트림을 사용했을 때 다음과 같은 문제점들이 발생했습니다:

    2. 데이터 구조의 제한: Redis 스트림은 단순한 키-값 구조에 최적화되어 있어, 복잡한 데이터 구조를 효율적으로 저장하고 쿼리하는 데 한계가 있었습니다[1].

    3. 메모리 제한: Redis는 주로 인메모리 데이터베이스이기 때문에, 대용량 데이터를 처리할 때 메모리 사용량이 급격히 증가했습니다[5][7].

    4. 복잡한 쿼리 지원 부족: 데이터가 복잡해지면서 더 다양하고 복잡한 쿼리가 필요해졌는데, Redis는 이러한 복잡한 쿼리를 효율적으로 지원하지 못했습니다[7].

    5. 데이터 지속성 문제: Redis의 데이터 지속성 옵션은 있지만, 주 용도가 인메모리 저장소이기 때문에 데이터 손실 위험이 상대적으로 높았습니다[7].

    MongoDB의 다음과 같은 특성들이 이러한 문제들을 해결해 주었습니다:

    1. 유연한 데이터 모델: MongoDB의 문서 기반 모델은 복잡하고 중첩된 데이터 구조를 쉽게 저장하고 조작할 수 있게 해주었습니다[4][5].

    2. 디스크 기반 저장: MongoDB는 디스크 기반 저장을 사용하여 대용량 데이터를 효율적으로 관리할 수 있게 해주었습니다[5][7].

    3. 강력한 쿼리 기능: MongoDB Query Language (MQL)를 통해 복잡한 쿼리, 집계, 전문 검색 등을 수행할 수 있게 되었습니다[5][7].

    4. 데이터 지속성 향상: MongoDB의 디스크 기반 저장 모델은 데이터의 지속성과 내구성을 크게 향상시켰습니다[7].

    5. 확장성: MongoDB의 샤딩 기능을 통해 수평적 확장이 가능해져, 증가하는 데이터 양을 효과적으로 처리할 수 있게 되었습니다[5].

    이러한 MongoDB의 특성들이 우리의 캐시 시스템 요구사항에 더 적합했기 때문에 전환을 결정하게 되었습니다.”

    이 답변은 Redis의 한계점과 MongoDB의 장점을 대비시켜 설명하면서, 특정 사용 사례에 따라 데이터베이스 선택이 달라질 수 있음을 보여줍니다. 또한 실제 경험에 기반한 구체적인 문제점과 해결책을 제시하여 신뢰성을 높이고 있습니다.

답변: AWS에서 실시간 데이터 처리를 위해 다음 서비스들을 활용할 수 있습니다:

  4. 데이터 분석: Amazon Athena를 사용하여 SQL 기반의 임시 쿼리 수행

  5. 데이터 시각화: Amazon QuickSight를 사용하여 대시보드 생성 및 BI 분석

EMR은 Spark나 Hive 작업을 통해 대규모 데이터 처리에 사용되며, Athena는 저장된 데이터에 대한 빠른 SQL 쿼리를 가능하게 합니다. QuickSight는 처리된 데이터를 시각화하여 의사결정을 지원합니다.
