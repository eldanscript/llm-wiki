    💡

    SAML을 사용하여 외부 ID 공급자와 통합할 때, IAM Identity Center는 서비스 제공자(SP)로 작동하며, 외부 ID 공급자는 ID 공급자(IdP)로 작동합니다.

    1. 사용자가 AWS 리소스에 액세스하려고 할 때, 사용자는 먼저 외부 ID 공급자에 인증됩니다.

    2. 그 후 외부 ID 공급자는 SAML 응답을 IAM Identity Center의 ACS URL로 보냅니다.

      1. ACS (Assertion Consumer Service) : IAM Identity Center에서 SAML 인증 응답(assertion)을 수신하고 처리하는 서비스

      2. ACS URL : IAM Identity Center가 SAML 응답을 수신하고 처리할 수 있도록 하는 엔드포인트

    3. IAM Identity Center는 이 SAML 응답을 수신하고 처리하여 사용자의 AWS 리소스 액세스를 허용합니다.

SCIM federation

AWS IAM Identity Center supports provisioning users and groups from Okta using the SCIM (System for Cross-domain Identity Management) standard. 1(https://docs.aws.amazon.com/singlesignon/latest/userguide/gs-okta.html)

Some key points about SCIM federation between IAM Identity Center and Okta: 2(https://docs.aws.amazon.com/singlesignon/latest/userguide/scim-profile-saml.html)

  • IAM Identity Center acts as the SCIM service provider, while Okta is the SCIM identity provider.

  • Okta can automatically provision (create, update, deactivate) users and groups in IAM Identity Center based on assignments in Okta.

  • Attribute mapping between Okta and IAM Identity Center must be configured to match user data between the two systems.

  • SCIM allows bi-directional synchronization, so changes in either system can update the other over time.

  • Automatic provisioning helps maintain a single user directory across Okta and AWS managed applications/accounts.

The AWS documentation provides a detailed guide on setting up this integration, including configuring the SCIM connection in Okta and testing provisioning workflows. Let me know if you need help with any part of the Okta-IAM Identity Center SCIM federation process.

SAML federation

Yes, AWS IAM Identity Center supports identity federation with Okta using SAML 2.0 (Security Assertion Markup Language). 1(https://aws.amazon.com/blogs/aws/aws-identity-and-access-management-using-saml/)

When setting up SAML federation between IAM Identity Center and Okta: 2(https://docs.aws.amazon.com/singlesignon/latest/userguide/gs-okta.html)

  • Okta acts as the SAML identity provider (IdP) while IAM Identity Center is the SAML service provider. 3(https://repost.aws/knowledge-center/iam-identity-center-federation)

  • In Okta, you’ll need to configure IAM Identity Center as a SAML 2.0 application, generating metadata that gets uploaded to IAM Identity Center. 4(https://aws.amazon.com/blogs/apn/improve-the-availability-of-existing-okta-iam-federation-setup-using-multi-region-saml-endpoints/)

  • In IAM Identity Center, you can add Okta as a SAML identity provider. This establishes the trust relationship.

  • Users in Okta can then be assigned to the IAM Identity Center application and federated SSO enabled.

  • Federated users can access AWS accounts and applications linked to IAM Identity Center single sign-on using their Okta credentials.

The AWS documentation provides a detailed step-by-step guide for configuring SAML between IAM Identity Center and Okta. Let me know if you need help with any part of the setup or have additional questions!
