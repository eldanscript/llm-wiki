Domain 3. Modeling

Objectives

  • Framing business problems as ML problems

  • Selecting the appropriate model(s) for a given ML problem

  • Training ML models

  • Performing hyperparameter optimization

  • Evaluating ML models

Domain 3.1: Frame business problems as ML problems

기계 학습이 적절한 해결책인지 먼저 고려해야 합니다.

기계 학습은 데이터에 숨겨진 패턴을 찾아내어 예측을 하는 기술입니다. 많은 양의 데이터를 가지고 모델을 훈련하면 점점 더 정확한 예측을 할 수 있습니다.

신용카드 거래 내역의 이상 거래를 탐지하는 것은 기계 학습이 적절한 사용 사례입니다. 수백만 건의 과거 거래 내역 데이터에서 정상 거래와 사기 거래의 패턴을 찾아내기는 사람이 직접 하기 어렵기 때문입니다. 이런 경우 기계 학습 모델을 이용하면 효과적으로 문제를 해결할 수 있습니다.

하지만 간단한 규칙이나 계산으로 목표값을 결정할 수 있는 경우에는 기계 학습이 적절하지 않습니다.

기계 학습을 적용해야 하는 경우

  1. 규칙을 코딩할 수 없는 경우
  • 스팸 메일 구분 등 많은 요인이 영향을 미치는 문제에서는 단순한 규칙 기반 솔루션으로는 부족합니다. 기계 학습을 이용하면 이런 문제를 효과적으로 해결할 수 있습니다.
  1. 규모를 확장하기 어려운 경우
  • 수작업으로는 소량의 데이터만 처리할 수 있지만, 기계 학습을 이용하면 대량의 데이터도 효과적으로 처리할 수 있습니다.

기계 학습 알고리즘

지도 학습과 비지도 학습이 있으며, 각각 다양한 문제 유형에 적용될 수 있습니다.

지도 학습(Supervised Learning)

  • 지도 학습은 가장 널리 사용되는 기계 학습 방식 중 하나 입니다.

  • 지도 학습 알고리즘은 **변수 간의 관계와 알려진 결과 사이의 패턴을 학습** 합니다.

  • 예를 들어, 이미지 인식 문제에서 모델에 동물 사진과 정답 라벨을 학습시키면, 새로운 사진에서 어떤 동물인지 예측할 수 있습니다.

  • 지도 학습은 **이미 동작하고 있는 시스템을 모델링할 수 있는 경우에 효과적**입니다. 즉, 정확하게 라벨링된 관측치를 가지고 있거나 얻을 수 있어야 합니다.

비지도 학습(Unsupervised Learning)

  • 비지도 학습은 훈련 데이터에 라벨이 없고 **입력과 출력의 관계를 미리 알 수 없는 경우에 사용**됩니다.

  • 대표적인 비지도 학습 알고리즘인 클러스터링은 데이터 포인트들을 유사한 특성을 가진 클러스터로 그룹화합니다.

  • 예를 들어, 사무 용품 고객 구매 패턴 분석에서 클러스터링을 통해 소규모 기업과 대규모 기업 고객 그룹을 발견할 수 있습니다.

  • 이를 통해 기업 규모별로 다른 마케팅 전략을 수립할 수 있습니다.

요약하면, 지도 학습은 정답이 주어진 데이터로 모델을 훈련하는 반면, 비지도 학습은 데이터 자체의 패턴을 찾아내는 방식입니다. 각각의 방법론은 문제 상황에 따라 적절하게 선택될 수 있습니다.

지도 학습 : 분류 문제와 회귀 문제

분류 문제에는 이진 분류와 다중 분류가 있습니다.

  • 이진 분류: **2개의 범주 중 하나**로 분류하는 문제 (예: 거래가 정상인지 사기인지)

  • 다중 분류: **3개 이상의 범주 중 하나로 분류**하는 문제 (예: 고객이 어떤 부서에 문의했는지)

회귀 문제는 **연속적인 수치 값을 예측**하는 문제입니다 (예: 주가 예측).

  • the target is numeric and it’s a regression problem

  • target is binary and it’s a classification problem

  • Frame in the simplest form, but make sure you aren’t losing important information

Domain 3.2: Select the appropriate model(s) for an ML problem

문제의 형태에 따라 사용할 수 있는 알고리즘이 달라집니다. 따라서 다양한 알고리즘의 특성을 이해하는 것이 중요합니다. 여기에는 Amazon SageMaker에서 제공하는 내장 알고리즘도 포함됩니다.

예를 들어 다음과 같은 ML 문제가 있다고 가정해 보겠습니다.

  1. 이진 분류 문제: “과거 고객 반응을 바탕으로 이 고객에게 메일을 보내야 하나요?” (예/아니오)

  2. 다중 분류 문제: “과거 고객 세분화 결과를 바탕으로 이 고객이 어느 세그먼트에 속하는가?” (빈둥지족, 교외 가족, 도심 전문직 등)

  • Amazon SageMaker의 **Linear Learner, XGBoost, K-Nearest Neighbors** 알고리즘을 사용할 수 있습니다.
  1. 회귀 문제: “과거 메일링 ROI를 바탕으로 이 고객 메일링의 ROI는 얼마인가?”
  • 이 경우 회귀 문제에 해당하며, Linear Learner, XGBoost 알고리즘을 회귀 문제에 맞게 하이퍼파라미터를 조정하여 사용할 수 있습니다.

Amazon SageMaker에는 자연어 처리(NLP)와 컴퓨터 비전(CV) 분야의 내장 알고리즘도 제공됩니다:

  • NLP: BlazingText(Word2Vec, 텍스트 분류), Sequence2Sequence, Object2Vec

  • CV: Image Classification, Object Detection, Semantic Segmentation

이 외에도 Apache Spark와 함께 SageMaker를 사용하거나, TensorFlow, MXNet 등의 딥러닝 프레임워크로 직접 코드를 구현하는 방법, AWS Marketplace에서 알고리즘을 구독하는 방법 등 다양한 옵션이 있습니다.

SageMaker Built-In algorithm & model

  1. 지도 학습 알고리즘:

    • **AutoGluon-Tabular**: 앙상블 모델링을 통한 자동화된 기계학습 프레임워크

    • **CatBoost**: 범주형 변수 처리와 gradient boosting 트리 알고리즘

    • **Factorization Machines** Algorithm: 고차원 희소 데이터셋의 특성 상호작용 모델링

    • **K-Nearest Neighbors** (k-NN) Algorithm: 근접 이웃 기반 **분류 및 회귀**

    • **LightGBM**: 효율성과 확장성이 향상된 gradient boosting 트리 알고리즘

    • **Linear Learner** Algorithm: 선형 모델 기반 분류 및 회귀

    • **TabTransformer**: 자기 주의 기반 (self-attention-based) 트랜스포머를 이용한 테이블 데이터 모델링

      • Use Case

        TabTransformer는 주로 **표 형태의 구조화된 데이터를 다루는 회귀 및 분류 문제에서 사용**됩니다. 다음과 같은 경우에 TabTransformer가 유용할 수 있습니다:

        1. 금융 및 경제 데이터 분석

        • 주식, 채권, 외환 등의 금융 데이터

        • 거시 경제지표, 기업 재무 데이터 등

        1. 고객 데이터 분석

        • 고객 정보, 구매 내역, 서비스 사용 기록 등

        • 고객 이탈 예측, 고객 세분화, 타겟 마케팅 등에 활용

        1. 센서 데이터 분석

        • 온도, 습도, 압력, 속도 등의 센서 측정값

        • 제조, 건설, 교통 등 다양한 산업 분야에 활용

        1. 의료 데이터 분석

        • 환자 기록, 검사 결과, 약물 처방 데이터 등

        • 질병 예측, 위험 인자 분석, 맞춤형 치료 등에 활용

        1. 사기 거래 탐지

        • 신용카드 거래 내역, 계좌 활동 데이터 등

        • 비정상적인 거래 패턴을 식별하여 사기 탐지에 활용

        TabTransformer는 표 형태의 복잡한 데이터 구조를 잘 처리할 수 있고, 비선형 관계도 효과적으로 모델링할 수 있습니다. 따라서 다양한 산업 분야의 구조화된 데이터 문제에서 우수한 성능을 보일 수 있습니다.

      • What Transformer?

        Sel-Attention 기법은 Transformer 모델의 핵심 구성 요소입니다. Transformer에서 Sel-Attention은 다음과 같이 활용됩니다:

        1. 장거리 의존성 모델링

        • Sel-Attention은 **입력 시퀀스의 모든 토큰 간 관계를 모델링**할 수 있습니다.

        • 이를 통해 **장거리 의존성을 효과적으로 포착**할 수 있어, 장문 텍스트 처리에 유리합니다.

        1. 병렬 처리 효율성

        • Sel-Attention은 순차적 처리가 아닌 **병렬 처리**가 가능합니다.

        • 이는 기존 순차적 **RNN/LSTM 모델보다 속도와 메모리 효율성**이 높습니다.

        1. 해석 가능성

        • Sel-Attention 가중치를 시각화하면 모델의 작동 원리를 이해할 수 있습니다.

        • 이는 **모델의 투명성과 신뢰성**을 높일 수 있습니다.

        Transformer를 사용하는 이유는 다음과 같습니다:

        1. 높은 성능

        • Transformer는 다양한 NLP 태스크에서 SOTA 성능을 보입니다.

        • Sel-Attention을 통해 장기 의존성을 잘 포착할 수 있기 때문입니다.

        1. 범용성

        • Transformer는 텍스트, 이미지, 비디오 등 **다양한 데이터 모달리티에 적용**될 수 있습니다.

        • 이를 통해 하나의 일반화된 아키텍처로 여러 과제를 해결할 수 있습니다.

        1. 병렬 처리 효율성
        • Transformer는 RNN/LSTM 대비 병렬 처리가 가능해 빠른 학습이 가능합니다.
        1. 해석 가능성
        • Sel-Attention 가중치 분석을 통해 모델 내부 작동 원리를 이해할 수 있습니다.

        따라서 Transformer는 다양한 도메인의 구조화된 데이터 문제에서 뛰어난 성능과 해석 가능성을 제공할 수 있는 강력한 모델 아키텍처라고 볼 수 있습니다.

      • 상세 분석

        TabTransformer: Tabular Data에 Transformer 아키텍처를 적용한 혁신적 모델

        TabTransformer는 테이블 형식 데이터(tabular data)에 Transformer 아키텍처를 적용한 혁신적인 딥러닝 모델입니다. 이 모델은 자연어 처리에서 큰 성공을 거둔 Transformer의 장점을 테이블 데이터 분석에 효과적으로 접목시켰습니다.

        TabTransformer의 등장 배경과 필요성

        기존 Tabular Data 모델링의 한계

        테이블 형식 데이터는 추천 시스템, 온라인 광고 등 다양한 분야에서 가장 널리 사용되는 데이터 유형입니다[1]. 현재 tabular 데이터 분석 분야에서 가장 높은 성능을 보이는 모델은 Gradient Boosted Decision Tree(GBDT)와 같은 앙상블 기반의 트리 모델입니다[1]. 하지만 이러한 트리 기반 모델은 다음과 같은 여러 한계점을 가지고 있습니다:

        1. 스트리밍 데이터를 사용한 훈련에 적합하지 않음[8]

        2. 테이블 데이터와 이미지/텍스트를 함께 처리하는 멀티모달 학습에서 end-to-end 학습이 불가능[8]

        3. 준지도학습(semi-supervised learning) 적용이 어려움[1]

        4. 결측치와 노이즈가 많은 데이터 처리에 한계 존재[8]

        다른 한편으로, 다층 퍼셉트론(MLP)과 같은 딥러닝 모델은 경사하강법을 통해 학습이 가능하고 end-to-end 학습이 가능하다는 장점이 있지만, 다음과 같은 한계가 있습니다:

        1. 학습된 임베딩과 모델의 해석이 어려움[8]

        2. 결측치와 노이즈에 취약함[8]

        3. 준지도학습에서 경쟁력 있는 성능을 내지 못함[8]

        4. GBDT와 같은 트리 기반 모델의 성능에 미치지 못함[1][8]

        이러한 기존 모델들의 한계를 극복하기 위해 TabTransformer가 등장했습니다.

        TabTransformer의 핵심 구조와 작동 원리

        TabTransformer는 다음과 같은 세 가지 주요 구성 요소로 이루어져 있습니다:

        1. **Column Embedding Layer**: 범주형 변수를 임베딩 벡터로 변환합니다.

        2. **Transformer Layers**: 범주형 변수의 임베딩을 컨텍스트 임베딩으로 변환합니다.

        3. **Multi-Layer Perceptron (MLP)**: Transformer에서 나온 컨텍스트 임베딩과 연속형 변수를 결합하여 최종 예측을 수행합니다.

        TabTransformer의 주요 특징은 범주형 변수와 연속형 변수를 다르게 처리한다는 점입니다[5]. **범주형 변수**는 먼저 Column Embedding을 통해 임베딩 벡터로 변환된 후, 여러 Transformer 레이어를 통과하면서 **컨텍스트 임베딩으로 변환**됩니다. 반면, **연속형 변수**는 Layer Normalization을 거친 후 최종 **MLP 레이어**로 바로 전달됩니다[5].

        이러한 구조적 특성은 테이블 데이터의 특성을 효과적으로 활용할 수 있도록 해줍니다.

        Transformer를 Tabular Data에 적용하는 이유

        1. Contextual Embedding의 생성과 장점

        TabTransformer는 Transformer의 self-attention 메커니즘을 활용하여 범주형 변수의 컨텍스트 인식 임베딩(contextual embedding)을 생성합니다[1][7]. 이는 기존 MLP가 생성하는 컨텍스트 없는(context-free) 임베딩과 달리, **관련 특성들 간의 관계를 효과적으로 포착**합니다[1].

        연구 결과에 따르면, Transformer를 통해 학습된 contextual embedding에서는 높은 상관관계를 가지는 특성들이 유클리드 거리에서 가까운 임베딩 벡터를 가지는 경향이 있습니다[1]. 이러한 특성은 MLP의 context-free 임베딩에서는 발견되지 않습니다.

        2. 결측치와 노이즈에 대한 강건성

        TabTransformer의 또 다른 주요 장점은 **결측치와 노이즈가 많은 데이터에 대한 강건성**입니다[1][7]. 연구에 따르면, 테스트 데이터에서 특정 값을 무작위로 만든 값으로 대체하는 방식으로 노이즈를 추가했을 때, TabTransformer는 MLP보다 더 좋은 성능을 유지했습니다[1].

        특히 노이즈가 증가할수록 TabTransformer와 MLP 간의 성능 차이가 더 커졌으며, 일부 데이터셋(Blastchar)에서는 TabTransformer가 MLP보다 확연히 더 좋은 성능을 보였습니다[1].

        3. 준지도학습(Semi-supervised Learning)의 용이성

        TabTransformer는 언어 모델의 사전 훈련(pre-training) 방법을 활용하여 **레이블이 없는 데이터(unlabeled data)를 효과적으로 활용**할 수 있습니다[1][2]. 이는 기존의 GBDT와 같은 트리 기반 모델이나 MLP가 가지지 못한 장점입니다.

        논문에서는 2단계 사전 훈련 방법론을 제시하여, 모델을 한 번만 사전 훈련한 후 여러 도메인에 맞게 미세 조정(fine-tuning)할 수 있도록 했습니다[1]. 이는 레이블이 없는 데이터가 많을 때 특히 유용합니다.

        TabTransformer의 실제 적용 사례

        TabTransformer는 다양한 분야에서 활용될 수 있습니다:

        1. 추천 시스템 및 온라인 광고

        테이블 데이터는 **추천 시스템과 온라인 광고 분야**에서 널리 사용됩니다[1]. TabTransformer의 강력한 특성 표현 능력은 이러한 분야에서 더 정확한 예측을 가능하게 합니다.

        2. 운영 체제 지문 인식

        TabTransformer는 운영 체제 지문 인식에도 적용되었습니다[6]. 이 연구에서는 네트워크 트래픽을 분석하여 운영 체제를 식별하는 데 TabTransformer를 사용했으며, 전통적인 머신러닝 모델보다 우수한 성능을 보였습니다[6].

        3. 의료 및 금융 서비스

        테이블 형식 데이터는 **의료 서비스와 금융 서비스 분야**에서도 널리 사용됩니다[3]. 이러한 분야에서는 데이터의 정확한 분석과 예측이 중요하며, TabTransformer의 높은 예측 정확도와 결측치 처리 능력은 큰 장점이 될 수 있습니다.

        4. 다양한 기계 학습 작업

        TabTransformer는 회귀, 이진 분류, 다중 분류, 순위 결정 등 다양한 기계 학습 작업에 적용될 수 있습니다[7]. 이는 TabTransformer가 다양한 비즈니스 문제에 활용될 수 있음을 의미합니다.

        TabTransformer의 성능과 효과

        TabTransformer는 여러 실험을 통해 그 효과가 입증되었습니다:

        1. TabTransformer는 15개 데이터셋 중 14개에서 MLP보다 AUC가 평균 1.0% 향상되었습니다[8].

        2. Transformer 레이어를 통과할수록 성능이 향상되었으며, 이는 여러 Transformer 레이어가 더 풍부한 컨텍스트 정보를 포착함을 시사합니다[1].

        3. 레이블이 없는 데이터가 많을 때(30K 이상), TabTransformer는 다른 모든 모델보다 우수한 성능을 보였습니다[1].

        4. 레이블이 없는 데이터가 적을 때도 다른 모델보다 좋은 성능을 유지했습니다[1].

        결론

        TabTransformer는 테이블 형식 데이터에 Transformer 아키텍처를 적용함으로써, 기존 모델들의 한계를 극복하고 더 높은 예측 정확도를 달성했습니다. 특히 컨텍스트 임베딩을 통한 특성 간 관계 포착, 결측치와 노이즈에 대한 강건성, 준지도학습의 용이성 등이 주요 장점으로 꼽힙니다.

        이러한 장점들로 인해 TabTransformer는 추천 시스템, 온라인 광고, 운영 체제 지문 인식, 의료 및 금융 서비스 등 다양한 분야에서 활용될 수 있습니다. 향후 더 많은 연구와 적용을 통해 TabTransformer의 잠재력이 더욱 발휘될 것으로 기대됩니다.

다른 데이터 분할 기법

교차 검증

  • 여러 모델의 성능을 비교하기 위해 교차 검증 기법을 사용합니다. 교차 검증의 목표는 결국 프로덕션에서 가장 잘 수행할 모델을 선택하는 것입니다.

K-겹 교차 검증은 일반적인 검증 방법

  • K-겹 교차 검증은 일반적인 검증 방법입니다. K-겹 교차 검증에서는 입력 데이터를 K개의 하위 데이터 세트(또는 폴드)로 분할합니다. 그런 다음 K-1개의 폴드를 사용하여 모델을 훈련하고, 나머지 1개의 폴드로 모델을 평가합니다. 이 과정은 K번 반복되며, 매번 다른 폴드가 평가에 사용됩니다.

예를 들어, 5-겹 교차 검증을 수행하면 4개의 모델, 4개의 모델 훈련 데이터 세트, 4개의 모델 평가 데이터 세트, 4개의 평가 결과를 얻게 됩니다. 이진 분류 문제의 5-겹 교차 검증에서는 각 평가 결과에 ROC-AUC 지표가 포함됩니다. 4개 AUC 지표의 평균을 계산하여 전체 성능 측정치를 얻을 수 있습니다.

다른 교차 검증 방법

  • 요구사항에 따라 다양한 교차 검증 방법을 사용할 수 있습니다. **데이터 세트가 작은 경우 Leave-one-out 교차 검증 또는 앞서 언급한 K-겹 교차 검증을 고려**할 수 있습니다. 데이터가 불균형한 경우에는 층화 K-겹 교차 검증을 사용할 수도 있습니다. 다만 이러한 기법들은 훈련 중 더 많은 계산 자원이 필요하다는 점을 유의해야 합니다.

  • Leave-one-out cross validation vs K-fold cross validation

    Leave-one-out 교차 검증(LOOCV)

    Leave-one-out 교차 검증은 특히 데이터 세트의 크기가 작을 때 사용하는 교차 검증 기법입니다. 이 방법에서는 총 N개의 샘플이 있다고 가정할 때, N번의 반복을 수행합니다. 각 반복에서는 N-1개의 샘플로 모델을 훈련하고, 나머지 1개의 샘플로 모델을 평가합니다. 이렇게 해서 N개의 평가 결과를 얻게 되며, 이를 평균하여 최종 성능 지표를 산출합니다.

    장점:

    • 데이터 세트가 작은 경우에도 최대한의 데이터를 활용할 수 있습니다.

    • 편향(bias)이 적은 성능 추정치를 제공합니다.

    단점:

    • 계산 비용이 높습니다. N번의 훈련과 평가를 수행해야 하므로 계산 시간이 오래 걸립니다.

    • 분산이 크게 나타날 수 있습니다. 데이터 세트가 작은 경우 각 평가 결과의 편차가 클 수 있습니다.

    K-fold 교차 검증

    K-fold 교차 검증은 데이터 세트를 K개의 폴드(fold)로 균등하게 나누고, 이 중 K-1개의 폴드로 모델을 훈련하고 나머지 1개의 폴드로 모델을 평가하는 과정을 K번 반복하는 방식입니다. 이를 통해 K개의 평가 결과를 얻고, 이를 평균하여 최종 성능 지표를 산출합니다.

    장점:

    • Leave-one-out 방법에 비해 계산 비용이 상대적으로 낮습니다.

    • 데이터 세트가 충분히 크다면 안정적인 성능 추정치를 제공합니다.

    단점:

    • 데이터 세트가 작은 경우 편향(bias)이 발생할 수 있습니다.

    • K 값 선택에 따라 편향과 분산의 trade-off가 달라질 수 있습니다.

    요약하면, Leave-one-out 방법은 데이터 세트가 작을 때 유용하지만 계산 비용이 높은 편입니다. K-fold 방법은 계산 비용이 상대적으로 낮지만 데이터 세트가 작은 경우 편향 문제가 발생할 수 있습니다. 따라서 데이터 세트의 크기와 요구사항에 따라 적절한 교차 검증 방법을 선택해야 합니다.

하이퍼파라미터란?

하이퍼파라미터는 **ML 알고리즘의 동작을 제어하기 위해 훈련 전에 조정할 수 있는 설정값**들입니다. 이는 훈련 시간, 모델 수렴, 모델 정확도 등에 큰 영향을 미칠 수 있습니다. 훈련 과정에서 얻어지는 모델 파라미터와는 달리, 하이퍼파라미터의 값은 훈련 중에 변경되지 않습니다.

하이퍼파라미터에는 다음과 같은 카테고리가 있습니다:

  • 모델 하이퍼파라미터: **신경망의 필터 크기, 풀링, 스트라이드, 패딩** 등의 **구조적 속성**

  • 최적화기(Optimizer) 하이퍼파라미터: **경사하강법, 확률적 경사하강법, Adam** 등 **최적화 알고리즘** 및 초기화 방법

  • 데이터 하이퍼파라미터: **데이터 증강 기법**(자르기, 크기 조절 등)

  • Hyperparameters

    1. 모멘텀(Momentum)

      • 모멘텀은 **경사 하강법의 단점을 보완**하기 위해 사용되는 하이퍼파라미터입니다.

      • 이전 업데이트 방향으로 일정 비율 가속화되어, 평평한 지역을 빠르게 지나갈 수 있습니다.

      • 적절한 모멘텀 값을 설정하면 **학습 속도와 성능 향상에 도움**이 됩니다.

    2. 최적화기(Optimizer)

      • 최적화기는 모델 파라미터를 업데이트하는 알고리즘입니다.

      • **경사 하강법, 확률적 경사 하강법, Adam** 등이 대표적인 최적화기 하이퍼파라미터입니다.

      • 각 최적화기마다 고유의 하이퍼파라미터(예: 학습률, 모멘텀 등)가 있습니다.

      • 문제 특성에 맞는 최적화기와 하이퍼파라미터 값을 선택하는 것이 중요합니다.

    3. 활성화 함수(Activation Function)

      • 활성화 함수는 **뉴런의 출력을 결정**하는 함수입니다.

      • **ReLU, Sigmoid, Tanh** 등의 활성화 함수가 사용됩니다.

      • 각 함수마다 학습 속도와 수렴 특성이 다르므로, 적절한 함수를 선택해야 합니다.

    4. 드롭아웃(Dropout)

      • 드롭아웃은 **과적합을 방지하기 위해 사용**되는 기법입니다.

      • 훈련 중 무작위로 **일부 뉴런의 출력을 0으로** 만듦으로써 모델의 **일반화 성능을 높일 수 있습니다**.

      • 드롭아웃 비율은 중요한 하이퍼파라미터로, 적절한 값을 선택해야 합니다.

    5. 학습률(Learning Rate)

      • 학습률은 **모델 파라미터를 업데이트하는 속도를 결정**하는 하이퍼파라미터입니다.

      • 학습률이 너무 **높으면 발산**할 수 있고, 너무 **낮으면 학습이 느려질** 수 있습니다.

      • 최적의 학습률을 찾는 것이 중요한데, 보통 **작은 값에서 시작하여 단계적으로 조정**합니다.

    이처럼 다양한 하이퍼파라미터들을 적절히 조정하는 것이 모델 성능 향상을 위해 매우 중요합니다. 자동화된 하이퍼파라미터 튜닝 기법을 활용하면 이 과정을 효율적으로 수행할 수 있습니다.

    • Overfitting 관련 Hyperparameter

      정규화는 모델의 복잡도를 제한하여 일반화 성능을 높이는 방법입니다. 대표적인 정규화 기법에는 다음과 같은 것들이 있습니다:

      1. L1 정규화(Lasso Regularization)

      • 모델 가중치의 절대값의 합을 최소화하도록 하는 기법

      • 가중치 값을 0에 가깝게 만들어 sparse한 모델을 만듦

      1. L2 정규화(Ridge Regularization)

      • 모델 가중치의 제곱합을 최소화하도록 하는 기법

      • 가중치 값을 작게 만들어 과적합을 방지

      1. 드롭아웃(Dropout)

      • 훈련 중 무작위로 뉴런의 출력을 0으로 만들어 과적합을 방지

      • 앞서 설명한 바와 같이 중요한 하이퍼파라미터

      1. 조기 종료(Early Stopping)

      • 검증 성능이 더 이상 향상되지 않을 때 훈련을 중단

      • 과적합을 방지하고 일반화 성능을 높일 수 있음

      이처럼 정규화 기법은 모델의 복잡도를 적절히 조절하여 과적합을 해결하는데 도움이 됩니다. 드롭아웃과 함께 다양한 정규화 방법을 사용하면 더 좋은 성능을 얻을 수 있습니다.

하이퍼파라미터 튜닝

매우 노력 집약적인 작업입니다. 전통적으로는 도메인 전문가가 직접 직관과 경험에 기반하여 하이퍼파라미터를 선택하고, 모델을 훈련하고 검증 데이터로 평가하는 과정을 반복했습니다. 그러나 이는 가장 철저하고 효율적인 방법은 아닙니다.

따라서 다양한 자동 하이퍼파라미터 튜닝 방법이 개발되었습니다.

그리드 서치(Grid Search)

  • 그리드 서치는 하이퍼파라미터와 그 값들의 조합을 격자(grid) 형태로 구성합니다.

  • 각각의 가능한 하이퍼파라미터 조합에 대해 모델을 훈련하고 검증 데이터로 점수를 산출합니다.

  • 이 방법은 모든 가능한 조합을 시도하므로 매우 포괄적입니다.

  • 하지만 이렇게 모든 조합을 대상으로 하는 것은 비효율적일 수 있습니다.

랜덤 서치(Random Search)

  • 랜덤 서치도 그리드 서치와 유사합니다.

  • 하지만 모든 조합을 시도하지 않고 랜덤으로 선택된 하이퍼파라미터 조합을 사용합니다.

  • 시간과 리소스 제약에 따라 탐색 반복 횟수를 설정할 수 있습니다.

즉, **그리드 서치는 모든 가능한 조합을 시도**하는 방식이지만 비효율적일 수 있습니다. **랜덤 서치는 무작위로 조합을 선택하므로 보다 효율적**이지만 모든 경우를 고려하지 않습니다.

이처럼 각각의 방법들은 장단점을 가지고 있으며, 사용 사례와 환경에 따라 적절한 방법을 선택해야 합니다.

Amazon SageMaker의 자동 하이퍼파라미터 튜닝

Amazon SageMaker는 **경사하강법, 베이지안 최적화, 진화 알고리즘** 등의 탐색 방법을 사용하여 자동으로 최적의 하이퍼파라미터를 찾아냅니다.

사용자가 알고리즘과 하이퍼파라미터 범위를 지정하면, Amazon SageMaker가 여러 훈련 작업을 실행하고 선택한 지표에 가장 잘 맞는 하이퍼파라미터 값을 찾아냅니다.

Domain 3.5: Evaluate ML models

모델 평가를 위해서는 훈련된 모델을 테스트 데이터에 적용하고, 실제 값과 예측 값을 비교하는 것이 중요합니다.

분류 문제 : 혼동 행렬(Confusion Matrix)이 모델 평가의 기본

예를 들어, 이진 분류 문제에서는 각 인스턴스에 대해 “고양이” 또는 “고양이가 아님”의 두 가지 클래스가 실제 레이블로 존재합니다. 이는 모델이 예측해야 하는 클래스입니다.

홀드아웃 테스트 데이터에 모델을 적용하면 예측된 클래스 결과를 얻을 수 있습니다.

혼동 행렬

혼동 행렬은 이 실제 클래스와 예측 클래스 간의 관계를 보여줍니다. 혼동 행렬의 각 요소를 클릭하면 다음과 같은 내용을 확인할 수 있습니다:

  • 참양성(True Positive, TP): 실제로 고양이이고 모델도 고양이로 예측한 경우

    • **암 환자를 정확히 진단 (생존 기회 증가)**

    • **재현율(Recall) 지표를 중점적으로 고려**

  • 거짓양성(False Positive, FP): 실제로 고양이가 아닌데 모델이 고양이로 예측한 경우

    • **스팸이 아닌데 스팸으로 잘못 분류**

    • **정밀도(Precision) 지표를 중점적으로 고려**

  • 거짓음성(False Negative, FN): 실제로 고양이인데 모델이 고양이가 아니라고 예측한 경우

  • 참음성(True Negative, TN): 실제로 고양이가 아니고 모델도 고양이가 아니라고 예측한 경우

분류 문제의 성능 지표

  • 정확도(Accuracy): 전체 예측 중 맞춘 비율

  • 정밀도(Precision): 양성으로 예측한 것 중 실제 양성의 비율

  • 재현율(Recall): 실제 양성 중 양성으로 예측한 비율

  • 그 외에도 F1 Score, ROC-AUC 등 다양한 지표 사용 가능

이와 같이 혼동 행렬과 다양한 성능 지표를 통해 분류 모델의 성능을 종합적으로 평가할 수 있습니다.

  • SageMaker Local mode

    SageMaker Local Mode는 개발자가 로컬 환경에서 ML 모델을 개발하고 테스트할 수 있게 해주는 기능입니다. 이를 통해 개발자는 클라우드 인프라를 사용하지 않고도 SageMaker의 주요 기능들을 활용할 수 있습니다.

    SageMaker Local Mode의 주요 특징은 다음과 같습니다:

    1. 로컬 환경에서 모델 훈련 및 배포 가능

      • 개발자의 로컬 머신에서 직접 모델을 훈련하고 테스트할 수 있습니다.

      • 이를 통해 클라우드 리소스를 사용하지 않고도 SageMaker 기능을 활용할 수 있습니다.

    2. 개발 및 디버깅 속도 향상

      • 로컬에서 바로 모델을 훈련하고 테스트할 수 있어, 개발 및 디버깅 속도가 향상됩니다.

      • 클라우드에 모델을 배포하고 실행하는 단계를 생략할 수 있습니다.

    3. 코드 이식성 향상

      • SageMaker Local Mode에서 작성한 코드는 클라우드 환경의 SageMaker에서도 그대로 실행할 수 있습니다.

      • 이를 통해 코드 이식성이 높아져 개발 프로세스가 효율적으로 진행됩니다.

    SageMaker Local Mode를 사용하는 방법은 다음과 같습니다:

    1. 로컬 환경에 Docker 설치

    2. SageMaker Python SDK 설치

    3. SageMaker Estimator를 사용하여 로컬에서 모델 훈련 및 테스트

    4. 필요 시 클라우드 SageMaker로 코드 이식

    이처럼 SageMaker Local Mode를 활용하면 개발자가 로컬 환경에서 빠르게 모델을 개발하고 테스트할 수 있습니다. 특히 이 문제의 경우, 데이터 과학자들이 로컬에서 모델을 실험하고 검증한 뒤 클라우드 SageMaker로 배포할 수 있어 효율적일 것입니다.

  • SageMaker Pipe mode

    SageMaker Pipe Mode는 훈련 데이터를 스트리밍 방식으로 제공하여 훈련 시간을 단축할 수 있는 기능입니다.

    Pipe Mode의 주요 특징은 다음과 같습니다:

    1. 데이터 스트리밍 방식

      • 훈련 데이터를 한 번에 모두 로드하지 않고 스트리밍 방식으로 제공합니다.

      • 이를 통해 데이터 로딩 시간을 단축할 수 있습니다.

    2. 메모리 효율적

      • 전체 데이터를 메모리에 로드하지 않아 메모리 소비가 적습니다.

      • 대용량 데이터 세트 처리에 적합합니다.

    3. 훈련 속도 향상

      • 데이터 로딩 시간이 줄어들어 전체 훈련 시간이 단축됩니다.

      • 모델 실험 및 반복 작업에 유리합니다.

    Pipe Mode를 사용하는 방법은 다음과 같습니다:

    1. 훈련 데이터를 S3 버킷에 업로드

    2. 훈련 입력 모드를 ‘Pipe’로 설정

    3. SageMaker Estimator에서 입력 채널을 정의할 때 Pipe 모드 사용

    이처럼 Pipe Mode를 활용하면 데이터 로딩 시간을 단축할 수 있어, 모델 실험 및 반복 작업에 도움이 됩니다.
    앞서 언급한 문제에서도 Pipe Mode를 적용하면 데이터 과학자들이 모델을 빠르게 실험할 수 있을 것입니다.

    다만 Pipe Mode는 전체 데이터를 한 번에 로드하지 않기 때문에, 데이터 처리 방식 및 알고리즘에 따라 성능 차이가 있을 수 있습니다. 따라서 사용 사례에 맞는 적절한 방법을 선택해야 합니다.

  • Pipe mode vs Full Load

    Pipe Mode의 데이터 공급 방식은 다음과 같습니다:

    1. 메모리에 전체 데이터를 로드하지 않음

    • 훈련에 필요한 데이터만 실시간으로 S3에서 스트리밍 방식으로 가져옵니다.

    • 따라서 전체 데이터를 메모리에 로드할 필요가 없어 메모리 효율성이 높습니다.

    1. 데이터 요청 예측 알고리즘 사용

    • Pipe Mode에서는 데이터 요청을 효율적으로 처리하기 위해 예측 알고리즘을 사용합니다.

    • 이를 통해 향후 필요할 것으로 예상되는 데이터를 미리 가져와 준비해 둡니다.

    • 이 예측 알고리즘은 데이터 패턴, 모델 아키텍처 등을 고려하여 최적화됩니다.

    1. 메모리 전체 로드 방식과의 비교

    • 메모리에 전체 데이터를 로드하는 방식은 한 번에 모든 데이터를 사용할 수 있어 속도가 빠릅니다.

    • 하지만 대용량 데이터의 경우 메모리 소비가 크고, 데이터 로딩 시간이 길어질 수 있습니다.

    • Pipe Mode는 메모리 효율성이 높고 데이터 로딩 시간이 단축되지만, 데이터 요청 예측의 정확도에 따라 성능이 달라질 수 있습니다.

    따라서 데이터 크기, 모델 복잡도, 예측 알고리즘의 성능 등을 고려하여 Pipe Mode와 메모리 전체 로드 방식 중 적절한 방법을 선택해야 합니다.

이 문제의 정답은 “Change the training job to use Pipe Mode to improve the time it takes to train the model.”입니다.

이유는 다음과 같습니다:

  1. “Use Amazon SageMaker in-built algorithms”은 틀린 선택입니다.

    • 문제에서 데이터 과학자들이 이미 모델 개발을 위해 노트북 인스턴스를 사용하고 있다고 언급되어 있습니다. 즉, 자체 개발한 모델을 사용하고 있는 상황입니다.

  2. “Use Amazon SageMaker Estimators in local mode to train the models”은 틀린 선택입니다.

    • 이 방법은 로컬 환경에서 모델을 훈련한 후 SageMaker로 배포하는 것입니다.

    • 하지만 문제에서는 데이터 과학자들이 이미 SageMaker에서 모델을 개발하고 있으며, 훈련 시간 지연 문제를 해결하고자 합니다.

  3. “Change the training job to use Pipe Mode to improve the time it takes to train the model”은 정답입니다.

    • Pipe Mode는 데이터를 스트리밍 방식으로 훈련에 제공하여 훈련 시간을 단축할 수 있는 SageMaker 기능입니다.

    • 따라서 데이터 과학자들이 Pipe Mode를 활용하면 모델 실험 및 반복 작업을 보다 효율적으로 수행할 수 있습니다.

따라서 이 문제의 정답은 Pipe Mode를 사용하여 모델 훈련 시간을 개선하는 것입니다.

알겠습니다. 다시 한번 문제와 답변 선택지를 자세히 살펴보겠습니다.

문제의 핵심 내용:

  • 기름 및 천연가스 회사가 Amazon SageMaker를 사용하여 ML 모델을 개발하고 있음

  • 데이터 과학자들이 노트북 인스턴스를 사용하고 있으나, 모델 훈련 시간이 오래 걸림

  • 데이터 과학자들이 모델을 빠르게 실험할 수 있도록 훈련 작업 시간을 단축하고자 함

문제의 서브 도메인:

  • 모델 훈련 및 튜닝과 관련된 내용

답변 선택지 분석:

  1. “Use Amazon SageMaker in-built algorithms”:

    • 문제에서 이미 모델 개발을 위한 노트북을 사용하고 있다고 언급되어 있어, 이 선택지는 적절하지 않습니다.

  2. “Use Amazon SageMaker Estimators in local mode to train the models”:

    • 이 방법은 로컬에서 모델을 훈련하고 SageMaker에 배포하는 것이므로, 문제에서 요구하는 빠른 모델 실험에는 적합하지 않습니다.

  3. “Change the training job to use Pipe Mode to improve the time it takes to train the model”:

    • Pipe Mode를 사용하면 데이터 스트리밍 방식으로 훈련 시간을 단축할 수 있습니다.

    • 하지만 여전히 데이터 로딩 시간이 소요되므로, 데이터 과학자의 빠른 모델 실험에는 다소 제한적일 수 있습니다.

  4. “Create the models on local laptops. Then, port the code over to use Amazon SageMaker”:

    • 이 방법은 문제에서 요구하는 “최소한의 코드 변경”이라는 조건에 부합합니다.

    • 로컬 환경에서 빠르게 모델을 실험한 뒤 SageMaker로 배포할 수 있습니다.

따라서 가장 적절한 답변은 4번 선택지인 “Create the models on local laptops. Then, port the code over to use Amazon SageMaker”입니다.

  • Instance segmentation vs Semantic segmentation

    instance segmentation과 semantic segmentation은 둘 다 이미지 내의 객체를 구분하고 레이블링하는 작업이지만, 접근 방식과 결과물에서 차이가 있습니다.

    instance segmentation:

    • 각 개별 객체 인스턴스를 구분하여 검출하고 레이블링합니다.

    • 예를 들어, 이미지 내에 있는 여러 개의 자동차를 **각각 구분하여 레이블링**합니다.

    • 객체 간의 경계를 명확히 구분할 수 있습니다.

    • **개별 객체 단위로 정보를 제공**하므로, 이후 작업(예: **객체 계수, 객체 추적 등)에 유용**합니다.

    semantic segmentation:

    • 이미지 내의 유사한 의미를 가진 영역을 구분하여 레이블링합니다.

    • 예를 들어, 자동차, 보도, 하늘 등의 **영역을 각각 구분하여 레이블링**합니다.

    • 개별 객체 인스턴스를 구분하지 않고 전체 **이미지를 의미론적으로 분할**합니다.

    • 객체의 **형태나 경계에 대한 정보는 제공하지 않습니다**.

    • **이미지 분할이나 장면 이해 등의 작업에 유용**합니다.

    요약하면, instance segmentation은 개별 객체 단위로 세밀한 분할을 수행하고, semantic segmentation은 이미지 전체를 의미론적으로 분할한다는 점에서 차이가 있습니다.
    적용 사례에 따라 두 방법 중 더 적절한 것을 선택해야 합니다.

이 문제에서 데이터 과학자가 구축하려는 ML 모델은 이미지 내에서 사람, 차량, 표지판 등 다양한 객체를 검출하고 레이블링하는 것입니다.

따라서 이 문제에 가장 적합한 ML 알고리즘은 4번 “semantic segmentation”입니다.

그 이유는 다음과 같습니다:

  1. image localization:

    • 이미지 내에서 객체의 위치만 검출하는 것이므로, 이 문제에서 요구하는 객체 검출 및 레이블링 작업에는 적합하지 않습니다.

  2. instance segmentation:

    • 개별 객체 인스턴스를 구분하여 검출하는 것이므로, 이 문제에서는 약간 과도한 작업이 될 수 있습니다.

  3. image classification:

    • 전체 이미지를 분류하는 것이므로, 이미지 내 객체 검출 및 레이블링에는 적합하지 않습니다.

  4. semantic segmentation:

    • 이미지 내 각 픽셀을 의미론적으로 구분하여 레이블링하는 것입니다.

    • 이를 통해 이미지 내 여러 객체를 검출하고 레이블링할 수 있습니다.

    • 따라서 이 문제의 요구사항에 가장 잘 부합하는 알고리즘입니다.

따라서 이 문제의 정답은 4번 “semantic segmentation”입니다.

이 문제에서 데이터 과학자가 직면한 상황은 CNN 모델의 느린 수렴 속도와 오랜 기간 동안 오실레이션이 발생하는 것입니다.

이를 해결하기 위한 적절한 조치는 다음 두 가지입니다:

  1. Add batch normalization (정답)

    • 배치 정규화(Batch Normalization)는 모델의 수렴 속도를 높이고 오실레이션을 줄이는 데 효과적입니다.

    • 배치 정규화를 통해 내부 covariate shift 문제를 해결할 수 있어 안정적인 학습이 가능해집니다.

  2. Normalize the images before training (정답)

    • 입력 이미지를 적절히 정규화하는 것은 모델 학습에 도움이 됩니다.

    • 입력 분포를 정규화하면 모델이 학습하기 더욱 용이해지며, 수렴 속도를 높일 수 있습니다.

나머지 선택지는 적절하지 않습니다:

  1. Decrease weight decay (오답)

    • 가중치 감쇠(Weight Decay)를 줄이면 오히려 과적합 문제가 발생할 수 있습니다.

  2. Increase batch size (오답)

    • 배치 크기를 늘리면 수렴 속도가 빨라질 수는 있지만, 오실레이션 문제는 해결하기 어려울 수 있습니다.

  3. Add more epochs (오답)

    • 에폭 수를 늘리는 것만으로는 수렴 속도와 오실레이션 문제를 해결하기 어렵습니다.

따라서 이 문제의 정답은 1) 배치 정규화 추가, 2) 입력 이미지 정규화의 두 가지 선택지입니다.
