IP Address

CIDR

  • IP Address Class

    • Network Address + Host Address 구분 방식에 따라 분류

    • Network Address : 네트워크를 식별 하기 위한 주소

    • Host Address : 네트워크 내의 host computer를 식별 하기 위한 주소

    • A Class

      • N 8bit : 1.0.0.0 ~ 127.0.0.0 (126)

      • H 24bit : 2^24 (16M)

      • Private IP : 10.0.0.0 ~ 10.255.255.255

    • B Class

      • N 16bit : 128.0.0.0 ~ 191.255.0.0 (16,382)

      • H 16bit : 2 ^16 (64K)

      • Private IP : 172.16.0.0 ~ 172.31.255.255

    • C Class

      • N 24bit : 192.0.0.0 ~ 223.255.255.0 (2M)

      • H 8 bit : 2^8 (254)

      • Private IP : 192.168.0.0 ~ 192.168.255.255

    • D,E Class : 연구 또는 개발용으로 예약된 IP

  • CIDR notation

    • IP 주소 할당 방법, supernetting : 여러개의 작은 network를 하나의 커다란 network으로 바꾸는 작업, subnetting의 반대

    • 가변 길이의 subnet maasking을 기반으로 함

    • CIDR block은 같은 prefix를 공유하는 address group

    • Prefix (network address) + suffix (address bit)

Reserved IP

  • Subnet의 처음 4개 IP와 마지막 1개 IP는 예약 되어 있음

    • 10.0.0.0/24 subnet

    • 10.0.0.0 : Network address

    • 10.0.0.1 : Reserved for the VPC route

    • 10.0.0.2 : Reserved by AWS

    • 10.0.0.3 : Reserved for future use

    • 10.0.0.255 : Network broadcast address (broadcast not support)

Public IP - EIP (Elastic IP Address)

  • EIP는 생성 후 실행 중 인스턴스와 연결되지 않거나, 중지된 혹은 연결되지 않은 network interface와 연결될 경우 소액의 시간당 요금이 부과

  • Amazon EIP Pool에서 주소를 할당 → Region당 기본 5개 EIP 할당 가능

  • Bring Your Own IP (BYOIP)

    • ARIN, RIPE, APNIC 등의 기관에 등록된 주소 범위를 가져와 사용 : up to /24 range

VPC Traffic Control

Network ACL (NACL)

  • Subnet 내부와 외부의 traffic 제어

  • 1개의 Subnet은 1개의 NACL에만 연결 가능

  • Default는 모든 inbound 및 outbound traffic을 허용

  • Network firewall

Security Group

  • Instance firewall

NACL Rule

  • 기본적으로 모든 인바운드 및 아웃바운드 IPv4 트래픽을 허용

  • 가장 낮은 번호가 지정된 규칙부터 시작 → 규칙에 일치하는 트래픽이 있으면 이와 모순되는 상위 규칙이 있더라도 적용

  • 별표로 된 기본 규칙이 포함 : 이 규칙은 패킷이 다른 어떤 규칙과도 일치하지 않을 경우에는 거부되도록 되어 있습니다. 이 규칙을 수정하거나 제거할 수 없습니다.

  • Source : Where it can come from

  • Destination : Where to go

SG Rule

  • 허용 규칙을 지정할 수 있지만 거부 규칙은 지정할 수 없습니다

  • 보안 그룹을 처음 만들 때 인바운드 규칙이 없습니다. 따라서 보안 그룹에 인바운드 규칙을 추가하기 전에는 어떤 인바운드 트래픽도 허용되지 않습니다.

  • 보안 그룹을 처음 생성하면 리소스의 모든 아웃바운드 트래픽을 허용하는 아웃바운드 규칙이 있습니다.

    • 규칙을 제거할 수 있으며 특정 아웃바운드 트래픽만 허용하는 아웃바운드 규칙을 추가할 수 있습니다. 보안 그룹에 아웃바운드 규칙이 없는 경우 어떤 아웃바운드 트래픽도 허용되지 않습니다.

  • Destination - Prefix List

    • CIDR block set : 보안 그룹과 라우팅 테이블을 보다 쉽게 구성하고 유지, 관리

VPC Peering

  • 2개의 VPC간 networking connection

  • 다른 Account VPC, 다른 Region VPC (inter-region VPC peering) 연결 가능

  • Transitive peering : Peering 전이는 지원되지 않음

  • 2개 VPC 사이에는 한번에 한개의 peering connection만 가능

  • DNS resolution 사용

    • https://docs.aws.amazon.com/vpc/latest/peering/modify-peering-connections.html#vpc-peering-dns

    • https://aws.amazon.com/premiumsupport/knowledge-center/vpc-peering-troubleshoot-dns-resolution/

  • Reachability Analyzer를 사용하여 VPC 피어링을 사용하여 연결된 VPC의 두 리소스 간 연결성 확인 가능

Inter-region VPC Peering Limitation

  • Max MTU : 1.5 KBytes (Jumbo Frame 지원되지 않음)

  • Security Group 참조 되지 않음

  • DNS resolution (해석) 되지 않음

  • Amazon VPC와 customer on-prem network 연결

  • AWS Classic VPN or AWS VPN connection

Concepts

  • VPN connection : VPC와 on-prem network간의 secure connection

  • VPN tunnel : Encrypted link로 customer network과 AWS간 데이터 송수신 됨. VPN connection당 2개의 VPN tunnel을 가지고 있음 (고가용성)

  • Customer Gateway (CGW) & Customer Gateway device : customer side gateway device or software application (Site-to-Site connection 연결을 담당)

  • Target Gateway : AWS side에서 Site-to-Site VPN connection을 하는 VPN endpoint

  • Virtual Private Gateway : VPN endpoint on the Amazon side로 단일 VPC에 연결 될 수 있음

  • Transit Gateway : VPN endpoint on the Amazon side로 여러개의 VPC를 연결할 수 있는 transit hub 역할

Virtual Private Gateway (VGW)

  • ASN (Autonomous System Number) 지정 : 회사에서 관리하는 자율 라우터 시스템을 식별하기 위한 고유한 숫자로 망식별 번호라고 함

    • 4 byte ASN ( ~ 2147483647) for VGW

    • 2 byte ASN ( ~ 65535) for CGW

    • public ASN을 사용할 수 있고 없는 경우 private ASN을 지정하여 사용 (64512 ~ 65534) : 기본값은 65000

  • Certificate 기반으로 인증할 경우 ARN의 ACM private certificate을 사용할 수 있음

Routing Options

  • Dynamic routing

    • CGW가 BGP (Border Gateway Protocol)을 지원할 경우 사용

    • BGP advertising을 사용하여 VGW로 routing 할 것을 알림

  • Static routing

    • BGP advertising 지원하지 않을 경우 static routing 선택하고 static IP prefix를 지정 : CIDR notation 사용

    • VPC를 advertising 하기 위해 IP prefix 사용

  • Route table

    • VPC내 traffic의 target을 VGW로 지정 → VGW에 생성된 VPN tunnel을 통해 전송

    • Route propagation을 활성화 하면 자동으로 network route를 전파

    • Route가 중복될 경우 Local route가 우선

      • Local route → VGW → Network Interface → Instance ID → VPC peering connection → NAT gateway → Transit gateway → Gateway VPC endpoint

VPN Performance

Requirements

Network Firewall

  • VPC를 위한 고가용성 네트워크 방화벽 서비스

  • 상태 저장 검사, 침입 차단 및 탐지, 웹 필터링 기능을 쉽게 배포 및 관리

  • Traffic에 따라 자동으로 확장

  • CrowdStrike, Palo Alto Networks, Splunk 등의 기존 AWS 파트너 에코 시스템과 상호 운용 가능

  • 커뮤니티에서 유지 관리하는 Suricata 규칙 세트를 가져와 활용 가능

Use Case

  • VPC가 승인되지 않은 도메인에 액세스 하지 못하도록 차단

  • 알려진 악성 IP 주소를 차단

  • 시그니처 기반 탐지를 사용하여 악의적인 활동을 식별
