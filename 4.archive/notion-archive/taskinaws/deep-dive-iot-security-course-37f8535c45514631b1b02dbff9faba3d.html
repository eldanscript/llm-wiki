Policy-based Authorization

Policy

  • JSON document

  • 허가 (permission)을 모아 둔 문서

  • 디바이스, 사용자, 역할에 연결된다 (attach)

AWS IoT authorization

  • Policy는 인증된 신원 (authenticated identity) 으로 무엇을 할 수 있는지 결정

  • 디바이스, 모바일 앱, 웹 앱, 사용자, 데스크탑 앱에서 사용

  • Authorization은 policy를 통해 수행

  • 예를 들면 어떤 디바이스를 MQTT의 모든 토픽에 접근할 수 있게 하거나 특정 토픽에 접근하도록 설정

  3. Explicit Allow

Control Plane vs Data Plane

Control Plane

  • Setup for routing : Traffic을 보낼 곳을 결정

  • Enable customer to perform administrative task relating to creating or updating certificate, things, rules, and so on

    • 관리자 작업을 수행 할 수 있도록 함

    • thing, rule, 인증서 생성과 업데이트 등의 작업

  • Administrative task (IoT actions 참조)

    • 인증서, policy, auditing, authorizers, Device Defender violation

    • Billing

    • Things, thing groups, thing types

    • IoT rules

    • Logging

    • Streams

    • Query search index

    • OTA updates

    • IoT jobs

  • Control plane action

    • AWS 사용자 혹은 rule이 AWS 관리 콘솔이나 AWS CLI를 통해 수행하는 action

Data Plane

  • Forward traffic

  • Control plan logic을 기반으로 routing

  • Data Routing (IoT data 참조)

    • Thing shadow : get, update, delete

    • MQTT : connect, publish, subscribe, receive

    • Job execution : describe, get, start, update

  • Data plane action

    • IoT Core에 연결된 디바이스 혹은 모바일 앱 등이 수행하는 action

    • AWS에 정의된 policy에 따라 허용된 action을 수행

인증 주체

  • User

    • 사람 혹은 애플리케이션을 표현하는 개체로 AWS와 상호 작용기 위해 사용

    • 이름과 자격 증명으로 구성 된다 (user)

  • Group

    • IAM user 집합체 (collection)

    • 여러명의 사용자에게 권한을 지정하여 사용자 권한을 쉽게 관리 하고자 함

  • Role

    • 특정 권한을 가지도록 계정에서 생성하는 개체

    • 권한 policy를 사용하여 AWS 에서 무엇을 하거나 할 수 없는지를 결정

    • 한 사람에게 권한을 연결하는 대신 필요로 하는 누구에게나 권한을 부여하기 위해 사용

    • 장기간 사용할 수 있는 표준 자격 증명이 아님

    • Role을 부여하면 role session 동안 사용할 수 있는 임시 보안 자격 증명이 공급 된다 (temporary security credential)

IAM users and roles

IAM federated identities

  • IdP (자격증명 공급자)에 의해 인증되는 ID

  • IAM role을 사용하여 보안 자격증명을 획득하여 AWS 리소스를 접근할 수 있다

Amazon Cognito federated identities

  • AWS에서 제공되는 자격 증명으로

  • 3rd party IdP에게 AWS 리소스에 임시적이고 제한된 접근 권한을 부여 한다

Use Case

  • Device : X.509 인증서, 커스텀 권한 부여자

  • Web & Mobile 앱 : Amazon Cognito 자격 증명

  • CLI commands : IAM 혹은 연합 자격 증명 (federated identity)

  • Desktop 앱 : IAM 혹은 연합 자격 증명 (federated identity)

Protocol

  • MQTT over TLS/TCP, TLS mutual auth : X.509 인증서

  • HTTPS, TLS mutual auth : X.509 인증서

  • HTTPS, AWS SigV4 auth : SigV4

  • HTTPS over custom auth : 커스텀 권한 부여자

  • SigV4

    • Signature Version 4 is the process to add authentication information to AWS requests.

    • For security, most requests to AWS must be signed with an access key, which consists of an access key ID and secret access key

Shared responsibility model

Customer : Security in the cloud

  • 디바이스 자격 증명 (credential)

  • Policy and permission

  • Unique identities to each device

AWS : Security of the cloud

X.509 Certificate

  • Recommended and most common form of authentication

  • Public Key Infrastructure를 사용하여 공개 키를 인증서에 포함 된 ID와 연결하는 표준을 사용하는 디지털 인증서

CA (Certificate Authority)

  • 인증서를 발급하는 trusted entity

  • X.509 인증서를 발급하는데 사용되는 CA 인증서 관리 → CA 인증서의 개인 키 접근

  • 인증서 생성을 위해 CSR (Certificate Signing Request) 서명

Protocol

  • AWS IoT support : MQTT (port 8883, 443) and HTTPS (port 443)

  • X.509 인증서로 443 port로 연결할 때 ALPN (Application Layer Protocol Negotiation) TLS extension 구현 필요

  • ClientHello 메시지에

    • ALPN Protocol name, x-amzn-mqtt-ca, ALPN ProtocolNameList를 client에서 전송

BP

  • Each device a unique certificate

    • 디바이스의 미세한 관리를 가능하게 함

    • 불법적인 사용자가 단일 장치에 액세스하면 특정 고유 한 장치에 대한 인증서를 취소 할 수 있음

    • 여러 장치가 동일한 인증서를 사용하면 장치가 손상되었음을 (compromised) 나타 낼 수 있음

  • Support rotation and replacement of certificate

    • AWS IoT job을 통해 인증서 교체를 할 수 있음

Authentication

Chain of trust

  • This chain goes back until a self-signed root certificate is reached

Mutual Authentication

  • 디바이스는 연결하려는 서버가 올바른 것인지 서버의 유효성 확인

  • AWS IoT Core endpoint는 연결하려는 장치의 유효성을 확인

  • Mutual Authentication을 진행하는 동안 디바이스와 서버는 TLS handshake를 수행

Server authentication

  • 서버 인증서는 디바이스로 복사되어 AWS IoT 연결시 사용

  • AWS IoT 서버 인증서

Amazon Trust Services (ATS) Endpoint

https://www.amazontrust.com/repository/

  • iot:Data-ATS endpoint에서 제공하는 서버 인증서

  • 디바이스가 지원하는 검증 suite에 따라 Root 인증서 선택 : RSA or ECC

  • 전체 인증서 hash 인증서 고정 방법은 사용하지 않는 것을 권고

    • ATS 인증서는 Starfield에서 교차 서명되어 발급자 이름이 다름

    • 신뢰 root 검증이 필요한 경우 클라이언트에 Starfield CA 인증서 설치가 필요

  • Amazon Root CA 1 : RSA 2048 bit key

  • Amazon Root CA 2 : RSA 4096 bit key (reserved for future use)

  • Amazon Root CA 3 : ECC 256 bit key (타원 곡선 암호, Elliptic Curve Cryptosystems)

  • Amazon Root CA 4 : ECC 384 bit key

Verisign Endpoint

  • iot:Data endpoint에서 제공하는 서버 인증서

  • Verisign Class 3 Public Primary G5 : RSA 2048 bit key

  • 디바이스에 Symantec 또는 Verisign CA 인증서가 필요한 경우가 아니면 iot:Data-ATS 엔드포인트를 사용

  • Symantec 및 Verisign 인증서는 이제 사용되지 않으며 대부분의 웹 브라우저에서 더 이상 지원되지 않음

Server 인증

  • 디바이스가 AWS IoT Core 연결 시도할 때 IoT Core 서버에서 서버 인증을 위한 X.509 인증서를 전송

  • HTTPS URL 방문시 브라우저에서 사용하는 것과 동일

Client (디바이스) 인증서 생성 및 등록

  • CSR (Certificate Signing Request) : 디바이스의 인증서가 유효함을 디지털 서명을 통해 보증하는 절차 진행

디바이스 인증성 생성 Option

One-click 생성

  • AWS IoT CA로 서명한 인증서를 생성

    • CSR : AWS IoT CA에서 서명

  • 디바이스 인증서와 공개키, 개인키를 다운로드

    • 디바이스 인증서

    • 디바이스 공개키

    • 디바이스 개인키

고객의 고유한 CSR 제공 (Provide your own CSR)

  • 고객이 디바이스 고유한 인증서를 생성

  • 디바이스 인증서만 다운로드 → AWS에서 개인키를 생성하지 않는 이점

BYOC (Bring Your Own Certificate)

  • 고객인 신뢰하는 CA에서 서명한 디바이스 인증서를 등록하여 사용

  • 디바이스 제조 과정에서 고유한 인증서를 생성하거나 이미 필드에서 사용하고 있는 많은 디바이스가 있을 경우 유용

  • AWS에서 다운로드 하지 않음

디바이스 인증서 등록

  • 등록된 디바이스 인증서를 사용하여 디바이스 인증 진행

Just-in-time Registration (JITR)

  • 디바이스가 처음 연결하는 시점 (Just-in-time)에 디바이스 등록을 진행 한다는 의미

  • CA 인증서 등록 → 등록된 CA로 서명된 어떤 디바이스 인증서도 AWS IoT에 등록 가능하고 인증에 사용될 수 있음

  • CA 서명된 인증서로 JIT registration → 디바이스 인증서 활성화 (activate) 하고 자동으로 IoT policy를 연결

  • Workflow

    1. 디바이스가 디바이스 인증서로 AWS IoT에 최초 연결

    2. IoT service는 등록된 CA가 서명한 알 수 없는 인증서를 감지 (detect unknown certificate)

    3. 자동으로 디바이스 인증서 등록

    4. Registration 성공하면 AWS IoT는 registration 메시지를 publish (reserved MQTT topic - $aws/events/certificates/registered/)

    5. 클라이언트 연결 끊음 (disconnect the client)

    6. MQTT registration event는 연결되어 있는 Lambda rule engine action을 trigger

    7. Lambda 함수를 통해 인증서 공급을 완료 (complete the provisioning of the certificate) - 추가 Custom Logic

      1. Allow List, 인증서 해지 목록 (Certificate Revocation List) 적용

      2. 특정 사용자에 등록 하거나 추가적인 온보딩 단계를 호출

    8. 디바이스 인증서가 준비되어 AWS IoT에서 디바이스 연결 및 인증에 사용 가능해 짐

Just-in-time Provisioning (JITP)

  • JITR의 Lambda 로직이 필요하지 않음

  • 디바이스 처음 연결하는 시점에 디바이스 온보딩과 리소스 공급을 진행 한다는 의미

  • Workflow

    1. Provisioning template을 CA 인증서에 연결 (IAM role 포함)

    2. JITP는 template을 기반으로 리소스 생성, 업데이트, 연결을 진행

    3. IAM role은 리소스 공급에 필요한 권한을 허용

  • 대규모 파일 (video, aggregated telemetry 등)의 경우 AWS 서비스로 직접 연결이 좋은 선택

Credential provider

  • 내장 X.509 인증서를 AWS request를 인증하기 위한 디바이스 자격 증명으로 사용

  • Credential provider는 caller를 X.509 인증서로 인증하고 임시적이고 제한적인 보안 토큰을 발급

  • Security Token을 사용하여 AWS 요청을 생성하고 구성

    • AWS IAM role 구성과 IAM policy 연결이 필요

Customer Authroizer

  1. Request security token

    1. The device makes an HTTPS request to the credentials provider for a security token

    2. The request includes the device X.509 certificate for authentication

  2. Validate request

    1. The credentials provider forwards the request to the AWS IoT authentication and authorization module

  3. Success / Failure

    1. In the authentication and authorization module, the X.509 certificate is authenticated. The certificate’s policies are then evaluated to ensure that the proper permissions are included to request the security token

    2. To succeed, the certificate needs permission to take the action **iot:AssumeRoleWithCertificate** on a role alias

    3. If the certificate is valid and has permission to assume the role, the AWS IoT authentication and authorization module returns success. Otherwise, it returns failure, which goes back to the device with the appropriate exception

  4. Assume the role

    1. On successful validation, the credentials provider invokes the AWS Security Token Service (AWS STS) to assume the preconfigured IAM role defined with the role alias

    2. To succeed, the role must have a trust policy that allows credentials.iot.amazonaws.com to take the action sts:AssumeRole

  5. AWS STS returns security token

    1. Assuming that the role succeeds, AWS STS returns a temporary, limited-privilege security token to the credentials provider

  6. Credentials provider returns security token

    1. The credentials provider returns the security token to the device

  7. Sign request with retrieved security token

    1. The AWS SDK on the device uses the security token to sign an AWS request with AWS Signature Version 4

  8. Validate signature

    1. The requested AWS service invokes IAM to validate the signature and authorize the request against access policies attached to the preconfigured IAM role

    2. The IAM role is authorized if it has the appropriate permissions to take the desired action in the AWS service

  9. Success / Failure

    1. If IAM validates the signature successfully and authorizes the request, the request goes through

Authenticating and Authorizing

  1. 연결 되었지만 SigV4 header가 없다면 → AWS IoT device gateway는 IoT endpoint에 대한 custom authorizer가 구성 되어 있는지 확인

  2. Custom authorizer가 있다면 사용

  3. Custom authorizer가 인증을 하기 위해서는 token과 token signature가 필요 → HTTP request의 authorizer에 포함 되어야 함

    1. HTTP request 요청 시 token signature는 개인키로 암호화

    2. customer authorizer는 공개키로 token signature로 복호화

    3. Custom authorizer Component

      1. AWS Lambda Function : authentication and authorization logic

      2. Token signature 생성을 위한 공개키와 개인키

  1. AWS IoT device gateway는 연결을 수립

  2. AWS IoT는 policy를 cache하여 이후 연속적인 호출에 대해 재 인증을 하지 않음 → refresh time까지 지속

IAM, Federated Identities, Cognito Identities

  • Do not use IAM user credentials with the IoT data plane.

    • There is a limit on how many IAM users can be created. Each identity should always have unique credentials.

    • Additionally, it is best to always use temporary credentials with the data plane so that you remember to rotate the credentials.

  • Use Amazon Cognito Federated Identities instead of IAM federated identities when possible. 

    • Amazon Cognito is an AWS service that manages the process for federated identities and makes it easier to use.

  • Authenticated Amazon Cognito identities require both IAM and IoT policies. 

    • Remember to use least privilege for both policies.

    • Do not give full iot:attachpolicy permissions and use Amazon Cognito policies variables and token attributes to further strengthen your policies.
