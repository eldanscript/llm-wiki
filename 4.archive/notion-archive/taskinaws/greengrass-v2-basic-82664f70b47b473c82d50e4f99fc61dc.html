GGv2 Component

Concept

  • Components are building blocks that enable easy creation of complex workflows : 복잡한 작업 흐름을 쉽게 만들 수 있도록 하는 빌딩 블락이다

    • ML 추론 (예측), Local 처리, 메시징, 데이터 관리

  • 디바이스 애플리케이션 개발 가속화를 지원하기 위한 것 이다 → 디바이스 프로토콜, 자격증명 관리, 외부 API 연결에 대해 충분한 지식이 없더라도 사용할 수 있도록 한다

  • AWS 서비스와 3rd party 애플리케이션을 코드 구현 없이 사용할 수 있도록 한다

  • 공통 비지니스 로직의 재 사용성을 높인다 → 엣지 디바이스들에 대해 component 조회, 로드, 구성, 배포

  • 오픈 소스 및 AWS에서 제공하는 pre-built component 외에도 Custom component 생성이 가능하다

GG Core device

  • GG 소프트웨어가 동작되는 디바이스를 의미 한다

  • Core device도 AWS IoT Thing 이다

  • 여러개의 Core device를 AWS IoT Thing group에 추가하여 GG Core device group을 만들 수 있다

GG Component

  • GG Component는 GG Core device에 배포되어 동작되는 소프트웨어를 의미 한다

Element

  • Recipe

    • JSON 혹은 YAML 파일로 component 소프트웨어에 대한 상세 내용, 설정, 패러미터를 기술한다

  • Artifact

    • 디바이스에서 실행 될 소스 코드, 바이너리 파일, 스크립트를 의미

    • 처음 부터 직접 생성하거나 Lambda 함수, Docker 컨테이너, Custom runtime을 사용하여 만들 수 있다

  • Dependency

    • Component 간 의존성을 의미

    • 자동 업데이트나 재 시작할 때 필요

GG Software Catalog

  • GG component index : GG community에서 개발

  • Community component

    • Video : KVS, WebRTC

    • Connectivty : Modbus TCP, BT IoT Gateway, LoRaWAN, TES Routing to Container, IoT PubSub Framework

    • 시계열 Database : InfluxDB, InfluxDB Publisher

    • Observability : Grafana

    • Application : Home Assistant, Local Webserver

    • ML : Jupyter Labs, GStreamer for L4V

  • AWS provided component

    • GG nucleus

    • Client device auth, Secret manager, Shadow manager

    • MQTT bridge, Mosquette MQTT broker, Nucleus telemetry emitter

    • CloudWatch metric, Log manager

    • Device Defender, IP detector

    • Docker application manager

    • Local debug console

Component 배포

  • Component를 target device로 전송하는 과정과 component 구성을 적용하는 것

  • Nucleus

    • 최소 기능을 위한 required component

    • 다른 component에 대한 배포, orchestration, 생명 주기 관리를 수행

    • Component간 IPC를 용이하게 함

  • Optional Components

    • 엣지 디바이스의 추가적인 기능을 가능하게 함

Review GGv2 Installation process

  • Installation parameter

    • Greengrass.jar

      • Installer + SetUp 소프트웨어

      • GG core device 구동에 필요한 AWS 리소스 생성

    • -Droot : GG root 폴더 지정

    • —thing-name, —thing-group-name : AWS 콘솔에서 생성하는 이름과 동일하게

    • —component-default-user ggc_user:ggc_group

      • GG core software가 component 구동할 때 사용하는 user ID 혹은 name

      • Root로 동작 시킬 때 component user는 설정 파일에 정의된 사용자를 사용 → 사용자가 없다면 기본값으로 ggc_group의 ggc_user를 사용하며 없으면 생성한다

    • —provision true

      • GG core 소프트웨어가 AWS IoT thing, IoT thing group, IoT role을 생성

      • Things → GreengrassQuickStartCore-Cloud9

    • —setup-system-service : GG core 소프트웨어를 system service로 동작. service name은 greengrass

    • —deploy-dev-tools : GG CLI component를 다운로드 하고 설치

  • Install Log

  • Things → GreengrassQuickStartCore-Cloud9 → Certificate

  • GreengrassV2IoTThingPolicy

Token Exchange Service (TES)

  • TES component는 AWS 서비스와 Custom component간의 상호 작용에 사용할 수 있는 AWS 자격 증명을 제공한다

  • TES는 로컬 서버로 Amazon ECS 컨테이너 인스턴트를 구동한다 → 로컬 서버는 AWS IoT credential에 접속하여 GG core nucleus component에 설정한 IoT role alias를 사용한다

  • GreengrassTESCertificatePolicyGreengrassV2TokenExchangeRoleAlias

  • TES role : TokenExchangeRole
