1.2 Transform data and perform feature engineering

Fundamentals of Data Transformation

Data Cleaning Techniques

Incorrect and Duplicated Data

Incorrect data

데이터 클리닝 시 주의해야 할 사항:

  • 언어 차이로 인한 문제

  • 잘못된 데이터 입력으로 인한 오류

  • 예상 형식과 맞지 않는 값

  • 이상치 데이터 점검 필요

데이터 클리닝 방법:

  • **정확한 값 채워 넣기**

  • **잘못된 형식을 올바른 형식으로 변환**

  • **잘못된 데이터 완전히 제외시키기**

데이터 클리닝의 중요성:

  • 부정확한 모델 예측 방지

  • 신뢰할 수 있는 모델 성능 확보

  • 시간과 노력이 필요한 작업이지만 필수적

Duplicated data

데이터 중복 관리에 대한 한글 불릿 포인트 정리:

  • 데이터 중복이란?

    • 동일한 정보를 담고 있는 데이터 레코드

    • 다양한 출처에서 데이터를 수집하거나 잘못 입력할 때 발생

  • 데이터 중복 확인의 중요성

    • **데이터 분포를 왜곡**시킬 수 있음

    • 특정 예시를 **과도하게 대표**할 수 있음

  • 데이터 중복 해결 방법

    • 데이터셋 내 중복 레코드 식별

    • 중복 레코드 삭제 또는 통합

    • deduplication

      • retaining one copy of the information, and replacing the other instances with pointers that direct back to the stored copy

      • 데이터 저장소에서 고유한 정보만 유지함으로써 저장 용량을 크게 늘릴 수 있음

  • 데이터 중복 관리의 효과

    • 더 정확한 데이터 분석 및 모델링 가능

    • 데이터의 품질 및 신뢰성 향상

Data Outliers

Methods for detecting outliers

  • Calculating mean and median

  • 평균(Mean) 이란?

    • 데이터셋 내 모든 값의 산술 평균

  • 평균의 장점

    • **데이터가 대칭적인 경우 유용한 중심 경향 지표**

  • 평균의 한계

    • 데이터에 **이상치가 포함되면 평균이 편향**될 수 있음

    • 이 경우 실제 데이터의 중심을 잘 반영하지 못함

  • 예시: 응답자 나이 데이터셋

    • 대칭적인 데이터에서는 평균과 중앙값이 동일(50세)

    • 이상치가 있으면 평균이 실제 중심을 잘 나타내지 못함

  • 평균 활용의 주의점

    • 데이터의 분포와 특성을 잘 파악해야 함

    • 이상치에 의해 평균이 왜곡되지 않도록 주의

  • 중앙값(Median) 이란?

    • 데이터셋을 두 개의 동일한 부분으로 나누는 값

    • 오름차순으로 정렬했을 때 가운데에 위치한 값

  • 중앙값의 장점

    • **데이터가 편향되거나 이상치를 포함할 때 더 적합한 중심 경향 지표**

    • **평균보다 데이터의 중심을 잘 나타냄**

  • 예시: 소득 수준 데이터셋

    • 평균은 높거나 낮은 값에 영향을 받을 수 있음

    • 중앙값은 데이터의 실제 중심 경향을 더 정확히 보여줌

  • 중앙값 활용의 중요성

    • 데이터 분석 및 의사결정 시 중요한 지표

    • 이상치에 강건한 중심 경향 측정

Identifying natural and artificial outliers

자연적 이상치(Natural Outliers)

  • **정확한 데이터 표현이지만 중심 데이터와 극단적인 차이**를 보이는 경우

  • 예: 키 데이터셋에서 매우 큰 키의 개인은 자연적 이상치

인공적 이상치(Artificial Outliers)

  • **오류나 부적절한 데이터 수집**으로 인한 비정상적인 데이터 포인트

  • 예: 고장난 체온계로 측정된 비현실적으로 높거나 낮은 체온

공통점

  • 둘 다 데이터 분석 및 모델링 시 주의가 필요한 이상치에 해당

차이점

  • **자연적 이상치**는 실제 데이터이지만 **극단값**

  • **인공적 이상치**는 데이터 수집/처리 과정의 오류로 발생한 **비정상값**

Incomplete or Missing Data

  • 대부분의 ML 알고리즘은 자동으로 누락 값을 처리할 수 없음

  • 문제 해결에 적합하고 의미 있는 값으로 **수동 대체가 필요**

  • 누락 값의 영향

    • 일부 누락값은 문제가 되지 않을 수 있음

    • 하지만 특정 열의 누락값이 많으면 해당 특성과 타깃 간 관계 해석이 어려워짐

    • **예측 모델의 성능에 부정적 영향**을 줄 수 있음

  • 누락 값 처리를 위한 핵심 단계

    • **누락 값의 원인과 분포 파악**

    • 문제 해결에 **적합한 대체 값 선택 및 적용**

    • **누락 값 처리 후 데이터셋 재평가**

  • 누락 값 처리의 중요성

    • 데이터 분석 및 모델링의 정확성 제고

    • 예측 모델의 성능 향상

Identify missing values

Python 라이브러리:

  • Pandas와 같은 라이브러리를 이용하여 누락 값 확인 가능

AWS 서비스:

  • **Amazon SageMaker Autopilot**

    • 다양한 누락 값 대체 방식 제공

  • **Amazon SageMaker Data Wrangler**

    • 데이터 준비를 위한 종합적인 도구

AWS 서비스의 장점:

  • 누락 값 처리를 위한 사용자 편의적인 기능 제공

  • 추후 이 과정에서 SageMaker Data Wrangler에 대해 자세히 학습할 예정

Python 라이브러리와 AWS 서비스 활용:

  • 누락 값 확인 및 대체 방식 선택에 도움

  • 데이터 준비 작업의 효율성 향상

Determine why values are missing

  1. Missing at Random (MAR) - 무작위 누락

    • 누락 데이터가 **관찰 가능한 데이터에만 의존**하고, 누락 데이터 자체에는 의존하지 않음

    • 데이터가 누락된 이유가 관찰된 다른 데이터에 의해 설명될 수 있는 경우

    • 예: 결석한 학생의 시험 점수 누락

  2. Missing Completely at Random (MCAR) - 완전 무작위 누락

    • 누락 데이터 여부가 관찰 가능한 데이터나 관찰되지 않은 데이터에 **전혀 의존하지 않음**

    • 데이터가 누락된 이유가 관찰된 데이터나 누락된 데이터 자체와 전혀 관련이 없는 경우

    • 예: 직원 설문조사에서 가족 수 정보 누락

  3. Missing Not at Random (MNAR) - 비무작위 누락

    • 누락 데이터 여부가 **누락된 데이터 자체에 의존**함

    • 데이터가 누락된 이유가 누락된 데이터 자체와 관련되어 있는 경우

    • 예: 회계 부정이 있는 기업의 재무 기록 누락

데이터 누락 원인 파악의 중요성:

  • 누락 데이터의 유형에 따라 적절한 처리 방법이 달라짐

  • 이를 고려하지 않으면 잘못된 데이터 처리로 이어질 수 있음

시계열 데이터의 누락 데이터 처리 방법 : https://docs.aws.amazon.com/sagemaker/latest/dg/timeseries-forecasting-data-format.html

  1. 타깃 변수(target column - 모델이 예측해야 하는 핵심 변수) 누락 데이터 처리

    • **기본적으로 0 filling** 적용

    • 0 외에도 **특정 값, NaN, 평균, 중위값, 최소값, 최대값** 등으로 대체 가능

  2. 기타 수치형 변수 누락 데이터 처리

    • 기본적으로 자동 filling 없음

    • 중간 값 filling, 뒤쪽 값 filling, 미래 값 filling 등의 방법 사용 가능 (Middle, Back, Front, Future filling)

    • 0, 특정 값, 평균, 중위값, 최소값, 최대값 등으로 대체 가능

  3. 누락 데이터 처리 시 고려 사항

    • 타깃 변수와 다른 변수의 누락 처리 방식 구분 필요

    • 누락 데이터의 의미와 모델 성능 영향을 고려하여 적절한 filling 방식 선택

  4. Amazon SageMaker Autopilot의 누락 데이터 처리 지원

    • 다양한 filling 방식 제공

    • 타깃 변수와 기타 변수에 대한 별도 설정 가능

  5. 누락 데이터 처리의 중요성

    • 데이터 품질 향상

    • 모델 성능 제고

Categorical Encoding Techniques

Categorical Encoding

Types of categorical values

  1. 이진 범주형 (Binary Categorical)

    • 두 가지 옵션 중 하나를 나타내는 값

    • 예: 어떤 행사에 참석했는지 여부(true/false)

  2. **명목형** 범주형 (Nominal/Multi-Categorical)

    • 순서가 중요하지 않은 범주형 값

    • 예: 지역(주, 시 등)

  3. **순서형** 범주형 (Ordinal)

    • 순서가 중요한 범주형 값

    • 예: 커피 사이즈(small, medium, large)

공통점:

  • 수치형 데이터와 구분되는 범주형 데이터의 유형

차이점:

  • 이진 범주형: 2가지 옵션

  • 명목형/다중 범주형: 순서 무관

  • 순서형: 순서가 중요

When to encode

  1. **모든 범주형 변수를 인코딩할 필요는 없음**

    • 문제 사례에 따라 인코딩이 필요하지 않은 경우도 있음

  2. 기계 학습 알고리즘에 따른 차이

    • 예) 랜덤 포레스트 모델은 범주형 변수를 직접 처리할 수 있음

    • 이 경우 “teal”, “green”, “blue” 등을 숫자로 인코딩할 필요 없음

  3. 인코딩 필요 여부 판단 시 고려 사항

    • 사용하려는 기계 학습 알고리즘의 특성

    • 범주형 변수의 특성(이진, 명목, 순서 등)

    • 문제 해결을 위한 최적의 접근 방식

  • Ordinal data describes data that is categorical, but ranked in a numeric order

Encoding Techniques

Label encoding

  • converts categorical values into binary numbers, assigning each **unique category value** a binary code

One-hot encoding

  1. 개념

    • 각 범주형 변수의 **고유한 값마다 새로운 이진 특성(feature)**을 만드는 기법

    • **해당 범주에 대해서는 1, 나머지 범주에 대해서는 0**으로 표현

  2. 장점

    • 범주형 변수를 구별할 수 있는 수치 데이터로 변환

    • 범주 간 순서나 크기 관계를 고려하지 않음

  3. 구현 과정

    • 범주형 변수의 고유한 값 수만큼 새로운 열 추가

    • 해당 범주에 속하는 데이터는 1, 나머지는 0으로 표현

  4. 특징

    • 특성 공간이 확장되어 데이터셋 크기가 증가

    • 범주형 변수의 고유한 값 수에 따라 새로운 열이 생성

  5. 활용

    • 범주형 변수를 다룰 수 있는 대부분의 ML 알고리즘에서 사용

  6. 범주 수가 많은 경우 적합하지 않음

    • 범주의 수가 많아지면 새롭게 생성되는 열의 수가 급격히 증가

    • 데이터셋의 크기가 너무 커져 효율적인 분석이 어려워질 수 있음

  7. 데이터셋 크기 증가

    • 범주형 변수의 고유 값 수만큼 새로운 열이 생성되므로

    • 데이터셋의 크기가 크게 늘어날 수 있음

  8. 희소성 증가

    • 각 열은 대부분 0으로 구성되어 데이터의 희소성이 높아짐

    • 이로 인해 모델 학습 및 분석의 효율성이 떨어질 수 있음

  9. 대안으로 고려해 볼 수 있는 방법

    • 라벨 인코딩(Label Encoding)

    • 다른 인코딩 기법(예: 목적함수 기반 인코딩 등)

Feature Engineering

Feature Engineering Concepts

Requirements

  • Understanding the raw data

  • Recognizing the business problem

  • Selecting the right ML algorithm

Tailoring feature engineering for your business

  1. 피처 엔지니어링은 과학보다 예술에 가까움

    • 엄격한 규칙이 아닌 **직관적인 접근**이 필요

    • 해결하고자 하는 문제에 따라 접근 방식이 달라짐

  2. 피처 엔지니어링의 핵심 요소

    • **원시 데이터**에 대한 이해

    • **비즈니스 문제**에 대한 이해

    • 데이터와 알고리즘을 연결하는 **직관력**

  3. 인간의 역할 중요성

    • 데이터와 문제 간의 관계를 발견하는 능력이 중요

    • 직관을 활용하여 효과적인 피처 엔지니어링 수행

  4. 접근 방식의 특징

    • 규칙 기반이 아닌 **문제 중심적**

    • 데이터와 비즈니스 이해가 선행되어야 함

  5. 시사점

    • 피처 엔지니어링은 데이터 분석가의 전문성이 발휘되는 영역

    • 데이터와 문제에 대한 깊이 있는 이해가 필요

Feature engineering methods

데이터 유형별 피처 엔지니어링 기법

  • **숫자형 데이터: 그룹화, 스케일링, 변환** 등

  • **텍스트 데이터: 토큰화, N-gram** 등

Numeric feature engineering

  1. 숫자형 피처 엔지니어링 활용 사례

    • 높은 분산을 가진 수치 특성

    • 극단값이 포함된 분포도

    • 시간 관련 수치 특성

  2. 숫자형 피처 엔지니어링 기법

    • **특성 스케일링, 빈 집계, 로그 변환** 등 (scaling, binning - 구간으로 나누어 관리, and log transformation)

    • 모델이 수치 관계를 더 잘 이해할 수 있게 함

Text feature engineering

  1. 텍스트 피처 엔지니어링 활용 사례

    • 대부분의 텍스트 데이터에서 유용

  2. 텍스트 피처 엔지니어링 기법

    • **Bag-of-Words, N-gram** 등

    • **텍스트를 토큰 단위로 분해**하여 모델이 이해할 수 있게 함

Numeric Feature Engineering

Feature Scaling

  1. 피처 스케일링이란?

    • 데이터를 **특정 범위 내에 맞추어 크기를 조정**하는 기법

    • 모든 수치형 변수를 **동일한 척도(scale)**로 변환

  2. 목적

    • 큰 수치를 줄여 ML 알고리즘의 빠른 계산 가능

    • 데이터 범위의 차이로 인한 편향 방지

  3. 예시

    • 주택 데이터: 침실 수(1~5)와 주택 가격(100,000 1,000,000)

    • 침실 수와 가격의 범위가 크게 다름

  4. 필요성

    • 많은 ML 알고리즘이 데이터 범위에 민감

    • 피처 스케일링이 필요한 경우가 많음

  5. 예외적 경우

    • 의사결정 트리 등 일부 ML 모델은 데이터 범위에 영향을 받지 않음

    • 이런 경우 피처 스케일링이 필요하지 않을 수 있음

  6. 적용 여부 결정

    • 사용할 ML 알고리즘의 특성을 고려하여 결정

Normalization

  1. 정규화란?

    • 수치형 특성의 값을 일반적으로 **0과 1 사이의 범위로 재조정**하는 기법

  2. 목적

    • 특성 간 값의 크기 차이를 줄여 모델의 공정성 확보

    • 특성 크기가 큰 값이 모델에 과도한 영향을 미치는 것 방지

  3. 주택 데이터 예시

    • 주택 가격 특성: 100,000 ~ 1,000,000

    • 정규화 후: 0 ~ 1 사이의 값으로 변환

  4. 정규화 방식

    • 최소값을 0, 최대값을 1로 설정하고 나머지 값 선형 조정

  5. 장점

    • **특성 간 크기 차이 해소**

    • **모델의 공정성 및 안정성 향상**

  6. 한계

    • **극단값에 민감**할 수 있음

    • **이상치에 영향** 받을 수 있음

Standardization

  1. 표준화란?

    • 데이터 값을 **평균 0, 표준편차 1로 재조정**하는 기법

  2. 정규화와의 차이

    • 정규화는 0-1 사이 범위로 조정

    • 표준화는 평균 0, 표준편차 1로 조정

  3. 주택 데이터 예시

    • 주택 가격의 평균을 0, 표준편차 1로 변환

  4. 장점

    • **이상치의 부정적 영향 감소**

    • **정규화보다 안정적인 특성 변환**

  5. 구현 방식

    • (값 - 평균) / 표준편차

  6. 활용 사례

    • 이상치가 많은 경우 표준화가 더 적합

    • 선형 모델, 신경망 등 다양한 알고리즘에서 활용

표준화는 이상치에 덜 민감하며, 모델 학습에 도움이 되는 피처 엔지니어링 기법입니다.

Binning

  1. 빈 집계란?

    • 수치형 특성을 **더 작은 범주(bin)로 그룹화**하는 기법

    • **수치형 특성을 범주형 특성으로 변환**

  2. 목적

    • **이상치의 영향 감소**

    • **특성과 타깃 간 비선형 관계 포착 용이**

  3. 활용 사례

    • 정확한 수치보다는 범위 구분이 중요한 경우

    • 예) 주택 가격 특성 - 150,000과151,000은 구분하지 않고 150,000과500,000은 구분

  4. 빈 집계 방식

    • 등간격 빈: 일정 간격으로 구간 나누기

    • 등도수 빈: 데이터 개수가 동일하도록 구간 나누기

    • 퍼센타일 빈: 지정한 퍼센타일 단위로 구간 나누기

  5. 장점

    • **이상치 영향 감소**

    • **비선형 관계 모델링** 용이

빈 집계는 수치형 데이터의 특성 변환에 효과적인 피처 엔지니어링 기법입니다.

Log Transformation

  1. 로그 변환이란?

    • 수치형 특성에 **로그 함수를 적용하여 변환**하는 기법

  2. 로그 함수의 종류

    • 주로 밑이 10 또는 자연상수 e인 로그 함수 사용

    • 지수 함수의 역함수 특성을 갖음

  3. 사용 목적

    • **편향된 데이터 분포 정규화**

    • **이상치의 영향 감소**

    • 정규 분포에 더 가깝게 만들기

  4. 주택 가격 데이터 예시

    • 지역별 극단적인 가격 차이

    • 로그 변환을 통해 큰 이상치 값 축소

  5. 장점

    • 데이터 분포의 정규성 향상

    • 이상치 영향 감소

    • 모델 성능 개선

로그 변환은 편향된 수치형 데이터를 정규화하고 이상치 영향을 줄이는 데 효과적인 피처 엔지니어링 기법입니다.

Text Feature Engineering

Bag-of-words (단어 주머니)

  1. 단어 주머니 모델이란?

    • 단어의 **순서는 고려하지 않고** 단어 **출현 빈도만 세는 기법**

  2. 작동 방식

    • **텍스트를 토큰화하여 단어별 통계 정보 생성**

    • 단어와 빈도를 포함한 행렬 형태로 표현

  3. 주택 데이터 활용 예시

    • 학군 평가 관련 학부모 후기 텍스트 데이터 활용

    • 후기 텍스트를 토큰화하여 단어 빈도 행렬 생성

  4. 장점

    • 단순하면서도 효과적인 텍스트 특성 추출 방법

    • 단어의 순서 정보는 필요하지 않음

  5. 한계

    • **단어 간 상관관계 및 문맥 정보 손실**

    • **고차원적인 특성 벡터** 생성으로 인한 메모리 및 계산 비용 증가

단어 주머니 모델은 기본적이면서도 유용한 텍스트 피처 엔지니어링 기법입니다.

N-gram

  1. N-gram이란?

    • **단어 주머니 모델을 확장**한 기법

    • **n개의 연속된 단어 조합**을 토큰으로 사용

  2. 작동 방식

    • 문장을 n개 단어씩 슬라이딩 윈도우로 분할

    • 각 n개 단어 조합을 하나의 토큰으로 취급

  3. 주택 데이터 활용 예시

    • 학부모 후기에서 “great teachers”, “after-school programs” 등의 단어 조합 빈도 파악

  4. 장점

    • **단어 간 관계 및 문맥 정보 반영** 가능

    • 특정 단어 조합의 중요성 파악

  5. 단점

    • **특성 벡터의 차원이 높아질 수 있음**

    • **희소성**으로 인한 계산 비용 증가

N-gram 모델은 단어 간 관계와 문맥 정보를 보존하는 텍스트 피처 엔지니어링 기법입니다.

Temporal data

  1. 시계열 데이터란?

    • 시간에 따라 변화하는 데이터

    • 날짜, 시간 정보를 포함하는 데이터

  2. 시계열 데이터의 특징

    • **숫자형 및 텍스트형 데이터가 혼재** 될 수 있음

  3. 시계열 데이터의 피처 엔지니어링 중요성

    • 시간에 따른 트렌드, 주기, 패턴 포착 가능

    • 예) 시간대, 요일, 계절 등의 특성 추출

  4. 주택 데이터 예시

    • 매물 등록 날짜 정보 활용

    • 날짜를 일, 월, 연 단위로 나누어 새로운 특성 생성

    • 여름철, 매월 초 등 패턴 발견 가능

  5. 피처 엔지니어링의 효과

    • 시간 기반 관계를 더 잘 이해하고 예측할 수 있게 함

시계열 데이터의 경우, 시간 정보를 효과적으로 활용할 수 있도록 피처 엔지니어링이 필수적입니다.

Feature Selection Techniques

Feature Selection

  1. 피처 선택이란?

    • 모델 학습에 **가장 적합한 특성을 선별**하는 과정

  2. 피처 스케일링과의 차이

    • 피처 스케일링은 특성 값의 범위를 조정

    • 피처 선택은 **불필요한 특성을 제거**

  3. 주택 데이터 예시

    • 가격, 위치, 등록 날짜, 침실 수 등의 특성

    • 위치와 등록 날짜는 제거하고 침실 수와 가격 관계에 집중

  4. 피처 선택의 장점

    • 모델 성능 향상

    • 모델 복잡도 감소

    • 과적합 위험 감소

  5. 피처 선택 방법

    • 상관관계 분석, 분산 분석 등을 통한 수동 선택

    • 알고리즘 기반 자동 선택 기법 활용

Feature Splitting and combining

  1. 피처 분할(Feature Splitting)

    • 기존 특성을 세부적인 특성으로 분할하는 기법

    • 특성 공간을 확장하여 모델링에 활용할 수 있는 정보 증가

  2. 피처 결합(Feature Combining)

    • 여러 특성을 하나의 새로운 특성으로 통합하는 기법

    • 특성 공간을 축소하여 모델 복잡도 감소

  3. 주택 데이터 예시

    • 피처 분할: 침실 수를 소형, 중형, 대형 침실 수로 세분화

    • 피처 결합: 각 실 면적 특성을 통합하여 총 면적 특성 생성

  4. 장점

    • 더욱 의미 있는 특성 생성

    • 모델 성능 향상

    • 모델 복잡도 감소

  5. 고려 사항

    • 데이터에 대한 깊은 이해 필요

    • 적절한 분할/결합 기준 설정 필요

Principal component analysis

  1. PCA란?

    • **데이터의 차원을 축소하는 통계적 기법**

    • 원본 데이터의 변동성을 최대한 보존하면서 특성 수를 줄임

  2. PCA의 작동 원리

    • **상관관계가 없는 새로운 특성(주성분)을 생성**

    • 주성분들을 변동성 순으로 정렬

  3. 주택 데이터 예시

    • 5개 특성을 2개의 주성분으로 축소

    • 1번 주성분: 주택 크기 관련

    • 2번 주성분: 주택 가격 관련

  4. PCA의 장점

    • 모델 계산 효율성 향상

    • 과적합 위험 감소

  5. 활용 시 고려 사항

    • 데이터의 특성과 문제 상황에 적합한 주성분 선택 필요

    • 원본 데이터의 변동성을 충분히 설명할 수 있는 주성분 개수 결정

PCA는 데이터 차원 축소를 통해 모델 성능과 효율성을 높일 수 있는 중요한 기법입니다.

Mechanical Turk

  • 데이터 변환은 복잡하고 지루한 작업

  • 인간의 판단력과 품질 관리가 필수적

  • Amazon Mechanical Turk을 통해 마이크로태스크 단위로 분해하여 처리

  • 비용과 시간을 효과적으로 절감할 수 있음

Key Benefits

  1. 온디맨드 인력 접근성

    • 전 세계에 분포된 다양한 인력에게 즉시 접근 가능

  2. 낮은 비용

    • 기존 방식보다 마이크로태스크 단위로 비용 절감

  3. 신속한 처리 속도

    • 분산된 온라인 인력을 활용하여 작업을 빠르게 완료

  4. 유연한 태스크 구성

    • 다양한 유형의 마이크로태스크로 워크플로우 분해 가능

  5. 품질 관리 기능

    • 작업자 평가, 샘플링, 검토 등을 통해 품질 보장

Use Cases

  1. 이미지 주석 달기

    • 이미지에 경계 상자, 의미 분할 등 라벨링

    • 컴퓨터 비전 모델 학습에 활용

  2. 텍스트 주석 달기

    • 대본, 설문지, 문서 등에 감성 분석, 개체 추출 등 주석

    • 언어 모델 학습에 활용

  3. 데이터 수집

    • 설문, 작업 등을 통해 새로운 데이터셋 생성

    • 공개된 데이터가 부족한 경우 유용

  4. 데이터 정제 (cleanup)

    • 기존 데이터셋의 문제점 해결

    • 부정확한 라벨 수정, 형식 통일 등

    • 모델 정확도 향상에 기여

  5. 음성 전사 (Transcription)

    • 인터뷰, 통화 등 음성을 텍스트로 변환

    • 법률, 의료, 고객 지원 분야에서 유용

  1. 온디맨드 인력 활용

    • 컴퓨터로 처리하기 어려운 작업을 수행할 수 있는 다양한 인력에 접근 가능

  2. 사용자 편의성

    • 사용자 인터페이스 및 API를 통해 손쉽게 활용 가능

  3. 인간 지능 활용

    • 데이터 처리, 콘텐츠 모더레이션 등 AI로는 어려운 마이크로태스크를 수행

  4. 확장성

    • 상시 근로자를 고용하지 않고도 인력 동원이 가능

  5. 비용 효율성

    • 마이크로태스크 단위로 저렴한 비용으로 작업 처리

SageMaker Ground Truth

SageMaker Ground Truth는 Mechanical Turk 등의 데이터 처리 방식을 활용하여 **데이터 준비 과정을 더욱 간소화한 서비스**

SageMaker Ground Truth의 핵심 장점:

  1. 확장 가능한 인적 레이블링을 통해 ML 모델 개발 **가속화** (Expedites training data preparation)

  2. 이미지, 텍스트, 객체 감지 등을 위한 **레이블링 워크플로우 제공** (Streamlines setting up labeling projects)

  3. 능동 학습, 검증, 부실 작업자 제거를 통한 **고품질 학습 데이터 확보** (Ensures high quality training data)

  4. 액세스 제어, 암호화, 종량제 과금 모델을 통한 데이터 프라이버시, 보안, 비용 효율성 제공 (Provides data privacy, security, and cost efficiency)

주요 활용 사례:

  • 이미지 분류: 이미지에 분류 레이블 지정

  • 텍스트 분류: 텍스트 문서에 주제 레이블 지정

  • 객체 감지: 이미지에서 객체 경계 상자 그리기

  • 개체명 인식: 텍스트에서 개체명 태깅

SageMaker Ground Truth 제공 옵션:

  • SageMaker Ground Truth: 자체 관리형 레이블링 플랫폼

  • SageMaker Ground Truth Plus: 전문가의 관리형 데이터 레이블링 서비스

SageMaker Feature Store

  • **특성 엔지니어링 결과를 중앙에서 관리하는 저장소**

  • 모델 **학습과 추론에 공유 및 재사용** 가능

  • 자동 데이터 전처리, 특성 거버넌스, 성능 향상 등의 기능 제공

주요 활용 사례:

  • 자동 데이터 전처리: 스케일링, 인코딩, 변환 등 (Automated data preprocessing)

  • 중앙 특성 저장소: 특성의 표준화 및 재사용 (Centralized feature repository)

  • 특성 파이프라인 관리: 생애주기 전반의 관리 및 모니터링 (Management of feature pipelines)

  • 성능 향상: 자주 사용되는 특성의 캐싱 (Caching for performance)

  • Standardized features: 조직 내 특성 데이터의 단일 소스를 확립

Import training data : Import your training data into the SageMaker Feature Store by creating a feature group and populating (등록) it with data from Amazon S3, Redis, or a Java Database Connectivity (JDBC) source.

Transform data : Transform the data as needed using SQL queries. You can query and join feature groups to derive new features. For example, you could create new aggregate features like averages or counts.

Define feature transformation job : Define a feature transformation job to configure a batch transform job that runs on a recurring schedule and applies transformations to your data.

Configure and start job : Configure the output location for the transformed data, which is often a separate Amazon S3 location or feature group. Start the feature transformation job that will run the data transformations on the input data based on the defined schedule.

Use transformed features : Use the transformed features in your model training and inference jobs. The output can be accessed through the location configured in step 4.
