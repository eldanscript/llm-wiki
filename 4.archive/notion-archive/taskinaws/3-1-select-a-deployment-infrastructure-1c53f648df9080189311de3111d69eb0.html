3.1 Select a Deployment Infrastructure

Course Overview

💡

이 과정에서 다루는 주요 내용은 다음과 같습니다:

  1. 배포 인프라 선택하기

    • 모델 배포 및 실행을 위한 **적절한 컴퓨팅 환경을 선택하는 방법**을 학습합니다.

    • **성능과 비용 간의 균형**을 이해하는 것이 중요합니다.

  2. 인프라 생성 및 스크립팅

    • **확장성, 유지보수성, 비용 효율성**을 갖춘 ML 솔루션을 구축하는 방법을 배웁니다.

    • 프로그래밍 방식으로 **리소스를 프로비저닝**하고, Amazon **SageMaker를 사용**하여 **모델을 배포**하며, **DevOps와 성능 최적화**를 지원하는 AWS 서비스를 활용하는 방법을 다룹니다.

  3. 배포 자동화

    • **MLOps와 CI/CD 파이프라인을 활용**하여 ML 워크로드에 DevOps 실practices를 적용하는 방법을 학습합니다.

    • 프로덕션 환경에서의 **위험 관리 및 성능 향상 전략**을 다룹니다.

    • 새로운 데이터나 모델 코드 업데이트에 대응하기 위한 **모델 재교육 메커니즘**을 구축하는 방법을 배웁니다.

기계 학습 엔지니어의 주요 책임 중 하나는 ML 모델을 프로덕션 환경에 배포하는 것입니다. 이 영역의 첫 번째 과정부터 시작하여 자세히 알아보시기 바랍니다.

ML 파이프라인에서의 모델 배포:

  • ML 모델을 실제 운영 환경에 배포하는 과정

프로덕션 인프라와 구성 요소:

  • 모델을 실제로 배포하고 운영하는 인프라

  • 주요 구성 요소: 컴퓨팅 환경, 데이터 저장소, 네트워킹, 모니터링 등

오케스트레이션 서비스 비교 및 대조:

  • ML 워크플로우를 관리하고 자동화하는 서비스

  • 서비스 간 기능, 사용성, 확장성 등 비교

배포 인프라 설계 고려 사항:

  • 확장성, 보안, 비용, 운영 효율성 등 다양한 요소 고려

최적의 배포 대상 선택:

  • 핵심 이점을 기반으로 클라우드, 온프레미스, 엣지 등 선택

ML 모델 배포 전략과 엔드포인트 요구 사항:

  • 블루/그린, 캐나리, 람다 등 다양한 배포 전략

  • 각 전략의 엔드포인트 요구 사항 차이

최적의 모델 배포 호스팅 전략 선택:

  • 핵심 이점을 기반으로 서버리스, 컨테이너, 가상머신 등 선택

멀티 모델 또는 멀티 컨테이너 배포 선택:

  • 핵심 이점을 기반으로 단일 모델/컨테이너 또는 멀티 모델/컨테이너 선택

최적의 컨테이너 옵션 선택:

  • 핵심 이점을 기반으로 Docker, Podman, containerd 등 선택

컴퓨팅 인스턴스 유형 및 선택:

  • AWS 인스턴스 유형 나열 및 설명

  • 학습 및 추론을 위한 최적의 컴퓨팅 환경 선택

온디맨드 vs. 프로비저닝 리소스:

  • 성능과 확장성 측면에서의 차이점 설명

  • 프로덕션/테스트 환경에서의 리소스 프로비저닝 방법

엣지 디바이스의 모델 최적화:

  • 모델 경량화, 양자화, 압축 등 기법으로 엣지에 배포

Model Deployment Workflows

모델 배포 인프라 작동 방식:

  • 모델 배포는 ML 프로세스의 다양한 부분에 적용될 수 있는 광범위한 용어

  • 인프라라는 용어 또한 ML 수명 주기의 다양한 구성 요소를 설명하는 데 사용되어 혼란스러울 수 있음

  • 모델 배포 인프라를 선택하고 오케스트레이션할 때는 여러 계층을 고려해야 함

배포 관련 주요 질문:

  1. 무엇을 배포하고 있는가?

  2. 어디에 배포하고 있는가?

모델 구축 및 배포 인프라:

  • 기계 학습 모델의 학습 및 최적화

  • **데이터 처리, 특성 엔지니어링, 모델 학습, 검증 및 최적화**

  • GPU 등의 **컴퓨팅 리소스** 필요

  • 추론에 사용될 최종 학습된 **모델 산출물** 출력

추론 인프라:

  • 배포된 학습된 **모델 호스팅 및 추론 실행**

  • 새로운 **데이터 수신, 모델 실행, 예측 및 결과 반환**

  • 저지연성, 고처리량 추론 서빙에 중점, 높은 요청 볼륨 확장 지원

  • 클라우드, 온-프레미스, 엣지 환경에 배포 가능

모델 배포의 주요 challenges:

  • 데이터 품질 및 전처리 (Data quality and preprocessing)

  • 모델 모니터링 및 유지보수 (Model monitoring and maintenance)

  • 확장성 및 성능 (Scalability and performance)

  • 인프라 및 DevOps (Infrastructure and DevOps)

  • 지속적 배포 및 업데이트 (Continuous delivery and updates)

Building a Repeatable Framework

ML 파이프라인

ML 운영 프레임워크의 구성 요소

  • 효과적이고 반복 가능한 모델 배포 인프라 구축이 목표

  • 입력 데이터셋에서부터 추론 요청 처리까지 자동화된 end-to-end 파이프라인 구축

MLOps 기능 내 프레임워크 구성 요소

버전 관리

  • 버전 관리 시스템을 통해 **변경 사항 추적, 팀원 협업, 재현성 보장**

  • Github를 활용할 수 있음

CI/CD (지속적 통합 및 배포)

  • **코드, 데이터, 모델 변경사항을 자동으로 테스트, 검증, 배포**

  • 오류 감소 및 일관성 있는 ML 시스템 배포 보장

  • AWS CodePipeline, AWS CodeBuild 활용

ML 모델 구축

  • 데이터 준비, 특성 엔지니어링, 모델 학습, 평가 과정 포함

  • **Amazon SageMaker Training Jobs**를 통해 **확장 가능하고 재현 가능한 모델 학습 파이프라인** 구축

ML 모델 배포

  • 학습된 모델 컨테이너화, 타겟 애플리케이션/서비스 통합, 시스템 아키텍처와의 연계

  • **Amazon SageMaker를 통해 안전하고 확장 가능한 모델 호스팅 및 서빙**

모니터링

  • 모델 성능, 편향 검출 등 **지속적 평가 및 개선**

  • **Amazon SageMaker Clarify** 활용

워크플로 보안

  • **민감 데이터, 중요 애플리케이션을 위한 보안 및 데이터 보호** 조치

  • IAM 정책, 암호화 등 보안 제어 장치 적용

모델 레지스트리

  • **ML 모델, 메타데이터, 관련 아티팩트의 중앙 저장소**

  • **버전 관리, 추적, 배포, 거버넌스**를 지원

  • Amazon SageMaker Model Registry 활용

테스트 및 평가

  • 단위, 통합, 엔드-투-엔드 테스트 수행

  • 프로덕션 환경에서의 **성능, 공정성, 강건성 지속 평가**

  • AWS Lambda를 통해 CI/CD 파이프라인 내 테스트 자동화

예시 파이프라인 시퀀스 1

데이터 처리 파이프라인:

  • 데이터 정제, 특성 엔지니어링 등을 통한 데이터 준비

  • ML 모델 학습 및 개발을 위한 데이터 준비 과정

Docker 빌드 파이프라인:

  • 소스 코드 리포지토리의 Docker 파일을 사용하여 Docker 이미지 빌드

  • Amazon ECR 등의 컨테이너 레지스트리에 이미지와 메타데이터 푸시

모델 구축, 학습 및 평가 파이프라인:

  • 기존 Docker 컨테이너 이미지와 데이터셋을 사용하여 모델 학습 및 평가

  • 모델 정확도 검증

모델 등록 파이프라인:

  • 학습된 모델을 Amazon SageMaker 모델 레지스트리에 등록

  • S3에 저장된 모델 아티팩트와 ECR의 추론 컨테이너 연결

  • 모델 구축 및 학습 파이프라인의 조건부 단계로 포함될 수 있음

배포 파이프라인:

  • 기존 모델을 엔드포인트에 배포

  • 엔드포인트 호스팅을 위한 인프라 프로비저닝 포함

모니터링 파이프라인:

  • 추론 인프라와 프로덕션 데이터에 대한 모델 성능 모니터링

  • 알림 및 자동 remediation 기능 포함

예시 파이프라인 시퀀스 2

CI/CD 도구:

  • 코드 리포지토리와 통합된 CI/CD 도구 필요

  • 파이프라인 코드의 버전 관리를 위한 코드 리포지토리

데이터 소스:

  • 모델 학습 작업을 위한 데이터 소스 통합 필요

  • 모델 구축 데이터셋의 버전 관리를 위한 데이터 저장소

모델 학습 및 검증 도구:

  • 모델 학습 및 검증을 위한 도구 접근 필요

  • 학습 컨테이너 이미지 관리를 위한 컨테이너 레지스트리 접근

모델 저장소:

  • 성능 요구사항을 충족하는 모델을 저장하는 모델 저장소 필요

Workflow Orchestration Options

Amazon SageMaker Pipelines

  • ML 워크플로 자동화 및 관리를 위한 전용 오케스트레이션 솔루션

  • SageMaker 기능 및 다른 AWS 서비스와 통합

SageMaker Pipeline 구성 요소

  • 데이터 처리, 모델 학습, 모델 등록 등 ML 라이프사이클 자동화

  • 조건부 분기, 오류 처리 등 다양한 파이프라인 단계 지원

데이터 소스 통합

  • 모델 구축 파이프라인은 데이터 소스에 대한 적절한 권한과 통합이 필요

SageMaker Feature Store

  • 효과적인 모델을 위한 **특성 저장 및 관리**

  • 학습 작업 간 특성 재사용을 지원하여 파이프라인 반복성 향상

SageMaker 처리

  • 데이터 전처리, 학습/검증/테스트 데이터셋 생성

  • SageMaker DataWrangler, SageMaker Clarify 활용

Amazon ECR

  • 학습 컨테이너 이미지를 ECR에서 가져와 학습 작업 실행

  • SageMaker와의 통합으로 간편한 통합 제공

SageMaker 학습

  • 처리 작업에서 생성된 데이터와 학습 컨테이너를 사용하여 모델 학습

모델 검증

  • 학습 작업으로 생성된 모델이 성능 요구사항을 충족하는지 테스트

SageMaker Pipeline Step Types

원시 데이터:

  • ML 라이프사이클의 시작점

  • Amazon S3, Amazon Athena, Amazon Redshift 등에 저장 가능

학습 데이터:

  • 전처리 및 정제된 데이터

  • SageMaker Pipeline의 처리 단계에서 데이터 변환, 특성 공학, 학습/검증 데이터 분할 수행

모델 개발:

  • 준비된 학습 데이터로 ML 모델 학습

  • SageMaker Pipeline의 학습 단계에서 알고리즘, 인스턴스, 하이퍼파라미터 등 구성

SageMaker 학습:

  • 데이터 처리, 모델 학습, 모델 평가 등 전체 워크플로 자동화

SageMaker 처리:

  • 데이터 전처리, 특성 엔지니어링, 모델 평가, 배치 변환 등에 활용

SageMaker 모델 레지스트리:

  • 승인된 모델을 버전 관리, 카탈로그화하여 배포 또는 재학습에 활용

기타 AWS/3rd-party 오케스트레이션 도구

  • **AWS Step Functions**: 서버리스 워크플로 오케스트레이션

  • **Amazon MWAA**: Apache Airflow 기반 워크플로 오케스트레이션

  • **MLflow**: ML 라이프사이클 전반 관리

  • **Kubernetes**: ML 워크플로 Kubernetes 상에서 오케스트레이션

AWS Step Functions

  • SageMaker 기능과 직접 통합된 워크플로 오케스트레이션

  • 데이터 전처리, 모델 학습/배포 등 단계 자동화

Apache Airflow & Amazon MWAA

  • Python 기반 프로그래밍 방식의 워크플로 정의

  • DAG를 통한 복잡한 워크플로 관리 및 시각화

  • 재사용 가능한 오퍼레이터를 통한 확장성

MLflow

https://aws.amazon.com/blogs/machine-learning/managing-your-machine-learning-lifecycle-with-mlflow-and-amazon-sagemaker/

  • ML 라이프사이클 전반(실험, 재현성, 배포, 모델 레지스트리) 관리

  • 실험 추적(**Tracking**): 실험 코드, 데이터, 구성, 결과 등을 기록하고 추적할 수 있습니다.

  • 프로젝트(**Projects**): 재현이 가능한 데이터 사이언스 코드 패키징을 지원합니다.

  • 모델(**Models**): 다양한 서빙 환경에 ML 모델을 배포할 수 있습니다.

  • 레지스트리(**Registry**): 중앙 저장소에서 모델을 저장, 주석, 검색, 관리할 수 있습니다.

Kubernetes

With ACK (AWS Controllers for Kubernetes)

AWS Controllers for Kubernetes (ACK):

  • **Kubernetes 상에서 SageMaker를 사용**하여 ML 모델을 학습, 튜닝, 배포하는 과정을 지원하는 **SageMaker 오퍼레이터**

SageMaker 오퍼레이터 설치:

  • Amazon EKS(Elastic Kubernetes Service) **클러스터에 SageMaker 오퍼레이터 설치** 가능

SageMaker 작업 생성:

  • **Kubernetes API와 kubectl 등 Kubernetes 명령줄 도구를 사용하여 SageMaker 작업 생성** 가능

가격 정책:

  • 오퍼레이터 사용에 별도 요금 없음

Deployment Considerations and Target Options

모델 배포 인프라 설계 고려사항

성능 (Performance)

  • 모델 예측 성능이 시간이 지나도 유지되도록 최적화

  • 모델 아키텍처와 하이퍼파라미터 조정을 통한 효율적 계산 및 추론 달성

가용성 (Availability)

  • 중복성과 장애극복 메커니즘으로 지속적인 서비스 가용성 보장

  • 로드 밸런싱과 수평 확장을 통한 워크로드 분산

확장성 (Scalability)

  • 증가하는 워크로드에 대응하기 위한 모듈형, 분산형 아키텍처 설계

  • 자동 스케일링, 비동기/이벤트 기반 처리로 컴포넌트 간 분리와 확장성 향상

회복성 (Resiliency)

  • 데이터 중복과 백업으로 데이터 손실 방지

  • 부분적 장애에도 기능 저하로 대응하고 자동 복구 구현

내고장성 (Fault Tolerance)

  • 오류 처리와 로깅으로 신속한 문제 식별 및 진단

  • 자동 스케일링, 재시작, 장애조치 등 자체 복구 기능 구현

  • 수동 개입 없이 자동으로 장애로부터 복구

모델 배포를 위한 best practices

  • 자동 스케일링: 워크로드 변화에 따라 인스턴스 자동 조정

  • 모델 변형 테스트: 새로운 모델을 점진적으로 배포하여 검증

  • 대량 데이터를 위한 배치 변환: 배치 변환으로 전체 데이터셋 처리

배포 대상 옵션 (Deployment Targets)

SageMaker 엔드포인트

  • 완전 관리형 서비스, 운영 부담 최소화

  • 모니터링, 로깅 등 기능 제공

  • 커스터마이징이 제한적이며 비용이 높을 수 있음

Amazon EKS

  • 고확장성, 유연성, 커스터마이징 가능

  • 운영 오버헤드 존재, 러닝 커브 있음

Amazon ECS

  • 관리형 컨테이너 오케스트레이션, AWS 연계 좋음

  • 고급 기능은 제한적, 공급업체 종속성 있음

AWS Lambda

  • 서버리스, 자동 스케일링, 저운영 부담, 従량제

  • 실행 시간 제한, 콜드 스타트로 지연 발생, 복잡한 모델에 부적합

SageMaker를 이용한 배포 워크플로

  • SageMaker 엔드포인트 생성

  • 컴퓨팅 리소스, 스케일링 정책, 데이터 캡처, 배포 전략, 보안, 모니터링 등 구성

  • 자동 스케일링, 모델 변형 테스트, 대량 데이터를 위한 배치 변환 등 best practices 적용

  • SageMaker 모델 생성

    • **Amazon S3 버킷에 저장된 모델 아티팩트**와 **Amazon ECR 컨테이너 이미지** 지정

    • **SageMaker Inference Recommender**를 사용하여 추론 옵션 추천 받기

  • SageMaker 엔드포인트 구성 생성

    • 필요한 인스턴스 유형과 수 선택

  • SageMaker 추론 엔드포인트 생성

    • 생성한 추론 엔드포인트 구성으로 엔드포인트 생성

    • 생성된 엔드포인트에 요청을 보내 추론 응답 받기

SageMaker Endpoints

  • 엔드포인트의 개념

    • 엔드포인트는 물리적 객체로 취급되지만, 다양한 인프라 구성 요소로 구현될 수 있음

    • 여러 논리적 단계의 파이프라인으로 구성될 수 있으며, 수동 또는 자동화 도구로 생성 가능

    • IP 주소는 엔드포인트에 포함되지 않고 연결되는 것으로 간주됨

  • 엔드포인트 구성

    • 실시간 추론 엔드포인트로 모델을 배포하기 위한 설정과 매개변수 정의

    • 다음 6가지 요소를 고려하여 구성:

    1. 컴퓨팅 리소스: 모델 호스팅에 필요한 인스턴스 유형/리소스 선택

      • 최소 2개의 동일한 인스턴스로 구성하여 가용성과 내결함성 보장

    2. 스케일링 정책: 트래픽, 리소스 사용률, 맞춤 지표에 따른 스케일링 정책 정의

    3. 데이터 캡처: 입력 데이터와 예측 결과를 캡처/저장하여 디버깅, 감사, 규제 목적으로 활용

    4. 배포 전략: 새로운 모델 버전의 출시 방식과 트래픽 라우팅 정책 정의

    5. 보안 및 접근 제어: 권한, 암호화, 네트워크 접근 제어로 모델과 예측 결과의 보안과 프라이버시 보장

    6. 모니터링 및 로깅: 배포된 모델의 성능과 상태를 추적하기 위한 모니터링 및 로깅 설정

Best Practices for deployment with SageMaker

  • SageMaker를 통한 모델 배포

    • **SageMaker가 프로비저닝, 보안, 모니터링, 자동 스케일링 처리**

    • 사용자는 학습된 **모델 아티팩트와 엔드포인트 지정**

  • 자동 스케일링 적용

    • SageMaker 지원 자동 스케일링으로 워크로드 변화에 따라 **인스턴스 동적 조정**

    • 워크로드 증가 시 추가 인스턴스 프로비저닝, 감소 시 불필요한 인스턴스 제거

  • 모델 변형 테스트 (Model variants)

    • **동일한 HTTPS 엔드포인트에서 다중 모델 버전 테스트**

    • 새로운 모델 변형을 프로덕션 **트래픽의 일부에 먼저 적용하여 검증**

  • 대량 데이터를 위한 배치 변환 (Batch Transform)

    • **전체 데이터셋에 대한 추론**이 필요한 경우 배치 변환을 활용

    • SageMaker가 계산 인스턴스를 초기화하고 **워크로드를 분산** 처리

Model Inference Strategy

SageMaker Inference Option

  • **실시간** 추론: 저지연, 고처리량 요청에 적합

  • **서버리스** 추론: 인프라 관리 없이 간헐적 트래픽 처리

  • **비동기** 추론: 대용량 페이로드 처리를 위해 요청을 대기열에 넣음

  • **배치 변환**: 대용량 오프라인 데이터셋 처리

Real-Time Inference

  • 실시간 호스팅 추론 아키텍처 샘플

    • API 게이트웨이:

      • RESTful API 호출을 위한 엔드포인트 제공

      • 보안, 모니터링, 클라이언트-호스트 간 트래픽 관리

    • 로드 밸런서:

      • 여러 서버 간 트래픽 분산

  • SageMaker 엔드포인트 생성 과정

    1. 모델 아티팩트와 추론 컨테이너 이미지로 SageMaker 모델 생성

    2. SageMaker 엔드포인트 구성 정의

    3. SageMaker 엔드포인트 생성

  • SageMaker 실시간 엔드포인트 아키텍처

    • SageMaker가 엔드포인트 유형과 구성 정보 참조하여 인프라 프로비저닝

    • EC2 인스턴스에 추론 컨테이너( Helper 코드 + 추론 코드) 배포

    • 컨테이너 및 인스턴스 옵션에 대해서는 추후 자세히 학습할 예정

Serverless Inference

  1. 주문형 서버리스 추론

    • 유휴 기간 (idle periods) 이 있고 **콜드 스타트를 감내할 수 있는 워크로드**에 적합

    • 자동으로 컴퓨팅 리소스를 프로비저닝하고 트래픽에 따라 스케일링

    • 인스턴스 선택이나 스케일링 정책 관리가 필요 없음

    • 비정기적이거나 예측 불가능한 트래픽 패턴에 대해 비용 효율적

    • **요청이 없을 때 0까지 스케일링하여 비용 절감**

    • 고가용성, 내결함성, 자동 스케일링을 위해 Lambda와 통합

  2. 서버리스 추론의 프로비저닝된 동시성

    • 예측 가능한 트래픽 급증에 비용 효율적인 옵션

    • **최소한의 추론 용량을 프로비저닝하여 엔드포인트를 워밍업**

    • 프로비저닝된 동시성 용량만큼 즉시 응답할 수 있도록 리소스 준비

    • 처리된 데이터량과 프로비저닝된 동시성 용량에 따라 비용 청구

  • 서버리스 호스팅 추론 아키텍처 샘플

    • 애플리케이션이 SageMaker 서버리스 엔드포인트에 추론 요청 전송

    • 요청은 엔드포인트를 통해 서버리스 컴퓨팅 리소스에 호스팅된 추론 컨테이너로 전달

    • 추론 응답이 다시 엔드포인트를 통해 애플리케이션에 반환

Asynchronous Inference

  • 자동 스케일링

    • SageMaker 비동기 추론을 사용하면 **요청이 없을 때 인스턴스 수를 0으로 자동 스케일링하여 비용을 절감**할 수 있음

    • 요청이 들어올 때만 엔드포인트 처리 비용 발생

  • 비동기 호스팅 추론 아키텍처 샘플

    • 엔드포인트 구성 생성 시 AsyncInferenceConfig 객체 지정

    • **요청 페이로드를 Amazon S3에 저장**하고 InvokeEndpointAsync 요청에 **S3 URL 제공**

    • 요청 수신 시 **Amazon SQS에 요청을 대기열**에 넣고 식별자와 출력 위치 반환

    • 처리 완료 후 **결과를 지정된 Amazon S3 위치에 저장**

    • 성공/오류 알림을 Amazon SNS로 선택적으로 받을 수 있음

Batch Transform

  • 배치 변환 사용 사례

    • 데이터셋에서 노이즈나 편향을 제거하기 위한 **전처리**

    • **대용량 데이터셋에 대한 추론** 실행

    • **지속적인 엔드포인트가 필요 없는 경우**

    • **입력 데이터와 추론 결과를 연결하여 결과 해석 지원**

  • 배치 변환 흐름 샘플

    • 배치 변환 작업 생성(콘솔 또는 API)

    • 다음 정보 제공:

      • 입력 데이터가 저장된 S3 버킷 경로

      • 작업 실행을 위한 컴퓨팅 리소스

      • 출력 데이터를 저장할 S3 버킷 경로

      • 추론에 사용할 SageMaker 모델 이름

    • 배치 변환이 컴퓨팅 리소스 프로비저닝, 데이터-모델 상호 작용 등 모든 처리 관리

    • 인스턴스 노드의 에이전트가 이 작업을 수행

Choosing an inference Option

추론 옵션 선택 플로우:

  1. 요청별 추론이 필요한가?

    • 아니요: 배치 변환이 적합

    • 예: 질문 2로

  2. 요청 대기열링이 필요한가?

    • 아니요: 질문 3으로

    • 예: 비동기 추론이 적합

  3. 지속적인 트래픽과 일관된 낮은 지연 시간이 필요한가?

    • 아니요: 질문 4로

    • 예: 실시간 추론이 적합

  4. 지속적인 트래픽과 일관된 낮은 지연 시간이 필요한가?

    • 예: 실시간 추론이 적합

    • 아니요: 서버리스 추론이 적합

배치 변환:

  • 대량의 데이터 처리, 사전 준비된 데이터셋, 지속적 엔드포인트 불필요 시 적합

비동기 추론:

  • 긴 처리 시간 또는 대용량 페이로드로 인한 요청 대기열링이 필요할 때 적합

실시간 추론:

  • 지속적인 트래픽과 낮은 지연 시간이 필요한 온라인 예측에 적합

서버리스 추론:

  • 예측 불가능하거나 간헐적인 트래픽에 적합, 인프라 관리 불필요

Multi-model and multi-container deployments

다중 모델 배포

  • **여러 모델을 호스팅**

  • **공유 서빙 컨테이너** 사용

  • 호스팅 비용 절감

다중 컨테이너 배포

  • 여러 개의 컨테이너 배포

  • **다양한 프레임워크 사용 가능**

  • 직접 호출 방식

다중 모델 배포를 위한 엔드포인트 옵션

  • 개별 엔드포인트 생성 시 인스턴스 활용도가 낮아 비용 증가

  • CloudWatch에서 인스턴스 사용률 지표(CPU, GPU 등) 확인 필요

  • **여러 엔드포인트를 하나의 엔드포인트로 통합하여 인스턴스 활용도 향상 가능**

  • SageMaker는 **단일 엔드포인트에 다중 모델 또는 컨테이너 배포를 지원**

전용 엔드포인트

  • 성능이 가장 우수하지만, 비용이 가장 높음

다중 모델 엔드포인트

  • 여러 모델을 효율적으로 배포할 수 있는 확장성 있고 비용 효율적인 솔루션

  • 단일 모델 엔드포인트에 비해 리소스 활용도 향상으로 호스팅 비용 절감

  • SageMaker가 **모델 메모리 로딩, 트래픽 패턴에 따른 스케일링 관리**

  • 다중 모델 엔드포인트 사용 사례

    A/B 테스트:

    • 모델 버전 간 성능 비교를 위한 A/B 테스트 수행

    • 다양한 모델 버전을 병렬로 호스팅

    앙상블 모델:

    • 문제 도메인의 다양한 부분을 담당하는 모델을 앙상블로 구성

    • 최적의 모델에 요청 라우팅

    동적 모델 로딩:

    • 자주 사용되지 않는 많은 모델을 필요 시에만 로딩

    • 모든 모델을 동시에 호스팅하는 것보다 리소스 절감

    멀티 테넌트 애플리케이션:

    • 고객별 고유 모델 제공을 위한 단일 엔드포인트

다중 컨테이너 엔드포인트

  • 단일 SageMaker 엔드포인트에 다양한 모델/프레임워크의 컨테이너 배포 가능

  • **컨테이너를 연속 실행하는 추론 파이프라인 구축** 또는 **개별 직접 호출** 가능

  • 엔드포인트 활용도 향상과 비용 최적화

  • 다중 컨테이너 엔드포인트 사용 사례:

    데이터 전처리:

    • 전처리 컨테이너로 데이터 정규화, 특성 엔지니어링 등 수행

    사후처리 및 해석:

    • 모델 예측 결과에 대한 추가 작업(설명 생성, 출력 포맷팅 등)

    멀티모달 추론:

    • 데이터 유형별 최적화된 전용 컨테이너 활용

    복잡한 워크플로:

    • 모듈화된 재사용 가능한 컴포넌트로 구성

    • 테스트성, 유지보수성, 확장성 향상

Container and Instance Types for Inference

컨테이너 선택

SageMaker 관리형 컨테이너

  • 보다 간편한 솔루션

  • 모델 배포 : 모델 호스팅, 추론 처리 등 필요한 설정이 사전 구성된 컨테이너 사용

  • 관리형 컨테이너의 사전 구축된 코드 : 추론 요청/응답 처리를 위한 사전 구축된 코드 포함

  • 학습 모델과 동일한 컨테이너 이용

    • 학습에 사용한 SageMaker 관리형 컨테이너 이미지에 추론 로직이 포함될 수 있음

    • 학습과 추론에 동일한 컨테이너 이미지 사용 가능

사용자 정의 컨테이너

  • 더 많은 커스터마이징이 가능하지만 컨테이너 관리 필요

  • 사용자 정의 추론 코드 이용:

    • **인바운드 요청과 아웃바운드 응답 처리**에 대한 유연성 확보

  • SageMaker 컨테이너 확장:

    • 프레임워크, 종속성, 라이브러리 등 사전 구성된 구성 요소가 포함된 **SageMaker 관리형 컨테이너에 사용자 정의 추론 코드 추가**

  • Bring Your Own Container (BYOC):

    • 사용자가 직접 모델, 종속성, 기타 필요 구성 요소를 포함한 **커스텀 컨테이너 이미지** 사용

    • 가장 유연한 옵션을 제공

인스턴스 선택

  • CPU, GPU, Trainium 인스턴스 중 선택

  • CPU: 소규모 모델에 적합, 단일 스레드 성능 중요

  • GPU: 딥러닝, 대규모 모델에 적합, 높은 처리량 요구

  • Trainium: 추론에 최적화, GPU 대비 비용 효율적

CPU 인스턴스

  • 전통적인 ML 모델에 효과적

  • 신속한 DL 모델 프로토타이핑, 소규모 DL 모델 학습, 작은 데이터셋 fine-tuning에 적합

  • 비용 대비 시간 절충이 필요한 경우에 적합

  • CPU 인스턴스 장점

    • 소규모 데이터셋, 복잡도 낮은 모델에 적합

    • GPU 인스턴스 대비 시간당 요금 저렴

  • 적용 사례

    • 텍스트 분류, 감성 분석

    • 금융 데이터

    • 중소규모 모델

GPU 인스턴스

  • TensorFlow, PyTorch, MXNet, XGBoost 등 ML 프레임워크 학습에 효과적

  • 신경망을 포함한 DL 모델 학습에 효과적

  • 성능과 비용을 고려하여 다양한 GPU 인스턴스 선택 가능

  • GPU 인스턴스 장점

    • 대부분의 ML 학습 작업에 자주 사용

    • 병렬 처리로 인한 빠른 학습 속도, 큰 데이터셋 처리 능력

  • 적용 사례

    • 시퀀스 모델링

    • 객체 탐지, 영상 분석

    • 대규모 모델, GAN

Trainium 인스턴스

  • 추론에 적합

  • GPU 대비 비용 효과적, 대규모 ML 학습/추론에 적합

  • 지역별 가용성이 제한적일 수 있음

  • 적용 사례

    • 컴퓨터 비전, 음성 인식

    • 추천 모델

    • 시뮬레이션

온디맨드 vs 프로비저닝 리소스

  • 온디맨드: 필요 시 바로 사용 가능, 예측 불가능한 워크로드에 적합

  • 프로비저닝: 장기, 예측 가능한 워크로드에 적합, 사전 계획과 약정 필요

테스트 vs 프로덕션 환경 리소스 프로비저닝

  • 테스트: 비용 절감, 유연성, 다양한 테스트

  • 프로덕션: 안정성, 성능, 자동 확장

비용 관리

  • 테스트 환경

    • 비용 효율적인 인스턴스 사용(Spot 인스턴스, T3/T3a 등)

    • 필요 시에만 리소스 프로비저닝, 테스트 완료 후 즉시 종료

  • 프로덕션 환경

    • 안정성과 가용성 우선(On-Demand, Reserved 인스턴스)

    • 장기, 안정적 워크로드에 AWS Savings Plans 활용

성능 및 확장성

  • 테스트 환경

    • 프로덕션과 유사하지만 축소된 리소스 프로비저닝

    • 다양한 인스턴스 유형/구성 실험으로 최적 성능 탐색

    • 낮은 확장성 요구

  • 프로덕션 환경

    • 요구 성능과 신뢰성을 제공하는 인스턴스 유형/구성 선택

    • 피크 부하 처리와 지연 시간 최소화

    • Auto Scaling, Elastic Load Balancing 활용

배포 및 테스팅

  • 테스트 환경

    • 빈번한 변경 및 배포, CI/CD 파이프라인 활용

    • 단위, 통합, 성능 테스트 수행

  • 프로덕션 환경:

    • 제어된 배포(블루/그린, 캐너리)로 변경 위험 최소화

    • 스테이징 환경에서 철저한 테스트 후 배포

    • 신속한 롤백 메커니즘 구현

컴퓨팅 리소스 선택 시 고려사항

모델 복잡도

  • 심층 신경망, 앙상블 등 복잡한 모델은 학습과 추론 시 더 많은 컴퓨팅 리소스 요구

  • 수요가 많은 워크로드를 처리하기 위해 충분한 CPU, GPU, 메모리 리소스 할당 필요

데이터셋 크기

  • 대용량 데이터셋은 메모리와 저장 공간 리소스에 큰 부담을 줌

  • 멀티노드 데이터 처리 또는 병렬 처리 기법 활용으로 성능 향상

실시간 추론

  • 지연 시간이 중요한 추론을 위해 전용 GPU 인스턴스 프로비저닝

확장성 및 탄력성

  • 자동 스케일링, 로드 밸런싱으로 워크로드 변화에 따른 리소스 동적 조정

비용 최적화

  • 성능 요구사항과 비용 간 균형 고려

  • Spot 인스턴스, 자동 스케일링 등을 활용하여 비용은 절감하되 성능은 유지

Deployment with Edge Computing

엣지 컴퓨팅이란?

  • 데이터를 데이터 센터나 클라우드가 아닌 네트워크 가장자리에서 처리하는 것

  • 낮은 지연 시간, 향상된 효율성을 제공

엣지 디바이스의 종류:

  • 스마트폰, 태블릿, 웨어러블

  • 산업/제조 장비

  • 감시 카메라, 보안 시스템

  • 자동차, 운송 시스템

  • IoT 센서, 게이트웨이

AWS IoT Greengrass:

  • 엣지 디바이스에서 로컬 추론 실행으로 지연 시간과 비용 절감

  • 추론 결과를 분석하여 모델 개선에 활용

AWS IoT Greengrass 활용 사례:

  • 엣지에서 실행: 정밀 농업의 이상 탐지 등 엣지 디바이스에 지능 구현

  • 애플리케이션 관리: 언어, 패키징, 런타임에 관계없이 애플리케이션 배포

  • 디바이스 관리: MQTT 등 프로토콜로 현장 디바이스 관리 및 운영

  • 로컬 데이터 처리: 데이터 수집, 집계, 필터링, 전송 등 로컬에서 처리

Amazon SageMaker Neo:

  • 클라우드, 엣지 디바이스 추론 성능 최적화

  • 정확도 저하 없이 모델 실행 속도 향상

Amazon SageMaker Neo 활용 사례:

  • 추론 속도 향상: TensorFlow, PyTorch, MXNet 등 프레임워크 모델 최적화

  • SageMaker, 엣지 디바이스 배포: 최적화된 모델 배포

  • 모델 이식성: 프레임워크 간 모델 변환, 플랫폼/하드웨어 간 실행

  • 모델 크기 압축: 양자화, 가지치기로 모델 크기 감소
