2.4 Analyze Model Performance

Performance Baseline

  • 성능 기준선 수립

    • 모델 개선을 측정할 수 있는 기준점 마련

    • 모델 평가 데이터셋 준비가 필수적

  • 모델 평가 데이터셋 준비

    • 일반적으로 **훈련 80%, 검증 10%, 테스트 10%**로 구분

    • **검증** 데이터셋: **하이퍼파라미터 튜닝, 모델 아키텍처 선택, 모델 성능 모니터링**

    • **테스트** 데이터셋: **최종 모델 성능 평가**, 실제 배포 환경과 유사해야 함

  • 성능 기준선 구축을 위한 3가지 모범 사례

    1. 문제와 비즈니스 목표에 부합하는 **평가 지표** 설정

    2. 단순 모델(선형 회귀 등)로 시작하여 **성능 기준선** 확립

    3. 평가 데이터셋이 실제 데이터 분포를 대표하고 **편향이 없도록 확인**

성능 기준선 구축을 위한 3가지 모범 사례

적절한 평가 지표 설정

  • 문제와 비즈니스 목표에 부합하는 지표 선택

  • 정확도(Accuracy), 정밀도(Precision), 재현율(Recall), F1 Score, MSE, AUC-ROC 등

단순 모델로 성능 기준선 확립

  • 선형 회귀 등 **단순 모델로 시작하여 성능 평가 (initial baseline)**

  • 이를 통해 문제의 복잡성 파악 가능

  • 이후 고도화된 모델과의 성능 비교를 통해 개선 정도 확인

실제 데이터 분포를 반영한 평가 데이터셋 준비

  • 훈련/검증/테스트 데이터셋이 실제 환경을 대표하도록 함

  • 데이터 전처리, 누출 및 편향 제거 등 주의 필요

Assessing Trade-offs

  • 이와 더불어 모델 성능, 훈련 비용, 훈련 시간 간의 trade-off를 균형있게 고려

모델 성능

  • 정확도, 정밀도 등의 지표로 나타내는 모델의 성능

  • 일반적으로 **더 복잡한 모델이 더 좋은 성능**을 보임

  • 하지만 이를 위해서는 더 많은 계산 자원과 훈련 시간이 필요

  • 모델 성능 향상을 위해서는 **모델 복잡도 증가, 고급 아키텍처 사용, 데이터 양 확장** 등이 필요

  • 또한 특징 엔지니어링, 데이터 품질, 하이퍼파라미터 튜닝, 규제화, 최적화 알고리즘 선택도 중요

모델 훈련 비용

  • 훈련 및 배포 비용은 중요한 고려 사항

  • 사용 컴퓨팅 자원, 데이터 저장 용량, 훈련/추론 시간 등이 비용에 영향

  • AWS는 다양한 비용 효율적인 솔루션을 제공

모델 훈련 시간

  • **데이터셋 크기, 모델 복잡도, 하이퍼파라미터 튜닝 정도에 따라 결정**

  • **빠른 훈련 시간은 반복 실험에 유리하지만, 성능 저하**로 이어질 수 있음

How to Choose

Priority solely on model performance

  • **모델 성능이 최우선** 목표인 경우

  • **더 복잡한 모델**과 **더 많은 계산 자원**을 사용하는 것이 적합

  • 훈련 시간이 늘어나고 비용이 증가하더라도 성능 향상에 초점

Model performance and time priorities

  • **성능과 훈련 시간**이 중요한 경우

  • **보통 수준의 복잡성**을 가진 모델과 데이터셋 사용

  • 더 많은 계산 자원을 할당하여 성능과 시간의 균형 맞추기

  • 비용 증가에 유의

Cost and time priorities

  • **비용과 시간**이 주요 우선순위인 경우

  • **보다 단순한 모델**과 적은 계산 자원 활용

  • 성능이 다소 저하될 수 있지만 비용과 시간 절감 달성

Model Evaluation Techniques and Metrics

Evaluation Techniques

검증 및 평가 데이터셋 사용

  • 검증 데이터셋: 모델 개선을 위해 사용

  • 테스트 데이터셋: 최종 모델 성능 평가를 위해 사용

Model Metrics

  • Common Metrics

분류 문제 평가 지표

  • 정확도, 정밀도, 재현율, F1 점수, AUC-ROC

Confusion Matrix(혼동 행렬)

  • 이러한 지표 계산의 기반이 됨

  • 정답 여부 (T,F) + 예측 값 (P,N)

    True Positive (TP)

    • 실제 라벨이 양성(P)이고, 모델 예측값도 양성인 경우 → 암 환자를 정확히 진단 (생존 기회 증가)

    • 모델이 정확하게 양성을 예측한 경우

    True Negative (TN)

    • 실제 라벨이 음성(N)이고, 모델 예측값도 음성인 경우 → 건강한 사람을 정확히 식별

    • 모델이 정확하게 음성을 예측한 경우

    False Positive (FP)

    • 실제 라벨이 음성(N)인데, 모델이 양성으로 잘못 예측한 경우 → 건강한 사람을 오진 (불 필요한 치료)

    • 모델이 음성을 양성으로 잘못 판단한 경우

    False Negative (FN)

    • 실제 라벨이 양성(P)인데, 모델이 음성으로 잘못 예측한 경우 → 암 환자를 놓침 (치명적 결과)

    • 모델이 양성을 음성으로 잘못 판단한 경우

Accuracy (정확도) - 실제값을 정확히 맞춘 비율 (양,음 모두 포함)

  1. **불균형 데이터셋에서 유용하지 않음**

    • true negative가 많은 경우, 정확도가 높게 나올 수 있음

    • 이는 단순히 “비 고양이”를 잘 예측한다는 것을 의미할 뿐

  2. 실제 비즈니스 목표와 부합하지 않을 수 있음

    • 예를 들어, **신용카드 사기 탐지에서는 true positive(사기 예측)가 중요함**

    • 그런데 **정확도 지표가 높더라도 true positive가 낮을 수 있음**

Precision (정밀도) - 참 예측을 정확하게 한 정도

  • 정밀도는 **false positive가 높은 비용을 발생시킬 때** 유용한 지표

  • 예) 이메일 스팸 분류 모델

    • 중요한 이메일을 스팸으로 잘못 분류하는 것은 바람직하지 않음

    • 이 경우 정밀도가 높은 모델을 선호하게 됨

      • false positive(**정상 이메일을 스팸으로 잘못 분류**)를 최소화할 수 있기 때문

Recall (재현율) - 실제 참을 정확히 찾아내는 정도

  • 재현율은 **모델이 중요한 속성을 얼마나 잘 탐지하는지** 보여줌

  • 예) **환자의 말기 질환 예측** 모델

    • 정밀도 지표만으로는 false negative(실제 환자를 건강자로 잘못 분류)를 반영하지 못함

    • 모델이 환자를 건강하다고 잘못 예측하는 것은 치명적일 수 있음

F1 점수

  • 정밀도와 재현율을 균형있게 종합

AUC-ROC

  • AUC-ROC(Area Under Curve - Receiver Operating Characteristic)

    • ROC 곡선 아래의 면적을 나타내는 지표

    • ROC 곡선은 true positive rate와 false positive rate의 관계를 보여줌

  • AUC-ROC 계산 방법

    • 다양한 **임계값에서의 혼동 행렬을 생성하고 비교**

    • 이를 통해 비즈니스 요구사항에 맞는 적절한 임계값 식별 가능

  • AUC-ROC의 의미

    • **분류기의 분리 능력**을 나타내는 척도

    • **AUC-ROC가 높을수록 모델의 성능이 좋다고 볼 수 있음**

  • AUC-ROC는 분류기 선택에 유용한 지표

    • 다양한 분류 모델을 비교하여 우수한 모델을 선택할 수 있음

기타 평가 기법

  • ROC 곡선 및 AUC-ROC: 분류기 선택에 유용

히트맵

  • 다중 클래스 분류 문제에서 강약점 파악에 도움

회귀 문제 평가 지표

  • 평균 제곱 오차(MSE), 제곱근 평균 제곱 오차(RMSE)

R-squared

  • R-squared는 선형 회귀 문제에서 자주 사용되는 지표

  • R-squared는 모델이 설명할 수 있는 데이터 분산의 비율을 나타냄

  • R-squared 값의 범위는 0에서 1 사이

  • R-squared 해석

    • R-squared가 **1에 가까울수록 모델이 데이터 변동성을 잘 설명한다**고 볼 수 있음

    • 하지만 R-squared 값이 높다고 해서 항상 모델이 우수한 것은 아님

  • R-squared 기준은 문제 상황에 따라 다름

    • 예: 0.6(60%), 0.7(70%), 0.8(80%), 0.85(85%) 등

    • 일부 문제에서는 높은 R-squared를 달성하기 어려울 수 있음

  • 주의사항

    • R-squared는 변수 추가 시 항상 증가하므로 **과적합 문제가 발생할 수 있음**

    • R-squared가 높다고 해서 무조건 좋은 모델이라고 단정 지을 수 없음

Adjusted R-squared

  • 조정 R-squared는 R-squared의 한계를 보완하기 위한 지표

  • R-squared는 변수 추가 시 항상 증가하지만, 이는 과적합으로 이어질 수 있음

  • 조정 R-squared의 특징

    • **변수 추가에 따른 영향을 고려하여 계산**됨

    • **추가 변수가 예측력 향상에 기여하는 경우에만 조정 R-squared가 증가**

  • 조정 R-squared 계산

    • 데이터셋의 특징 수와 관측치 수를 반영하여 계산

    • R-squared보다 보수적인 값을 제공

  • 권장 사항

    • R-squared와 조정 R-squared를 함께 확인

    • 이를 통해 모델의 성능과 과적합 위험을 균형있게 평가할 수 있음

  • R-제곱은 과적합 문제에 유의해야 함

이 문제의 적절한 평가 지표는 F1 score입니다.

그 이유는 다음과 같습니다:

  1. MSE (Mean Squared Error)

    • 회귀 문제에 주로 사용되는 지표로, 이 문제는 분류 문제이므로 적절하지 않습니다.

  2. 정확도 (Accuracy)

    • 정확도는 class 불균형 문제에 취약할 수 있습니다.

    • 이 문제에서는 FP와 FN을 균형있게 고려해야 하므로, 정확도 단독으로는 부족합니다.

  3. 재현율 (Recall)

    • 재현율은 FN을 줄이는 데 초점을 두지만, FP도 중요한 이 문제에는 적절하지 않습니다.

  4. F1 score

    • F1 score는 정밀도와 재현율을 균형있게 고려하는 지표입니다.

    • FP와 FN을 동시에 최소화하려는 이 문제의 목적과 잘 부합합니다.

    • 따라서 F1 score가 가장 적절한 평가 지표라고 볼 수 있습니다.

따라서 이 소득 자격 판단 모델의 경우 F1 score가 가장 적합한 평가 지표입니다.

이 문제에서 가장 적절한 평가 지표는 Recall입니다.

그 이유는 다음과 같습니다:

  1. 정확도 (Accuracy)

    • 정확도는 전체적인 분류 성능을 나타내지만, 불균형 데이터셋에서는 한계가 있습니다.

    • 이 문제에서는 모든 양성 사례를 찾아내는 것이 중요하므로, 정확도는 적절하지 않습니다.

  2. 정밀도 (Precision)

    • 정밀도는 FP를 줄이는 데 초점을 두지만, 이 문제에서는 FP보다 모든 양성 사례를 찾아내는 것이 더 중요합니다.

  3. 재현율 (Recall)

    • 재현율은 실제 양성 사례 중 얼마나 많은 것을 찾아내는지를 나타냅니다.

    • 이 문제에서는 모든 양성 사례를 찾아내는 것이 가장 중요하므로, 재현율이 가장 적절한 평가 지표입니다.

  4. F1 score

    • F1 score는 정밀도와 재현율의 균형을 고려하지만, 이 문제에서는 재현율이 더 중요합니다.

따라서 이 문제에서는 Recall이 가장 적절한 평가 지표라고 볼 수 있습니다.

이 문제에서 가장 적절한 평가 지표는 Precision입니다.

그 이유는 다음과 같습니다:

  1. 정확도 (Accuracy)

    • 정확도는 전체적인 분류 성능을 나타내지만, 이 문제에서는 FP(실제 비스팸 메일을 스팸으로 잘못 분류)가 중요하므로 적절하지 않습니다.

  2. 정밀도 (Precision)

    • 정밀도는 모델이 스팸으로 분류한 메일 중 실제 스팸인 비율을 나타냅니다.

    • 이 문제에서는 비스팸 메일을 스팸으로 잘못 분류하는 것이 매우 바람직하지 않으므로, 정밀도가 가장 적절한 평가 지표입니다.

  3. 재현율 (Recall)

    • 재현율은 실제 스팸 메일 중 모델이 스팸으로 분류한 비율을 나타냅니다.

    • 이 문제에서는 FP가 더 중요하므로, 재현율은 적절하지 않습니다.

  4. F1 score

    • F1 score는 정밀도와 재현율의 균형을 고려하지만, 이 문제에서는 정밀도가 더 중요합니다.

따라서 이 스팸 메일 분류 문제에서는 Precision이 가장 적절한 평가 지표라고 볼 수 있습니다.

Convergence Issues

모델 수렴성의 중요성

  • 최적의 해에 수렴하지 못하면 과적합, 발산 등의 문제 발생

  • 수렴 실패는 학습 및 평가 단계 모두에서 문제 초래

수렴 문제의 유형

  • 기울기 소실/폭발, 과적합/과소적합, 지역 최소값 등

  • 딥러닝 모델의 수렴 문제

    • 많은 매개변수로 인해 지역 최소값, 안장점 등에 빠질 수 있음

    • 불균형 데이터셋에서 다수 클래스에 편향될 수 있음

AWS의 수렴성 개선 솔루션

  • SageMaker Automatic Model Tuning (AMT)

    • 하이퍼파라미터 자동 튜닝을 통해 최적 구성 찾기

  • SageMaker Training Compiler

    • 딥러닝 모델 최적화로 학습 시간 단축 및 하드웨어 활용도 향상

  • Example

    • 자연어 처리는 순환 신경망(RNN)의 한 예시입니다. RNN을 사용한 순차 모델링 작업 학습에는 다음과 같은 몇 가지 과제가 있습니다:

      • 기울기 소실 또는 폭발

      • 합성곱 신경망(CNN)을 사용한 자연어 처리 등의 순차 모델링 작업에서도 이러한 기울기 소실 또는 폭발 문제가 발생할 수 있습니다

      • 이는 계산의 순환적 성격 때문입니다

      • 심층 신경망에서 역전파 과정에서 계산된 기울기가 극단적으로 작아지거나(기울기 소실) 크게 되어(기울기 폭발) 수렴 속도가 느리거나 불안정한 학습이 이루어질 수 있습니다

    • SageMaker 자동 모델 튜닝(AMT)은 이러한 문제를 해결할 수 있습니다:

      • AMT는 학습률 일정, 초기화 기법, 정규화 방법 등의 하이퍼파라미터를 최적화하여 모델 성능을 향상시킬 수 있습니다

      • AMT를 통해 수렴 속도 향상 및 학습 과정의 안정성 개선을 기대할 수 있습니다

Challenge with DL models

  • 최신 딥러닝 모델에는 다음과 같은 특징이 있습니다:

    • 수십억 개의 파라미터로 구성된 복잡한 다층 신경망 구조

    • 수천 시간의 GPU 연산이 필요한 학습 과정

  • 이러한 딥러닝 모델의 최적화를 위해서는 다음과 같은 전문 지식이 필요합니다:

    • 딥러닝에 대한 광범위한 지식

    • 시스템 엔지니어링 능력

  • 이는 매우 좁은 범위의 사용 사례에서도 큰 도전과제가 됩니다.

  • 오픈 소스 컴파일러도 있지만, 딥러닝 프레임워크와 GPU 인스턴스 등 하드웨어를 유연하게 통합하기 어려운 문제가 있습니다.

  • 이에 Amazon SageMaker Training Compiler는 다음과 같은 장점으로 딥러닝 모델 최적화에 도움을 줍니다

    • 하드웨어 활용도 향상

    • 추가 요금 없이 제공

    • 총 청구 시간 절감

  • Example

    • 이를 해결하기 위해 Amazon SageMaker Training Compiler를 활용할 수 있습니다:

      • 텐서 재배치, 연산자 융합, 커널 최적화 등의 최적화 기법을 자동으로 적용할 수 있음

      • 이를 통해 학습 과정의 수렴 속도와 안정성을 높일 수 있음

SageMaker Clarify and Metrics Overview

Amazon SageMaker Clarify

  • 머신 러닝 모델의 공정성과 투명성을 모니터링, 설명, 개선하는 데 도움을 줍니다.

주요 기능

  • 편향 탐지, 설명 가능성, 데이터 품질 모니터링 도구 제공

  • ML 라이프사이클 전반에 걸쳐 적용 가능

  • 모델 설명 가능성 제공:

    • 모델의 전반적인 행동과 개별 예측에 대한 각 특징의 상대적 중요도 이해 지원

  • 학습 데이터 편향 탐지:

    • 9가지 사전 탐지 방법을 활용하여 학습 데이터의 속성별 편향 탐지

  • 학습 모델 편향 탐지:

    • 9가지 사후 탐지 방법으로 모델 내 다양한 유형의 편향 정도 평가

  • 컴퓨터 비전 및 자연어 처리 모델 설명:

    • 일반적으로 블랙박스 방식인 비정형 데이터 모델의 예측 과정 설명

  • 편향 및 모델 행동 변화 탐지:

    • SageMaker Model Monitor를 통해 실제 세계의 동적 변화로 인한 변화 감지 및 경보 제공

  • 모델 보고서 제공:

    • 편향의 원인과 심각성에 대한 시각화된 보고서 생성

  • 이를 통해 편향 완화, 공정성 향상 등을 위한 계획을 수립할 수 있습니다.

주요 지표

  • 데이터 편향 지표 범주 (Data bias)

    • 클래스 불균형: 학습 데이터의 클래스 또는 레이블 분포 불균형 측정 (Class Imbalance)

    • 속성 불균형: 다양한 클래스 또는 레이블 간 연령, 성별, 인종 등 민감 속성의 분포 불균형 평가 (Feature Imbalance)

    • 속성 상관관계: 민감 속성과 타겟 변수 간 상관관계 측정 (Facet Correlation)

  • 모델 편향 지표 범주 (Model bias)

    • 차등 타당도: 다양한 속성 그룹 간 정확도, 정밀도, 재현율 등의 모델 성능 차이 평가 (Differential Vidality)

    • 차등 예측 편향: **동일한 입력 특징**에 대한 **다른 속성 그룹의 예측 결과 또는 확률 차이** 측정 (Differential Prediction bias)

    • 차등 특징 중요도: **다른 속성 그룹 간 특징 중요도의 차이 분석**으로 **편향 식별** (Differential feature importance)

  • 모델 설명 가능성 지표 범주 (Model explainability)

    • SHAP: 각 특징의 기여도 정량화를 통한 개별 예측 설명 (SHapley Additives exPlanations)

    • SHAP

      SHAP은 SHapley Additive exPlanations의 약자입니다.

      SHAP은 모델의 예측 결과에 대한 설명 가능성을 제공하는 기법입니다. 이 기법은 게임 이론의 Shapley value 개념을 기반으로 합니다.

      SHAP의 주요 특징은 다음과 같습니다:

      1. 개별 예측에 대한 설명: SHAP은 각 데이터 포인트의 예측 결과에 대해 개별적으로 설명을 제공합니다. 이를 통해 모델의 의사결정 과정을 이해할 수 있습니다.

      2. 특징 중요도 정량화: SHAP은 각 특징이 예측 결과에 미치는 영향력을 정량화합니다. 이를 통해 모델이 어떤 특징에 가중치를 두고 있는지 파악할 수 있습니다.

      3. 비선형 관계 모델링: SHAP은 특징과 타겟 변수 간의 복잡한 비선형 관계를 잘 포착할 수 있습니다. 이는 다른 설명 가능성 기법들에 비해 SHAP의 장점 중 하나입니다.

      4. 전역 및 지역 설명: SHAP은 전체 모델에 대한 전역 설명과 개별 데이터 포인트에 대한 지역 설명을 모두 제공합니다.

      이와 같은 특징으로 인해 SHAP은 복잡한 머신 러닝 모델의 예측 결과를 해석하고 이해하는 데 널리 사용되고 있습니다. SageMaker Clarify에서도 SHAP 기반의 설명 가능성 분석 기능을 제공하고 있습니다.

    • 특징 귀인: 특정 예측에 **가장 크게 기여하는 특징 식별** (Feature Attribution)

    • 부분 의존도 도표: 특징과 타겟 변수 간 관계 이해를 돕는 시각화 (Partial Dependence Plots)

  • 데이터 품질 지표 범주 (Data quality)

    • 결측값: 학습 데이터 내 결측값의 존재 및 분포 식별 (Missing Data)

    • 중복 데이터: 학습 데이터 내 중복 인스턴스 또는 행 탐지 (Duplicate Data)

    • 데이터 변동: 추론 또는 운영에 사용되는 데이터와 학습 데이터 간 통계적 차이 측정 (Data Drift)

  • 이를 통해 데이터와 모델의 편향성을 파악하고, 모델의 의사결정 과정을 이해할 수 있습니다. 이는 편향 완화, 공정성 향상, 투명성 제고에 활용될 수 있습니다.

정답은 “Differential prediction bias”입니다.

이유:

Differential prediction bias 지표는 입력 특징이 동일할 때 서로 다른 속성 그룹(예: 연령, 성별, 인종 등)에 대한 예측 결과 또는 확률의 차이를 측정합니다. 이를 통해 모델이 특정 인구통계학적 그룹에 대해 편향된 예측을 하는지 확인할 수 있습니다.

반면 class imbalance와 facet imbalance 지표는 학습 데이터의 클래스 또는 속성 분포 불균형을 측정할 뿐, 모델의 예측 편향을 직접적으로 파악하기는 어렵습니다.

feature attribution 지표는 모델의 의사 결정 과정을 설명하는 데 도움이 되지만, 편향 여부를 직접적으로 확인하기는 어렵습니다.

따라서 대출 승인 예측 모델의 공정성 및 편향성 평가를 위해서는 differential prediction bias 지표가 가장 유용할 것입니다.

  • 최고 성능 모델과 해당 입력 구성을 추적하기 어려워집니다.

  • 과거 실험과 현재 진행 중인 실험을 비교하여 개선 기회를 찾기 어렵습니다.

주요 이점

  • 실험을 구조화되고 체계적으로 관리할 수 있습니다.

  • 실험을 그룹화하고 구성할 수 있어 분석이 용이합니다.

  • 모델 생성 과정의 모든 단계와 산출물을 추적할 수 있습니다.

    • 이를 통해 운영 문제 해결과 규정 준수 감사에 도움이 됩니다.

주요 기능

  • 실험 구성 (Organize)

  • 재현성 보장 (Reproduce)

  • 모델 등록 및 배포 (Deploy)

    • 중앙 모델 레지스트리를 통한 모델 배포 지원

  • 확장성 있는 추적 (Track)

그렇다면 금융 서비스 회사의 중요한 모델을 배포하기 전 철저한 테스팅을 위해 사용해야 할 정답 AWS 서비스는 Amazon SageMaker Debugger 입니다.

그 이유는 다음과 같습니다:

  • Amazon SageMaker Debugger는 모델 학습 과정 중에 발생하는 문제를 식별하고 해결하는 데 도움을 줍니다. 이를 통해 모델 배포 전 철저한 테스팅과 디버깅이 가능합니다.

  • Amazon SageMaker Model Monitor는 배포된 모델의 성능을 모니터링하는 데 유용하지만, 배포 전 테스팅과 디버깅을 위한 기능은 제공하지 않습니다.

  • Amazon SageMaker Experiments와 Clarify는 각각 모델 실험 추적, 편향 탐지 등의 기능을 제공하지만 배포 전 테스팅과 디버깅에 적합하지 않습니다.

따라서 이 경우 정답은 Amazon SageMaker Debugger 입니다. 이 서비스를 사용하면 기계 학습 엔지니어가 배포 전 모델을 철저히 테스팅하고 디버깅할 수 있습니다.

정답은 다음과 같습니다:

Amazon SageMaker Training Compiler

이유:

RNN(Recurrent Neural Network) 모델 학습 시 발생할 수 있는 폭발적인 기울기(exploding gradients) 문제를 해결하기 위해서는 Amazon SageMaker Training Compiler 기능을 활용할 수 있습니다.

폭발적인 기울기 문제는 RNN 모델의 역전파 과정에서 기울기 값이 지수적으로 증가하여 모델 수렴에 문제가 발생하는 현상입니다. SageMaker Training Compiler는 이러한 문제를 해결하기 위해 다음과 같은 기능을 제공합니다:

  • 가중치 클리핑(weight clipping): 기울기 값의 크기를 제한하여 폭발을 방지합니다.

  • 정규화(normalization): 기울기 값을 정규화하여 안정적인 학습을 돕습니다.

  • 옵티마이저 튜닝: 적절한 옵티마이저와 하이퍼파라미터를 자동으로 선택하여 수렴 문제를 해결합니다.

반면 다른 선택지는 적절하지 않습니다:

  1. Amazon SageMaker Model Monitor: 이 기능은 배포된 모델의 성능을 모니터링하는 것이지, 학습 중 발생하는 수렴 문제를 해결하는 것은 아닙니다.

  2. Amazon SageMaker Clarify: 이 기능은 모델의 편향(bias)을 분석하는 것이며, 폭발적인 기울기 문제를 해결하는 것과는 관련이 없습니다.

  3. Amazon SageMaker Ground Truth: 이 기능은 고품질의 레이블링된 데이터를 생성하는 것이며, 모델 학습 과정의 수렴 문제를 해결하는 것과 관련이 없습니다.

따라서 정답은 Amazon SageMaker Training Compiler 기능입니다.

  • Accuracy 높음 : TN (이탈하지 않는 고객을 이탈하지 않는다고 예측)과 TP 비율 확인 안됨

  • Recall 낮음 (row에서 R 연상) : TP + FN (이탈하지 않는다는 예측이 틀림) → 이탈한 고객을 이탈하지 않는다고 예측하는 비율이 낮음

  • Precision 높음 : TP + FP (이탈한다고 예측하지만 이탈하지 않음) → 이탈하지 않은 고객을 이탈한다고 하는 예측이 낮음

정답은 다음과 같습니다:

The model has a high precision, indicating a low false positive rate. However, the lower recall suggests a higher false negative rate, meaning the model may struggle to identify churning customers accurately.

이유:

  • 정밀도(Precision)가 0.85로 높은 것은 모델이 실제로 이탈한 고객을 예측할 때 false positive(실제로는 이탈하지 않은 고객을 이탈한 것으로 잘못 예측)의 비율이 낮다는 것을 의미합니다.

  • 반면, 재현율(Recall)이 0.70으로 상대적으로 낮은 것은 모델이 실제 이탈한 고객을 정확하게 예측하지 못하고 있음을 나타냅니다. 즉, false negative(실제로 이탈한 고객을 이탈하지 않은 것으로 잘못 예측)의 비율이 높다는 것을 의미합니다.

  • F1 점수가 0.77인 것은 정밀도와 재현율의 조화 평균이 높지 않음을 나타냅니다.

  • 정확도(Accuracy)가 0.82로 높은 것은 모델이 전반적으로 잘 작동하고 있다는 것을 보여주지만, 이탈 고객을 정확히 예측하지 못하는 부분이 있음을 간과할 수 없습니다.

따라서 이 모델은 정밀도가 높아 false positive 율은 낮지만, 재현율이 상대적으로 낮아 false negative 율이 높다는 특징을 가지고 있습니다.

네, 틀린 예시에 대해 각각 설명드리겠습니다.

  1. “The high accuracy of 0.82 suggests that the model is performing well in predicting both churning and non-churning customers.”

    • 이 문장은 잘못된 해석입니다. 정확도(Accuracy)가 높다고 해서 모델이 이탈 고객과 비이탈 고객을 모두 잘 예측한다고 볼 수 없습니다.

    • 정확도는 전체 예측 성능을 나타내는 지표이지만, 이탈 고객과 비이탈 고객의 예측 성능을 각각 보여주지는 않습니다.

    • 따라서 이 문장은 정확도만을 보고 모델의 전반적인 성능을 과대평가하고 있습니다.

  2. “The model has a low F1 score, indicating poor overall performance in both precision and recall.”

    • 이 문장은 잘못되었습니다. F1 점수가 0.77로 상당히 높은 편이기 때문입니다.

    • F1 점수는 정밀도와 재현율의 조화 평균으로, 두 지표가 모두 낮은 경우에만 전반적인 성능이 저조하다고 볼 수 있습니다.

    • 하지만 이 모델의 경우 정밀도가 0.85로 높고, 재현율도 0.70으로 양호한 편이므로 전반적인 성능이 좋다고 할 수 있습니다.

  3. “The model has a high false positive rate, meaning it may incorrectly classify non-churning customers as churning.”

    • 이 문장도 잘못되었습니다. 모델의 정밀도가 0.85로 높다는 것은 오히려 false positive 율이 낮다는 것을 의미합니다.

    • 정밀도가 높다는 것은 예측한 이탈 고객 중 실제로 이탈한 고객의 비율이 높다는 것을 뜻하므로, false positive 율이 낮다고 할 수 있습니다.

따라서 첫 번째 문장이 가장 정확한 모델 성능 해석이라고 할 수 있습니다.

정답은 다음과 같습니다:

Use early stopping to terminate training when the validation loss stops improving.

이유:

Amazon SageMaker Automatic Model Tuning 과정에서 수렴 문제(convergence issues)를 예방하기 위해서는 조기 중지(early stopping) 기법을 사용하는 것이 가장 효과적입니다.

조기 중지 기법은 검증 손실(validation loss)이 더 이상 개선되지 않을 때 자동으로 모델 학습을 중단하는 방식입니다. 이를 통해 불필요한 학습 시간을 절감하고, 과적합(overfitting)을 방지할 수 있습니다.

다른 선택지는 적절하지 않습니다:

  1. “Reduce the number of epochs to limit the amount of training time.”

    • 이 방법은 모델 학습 시간을 줄일 수는 있지만, 수렴 문제를 해결하기 위한 직접적인 대응책은 아닙니다. 오히려 학습 시간이 부족하여 모델이 최적의 성능에 도달하지 못할 수 있습니다.

  2. “Increase the learning rate to allow the model to explore a wider range of parameter values.”

    • 학습률을 높이면 모델이 더 넓은 매개변수 영역을 탐색할 수 있지만, 수렴 문제를 해결하기는 어려울 수 있습니다. 오히려 학습률이 너무 높으면 모델이 발산(divergence)할 수 있습니다.

  3. “Increase the batch size to improve computational efficiency.”

    • 배치 크기를 늘리는 것은 계산 효율성을 높일 수 있지만, 수렴 문제를 해결하는 데에는 도움이 되지 않습니다. 배치 크기는 모델 학습에 영향을 미칠 수 있지만, 수렴성과 직접적인 관련은 없습니다.

따라서 정답은 Amazon SageMaker Automatic Model Tuning 과정에서 조기 중지 기법을 사용하여 수렴 문제를 해결하는 것입니다.

아마존 SageMaker를 사용하여 심층 학습 모델을 학습할 때, 특정 epoch 횟수 이후 손실 함수가 더 이상 감소하지 않는 원인은 모델이 지역 최소값에 도달했기 때문입니다.

설명:

지역 최소값은 손실 함수의 값이 주변에 비해 낮은 지점이지만, 전역 최소값은 아닐 수 있습니다. 모델이 지역 최소값에 도달하면 추가 학습이 성능 향상으로 이어지지 않아 손실 함수가 더 이상 감소하지 않게 됩니다.

다른 선택지는 잘못된 답변입니다:

  1. 모델 아키텍처가 너무 복잡해 학습 데이터에 과적합되었기 때문

    • 과적합은 학습 데이터에서는 손실 함수가 계속 감소할 수 있지만, 검증 또는 테스트 데이터에서는 그렇지 않은 문제를 야기합니다.

    • 이는 손실 함수가 특정 epoch 이후 더 이상 감소하지 않는 이유가 아닙니다.

  2. 학습률이 너무 높아 최적의 해에서 벗어났기 때문

    • 높은 학습률은 손실 함수의 진동이나 발산을 초래할 수 있지만, 특정 epoch 이후 손실 함수가 중단되는 직접적인 원인은 아닙니다.

  3. 학습 데이터가 불균형하여 다수 클래스에 과적합되었기 때문

    • 데이터 불균형은 모델이 다수 클래스를 더 잘 학습하게 만들 수 있지만, 손실 함수가 특정 epoch 이후 중단되는 직접적인 원인은 아닙니다.

따라서 정답은 모델이 지역 최소값에 도달했기 때문에 추가 학습이 성능 향상으로 이어지지 않는다는 것입니다.

정답은 다음과 같습니다:

Use the SageMaker Clarify model explainability feature to identify the most influential features for the model’s predictions.

이유:

Amazon SageMaker Clarify는 모델의 설명 가능성(explainability)을 평가하기 위한 기능을 제공합니다. 이 기능을 사용하면 ML 엔지니어가 모델의 예측에 가장 큰 영향을 미치는 특징(feature)을 식별할 수 있습니다.

이를 통해 엔지니어는 모델의 작동 방식을 이해하고, 모델이 의사 결정을 내리는 방식을 설명할 수 있습니다. 이는 모델의 신뢰성과 투명성을 높이는 데 매우 중요합니다.

반면 다른 선택지는 적절하지 않습니다:

  1. “Retrain the model using SageMaker Clarify to remove any potential bias.”

    • SageMaker Clarify는 모델의 편향(bias)을 탐지하는 기능을 제공하지만, 모델을 직접 재학습하는 기능은 없습니다.

  2. “Use SageMaker Clarify to automatically fix any detected bias in the model.”

    • SageMaker Clarify는 편향을 탐지할 수 있지만, 자동으로 편향을 해결하는 기능은 없습니다. 이는 엔지니어가 직접 개입하여 데이터 및 모델 설계를 개선해야 합니다.

  3. “Use the SageMaker Clarify bias detection feature to analyze the model’s inputs, outputs, and metadata against known protected variables.”

    • 이 선택지는 부분적으로 맞지만, 편향 탐지만으로는 모델의 설명 가능성을 평가하기 어렵습니다.

따라서 정답은 SageMaker Clarify의 모델 설명 가능성 기능을 활용하여 가장 영향력 있는 특징을 식별하는 것입니다.
