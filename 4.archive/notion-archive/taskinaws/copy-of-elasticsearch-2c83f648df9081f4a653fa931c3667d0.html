Lab Goals

  • Deploy a secure end to end solution within VPC Private Networking

  • Host two indexes (movies and logs) with which the solution interacts

  • Leverage managed services from AWS and popular tools from the Elasticsearch ecosystem

Build a Kibana Dashboard

💡

Kibana has a set of visualizations that can configure and deploy into a dashboard

ES aggregations

  • ES is a search engine and an analytics engine

  • Log parse example

    • log line example
    • Logstash parse the full string and assigns the values to JSON elements

    • When perform a search, ES retreives documents from its index

    • The result of retrieval is called a match set

    • ES creates an aggregation by iterating over the match set

    • Creates buckets according to the aggregation and calculating a numeric value

Simple metrics

  • Count the requests to web server and display that count as a number

  • Switch to Visualize and click + button

  • Select Metrics and specifying the index pattern

  • Click logstash-*

  • Select Metrics and selcet Unique Count

  • Select Field and select referr.keyword

  • Click arrow button

  • Add metrics - Unique Count for request.keword

  • Add Count again

  • Save visualization for later use in dashboard

  • At the top of the screen, click Save

Track result codes

  • Switch to Visualzie and click + to create a new visualization

  • Select Vertical Bar and select logstash-*

  • Under Buckets, click x-Axis

  • Select Date Histogram from the Aggregation menu

  • Click arrow button

  • Add sub-buckets to subdivide the time slices by the value in the response field

  • Click Split Series

  • Select Terms from the Sub Aggregation menu

  • Select response from the Field menu

  • Click arrow button

  • Modify the results by adding a search in the search bar

  • Click Update

  • This will filter the data for visualization to only documents that don’t have HTTP 200 response

  • Save as new visualization

Set up destination - SNS

Create SNS Topic

  • Open AWS Management Console and go to SNS console

  • Input topic name and create topic

  • Create subscription in new topic

  • Select Protocol - email

  • Click confirmation link in destination email

Set up a role - ES

  • Let Amazon ES publish alert to topic

  • Get Topic ARN from SNS

  • Create role in IAM console

  • Select EC2 service that will use this role

  • Choose create policy and select JSON tab

  • Input policy in JSON edit window

    • copy Topic ARN here : sns-topic-arn

  • Review and input role name and create policy

  • Search newly created policy and select

  • Input role name and create role

  • Select newly created role and select Trust relationships tab

  • Edit trust relationship

  • Chnage ec2.amazonaws.com as es.amazonaws.com
  • Update policy

  • Copy Role ARN

Set up Amazon ES alerting

  • In Kibana, choose Alerting

  • Select Monitors tab and click Create monitor

  • Input name and select Schedule in Configure Monitor

  • Define Monitor

    • Define using visual graph

    • Index : input name metricbeat-*

    • Time field : @timestamp

  • Edit Condition

    • WHEN : max()

    OF : system.cpu.user.pct

  • OVER : all documents

  • FOR THE LAST : 2 minutes

Create a trigger

  • Input Trigger name

  • Severity level : can select from 1 to 5

  • Trigger condition : <, >, =

Add Destination

  • Click Add Destination button in Configure Actions

  • Input Name

  • Select Type : Amazon SNS

  • SNS topic ARN : from created topic

  • IAM role ARN : from created role

Configure Actions

  • Input Action name

  • Select Destination name : from created destination

  • Input Message subject

  • Click Create
