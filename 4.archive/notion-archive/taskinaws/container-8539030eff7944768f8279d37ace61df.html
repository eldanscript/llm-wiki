  • Hypervisor 기반의 가상화와 Container 기반의 가상화는 어떤 차이점이 있는지?

  • Kubernetes와 Docker의 차이는?

    • Docker provides an open standard for packaging and distributing containerized applications

    • Kubernetes provides for the orchestration and management of distributed, containerized applications created with Docker

  • Docker Compose, Docker Swarm과 Kubernetes는 언제 사용하는게 좋은가?

    • Docker is a container engine

      • no more than one container at most, locally on your PC for development purposes

    • Docker Compose is a Docker utility to run multiple containers and let them share volumes and networking

      • runs locally to emulate service composition and remotely on clusters.

      • Docker Compose is mostly used as a helper when you want to start multiple Docker containers and don’t want to start each one separately using docker run ....

    • Docker Swarm is for running and connecting containers on multiple hosts

      • It does things like scaling, starting a new container when one crashes, networking containers.

    • Kubernetes is a container orchestration platform, it takes care of running containers and enhancing the engine features so that containers can be composed and scaled to serve complex applications (sort of PaaS, managed by you or cloud provider). Kubernetes’ goal is very similar to that for Docker Swarm but it’s developer by Google.

실무 경험에 대한 부분

  • 여러 Process를 실행하는 단일 Container와 단일 Process를 실행하는 다중 Container 중 어떤 방법이 좋을까? 이유는?

    • Container는 단일 Process를 실행하기 위한 목적으로 설계. 개별 Process가 실패할 경우 자동 재시작 mechanism이 포함되어야 하고 모든 Process는 동일한 표준 출력으로 log를 기록하기 때문에 여러 Process의 경우 log 파악이 어렵다

  • Kubernetes Pod에서 Container의 적절한 구성 방법은 뭐가 있을까?

    • 다 계층 애플리케이션을 여러 Pod로 분할, 개별 확장이 가능하도록 여러 Pod로 분할

  • Infra Structure의 System Monitoring Tool을 어떤 것을 사용해 보았는지?

  • 앞에서 얘기한 System Monitoring Tool의 장단점을 비교 한다면?

  • Resource 사용량이 적다고 하면 무엇에 비해 적은 것 인지?

  • 동일 Pod내에 있는 Container간 통신은 어떻게 되는가?

    • if you have two containers within a pod, a MySQL container running on port 3306, and a PHP container running on port 80, the PHP container could access the MySQL one through localhost:3306

  • Kubernetes cluster에 대해 설명한다면? Cluster의 node type별 component는 어떤 것들이 있는가?

    • a set of node machines for running containerized applications

    • worker node

      • kubelet : an agent responsible for node communication with the master

      • kube-proxy : load balancing traffic between app components

      • container runtime : the engine runs the containers

    • master node

      • Scheduling applications

      • Managing desired state

      • Rolling out new updates

      • ETCD

      • Controller Manager

      • Scheduler

      • API Server

  • etcd가 하는 역할은?

    • store all its data – its configuration data, its state, and its metadata. etcd lets any of the nodes in the Kubernetes cluster read and write data. Because Kubernetes is a distributed system that runs on one master and several worker nodes – that database needs to be distributed. So etcd is a distributed database

    • exposed on the master nodes of a Kubernetes cluster on the port 2379

  • Kubernetes에서 StatefulSet은? 언제 사용하는지?

    • 애플리케이션의 상태를 저장하고 관리하는 데 사용되는 쿠버네티스 객체

    • A Redis pod that has access to a volume, but you want it to maintain access to the same volume even if it is redeployed or restarted : 안정적이고 지속적인 스토리지를 사용해야 하는 경우

    • A Cassandra cluster and have each node maintain access to its data

    • A webapp that needs to communicate with its replicas using known predefined network identifiers : 안정적이고 고유한 네트워크 식별자가 필요

  • Ingress Controller는?

    • 쿠버네티스에서 실행 중인 Deployment와 Service에 접근하기 위한, 일종의 관문 (Gateway) 같은 역할을 담당

    • Ingress란 HTTP(S) 기반의 L7 로드밸런싱 기능을 제공하는 컴포넌트

    • 규칙들을 실제로 동작하게 해주는건 Ingress-Controller

    • 가장 많이 사용되는 것이 바로 Ingress-nginx

  • 특정 worker node에 pod를 배포하기 위한 방법은 어떤 것들이 있는가?

    • nodeSelector

    • Taint & Toleration : taint는 pod가 할당되는 것을 막음. toleration을 설정하면 node에 할당 가능해 짐

    • Affinity : Affinity는 operator 설정이 가능. in, Exists, Gt, Lt, NotIn, DoesNotExist

  • DaemonSet이란?

    • DaemonSets are used in Kubernetes when you need to run one or more pods on all (or a subset of) the nodes in a cluster

    • The typical use case for a DaemonSet is logging and monitoring for the hosts
