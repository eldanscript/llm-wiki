Registering your own CA certficates

  • To use your own X.509 certificates, you must register a CA certificate with AWS IoT.

  • The CA certificate can then be used to sign device certificates.

  • Intermediate CAs can also be used, but they must also be registered.

  1. Get a registration code from AWS IoT. (**This code is used as the Common Name of the private key verification certificate.**)
  1. Generate a key pair for the private key verification certificate using OpenSSL.
  1. Create a CSR for the private key verification certificate.

  1. Fill out the information as prompted. (Set the Common Name field of the certificate to your registration code from Step 1.)

  2. Use the CSR to create a private key verification certificate.

  1. Register the CA certificate with AWS IoT.
  • To set up just in time registration (see below for more details) for this CA certificate, you can add the —allow-auto-registration tag.

Creating your own device certificates

  • You can use a CA certificate registered with AWS IoT to create a device certificate.

  • The device certificate must be registered with AWS IoT before use.

For each step, at the command prompt, enter the specified command.

  1. Generate a key pair using OpenSSL.
  1. Create a CSR for the device certificate. Fill out the information as prompted.
  1. Create a device certificate from the CSR.

Registering your own device certificate

  • To sign device certificates, you must use the CA certificate registered with AWS IoT.

  • If you have more than one CA certificate (with the same subject field and public key) registered in your AWS account, when you register your device certificate, you must specify the CA certificate used to sign the device certificate.

  • You can register each device certificate manually.

  • Alternatively, you can use automatic registration, which allows devices to register their certificate when they connect to AWS IoT for the first time.

  1. Register a device certificate.

  1. Activate the device certificate.
  1. See the certificate on the AWS Management Console by going to Services, IoT Core. Choose Secure, Certificates.

Set up JITR

  • To register device certificates automatically when devices first connect to AWS IoT, you must enable automatic registration for your CA certificate.

  • This registers any device certificate signed by your CA certificate when it connects to AWS IoT.

  1. Enable automatic registration.

    • When a device attempts to connect with an X.509 certificate that is unknown to AWS IoT but was signed by a CA that was registered with AWS IoT, the device certificate will be auto-registered by AWS IoT in a new PENDING_ACTIVATION state.

    • AWS IoT publishes a message to the following MQTT topic:

      $aws/events/certificates/registered/<__caCertificateID>

  2. Create an IoT rule that triggers a Lambda function.Create a rule that listens to the $aws/events/certificates/registered/<__caCertificateID> topic and performs some actions.

  3. Create a Lambda function.We recommended that you create a Lambda rule that:

    • Verifies that the device certificate is not on a certificate revocation list (CRL).

    • Activates the certificate.

    • Creates and attaches a policy to the certificate. (The policy determines which resources the device is able to access.)

For more information about how to create a Lambda rule that listens on the $aws/events/certificates/registered/<__caCertificateID> topic and performs these actions, see Just-in-Time Registration.

Set up JITP

  1. Create a service role.This role should include the policy AWSIoTThingsRegistration.

  2. Create a provisioning template. The template provisions resources for the certificate, such as:

    • Create an IoT thing and attach the certificate to the thing.

    • Create an IoT policy to attach to the certificate.

    • Update the certificate status to ACTIVE.

  3. Register the CA certificate with auto-registration.

For more information on JITP provisioning templates, see the JITP documentation, the provisioning template documentation, or this blog.
