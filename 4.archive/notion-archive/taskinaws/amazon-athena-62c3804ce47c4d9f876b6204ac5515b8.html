Amazon Athena

Short Term Definition

  • Serverless Distributed (SQL) Query Engine for Amazon S3

    • Distributed

    • Query Engine

    • Amazon S3 : 데이터가 S3에 있어야 함

    • Serverless : 별도의 Infra 구성이 필요하지 않음

Strength

  • Decouple storage from computer : 데이터 저장과 처리를 분리하기 위해

  • Serverless : 관리 용이

  • Pay only for data scanned : query한 만큼 비용 지불

  • Schema on read

    • 데이터를 읽어올 때 schema를 정의하기 때문에 데이터를 ingest할 때 고려할 필요가 없음

    • 저장 된 데이터가 있을 때 사용하기 쉬움

    • Same data, many views

  • Secure

    • Authentication : IAM, SAML v2

    • Encryption : At rest & In transit

  • Standard compliant

  • Open Storage file format

  • Built on powerful community supported OSS solutions

Pricing

  • Free : DDL / SQL / Query concurrency

  • Data scanned : $5 per TB

  • S3 rates for storage, requests, data transfer

SQL

Query

  • Use Presto with ANSI SQL support

    • Presto에서 지원되는 대부분의 query 지원 (안되는게 있는 것인가?)

💡

프레스토는 페이스북이 개발한 빅 데이터 분석도구로, 분산된 SQL 쿼리 엔진이다. 기존 분석도구인 하이브/맵리듀스에 비해 CPU 효율성과 대기 시간이 10배 빠르다고 발표. Open source distributed SQL query engine for running interactive analytic queries against data sources of all sizes ranging from gigabytes to petabytes

Complex queries

  • Large Joins

  • Window functions : SQL에서 행과 행 간의 관계를 정의하기 위해서 제공되는 함수

  • Arrays

Data format

  • CSV (Comma-Separated Values)

  • Apache Weblogs

  • JSON (JavaScript Object Notation)

    • Key-Value pair로 이루어진 data object를 전달하기 위해 text를 사용하는 open standard format

  • Parquet

    • Apache Hadoop ecosystem의 open-source column-oriented data storage format

  • ORC (Optimized Row Columnar)

    • Apache Hadoop workload를 위한 self-describing type-aware columnar file format

    • Apache Hive 처리 속도를 높이기 위해 개발 됨

Fast Performance for Large DataSet

  • S3에 저장된 대용량 데이터에 대해 빠른 query를 수행하기 위해 사용

    • Fast, ad-hoc queries

    💡

    Ad-Hoc query는 특정한 형식 없이 사용할 수 있는 query문 이다. 미리 지정된 query가 아닌 변수를 통해 즉석에서 사용되는 query 이다. var newSqlQuery = “SELECT * FROM table WHERE id = ” + myId;

    • Execute queries in parallel

  • Complex query를 위해 별도의 Infra provisioning이 필요하지 않음

  • Scales automatically

  • Federated Query

    • 다른 종류의 DW나 DB와 Athena간 연동하여 query 수행

    • Federated Query Example

Performance 향상

RDS

  • RDS에서 Multi-master가 지원이 안된는 상황에서

  • Read performance를 향상하기 위해 replica를 생성하여 scale-out하는 방식으로 접근

  • Write performance 향상이 필요하면 scale-up 방식 으로 접근

Athena

  • Scale Out 전략

  • Computing과 Storage를 분리하여 각각 scale-out이 가능하도록 함

  • Write performance는 Storage에서 scale-out하여 확보

  • Read performance는 Compute에서 scale-out하여 확보

Design Pattern

Ad-hoc use case

SaaS use case

  • 고객에게 계정만 제공하고 그 계정을 통해 솔루션을 구성하는 경우에서 데이터를 Athena로 처리하는 방식

  • 빈번하게 access하지 않고 한 번에 많은 양의 데이터를 처리하는 기능은 Athena로 수행

  • 실시간으로 데이터를 빠르게 처리하는 기능은 RDS나 ElastiCache 등으로 수행

ETL and query use case

  • 데이터 변형(특정 column 추출, format 변경 등)이 필요한 경우 Spark, Flink, Hadoop MapReduce 등을 사용할 수 있지만 보유 기술 set이 MySQL등에 익숙하고 program으로 데이터 처리하는 것에 익숙하지 않다면 Athena를 활용하여 query로 이런 작업을 진행할 수 있음

Data Science exploration and Feature engineering

  • ML 개발자의 경우 데이터 변형 작업이 익숙하지 않다면 Athena를 사용하여 데이터 변형 및 전처리 작업에 활용

Comparison of SQL Processing engine

  • Athena나 EMR Flink, presto를 직접 비교하기는 어려움 → Athena의 cluster 크기를 명확하게 알기 어려음

  • 운영 효율성이나 비용의 측면에서 검토할 때 Athena가 유리할 수 있음

Partitions

Partition Projection

  • 모든 데이터를 scan하지 않고 특정 Partition에 대해서 선택적 scan → 성능 향상

  • Partition values and locations are calculated from configuration

  • Partition pruning gathers metadata

    • performance optimization that limits the number of files and partitions

  • Specify the ranges of partition values and projection types in AWS Glue Data Catalog or in Hive metastore

Partition 생성

  • MSCK REPAIR command

    • msck repair table

    • Data is already partitioned in Hive format

    • Sync all new data in S3 with Hive metastore

    • Manually add

      • ALTER TABLE ADD PARTITION

      • ALTER TABLE

      • ADD PARTITION (year=‘2021’, month=‘01’, day=‘01’) location

    • Partition이 존재하지만 Data에 해당 정보가 없는 경우는 문제 없음

      • 시계열 데이터의 경우 미리 Partition을 생성하여 사용할 수 있음

    • Data에 정보가 있지만 해당 Partition이 존재하지 않는 경우 Partition으로 scan할 경우 문제 발생

      • Different Workload - OLTP vs OLAP

      OLTP

      • Online transaction processing

      • RDB에서 많이 사용

      • 하나의 row에 있는 모든 데이터를 모두 사용 : Lots of small operations involving whole rows

      OLAP

      • Online analytical processing

      • 전체 row에서 특정 column만 사용하는 경우가 많음 : Few large operations involving subset of all columns

      • Partition data

      • Bucket data

        • Partition이 물리적으로 데이터를 구분 한다면 Bucketing은 metadata를 partition 하는 것

      • Compress and split data

      • Optimize columnar data store generation

      • Optimize queries

        • JOIN

        • GROUP BY

        • LIKE

      • Only include the columns needed
