  • Elasticsearch domain을 build 하는 Template file

B. CloudFormation에서 Template file로 stack 생성

  • CloudFormation 콘솔에서 Create stack 메뉴를 선택합니다.

  • Specify Template에 bootcamp-aes-moas.json file의 S3 URL을 입력하거나 template file을 업로드합니다.

    • Amazon S3 URL은 다음과 같습니다.

    • https://cf-template-jammylab.s3.ap-northeast-2.amazonaws.com/aes-imdb/bootcamp-aes-moas.json

  • Stack에서 사용할 Parameter를 입력합니다.

    • Stack name

    • CIDR Prefix : B class prefix를 입력합니다. 설정하지 않으면 VPC의 CIDR은 10.1.0.0/21 입니다

    • ElasticsearchDomainName : Elasticsearch service 의 domain 이름입니다. 기본값은 labdomain 입니다.

    • KeyName : EC2 생성시 SSH 연결을 위해 사용할 Key Pair 이름입니다. Key Pair가 보이지 않는다면 EC2 콘솔의 Key Pairs 메뉴에서 별도로 Key Pair를 생성합니다.

    • OperatorEMail : Stack 생성시 발생하는 SNS Topic을 수신할 EMail 입니다. 별도로 EMail Confirmation을 해 주어야 합니다.

  • 나머지 단계는 기본값을 그대로 사용합니다. 마지막 단계에서 Capabilities에 대해 동의한 후 ‘Create stack’ 을 진행합니다.

2-1. Visualizing Data

  • Kibana를 통해 data에 대한 index pattern을 만들고 이를 시각화 합니다.

A. Configure index pattern

  • Management 메뉴의 Index Patterns 을 통해 pattern을 생성합니다.

  • Index pattern name을 logstash-*로 입력합니다. Logstash에 입력되는 log file을 index 합니다.

  • Time Filter를 @timestamp 로 설정합니다.

  • Index pattern 생성을 완료합니다.

  • Discover 메뉴로 이동하면 생성된 index pattern에 매칭되는 log를 확인할 수 있습니다.

B. Logstash Index의 Template 변경

  • Dev Tools 메뉴를 선택합니다.

  • Console에 Put template을 입력 후 녹색 화살표를 눌러 template을 업데이트 합니다.

    • keyword에 field data를 추가하는 예시 입니다.

  • 정상적으로 처리되면 Elasticsearch에서 acknowledge를 true로 응답합니다.

  • 기존에 로드된 index를 삭제하기 위해 Console에 **DELETE logstash*** 를 입력한 후 녹색 화살표를 눌러 실행합니다.

3-1. Elasticsearch service Alerting

  • 특정 조건이 만족되면 notification을 발생 시키는 기능입니다.

  • Destination을 설정하여 notification을 전달할 방법을 생성합니다.

  • Monitor를 구성하여 어떤 action을 진행할 지 결정합니다.

  • Trigger를 어떤 조건에서 발생시킬 것인지 결정하여 생성합니다.

  • Trigger가 발생하면 Monitor가 action을 하여 Destination으로 message를 전달합니다.

지원되는 Destination

  • Elasticsearch Alerting에서 다음과 같은 channel에 alerting message를 전달할 수 있습니다.

  • Amazon SNS

    • HTTP/S endpoint, E-mail, Amazon SQS, AWS Lambda, SMS

  • Slack / Amazon Chime

  • E-mail

  • Custom webhook

3-2. Alerting 생성 - Webhook

  • Webhook으로 alerting message를 전달하도록 설정합니다.

A. Test용 Webhook URL 준비

  • 서비스와 연계할 Webhook URL을 사용하면 됩니다.

  • 시험용으로 사용하기 위해 아래의 site에서 임시로 생성합니다.

    • https://webhook.site

B. Destination 생성

  • Alerting 메뉴에서 Destinations 탭을 선택합니다.

  • Add Destination 버튼을 클릭하여 새로운 Destination을 등록합니다.

    • Webhook URL : 이전 단계에서 Test용으로 생성한 URL을 입력합니다.

    • Query Parameter 에는 message에 포함할 값들을 추가합니다.

    • Header Information 에서는 applicaion/json, application/xml, text/plain과 같은 Content-Type을 설정합니다.

    • Custom Header가 필요하면 Add Header를 사용합니다.

C. Monitor 생성

  • Monitors 탭으로 이동합니다.

  • Create monitor를 클릭하여 새로운 Monitor를 생성합니다.

  • Monitor 이름을 cpu로 입력하고 Schedule을 설정합니다.

  • 다음과 같이 Monitor를 구성합니다.

    • Define using visual graph

    • Index : input name metricbeat-*

    • Time field : @timestamp

  • Condition을 설정하여 cpu Monitor 생성을 완료합니다.

    • WHEN : max()

    • OF : system.cpu.user.pct

    • OVER : all documents

    • FOR THE LAST : 2 minutes

D. Trigger 생성

  • 생성된 cpu Monitor에 대해 Trigger를 생성합니다.

  • Create Trigger에서 cpu monitor를 선택합니다.

  • Add trigger를 선택한 후 Trigger를 정의합니다.

  • Add action에서 Destination을 설정합니다.

  • 이전 단계에서 생성한 webhook을 선택합니다.

  • Create 버튼을 눌러 생성을 완료합니다.

E. Alerting 발생 Test

  • JMeter와 같은 Load / Stress Test 도구를 사용하여 Webserver 부하를 생성합니다.

  • CPU Visualize 메뉴에서 CPU 부하가 증가하는 것을 확인 합니다.

  • 등록된 Webhook URL에서 수신되는 Alerting을 확인합니다.

  • 다음과 같이 Alert message가 전송되는 것을 확인할 수 있습니다.

    • user-agent : Apache-HttpClient/4.5.2 (Java/11.0.6)

    • 기본 message는 다음과 같습니다.

  • Alerting 메뉴에서 Monitor 항목을 Dashboard 형태로 확인할 수 있습니다.

  • History 항목에서는 시간별로 발생한 Alerting 을 표시합니다.

3-3. Alerting 생성 - Amazon SNS Webhook

  • Amazon SNS에 Topic을 생성하고 Elasticsearch의 Alerting을 SNS Topic으로 전달할 수 있습니다.

  • Amazon SNS에서 지원하는 Topic 구독 방법 중 Webhook으로 전송하는 방법을 사용합니다.

A. Webhook Subscription 생성

  • Amazon SNS 콘솔을 열고 Topics 메뉴에서 Create topic을 클릭하여 구독을 생성합니다.

  • 생성된 구독을 선택한 후 Create subscription 을 클릭합니다.

  • Protocol : HTTPS 혹은 HTTP를 선택합니다.

  • Endpoint : 사용할 Webhook의 URL을 입력합니다.

  • Create subscription을 클릭하면 생성이 완료 됩니다.

B. Topic 구독에 대한 동의 요청 - Confirmation Request

  • Subcription을 생성하면 등록한 Endpoint로 confirmation message가 전송됩니다.

  • Confirm이 되기 전에는 Status가 Pending confirmation 으로 표시됩니다.

  • Webhook에서 다음과 같은 Confirmation 요청이 수신 되는 것을 확인할 수 있습니다.

    • x-amz-sns-topic-arn : arn:aws:sns:us-east-1:189427507247:es-alert

    • x-amz-sns-message-id : 5ea4fb53-d1b0-4b67-aa54-4cc6c9687e22

    • x-amz-sns-message-type : SubscriptionConfirmation

C. Topic 구독 동의 - Confirmation Reply

  • Webhook URL로 전송되는 Confirmation Request message는 다음과 같습니다.

  • Confirmation을 하기 위해 필요한 부분은 SubscribeURL 입니다.

  • 전송된 SubscribeURL을 Browser로 Open만 하면 Confirmation이 완료 됩니다.

  • Confirmation이 완료되면 다음과 같이 생성된 Subscription이 Confirmed 상태로 변경됩니다.

  • Amazon SNS Topic의 ARN 값을 복사합니다. IAM Role 및 Alerting 생성에 필요합니다.

💡

Confirmation Reply 코드 작성은 다음의 링크를 참고하십시오. Sens Messages to HTTP/HTTPS Endpoint

D. Elasticsearch Domain의 SNS 접근 권한 생성

  • Elasticsearch Alerting을 SNS Topic으로 전송하기 위해서는 Elasticsearch domain의 SNS 접근 권한이 설정되어야 합니다.

  • SNS Topic 접근 role을 IAM 콘솔에서 생성합니다.

Set up a role - ES

  • IAM 콘솔에서 Create role을 선택합니다.

  • EC2 service를 선택하여 Role 생성을 진행합니다.

  • Create policy 단계에서 JSON tab을 선택합니다.

    • JSON policy edit 창에서 다음과 같이 SNS Publish 권한을 허용하는 정책을 입력합니다.

      • Reource 항목에는 생성한 SNS Topic의 ARN 을 입력합니다.

  • 입력된 Policy에 대해 이름을 입력하고 생성을 완료 합니다.

  • Role 이름을 입력한 후 Create role을 선택하여 생성을 마무리 합니다.

  • Policy 생성이 완료되면 Role 생성 단계로 전환됩니다.

  • 생성중인 Role의 Policy에 생성한 Policy를 선택하여 연결합니다.

  • Role 생성이 완료되면 다음과 같은 요약 정보가 표시 됩니다.

  • Trust relationships 탭을 선택합니다.

  • Trust relationship 을 편집합니다.

  • EC2 서비스로 Policy를 선택하여 Service 항목이 ec2.amazon.aws로 되어 있습니다.

  • ec2.amazonaws.com을 es.amazonaws.com 변경하여 Elasticsearch 서비스가 권한을 갖도록 변경합니다.

  • Update policy를 선택하여 변경 내용을 반영합니다.

  • 설정이 완료되면 Role의 ARN을 복사합니다. Alerting 설정에 사용됩니다.

E. Alerting Destination 추가 - Amazon SNS

  • Configure Actions에서 Destination을 추가합니다.

  • Amazon SNS Topic으로 전송하도록 설정합니다. 사전에 SNS Topic이 생성 되어 있어야 합니다.

    • Input Name

    • Select Type : Amazon SNS

    • SNS topic ARN : Amazon SNS 콘솔에서 생성한 Topic의 ARN을 입력합니다.

    • IAM role ARN : SNS Topic에 접근할 수 있는 Role의 ARN을 입력합니다.

  • Configure Actions 설정을 진행합니다.

  • Destination name : 앞에서 생성한 Amazon SNS destination을 선택합니다.

  • Message subject : 이전 단게에서 생성한 Trigger를 선택할 수 있습니다.
