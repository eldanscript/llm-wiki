4.1 Monitor Model Performance and Data Quality

Overview

모델 성능 모니터링:

  • 입력 데이터 품질 변화에 따른 모델 정확성 및 성능 모니터링

  • **데이터 품질, 모델 품질, 통계적 편향, 특성 기여도** 등 4가지 드리프트 유형 탐지

  • 모델 모니터링 및 문제 해결 도구 활용, 알림 생성, 자동 조치 수행

인프라와 비용 최적화:

  • 호스팅 인프라의 적절성과 비용 효율성 평가

  • SageMaker Inference Recommender를 사용한 컴퓨팅 리소스 최적화

  • 비용 관리 도구 활용, 태깅을 통한 비용 관리, 구매 옵션 선택

보안 및 규정 준수:

  • IAM을 통한 액세스 제어

  • 최소 권한 원칙 적용

  • SageMaker의 규정 준수 및 거버넌스 기능 활용

Monitoring ML Solutions

  1. 비즈니스 요구사항 충족:

    • 모니터링을 통해 ML 솔루션이 비즈니스 목표를 달성하고 있는지 평가

    • 핵심 성과 지표(KPI) 분석으로 투자 수익(ROI) 확인 및 전략적 조정

  2. 인프라 성능 모니터링:

    • ML 솔루션은 많은 컴퓨팅 리소스 요구

    • CPU/GPU 사용률, 메모리 사용량, 네트워크 처리량 등의 모니터링으로 효율적 운영 보장

    • 수요 변화에 맞춰 리소스 확장 지원

  3. 모델 성능 평가:

    • 실제 환경에서 모델의 정확도, 효율성, 전반적 효과성 모니터링

    • 정확도, 재현율, F1 점수, 추론 시간 등의 지표 추적

    • 엣지 케이스와 고장 모드에 대한 모델 성능 평가

  4. 모델 재학습 지원:

    • 데이터와 환경 변화에 따른 모델 노후화 문제 해결

    • 데이터 분포 변화, 예측 성능 저하 등의 지표 모니터링으로 재학습 시기 파악

  5. 규제 및 산업 표준 준수:

    • 개인정보 보호, 보안, 공정성 등의 규정 준수 필요

    • 데이터 보호, 윤리적 AI/ML 원칙 준수를 위한 모니터링 체계 구축

ML Lens

ML 워크로드를 위한 모범 사례와 설계 원칙:

  • 안전하고, 고성능이며, 복원력 있고, 효율적인 ML 워크로드 구축 및 운영을 지원

  • 소유권 지정, 보호, 리소스 최적화, 지속적 개선, 비용 절감, 자동화, 복원력, 재사용성, 재현성, 환경적 영향 최소화 등 실현

리소스 최적화:

  • 컴퓨팅, 스토리지, 네트워킹 등 클라우드 리소스의 효율적 활용

  • 리소스 풀링, 캐싱, 데이터 관리 등의 방법 활용

    1. 리소스 풀링:

      • 여러 워크로드에 걸쳐 컴퓨팅, 스토리지, 네트워킹 리소스를 공유

      • 리소스 활용도 향상 및 비용 절감

    2. 캐싱:

      • 자주 액세스되는 데이터 또는 중간 결과에 대한 캐싱 전략 구현

      • 계산 오버헤드 감소 및 성능 향상

    3. 데이터 관리:

      • 데이터 압축, 파티셔닝, 수명 주기 관리 등의 효율적인 데이터 관리 실행

      • 스토리지 및 처리 비용 최적화

수요 기반 확장성:

  • Auto Scaling, SageMaker, Lambda 등을 통한 동적 확장 지원

비용 관리:

  • 태깅을 통한 ML 활동별 비용 모니터링

  • ROI 추적, 수요 예측, 인스턴스 유형 최적화 등으로 비용 절감

지속적 개선:

  • 피드백 루프 구축, 성능 모니터링, 자동 재학습 파이프라인 구축

  • SageMaker Model Monitor, CloudWatch 활용

    피드백 루프 구축:

    • ML 생애주기 전반에 걸쳐 이해관계자, 전문가, 최종 사용자의 피드백 수집

    • 성공/실패 사례, 운영 활동을 분석하여 개선 영역 파악

    • 데이터 증강, 알고리즘 변경, 학습 접근법 실험으로 최적 성과 달성

    • 발견 사항을 문서화하여 프로세스 반복적으로 개선

    성능 모니터링:

    • SageMaker Model Monitor를 사용하여 개념 drift와 모델 drift 지속 평가

    • CloudWatch를 통해 이상 징후 탐지 시 신속한 조치 지원

    • SageMaker Model Dashboard로 성능 지표와 과거 행동 추적

    자동 재학습 파이프라인:

    • SageMaker Model Monitor에서 이상 또는 drift 감지 시 EventBridge 규칙으로 자동 재학습 파이프라인 실행

    • 신속한 모델 반복 및 프로덕션 배포로 ML 솔루션의 최신성과 고성능 유지

Detecting Drift in Monitoring

드리프트의 정의:

  • **모델의 예측 성능이 시간에 따라 저하**되는 현상

  • 사용자 행동, 시장 환경, 외부 요인 등의 **변화로 인해 발생**

  • **데이터 분포 변화로 모델 성능 저하**(정확도, 정밀도, 재현율 등)

  • **편향된 예측을 초래하여 공정성 문제** 발생 가능

Types of drift

ML 모델에서 모니터링 단계에서 발견될 수 있는 4가지 유형의 드리프트:

  1. 데이터 품질 드리프트:

    • 모델 학습 데이터와 실제 프로덕션 **데이터 분포의 차이**

    • 프로덕션 데이터의 **통계적 특성이 학습 데이터와 달라져 모델 정확성 저하**

  2. 모델 품질 드리프트:

    • 모델의 예측 결과와 **실제 정답 라벨 간의 차이**

    • **모델 성능이 시간에 따라 저하**되는 현상

  3. 편향 드리프트:

    • 모델 **예측에 영향을 미치는 편향이 증가**하는 현상

    • 학습 데이터의 **편향성, 중요 데이터 누락 등으로 인해 발생**

    • 실제 **데이터의 변화로 인해 새로운 편향이 도입**되는 경우도 있음

  4. 특성 기여도 (Feature Attribution) 드리프트:

    • 모델 예측에 대한 **개별 특성의 기여도가 학습 기준과 달라지는 현상**

    • 개념 드리프트라고도 불림 (Concept drift)

이러한 다양한 유형의 드리프트를 모니터링 단계에서 탐지하고 대응하는 것이 중요합니다.

Monitoring data quality and model performance

ML 모델의 다양한 유형의 드리프트를 모니터링하는 방법:

데이터 품질 모니터링:

  • 입력 데이터의 형식, 범위, 품질 검사 (data validation checks)

  • 평균, 표준 편차, 결측값, 이상치 등의 통계 지표 계산 및 기준과 비교 (Calculate statistical metrics)

  • 데이터 분포 변화 탐지(Kolmogorov-Smirnov 검정, 최대 평균 차이 등) (data drift detection)

모델 품질 모니터링:

  • 테스트 데이터 또는 프로덕션 샘플에서 정확도, 정밀도, 재현율, F1-score, AUC-ROC 등의 평가 지표 계산 (relevant evaluation metrics)

  • 신뢰 점수 임계값 설정, 불확실성 추정 기법 활용으로 신뢰할 수 없는 예측 식별 (confidence thresholding or uncertainty estimation)

  • 다양한 데이터 세그먼트에 대한 성능 모니터링으로 편향 이슈 파악 (different subpopulations, low confidence or high uncertainty)

편향 드리프트 모니터링:

  • 격차 지수, 기회 균등 차이, 평균 오즈 차이 등의 편향 지표 계산 (Calculate bias metrics)

  • 기준값 또는 허용 임계값과 비교하여 편향 증가 탐지 (Compare the bias metrics with baseline values or acceptable thresholds)

  • 역전파 디바이어싱, 균등 오즈 보정 등의 기법으로 편향 완화 (adversarial debiasing or calibrated equalized odds to mitigate bias)

특성 기여도 드리프트 모니터링:

  • SHAP 등의 기법으로 특성 중요도 점수 계산

  • 특성 중요도 통계 지표(평균, 표준 편차) 산출 및 기준과 비교

  • 특성 중요도 변화가 큰 것을 식별하여 데이터 또는 모델 드리프트 파악

이러한 모니터링 기법을 활용하여 다양한 유형의 드리프트를 조기에 감지하고 대응할 수 있습니다.

SageMaker Model Monitor

SageMaker Model Monitor란?

  • 프로덕션 환경의 **ML 모델 품질을 지속적으로 모니터링하는 완전 관리형 서비스**

  • **데이터와 모델 성능을 가시화**하고, **문제 발생 시 알림 제공**

동작 방식:

학습 데이터셋 기준 설정:

  • SageMaker Model Monitor는 모델 학습에 사용된 데이터셋을 기준으로 삼음

  • 데이터셋의 통계량(평균, 표준 편차 등)을 기준으로 설정

신규 데이터와 비교:

  • 프로덕션 환경에서 들어오는 새로운 데이터를 기준 데이터와 비교

  • 데이터 품질 이슈가 있는지 검사

모니터링 레포트 생성:

  • 데이터 품질 문제 발견 시 그 내용을 포함한 레포트를 생성

  • 레포트는 지정된 Amazon S3 버킷에 저장

4가지 모니터링 유형:

  1. 데이터 품질 모니터링: 입력 데이터 무결성 검사

  2. 모델 품질 모니터링: 모델 성능 지표의 변화 탐지

  3. 편향 드리프트 모니터링: 민감 속성에 따른 편향 증가 탐지

  4. 특성 기여도 드리프트 모니터링: 특성 중요도 변화 탐지

이를 통해 SageMaker Model Monitor는 데이터 품질, 모델 성능, 편향, 특성 기여도 등의 다양한 측면에서 ML 모델의 품질을 지속적으로 모니터링할 수 있습니다.

SageMaker Model Monitor의 주요 이점:

  1. 모델 성능 및 정확도 향상:

    • 지속적인 데이터 품질 모니터링으로 가장 정확하고 신뢰할 수 있는 데이터 사용 보장

    • 이를 통해 모델 성능과 정확도 개선

  2. 데이터 품질 이슈의 조기 탐지:

    • 모델 데이터에 문제가 생기면 신속히 식별

    • 성능 저하 발생 전에 문제를 해결할 수 있어 시간과 자원 절감

  3. 데이터 모니터링 운영 오버헤드 감소:

    • 데이터 품질 모니터링을 자동화하여 수작업 부담 경감

    • 팀이 모델 개발 및 배포의 다른 핵심 영역에 집중할 수 있게 함

  4. 데이터 품질 표준 준수:

    • 다양한 산업과 조직의 데이터 품질 표준 준수 지원

    • 규제 관련 문제 발생 위험 감소

실시간 모니터링:

  • 프로덕션에 배포된 ML 모델의 실시간 성능 모니터링 가능

다른 AWS 서비스와의 통합:

  • CloudWatch, CloudWatch Logs, EventBridge, CloudTrail 등과 통합되어 다양한 모니터링 및 감사 기능 제공

  • SageMaker Clarify와 연계하여 편향 문제에 대한 가시성 개선

SageMaker와의 긴밀한 연계:

  • SageMaker의 기능 중 하나로, 특성별 지표를 CloudWatch로 내보냄

  • SageMaker 전반에 걸쳐 모니터링 및 감사 기능을 제공

활용 시나리오:

  1. 실시간 엔드포인트 모니터링: 실시간 엔드포인트에 배포된 모델의 지속적인 모니터링

  2. 배치 변환 작업 모니터링: 정기적 또는 예약된 배치 작업에 사용되는 모델 모니터링

  3. 온디맨드 모니터링 작업: 언제든 모델 성능을 평가할 수 있는 온디맨드 모니터링 작업

모니터링 빈도:

  • 실시간 엔드포인트: 연속 모니터링으로 데이터 품질 이슈의 신속한 탐지

  • 배치 작업: 데이터 가용성과 원하는 빈도에 따라 조정 가능

모니터링 작업 스케줄링:

  • Cron 표현식을 사용하여 원하는 빈도로 작업 예약

  • 매시간, 매일 특정 시간, 요일, 월별 등의 일정 지원

모니터링 작업 상태:

  • 완료: 제약 위반 없음

  • 위반 있음: 제약 조건 위반 탐지

  • 실패: 권한, 인프라 문제로 인한 작업 실패

모니터링 작업 출력:

통계(STATISTICS):

  • 기준(baseline) 데이터와 모니터링 대상 데이터에 대한 통계 지표

  • 레코드 수, 각 특성의 평균, 최대/최소값, 결측값 수 등

위반 사항(VIOLATIONS):

  • 제약 조건(constraints.json 파일에 정의)을 데이터에 적용했을 때의 위반 내역

  • 위반 사항은 constraints_violations.json 파일에 출력

지표(METRICS):

  • SageMaker Model Monitor는 특성별 지표를 CloudWatch로 내보냄

  • CloudWatch의 지표를 기반으로 대시보드와 경보를 설정할 수 있음

  • SageMaker Studio에서도 요약 지표 확인 가능

로그(LOGS):

  • 모니터링 작업의 시작 시간, 종료 시간, 상태 등의 정보가 포함된 로그

  • CloudWatch 콘솔에서 로그 확인 가능

Monitoring for Data Quality Drift

How works

  1. 데이터 캡처 구성 설정:

    • SageMaker 엔드포인트에서 데이터 캡처 구성 설정

  2. 기준선 생성:

    • SageMaker에 기준 제약 조건과 통계 지표 생성을 요청

    • 학습 데이터에 대한 기준선 생성

  3. 기준선 통계 및 제약 조건:

    • 기준선 실행 후 각 특성에 대한 통계 지표 출력

  4. 데이터 드리프트 모니터링 작업:

    • 배포된 엔드포인트에서 새로운 추론 데이터 캡처

    • 기준선과 비교하여 위반 사항 또는 데이터 품질 이슈 보고

이와 같은 단계를 거쳐 SageMaker Model Monitor는 프로덕션 환경의 데이터 품질과 모델 성능을 지속적으로 모니터링할 수 있습니다.

데이터 캡처 구성 설정과 기준선 생성으로 모니터링의 기준을 마련하고, 이후 실시간으로 드리프트를 탐지하여 보고하는 방식입니다.

    • 필요에 따라 기준 제약 조건 수정

How works

유사점:

  • 데이터 캡처, 기준선 작업, 기준 통계 및 제약 조건 설정 등의 프로세스가 유사

  • 추론 요청 및 예측 처리 방식도 동일

차이점:

    • Ground Truth는 모델이 예측하거나 분류하고자 하는 진짜 라벨 또는 값

  • Merge 작업:

    • 모니터링 작업에서 **예측과 Ground Truth 데이터를 병합하여 비교**

즉, 데이터 품질 모니터링과 달리 모델 품질 모니터링에서는 사람이 개입하여 Ground Truth 데이터를 제공하고, 이를 기반으로 모델의 예측과 비교하는 과정이 추가됩니다.

SageMaker Model Monitor를 활용한 모델 품질 모니터링 방식을 정리하면 다음과 같습니다:

개요:

  • 모델 품질 모니터링 작업에는 다음과 같은 입력이 필요:

    • 기준 데이터

    • 배포된 모델의 추론 입력 및 예측

    • 모델 입력에 대한 SageMaker Ground Truth 라벨

  • 모델 예측과 Ground Truth 라벨을 비교하여 모델 품질을 평가

모델 품질 지표:

  • 문제 유형(이진 분류, 다중 분류, 회귀)에 따라 다른 지표 분석

  • 이진 분류의 경우 정확도, 재현율, 정밀도, F1 점수 등

  • 다중 분류와 회귀에도 유사한 핵심 지표 적용

모델 품질 모니터링 고려 사항:

  1. SageMaker Ground Truth 데이터 수집:

    • 최신 라벨 데이터 확보로 정확한 평가 보장

  2. 고유 식별자:

    • 예측과 Ground Truth 라벨을 정확히 연결하기 위한 고유 식별자 필요

  3. SageMaker Ground Truth 통합:

    • 라벨이 있는 데이터만 모니터링 작업에 사용하도록 시간 범위 조정

이러한 방식으로 SageMaker Model Monitor는 모델 품질을 지속적으로 모니터링하고 평가할 수 있습니다.

Monitoring Model Performance Using A/B Testing

A/B Testing

A/B 테스팅이란 다음과 같은 기법입니다: split testing, bucket testing

  • 둘 이상의 모델의 **상대적인 성능을 동시에 평가**하는 기법

  • **실제 데이터와 프로덕션 트래픽을 활용하여 평가**

  • 여러 모델을 병렬로 실행하고 제한된 프로덕션 트래픽에 노출하여 각 모델의 강점, 약점, 실제 성능 특성을 파악

이를 통해 현재 프로덕션 모델을 계속 사용할지, 새로운 모델을 배포할지에 대한 판단을 내릴 수 있습니다.

**SageMaker에서는 프로덕션 variant를 사용하여 동일한 엔드포인트에서 다양한 모델 또는 모델 버전을 테스트**할 수 있습니다.

프로덕션 variant는 엔드포인트 호출 시 요청을 어떻게 라우팅할지에 대한 유연성을 제공합니다. 각 프로덕션 variant는 ML 모델과 이를 호스팅하는 리소스를 식별합니다.

A/B 테스팅의 주요 이점

실제 성능 평가:

  • 실제 데이터와 사용자 상호 작용에 노출하여 **프로덕션 환경에서의 모델 성능을 더 정확하게 평가**

  • 오프라인 테스트에서는 발견되지 않았던 잠재적 문제나 편향 식별 가능

데이터 기반 의사 결정:

  • 실제 프로덕션 환경에서 다양한 모델을 비교하여 가장 우수한 성능을 내는 모델을 객관적으로 선별

  • 저성능 모델 배포로 인한 위험을 완화하고 최적의 성능과 사용자 경험 보장

지속적 모니터링:

  • 다양한 모델 간 지속적인 성능 비교를 통해 성능 저하나 개념 drift를 신속히 감지하고 대응

  • 잠재적 문제를 선제적으로 파악하여 애플리케이션과 사용자에 미치는 영향을 최소화

위험 완화:

  • 새로운 모델을 점진적으로 일부 사용자 또는 데이터에 도입하여 광범위한 성능 문제나 부정적 영향 최소화

사용자 경험 최적화:

  • 사용자 경험이 핵심인 애플리케이션에서 최적의 모델 선별

통제 실험:

  • 제한된 프로덕션 트래픽에 모델을 노출하여 변경 사항의 영향을 격리 및 분석

  • 더 나은 의사결정과 반복적 개선 지원

모델 성능 향상:

  • 실제 환경에서 직접 모델을 비교하여 최고의 성능을 내는 모델을 선택

  • 정확도, 효율성, 전반적인 모델 성능 개선

신뢰도 향상:

  • 실제 프로덕션 환경에서 검증된 A/B 테스트 결과로 인한 이해관계자의 신뢰 및 확신 제고

이처럼 A/B 테스팅은 ML 모델 배포와 모니터링 과정에서 다양한 이점을 제공합니다.

How works

A/B 테스팅을 활용한 프로덕션 모델 모니터링 과정을 정리하면 다음과 같습니다:

프로덕션 환경 업데이트:

  • 기존 프로덕션 모델 variant와 후보 replacement 모델 variant를 모두 지원하도록 업데이트

추론 요청 라우팅:

  • 추론 요청을 무작위로 A(현재 프로덕션 variant) 또는 B(후보 variant)로 라우팅

  • SageMaker의 다중 모델 엔드포인트 배포 기능을 직접 활용

트래픽 분배:

  • 모델 간 요청 분배 비율 지정 가능

  • 예: 프로덕션 모델 45%, variant1 10%, variant2 20%, variant3 15%, variant4 10%

  • 특정 모델의 새로운 기능 테스트를 위해 직접 호출 가능

지표 내보내기:

  • 지연 시간, 호출 수, 각 variant에 대한 호출 분배 등의 CloudWatch 지표 제공

SageMaker Model Monitor 지표 활성화 및 구성:

  • 모델 성능 지표는 기본적으로 내보내지 않으므로 별도 활성화 필요

  • 모니터링 유형에 따른 CloudWatch 지표 캡처 구성 필요

이를 통해 프로덕션 환경에서 다양한 모델 variant를 A/B 테스팅 방식으로 비교하고, 성능 지표와 모니터링 데이터를 활용할 수 있습니다.

When to use

A/B 테스팅이 필요한 상황은 다음과 같습니다:

실제 데이터 분포와 학습 데이터 분포의 차이:

  • 실제 데이터 분포와 학습 데이터 분포의 차이로 인한 프로덕션 상의 성능 격차

의도하지 않은 결과 감지:

  • 오프라인 테스트에서 포착되지 않은 데이터 drift, 개념 drift, 예상치 못한 사용자 행동 등의 문제 식별

사용자 상호 작용 및 피드백:

  • 추천 시스템, 대화형 에이전트 등 사용자 피드백에 크게 의존하는 모델의 경우 오프라인 평가만으로는 한계

동적 환경:

  • 전자상거래, 금융 등 **빠르게 변화하는 환경에서 모델의 신속한 적응이 필요할 때** A/B 테스팅이 유용

비즈니스 영향 평가:

  • 새로운 모델 배포 시 수익, 고객 만족도, 사용자 참여 등 **핵심 비즈니스 지표에 미치는 영향 파악**

고위험 의사결정:

  • 저성능 모델 배포로 인한 심각한 결과가 우려되는 의료, 금융 분야에서 추가적인 검증 필요

이러한 다양한 상황에서 A/B 테스팅을 활용하면 ML 모델의 실제 성능을 평가하고 최적의 모델을 선택할 수 있습니다.

Choosing Your Monitoring Approach

ML 모델 모니터링 전략을 수립할 때 고려해야 할 주요 요인들:

모델 복잡성:

  • 단순한 모델과 복잡한 모델에 적합한 모니터링 접근법이 다를 수 있음

  • 복잡한 모델일수록 더 면밀한 모니터링이 필요할 수 있음

애플리케이션 중요도:

  • 모델이 사용되는 애플리케이션의 비즈니스적 중요성

  • 중요도가 높은 경우 더욱 엄격한 모니터링이 필요

자원 가용성:

  • 모니터링을 위한 컴퓨팅, 스토리지, 네트워크 자원의 여유

  • 자원이 제한적인 경우 효율적인 모니터링 전략이 필요

규제 및 준수 요건:

  • 특정 산업이나 지역의 규제 및 준수 요구사항

  • 이에 부합하는 모니터링 기능 및 거버넌스 체계가 필요

모델 수명 주기:

  • 모델 개발, 배포, 운영 단계별 모니터링 요구사항 차이

  • 단계에 따른 맞춤형 모니터링 접근법 필요

이해관계자 요구사항:

  • 비즈니스 부문, 운영 부문, 데이터 과학 부문 등 다양한 이해관계자의 니즈 고려

  • 통합적이고 균형 잡힌 모니터링 전략 수립

이러한 다양한 요인을 종합적으로 고려하여 상황에 맞는 최적의 ML 모델 모니터링 접근법을 설계해야 합니다.

Influence Factors

원활한 모델 모니터링을 위해 고려해야 할 주요 요인들을 정리하면 다음과 같습니다:

모델 복잡성:

  • 기본적인 모델은 집중적인 모니터링이 필요하지 않을 수 있음

  • 복잡한 아키텍처의 모델은 더 정교한 모니터링 기법이 요구될 수 있음

애플리케이션의 중요도:

  • 금융, 의료, 안전 관련 애플리케이션과 같은 고위험 분야는 더 엄격한 모니터링과 신속한 대응 필요

  • 중요도가 낮은 애플리케이션은 상대적으로 완화된 모니터링 전략 가능

모니터링 빈도와 실시간성:

  • 실시간 모니터링은 즉각적인 영향이 우려되는 핵심 애플리케이션에 필요

  • 배치 모니터링은 비교적 중요도가 낮은 애플리케이션에서 적합

실제 사례 예시:

  • 자율 주행 자동차 시스템: 실시간, 고위험, 높은 상호 작용이 필요하므로 데이터 및 모델 중심의 포괄적이고 저지연 모니터링 접근법 필요

가용 자원:

  • 인력, 계산 자원, 예산 등의 제약에 따라 모니터링 기법의 적용 수준이 달라질 수 있음

  • 여유 자원이 충분한 경우 집중적인 모니터링이 가능하지만, 제한된 자원에서는 간소화된 접근법이 필요

이와 같은 다양한 요인을 고려하여 상황에 맞는 최적의 ML 모델 모니터링 전략을 수립해야 합니다.

Model Quality Monitoring

SageMaker Model Monitor를 활용한 ML 모델 모니터링 단계:

  1. 데이터 캡처 구성:

    • SageMaker 엔드포인트에 대한 데이터 캡처 설정

  2. 모델 성능 모니터링:

    • 정확도, 정밀도, 재현율, F1 점수 등의 핵심 성능 지표 추적

    • 허용 가능한 성능 임계값을 설정하고 위반 시 경보 발생

  3. 특성 기여도 모니터링:

    • 특성 중요도 변화를 해석 기법(SHAP 등)으로 모니터링

  4. 기준선 통계 및 제약 조건:

    • 편향 지표를 계산하고 기준과 비교

    • 편향 완화 기법 구현

이를 통해 SageMaker Model Monitor는 다양한 측면에서 ML 모델의 성능과 품질을 지속적으로 모니터링하고 관리할 수 있습니다.

Additional approaches to monitoring

ML 모델 모니터링을 위한 추가적인 접근법 및 고려 사항:

추론 데이터 모니터링:

  • 입력 데이터 검증: 형식, 범위, 제약 조건 준수 여부 확인

  • 출력 데이터 모니터링: 이상 패턴 감지

  • 추론 지연 시간 및 처리량: 성능 요구사항 충족 여부 확인

애플리케이션 사용 패턴 모니터링:

  • 사용자 행동 모니터링: 사용자 경험 개선 및 추가 안내 필요 영역 식별

  • 트래픽 패턴 모니터링: 용량 계획 및 확장 의사결정에 활용

  • 오류 및 예외 모니터링: 문제 진단 및 해결에 도움

비용 최적화:

  • 데이터 캡처 구성: 필요한 최소 샘플링, 요청/응답 캡처 범위 결정

  • Savings Plans, 리소스 태깅, ROI 보고 등으로 비용 관리

  • 사용자 정의 규칙보다는 기본 제공 규칙 활용

  • 유휴 리소스 정지 등으로 비용 절감

지속적인 개선:

  • 모니터링 접근법의 효과성 지속 검토 및 개선

  • 최신 기술 동향 파악 및 적용

  • 요구사항 변화에 맞춰 모니터링 접근 조정

이와 같은 추가적인 고려 사항들을 반영하여 ML 모델 모니터링 전략을 지속적으로 최적화할 수 있습니다.

Instead, a batch monitoring approach that focuses on data quality, and model performance would be most suitable. Automated Remediation and Troubleshooting

Automated Remediation and notifications

ML 모델 모니터링을 통한 자동화된 개선 및 알림 방법:

  1. 이해관계자 알림:

    • 모니터링 지표가 비즈니스 KPI에 영향을 줄 때 관련자에게 알림 전송

  2. 데이터 분석 자동화:

    • 데이터 드리프트 또는 누락 감지 시 데이터 과학자에게 알림

  3. 모델 재학습 자동화:

    • 드리프트, 편향, 성능 저하 감지 시 자동으로 모델 재학습 구동

  4. 자동 수평 스케일링:

    • 인프라 모니터링 지표(CPU/메모리/디스크 사용률 등)를 토대로 자동 수평 스케일링 실행

    • 비용 절감을 위해 활용

이러한 자동화된 조치를 통해 ML 모델의 신뢰성과 안정성을 높일 수 있습니다. 모니터링을 통해 탐지된 문제를 신속하게 해결하고, 리소스 활용도를 최적화할 수 있습니다.

Model Retraining Strategies

ML 모델 재학습 전략을 정리하면 다음과 같습니다:

재학습 접근법:

  1. 이벤트 기반 재학습:

    • CloudWatch 경보를 통해 드리프트 탐지 시 자동 재학습 파이프라인 실행

    • 비용과 시간이 많이 소요되므로 필요한 경우에만 재학습 수행

  2. 온디맨드 재학습:

    • 시장 환경 변화 등 특정 비즈니스 이벤트에 대응하여 재학습 수행

    • 데이터 과학자와 이해관계자에게 자동 알림 전송

  3. 예약 재학습:

    • 계절성 변화나 추론 데이터, 모델 성능 패턴을 토대로 주기적 재학습 예약

    • 정적 환경의 ML 모델에 적합

동적 환경의 적응형 재학습:

  • 경쟁 가격, 금리 변동 등 급변하는 요인에 의존하는 모델

  • 비즈니스 지표 대비 성능 저하 시 자동으로 재학습 실행

  • 예를 들어 평균 예측이 10% 감소하면 개념 drift 발생 가능성

이러한 다양한 재학습 전략을 통해 모델의 지속적인 최신성과 정확성을 유지할 수 있습니다.

Monitoring for automated retraining

Manual Intervention

자동화된 개선 조치만으로는 해결되지 않는 상황에서의 수동 개입 필요성:

데이터 변화 관찰:

  • 예상치 못한 데이터 변화 또는 누락 발생

  • 데이터 특성 변화(예: 카메라 업그레이드로 인한 영상 데이터 변화)

  • 데이터 과학자의 분석과 개입이 필요

규제 및 준수 문제:

  • 데이터나 모델이 규제 요건에 부합하는지 수동 검토 필요

  • 의료, 금융 등 규제 산업의 경우 추론 결과 검토

비즈니스 변화 및 문제 영역 변화:

  • 이자율 변동, 대출 정책 변경 등 비즈니스 변화에 대한 대응 필요

  • 모델 예측 결과가 잘못 사용되고 있는지 확인

KPI 및 문제 정의 재평가:

  • 비즈니스 목표 달성을 위한 올바른 KPI 측정 여부 검토

  • 변화된 비즈니스에 맞는 ML 솔루션인지 재평가

이와 같이 모니터링을 통해 탐지된 문제 중 일부는 데이터 과학자, 비즈니스 관계자 등의 수동 개입과 분석이 필요합니다. 자동화된 조치와 수동 개입을 적절히 조합하여 ML 모델의 안정적 운영을 달성할 수 있습니다.

Tools for troubleshooting issues

ML 모델 및 데이터 문제 해결을 위해 활용할 수 있는 주요 도구:

  1. 모델 레지스트리, 모델 카드, 계보 추적:

    • 모델 레지스트리: 프로덕션 모델 카탈로그와 버전 관리

    • 모델 카드: 모델 문서화, 학습 데이터, 평가 결과, 비즈니스 정보 등 중앙 관리

    • 계보 추적: **아티팩트 생성 파이프라인과 이벤트 추적, 근본 원인 분석**

이를 통해 다음과 같은 이점을 얻을 수 있습니다:

  • 모델 이력 관리 및 문서화로 문제 해결 지원

  • 문제의 근본 원인 파악과 지속적인 영향 파악

  • 문제가 감지되지 않은 경우에도 선제적 조치 가능

이러한 도구들은 ML 모델과 데이터 관련 문제를 효과적으로 해결하고 미리 대응하는 데 도움이 됩니다.

SageMaker Linear Tracking

SageMaker Lineage Tracking을 활용한 문제 해결 방법:

문제 상황 예시:

  • 학습 작업 실행, 모델 레지스트리 등록, 엔드포인트 배포의 워크플로우

  • 문제가 있는 데이터셋 발견, 해당 데이터로 학습된 모델이 배포된 엔드포인트 롤백 필요

SageMaker Lineage Tracking 활용:

  1. 문제가 있는 모델의 학습에 사용된 데이터셋 식별

  2. 해당 모델이 배포된 엔드포인트 또는 애플리케이션 파악

이를 통해 다음과 같은 효과를 얻을 수 있습니다:

  • 근본 원인 조사와 잠재적 영향 파악

  • 문제 해결을 위한 집중적이고 효과적인 대응 가능

즉, SageMaker Lineage Tracking은 ML 워크플로우의 추적 정보를 제공하여 문제의 근본 원인을 파악하고 필요한 조치를 취할 수 있게 합니다.

이는 모니터링 시스템에서 발견된 문제를 신속히 해결하고, 관련 영향을 최소화하는 데 도움이 됩니다.
