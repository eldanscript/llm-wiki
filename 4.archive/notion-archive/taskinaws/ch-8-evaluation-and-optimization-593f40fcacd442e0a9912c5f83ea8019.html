Evaluation Step

Define Evaluation

  • 알고리즘이 충분히 좋다 (정확하다…)를 판단하기 위해 어떤 척도 (metric) 혹은 척도들을 사용해야 할 지 결정

  • metric은 미터법 이라고 하며 말 그대로 측정하여 판단하는 것을 의미 한다. 머신 러닝에서는 학습을 통해 목표를 얼마나 잘(못) 달성했는지를 나타내는 값으로 사용된다

Evaluate

  • 학습 과정 혹은 완료 후 metric을 평가

  • 알고리즘에 따라 수동 혹은 자동으로 진행할 수 있음

Tune

  • Hyperparameter, 데이터, 평가 전략 (evaluation strategy)을 조정 또는 전체 알고리즘도 조정할 수 있다

  • 원하는 결과에 최대한 근사할 수 있도록 조정 → Tuning후 다시 Define 단계로 계속 iteration을 진행

Validation

Offline Validation

  • 시험용 데이터셋을 사용하여 검증

  • Validation (올바른 제품을 만들고 있는가?) vs Verification (제품을 올바르게 만들고 있는가?)

  • Validation Set, K-Fold Validation 방법 등이 있음

Online Validation

  • 실제 환경에서 검증

  • Canary Deployment나 A/B Testing 방법 등이 있음

Training Metrics

  • See if that process is going okay

  • Test prefix

Validation Metrics

  • Use testing model

  • Validation prefix

SageMaker Environment

  • SageMaker 알고리즘은 pre-configured SageMaker container를 통해 CloudWatch로 관련 metric을 전송

  • Logs of container, built-in algorithm 등과 관련된 metric 전송

  • View and visualize metrics in CloudWatch

  • ML 작업을 위해 EMR 혹은 Apache Mahout 을 사용할 경우 오른쪽과 같이 SageMaker 콘솔에서 chart를 통해 metric을 확인 → troubleshooting 이나 testing 과정에서 유용하게 사용 됨

Evaluating Model Accuracy

Underfitting (과소적합)

  • 모델이 기본 데이터 모양을 반영하지 못함

  • 모델을 적합하게 훈련하기 위해 더 많은 변수가 필요할 수 있음

Underfitting 방지

More Data

  • 엔트로피가 커질수록 불확실성이 높아지고 (발생 확률이 감소, unlikely event) 정보량이 많아짐

  • Underfitting은 feature가 적고 엔트로피가 낮음

  • Overfitting은 feature가 많고 엔트로피가 높음

  • 때로는 더 많은 데이터가 알고리즘을 과적합 (overfitting)에서 벗어나게 하기에 충분한 추가 엔트로피를 제공 → 엔트로피 값을 낮추게 하는 것이 목표

Train Longer

  • 에러를 최소화 하기 위해 (데이터안의 더 많은 데이터로 더 많은 반복 (iteration)을 필요로 한다

Overfitting (과적합)

  • 학습에 사용된 특정 데이터에 지나치게 의존적인 됨

  • 새로운 데이터가 학습 데이터와 유사하거나 동일하지 않다면 예측 정확도가 낮음

  • 알고리즘은 일반화 (generalize) 되었다기 보다는 기억 (memorize) 되었음

  • 모델이 어떤 수준까지 적합해 지면 overfitting 을 막기 위해 학습을 중단해야 함 → early stop

Overfitting 방지

More Data

  • 때로는 더 많은 데이터가 알고리즘을 과적합 (overfitting)에서 벗어나게 하기에 충분한 추가 엔트로피를 제공 → 엔트로피 값을 낮추게 하는 것이 목표

Sprinkle in some noise

  • 학습 데이터가 너무 깨끗 (pristine) 할 수 있음

  • 모델을 일반화 하기 위해서는 어느 정도의 잡음이 필요할 수 있음

Ensemble

  • 다른 모델을 함께 섞음

  • 약한 모델을 증폭 하거나 → boosting

  • 강한 모델을 부드럽게 함 → bagging

Early Stopping

  • 과도학습 (overtrain) 되기 전에 학습 과정을 중단

  • Hyperparameter에 포함되어 있음

Regulate

  • 정규화로 모델을 일반화 → 값의 범위를 확장하거나 가중치를 변경

  • 가중치 주위에 제약 조건을 만들거나 입력 데이터를 부드럽게 (smoothing) 한다 → 모델을 더욱 일반화

Ditch(도랑) some Features → Feature Selection

  • 너무 많은 무의미한 (irrelevant) 특성은 잡음으로 신호가 드러나지 않게 되어 모델에 부정적인 영향을 줄 수 있음

  • 어떤 특성들은 제거 할 수 있음

Robust Model

  • 학습 데이터에 적합화 되었으면서도 새로운 데이터가 나와도 합리적으로 예측됨

  • 새로운 데이터에 대해 효과적으로 일반화 할 수 있다

  • 데이터를 잘 따라 가지만 너무 가깝게 가지는 않는 모델

  • 데이터에 있는 잡음 (noise)를 다룰 (deal) 수 있다

Residual Distribution

  • Residual (잔차) : 실제 값과 예측 값의 차이

RMSE (Root Mean Square Error)

  • Measure of the distance between an actual observation and predicted value

  • Lower is better

Binary Classification Accuracy

Confusion Matrix

  • True False (False Positive) → Type I Error

    • 실제 음성 / 검사 양성 : 스팸이 아닌데 스팸이라고 판정 (거짓 양성)

  • False True (False Negative) → Type II Error

    • 실제 양성 / 검사 음성 : 스팸인데 스팸이 아니라고 판정 (거짓 음성)

AUC (Area Under the Curve)

  • Industry standard metric for binarly classification model

  • Data range : 0 ~ 1 → 1 means highly accurate

F1 Score

  • Recall (재현율) = TP / (TP + FN)

    • 참인 것에 대해 어느 정도 정확했는가 → sensitivity, hit rate

    • 실제 Spam 인데 Spam이 아니라고 예측 → Spam이 통과됨

  • Precision (정밀도) = TP / (TP + FP)

    • 참이라고 예측한 것은 어느 정도 정확했는가 → PPV (Positive Predicted Value)

    • Spam이라고 예측 (True) 했는데 Spam이 아님 → 합법적인 이메일이 차단

  • F1 Score는 Recall과 Precision의 조화 평균 (balance between Precision and Recall)

    • 값이 클수록 예측이 정확함을 의미

Improving Model Accuracy

Collect Data

  • 학습 예제의 수를 증가 → 좋은 데이터가 많을 수록 더 정확한 모델이 생성

Feature Processing

  • 추가적인 품질 변수를 제공하거나 기존 변수를 수정하여 더 많은 대표 특성이 나오도록 함

Model Parameter Tuning

  • 학습 알고리즘에서 사용되는 Hyperparameter를 조정

Model Tuning

  • Small Adjustments to hyperparameters → Improve the performance of the model

Automatic Model Tuning

Hyperparameter Tuning

  • 데이터셋에 대해 일정 범위의 hyperparameter를 시험하는 여러 작업을 수행하여 모델의 최적 버전을 찾아내는 작업

Process

  1. Choose tunable hyperparameter → 조정할 hyperparameter를 결정

  2. Choose a range of value → 조정 범위를 결정 (min/max)

  3. Choose the objective metric → auto tuning 작업이 최적화할 목표 metric을 지정

Bayesian Reasoning

  • 무슨 일이 일어 났는지와 현재 점수가 무엇인지 아는 것 → 베이지안 추론의 핵심

Bayesian Optimization

  • 더 많은 개선을 주는 Hyperparameter 값에 초점을 맞추어 비용이 많이 드는 반복을 피해야 함
