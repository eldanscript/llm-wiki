Container

Q) Docker와 Kubernetes에 대해 설명한다면?
A) Docker는 컨테이너를 run 하는 것으로 쓰이고 Kubernetes는 Container간의 통신이나 스토리지 공유와 같은 전반적인 시스템을 처리해 주는 역할을 하고 있다.

Q) Kubernetes에서 Control Plane의 역할과 기능은?
A) Control Plane은 API 서버, etcd가 존재 하면서 서로 다른 부분에 있는 pod들의 동작들을 상호 작용하게 해주고 어떤 노드에 pod들을 배치할 지 서로 공유를 시켜주고 IP 대역에 대해 어디에 어떤 pod가 있는지 찾을 수 있도록 REST API를 제공해 주고 있다

Q) Pod를 배치할 때 리소스들의 부족이 발생하면 어떻게 처리가 되는지?
A) 리소스가 부족하게 되면 K8s의 node selector를 활용하여 가용 노드에 pod에 배치하거나 auto scaler를 설정하여 해당 node의 자동적으로 증감을 설정할 수 있다. Pod 안에서의 가용되는 instance가 부족하면 scale up 이라는 기능을 통해 pod 자체를 복제하여 여유 공간을 늘릴 수 있다.

Q) 리소스 관리를 위해 모니터링이 필요한 데 관련 Tool에 대한 경험은?
A) 모니터링에 대해서는 Grafana나 Kibana를 사용해 본 정도 이며 직접적으로 Data 수집을 해 본 경험은 없음

Q) Kubernetes에서 Pod의 서버스 노출에 사용되는 방법들은?
A) AWS Load Balancer와 pod 내의 cluster IP 설정을 통해서 그것들을 연결하고 port에 해당하는 패킷을 전달하여 system에 직접적으로 접근하는 방법이 있고, K8s에 제공하는 load balancer type을 오픈하여 pod에 직접 접근할 수 있는 방법이 있음.
이런 접근을 위해 ingress 설정을 사용하는데 path 기반 방법과 doamin 기반 방법 2가지가 있는 것으로 알고 있음.

DataBase

Q) RDB와 NoSQL의 차이에 대해 설명한다면?
A) RDB의 경우에는 데이터를 테이블로 관리하는데 테이블의 정의하는 스키마가 정의되고, 스키마로 이루어진 테이블의 관계를 정의하고 데이터간의 연관성을 표시 하여야 함. 테이블에 들어가기 위해 데이터의 정제 작업을 통해 형식에 맞춰 주어야 함. 데이터 중복이 없도록 무결성을 확보해야 함
NoSQL은 확장을 용이하게 하기 위해 나온 것으로 대용량의 데이터를 처리 할 경우 RDBMS에서는 많이 비용이 필요하여 NoSQL이 나오게 되었음. Key-Value 형식의 데이터 관리가 이루어지고 확장이 용이한 대신에 데이터의 중복이 발생할 수 있어서 데이터 수정이 발생할 때 전체 row에 대해 수정할 수 있는 단점이 있음

Q) RDB에서 쓰기 성능이 저하되고 있을 때 어떤 조치를 취할 수 있는가?
A) 성능 저하 원인을 파악해야 하며, CRUD가 하나의 DB에서 일어난다고 하면 Read DB를 따로 구성하여 리소스를 확보 하고, 그래도 문제가 지속된다면 DB의 성능을 up 시킨다.

Q) Big Data 처리에서 NoSQL이 선호되는 이유는?
A) 현재 Big Data 처리 업무는 RDBMS로만 작업이 되고 있어 NoSQL을 사용하지 않고 있음

Q) Index가 하는 역할과 좋은 사용 방법은?
A) DB Index는 검색 속도나 Join 속도를 빠르게 하기 위해 사용됨. Constraint관점에서 데이터의 무결성을 보장하기 위해 사용될 수 있음.
단일 또는 복수의 mulit column에 대해 index를 설정할 수 있는데 조심할 점은 index를 과도하게 걸 경우 검색 속도는 빨라지지만 실제 성능에 대한 비용이 늘어날 수 있음.
DB Modeling이 제대로 되지 않은 상태에서 index로 문제를 해결하려 하면 요구 사항 변경등의 대응이 어려워 지게 됨. Index에 대해서는 적절한 관리가 필요.

Q) CDC에 대해 설명한다면?
A) Change Data Capture로 실제 DBMS가 가지고 있는 로그를 읽어서 로그의 변경 사항이 있는 경우 다른 쪽 DB에 동기화 하기 위해 사용됨

Q) ETL에 대해 설명한다면?
A) Extract, Transform, Laoder로 대용량 데이터를 일괄로 로딩하거나 DB to DB, DB to file, File to DB 등의 경우에서 데이터를 로드하고 추출해서 필요한 가공을 거치고
특정 데이터 소스나 repository에 데이터를 이동시켜 주는 솔루션

Q) Unitcast와 Multicast의 차이와 각각의 용도는?
A) Unicast는 단일 연결에 대해 메세지를 전송, Multicast는 브로드캐스트 방식으로 메시지를 받아야 하는 리스트를 구성하면 해당하는 리스트에 모두 전송하는 방식

Q) CIDR에 대해 설명할 수 있는지?
A) 알지 못함

Q) L4, L7 Load Balancer에 대해 설명할 수 있을지?
A) L4는 물리적인 IP나 Port를 보고 패킷을 해당 위치로 routing 하고 L7은 HTTP에 대한 요청이 들어올 때 Load Balancer에 규칙에 기반하여 해당 endpoint에 전달하는 것임

Security

Q) L4, L7에서의 보안 방법은 어떤것 들이 있는지?
A) 기본적인 방화벽 설계는 DMZ와 내부망으로 구분하고 여기에 방화벽을 구축할 수 있음. L4 layer에서 IP와 port를 컨트롤하는 방화벽이 있고 인터넷망에 있어서는 Web 방화벽이나 Layered Secure 기반으로 L7에서의 지능형 공격등에 대해 방어.
Log 분석 기법이나 DDoS 방지등의 기법이 있을 수 있음

Q) SQL Injection, XSS, XSS Request Forgery에 대한 방어 방법도 설명해 줄 수 있는지?
A) SQL Injection은 SQL 표현식을 변형하여 attach하는 것을 말하며 이에 대해서는 Parameter passing 방식이나 parameter 앞단에 filter등을 삽입하는 방식이 있음.
XSS는 host file을 수정하여 특정 domian ip를 다른 쪽으로 forwarding하고 iframe이나 popup등을 통해 site를 hooking하는 형식이며 이를 방어하기 위해 sub domain 설정으로 처리할 수 있음
Directory Indexing 등은 WAS나 OS 설정에서 처리할 수 있음

Q) Staeless에서 Stateful의 차이에 대해 설명할 수 있는지?
A) Session의 값을 유지하는 여부에 따라 구분할 수 있음. load balancer 같은 경우는 session 정보를 유지한다고 하면 커넥션이 이루어진 쪽으로 연결하는 것이 있을 수 있고
Image 서버나 Web page만 구성하는 등의 Application과 같이 session이 필요 없는 서비스에 대해서는 이전 정보 확인 없이 분배하여 사용한다.
MSA 관점에서는 독립적인 정보를 가지고 구성하는 여부에 따라 Stateless, Stateful의 의미적으로 구분하여 사용한다.
Network Security 관점에서는 Session 정보 유지 여부에 따라 구분하여 적용할 수 있을 것 같음
