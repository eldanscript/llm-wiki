4.3 Secure AWS ML Resources

Securing ML Solution

핵심 내용 요약:

  1. 기계 학습과 AI의 부상:

    • 데이터 기반 통찰력 확보, 프로세스 자동화, 의사 결정 지원

    • 안전하고 강력한 데이터 과학 워크로드 환경 구축의 중요성

  2. Amazon SageMaker의 역할:

    • 기계 학습 수명 주기 전반 간소화

    • 데이터 과학자와 엔지니어의 핵심 업무 집중 지원

  3. SageMaker와 AWS 서비스의 통합:

    • 거버넌스, 규정 준수, 보안 요구사항을 충족하기 위한 협업

    • 다양한 AWS 서비스와의 연계로 안전하고 확장 가능한 워크플로우 구현

  4. 보안 기능 및 서비스:

    • IAM을 통한 세부적인 액세스 제어

    • KMS로 데이터와 모델 암호화

    • VPC로 네트워크 격리 및 인프라 보안

    • CloudTrail과 CloudWatch로 모니터링 및 감사

    • S3를 통한 확장 가능하고 안전한 데이터 저장

  5. 포괄적인 보안 프레임워크:

    • CI/CD 파이프라인 등 인프라 전반의 보안 모범 사례 적용

    • 규모에 관계없이 AWS 보안 도구로 포괄적인 보안 실현

AWS는 SageMaker를 포함한 다양한 서비스를 통해 데이터 과학자와 엔지니어가 안전하고 확장 가능한 ML 환경을 구축할 수 있도록 지원합니다. 이를 통해 데이터와 ML 솔루션의 혁신적인 활용이 가능해집니다.

Shared Responsibility Model

  1. 공동 책임 모델(Shared Responsibility Model)의 개요:

    • AWS는 클라우드 인프라에 대한 보안(Security of the Cloud)을 담당

    • 고객은 사용 중인 서비스의 데이터, 모델, 구성 등에 대한 보안(Security in the Cloud)을 책임

  2. 공동 책임의 범위:

    • AWS는 물리적/환경적 통제 등 상속된 IT 통제 관리

    • 고객은 데이터 암호화, 액세스 관리, 규정 준수 등 자체적인 IT 통제 관리

  3. 고객의 책임:

    • 사용 중인 기계 학습 서비스와 배포 리전에 따른 책임 이해

    • 기존 IT 환경과의 통합 고려

    • 관련 법규(데이터 보안, 프라이버시 등) 준수

  4. 공동 책임 모델 적용:

    • 고객의 기계 학습 리소스에 대한 보안 확보

    • 데이터, 모델, 애플리케이션 보호

  5. 사례: Amazon S3 데이터 저장

    • AWS는 기반 인프라 보안 담당

    • 고객은 데이터 암호화, 액세스 권한, 규정 준수 관리 책임

공동 책임 모델을 이해하고 준수함으로써 AWS 상에서 기계 학습 리소스를 안전하게 운영할 수 있습니다.

Access Control Capabilities Using IAM

AWS Identity and Access Management (IAM)의 핵심 내용:

  1. IAM의 중요성:

    • ML 시스템, 모델, 관련 리소스에 대한 안전한 액세스 제어

    • 권한이 부여된 개인 및 엔티티만 ML 구성 요소에 접근하고 사용 가능

  2. IAM 사용자, 그룹, 역할:

    • ML 워크로드를 위한 안전한 환경 구축

    • 인간 및 기계 ID 프로비저닝을 통한 리소스 액세스 제어

  3. 사용자 역할:

    • 데이터 과학자/ML 엔지니어, 데이터 엔지니어, MLOps 엔지니어 등

    • 각 역할에 따른 권한 및 책임 정의

  4. 서비스 역할:

    • SageMaker, AWS Glue, Step Functions, CodePipeline 등의 서비스에 필요한 권한 제공

    • ML 워크플로우 관리 및 보안 지원

  5. IAM 정책:

    • ID 기반 정책(IAM 사용자/그룹/역할에 적용)

    • 리소스 기반 정책(Amazon S3 버킷, VPC 엔드포인트 등에 적용)

    • 최소 권한의 원칙에 따른 정책 수립

IAM은 ML 리소스 보안을 위한 핵심 서비스로, 안전한 ID 관리와 액세스 제어를 지원합니다. 최소 권한의 원칙을 적용한 정책 관리가 필수적입니다.

Principle of Least Privilege

최소 권한의 원칙(Principle of Least Privilege) 정의:

  1. 개요:

    • 데이터와 기계 학습 모델은 민감한 자산이므로 최소 권한의 원칙을 준수해야 함

    • 사용자, 역할, 서비스가 해당 작업을 수행하는데 필요한 최소 권한만 가지도록 하는 보안 모범 사례

  2. 구현을 위한 핵심 원칙:

    • 개인에 대한 역할 기반 액세스 제한

    • 계정 분리 및 AWS Organizations 활용

    • 액세스 패턴에 따른 ML 워크로드 구분 및 조직 단위 구조화

  3. 역할 기반 액세스 제한:

    • IAM을 통해 데이터 과학자, ML 엔지니어 등 역할별 권한 정의

    • SageMaker Role Manager로 노트북 인스턴스에 최소 권한 부여

  4. 액세스 패턴에 따른 워크로드 분리:

    • 데이터 접근, 모델 학습, 배포, 모니터링 등 다양한 구성 요소와 액세스 패턴 이해

    • 이에 따라 IAM 역할과 정책 구조화

  5. 계정 분리와 AWS Organizations:

    • 환경/팀/프로젝트별 계정 분리로 격리와 액세스 제어 강화

    • Organizations의 SCP로 전체 계정에 대한 최소 권한 정책 적용

  6. 최소 권한 원칙 적용 모범 사례:

    • 각 주체의 책임과 필요 권한 분석

    • 최소 권한만 부여하는 IAM 역할 생성

    • 지속적인 권한 검토 및 감사

최소 권한의 원칙을 철저히 준수하여 ML 자산과 리소스를 안전하게 보호할 수 있습니다.

Network Access Controls for ML Resources

ML 리소스 격리 방법 요약:

  1. Virtual Private Cloud (VPC):

    • 논리적으로 격리된 AWS 클라우드의 가상 네트워크

    • 인터넷 접근이 없는 프라이빗 서브넷을 생성하여 리소스 격리

  2. VPC 엔드포인트:

    • VPC 내부에서 AWS 서비스에 안전하게 접근할 수 있도록 지원

    • 엔드포인트 정책으로 액세스 제어 및 권한 관리

  3. NAT 게이트웨이:

    • 프라이빗 서브넷의 아웃바운드 트래픽을 인터넷에 연결

    • 인바운드 트래픽은 차단하여 리소스 보호

  4. VPC 내부 접근 제한:

    • VPC 외부에서의 접근을 차단하여 보안 수준 향상

    • 신뢰할 수 있는 내부 엔티티만 리소스에 접근 가능

  5. 보안 그룹:

    • 인바운드/아웃바운드 트래픽 제어를 통한 ML 리소스 보호

    • 프로토콜, 포트, IP 주소 기반 액세스 제어

  6. 네트워크 ACL (NACL):

    • 서브넷 단위의 추가적인 방화벽 기능 제공

    • 트래픽 차단을 위한 세부적인 규칙 구성

  7. AWS Network Firewall:

    • VPC 전반의 네트워크 보안을 관리하는 관리형 서비스

    • 침입 차단/탐지, 웹 필터링, 콘텐츠 검사 등의 기능

이러한 다양한 네트워크 액세스 제어 수단을 통해 ML 리소스의 보안을 한층 더 강화할 수 있습니다.

Security and Compliance Features

Amazon SageMaker의 데이터 프라이버시 및 옵트아웃 기능:

  1. 데이터 프라이버시:

    • AWS 서비스 약관에 따른 프라이버시 보장 및 고객 권한 명시

    • 리소스 식별자, 성능 지표 등 사용 데이터 공유 거부 가능

    • GDPR, HIPAA 등 규제 준수를 통한 민감 데이터 안전한 처리

  2. 메타데이터 수집 옵트아웃:

    • AWS 문서와 Trusted Advisor의 지침에 따라 옵트아웃 수행 가능

  3. 데이터 암호화:

    • 저장 데이터(모델, 노트북, S3 아티팩트) 서버 측 암호화

    • AWS KMS로 AWS 관리형 키 또는 고객 관리형 키(BYOK) 사용

    • 전송 중 데이터는 TLS 프로토콜로 암호화

  4. ID 및 액세스 관리:

    • IAM을 통한 세부적인 리소스 액세스 제어

    • 관리형 정책과 SageMaker Role Manager로 편리한 권한 관리

  5. 로깅 및 모니터링:

    • CloudWatch로 ML 워크로드 성능 및 상태 모니터링

    • CloudTrail로 보안 및 규정 준수 이슈 파악

SageMaker는 다양한 데이터 프라이버시 및 보안 기능을 제공하여, 고객의 민감한 정보와 ML 자산을 안전하게 보호합니다.

Compliance and Governance Features

기계 학습 시스템의 규정 준수 고려 사항:

  1. 규정 준수 수준 결정 요인:

    • 데이터의 민감도(개인정보, 재무 데이터 등)

    • 기업 목표 및 위험 허용도

    • 적용 법규 및 규정(HIPAA, GDPR 등)

    • 규정 대상 AWS 서비스(SageMaker 등)

  2. AWS의 규정 준수 지원 서비스:

    • AWS Artifact: 규정 준수 보고서 및 계약 제공

    • AWS Config: 리소스 구성 평가 및 모니터링

    • AWS Security Hub: 보안 상태 및 규정 준수 점검

    • AWS Audit Manager: 지속적인 규정 준수 감사

    • Amazon Inspector: 취약점 및 네트워크 익스포저 검사

  3. SageMaker의 거버넌스 도구:

    • SageMaker Role Manager: 최소 권한 역할 정의

    • SageMaker Model Cards: 모델 정보 문서화 및 공유

    • SageMaker Model Dashboard: 모델 행동 가시화

    • SageMaker Assets: ML 아티팩트 관리 워크플로우

  4. 규정 준수 인증 및 프레임워크:

    • ISO 27001, SOC 2, PCI-DSS, HIPAA, FedRAMP 등

    • 산업 표준과 모범 사례에 부합하는 SageMaker 설계

규정 준수와 보안을 고려하여 SageMaker로 ML 솔루션을 구축하고 배포함으로써, 기업은 민감 데이터와 워크로드를 안전하게 보호할 수 있습니다.

Security Considerations for CI/CD Pipelines

CI/CD 파이프라인의 보안성 확보:

  1. CI/CD 파이프라인의 중요성:

    • 코드 구축, 테스트, 배포 자동화로 애플리케이션 배포 프로세스 개선

    • 모든 코드 변경에 대해 자동화된 검증 및 배포 수행

  2. 기계 학습 모델 개발 시 보안의 중요성:

    • 데이터 유출, 모델 위변조, 인프라 침해 등 심각한 결과 초래 가능

    • CI/CD 파이프라인의 각 단계에서 보안 관행 통합 필요

  3. CI/CD 파이프라인 단계별 보안 관행:

    • 사전 커밋 단계: 사전 커밋 후크, IDE 플러그인을 통한 코드 준수성 검사

    • 커밋 단계: SAST(정적 코드 분석)로 취약점 탐지

    • 빌드 단계: SCA(소프트웨어 구성 분석)로 오픈소스 패키지 취약점 식별

    • 테스트 단계: DAST(동적 애플리케이션 보안 테스트), IAST(대화형 애플리케이션 보안 테스트)

    • 배포 단계: 침투 테스트로 최종 제품 검증

    • 모니터링 단계: 적색팀/청색팀/자주팀 활용 시뮬레이션 테스트

  4. 인프라 보안:

    • IaC(인프라 코드화)로 일관된 환경 구축

    • Config, CloudTrail로 인프라 변경 모니터링 및 감사

    • Secrets Manager로 보안 암호 저장 및 교체

    • IAM으로 액세스 및 권한 관리

종합적인 보안 관행을 CI/CD 파이프라인에 통합함으로써, 기계 학습 모델과 인프라를 취약점과 위협으로부터 보호할 수 있습니다.

Implementing Security and Compliance through Monitoring and Logging

Amazon CloudWatch를 통한 ML 워크로드 모니터링 및 보안 관리:

  1. CloudWatch 지표:

    • ML 워크로드와 SageMaker 성능 실시간/역사적 모니터링

    • CPU, 메모리, 데이터 전송, 모델 지연 시간 등의 지표 수집 및 분석

    • 보안 문제, 리소스 남용, 성능 병목 식별에 도움

  2. CloudWatch 경보:

    • 임계값 초과 시 알림 전송 및 자동 조치 트리거

    • SageMaker 학습 작업의 기간 또는 비용 초과 감지 등 활용

  3. CloudWatch Logs:

    • EC2, CloudTrail 등의 로그 파일 모니터링, 저장, 액세스

    • 로그 데이터 분석 및 특정 패턴 감지 시 경보 설정

    • SageMaker 학습 작업의 오류/경고 모니터링 및 권한 없는 접근 탐지

  4. CloudTrail:

    • SageMaker에 대한 사용자/역할/서비스 활동 기록

    • API 요청의 IP 주소, 요청자, 시간 등 정보 제공

    • 보안 및 규정 준수를 위한 감사 및 모니터링

  5. 사용 사례:

    • 규정 준수 감사 보고

    • 리소스 최적화

    • 보안 인시던트 대응

    • 이상 징후 탐지

CloudWatch와 CloudTrail을 활용하여 ML 시스템의 무결성과 신뢰성을 확보하고, 규제 요건을 준수할 수 있습니다.
