Best Practices

Device Gateway

Secure Communication

  • Certificates for mutual authentication by using Message Queuing Telemetry Transport (MQTT) over Transport Layer Security (TLS) v1.2

  • SigV4 over HTTP - Access Key ID, Secret Access Key

  • MQTT over WebSockets, which is similar to other AWS services

  • Custom authentication tokens that are provided by your authentication or authorization service

  • Provides flexible authorization options and fine-grained access control through JavaScript Object Notation (JSON) policies

IoT Device Gateway

  • Enables devices to securely and efficiently communicate with AWS IoT Core

  • IoT Device Gateway can exchange messages using a publish/subscribe model

  • Enables one-to-one and one-to-many communications

IoT Message Broker

  • Processes and routes data from your devices into AWS IoT Core

  • Message broker is scalable, has low-latency, and provides reliable message routing

  • Uses a publish and subscribe model to decouple devices and applications

  • Allows two-way message streaming between devices and applications and provides an opportunity for data transformation, rerouting, and enhancement with external data sources

IoT Rule Engine

  • Listens for incoming messages that match a rule

  • When a matching message is received, the rule acts on the data

IoT Device Shadow Service

  • Often referred to as a thing shadow or a digital twin

  • Maintains a shadow for each device you connect to AWS IoT

  • Use the shadow to get and set the state of a device over MQTT or HTTP, regardless of whether the device is connected to the Internet

  • Each device’s shadow is uniquely identified by the name of the corresponding thing

  • Topics

  • State

  • Metadata

  • Lifecycle

  • Things

    • Reports the current state to shadow

    • Retrieve desired state from shadow

  • Device Shadow

    • Coordinates and synchronizes shadow document updates

    • Publish update events on related shadow topics

  • Mobile App

    • Set the desired state of a device

    • Get the last reported state of the device

  • Device Shadow MQTT Topics

    • UPDATE : **$aws/things/**thingName/shadow/update

    • GET : **$aws/things/**thingName/shadow/get

    • DELETE ; **$aws/things/**thingName/shadow/delete

    • DELTA ; **$aws/things/**thingName/shadow/delta

IoT Registry

  • A database of devices

  • The registry helps you manage your device ecosystem effectively and acts as a repository for device certificates

  • The registry also enables you to search for your things based on attributes and tags

Device vs Thing

  • Device refers to the physical entity

  • Thing refers to the logical entity

    • identified by a name - unique within your account

    • thing type and groups must be unique within your account

    • thing type is a method to organize IoT things into logical categories

    • Associate things to only one thing type at a time

    • Thing type can have up to 50 attributes

    • A thing that is not associated with a thing type can have three attributes

    • Associate things with up to 10 groups at the same time

Device Authentication

  • Authentication enables you to verify the identity of a client or a server

  • Server authentication

    • Process by which devices or other clients ensure that they are communicating with an actual AWS IoT endpoint (디바이스 또는 다른 클라이언트가 실제 AWS IoT 엔드 포인트와 통신하는지 확인하는 프로세스)

  • Client authentication

    • Process by which devices authenticate themselves with AWS IoT Core (디바이스가 AWS IoT Core로 자신을 인증하는 프로세스)

  • Store Keys on devic

    • Certificates enable asymmetric keys to be used with devices

    • Burn private keys into secure storage on a device

    • Sensitive cryptographic material never leaves the device

    • Certificates also provide stronger client authentication over other methods, such as user name and password or bearer tokens, because the secret key never leaves the device

  • Use X.509 certificate

    • Use a public key infrastructure standard to associate a public key with an identity contained in a certificate

    • X.509 certificates are issued by a third party called a certification authority (CA).

    • The CA maintains one or more special certificates called CA certificates that it uses to issue X.509 certificates

    • X.509 certificate chains are used both for server authentication by clients and client authentication by the server

  • Activate and revoke certificate

    • Certificates are created within AWS IoT Core and downloaded to the device through TLS v1.2

    • Before the device can authenticate, the certificate must be activated

    • Certificates can be revoked if there’s concern that the device has been compromised or is being decommissioned

Device Authorization

  • Authorization is the process of granting permissions to an authenticated identity

  • Policies for AWS IoT define what an authenticated identity can do

  • IoT policies primarily control an identity’s access to the IoT data plane

    • The data plane enables you to send data to and receive data from AWS IoT

    • Defines whether you can connect to the message broker, send or receive MQTT messages, or publish or subscribe to a specific topic

  • IAM policies grant an IAM identity, or AWS resource, permissions to access a service or perform a function with AWS

  • IAM roles work with IAM policies to grant AWS IoT Core permissions to access the rest of AWS

  • Policy format

    • Effect, Action, Resource

MQTT - The Standard for IoT Messaging

MQTT clients are very small, require minimal resources so can be used on small microcontrollers. MQTT message headers are small to optimize network bandwidth. MQTT allows for messaging between device to cloud and cloud to device. This makes for easy broadcasting messages to groups of things.

https://mqtt.org/

](https://mqtt.org/)

  • Topics are 8-bit Unicode Transformation Format (UTF-8) encoded hierarchical strings that use a forward slash (/) to separate the levels in the hierarchy

  • The message broker maintains a list of all client sessions and the subscriptions for each session

  • AWS IoT Core supports MQTT over WebSockets to enable browser-based and remote applications to send and receive data using AWS credential

IoT Device Registry

  • Helps you manage things and organizes the resources associated with each device in the AWS Cloud

  • Associate certificates and MQTT client IDs with each device to improve your ability to manage and troubleshoot them

  • A catalog of static metadata and attributes about the devices

  • Fully managed and scales to over a billion devices

  • A repository of the device certificates

IoT Rules Engine

  • Rules engine is one of the primary methods of filtering and directing communication from AWS IoT Core to other AWS services

  • When data comes into the AWS IoT Core, rules are analyzed and actions are performed based on the MQTT topic stream

  • Rule engine language

    • Uses SQL-like statements that are built within a structured development environment to filter and route MQTT messages

    • roleARN gives AWS IoT permission

IoT Analytics

  • Automates the steps required to analyze data from AWS IoT devices

  • Channel

    • Collects and archives raw, unprocessed message data before publishing this data to a pipeline

  • Pipeline

    • Consumes messages from a channel and enables you to process and filter the messages before storing them in a data store

  • Data Store

    • Not a database, but it is a scalable and queryable repository of your messages. You can have multiple data stores for messages that come from different devices or locations

  • Dataset

    • Retrieve data from a data store by creating a dataset. AWS IoT Analytics enables you to create a SQL dataset or a container dataset. Here, the simple SQL dataset is similar to a materialized view from a SQL database. In fact, you create a SQL dataset by applying a SQL action

  • Dataset contents

    • The results. After you create dataset contents, you can view them from the console

  • Analysis of the process

    • Collect

      • Define an AWS IoT analytics channel and selecting the specific data to collect

    • Process

      • Configure AWS IoT Analytics pipelines to process data

    • Store

      • After processing the data in the pipeline, AWS IoT Analytics stores it in an IoT-optimized data store for analysis

    • Analyze

      • Query the data store by using the built-in SQL query engine in AWS IoT Analytics to answer specific business questions

    • Build

      • Build visualizations and dashboards to get business insights quickly from your AWS IoT Analytics data using Amazon QuickSight
