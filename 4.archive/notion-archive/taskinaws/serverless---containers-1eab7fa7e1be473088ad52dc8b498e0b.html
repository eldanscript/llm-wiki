  • configuration file break down

    • “eksctl” is creating cluster.

    • metadata section.

      • This section defines what region we want to deploy to and the name of our cluster.

    • “fargateProfiles” section

      • create EKS Fargate profiles that are used to tell EKS which Kubernetes Pods to schedule on Fargate.

      • Kubernetes uses selectors (a.k.a labels) to connect different objects together, rather than tightly coupling resources.

      • The same is true for Fargate Profiles. In our configuration, when a new pod is scheduled in the “default” or “kube-system” namespace

      • EKS will automatically schedule that pod onto a Fargate instance.

    • “IAM” section

      • allows us to configure least privileged pods. By default, pods will inherit the IAM access from the underlying host that they are running. For example, if an EC2 instance has access to the S3 logs bucket, the pod will have access to that bucket as well.

      • Conversely, we don’t want to have to attach all possible IAM permissions to the EC2 instance that our pods may need. IAM Roles for Service Accounts (IRSA) enable us to associate a specific IAM role with a Kubernetes Service Account.

      • All pods in Kubernetes run with a Service Account. If a Service Account is associated with an IAM role, Kubernetes will inject temporary credentials into the pod.

    • In this example, we are creating a alb-ingress-controller Service Account with the IAM permissions it needs to create and configure load balancers on our behalf. By using IRSA, we are enabling least privileged pods.

    • Best Practice: It is best practice to associate the default service account in all Kubernetes namespaces with an explicit deny all IAM role so that by default, pods have no access to AWS resources

    Notice that we have added a few annotations.

    • kubernetes.io/ingress.class: alb. This tells the ALB Ingress Controller that we want it to handle this resource.

    • alb.ingress.kubernetes.io/scheme: internet-facing tells the ALB Ingress Controller that we want to configure a public facing load balancer. The ALB Ingress Controller will use tags on the subnets to determine which subnets to place the load balancer.

    • alb.ingress.kubernetes.io/target-type: ip. This is a critical annotation for use with Fargate.

    By default, load balancers attach the instance to the target group and map a randomly generated port number into the target group to route traffic.

    By placing the load balancer in IP mode, we will route traffic directly to that IP address on the
    network rather than an instance.

    AWS Fargate does not expose instances into our VPC so we must configure the load balancer to use IP mode.
