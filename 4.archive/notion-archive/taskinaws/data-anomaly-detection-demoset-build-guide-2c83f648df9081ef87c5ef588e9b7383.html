Introduction

  • Streaming data를 실시간으로 분석 하여 data pattern의 이상을 감지하는 solution example

  • Amazon Kinesis 서비스를 이용하여 data analytic pipeline을 build

  • Solution example은 **data ingest** → **data analytic** → **anomaly alert** 로 구성

  • Streaming data는 가상의 data를 random하게 generation하여 공급

  • Data Generator Tool을 이용하여 production data와 유사한 format으로 생성 후 streaming

Build DemoSet

💡

CloudFormation Template을 사용하여 Data Generator와 Kinesis Data Analytic resource를 구축합니다.

A. Anomaly Detection

1. Upload Template

  • BillingAnomalyDetection-CFN.json Upload

    • 설치할 Region의 CloudFormation을 선택한 후 CreateStack 메뉴를 실행합니다.

2. Configure Stack Parameter

  • Template file을 Upload후 Next를 선택하여 Stack 구성 설정을 합니다.

  • Email

    • Amazon SNS로 alert를 받을 email 주소를 입력 합니다.

    • Stack build 후 해당 Email로 전송되는 수신 동의를 진행해야 합니다.

  • SMS

    • Amazon SNS로 alert를 받을 문자 메세지의 전화 번호를 입력 합니다.

    • 전화 번호 형식은 E.164로 국가 코드를 포함하여 입력 합니다.

  • SMSActivate

    • SMS 전송을 지원하지 않는 Region에서는 ‘disable’ 시켜야 합니다.

    • SMS 전송 지원 Region은 AWS 가이드에서 확인 할 수 있습니다.

  • ShardCount

    • Kinesis Data Stream의 Shard 수를 설정합니다. Shard는 리전당 10개 까지 구성할 수 있습니다.

    • 하나의 Shard는 초당 1MB data input 및 2MB data output 용량을 제공하고 최대 1000개의 PUT record를 지원합니다.

    • Data Stream 생성 후 에는 Resharding을 이용하여 동적으로 Shard를 추가하거나 제거할 수 있습니다.

  • UseDemoAnalytic

    • Amazon Kinesis Data Analytic을 자동으로 구성하고 사전에 설정한 Data의 Schema를 사용하도록 구성합니다.

    • ‘Disable’ option을 선택하면 Kinesis Data Analytic이 구성되지 않으며 수동으로 구성하여 사용합니다. Data 소스를 직접 만들어 Analytic Application을 만들거나 Demo용이 아닌 다른 Data 소스를 사용하고자 할 때 사용할 수 있습니다.

3. Create Stack

  • 다음 단계에서 CloudFormation 설정을 합니다. 변경하지 않고 다음 단계로 넘어 갑니다.

  • IAM Role 설정 항목에 동의를 click하고 stack을 생성합니다.

4. Creation Result

  • Resource 탭을 선택하여 다음과 같이 생성된 결과를 확인할 수 있습니다.

  • 주요 Resource의 역활은 다음과 같습니다.

    1. KinesisInputStream

      • Data Generator에서 생성되는 Data Stream을 수신 합니다.

    2. KinesisAnomalyApplication

      • Data Stream의 Anomaly Score를 산출하는 Data Analytic Application 입니다.

    3. KinesisOutputStream

      • 이상 감지 대상인 DataSet과 산출된 Anomaly Score를 Data Stream으로 출력합니다.

    4. AnomalyHandler

      • Anomaly Score Data Stream을 입력으로 받아 Alert 여부를 처리합니다.

      • Alert를 발생 하게 되면 AnomalyDataDetect Topic으로 메시지를 publish 합니다.

    5. AnomalyDataDetect

      • Alert를 구독하는 Topic 입니다.

      • Stack 구성 시 설정된 Email과 SMS로 메시지를 전송합니다.

B. Data Generator

1. Upload Template

  • KineisDataGenerator-CFN.json Upload

    • AnomalyDetection을 설치한 Region의 CloudFormation을 선택한 후 CreateStack 메뉴를 실행합니다.

2. Configure Stack Parameter

  • Template file을 Upload후 Next를 선택하여 Stack 구성 설정을 합니다.

  • Data Generator Web Page에 Login할 사용자 이름과 비밀 번호를 입력합니다.

  • 비밀 번호는 6개 이상의 문자와 1개 이상의 숫자를 사용해야 합니다.

  • 사용자 이름과 비밀 번호는 Amazon Cognito의 UserPool에 등록됩니다.

3. Create Stack

  • 다음 단계에서 CloudFormation 설정을 합니다. 변경하지 않고 다음 단계로 넘어 갑니다.

  • IAM Role 설정 항목에 동의를 click하고 stack을 생성합니다.

4. Creation Result

  • Resource 탭을 선택하여 다음과 같이 생성된 결과를 확인할 수 있습니다.

    • SetupCognitoCustom

      • Kinesis Data Stream으로 data를 전송할 수 있는 권한을 설정하는 Lambda 함수

      • Cognito User Pool을 생성하고 Generator 사용자를 등록

      • 등록되는 User에 Kinesis를 Access 할 수 있는 permission을 부여

  • Output 탭을 선택하여 DataGenerator 접속 URL을 확인합니다.

  • URL을 클릭하여 DataGenerator Web Page를 확인합니다.

Run DemoSet

💡

Data Generator Tool에서 생성한 data stream을 Anomaly detection application을 이용하여 이상 패턴을 감지하여 등록된 정보에 따라 Alert를 송신 합니다.

A. Generate Data Stream

1. Login Data Generator

  • Data Generator Stack 생성 시 등록한 사용자 이름과 비밀번호로 Login 합니다.

    • billinglog-kdg / billinglog2020

2. Config Data Generator

  • Login 후 Data Stream을 위한 설정을 합니다.

  • Region 항목에서 Kinesis Data Stream을 구축한 **Region을 선택**합니다.

  • 선택한 Region에서 Kinesis Data Input / Output Stream List를 가져옵니다.

  • 구축된 **Data Input Stream을 선택**합니다.

  • Data 전송 Rate - **초당 전송할 Record 값을 설정**합니다. 기본값은 100 입니다.

    • Kinesis Data Stream은 1개 Shard가 초당 최대 1000 records 까지 가능합니다. 구축한 Shard 수 및 Test 목적에 맞게 설정합니다.

    • Constant는 Data Stream을 일정하게 전송합니다.

    • Periodic은 시간 단위로 일주일 동안의 Data Stream을 설정할 수 있습니다. Workload의 패턴에 따라 Data Stream을 유사하게 설정하여 시험할 수 있습니다.

  • **Compress Records option은 사용하지 않습니다**.

    • Compress option을 사용하면 Data Stream을 gzip으로 압축하여 전송 할 수 있습니다.

    • 압축하여 전송하면 Stream Consumer에서 decryption을 합니다. Kinesis Data Analytics을 사용할 경우에는 Analytics Application 전 단에서 decryption을 구성 합니다.

  • Record Template에 DemoSet용 **Template Data를 아래와 같이 입력**합니다.

  • ‘Test template’을 클릭하여 Template Data로 생성되는 Data Example을 확인합니다.

  • Record Template 추가 설명

    • Data Generator는 PutRecord API를 사용하여 data record를 전송하는데 이 record 생성에 Record Template을 이용합니다.

    • Record Template은 JSON, CSV 및 Unstructured type으로도 만들 수 있습니다.

    • Data element 중 가변되는 element는 moustache syntax를 사용하여 표현합니다.

3. Produce Data Stream

  • Data Record 설정이 완료되면 ‘Send data’를 클릭하여 Data Record를 Kinesis Data Stream으로 Put 합니다.

B. Run Analytic Application

  • Template을 이용하여 2개의 Kinesis Data Stream과 1개의 Data Analytic을 구축하였습니다.

  • 콘솔에서 Amazon Kinesis Dashboard를 선택하면 다음과 같이 확인할 수 있습니다.

1. Monitor Input Data Stream

  • Data Stream 중 InputStream을 선택하여 세부 메뉴를 확인합니다.

  • ‘Monitoring’ 탭을 선택하여 세부 지표를 확인합니다.

    • Input data record 수, latency 값 등을 확인 할 수 있습니다.

    • Data metric 조회 주기를 설정하여 Data 누적 범위를 조정할 수 있습니다.

    • Input Data Latency는 평균 20msec 입니다.

2. Run Analytic Application

  • Data Analytics를 선택하여 구축된 application을 확인합니다.

  • Status가 Ready이므로 Run 시키기 위해 application을 선택합니다.

  • Real time analyticsdm의 ‘Go to SQL editor’를 선택합니다.

  • Pop-up 메뉴에서 ‘Yes, start application’을 선택하여 application을 시작합니다.

  • ‘Source’ 탭에서 현재 수신되는 Data Record를 확인 할 수 있습니다.

  • ‘Real-time analysis’ 탭을 선택하면 Input되는 Data Stream에 대해 실시간으로 Anomaly Scoring 되고 있는 값을 확인할 수 있습니다.

  • ‘Destination’ 탭을 선택하면 Anomaly_Score가 포함된 Data Output Stream을 확인할 수 있습니다.

  • Anomaly Detection SQL code

    • Data record의 ‘COL_cpuidle’과 ‘COL_cputotal’의 data 값을 monitoring 하면서 Anomaly_Score 값을 산출하고 Data column과 함께 Output Stream으로 생성합니다.

    • Anomaly Detection Algorithm은 RANDOM CUT FOREST를 사용합니다.

    💡

    Data Source인 Data Input Stream (SOURCE_SQL_STREAM_001) 의 행을 읽고 RANDOM_CUT_FOREST 함수로 이상 점수를 할당하고 결과 행을 다른 in-application stream (TEMP_STREAM)에 씁니다. 그런 다음 TEMP_STREAM의 record를 정렬하고 결과를 다른 in-application stream (DESTINATION_SQL_STREAM)에 저장합니다. DESTINATION_SQL_STREAM은 연결된 Data Output Stream으로 출력됩니다.

3. Anomaly Score Output Stream

  • Data Stream 중 OutputStream을 선택하여 세부 메뉴를 확인합니다.

  • ‘Monitoring’ 탭을 선택하여 세부 지표를 확인합니다.

    • Output data record 수, latency 값 등을 확인 할 수 있습니다.

    • Data metric 조회 주기를 설정하여 Data 누적 범위를 조정할 수 있습니다.

    • DemoSet의 Output Stream latency는 450msec 정도를 보이고 있습니다.

C. Check Alert Operation

1. Lambda Function

  • 콘솔에서 Lambda를 선택하여 생성된 함수를 확인합니다.

  • Lambda 함수는 Kinesis Analytics의 Anomaly_Score Output Stream이 Trigger 소스로 설정되어 있습니다.

  • Lambda 함수의 Function Code는 Anomaly_Score 값이 기준치를 넘게 되면 SNS로 Topic을 publish 하도록 구성되어 있습니다.

2. SNS Push Message

  • 콘솔에서 Simple Notification Service를 선택하여 등록된 Topic을 확인합니다.

  • Topic name을 선택하여 Subscriptions를 확인합니다.

    💡

    Stack create 할 때 SMSActive를 enable 시킨 경우에는 등록된 모바일 번호로 SMS 구독이 포함되어 표시됩니다.

  • Email 수신은 사용자의 동의가 되어 있지 않으면 Status가 ‘Pending confirmation’ 상태입니다.

  • 등록된 Email로 전송된 수신 동의 메일을 확인하여 수신 동의를 진행 합니다.

  • 수신 동의가 되면 Email Subscription 상태가 ‘Confirmed’로 변경됩니다.

  • Lambda 함수에서 설정한 Anomaly Score 기준 값을 넘는 경우 다음과 같이 Email로 Alert 메일을 수신할 수 있습니다.

Data Anomaly Detection

Data Range 변경 시험

Normal Data

  • Data 변화 Range를 40 ~ 50 사이의 값으로 설정하여 Record 생성

  • Anomaly Score

    • Data Range의 최 외각 범위의 값에서 0.6 score를 보임

Abnormal Data

  • Data 변화 Range를 0 ~ 100 사이의 값으로 설정하여 Normal Data 대비 변동 범위가 큰 Record의 Anomaly Score를 확인

    • Data Range가 40 ~ 50 범위에서 많이 벗어나게 되면 Anomaly score가 1.5 ~ 1.7로 증가
