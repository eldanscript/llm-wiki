1.1 Collect, Ingest, and Store Data

Learning Objectives

  1. 이 과정은 기계학습(Machine Learning) 수명 주기 중 데이터 준비 단계를 다룹니다.

  2. 이 과정에서 다루는 주요 내용은 다음과 같습니다:

    • 데이터 기본 개념 - **데이터 유형, 효과적인 데이터 판별, 데이터 시각화 및 탐색적 데이터 분석**

    • AWS 스토리지 옵션 - Amazon S3 등 **ML 프로세스에 사용되는 AWS 스토리지 서비스**

    • 데이터 수집 - **데이터 인제스트, 추출, 병합** 등 AWS 서비스 활용

    • 데이터 인제스트 및 스토리지 문제 해결

Fundamentals of Data Collection

Introduction

  1. 데이터 수집 및 준비의 중요성

    • ML 모델 훈련을 위해 대표성 있고 가치 있는 고품질 데이터 수집이 중요

    • 정확하고 깨끗한 데이터가 필요하며, **편향성 없이 윤리적으로 수집**해야 함

    • 적절한 데이터 수집이 이루어지면 훗날 ML 알고리즘 학습에 도움이 됨

  2. 데이터 저장소 유형

    • 데이터 **레이크**: 다양한 데이터 원천의 **구조화/비구조화 데이터**를 모아놓은 저장소

    • 데이터 **웨어하우스**: 정형화된 데이터를 **관계형 데이터베이스**에 저장하여 분석에 최적화

    • **데이터베이스**: **온라인 트랜잭션** 처리에 최적화된 데이터 저장소

  3. 데이터 수집 및 준비 프로세스

    • 데이터 원천 파악 및 **중앙 저장소에 데이터 수집/인제스트**

    • 수집된 데이터 클렌징, 준비, 보안 작업 수행

  4. 데이터 특성이 ML 모델 성능에 미치는 영향

    • 데이터의 **정확성, 완전성, 관련성** 등 특성이 ML 모델 학습에 중요

Data Quality

  1. 데이터 품질:

    • 데이터 수집 단계에서 데이터의 유효성, 정확성, 완전성 등 데이터 품질에 대해 고려해야 함을 강조합니다.

    • 데이터 시각화와 탐색적 데이터 분석을 통해 데이터 품질을 평가하고 개선할 수 있는 방법을 설명합니다.

  2. 고성능 데이터:

    • 기계 학습 모델의 성능을 최적화하기 위해서는 고품질의 데이터가 필요함을 강조합니다.

    • AWS 스토리지 서비스 선택 시, 데이터 액세스 패턴, 비용, 성능 등을 고려하여 적절한 스토리지 솔루션을 선택하는 방법을 다룹니다.

    • 데이터 형식 선택 시에도 데이터 액세스 패턴을 고려하여 최적의 데이터 형식을 선택하는 방법을 설명합니다.

Representative (대표성)

  1. 실제 세계를 정확하게 반영하는 고품질 데이터 사용:

    • 모델에 제공되는 데이터는 **실제 상황을 정확하게 나타내어야** 함

    • 예를 들어, 고객 이탈률이 실제 20%라면 데이터에도 그와 유사한 이탈률이 표현되어야 함

    • 그렇지 않으면 모델이 더 많거나 적은 이탈을 잘못 예측할 수 있음

  2. 데이터와 실제 세계의 불일치 주의:

    • 데이터가 실제 상황을 정확하게 반영하지 못한다면, 의미 있는 패턴을 찾아내고 정확한 예측을 하기 어려움

    • 따라서 데이터와 실제 세계 간의 불일치를 주의 깊게 관찰해야 함

요약하면, 기계 학습 모델의 성능을 최적화하기 위해서는 **실제 상황을 정확하게 반영하는 고품질의 데이터를 사용**하는 것이 매우 중요하다는 점이 핵심입니다.

Relevant (관련성)

  1. 대표성 있는 데이터 사용:

    • 실제 상황을 대표성 있게 반영하는 고품질 데이터를 사용해야 함

    • 예를 들어 회원 탈퇴율 예측 시 회원 기간 등의 속성이 잘 포함되어야 함

  2. 관련성 있는 데이터 사용:

    • 예측 대상과 관련성이 높은 속성들을 포함해야 함

    • 관련성이 낮은 정보가 섞여 있다면 모델의 성능을 저하시킬 수 있음

    • 예를 들어 회원 탈퇴율 예측 시 고객 이메일 정보는 관련성이 낮아 성능을 떨어뜨릴 수 있음

관련성이 높은 속성들을 포함해야 모델의 성능을 높일 수 있음

Feature Rich (다양한 속성)

  1. 풍부한 특징을 가진 데이터 사용:

    • 모델이 내재된 패턴을 학습할 수 있도록 다양한 특징(feature)이 포함된 데이터를 사용해야 함

    • 가능한 많은 관련 데이터를 포함하면 더 정확한 예측이 가능함

    • 특징이 제한적인 데이터는 고객 이탈 예측 등의 정확도를 떨어뜨릴 수 있음

Consistent (일관성)

  1. 일관된(consistent) 데이터 사용:

    • 특징이나 형식 등 **데이터의 속성이 일관**되어야 함

    • 일관성 있는 데이터는 더 정확하고 신뢰할 수 있는 결과를 제공함

    • 데이터 소스가 다양하여 형식이나 메타데이터가 다르다면 일관성이 떨어져 모델의 성능이 저하될 수 있음

Types of Data

Data Types

  • Text / Tabular / Time Series / Image

Formatting data

  • Unstructured data : lacks a predefined structure

  • Structured data : has a well-defined schema

  • Semi-structured data : has organizational properties, ex) tags, markup

Row-based data format

  • each row represents a single record or entity

  • the columns represent each of the features of that entity

  • Row-based file types

    • CSV (Comma-separated values) : lightweight, space-efficient text files that represent tabular data

    • Avro RecordIO : row-based data storage format that stores records sequentially,

Column-based data format

  • stores information with columns as the primary structure

  • queries extract insights from patterns within a column

  • efficient analysis of trends across large datasets

  • Column-based file types

    • Parquet : columnar storage format typically used in analytics and data warehouse, data can be compressed

    • ORC (Optimized row columnar) : similar to Parquet, big data workloads (Apache Hive, Spark), efficiently compress data

Object-notation data

  • non-tabular, hierarchical data, such as graphs or textual data

  • structured into hierarchical objects with features and key-value pairs

  • Object-notation file types

    • JSON (JavaScript Object Notation) : flexible data structure, compact, hierarchical, and easy to parse

    • JSONL (JavaScript Object Notation Lines)

      • newline-delimited JSON

      • encoding JSON objects that are separated by new lines instead of being nested

      • improves efficiency because individual objects can be processed without loading a larger JSON array

Batch and Streaming data

Batch data

  • collected and processed in batches rather than continuously

  • processed one time or on a recurring schedule

  • not time-critical and is used for long-term analysis

Streaming data

  • continuously generated and processed in real-time or near real-time

  • requires additional considerations like data buffering, real-time monitoring

Data Visualization and Exploratory Data Analysis

Data Visualization

  • gather insights into the quality and relevance of the data

  • Analyze data to understand patterns, trends, structure, and limitations → Algorithm selection

  • Visualize data to identify quality issues (missing values, outliers, inconsistencies) → Clean data

  • Shape data through transformations → Feature engineering to optimize for modeling

Methods for data visualization

  • Relationship analysis : Identifies correlations, select relevant features and remove redundancies

  • Distribution analysis : central tendency, variability, shape, and outliers, understand the characteristics of the data

  • Comparison : Quantifies differences between subgroups, reveals separate trends

  • Composition (구성) : Identifies biases by visualizing proportions, percentages, and counts within the data (데이터 속 비율, 퍼센티지, 개수 등을 시각화하여 데이터 내의 편향성을 파악)

Graphs for data visualization

Categorical data

  • qualitative information (비정형 정보)

  • bar charts, pie charts, heatmaps : frequency of distribution across categories

    • heatmaps : depict patterns and relationships in a dataset

    • pie charts : circular graph that represents the entirety of the dataset.

    • bar charts : using bars to represent the proportion of a dataset for specific attributes

  • Statistical analysis : calculating frequencies, proportions, contingency tables (상관관계 표)

Numerical data

  • quantitative information (정량적 정보)

  • Scatterplots

    • relationship between two variables on a coordinate system

  • Histogram

    • divided into bins (구간, 범위) representing a range that variables fall within

  • Density Plots

    • show the shape and spread of data

    • the distribution of a single feature

  • Box Plots

    • displaying the location of key data points

    • quickly comparing distributions and identifying skewness (왜도, 데이터 분포의 치우침 정도), spread, and outliers

AWS Storage Options

S3

  • flexible, scalable, object storage service

  • data lakes, websites, cloud-centered apps, backups, archives, analytics, and ML

Use Case

  • Data ingestion and storage

    • ingested into Amazon S3 through streaming or batch processing

    • well-suited for storing the large volumes of data needed for effective machine learning

  • Model training and evaluation

    • versioning to manage different model iterations → store training and validation data

    • manage and compare models to evaluate performance

  • Integration with other AWS services

EBS

  • well-suited for databases, web applications, analytics, and ML workloads

  • high-performance, low-latency block storage

  • Permits point-in-time snapshot backups

Use Case

  • High-performance storage

    • requiring fast access to large datasets

    • high throughput and IOPS accelerate ML workflows and applications

  • Host pre-trained models

    • upload, store, and access pre-trained ML models

    • generate real-time predictions without setting up separate hosting infrastructure

EFS

  • performance remains high even as file system usage changes

  • NFSv4 networking protocol to allow compute instances access to the file system across a standard file system interface

Benefits

  • Scalable and performant : accessed concurrently from multiple Amazon EC2 instances

  • High throughput : Promotes high throughput and parallelism

  • Low-latency access : low-latency access to petabyte-scale shared file systems

Use Cases

  • Concurrent access

    • multiple Amazon EC2 instances to access the same datasets simultaneously

    • well-suited for ML workflows that require shared datasets across multiple compute instances

  • Shared datasets

    • Multiple instances can access data, such as ML learning libraries, frameworks, and models, simultaneously without contention (간섭, 충돌)

    • contributes to faster model training and deployment

FSx

  • provides access to popular file systems : Lustre, NetApp ONTAP, OpenZFS, Windows File Server

  • delivers millions of IOPS with sub-millisecond latency

Benefits

  • Shared access : mount file systems to multiple compute instances for shared access

  • High performance : low latency and high throughput

  • File system types : a variety of file system

  • Storage options : ephemeral storage for temporary tasks, persistent storage for long-term data retention

Use Case

  • Two types of file systems

    • fully managed service that provides two types of file systems: Lustre and Windows File Server

  • Distributed architecture

    • Lustre’s distributed architecture provides highly parallel and scalable data access

Choosing Storage

Performance

  • Scalability Elasticity (확장 탄력성)

  • Data access patterns

  • Throughput Latency

Key considerations

  • Inference workloads

    • usually don’t require high I/O performance, except for real-time inference cases : EBS gp3, EFS

    • low-latency demands : EBS io2

  • Training workloads

    • high performance and frequent random I/O access : EBS

  • Real-time and streaming workloads

    • EFS

  • Dataset storage

    • S3

Data access patterns

  • Copy and Load

    • copied from Amazon S3 to a training instance backed by EBS

  • Sequential Streaming

    • streamed to instances as batches or individual records

    • from S3 to instance backed by EBS

  • Randomized Access

    • with a shared file system data store

    • Amazon FSx and Amazon EFS

Cost

  • S3 : the lowest cost

  • EBS : more expensive per gigabyte than Amazon S3

  • EFS : read and write access and the amount of gigabyte used with different storage tiers available

  • FSx : depends on the file system, storage type used for each gigabyte, throughput capacity provisioned, and requests

Cost-optimized storage for ML

  • S3

    • Use Amazon S3 storage tiers based on how often you access data

    • Use Amazon S3 Intelligent-Tiering with unknown access patterns to optimal tiers

    • Archive rarely-accessed data to reduce costs and delete any data no longer needed

  • EBS

    • Select the EBS volume type that matches the performance needs

    • Right-size the capacity of volumes

    • Use EBS optimized instances for dedicated throughput

  • EFS

    • Right-size your Amazon EFS share

    • choose the best performance mode

    • Manage file lifecycle management: Move infrequently-accessed data to a lower cost tier

  • FSx

    • Select storage capacity, throughput, and single compared with multi-Availability Zone deployment

    • Use the lifecycle management : move infrequently-accessed data to lower-cost storage

Data Structure

  • Optimizing the data format can significantly reduce overall costs

  • Well-formatted data requires less processing time and improves data efficacy

Transform data

  • only include relevant information

  • Removing unnecessary data

Use columnar storage

  • efficient, accessible format

  • reduce storage needs and speed up processing

Compress data

  • decrease storage requirements

Format splittable data

  • only necessary data chunks are loaded rather than full datasets

  • allows distributed training across instances for faster parallel processing and improves overall performance

Data Ingestion

Collecting data

  • data arrives in varied formats, including unstructured, semi-structured, and structured

  • AWS provides storage services that can serve as a point of origin and destination for data ingestion

  • S3 often serves as the primary destination for data ingestion and collection

Data Ingestion methods

  • Batch Ingestion (historical analysis)

    • collects and processes data on scheduled intervals

    • well for less time-sensitive, historical data

  • Real-time Ingestion

    • streams data as it is generated

    • time-sensitive data, like transactions or sensor metrics

Use Cases

  • Time-sensitive processing

    • ingesting data and detecting insights immediately as events occur

    • real-time alerts and rapid response

    • fraud detection

  • Historical analysis

    • ingesting data in batches over longer periods of time

    • insights gathered are less time-sensitive but allow for spotting big-picture trends by aggregating data

    • historical analysis of transactions

Dedicated Streaming Services

Kinesis

  • ingest and process in real-time data streams

  • Kinesis Data Streams is primarily used for ingesting and processing data

    • read and process streaming data that is durable and available for up to 7 days

  • Firehose provides a streamlined method of streaming data to data storage locations

    • destinations such as Amazon S3 and Amazon Redshift

  • Amazon Managed Service for Apache Flink provides consumption of streaming data in real-time for analysis

    • Java or Scala applications

    • manages the underlying Flink clusters and infrastructure

  • Use Case

    • Data ingestion

    • Data processing

    • Real-time inference

MSK

  • Apache Kafka to enable real-time streaming data

  • provides Apache Kafka clusters with built-in high availability, security, and scalability

Data Extraction

Transferring data

  • act as sources and destinations for data

  • access large datasets from diverse sources

  • provides services to help transfer data between different services and sources

Data transfer and extraction tools

CLI

  • handling authentication, validation, and formatting

SDKs

  • Python, Java, and JavaScript

S3 Transfer Acceleration

  • Amazon CloudFront edge locations to accelerate large data transfers to and from Amazon S3

  • speed up data collection for ML workloads that require moving large datasets

DMS (Database Migration Service)

  • migration between databases or to Amazon S3

  • SQL, JSON, CSV, and XML

  • run on schedules or in response to events for frequent data extraction

Lambda

  • no server management and flexible function initiation without managing infrastructure

Glue

  • fully managed extract, transform, and load (ETL) service

  • discover, catalog, and extract data from S3, RDS, DynamoDB

DataSync

  • efficiently transfer data between on-premises systems or AWS services

  • extracting data from sources (data file systems, NAS)

  • then upload data to AWS services (S3, EFS, FSx, RDS)

  • moving large datasets to the cloud while reducing network costs and data transfer times

Snowball

  • physical device service used to transfer large amounts of data into and out of AWS

  • move terabytes or petabytes of data into Amazon S3 for initial data transfer or extraction

Services to extract data from

S3

  • Amazon S3 Transfer Accelerator, AWS CLI, AWS SDK, AWS Snowball, AWS DataSync, AWS DMS, AWS Glue, and AWS Lambda

EBS

EFS

RDS

DynamoDB

  • AWS DMS, AWS Glue, and AWS Lambda

Data Ingestion and Storage Troubleshooting

Monitoring tools

CloudWatch Metrics

  • view and analyze metrics

  • give insights into the performance and health of storage resources

CloudWatch Logs

  • collecting, storing, and analyzing logs from various AWS services

  • gaining insights for potential issues for data ingestion and storage

Service Dashboards

  • provides service dashboards that integrate with CloudWatch metrics

  • monitor the performance and health of the services from their services dashboard

  • provide real-time insights into service availability and performance

  • view events across a period of operation

AWS Storage service metrics

EBS

  • VolumeReadBytes: The total number of bytes read from the volume

  • VolumeWriteBytes: The total number of bytes written to the volume

  • VolumeReadOps: The total number of read operations from the volume

  • VolumeWriteOps: The total number of write operations to the volume

  • VolumeThroughputPercentage: The percentage of provisioned IOPS being used by the volume

  • VolumeQueueLength: The number of outstanding I/O requests waiting to be completed

S3

  • BucketSizeBytes: The total size of all objects in the Amazon S3 bucket

  • NumberOfObjects: The total number of objects in the Amazon S3 bucket

  • AllRequests: The total number of requests made to the Amazon S3 bucket

  • GetRequests: The number of successful GET requests made to the Amazon S3 bucket

  • PutRequests: The number of successful PUT requests made to the Amazon S3 bucket.

EFS

  • StorageBytes: The total storage used by the Amazon EFS file system

  • PercentIOLimit: The percentage of the throughput limit that the file system is using

  • TotalIOBytes: The total number of bytes read from and written to the file system

FSx

  • DataReadBytes: The total number of bytes read from the file system

  • DataWriteBytes: The total number of bytes written to the file system

  • ThroughputCapacity: The total throughput capacity of the file system

  • PercentThroughputCapacityUtilized: The percentage of the total throughput capacity that is being used

Scalability issues

Capacity issues with data destinations

  • lead to performance degradation

  • regular monitoring of the storage utilization and capacity planning : done in advance

  • seamlessly scale storage increasing or decreasing in size : S3, EFS, FSx

Latency issues, IOPs, and data transfer times

  • slow data transfer times significantly impact performance of storage systems and data ingestion

  • Network bottlenecks, undersized provisioned storage volumes, or using inefficient methods of ingestion

  • provisioned IOPS volumes for Amazon EBS

  • compression or batching lead to improved data-transfer efficiency

Uneven distribution of data access

  • Hotspots or bottlenecks by uneven distribution of data access resulting in performance degradation or data availability issues

  • automatically distribute data and provide load balancing capabilities : S3, EFS

  • Data partitioning : distributes data across multiple storage resources, reducing the likelihood of hotspots

Ingestion modifications

Batching with Amazon Kinesis

  • improves efficiency and throughput

  • combines multiple data records into fewer API calls and network roundtrips

  • helpful for combining high data volumes at peak times

  • minimizes cost and latency when ingesting high throughput on Kinesis

Compressing data during transfer

  • cuts bandwidth use and speeds up data movement

  • compression’s transfer optimization and CPU costs → balance

Data partitioning with Amazon Kinesis

  • partition streaming data based on keys

  • partitioned data is then delivered to matching Amazon S3 bucket prefixes based on the keys

  • streams data in parallel to multiple locations
