DNS

  • Domain Name System or Domain Name Server : Internet standard name system 이며 worldwide급의 대형 분산 데이터 베이스로 볼 수 있음

  • 인터넷에서 사용되는 이름 (DNS host name)에 해당하는 IP 주소를 확인. DNS host name은 고유하고 절대적으로 지정된 이름으로 host name과 domain name으로 구성

  • DNS client가 DNS server를 질의해 데이터를 검색하는 client-server system

  • DNS client : resolver (해석기)

    • 클라이언트의 질의에 대한 응답을

    • DNS server의 분산 데이터베이스에 특정 index(색인) 정보를 요청하고

    • DNS server의 응답을 해석하고 적절한 형태로 변경하여 클라이언트에게 전달

    • /etc.resolv.conf

      • 여러개의 지시자로 존재

      • Domain, Search, Nameserver, Sortlist indicator + Options

  • DNS server : name server

  • Web Brower (client) → DNS resolver → DNS server

Domain Name & NameSpace

Domain Name

  • DNS 분산 DB에 대한 index

  • email (cricket@foo.example) → foo.example

  • URL (http://www.bar.example/test) → www.bar.example

NameSpace

  • Domain Name은 DNS NameSpace의 node를 표시

  • Inverse tree → root node가 상단에 존재

  • 각 node는 임의 수의 자식 node를 가질 수 있고

Resource Record

💡

DNS의 데이터는 어디에 존재 하는가?

  • DNS 데이터를 저장하는 단위 : resource record

  • 다양한 Class와 Type 으로 제공

  • 데이터가 저장된 table의 하나의 row가 Record (RDATA)가 되며 저장되는 Type에 따라 record type으로 구분

IN class resource record type

  • A record : IPv4 address

  • AAAA record : IPv6 address

  • CNAME (Canonical NAME) : Domain name을 다른 domain name으로 매핑 (alias mapping)

  • MX (Mail eXchanger) : e-mail 대상에 대한 mail server (mail exchanger) 이름 지정

  • NS (Name Server) : 영역에 대한 DNS server 이름 (영역을 풀이-resolve 할 수 있는 DNS server 목록)

  • PTR (Pointer) : IP 주소를 domain name에 다시 매핑

  • SOA (Start Of Authority) : 권한 시작 정보로 영역에 대한 매개 변수 제공

DNS server authority

Query response

  • Priamry DNS server : 영역 데이터 파일에서 영역에 대한 정보를 load 하는 서버

Query to another DNS server

  • Secondary DNS server : 영역 전송 (transfer) 메커니즘으로 다른 DNS 서버의 영역 데이터를 load 하는 서버

    • 주기적으로 Primary DNS server에 새 버전의 영역을 전송 → Primary DNS가 disk의 데이터를 업데이트

Resolver (해석기)

  • Application의 Domain name에 대한 정보를 요청하고 DNS query로 변환

  • Query를 DNS server로 전송하고 응답을 대기

  • 시간내에 지정된 query에 대한 응답을 받지 못하면 query를 동일 혹은 다른 DNS server로 전송 혹은 질의

Resolution (해석)

  • DNS의 분산 DB에 저장된 resource record를 찾는 프로세스

  • DNS namespace의 맨 위에서 아래로 진행

  • DNS server는 시작할 위치를 지시하는 ‘hint’가 필요 → NS record (Root 영역 권한이 있는 DNS server domain name)

Query

  • Recursive Query (재귀 질의)

    • Primary DNS server에서 시작해 응답을 받을 때까지 조회 하는 것

  • Iterative Query (반복 질의)

Caching

  • Local(host) → DNS cache table → DNS server

  • www.google.co 해석 → Root DNS server 혹은 com DNS server query를 건너뛰고 진행하여 시간을 단축

    • com 권한이 있는 DNS 서버 domain name 및 IP 주소 해석

    • google.com 권한이 있는 DNS 서버 domain name 및 IP 주소 해석

    • www.google.com의 IPv6 주소 해석

What is Amazon DNS Server?

https://docs.aws.amazon.com/ko_kr/vpc/latest/userguide/vpc-dns.html#AmazonDNS

💡

Amazon Route53 Resolver server : Amazon이 customer의 VPC를 위해 공급하는 DNS server 이다

DNS Server Provision

DHCP 기본 option set

💡

domain-name-servers=AmazonProvidedDNS

  1. 기본 option set에 저장된 network 구성을 사용하여

  2. Amazon DNS server에 도달

  3. VPC router를 통해 network의 다른 Device에 연결

  4. Amazon DHCP server와 상호 작용하여 IP 주소 임대 및 추가 network 구성 가능

DHCP 사용자 option set

💡

domain-name= domain-name-for-your-region

  • Amazon DNS server 대신 자체 DNS server를 사용하려면 VPC에 대해 새로운 DHCP option set를 생성 해야 한다

  • NTP Server

  • NetBIOS name server : Windows instance

  • NetBIOS node type

AmazonProvidedDNS

  • Amazon Route 53 Resolver 서버 → VPC internet gateway를 통해 통신할 필요가 있는 instance의 DNS를 활성화

  • Amazon DNS server는 특정 subnet 혹은 AZ에 상주하지 않음

  • 169.254.169.253에서 실행되는 DNS 서버에 매핑 : VPC IPv4 network range + 2로 reserve된 IP address (10.0.0.0/16 network → 10.0.0.2)

Rule and Consideration

  • NACL 혹은 SG로 DNS server의 in, out traffic을 필터링 할 수 없음

  • Recursive DNS query만 지원

Private DNS name

💡

instance 시작 시 private IPv4 주소와 이 주소에 해당하는 private DNS hostname을 항상 수신

  • 동일 VPC에 있는 instance간 통신을 위해 사용

  • 동일 Region에 있지만 다른 VPC에 있는 instance : RFC1918에 정의된 private 주소 공간에 있는 경우 해석(resolve) 가능 (10/8, 172.16/12. 192.168/16)

Public(External) DNS name

💡

instance에 public IPv4 주소가 있는 경우 VPC DNS attribute의 public DNS hostname 수신 여부를 결정

  • Instance의 network 외부에 있는 경우 : public IPv4 주소로 해석

    • ec2-public-ipv4-address.region.compute.amazonaws.com

  • Instance와 동일 network에 있는 경우 : private IPv4 주소로 해석

    • ec2-public-ipv4-address.compute-1.amazonaws.com

VPC DNS attribute

enableDnsHostnames

  • Default : false

  • public IPv4가 있는 instance에 public DNS hostname을 할당 하도록 지원

  • enableDnsSupport와 함께 true 인 경우 public DNS hostname을 가져옴 → Amazon Route53 Resolver 서버에서 제공한 Amazon provided private DNS hostname을 resolve

enableDnsSupport

  • Default : true

  • Amazon provided DNS에 대한 query 성공 → AmazonProvidedDNS를 통해 DNS resolution

Private Hosted Zone

  • 사용자 지정 DNS domain name으로 VPC 리소스 액세스 → Private Hosted Zone을 생성

  • 인터넷에 리소스를 노출하지 않고 VPC내의 domain 및 sub-domain의 traffic을 routing 정보를 저장하는 container → Route53에 resource record set을 생성

  • VPC내 에서 instance가 연결 되어야 함 → instance SG에서 ICMP inbound traffic이 혀용 되어야 함

  • enableDnsHostnames아 enableDnsSupport attribute → true
