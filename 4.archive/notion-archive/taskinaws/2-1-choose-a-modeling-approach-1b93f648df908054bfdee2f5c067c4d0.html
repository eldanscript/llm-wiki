2.1 Choose a Modeling Approach

Introduction

  • 첫 번째 과정: AWS의 기계 학습 스택 소개

    • AWS AI 서비스와 Amazon SageMaker, Amazon Bedrock의 사전 구축된 ML 솔루션 탐구

    • 맞춤형 ML 모델 구축을 위한 프레임워크와 인프라 학습

    • 일반적인 비즈니스 문제에 적합한 ML 모델 및 알고리즘 선택 전략 탐구

    • 모델 및 알고리즘 선택에 있어 해석 가능성과 비용의 중요성 학습

  • 두 번째 과정: 모델 학습 프로세스의 핵심 구성 요소

    • 학습 및 추론을 위한 적절한 컴퓨팅 환경 선택 방법 학습

    • SageMaker의 사전 구축된 컨테이너와 Docker 이미지, 지원 프레임워크를 이용한 학습 작업 생성 방법 학습

    • 효율적인 학습 프로세스를 위한 학습 시간 단축 방법 탐구

  • 세 번째 과정: ML 모델 개선

    • 편향 완화, 과적합 및 과소적합 방지 방법 리뷰

    • 모델 조합과 하이퍼파라미터 튜닝을 통한 모델 성능 향상 방법 학습

    • SageMaker를 이용한 반복적 모델 가지치기를 통한 모델 크기 감소 방법 학습

    • 사전 학습된 모델의 fine-tuning 및 SageMaker 모델 레지스트리를 통한 모델 버전 관리 학습

  • 네 번째 과정: 모델 성능 분석

    • 분류 및 회귀 문제에 대한 주요 평가 지표 학습

    • 모델 수렴 문제 식별 방법 학습

    • Amazon SageMaker Clarify와 Amazon SageMaker Debugger를 통한 학습 데이터와 모델 문제 인사이트 확보 방법 학습

Amazon SageMaker Built-in Algorithm

Amazon SageMaker

  1. 통합 및 엔드-투-엔드 ML 환경:

    • 데이터 준비, 모델 빌드/학습/배포/모니터링 등 ML 생애주기 전반을 하나의 장소에서 수행할 수 있습니다.

    • 선호하는 IDE(JupyterLab, RStudio, Visual Studio Code 기반 Code Editor)를 사용할 수 있습니다.

  2. 팀 협업 지원:

    • 데이터 과학자, ML 엔지니어, 비즈니스 애널리스트 등 팀원들 간 협업이 가능한 공유 공간을 제공합니다.

  3. ML 프로세스 자동화:

    • MLOps 도구를 통해 모델 배포 및 모니터링의 일관성과 효율성을 높일 수 있습니다.

  4. 400개 이상의 사전 구축 모델 제공:

    • Amazon SageMaker JumpStart를 통해 널리 사용되는 사전 학습된 기반 모델(Foundation Model)을 활용할 수 있습니다.

  5. 비용 관리 기능:

    • 팀, 사용자, 프로젝트별로 자동 태깅을 통해 ML 프로세스 전반의 비용을 관리할 수 있습니다.

SageMaker Studio

Benefits

  • ML 전용으로 설계된 최초의 완전히 통합된 개발 환경(IDE)

  1. 웹 기반 시각적 인터페이스

    1. 데이터 준비, 모델 구축/학습/배포 등 ML 개발 전 과정을 수행

  2. ML 기능이 통합된 단일 환경

    1. 맞춤 통합 코드 작성 시간을 줄이고 비용을 절감

  3. 목적 지향적으로 설계된 도구들

    1. 라벨링, 데이터 준비, 피처 엔지니어링, 편향 탐지, AutoML, 학습, 튜닝, 호스팅, 설명 가능성, 모니터링, 워크플로 등 ML 개발의 모든 단계를 단일 환경에서 수행

  4. 하나의 환경에서 다양한 작업 수행 가능

    1. 빠르게 단계 간 이동하며 변경 사항을 관찰하고 반복할 수 있어 고품질 ML 애플리케이션의 출시 시간을 단축

  5. 데이터 분석 및 시각화 기능 제공

    1. RStudio에서 R 언어로 데이터 분석 및 시각화를 수행할 수 있는 완전 관리형 클라우드 환경을 제공

Roles and personas

  • 다양한 역할과 persona의 ML 팀 구성원들이 활용할 수 있는 협업 도구

    • 데이터 엔지니어: Amazon EMR과 AWS Glue의 대화형 세션 기능을 활용하여 데이터 준비 가능

    • 데이터 과학자: 프로세싱 및 학습 작업을 직접 SageMaker Studio에서 생성할 수 있음

    • ML 엔지니어: 프로덕션 모델 관리 및 모니터링을 SageMaker Studio에서 직접 수행할 수 있어 생산성이 향상됨

IDE choice

  1. JupyterLab 통합:

    • 노트북, 코드, 데이터를 위한 완전 관리형 JupyterLab 환경을 빠르게 실행할 수 있습니다.

  2. Code Editor (Visual Studio Code - Open Source 기반):

    • 익숙한 단축키, 터미널, 디버거, 리팩토링 도구 등을 갖춘 가벼운 강력한 코드 편집기를 제공합니다.

    • 개발자 생산성을 크게 향상시킵니다.

  3. R 전용 IDE 통합:

    • 완전 관리형 RStudio 환경을 제공하여 R 개발을 지원합니다.

    • R과 Python 개발을 위해 다른 IDE 간 원활하게 전환할 수 있습니다.

SageMaker notebook instances

  1. SageMaker Studio와 SageMaker Studio Classic은 Jupyter Notebook을 통해 SageMaker와 상호작용할 수 있는 ML 환경입니다.

  2. Jupyter Notebook은 데이터 시각화, 코드 작성 및 보고서 생성 등의 기능을 제공하는 도구입니다.

  3. Notebook에는 TensorFlow, PyTorch, MXNet 등 다양한 ML 프레임워크가 지원됩니다.

  4. SageMaker Notebook Instance는 Jupyter Notebook 애플리케이션이 실행되는 관리형 Amazon EC2 인스턴스입니다.

  5. SageMaker는 데이터 처리, 모델 학습, 배포, 테스트 등 ML 작업을 Notebook Instance에서 수행할 수 있는 환경을 제공합니다.

  6. SageMaker는 샘플 Notebook을 제공하여 ML 태스크 수행 방법을 학습할 수 있습니다.

  7. Notebook Instance는 다양한 라이브러리와 도구를 사전에 구성하여 제공합니다.

  8. SageMaker는 워크로드 유형별로 적합한 인스턴스 유형을 제안합니다.

  9. Notebook에서 데이터 시각화 도구를 활용하여 데이터 패턴과 인사이트를 발견할 수 있습니다.

Model Selection

Algorithm options

  1. SageMaker의 내장 알고리즘 사용

  2. 지원되는 프레임워크로 스크립트 작성

  3. AWS Marketplace에서 구독한 알고리즘 선택

  4. 사용자 고유의 알고리즘 도입

Model Selection

  1. 문제 유형 파악: 분류, 회귀, 클러스터링, 추천 시스템 등 문제 유형에 따라 적합한 알고리즘 선택이 필요합니다.

  2. 데이터 특성 분석: 데이터 크기, 차원, 노이즈, 편향 등을 파악하여 모델 아키텍처와 알고리즘을 선택합니다.

  3. 성능 목표 고려: 정확도, 정밀도, 재현율, F1 스코어 등 원하는 성능 지표를 염두에 두고 적절한 모델을 선택합니다.

  4. 자원 및 시간 제약 고려: 학습에 필요한 CPU, GPU, 메모리 등 가용 자원과 시간 제약을 감안합니다.

  5. 해석 가능성 필요 여부 (Interpretability): 복잡도가 낮은 선형 또는 트리 기반 모델을 선택할 수 있습니다.

  6. 모델 복잡도와 일반화 성능의 균형: 과도한 복잡도는 과적합을 야기할 수 있으므로 적절한 균형을 모색합니다.

  7. 확장성 고려 (Scalability): 향후 데이터와 복잡도 증가에 잘 대응할 수 있는 모델을 선택합니다.

  8. 도메인 전문성 활용: 문제 영역에 적합한 모델 선택을 위해 관련 전문가의 의견을 참고합니다.

Model types

  1. 분류 모델: 데이터를 여러 클래스로 구분하는 모델

  2. 회귀 모델: 연속적인 값을 예측하는 모델

  3. 클러스터링 모델: 데이터를 유사한 그룹으로 구분하는 모델

  4. 추천 시스템: 사용자에게 선호할만한 항목을 추천하는 모델

  5. 시계열 모델: 시간에 따른 데이터 패턴을 모델링하는 모델

  6. 자연언어처리 모델: 텍스트 데이터를 다루는 모델

  7. 컴퓨터 비전 모델: 이미지/비디오 데이터를 다루는 모델

  1. 선형 모델(선형 회귀, 로지스틱 회귀, 선형 SVM):

    • 빠른 학습 및 해석 가능성, 하지만 유연성이 낮음

  2. 트리 기반 모델(부스팅 트리, 랜덤 포레스트, 결정 트리):

    • 선형 모델보다 정확성이 높고 학습 시간이 조금 더 소요

    • 신경망보다 유연성과 해석 가능성이 높음

  3. 신경망 모델(다층 퍼셉트론, 합성곱 신경망):

    • 복잡한 비선형 관계 모델링에 유용

    • 대량의 데이터 필요, 학습이 느리고 해석이 어려움

  4. 클러스터링 모델(K-means, DBSCAN):

    • 데이터 탐색적 분석에 유용

  5. 차원 축소 및 특징 학습 모델 (Matrix factorization):

    • PCA 등을 활용한 추천 시스템, 차원 축소, 특징 학습

  6. 시계열 모델(ARIMA):

    • 과거 데이터 기반 미래 값 예측

  7. 컴퓨터 비전 모델:

    • 객체 탐지, 의미 분할 등 이미지/비디오 작업에 특화

  8. 시퀀스 모델(LSTM 등):

    • 텍스트, 시계열, 오디오 등 순차 데이터 모델링

Built-in algorithm

지도학습 알고리즘:

  • 선형 학습기 (Linear Learner): 이진 분류, 회귀

  • XGBoost: 이진/다중 분류, 회귀

  • K-최근접 이웃(K-NN): 다중 분류, 회귀

  • 요인 분해 기계 (Factorization Machines): 이진/다중 분류, 회귀

비지도학습 알고리즘:

  • K-Means: 클러스터링

  • 잠재 디리클레 할당(LDA): 토픽 모델링

    • 문서 집합 내의 토픽을 결정하기 위한 알고리즘

    • 비지도학습 알고리즘으로, 학습 시 정답이 포함된 예제 데이터를 사용하지 않음

    • 클러스터링 및 토픽 모델링에 활용

    즉, LDA는 문서 집합에서 토픽을 추출하는 비지도학습 알고리즘으로, 클러스터링과 토픽 모델링 등의 용도로 사용됩니다.

  • 랜덤 컷 포레스트(RCF): 이상치 탐지

  • 주성분 분석(PCA): 차원 축소

  • IP Insights

  • Object2Vec

    • 고차원 객체의 저차원 밀집 임베딩을 학습하여 특징 엔지니어링을 수행하는 다목적 알고리즘

    • 학습 효율을 높이기 위해 레이블이 지정된 데이터를 필요로 하는 지도학습 알고리즘

    • 그러나 데이터의 자연스러운 클러스터링을 통해 관계 레이블을 얻을 수 있는 경우 비지도학습으로도 활용 가능

    • 임베딩 생성을 위한 주요 활용 시나리오

    따라서 Object2Vec은 지도학습 알고리즘이지만, 특정 상황에서는 데이터의 클러스터링을 활용하여 비지도학습으로도 사용할 수 있음을 알 수 있습니다.

텍스트/음성 알고리즘:

  • BlazingText: 텍스트 분류, 임베딩, 언어 모델링

    • Word2Vec 및 텍스트 분류 알고리즘의 최적화된 구현

    • 대용량 데이터셋에 스케일링이 가능

    • 다양한 자연어 처리(NLP) 태스크에 활용 가능

    • 주요 활용 분야:

      • 텍스트 분류

      • Word2Vec

    즉, BlazingText는 Word2Vec과 텍스트 분류 기능을 최적화하여 대규모 데이터에도 효과적으로 적용할 수 있는 알고리즘입니다. 다양한 NLP 태스크에 활용될 수 있습니다.

  • Sequence-to-Sequence: 언어 번역, 요약, 전사

    • 주로 신경망 기반 기계 번역에 사용되는 지도학습 알고리즘

    • 텍스트 또는 음성 데이터의 기계 번역에 활용

    • 자세한 내용은 Sequence-to-Sequence 알고리즘 문서 참조

    즉, Sequence-to-Sequence 알고리즘은 텍스트 및 음성 데이터의 기계 번역 태스크에서 널리 사용되는 지도학습 알고리즘입니다.

  • 신경망 토픽 모델(NTM): 텍스트 데이터 토픽 모델링

    • 신경망 기반 접근 방식을 사용하는 비지도학습 기술

    • 문서 집합의 토픽 모델링에 활용

    즉, NTM 알고리즘은 문서 집합에서 토픽을 추출하는 또 다른 비지도학습 기법으로, 신경망 모델을 활용한다는 점이 특징입니다.

컴퓨터 비전 및 시계열 알고리즘:

  • ResNet

    • This is a deep learning network developed to be highly accurate for image classification.

    • Uses: Image classification

  • SSD (Single Shot multibox Detector)

    • 분류 태스크용으로 사전 학습된 CNN 모델을 기반으로 함

    • VGG-16, ResNet-50 등 다양한 CNN 모델을 지원

    • 객체 탐지 태스크에 활용

    즉, SageMaker에서는 분류 문제에 대해 사전 학습된 CNN 모델을 활용하여 객체 탐지 기능을 제공합니다.

  • 의미 분할 (Semantic Segmentation): 이미지/비디오 분류, 객체 탐지, 분할

    • 컴퓨터 비전 애플리케이션 개발을 위한 세밀한 픽셀 단위 접근법

    • 장면 이해를 위한 기반이 되는 핵심 기술

    • 자율 주행 차량, 의료 영상 진단, 로봇 센싱 등 다양한 컴퓨터 비전 애플리케이션에 중요

    • MXNet Gluon 프레임워크와 Gluon CV 툴킷을 사용하여 구현

따라서 Amazon Bedrock은 대화형 인터페이스와 API를 통해 다양한 기반 모델을 활용할 수 있으며, 사용자 맞춤형 모델 가져오기 기능도 제공합니다.

Typical Use Cases

  1. 텍스트 생성:

    • 단편 소설, 에세이, 소셜 미디어 게시물, 웹페이지 콘텐츠 등의 새로운 원본 콘텐츠 생성

  2. 챗봇:

    • 고객 경험 향상을 위한 대화형 인터페이스, 가상 비서 구축

    • 사용자 요청 이해, 작업 분해, 대화를 통한 정보 수집, 요청 이행 등 수행

  3. 검색:

    • 대량의 텍스트 및 이미지 데이터로부터 관련 정보 검색 및 종합

  4. 텍스트 요약:

    • 기사, 보고서, 연구 논문, 기술 문서, 도서 등의 장문 문서 요약

  5. 이미지 생성:

    • 광고, 웹사이트, 프레젠테이션 등을 위한 언어 프롬프트 기반 사실적이고 시각적으로 매력적인 이미지 생성

  6. 개인화:

    • 단어 일치 기반 추천보다 더 관련성 있고 상황 인지적인 제품 추천

따라서 Amazon Bedrock은 텍스트 및 이미지 생성, 대화형 인터페이스, 검색, 요약, 개인화 등 다양한 생성형 AI 사용 사례에 활용할 수 있습니다.

Model Selection Considerations

How to consider interpretability during model or algorithm selection

  1. 투명성과 설명 가능성:

    • 의사결정 트리, 규칙 기반 모델, 선형 회귀 등 일부 알고리즘은 더 해석 가능성이 높음

    • 입력 요소와 출력 간 관계를 명확히 이해할 수 있어 개발자가 결정을 설명하기 용이함

  2. 도메인 지식과 모델 복잡성:

    • 의료 진단, 대출 승인 등의 도메인에서는 모델 복잡성보다 해석 가능성이 중요할 수 있음

    • 성능 손실을 감수하더라도 해석 가능한 모델을 선호할 수 있음

  3. 규제 및 법적 요구사항:

    • 일부 산업 및 지역에서는 모델의 투명성과 설명 가능성을 요구하는 규정이 존재함

    • 공정 대출, 차별 방지 등을 위해 해석 가능한 모델이 필요할 수 있음

  4. 이해관계자 신뢰와 수용성:

    • 엔드 유저나 이해관계자가 불투명한 모델을 신뢰하지 못할 경우, 해석 가능한 모델이 필요함

    • 부작용이 큰 의사결정 상황에서 특히 중요함

따라서 모델 선택 시 이러한 해석 가능성 요인들을 고려하여 적절한 균형을 잡는 것이 중요합니다.

Interpretability and model performance

개발자는 다음과 같은 전략을 통해 모델 해석 가능성과 성능의 균형을 고려할 수 있습니다:

  1. 모델 복잡도 조정:

    • 복잡도가 높은 모델(예: 딥러닝)은 정확도가 높지만 해석이 어렵다.

    • 복잡도가 낮은 모델(예: 선형 모델)은 해석 가능성이 높지만 성능이 낮을 수 있다.

    • 문제와 상황에 맞게 적절한 복잡도의 모델을 선택한다.

  2. 하이브리드 모델 사용:

    • 복잡한 모델과 해석 가능한 모델을 결합하여 장점을 활용한다.

    • 복잡한 모델의 예측 결과를 해석 가능한 모델이 설명할 수 있게 한다.

  3. 사후 해석 방식 적용:

    • 미지의 블랙박스 모델을 사용하더라도 사후 해석 기법을 통해 설명 가능성을 높일 수 있다.

결국 모델 해석 가능성과 성능 간의 균형은 애플리케이션의 요구사항과 제약 조건에 따라 달라질 것입니다. 정확성, 공정성, 투명성, 이해관계자 수용성 등의 요소를 종합적으로 고려하여 최적의 모델을 선택해야 합니다.

  1. 해석 가능한 모델 근사화:

    • 복잡한 블랙박스 모델의 예측 결과를 모방하는 더 단순한 해석 가능한 모델을 학습시키는 방식

    • 증류(Distillation) 또는 모델 추출(Model Extraction) 기법을 활용할 수 있음

  2. 국소적 해석 가능성:

    • 전체 모델의 동작을 이해하기 어려운 경우에도, 특정 데이터 인스턴스나 부분 집합에 대한 예측 과정을 설명할 수 있는 방법

    • LIME(Local Interpretable Model-Agnostic Explanations), SHAP(SHapley Additive exPlanations) 등의 기술을 사용할 수 있음

  3. 모듈식 설계:

    • 복잡한 모델을 더 작고 해석 가능한 구성 요소로 분해하는 방식

    • 예를 들어 초기 단계에 해석 가능한 모델을 사용하고, 최종 예측은 복잡한 모델이 담당하게 함

  4. 앙상블 방식:

    • 의사결정 트리, 규칙 기반 모델 등 해석 가능한 개별 모델들을 조합하는 방식

    • 복잡한 단일 모델 수준의 성능을 달성하면서도 해석 가능성을 유지할 수 있음

이러한 다양한 전략들을 활용하여 모델 해석 가능성과 성능 간의 균형을 맞출 수 있습니다.

Selecting models or algorithms based on costs

  1. CPU vs GPU 선택:

    • CPU는 일반적으로 더 저렴하지만 계산 집약적인 작업에는 부적절

    • GPU는 성능이 뛰어나지만 비용이 높음

    • 프로젝트 요구사항에 따라 적절한 선택 필요

  2. 작업 유형에 따른 고려사항:

    • 구조화된 데이터 작업: 선형 모델, 의사결정 트리 등 CPU에 적합한 알고리즘 활용

    • 비구조화된 데이터 작업: 복잡한 신경망 모델이 필요하여 GPU 활용이 유리

  3. 클러스터 활용:

    • 대규모 작업을 위해 클러스터 활용이 필요할 수 있음

    • 온디맨드 인스턴스를 활용하여 수요에 맞게 탄력적으로 확장하는 것이 중요

  4. 비용 최적화 방안:

    • 모델/알고리즘 최적화, 전이 학습, 연합 학습 등의 기법 활용

    • 분산 컴퓨팅 자원의 필요성을 면밀히 검토

이와 같은 다각도의 접근을 통해 비용 효율적인 모델과 알고리즘을 선택할 수 있습니다. 이는 예산 최적화와 함께 고품질 솔루션 제공에도 도움이 될 것입니다.
