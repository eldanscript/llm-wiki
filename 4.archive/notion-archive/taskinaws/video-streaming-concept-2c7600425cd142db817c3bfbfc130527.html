Summary

Key Concept

  • Media Workflow

    • 수집 (시스템에 소스 콘텐츠 가져오기) → 처리 (쉽게 사용할 수 있도록 콘텐츠 조작하기) → 저장 (시청자 요청에 앞서 콘텐츠 저장 또는 캐싱) → 전송 (많은 동시 시청자에게 콘텐츠 배포)

  • Video 주요 속성

    • 해상도, Frame rate (속도), Bit rate (전송률)

  • Image 색상 정보 적용

    • Bit 심도, 색상 공간

  • Video Stream 압축

    • GOP (Group of Pictures) encoding

  • Multi screen 전송

    • ABR (Arbitrary bit rate - 가변 비트 전송률) streaming

    • JIT (Just-in-time) packaging

  • Ad insertion

    • Video 광고 삽입 및 교체

  • DRM (디지털 권한 관리)

  • Video file store

    • Contents 전송 network의 대역폭 효율적인 위치 저장

Video Streaming

VOD (Video on demand)

  • 대여 또는 소유

  • 서비스 구독, 일회성 지불, 구매

  • VOD video에 대한 시작, 중지, 일시 중지, 되감기, 빨리 감기 가능

Live Streaming

  • Live event 혹은 사전 녹화된 파일 전송

  • 시작 및 중지 시간이 정의

  • 시청자는 되감기 할 수 있지만 stream이 종료되면 access 안 됨

Technology

  • Video Stream 압축, 패키징 → 다양한 디바이스에서 재생

  • Video를 network bandwidth에 맞게 조정하고 모든 크기의 디바이스에서 최대한의 선명성 유지 필요

Workflow

  • From video source to screen

  • 소스 → 수집 → 처리 → 저장 → 전송 → 대상

수집 (Ingest)

  • raw video : live는 streaming type, VOD는 file type

  • CSP에 전송 : public internet, high-bandwidth IP network, dedicated network connection, satellite uplink

  • AWS related service

    • AWS Elemental Live

    • AWS Elemental Link

    • AWS Elemental MediaConnect

    • AWS Direct Connect, AWS Snowball, Amazon S3

처리 (Process)

  • video compression : file size reduction

  • 여러 해상도 stream으로 변환

  • 암호화를 통해 컨텐츠 보호

  • targeting된 광고 상입

  • AWS related service

    • AWS Elemental Live

    • AWS Elemental MediaLive

    • AWS Elemental MediaConnect

    • AWS Elemental MediaPackage

    • AWS Elemental MediaTailor

저장 (Store)

  • Live Stream : Cloud storage가 origin source of live streaming

  • VOD

    • Contents repository 및 archive

    • On-demand 단기 자산 archive

    • On-demand IP stream origin source

  • AWS related service

    • AWS Elemental MediaStore

    • AWS Elemental MediaPackage

    • Amazon S3

전송 (Deliver)

  • 많은 동시 시청자에게 콘텐츠 배포

  • 시청자 디바이스에 최대한 가깝게 이동 : CDN

  • AWS related service

    • AWS Elemental MediaConnect

    • Amazon CloudFront

Video Property

  • Video 품질 요소

Resolution (해상도)

  • 720x480 : SD (Standard Definition) TV

  • 1920x1080 : HD

  • 3840x2160 : UHD

Frame rate

  • Cinema : 24 fps

  • TV & Streaming Video : 50/25 fps (50Hz - EU), 60/30 fps (60Hz - USA)

Scan

Interlace

  • Even, Odd line (field) scan

Progressive

  • PAL : 625 scan line

  • NTSC : 525 scan line

Bit rate

  • high : small file size, low bandwidth

  • low : large file size, high bandwidth

Bit depth & Color channel

  • pixel당 할당된 정보의 양 (bit 수)

  • bit 심도가 크면 색상 pallete가 넓어지고

  • 음영 및 gradiation이 크면 이미지가 정확하고 세밀해 짐

Color space

  • 관찰 가능한 색상을 얼마나 정확하게 나타내는지 측정

  • CIE(국제조명위원회) color system

Video Compression

Compression/Encoding

  • 정보를 대체 형식으로 변환 → 인코더로 수행

Decoding

  • 인코딩된 비디오를 원본으로 변환 → 디코더로 수행

CoDec

  • Coding + Decoding

  • Digital Data Stream 혹은 Signal을 encoding 혹은 decoding

Transcoding

  • 인코딩된 정보를 다른 형식이나 유형으로 변환

Bandwidth

  • 비 압축 비디오 신호의 크기

Compression

  • Raw video data를 network를 통해 효율적으로 저장 또는 streaming 하기 위함

  • 인간의 눈으로 감지하지 못하는 detail을 제거 → 일부 색상 데이터를 제거

  • 인간의 눈은 색상 보다는 명암 수준에 민감

  • Gradient의 미묘한 변화는 민감

  • 복잡한 부분의 작은 차이는 감지 못함

Codec & Container

Codec

  • 무손실 코덱

    • 비디오 편집 및 비디오 효과에 사용

    • 비압축 비디오 충실도를 유지하며 파일 크기를 줄임

  • 손실 코덱

    • 원본 파일에서 가능한 많은 시각적 정보를 줄임

    • 이미지를 최대한 원본과 가깝게 보이도록 유지

    • Smart TV 및 개인용 디바이스에서 시청하는 streaming video file

Standard

  • VCEG : ITU-T Video Coding Experts Group

    • H.262

    • H.264

    • **H.265**

  • MPEG : Motion Picture Experts Group

    • MPEG-2

    • MPEG-4 : AVC

    • **MPEG-H : HEVC**

Container

  • 저장, 이동, 재생할 수 있는 형태로 압축된 비디오를 전달

  • Image, Audio, Capture, MetaData

  • 한 가지 유형 코덱 혹은 여러 유형의 코덱을 포함

  • container file extension : .mov, .mpg, .ts

  • MPEG 전송 stream (ts)

    • 여러 개의 video, audio codec 포함

GOP encoding

  • 인터넷에서 비디오를 실현 가능하게 만든 압축 기술

  • 디지털 이미지를 압축 : JPEG

  • Motion JPEG

    • 카메라는 일련의 정지 이미지를 캡처하고 JPEG 알고리즘을 각 프레임에 하나씩 적용

    • 최초 비디오 압축 기법

    • Video sequence의 frame 간 중복 고려 안됨 → temporal redundancy

  • MPEG codec

    • Inter-frame 압축 기법

    • 첫 번째 frame에 intra frame 알고리즘 적용 → I-frame 생성

    • frame간 이미지 부분 이동 추적하는 motion vector 사용 → 후속 frame의 차이 분석 → 새로운 frame은 예측 frame 혹은 P-frame으로 압축

    • frame 앞뒤 모두 보이는 방식 압축 : 양방향 압축

  • Bit 사용량

    • I-frame > P-frame > B-frame

  • GOP는 I-frame 부터 다음 I-frame의 마지막 frame 까지 실행

  • PTS (Presenation timestamp)

  • DTS (Decoding timestamp

Frame 계층 구조

  • Macro Block : 슬라이스를 구성

  • Pixel Block : 이미지에서 제어 가능한 가장 작은 요소

  • Macro Block : 슬라이스를 구성

Bit rate - 속도 제어 모드

  • 고 품질 이미지 → high bit rate

  • 속도 제어 모드

    • 인코더가 video frame당 사용 가능한 대역폭을 배포하는 방법을 결정

  • CBR (Constant Bit Rate)

    • 토크쇼 패널 그룹 등의 이미지 복잡성이 일정하게 유지 될 경우

  • VBR (Variable Bitrate Control)

    • 스포츠 방송, 액션 영화와 같은 비디오 복잡성이 변경될 대 자주 사용

    • 비디오 지속 시간 동안 비트 전송률 변경

      • 콘텐츠의 복잡한 부분은 많은 비트를 사용

      • 단순하고 정적인 장면은 적은 비트를 사용

  • QVBR (Quality-Defined Variable Bitrate Control)

    • 품질 기반 가변 비트 전송률

    • 비디오 소스의 모든 매크로 블록, 프레임 및 장면을 분석 후 정보 차이를 해결하기 위해 비트를 자동으로 할당

    • 낭비되는 비트 최소화 video bitrate 조정하여 일관된 video 품질 유지

Multi-screen Delivery

ABR Streaming

  • 비디오가 압축된 후에는 시청자 배포 단계에 사용할 준비가 됨

  • 인터넷을 통한 비디오 전송은 다양하고 불안정한 네트워크 속도를 해결하는 것

Packaging

  • 인코더는 다양한 비트 전송률의 stream 집합을 생성

  • 네트워크 연결 강도에 따라 적합한 비트 전송률 선택

  • 패키징

    • 여러 비트 전송률 스트림을 보기 위해 준비하는 프로세스

    • 디바이스에서 재생할 수 있도록 압축된 비디오 스트림을 포맷

  • 인코딩 vs 패키징

    • 인코딩 : 비디오 및 오디오를 트랜스코딩하고 압축하는 알고리즘을 적용 → transcoding된 stream 생성

    • 패키징 : 압축된 스트림을 가져와 분할하고 매니페스트라는 작은 파일을 통해 표현 → video 및 audio 데이터 조작 X

  • Origin 서버 : 스트림 시작 서버

ABR (Adaptive Bitrate - 가변 비트 전송률) Stream

  • 원본 소스가 여러 개의 작은 비트 전송률 버전으로 압축되면 매니페스트라는 다른 파일이 생성

  • 매니페스트는 특정 소스의 모든 버전 목록을 의미

  • 압축된 스트림은 실제로 단일 단위가 아니라 몇 초 길이의 세그먼트

  • 분할은 네트워크 전송 및 재생을 위해 비디오를 작은 부분으로 나누는 것이며 소비 디바이스가 분할 지점에서 비트 전송률을 전환

  • 소비 디바이스가 매니페스트 사본을 요청하고 몇 초마다 업데이트를 요청

  • 연결이 약한 경우 가장 작은 비트 전송률 세그먼트를 요청

  • 연결이 더 강한 경우에는 더 높은 비트 전송률 세그먼트를 요청

  • 매니페스트는 소비 디바이스의 유형, 광고 위치, 캡션, 언어 트랙 옵션과 같은 다른 정보를 포함

JIT Packaging

  • OTT 전송의 또 다른 당면 과제는 스토리지 → 미디어 세그먼트를 여러 형식으로 패키징

  • 패키징된 압축 스트림 집합은 보기 위해 저장될 때 디스크 공간을 차지 → 수천 개의 이벤트와 많은 수의 디바이스에 맞게 크기가 조정될 때 여러 패키지를 저장하면 불필요한 비용이 발생

Just-in-time pacakging

  • 압축된 스트림은 인코더에 의해 압축되지 않은 상태로 원본 서버로 전송 → 미디어 집합은 디스크에 저장

  • 최종 사용자가 세그먼트를 요청하면 요청을 하는 디바이스에 따라 세그먼트가 패키징 → 수많은 다른 패키지에 대한 요청에도 불구하고 하나의 실제 미디어 집합만 디스크에 저장

ABR + JIT Packaging

  • 인코더는 MPEG 전송 스트림으로 여러 비트 전송률 스트림을 전달 → 스트림은 세그먼트로 저장

  • 시청자가 콘텐츠를 요청하면 원본 및 패키징 서비스는 플레이어와 호환되는 형식으로 스트림을 패키징

Adaptive Streaming Format

Apple HTTP Live Streaming (HLS)

  • iOS 및 Android 디바이스를 포함하여 인터넷 스트리밍에 널리 사용

MPEG Dynamic Adaptive Streaming over HTTP (DASH)

  • 디지털 권한 관리를 위한 매니페스트 및 공통 암호화의 새로운 혁신을 제공

Common Media Application Format (CMAF)

  • HLS와 MPEG-DASH를 결합하여 인터넷 스트리밍을 단순화하고 간소화하기 위해 개발

Microsoft Smooth Streaming (MSS)

Adobe HTTP Adaptive Streaming (HDS)

  • 레거시 워크플로에서 여전히 사용

Streaming Protocol 비교

Ad insertion

  • 콘텐츠 공급자는 인코더로 전달된 후 최종적으로 시청자에게 전달되는 스트림에 광고를 삽입

  • 고도로 타겟팅된 광고는 지리적 위치 및 구독 자 프로필 정보를 기반으로 프로그램 스트림에 삽입

SCTE-35

  • SCTE : 케이블 통신 기술자 협회

  • 인코더는 SCTE-35 마커를 그대로 전달하도록 구성 또는

  • 인코더가 생성하는 출력 매니페스트를 수정(데코레이션)하는 데 사용하도록 구성

  • 원본 및 패키징 서비스가 데코레이션된 매니페스트 내에서 이러한 SCTE-35 메시지를 사용하여 광고 교체 또는 광고 제거를 시작

Client-side insertion

  • 비디오 플레이어(시청자 디바이스)가 원본 SCTE 마커로 패키지 생성기에서 스트림을 수신

  • 비디오 플레이어가 SCTE 마커를 사용하여 프로그램에서 광고로 전환한 다음 프로그램으로 다시 전환

  • 광고가 시작되고 종료되는 지점이 쉽게 감지되기 때문에 광고 차단기에 매우 취약

Server-side insertion

  • 원본 서버가 SCTE 마커를 사용하여 광고를 프로그램 스트림에 연결

  • 플레이어(시청자 디바이스)가 지속적인 콘텐츠 스트림을 수신하고 한 소스에서 다른 소스로 전환하지 않음

DRM

  • Media에 대한 access를 관리

  • 누가 언제 무엇을 볼 수 있는지 관리하는 것이 주요 관심사

암호화

  • 데이터 스크램블링 및 모호화

  • 고유 키를 기반으로 암호화 → 암호를 해독 하려면 키가 필요

인증 및 권한 부여

  • 키 관리 및 보호

  • 인증, 권한 부여

DRM Process

  • 콘텐츠 배포자/소유자

  • 플레이어

  • 키 공급자

  • 암호화 도구

CDN

  • Contents Delivery Network

  • 시청자에게 최대한 가까우면서 네트워크에서 가장 대역폭 효율이 높은 위치에 비디오 파일을 복제하여 저장

Hub and Spoke network

  • 서버 네트워크를 통해 전파되어 소비자에게 가깝게 미디어를 스테이징

POP (상호 접속 위치)

  • CDN에는 리전 전체에 여러 개의 엣지 로케이션 또는 상호 접속 위치(POP)가 있습니다. 대규모 콘텐츠 게시자는 여러 CDN을 사용하는 경우가 많습니다. 각 CDN은 서로 다른 리전에 상호 접속 위치(POP)가 있을 수 있고 기본 CDN에 네트워크 문제가 발생할 경우 백업이 가능하기 때문입니다.

Summary

인터넷을 통한 비디오 스트리밍

비디오를 인터넷(**OTT(over-the-top)**라고도 함)을 통해 라이브 스트림 또는 비디오 온디맨드(VOD)로 스트리밍하려면 다양한 디바이스에서 재생할 비디오 스트림을 압축하고 패키징하고 전송하는 복잡한 기술 프로세스가 필요합니다.

4가지 기본 단계

라이브 또는 온디맨드 등 거의 모든 비디오 워크플로에 공통적으로 사용되는 4가지 기본 단계가 있습니다.

  • 수집 - 시스템에 소스 콘텐츠 가져오기

  • 처리 - 쉽게 사용할 수 있도록 콘텐츠 조작하기

  • 저장 - 시청자 요청에 앞서 콘텐츠 저장 또는 캐싱

  • 전송 - 많은 동시 시청자에게 콘텐츠 배포

이미지 품질 및 크기에 영향을 주는 주요 비디오 속성

이미지 해상도는 이미지의 선명도와 명확도에서 중요한 요소입니다. 프레임 속도는 모션의 부드러움에 영향을 주고 비트 전송률은 스트림 크기와 인터넷을 통해 전송하는 데 필요한 대역폭에 영향을 줍 니다.

색상 정보는 픽셀 수준의 이미지에 적용되며 비트로 저장됩니다. 주어진 픽셀에 할당된 정보의 비트  수(비트 심도라고 함)가 많을수록 색상 표시가 더 정확해집니다.

압축을 통해 비디오를 효율적으로 전송 및 저장

비디오 압축은 인간의 눈으로 감지하지 못하는 것들을 제거하여 비디오 파일의 크기를 줄이기 위해 작동합니다. 이는 소스 비디오 데이터가 너무 커서 네트워크를 통해 효율적으로 저장하거나 스트리밍할 수 없기 때문에 필요합니다.

비디오와 오디오를 압축하는 소프트웨어 명령어를 코덱이라고 합니다. 코덱은 이미지 품질을 유지하면서 파일 또는 스트림 크기를 줄이는 것을 목표로 합니다. 비디오가 압축되면 디바이스에서 저장하거나 이동하거나 재생할 수 있도록 결과 데이터를 컨테이너에 넣어야 합니다.

압축 체계의 중요한 클래스는 각 프레임에서 거의 동일하게 유지되는 요소를 제거하기 위해 인터 프레임 압축 기법을 사용하는 GOP(Group of Pictures) 인코딩입니다.

고정 비트 전송률(CBR), 가변 비트 전송률(VBR) 및 품질 기반 가변 비트 전송률(QVBR)은인코더가 비디오 프레임당 사용 가능한 대역폭(비트 전송률)을 배포하는 방법을 결정하는 속도 제어 모드입니다.

콘텐츠를 패키징하여 시청자에게 배포

비디오 압축은 작업의 절반에 불과하며 나머지는 배포할 콘텐츠를 준비하는 것입니다. 가변 비트 전송률 스트리밍 및 JIT(JUST-IN-TIME) 패키징은 비디오 멀티 화면 전송의 두 가지 당면 과제, 즉 다양하고 불안정한 네트워크 속도와 여러 버전을 저장 및 전송하는 비용을 해결하는 기술입니다.

OTT 비디오 스트리밍을 통해 콘텐츠 공급자는 지리적 위치 및 구독자 프로필 정보 등을 기반으로 프로그램 스트림에 타겟팅된 광고를 삽입할 수 있습니다. SCTE 마커는 전송 스트림에 직접 내장되어 광고를 삽입할 수 있는 시기와 주 프로그램으로 돌아갈 시기를 지정합니다.

디지털 권한 관리는 기밀성 또는 수익의 이유로 비디오 스트림에 대한 액세스를 제어하는 프로세스,  즉 누가 무엇을 언제 볼 수 있는지 관리하는 프로세스입니다. 여기에는 다음 두 가지 주요 구성 요소가 있습니다.

  1. 암호화 - 데이터를 스크램블 및 모호화합니다.

  2. 인증 및 권한 부여 - 누구십니까? 당신은 누구입니까? 당신은 무엇을 할 수 있습니까?와 같은 질문에 답변합니다.

스트림이 트랜스코딩되고 패키징된 후에도 서버 하나로 수백, 수천 또는 수백만 명의 동시 시청자에게 비디오를 제공할 수는 없습니다. 콘텐츠 전송 네트워크는 시청자에게 최대한 가까우면서 네트워크에서 가장 대역폭 효율이 높은 위치에 비디오 파일을 복제하여 저장합니다. 콘텐츠는 허브 앤 스포크 서버 네트워크를 통해 전파됩니다. 원본 서버에서 시작하여 시청자에게 최대한 가까운 여러 엣지 서버로 전달됩니다.
