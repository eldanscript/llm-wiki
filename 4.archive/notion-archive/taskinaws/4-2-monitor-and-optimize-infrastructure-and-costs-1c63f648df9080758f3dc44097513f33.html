4.2 Monitor and Optimize Infrastructure and Costs

Overview

기계 학습 인프라 모니터링 및 핵심 성능 지표의 중요성:

  • 기계 학습 모델의 성능, 안정성, 효율성 보장을 위해 지속적인 모니터링이 필수적

  • 주요 성능 지표 (예: 처리량, 지연 시간, 오류율 등) 모니터링을 통해 잠재적인 문제 조기 감지 가능

Amazon CloudWatch Logs 및 경보 사용:

  • CloudWatch Logs를 통해 리소스의 로그 데이터 수집, 분석, 모니터링

  • 경보 기능을 활용하여 지표 임계값 초과 시 신속한 대응 가능

모니터링 및 가시성 도구 활용:

  • 지연 시간 및 성능 문제 해결을 위해 Amazon X-Ray, AWS CloudTrail, AWS CloudWatch 등 다양한 도구 활용

  • 통합 대시보드를 통해 전체 시스템 가시성 확보

SageMaker Inference Recommender 및 Compute Optimizer를 통한 인스턴스 최적화:

  • SageMaker Inference Recommender로 최적의 인스턴스 패밀리 선택

  • Compute Optimizer로 비용 및 성능을 고려한 인스턴스 크기 조정

비용 최적화 도구 및 ML Savings Plans:

  • AWS Cost Explorer, AWS Budgets, AWS Cost and Usage Report 등을 통해 비용 분석 및 최적화

  • ML Savings Plans로 장기적인 비용 절감 기회 확보

모범 사례 및 추가 리소스:

  • 비용 및 성능 최적화를 위한 다양한 AWS 제공 리소스 활용

  • 지속적인 모니터링, 분석, 최적화 프로세스 수립

Monitoring ML Infrastructure

기계 학습 인프라 최적화:

  1. 핵심 성능 지표 모니터링 및 분석:

    • 모델 정확도, 정밀도, 재현율, F1 점수, 지연 시간 등의 지표 모니터링

    • 지표 편차 감지 및 신속한 대응 조치

    • 리소스 활용도(CPU, 메모리, GPU) 및 데이터 파이프라인 성능 모니터링

    • 리소스 할당 최적화와 인프라 확장을 위한 통찰 제공

  2. 모델 드리프트 탐지 및 해결:

    • 시간에 따른 데이터 분포 및 특성-타깃 변수 관계 변화 모니터링

    • 모델 성능 저하 감지 및 모델 재학습/업데이트로 대응

  3. 비용 절감:

    • 리소스 낭비 식별 및 해결:

      • 과도한 리소스 프로비저닝 감지 및 최적화

    • 클라우드 기반 ML 서비스 비용 최적화:

      • 적절한 가격 책정 모델 선택

      • 실제 워크로드에 맞게 리소스 크기 조정

  4. 모니터링 도구 활용:

    • Amazon CloudWatch: 지표 수집, 분석, 경보 설정

    • Amazon SageMaker Inference Recommender: 최적의 배포 구성 추천

    • AWS Budgets: 비용 모니터링 및 초과 경보

  5. 지속적인 최적화 프로세스:

    • 모니터링, 분석, 최적화 작업의 지속적인 수행

    • ML 워크로드 특성에 맞는 인프라 구성 및 리소스 조정

이와 같이 기계 학습 인프라의 지속적인 모니터링은 성능 향상, 비용 절감, 안정성 확보를 위해 매우 중요합니다. AWS가 제공하는 다양한 모니터링 및 최적화 도구를 활용하면 이러한 목표를 효과적으로 달성할 수 있습니다.

KPIs for ML Infrastructure

기계 학습 인프라 주요 성과 지표(KPI):

  1. 리소스 활용도(Utilization)

    • Amazon EC2 인스턴스, 스토리지, 네트워크 등 컴퓨팅 리소스 활용도 모니터링

    • Amazon CloudWatch를 통한 리소스 활용 지표 및 경보 설정

    • GPU 활용도 모니터링으로 고비용 리소스의 효율적 사용 보장

    • Amazon SageMaker의 GPU 활용도 모니터링 기능 활용

  2. 비용(Cost)

    • AWS Cost Explorer, AWS Budgets를 통한 비용 모니터링 및 분석

    • AWS Compute Optimizer, AWS Trusted Advisor를 활용한 리소스 최적화 권장

    • 예약 인스턴스, 절감 요금제 등 활용을 통한 비용 절감

  3. 처리량(Throughput)

    • 데이터 처리 파이프라인, 실시간 추론 엔드포인트의 처리량 모니터링

    • Amazon CloudWatch를 통한 처리량 지표 확인 및 병목 지점 식별

  4. 가용성(Availability)

    • CloudWatch 경보, Auto Scaling, Elastic Load Balancing 등으로 가용성 확보

    • 서비스 가동 시간, 응답 시간, 오류율 등의 가용성 지표 모니터링

    • 다중 가용 영역/리전 배포 등 고가용성 아키텍처 구현

  5. 확장성(Scalability)

    • 리소스 활용도, 대기열 길이 등 지표 모니터링을 통한 확장/축소 정책 관리

    • 수요 변화에 맞춰 인프라 동적 조정

  6. 내결함성(Fault Tolerance)

    • CloudWatch, CloudTrail, AWS Health Dashboard 등으로 장애 감지 및 대응

    • 오류율, 실패 요청 등의 지표 모니터링을 통한 신뢰성 확인

이와 같은 핵심 성과 지표를 지속적으로 모니터링하고 분석함으로써, 기계 학습 인프라의 성능, 비용, 안정성을 최적화할 수 있습니다.

Monitoring Performance Metrics

Amazon CloudWatch에 대한 상세 설명:

  1. CloudWatch 개요:

    • AWS 리소스 및 애플리케이션을 실시간으로 모니터링하는 서비스

    • 지표(metrics) 수집, 추적, 경보 기능 제공

    • 리소스 활용도, 애플리케이션 성능, 운영 상태에 대한 가시성 확보

  2. CloudWatch 경보:

    • 지표 모니터링 및 임계값 설정을 통해 경보 생성

    • 임계값 초과 시 알림을 전송하고 자동으로 리소스 변경 가능

    • EC2 인스턴스의 CPU 사용량, 디스크 I/O 등을 모니터링하고 대응

  3. CloudWatch 대시보드:

    • 사용자 맞춤형 CloudWatch 홈페이지

    • 다양한 지역의 리소스를 단일 화면에서 모니터링

    • 지표와 경보를 시각화하여 표시

  4. 크로스 계정 모니터링:

    • 다중 AWS 계정 간 관찰성 확보

    • 모니터링 계정에서 소스 계정 지표, 로그 쿼리 등 포함 대시보드 생성

    • 모니터링 계정의 경보로 소스 계정 지표 모니터링 가능

  5. 기계 학습 인프라 모니터링:

    • SageMaker Model Monitor: 실시간 모델 품질 지속 모니터링

    • CloudWatch Logs: 모델 상태 모니터링 로그 수집 및 임계값 경보

    • 데이터 품질, 모델 성능, 편향, 특성 중요도 변화 등 모니터링

CloudWatch는 AWS 리소스 및 애플리케이션 전반에 걸친 관찰성을 제공하며, 이를 통해 기계 학습 인프라의 모니터링과 최적화를 달성할 수 있습니다.

Amazon CloudWatch Logs의 주요 기능:

  1. 패턴 분석(Patterns):

    • Logs Insights 페이지의 “Patterns” 탭에서 쿼리 결과의 반복 패턴을 찾아냄

    • 이를 통해 필요한 정보를 더 편리하게 찾고 로그의 새로운 또는 예상치 못한 내용을 심층 분석할 수 있음

  2. 비교 분석(Compare):

    • Logs Insights 페이지에서 “Compare (On)“을 선택하여 선택한 시간 범위의 쿼리 결과를 이전 기간과 비교

    • 이전 안정적인 시나리오와 비교하여 변화를 더 빠르게 관찰할 수 있음

    • 비교 대상 시간 범위는 전날, 전주, 전월 등 다양한 옵션 제공

  3. 로그 이상 탐지(Log anomalies):

    • Logs 섹션의 “Log anomalies” 페이지에서 로그 수집 중 감지된 이상 징후를 자동으로 표시

    • 이를 통해 로그에 나타난 이상 동작을 신속하게 파악할 수 있음

이와 같은 CloudWatch Logs의 다양한 분석 기능들은 기계 학습 인프라 모니터링에 유용하게 활용될 수 있습니다. 로그 데이터에 나타나는 패턴, 변화, 이상 징후를 효과적으로 탐지하고 분석할 수 있어 보다 신속하게 문제를 파악하고 대응할 수 있습니다.

Monitoring and Observability

모니터링과 관찰성의 차이:

  1. 모니터링(Monitoring):

    • 계측, 로깅, 경보 설정을 통해 지표를 수집하고 예상 행동으로부터의 이상을 감지

    • 감지된 이상 상황에 대한 경보 발생 및 자동 조치 수행

  2. 관찰성(Observability):

    • 기계 학습 시스템의 내부 상태와 동작에 대한 심층적인 이해를 제공

    • 단순한 지표 수집을 넘어 시스템 간 복잡한 상호작용과 의존성을 파악

    • 시스템 동작에 대한 질문에 답하고, 근본 원인을 파악하며, 전체적인 시스템 건강성을 파악

  3. 기계 학습 모델에서의 관찰성:

    • 모델 해석성, 데이터 추적성, 모델 버전 관리, 분산 추적 등의 기능 포함

  4. 관찰성 도구 및 실천:

    • 분산 추적, 구조화된 로깅, 데이터 시각화 등의 고급 기술 활용

    • 시스템 행동에 대한 종합적인 인사이트 제공, 효과적인 문제 해결 가능

  5. 모니터링과 관찰성의 활용:

    • 모니터링: 문제 감지 및 경보 발생

    • 관찰성: 근본 원인 파악 및 시스템 최적화

    • 효과적인 모델 배포를 위해 모니터링과 관찰성을 함께 구현

모니터링과 관찰성은 상호 보완적인 접근법으로, 안정적이고 성능이 우수하며 신뢰할 수 있는 기계 학습 모델 배포를 가능하게 합니다.

Monitoring

기계 학습 모델 모니터링을 위한 주요 지표:

  1. 모델 정확도(Model Accuracy)

    • 검증 또는 테스트 데이터셋에서의 모델 성능 추적

    • 목표한 수준의 정확도를 유지하는지 확인

  2. 추론 지연 시간(Inference Latency)

    • 새로운 입력에 대한 모델 처리 및 예측 생성 시간 측정

    • 실시간 응용 프로그램의 성능 요구사항 충족 여부 확인

  3. 리소스 활용도(Resource Utilization)

    • 추론 시 CPU, 메모리, GPU 사용량 모니터링

    • 리소스 활용의 효율성 보장

  4. 입력 데이터 분포(Input Data Distribution)

    • 입력 특성의 분포 변화 탐지

    • 모델 성능에 영향을 줄 수 있는 데이터 편향 모니터링

이와 같은 핵심 지표를 지속적으로 모니터링함으로써, 기계 학습 모델의 성능, 효율성, 신뢰성을 유지할 수 있습니다. 모니터링 정보는 문제 발생 시 신속한 대응을 가능하게 하고, 장기적으로는 모델 개선을 위한 의사결정에 활용될 수 있습니다.

Observability

기계 학습 시스템의 관찰성 향상을 위한 추가 지표 및 기능:

  1. 모델 해석성(Model Interpretability)

    • 특성 중요도 분석, 주목도 맵(Saliency Map), 모델 증류 기법 등 활용

    • 모델의 의사 결정 프로세스 이해 및 편향, 취약점 식별

  2. 데이터 추적성(Data Lineage)

    • 학습 및 추론에 사용된 데이터의 출처 추적

    • 데이터 변환 및 전처리 과정이 모델 동작에 미치는 영향 파악

  3. 모델 버전 관리(Model Versioning)

    • 아키텍처, 하이퍼파라미터, 학습 데이터 변경 내역 유지

    • 특정 모델 버전과 성능 간 상관관계 분석

  4. 분산 추적(Distributed Tracing)

    • 복잡한 분산 시스템에서 데이터와 요청의 흐름 추적

    • 성능 병목현상 또는 장애 원인 진단

이러한 관찰성 향상 기능은 기계 학습 모델의 내부 동작에 대한 심층적인 이해를 가능하게 하며, 보다 효과적인 문제 해결과 시스템 최적화를 지원합니다. 모니터링과 함께 이러한 관찰성 기능을 활용하면, 안정적이고 신뢰할 수 있는 기계 학습 시스템을 구축할 수 있습니다.

Tools

AWS 모니터링 및 관찰성 도구:

  1. AWS X-Ray

    • 분산 추적 시스템으로, 프로덕션 및 분산 애플리케이션의 성능과 지연 시간 분석

    • 애플리케이션 구성 요소의 성능 및 지연 시간에 대한 인사이트 제공

  2. Amazon CloudWatch Lambda Insights

    • Lambda 함수에 대한 향상된 모니터링 및 관찰성 제공

    • 성능 문제 식별을 위한 지표 및 로그 데이터 제공

  3. CloudWatch Logs Insights

    • 실시간에 가까운 로그 분석 및 문제 해결

    • 기계 학습 시스템의 성능 및 지연 시간 문제 파악

  4. AWS CloudTrail

    • AWS API 활동 기록 및 로그 파일 전달

    • 사용자 활동, API 사용, 시스템 성능 감사 및 조사 가능

  5. Amazon QuickSight

    • 대화형 데이터 시각화 및 분석 서비스

    • 기계 학습 시스템의 성능과 지연 시간에 대한 인사이트 제공

  6. Amazon EventBridge

    • 다양한 소스의 애플리케이션 데이터 연결

    • 실시간 모니터링 및 성능/지연 시간 이슈 경보 기능

  7. Amazon SageMaker Inference Recommender

    • 프로덕션 모델 배포를 위한 최적의 인스턴스 유형 및 구성 추천

Rightsizing Compute Infrastructure for ML Solutions

Amazon SageMaker Inference Recommender 개요:

  1. SageMaker Inference Recommender 소개:

    • SageMaker 내 기능으로, ML 추론 성능 및 비용 최적화 지원

    • ML 모델과 워크로드 패턴을 분석하여 가장 적합한 AWS 컴퓨팅 리소스 및 구성 제안

  2. 추론 성능 및 비용 최적화 사례:

    • 이미지 분류 딥러닝 모델의 실시간 추론 배포 지원

    • 계산 집약적 워크플로우의 경우 AWS Inferentia 활용 권장

    • 덜 계산 집약적인 경우 CPU 또는 GPU 인스턴스 유형 및 구성 제안

    • 배치 처리, 다중 모델 배포, 자동 스케일링 등의 최적화 추천

  3. 추론 권장 사항(Inference recommendations):

    • 권장 인스턴스 유형에 대한 로드 테스트 수행

    • 모델 패키지 ARN만 제공하면 45분 내 완료

  4. 엔드포인트 권장 사항(Endpoint recommendations):

    • 더 상세한 로드 테스트 및 엔드포인트 구성 권장

    • 비용, 처리량, 지연 시간 지표 제공

    • 자동 스케일링 정책 구성에 활용 가능

  5. AWS Compute Optimizer와의 연계:

    • 인스턴스 크기 조정 권장 기능으로 비용 및 성능 최적화

    • ML 워크로드의 리소스 활용도에 따른 최적 인스턴스 유형 제안

SageMaker Inference Recommender와 Compute Optimizer는 기계 학습 워크로드의 인프라 최적화를 위한 강력한 도구들입니다. 이를 통해 성능, 비용, 리소스 활용도 등을 균형있게 관리할 수 있습니다.

Example

  1. 샘플 워크로드 실행:

    • XGBoost 모델이 배포된 상태에서 샘플 데이터로 워크로드 실행

  2. SageMaker Inference Recommender 구성:

    • ML 도메인, 작업 유형, 모델 유형, 입력 콘텐츠 유형 등 설정

    • 인퍼런스 추천 작업을 위한 컨테이너 구성 파일 준비

  3. 기본(Default) 인퍼런스 추천 작업 실행:

    • 약 45분 소요, 여러 인스턴스 유형에 대한 성능/비용 지표 제공

  4. 결과 확인:

    • AWS Management Console 또는 SageMaker Studio에서 작업 결과 확인

    • 모델 지연 시간, 예상 비용, 처리량 등의 정보 활용 가능

  5. 고급(Advanced) 인퍼런스 추천 작업 실행:

    • 약 2시간 소요, 사용자 정의 임계값 및 중단 기준 설정 가능

    • 모델 지연 시간 목표, 최대 호출 수 등 파라미터 구성

  6. 고급 작업 결과 확인:

    • 인스턴스 유형별 호출 수, 비용 등 상세 정보 제공

    • 목표 성능과 비용을 충족하는 배포 구성 식별 가능

SageMaker Inference Recommender를 활용하면 기계 학습 모델 배포를 위한 가장 적합한 AWS 컴퓨팅 리소스를 효과적으로 식별할 수 있습니다. 이를 통해 성능과 비용 간의 균형을 최적화할 수 있습니다.

  2. 작업 모니터링:

    • ML 워크플로우의 성능 및 리소스 사용량 추적

    • 실시간 가시성을 위한 맞춤형 대시보드 및 경보 구현

    • 비용 할당 및 최적화 도구와의 통합

  3. 리소스 및 자산:

    • 컴퓨팅 인스턴스, 스토리지, 네트워크 대역폭 등 면밀한 추적

    • 비효율적인 리소스 사용 최적화를 위한 정책 및 자동화

    • 지속적인 수요 분석 및 예측으로 비용-성능 균형 유지

  • 비용 할당: 비즈니스 단위, 프로젝트, 코스트 센터 별 비용 배분

  • 비용 최적화: 태깅, 정기적 정책 검토를 통한 효과적인 비용 관리

이러한 접근법을 통해 ML 인프라 비용에 대한 심도 있는 이해와 최적화를 달성할 수 있습니다.

  5. 비용 최적화 도구 활용:

    • Cost Explorer로 비용 분석 및 최적화 기회 식별

    • Trusted Advisor의 권장사항을 통한 추가 최적화

  6. 서비스 할당량(쿼터) 고려:

    • 기계 학습 관련 서비스 할당량 확인 및 증가 요청

    • Capacity Blocks for ML을 통한 GPU 인스턴스 사전 예약

  7. Serverless Inference 및 프로비저닝 동시성 활용:

    • 콜드 스타트 지연 시간 해결

    • 버스트 트래픽 대응 및 비용 최적화

이와 같은 다양한 전략을 활용하여 기계 학습 인프라의 용량 문제를 효과적으로 식별하고 해결할 수 있습니다.

Provisioned Concurrency

Amazon SageMaker Serverless Inference에 대해 자세히 살펴보겠습니다:

  1. Serverless Inference 개요:

    • 인프라 구성 및 관리 없이 ML 모델을 배포하고 확장할 수 있는 서비스

    • **트래픽 변화가 큰 워크로드와 콜드 스타트에 대한 내성이 있는 경우** 적합

  2. 주요 특징:

    • 자동으로 컴퓨팅 리소스를 발동하고 대응하여 스케일 인/아웃

    • 인스턴스 유형 선택 및 스케일링 정책 관리 불필요

    • 유휴 기간 중 엔드포인트를 0으로 스케일링하여 비용 절감

  3. 아키텍처 및 가격 모델:

    • AWS Lambda와 통합되어 고가용성, 장애 허용성, 자동 확장성 제공

    • 사용한 만큼만 지불하는 종량제 방식의 저렴한 비용

  4. 프로비저닝 동시성(Provisioned Concurrency):

    • **콜드 스타트 지연 시간 해결을 위한 기능**

    • 대기 중인 인스턴스 풀을 사전에 준비하여 즉시 응답 가능

  5. 프로비저닝 동시성의 이점:

    • 트래픽 폭증 대응 능력 향상

    • 비용 최적화

    • 용량 계획 간소화

Serverless Inference와 프로비저닝 동시성은 기계 학습 엔지니어들에게 일관된 응답성과 신뢰성을 제공하는 동시에 리소스 활용과 비용 효율성을 최적화할 수 있는 강력한 도구입니다.

Cold Start Latency

프로비저닝 동시성을 통한 콜드 스타트 지연 시간 해결:

  1. 콜드 스타트 지연 시간 문제:

    • 새로운 인스턴스가 프로비저닝되고 초기화되는 데 발생하는 지연

    • 수초에서 수분 범위로, 실시간 또는 저지연 추론이 필요한 애플리케이션에 해로움

  2. 프로비저닝 동시성의 역할:

    • **미리 워밍업된 인스턴스 풀을 유지하여 콜드 스타트 지연 제거**

    • 추론 요청을 즉시 처리할 수 있게 함

  3. 프로비저닝 동시성의 이점:

    • 트래픽 폭증 대응:

      • 온디맨드 인스턴스 프로비저닝으로 인한 지연 문제 해결

    • 비용 최적화:

      • 워밍업된 인스턴스 풀 유지로 효율적인 리소스 활용 가능

    • 용량 계획 간소화:

      • 사전 준비된 인스턴스 풀로 용량 관리 용이

  4. 주의 사항:

    • 모든 사용 사례에 프로비저닝 동시성이 적합하지 않음

    • 적절한 동시성 수준 설정을 위한 모니터링 및 계획 필요

프로비저닝 동시성은 콜드 스타트 지연 해결, 트래픽 폭증 대응, 비용 최적화, 용량 계획 등의 이점을 제공하여 기계 학습 엔지니어들에게 강력한 도구가 됩니다.

Advantages of Provisioned Concurrency

프로비저닝 동시성의 장점 - 트래픽 폭증 대응:

  1. 트래픽 폭증 대응 능력:

    • 피크 시간 또는 프로모션 기간 등에 추론 요청이 급증하는 시나리오

    • 온디맨드 인스턴스로는 새로운 인스턴스를 프로비저닝하느라 지연 및 성능 저하 발생

  2. 프로비저닝 동시성의 해결책:

    • 미리 준비된 워밍업된 인스턴스 풀을 통해 폭증하는 트래픽을 원활히 처리

    • 일관되고 반응성 높은 사용자 경험 보장

  3. 비용 최적화:

    • 워밍업된 인스턴스를 유지하는 비용이 온디맨드로 반복 프로비저닝하는 비용보다 일반적으로 저렴

    • 일관되거나 예측 가능한 트래픽 패턴의 워크로드에 적합

  4. 금융 사기 탐지 사례:

    • 실시간 저지연 추론이 필요한 금융 사기 탐지 모델

    • 프로비저닝 동시성으로 콜드 스타트 지연 없이 신속한 사기 탐지 가능

  5. 용량 계획 간소화:

    • 원하는 동시성 수준을 설정하여 인스턴스 스케일링 관리를 SageMaker Serverless Inference에 위임

프로비저닝 동시성은 트래픽 폭증 대응, 비용 최적화, 용량 계획 간소화 등 다양한 이점을 제공하여 기계 학습 워크로드의 신뢰성과 효율성을 향상시킵니다.

Auto Scaling

Amazon SageMaker의 자동 확장 기능 설명:

  1. 자동 확장(Auto Scaling)의 개요:

    • 추론 워크로드 변화에 따라 프로비저닝된 인스턴스 수를 동적으로 조정

    • 워크로드가 증가할 때는 더 많은 인스턴스를 온라인으로 가져오고, 감소할 때는 불필요한 인스턴스를 제거

  2. SageMaker의 자동 확장 옵션:

    • 목표 추적(Target Tracking): 목표 지표(CPU 활용도, 처리량 등)를 설정하고 이를 달성하도록 자동 확장

    • 단계 확장(Step Scaling): CloudWatch 경보 위반 정도에 따른 고급 확장 방식

    • 예약 확장(Scheduled Scaling): 예상 수요에 맞춰 정기적인 확장/축소 스케줄 설정

  3. 온디맨드 Serverless 엔드포인트의 자동 확장:

    • SageMaker가 컴퓨팅 리소스 프로비저닝 및 관리

    • 요청 트래픽에 따라 리소스를 자동으로 확장/축소하여 사용량 기반 과금

  4. 프로비저닝 동시성의 자동 확장:

    • Application Auto Scaling과 통합되어 대상 지표 또는 예약 일정에 따른 동시성 수준 조정

  5. 프로비저닝 동시성 자동 확장 설정 과정:

    • 모델 등록

    • 스케일링 정책 정의

    • 스케일링 정책 적용

자동 확장 기능을 통해 기계 학습 엔드포인트의 가용성과 비용 효율성을 최적화할 수 있습니다. 특히 Serverless 인퍼런스와 프로비저닝 동시성의 자동 확장은 이를 더욱 효과적으로 지원합니다.

Cost Management Tools

AWS 비용 최적화 도구 및 기법 정리:

  1. 비용 분석 도구:

    • AWS Cost Explorer: 시간 경과에 따른 비용 패턴 파악, 미래 비용 예측, 최적화 기회 식별

    • AWS Trusted Advisor: 비용 최적화를 포함한 다양한 권장사항 제공

    • AWS Budgets: 사용자 정의 예산 설정 및 초과 경보

    • Amazon CloudWatch: 지표 수집, 경보 설정, 자동 조치

    • AWS CloudTrail: 계정 활동 로깅 및 모니터링

    • Amazon S3 Analytics: 데이터 수명 주기 분석 및 최적화 권장

  2. AWS Billing and Cost Management:

    • 비용 할당 태깅을 통한 프로젝트/팀별 비용 추적

    • 비용 최적화 기회 식별을 위한 상세 보고서 제공

  3. AWS Budgets:

    • 프로젝트/실험 단위 비용 제어 및 거버넌스

    • 비용 이상 징후 감지를 위한 경보 설정

  4. AWS Cost Explorer:

    • 미래 비용 예측을 통한 용량 계획 지원

    • 서비스, 리전 등 다양한 차원에서의 비용 최적화 분석

  5. AWS Trusted Advisor:

    • 인스턴스 최적화, 유휴 리소스 식별, 예약 인스턴스 권장

  6. 비용 할당 및 태깅 기법:

    • SageMaker Studio 도메인/사용자, 노트북 인스턴스, 관리 작업 등에 대한 태깅

    • 비용 추적, 보고, 거버넌스를 위한 태그 활용

다양한 비용 관리 도구와 태깅 기법을 활용하여 기계 학습 워크로드의 비용 효율성을 최적화할 수 있습니다. 이를 통해 예산 초과, 비용 이상 등의 문제를 사전에 방지할 수 있습니다.

Purchasing Option to Optimize ML Infrastructure Costs

AWS 인프라 비용 최적화를 위한 구매 옵션:

  1. Spot 인스턴스:

    • On-Demand 대비 크게 저렴한 가격

    • 중단 가능한 워크로드(일괄 처리, 데이터 분석, 일부 ML 학습 등)에 적합

  2. On-Demand 인스턴스:

    • 유연성과 신뢰성이 높은 옵션

    • 단기적이거나 예측 불가능한 워크로드(실시간 추론 서비스)에 적합

  3. 예약 인스턴스:

    • On-Demand 대비 최대 72% 할인

    • 상태 또는 예측 가능한 워크로드(장기 ML 학습)에 적합

  4. Capacity Blocks:

    • AWS Outposts, Wavelength 등에서의 용량 사전 예약

    • 피크 수요 기간 중 용량 확보가 필요한 경우에 활용

  5. SageMaker Savings Plans:

    • SageMaker 사용량 기준 1년/3년 약정 할인 제공

    • 반복적인 ML 모델 학습 및 배포에 적합

  6. Cost and Usage Report:

    • 세부적인 AWS 사용량 및 비용 데이터 제공

    • DIY 분석을 위한 원천 데이터로 활용

구매 옵션 선택 시 고려 사항:

  • 워크로드의 예측 가능성, 비용 민감도, 중단 허용도 등

이와 같은 구매 옵션을 적절히 활용하면 기계 학습 인프라의 비용 효율성을 극대화할 수 있습니다.

SageMaker ML Savings Plans을 통한 비용 최적화:

  1. SageMaker ML Savings Plans 개요:

    • 1년 또는 3년 동안 일정 금액의 SageMaker 사용량을 약정할 경우 할인 제공

    • 두 가지 유형: Compute Savings Plan, Machine Learning Services Savings Plan

  2. Compute Savings Plan 활용:

    • SageMaker 학습 작업, 호스팅 모델, 일괄 변환 작업 등의 컴퓨팅 비용 할인

  3. 활용 사례:

    • 장기간 지속되는 딥러닝 모델 학습 및 배포 프로젝트

    • 연간 SageMaker 컴퓨팅 비용 약 $100,000 예상

  4. 비용 절감 효과:

    • 3년 단위 $100,000/년 Compute Savings Plan 약정 시 최대 64% 할인 가능

    • 연간 100,000대신36,000만 지불하여 3년간 큰 비용 절감 효과

  5. 주의 사항:

    • 정확한 사용량 예측이 중요, 과다/과소 약정 시 문제 발생 가능

    • AWS 제공 도구 및 가이드를 활용하여 적절한 Savings Plan 선택

SageMaker ML Savings Plans를 통해 기계 학습 엔지니어는 인프라 비용을 최적화하고, 모델 구축 및 배포에 더 많은 자원을 투입할 수 있습니다.

Best Practices

ML 워크플로우의 각 단계별 비용 최적화 방법:

데이터 준비 단계:

  • Amazon S3를 사용하여 원시 데이터 저장

  • AWS Glue로 데이터 처리 파이프라인 자동화

  • Athena를 이용하여 S3에서 직접 데이터 쿼리

모델 학습 단계:

  • Spot 인스턴스를 활용하여 학습 워크로드 실행

  • SageMaker 관리형 Spot 학습 사용

  • 조기 중지 또는 체크포인팅으로 비효율적인 학습 중단

  • SageMaker 모델/데이터 병렬 처리로 학습 시간 및 비용 감축

모델 배포 단계:

  • Auto Scaling을 통한 추론 리소스 자동 확장/축소

  • SageMaker 다중 모델 엔드포인트로 인프라 비용 절감

  • 배치 처리 및 캐싱으로 리소스 활용도 향상

  • 경량 모델 또는 최적화 기법 적용으로 추론 비용 감축

모델 모니터링 및 관리 단계:

  • CloudWatch를 이용한 자동 모니터링 및 경보 설정

  • 자동 재학습 파이프라인 구현으로 수동 개입 최소화

  • Lambda 함수를 통한 추론 및 전처리 서버리스 실행

일반 모범 사례:

  • Cost Explorer와 AWS Budgets로 비용 추적 및 관리

  • 비용 할당 태그를 통한 프로젝트/팀별 비용 귀속

  • 리소스 사용량 정기 검토 및 최적화

  • Trusted Advisor의 비용 최적화 권장사항 활용

이와 같은 단계별, 일반적 비용 최적화 방법들을 적용하면 기계 학습 워크플로우의 전반적인 비용 효율성을 높일 수 있습니다.
