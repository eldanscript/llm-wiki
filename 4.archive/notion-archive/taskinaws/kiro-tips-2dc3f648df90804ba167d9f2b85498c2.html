Kiro Tips

MCP

MCP 서버 사용 가이드라인

MCP 서버의 본질

  • MCP 서버는 LLM을 위한 API로, 모델이 외부 애플리케이션과 상호작용할 수 있게 해주는 도구 세트를 제공

  • 예: Builder MCP의 InternalCodeSearch 도구로 Amazon 내부 코드베이스 검색 가능

일반적인 개발 작업에서의 제한사항

  • 대부분의 MCP 서버는 ‘일반적인 개발 작업’에는 크게 도움이 되지 않음

  • 내부 리소스와 애플리케이션에 자주 접근해야 하는 경우에만 필요한 최소한의 도구를 가진 MCP 서버 사용 권장

효과적인 활용 방법

Few-shot 프롬프팅 접근법:

  1. Builder MCP를 활성화하여 참고할 Brazil 패키지를 읽게 함

  2. MCP를 비활성화한 후 해당 패키지를 참고하여 코딩 작업 수행

  3. Amazon에서는 유사한 코드가 이미 존재할 가능성이 높아 이 방법이 효과적

설정 레벨 선택 기준

사용자 레벨 (Global) 설정:

  • 다양한 상황에 적용 가능한 범용적인 MCP 서버

  • 예: Builder MCP

프로젝트 레벨 설정:

  • 특정 프로젝트에서만 필요한 전용 애플리케이션

  • 예: 파이프라인 정보 조회용 Wayfinder MCP

관리 팁

  • MCP 서버를 설정에 포함시키되 필요에 따라 비활성화하여 관리하는 것이 유용

  • 필요할 때만 활성화하여 사용하는 방식 권장

이러한 접근법을 통해 MCP 서버를 효율적으로 활용하면서도 불필요한 복잡성을 피할 수 있습니다.

Builder MCP

Builder MCP vs AWS 공식 MCP 서버

Builder MCP의 특징

  • Amazon 내부 도구 중심: 내부 코드 검색, 티켓팅, 파이프라인 관리 등 Amazon 특화 기능

  • 개발 워크플로우 최적화: Brazil 패키지, 코드 리뷰, 내부 문서 등에 특화

  • 제한된 AWS 서비스 범위: 일부 AWS 기능만 포함

AWS 공식 MCP 서버의 장점

  • 포괄적인 AWS 서비스 지원: EC2, S3, Lambda, CloudFormation 등 광범위한 서비스

  • 최신 AWS 기능 반영: AWS에서 직접 관리하므로 새로운 기능이 빠르게 추가

  • 표준화된 AWS API 접근: 공식 SDK 기반의 일관된 인터페이스

추천 접근법

상황별 선택 기준

Builder MCP만으로 충분한 경우:

  • Amazon 내부 개발 워크플로우가 주 목적

  • 기존 Brazil 패키지 참조 및 내부 도구 활용

  • 제한된 AWS 서비스만 사용

AWS MCP 추가 등록이 유용한 경우:

  • 다양한 AWS 서비스와의 깊은 통합 필요

  • 최신 AWS 기능 활용 요구

  • 외부 고객 대상 AWS 솔루션 개발

실용적 권장사항

  1. 시작은 Builder MCP로: 대부분의 Amazon 내부 작업에 충분

  2. 필요시 AWS MCP 추가: 특정 AWS 서비스가 필요할 때만 선택적 추가

  3. 프로젝트별 관리:

    • 글로벌: Builder MCP

    • 프로젝트별: 필요한 AWS MCP만 활성화

Builder MCP 현재 제공 기능 목록

1. 내부 검색 및 문서

  • InternalSearch: Amazon 내부 검색 엔진 (is.amazon.com)

  • ReadInternalWebsites: 내부 Amazon 웹사이트 읽기

  • SearchAcronymCentral: 내부 약어 검색

  • InternalCodeSearch: Amazon 내부 코드 저장소 검색

2. 개발 도구

  • WorkspaceSearch: 워크스페이스 내 검색

  • CreatePackage: Amazon 소프트웨어 패키지 생성 (Brazil/Peru)

  • BrazilWorkspace: Brazil 워크스페이스 생성

  • BrazilBuildAnalyzerTool: Brazil 빌드 분석

  • BrazilPackageBuilderAnalyzerTool: 패키지 빌더 분석

  • CrCheckout: 코드 리뷰 체크아웃

  • CRRevisionCreator: 코드 리뷰 리비전 생성

  • WorkspaceGitDetails: Git 저장소 세부사항

3. 테스트 및 배포

  • RunIntegrationTest: 통합 테스트 실행

  • ReadRemoteTestRun: 원격 테스트 실행 결과 읽기

  • GetPipelinesRelevantToUser: 사용자 관련 파이프라인 조회

  • GetPipelineHealth: 파이프라인 상태 확인

  • GetPipelineDetails: 파이프라인 세부사항

4. 인프라 및 운영

  • MechanicDiscoverTools: Mechanic 도구 검색

  • MechanicDescribeTool: Mechanic 도구 설명

  • MechanicRunTool: Mechanic 도구 실행

  • ApolloReadActions: Apollo 배포 시스템 읽기

5. 프로젝트 관리

  • TaskeiGetTask: Taskei 작업 조회

  • TaskeiListTasks: Taskei 작업 목록

  • TaskeiUpdateTask: Taskei 작업 업데이트

  • TaskeiCreateTask: Taskei 작업 생성

  • TicketingReadActions: 티켓 시스템 읽기

  • TicketingWriteActions: 티켓 시스템 쓰기

6. 보안 및 위험 관리

  • GetSasRisks: SAS 위험 조회

  • CheckFilepathForCAZ: CAZ 파일 경로 확인

  • BarristerEvaluationWorkflow: Barrister 평가 워크플로우

7. 온콜 및 모니터링

  • OncallReadActions: 온콜 시스템 읽기

  • GetDogmaClassification: Dogma 분류 조회

  • GetDogmaRecommendations: Dogma 권장사항

8. 기타 도구

  • Delegate: 작업 위임

  • SimAddComment: SIM 댓글 추가

  • QuipEditor: Quip 문서 편집

  • ThirdPartyAnalysisGateway: 서드파티 분석

AWS 관련 기능 분석

Builder MCP에서 제공하는 AWS 기능:

  • Mechanic을 통한 AWS 리소스 관리 (EC2, CloudWatch, ECS 등)

  • Apollo를 통한 배포 관리

  • 파이프라인 관리 (AWS 서비스 배포 포함)

제한사항:

  • 직접적인 AWS SDK 호출 기능 없음

  • Bedrock 전용 도구 없음

  • 세밀한 AWS 서비스 제어 제한적
