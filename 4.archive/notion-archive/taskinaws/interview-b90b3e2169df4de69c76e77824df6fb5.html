Networking

  • OSI Layer에 대해 설명 한다면? Layer 구조화와 목적은?

    • 네트워크의 통신의 연결 과정을 계층화하여 표준으로 만든 것으로 OSI 7 Layer 또는 4 Layer로 분류한다.

    • 이기종 컴퓨터간의 네트워크 과정에서 HW나 SW 변경없이 통신이 가능할 수 있도록 구조화 시킨 표준이다.

    • OSI 7 Layer는 Physical - DataLink - Network - Transport - Session - Presentation - Application Layer로 표현되며

    • 4 Layer는 Physical/DataLink - Network - Transport - Application Layer로 분류한다.

    • Layer로 분리한 목적은 Capsule화와 은닉화를 통해 각각 Layer에 대해 필요한 내용만 이해하고 구현, 관리 할 수 있도록 하기 위함이다

  • Unicast와 Multicast에 대해 설명 한다면? 어떤 시나리오에서 사용하는지?

    • 유니 캐스트는 일대일 통신이며 멀티 캐스트는 일대 다 (one-to-many) 통신 프로세스 : 프레임에 자신의 MAC 주소와 목적지의 MAC 주소를 첨부하여 전송하는 방식

    • 멀티 캐스트는 특정 그룹에 속해 있는 시스템에게만 한 번에 정보를 전송 : 멀티캐스트 IP 주소와 멀티캐스트 MAC 주소를 라우터에 등록 → 멀티캐스트 그룹에 등록

    • 멀티 캐스트 Protocol : IGMP, CCMP, IGMP Snooping, Multicasting Routing Protocol

    • 다중 유니 캐스트는티 캐스트에 비해 더 많은 대역폭을 사용

    • 멀티 캐스트는 대역폭을 효율적으로 사용 : 중복 전송으로 인한 네트워크 자원 낭비를 최소화

    • 유니 캐스트는 스트리밍 미디어의 경우 확장 성이 좋지 않음, 멀티 캐스트는 대규모 네트워크에서 확장 성이 좋지 않음

    • 유니 캐스트 : 웹 서핑, 파일 전송

    • 멀티 캐스트 : 멀티미디어 스트리밍, 증권 거래소, 다자간 VoIP 통화

  • Broadcast와 Multicast의 차이점을 설명한다면? 어떤 시나리오에서 사용하는지?

    • 브로드캐스트 방식은 로컬 네트워크에 연결되어 있는 모든 시스템에게 프레임을 보내는 방식 : 같은 대역의 네트워크 주소를 가진 모든 호스트에게 전송하는 방식

    • 브로드캐스트 방식은 통신하고자 하는 시스템의 MAC 주소를 알지 못하는 경우, 네트워크에 있는 모든 시스템에게 알리는 경우, 라우터끼리 정보를 교환하거나 새로운 라우터를 찾는 경우 등에 이용

    • 모든 시스템에게 패킷이 전송되므로 트래픽이 증가하고 CPU 도 패킷을 처리해야 하므로 성능에 저하가 생긴다

    • Multicast와 Broadcast는 UDP 프로토콜을 사용

  • Switch와 Router의 차이를 설명할 수 있는지?

    • Switch는 데이터 목적지 파악 경로 스위칭

    • Router는 목적지까지의 적합한 경로를 Routing

    • Switch는 Data Link 계층, Router는 Network 계층

    • Switch는 MAC 주소 기반 동작, Router는 IP 주소 기반 동작

    • Switch는 Broadcast domain 구분 못함, Router는 구분 가능 하며 port별 다른 네트워크 대역을 연결, 구분

    • Switch는 불명확한 목적지를 가진 데이터를 브로트캐스팅, Router는 drop

  • CIDR에 대해 설명 한다면?

    • Classless Inter-Domain Routing의 약자로 연속되는 IP 주소 범위를 표기하는 방법이다.

    • 32bit의 IP 주소의 일부bit를 네트웍 Host 주소로 나머지를 서브네트 웍 주소로 사용하는 방식이다.

    • 192.168.32.0/26 이라고 표시하면 32bit중 26bit는 Newtwork 주소를 기술하고 나머지 6bit는 Host IP 주소 영역으로 사용한다는 의미이다.

    • 그러므로, 서브네트 주소 영역은 192.168.32.1 ~ 62가 된는 것이다. 192.168.32.63은 Broadcast 주소로 사용한다.

  • TCP의 3 way handshaking이 일어 나는데, 이것이 무엇이고 어떤 점 때문에 일어 나는지? 4 way handshaking은?

    • 3-Way : TCP SYN(‘synchronize sequence numbers’) / TCP SYN, ACK / TCP ACK

    • 양쪽 모두 데이타를 전송할 준비가 되었다는 것을 보장하고, 실제로 데이타 전달이 시작하기전에 한쪽이 다른 쪽이 준비되었다는 것을 알수 있도록 한다

    • 양쪽 모두 상대편에 대한 초기 순차일련변호를 얻을 수 있도록 한다

    • 3-Way handshake는 TCP의 연결을 초기화 할 때 사용, 4-Way handshake는 세션을 종료하기 위해 수행되는 절차

    • Client에서 세션을 종료시킨 후 뒤늦게 도착하는 패킷이 있다면 이 패킷은 Drop되고 데이터는 유실될 것입니다. 이러한 현상에 대비하여 Client는 Server로부터 FIN을 수신하더라도 일정시간(디폴트 240초) 동안 세션을 남겨놓고 잉여 패킷을 기다리는 과정을 거치게 되는데 이 과정을 “TIME_WAIT”

  • Ephemeral port란?

    • IANA에서는 포트를 3가지로 분류하고 있다.

    • Well Known Port : 0 ~ 1023, Registered Port : 1024 ~ 49151, Dynamic/Private Port : 49152 ~ 65535 이다.

    • Well Known Port는 root 권한으로 Bind 할 수 있는 Port이고, Registered Port는 일반 유저 권한으로 Bind 할 수 있는 Port이다.

    • Dynamic/Private Port는 client-server간 통신 시 client가 사용할 수 있는 Port이다.

    • 실제로는 Privileged Port 1 ~ 1023, Unprivileged Port 1024 ~ 65535로 나누어 사용된다.

    • Unprivileged Port는 Client Port 혹은 Ephemeral(임시) Port라고 부르기도 한다.

  • Load Balancer에 L4와 L7 유형이 있는데 이것의 차이는?

    • Load-balancer는 Scale-out 방식을 도입하여 서버의 성능을 증가시키는 방식

    • 서버에 가해지는 트래픽의 부하를 분산하는 작업이 필요합니다. 이렇게 두개이상의 컴퓨터자원에 작업을 나누는것을 로드밸런싱이라고 하고, 이런 작업을 하는 장비를 로드밸런서라고 합니다

    • L4 : Transport Layer (Port 기반) Level에서 Load Balancing : TCP, UDP Protocol

    • L7 : Application Layer (User request(URL)기반) Level에서 Load Balancing : HTTP, FTP, SMTP Prorocol

  • L7은 Packet 어디를 보고 Balancing을 하게 되는가?

  • **Static Load Balancer와 Dynamic Load Balancer 방식**

    • Static : Roud-Robin (순서대로 할당), Ratio (가중치가 높은 서버), Priority Group Active (Active-Standby, Active 장치에만)

    • Dynamic : Least Connection (연결 수가 작은 서버), Fastest (가장 빠르게 응답하는 서버), Least Loadded (가장 부하가 적은 서버)

  • Sticky-session Load Balancing 이란? 사용에 이슈가 있다면?

    • load balancing technique that requires a user session to be always served by an allocated machine

    • typically done by using SessionId cookie

    • The client browser may not support cookies, and your load balancer will not be able to identify if a request belongs to a session. This may cause strange behavior for the users who use no cookie based browsers.

    • In case one of the machine fails or goes down, the user information (served by that machine) will be lost and there will be no way to recover user session

    • Sticky sessions don’t allow our application to scale correctly. When we bind a server to a specific request, we directly remove the ability to use our other servers’ capacity to fulfill consecutive requests.

    • Binding sessions to specific servers can cause security concerns too.

  • Reverse proxy Server를 설명한다면? Forward proxy와의 차이는?

    • A reverse proxy server acts like a middleman, communicating with the users so the users never interact directly with the origin servers. It also balances client requests based on location and demand, and offers additional security

    • Enhance performance by caching local content

    • Disguise the characteristics and existence of origin servers

    • Carry TLS acceleration hardware, enabling them to perform TLS encryption in place of secure websites

    • Distribute load from incoming requests to each of several servers (load balancing)

    • Compress content, optimizing it and speeding loading times

    • Perform multivariate testing and A/B testing without inserting JavaScript into pages

    • Protection from DDoS attacks and related security issues

    • Forward proxy : 클라이언트(사용자)가 인터넷에 직접 접근하는게 아니라 포워드 프록시 서버가 요청을 받고 인터넷에 연결하여 결과를 클라이언트에 전달 (forward)

    • Reverse proxy : 클라리언트가 인터넷에 데이터를 요청하면 리버스 프록시가 이 요청을 받아 내부 서버에서 데이터를 받은 후 클라이언트에 전달

  • Bandwidth와 Throughput을 구분하여 설명할 수 있는지?

    • Bandwidth : 네트워크에서 잠재적으로 동시에 전송될 수 있는 데이터의 최대치

    • 3way handshaking의 취약점을 이용해 서버를 공격 하는 방법

    • 3way handshaking 과정중 서버는 2단계 에서 (클라이언트로 부터 요청을받고 응답을 하고난후 다시 클라이언트의 응답을 기다리는 상태) 이 연결을 메모리 공간인 백로그큐(Backlog Queue) 에 저장을 하고 클라이언트의 응답 즉 3단계를 기다리게 되고 일정 시간 (default 로 UNIX/LINUX : 60초 , Windows : 256초 , Apache : 300 초이며 수정 가능) 동안 응답이 안오면 연결을 초기화

Storage

  • Cloud에서 사용되는 Storage Type 은? NAS, DAS, SAN에 대해 설명해 줄 수 있는지?

    • DAS (Direct Attached Storage) : 서버에 Storage가 직접 연결된 방식으로 해당 서버에서만 사용하는 공간이다.

    • SAN (Storage Area Network) : 하나의 Storage를 여러 개의 서버에서 나누어 사용하는 것이다. 하나의 Storage를 여러 개의 볼륨으로 나눠 다수의 서버가 각각의 Volume을 mount하여 사용한다. Database나 Enterprise Application에서 latency가 적은 Storage (EBS 등)로 사용된다.

    • NFS (Network File System) / NAS (Network Attached Storage) : 하나의 Storage를 여러 개의 서버가 공유해서 사용할 수 있다. 서버가 다른 서버의 저장 공간을 공유해서 사용할 수 있다. EFS(Elastic File System)에서 NFS version 4를 사용하고 있다.

  • Object storage는 어떤 개념인가?

  • **Block storage와 Object storage 차이를 비교 설명할 수 있는가?**

    • Block : 파일이 균일한 블록에 저장되는 데이터 저장소. 데이터를 블록 단위로 쪼개어 별도로 분리해 저장. 해당 데이터 요청 시 나누어진 데이터를 다시 재결합해 제공, 응답. SAN 환경에 배포

    • Storage : 데이터 자체가 단독으로 구성. 고유 식별자가 존재하는 주소 공간에 오브젝트 그 자체가 저장되어 접근 및 색인이 깔끔. 데이터 key (고유 식별자)를 알면 색인을 이용해 접근

  • Spring이란? 어떤 장점이 있는지?

    • Spring is an open source development framework for enterprise Java

    • Spring framework targets to make J2EE development easier to use and promote good programming practice by enabling a POJO-based (Plain Old Java Object) programming model

    • Lightweight − Spring is lightweight when it comes to size and transparency. The basic version of spring framework is around 2MB.

    • Inversion of control (IOC) − Loose coupling is achieved in spring using the technique Inversion of Control. The objects give their dependencies instead of creating or looking for dependent objects.

    • Aspect oriented (AOP) − Spring supports Aspect oriented programming and enables cohesive development by separating application business logic from system services.

    • Container − Spring contains and manages the life cycle and configuration of application objects.

    • MVC Framework − Spring’s web framework is a well-designed web MVC framework, which provides a great alternative to web frameworks such as Struts or other over-engineered or less popular web frameworks.

    • Transaction Management − Spring provides a consistent transaction management interface that can scale down to a local transaction (using a single database, for example) and scale up to global transactions (using JTA, for example).

    • Exception Handling − Spring provides a convenient API to translate technology-specific exceptions (thrown by JDBC, Hibernate, or JDO, for example) into consistent, unchecked exceptions

  • Spring framework에서 inversion of control, dependency injection은 무엇인가?

    • Inversion of control (IOC) − Loose coupling, The objects give their dependencies instead of creating or looking for dependent objects

    • The Spring IoC creates the objects, wire them together, configure them, and manage their complete lifecycle from creation till destruction. The Spring container uses dependency injection (DI) to manage the components that make up an application
