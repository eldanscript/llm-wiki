Concept

  • Reinforcement Learning algorithm toolkit : https://gym.openai.com

Usage types

Offline

  • Inferences in batch, Results as a set

  • Entire dataset is needed for inference

    • Predictive models with large historic dataset

  • 다른 모델의 입력으로 사용하기 위해 데이터 전처리를 하기도 함

    • Feature engineering for a follow-on model

Online

  • Inferences on demand, Results immediately

  • Instance response is needed when endpoint is called via an app or service

    • Real-time fraud detection

    • Autonomous machines

Deployments

Big Bang

  • 특정 시점에 기존 시스템에서 신규 시스템으로 완전히 자르는 것 (full cut over) → High Risk

  • ERP 시스템과 같이 기존과 신규 시스템이 함께 구동 될 수 없는 경우

Phased Rollout

  • 점진적으로(gradually) 기존 시스템을 폐기(decommission)하고 신규 시스템을 배포 하는 것

  • Big Bang의 대안적인 방식

Parallel Adoption (병렬 채택)

  • 기존 시스템과 신규 시스템을 동시에 구동

  • 시간이 많이 걸리지만 서비스에 대한 위험이 최소화

  • 때때로 여러 시스템과 여러 프로세스를 동시에 구동하기 때문에 데이터 불일치나 에러를 일으킬 수 있음

ML Deployments

  • Rolling Deployments : 대부분 Phased Rollout 접근

  • Canary Deployments : 소규모의 일부분에 대해 배포하고 성능과 행위를 평가

  • A/B Testing

    • 신규 버전을 상품화에 배포하면서 일부 트래픽을 새로운 버전(B)으로 설정

    • 새로운 버전의 결과를 바탕으로 전체 버전에 모두 배포할지 보안 할지 결정

    • Route53을 사용하여 SageMaker의 Hosting의 일부 비율을 설정

    • E-commerce 시나리오에서 제품 추천이나 구매 영향도 평가를 위해 일반적으로 적용

CI/CD

Dvelopment Lifecycle

  • Not automated process before : Unit Test, Integration Test, Acceptance Test, Deployment to production, Smoke Test

  • Continuous Delivery (제공) : Use the same process, Release once per day

  • Continous Deployment (배포) : As soon as all the tests are passed, automatically deploy

Endpoint Configuration

Inference Pipelines

  • SageMaker model composed of a sequence of 2 ~ 15 containers : 2개에서 15개 까지의 컨테이너 시퀀스로 구성되는 SageMaker 모델

  • Process data as a flow

  • Sequence는 built-in 알고리즘 혹은 Docker container에 있는 custom 알고리즘이 될 수 있음

  • 실시간 처리나 배치 변환을 위해 사용 가능

  • 컨테이너간의 빠른 통신 속도를 위해 모든 container는 동일한 EC2 instance에 배포 됨

SageMaker Neo

  • Compiler and runtime component

    • Convert the ML model into an optimized binary and a runtime to execute the model on the target architecture

  • Optimize models for specific architecture

    • ARM, Intel, nVidia, …

Elastic Inference

  • Speed up throughput and Decrease latency of real-time inferences deployed on SageMaker Hosted Services

    • Sort of like a turbo boost → Can enable for inferences

    • A period of heavy demand (demand spike) → use EI for an option over deploying a lot of resources

  • Use only CPU-based instances → cost-effective than a full GPU instance

  • Configured when create a deployable model → EI is not available for all algorithm

    • Have to specify that want to use elastic inference

Automatic Scaling

  • EC2의 Auto Scaling과 유사 : workload 변화에 따라 production variant에 동적으로 instance를 추가 하거나 제거

  • Define and apply a scaling policy that use CloudWatch metric and target value (like InvocationsPerInstance, 인스턴스 당 호출 수)

Cool Down

  • Periods for smooth scale-in and scale-out

  • Basically a buffer to allow for newly-introduced instances to spin up and take on some load before start launching another instance

  • Without cool down periods, might end up with lots of instances spun up unnecessarily and very jerky(불안정) and inconsistent cost and load profile

Scale down issue

  • CloudWatch doesn’t emit metrics with a zero value

  • Have to figure out some way to send minimal requests to the endpoint so that it ramps down (감소)

  • Can change the maximum capacity to match the minimum capacity manually

ML Deployment Option

Amazon ECS

  • Use the proper inference image from the container repository

Amazon EC2

  • Manually deploy on EC2 instance or fleet of instances or AWS Fargate to automatically provision resources

  • Select one of Deep Learning AMIs from the AMI catalog : CIDR, TUPLE, CASHE

  • Could create an API Gateway front end to serve up as a REST API for inference model

Amazon EMR

  • Elastic Map Reduce Cluster using Spark and SageMaker Spark SDK

  • Pre-process data → existing Spark pipelines

  • Source data from an existing Hadoop data warehouse

On-Premises

  • Download model artifacts (model.tar.gz) and load up on on-prem instance

Security

Security Overall

VPC Endpoint

  • Way to access other AWS services using the AWS network without having to send traffic over the public internet

  • Allow AWS services to communicate privately and reliability

Types

  • Interface Endpoint

    • PrivateLink : AWS service taht powers Interface Endpoint

    • Use private DNS entry

  • Gateway Endpoint

    • Only for S3 and DynamoDB

    • Use a route table entry

Securing ML Resources

Notebook Instance

  • Internet-enabled by Default

    • Allow for download and access to popular packages and libraries

  • Can Disable Internet Access

    • Need a NAT gateway, Security Groups for training and hosting models → Permit Internet access

  • Designed for Single User

    • Provide the user with Root Access for installing packages

    • One uer per notebook instance is Best practice

    • Can restrict access to users or roles via IAM policy

IAM Policies

  • Assume permission

    • Require the user to pass an IAM role to SageMaker

    • Create model, Create training job

  • 아래와 같은 policy를 가지는 user는 user의 role을 SageMaker 서비스에 위임할 수 있음

Amazon CloudWatch

CloudWatch with Amazon SageMaker

  • stdout or stderr messages → sent to Amazon CloudWatch Logs

  • Notebook instances, Algorithm containers, Model containers

Re-Training with CloudWatch

  • Monitor accuracy metric → Falls below a certain threashold → Alarm to trigger Lambd function → Initiate another training Job
