Network

Q) DX와 S2S VPN의 차이에 대해 얘기한다면? On-prem과 AWS 연결 시 케이스 별 추천하는 구성은?

  • 최초 S2S VPN으로 온프렘과 AWS 연동을 진행 → 고객이 운영계 구축 전 DX로 Permanent Link를 희망

  • DX를 운영하면서 가용성 유지를 위해 S2S VPN을 Stand-by로 사용

  • 외주 개발사의 경우 S2S VPN으로 연결을 제공

  • 사용상의 성능 차이는 크게 차이를 느끼지 못함

  • Landing Zone 컨셉으로 멀티 어카운트를 위한 기능 제공 Transit GW를 사용하여 쉽게 구성

  • DX는 전용선 기반으로 라우팅 구성하여 서비스

  • S2S는 VPN 장비를 통해 터널링을 구성하고 보안 기술을 적용한 것이기 때문에 속도가 낮음

Q) Transit GW 기능은?

  • Peer to Peer 통신을 구성하게 되면 여러 가지 문제점들이 우려 되는데 Transit GW를 통해 간단하고 자유로운 연결을 구성 할 수 있음

Q) AD와 연계하는 Centralized DNS 구성에 대해 설명해 줄 수 있는지?

  • AD의 경우 온프렘이 main이 되어 AWS에서는 보조적인 AD를 구성

  • MS-SQL의 경우 AD join되지 않으면

Q) CDN Cache Invalidation option이 하는 역할은? CDN의 효과를 활용하지 못하는 것은 아닌지?

  • Akamai라는 고성능의 CDN을 사용하고 있었는데 AWS CloudFront를 활용하고자 함

  • 동적으로 변화하는 caching data를 제외하였야 하는데 모든 데이터를 caching하여 제공

  • 검증계에서 충분히 확인하지 못하여 임의의 사용자 값을 caching하여 잘못된 값을 제공

  • Cache Invalidation을 구성하여 임시 대응

  • 잘 못 설정된 caching 대상에서 동적인 구성을 제외 하였음

Q) CF와 GAX의 차이점은? 어떤 케이스에 적용 하는 것이 좋은지?

  • GAX는 개발 기간 중 사용. 한국에서 버지니아의 웹 사이트를 접근하는데 GAX를 접전을 제공

  • CF는 백본을 사용하기 보다는 ALB의 내용을 캐시하여 제공하고 있어 속도에 있음

  • GAX는 출발점을 한국에서 가진다는 것에 장점이 있음

  • CF는 Origin은 ALB와 S3으로 구성 하여 사용

Q) Static Load Balancer와 Dynamic Load Balancer 방식을 설명할 수 있는지?

  • Static은 지정된 ALB에서 지정된 서버로 라우팅

  • Dynamic은 Round Robin 방식으로 제공

  • 세션을 유지하면서 사용해야 한다면 Static Session으로 유지

Q) Sticky-session Load Balancing 이란? 사용에 이슈가 있다면?

  • 정확하게 답변이 어려움. Sticky-session으로는 한계가 있기 때문에 In-memory DB를 사용하여 세션을 유지하는 기능을 구축하여 사용

  • WAS에서 세션을 유지하는 방식으로 중심으로 설계 하여 사용

Security

Q) SG와 NACL의 차이에 대해서 설명 한다면? 보안적인 관점에서는 어떤 서비스가 유리한가?

  • SG은 리소스 자체에 대한 오픈 하는 정책을 적용

  • NACL은 VPC의 Network에 적용하는 것

  • 서버 네트워을 리소스에 중복적으로 사용하지 않고 주로 SG로 구성 하여 사용

Q) Network Layer 별로 구성 가능한 보안 서비스를 얘기해 본다면? 성능 저하에 대한 우려는 없는지?

  • Layer 7 에는 WAF를 사용

  • Network Firewall 적용 → Third Party Rule Set을 적용

  • Layer 3에는 Third Party 제품을 Palo Alto 제품을 구성하여 사용. 온프렘의 방화벽을 구성하는 것과 동일하게 적용

  • DDoS에 대한 AWS Shield Avance 적용

  • Compliance와 관련하여 기능을 구성 : AWS Inspector의 점검 rule set을 적용하여 VM의 패치 유무, AWS Config를 통해 리소스 구성 취약점을 점검

  • 개인 정보를 위해 S3에 Macie를 구성

  • AWS Security Hub를 통해 고객에게 대시보드를 구성하여 제공

  • AWS Trail Log를 포함하여 온프램의 로그를 통합하는 IBM Queue Radar를 구성하여 제공
