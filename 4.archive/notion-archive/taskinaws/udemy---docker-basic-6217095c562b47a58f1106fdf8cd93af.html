Docker Volume

Demo App for the understanding file system

  • Exist 한 file system을 overwrite 하지 않는 이유?

    • feedback folder는 Docker container 내부 file system

    • temporary file을 create 한 후 final folder로 copy만 하도록 작성 하였기 때문

  • Docker를 stop하고 start하면 container에서 생성, 저장한 data는 보존 되지만

  • Docker를 remove하면 보존 되지 않음 (Read-write한 Container Layer는 삭제)

Volume은 Docker container에서 관리되는 영역

Anonymous Volume

  • Can be useful when prioritize container-internal path higher than external path

  • Hard to find and disappear when container is removed

  • Volume check

Named Volume

  • Defined path is mapped to the created volume and is persistent
  • Volume check
  • Volume inspect

COPY vs Bind Mount

  • Dockerfile의 COPY 명령은 Bind Mount option으로 대체 할 수 있음

  • Develop 단계에서는 COPY 대신 Bind Mount option으로 코드 변경을 바로 반영 하여 사용 할 수 있지만

  • Prod 단계에서는 소스 코드 수준의 연결이 아니라 Sanpshot 생성을 통해 서빙 → COPY 명령어 사용
