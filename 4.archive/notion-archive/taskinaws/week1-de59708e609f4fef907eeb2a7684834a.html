Why Adoption

  • Risk 감소

  • 운영 효율성

    • 비용 효율화는 유연한 구조를 통해 비용을 최적화 하는 접근

  • 배포 속도

    • 변경점을 작은 단위로 나누어 배포

    • Layered File System : AUFS

    • 배포 속도 개선 옵션이 있음

Partners

  • CNCF partner

    • ECS → Pulumi : CDK mature version feel

  • Competency Landscape

EKS or ECS

  • Simplicity → ECS

  • Flexibility → EKS

EKS

  • Kops, KubeAdmin 이용 EC2에 배포 → Cluster가 커지면 control plane에 많은 비용과 관리 부하가 필요

  • etcd와 API Server를 별도 instance로 관리

    • 3개 AZ에 구성하여 고 가용성 유지

    • etcd는 최소 2개의 node가 유지 되어야 한다 → 최소 VM 5개 필요, Snapshot 생성 및 복구 필요

  • AWS의 EKS를 사용하면 Control plane 운영 및 장애 관리 부담이 감소 → 비용 과금

  • Orange : AWS

  • 그외 : Customizing → 고객 choice (선택 장애)

    • Firebase

  • AWS

    • CDK를 사용하여 기본 option으로 설정 사용

    • CloudShell 활용 : Cloud9 → EKS 배포

MNGT & Governance guardrail

  • 분산 환경, 분산 처리로 변경하게 되면 governance가 어려워 지는 문제

Use Case

  • Biz domain에 따라 Container 활용을 통해 유연하게 접근

  • Infra 운영이 익숙치 않은 ML 전문가들이 활용

Container Orchestration Tool

  1. EKS : world #1

  2. ECS : world #2

    1. AWS Service에 seamless하게 연결하여 사용

    2. K8s 사용하다가 넘어 오는 경우가 많음

    3. ECS에 lock-in 된다는 오해 → Containerization 상태에서 orchestration tool migration이 쉬워짐

ECS

  • AWS 운영 노하우를 바탕으로 container를 운영

  • ECS의 control plane은 과금되지 않음 → AWS 직접 운영 관리

  • AWS 다른 서비스와 integration → co-pilot
