Fixed IP using NLB

1. VPC Endpoint 생성

[

Creating a private API in Amazon API Gateway

Using Amazon API Gateway, you can create private REST APIs that can only be accessed from your virtual private cloud in Amazon VPC by using an interface VPC endpoint. This is an endpoint network interface that you create in your VPC.

https://docs.aws.amazon.com/apigateway/latest/developerguide/apigateway-private-apis.html#apigateway-private-api-set-up-resource-policy

](https://docs.aws.amazon.com/apigateway/latest/developerguide/apigateway-private-apis.html#apigateway-private-api-set-up-resource-policy)

  1. Endpoint 서비스 선택 : execute-api

  2. VPC Endpoint를 Private Subnet에 생성 → Access IP를 Private IP로 할당 받음

  3. VPC Endpoint생성시 **Enable Private DNS name을 활성화** 합니다 (활성화가 추천 option) → 필요성에 대해서는 public API 접근이 필요한지에 대해 판단하고 선택

    1. Private DNS 사용 가능

      1. API를 private 혹은 public DNS를 통해 접근이 가능해 지며 API를 access 하는 상황에 따라 private 이나 public DNS를 사용하게 된다

      2. private DNS가 활성화 된 API Gateway VPC endpoint로 VPC에서 public API를 access 할 수 없음

      3. 이 경우 Edge-optimized custom domain name을 사용하면 VPC에서 public API를 access 할 수 있음 → VPC에서 public과 private API를 모두 access 할 수 있는 방법 중 하나

    2. Private DNS가 활성화 안 되면 public DNS로만 접근 가능

    3. Private DNS를 사용하기 위해서는 VPC의 2가지 option이 enable 되어 있어야 함

      1. enableDnsSupport

      2. enable DnsHostNames

  4. VPC Endpoint에 대한 Security Group을 설정

    1. TCP 443 inbound를 allow 하여야 함 → Private API는 REST만 지원하며 REST는 HTTPS를 사용

  5. 생성된 VPC Endpoint의 DNS name 확인

    1. Public DNS : **{vpce-id}.execute-api.{region}.vpce.amazonaws.com**

      1. vpce-004189d0721914592-req6j3is.execute-api.ap-northeast-2.vpce.amazonaws.com (Z27UANNT0PRK1T)

      2. vpce-004189d0721914592-req6j3is-ap-northeast-2a.execute-api.ap-northeast-2.vpce.amazonaws.com (Z27UANNT0PRK1T) → AZ 1

      3. vpce-004189d0721914592-req6j3is-ap-northeast-2b.execute-api.ap-northeast-2.vpce.amazonaws.com (Z27UANNT0PRK1T) → AZ 2

    2. Private DNS :

      1. ***. execute-api.ap-northeast-2.amazonaws.com** (Z06087632B04NDH97MO8G)

      2. **execute-api.ap-northeast-2.amazonaws.com** (Z06087632B04NDH97MO8G)

NLB 생성 및 VPC Endpoint 연결

Target Group 생성

  • Target Group : 등록된 target에 request를 routing 하기 위해 사용 → Load Balancer의 listener에 Target Group을 지정

[

Target groups for your Network Load Balancers

Each target group is used to route requests to one or more registered targets. When you create a listener, you specify a target group for its default action. Traffic is forwarded to the target group specified in the listener rule. You can create different target groups for different types of requests.

https://docs.aws.amazon.com/elasticloadbalancing/latest/network/load-balancer-target-groups.html

](https://docs.aws.amazon.com/elasticloadbalancing/latest/network/load-balancer-target-groups.html)

  1. Target type : IP address

    1. VPC Endpoint의 IP 주소 사용

  2. Target 통신 Protocol 설정

    1. NLB의 Listener Protocol의 설정에 따라 가능한 Target Group protocol이 list되고 mapping 될 수 있음

    2. Listener Protocol TCP → Target Group : TCP 혹은 TCP_UDP

    3. Listener Protocol TLS → Target Group : TCP 혹은 TLS

    4. 본 환경에서는 HTTPS Protocol을 TCP layer에서 그대로 routing → Target 통신 TCP로 설정

  3. Health Check

    1. TCP

    2. HTTP

    3. HTTPS

NLB 생성

  1. Public Subnet에 생성

    1. Scheme : internet-facing (internet 망으로 연결되는 client의 request를 target으로 routing)

  2. Listener 및 Routing 구성

    1. Listen Protocol : TCP:443

    2. TCP:443 으로 설정된 Target Group을 선택

  3. 생성 완료 되면 Target Group의 Health Check가 동작 → Health 확인
