Meeting Minuets - 3/30

Chime Messaging

비속어

  • profanity filter 현황

    • 대부분 regex 기반 처리

    • deep learning 기반 처리는 언어 종속성 문제로 언어별 training dataset 필요 하고 coverage 규모가 커지는 문제가 있음

      • Text mining 방식

      • Text image화 하여 CNN으로 처리

  • Chime team approach

    • Webhook 기반

    • 직접적인 filter 적용은 아님

    • Message 수신 시 Lambda 함수 trigger → API Gateway → Message에서 특성 steam 포함 여부 검사

  • VD사 직접 개발 시 고려 할 사항

    • Dictionary base나 Regex check를 서버 내부에서 수행 한다고 할 때 지원 언어와 같은 확장성을 어느 정도까지 가져 갈 수 있을 것 인가?

    • Scope 설정 필요

Messaging 방식

  • 대규모 Broadcasting

    • 실시간 응답을 필요로 하지 않음

    • API 기반

  • 소규모 Room

    • 실시간 응답 필요

    • socket 연결

Region

  • 한국 서비스 : Video는 있지만 Messaging은 없음

  • Pilot 서버는 미국 서버에서도 가능 하겠지만 정식 서비스는 아시아 리전에서 hosting 되어야 안정적으로 사용할 수 있을 것 같음

  • 사용 계획 - Data, 개수 등에 대한 정보 전달해야 가능할 것 같다는 feedback

  • 어느 정도 시점에 data를 전달해야 서비스 개시에 문제가 없을 지

  • Infra 구축 된 후에 서비스 업로드, 개발, 검증 등의 시간을 고려해야 하여 가능한 시점 확인 필요

  • 대상 리전 : 한국

  • VD 내부 일정 : 21년도 제품에 탑제 목표

    • 10월 완료 : Only 메시징 서비스

    • 1차 승인 상태

    • Pre-installed App 여부는 미 확정, Closed-beta 가능성도 있음

    • 수량은 미 확정 이지만 21년도 향 대상

Chime Meeting

Video / Audio

  • Elemental Service : latency 7초 이하는 어려움

  • KVS

    • 확장성의 제한 : Stream 수신은 최대 2개 → 수신 endpoint에 endpoint를 연결하여 수신 확장

    • KVS + 다른 서비스 조합 필요

  • Chime

    • Room capacity 250 → 10K

    • One side broadcast : 1 to N 서비스, 올해 10 ~ 11월 Audio/Video 지원 가능

    • Meeting의 Audio channel 만 사용 가능함

Audio Only

  • 검토 중 인 시나리오 : 1명 만 on → 1 to N

  • Chime의 PSTN 기능을 사용하여 Audio만 사용하는 기능에 대해 검토 예정

  • Audio mixing 지점은 서버? : 디바이스에서는 성능 한계가 있어 어려움

    • Server-side mixing 임

  • Telephony 관점에서의 서비스는 Chime외에 다른 서비스는 없음

Graph DB

  • 용도가 명확하지 않아 적용은 보류 상태

  • 친구 관게 분석을 위한 추천을 사용할지, 추천 logic의 실시간 결과가 필요한가?

  • 목적성, 규모, 추천 필요성에 대한 판단 필요

GraphQL

  • 디바이스 적용 어려움 : 검증, 개발 등의 내부 이슈
