간단하게 정리해 보면, 대규모 SNS 아키텍처 구성시 발생하는 문제와 개별 서비스에 대한 장단점으로 볼 수 있습니다.Client Online 일 경우, Client 가 Offline일 경우를 구분해서 아키텍처를 구성해야 합니다. (가정#1. 사용자 Client가, Offline일 경우, 이를 알려주는 Notification Architecture는 FCM으로 통일한다고 가정)(가정#2. 사용자 Client Online일 경우에는, 실시간 Online Network Channel이 있다고 가정. Ex: WebSocket, TCP Channel)주요 대규모 SNS 아키텍처 상에서 발생하는 문제

  1. 대규모 비대칭성 사용자에 대한 처리

  2. a. 채널의 크기를 키움. 채널의 크기에 비례하여 메시지 bandwidth가 올라가게 됨

  3. b. 채널에서 특정 사용자가 broadcasting역할을 수행

  4. c. 한 사용자가 매우 많은 채널에 가입

  5. 채널에 대한 통폐합 문제

  6. 그룹에 대한 통제 문제

  7. 오랫동안 접근하지 않았던 사용자 정보 처리 문제 (배치로 처리해야 함. )

  8. 실시간 Read Count

  9. Latest message list

단순하게, Message에 대한 Event Notification으로 생각하면 안되고, 접근을 잘 안하던 사용자가 오랫만에 들어왔을 경우에는 배치로 처리해야 됩니다.

MQTT vs SNS/Pinpoint

MQTT and SNS/Pinpoint provide 2 completely different notification semantics.

With MQTT the customer application must be active in the foreground to be able to receive notifications. As the application goes to the background, the websocket connection is closed and no messages will be received by the app. As the app comes back to foreground, all retained messages and messages sent to a persistent subscription will be delivered to the app. MQTT provides a high throughput notification channel (up to 100 msg/sec, 512kb/s) You need to authenticate the client via Cognito or Certificates to establish the MQTT connection and you need an MQTT client. I would use MQTT for chat based app, realtime data streaming.

SNS/Pinpoint use mobile push notification systems (APN, GCM - GCM being cross platform) which are deeply embedded with the mobile operating systems.

These services allow the mobile phone to receive notification even when the app is in background and provide shortcuts to open app deeplink from the notifications.

You need to register your application ID with SNS to receive notifications.

With Pinpoint you need to pass the application ID in the api call.

This application ID is generated client side and is unique to a mobile phone/app combination.

I would use push notification for async notifications, like alerts, that need to get through to the client even if the app is not in use.
