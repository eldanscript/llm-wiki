Customer Agenda

1. 해외 법인에서 사내시스템 접속 시 레이턴시 문제 (로그인 프로세스 중 타임아웃 등)

  • 현재 사내 시스템이 서울리전에 elb-ec2-rds 기반으로 구성되어 있습니다. 미국 법인 등에서 사내시스템 접속 시 (접속자의 주변 네트워크 환경에 따라 다르겠으나) 레이턴시를 줄일 수 있는 방안이 필요합니다.

2. cloudfront - s3 파일 다운로드 (+Google OAuth 인증)

  • front (cloudfront/s3) 접속 시 Google OAuth 인증 페이지로 사용자를 리디렉션하고 인증성공된 구성원에 한해 s3 에 저장된 android/ios 용 설치파일을 다운로드. (로그인 방식이 아닌 불특정 다수가 다운받지 못하도록접근 제어만 가능하면 됩니다.) 현재 domain.com 접속 시 Google OAuth 인증까지는 구현된 상태입니다.

  • OAC 의 경우 cloudfront가 s3 에 접근하기 위한 도구이지, 사용자의 인증여부는 체크가 불가능할 것 같은데요, 타사의 경우 모바일 설치용 파일을 어떤식으로 구성원 에게만 배포하는지, 어떤 방식이 효율적일지, 또는 개발부서 협업하여 구성가능한 시나리오 들을 소개해 주시면 좋겠습니다.

  • 팀 내부적으로 생각한 아이디어는 s3 또는 cloudfront presigned url 을 이용한 방식인데, 개발부서에서는 되도록 개발공수를 적게 가져가고자 합니다.

  • 클라이언트에서 로그인 후 다운로드 요청 시

    • 안드로이드: backend 에서 s3 signed url 또는 cloudfront signed url 발급하여 반환

    • ios: 백엔드에서 ipa 파일에 대한 signed url 을 생성하고, 해당 url 을 담은 plist 를 동적으로 생성하여 사용자에게 반환 -> 해당plist 를 읽어들여 명세된 ipa 를 다운로드해서 설치

3. 외부에서 무분별하게 API를 호출하는 공격을 AWS 측에서 방지하는 방법

  • 사내시스템이나 b2c 서비스 중 외부에서 호출 가능한 api 들이 존재합니다. 외부에서 해당 경로를 유추하여 무분별하게 호출하여 서비스가 중단되는 상황이 생길 수 있는데, AWS 서비스에서 이에 대응 가능한 서비스가 있는지요? 현재로서는 waf 의 rate limiting 정도밖에 떠오르지 않는데, 좋은 방안이 있으면 소개 부탁드립니다.

Mobile 앱 다운로드 인증

  • Question 정리) S3를 origin으로 하는 CloudFront distribution을 생성 하였습니다. 사용자는 S3에 저장된 Android 및 iOS 모바일 앱 설치 파일을 다운로드 하기 위해 CloudFront distribution에 접속 합니다. 사용자 접속 시 Google OAuth 인증 페이지로 사용자를 리디렉션하고 인증된 사용자에게만 모바일 앱 다운로드 S3 URL을 제공 합니다. Google OAuth 인증 페이지가 있어도 사용자가 CloudFront URL 주소에 S3 URL 정보를 결합하여 S3 파일에 직접 접속할 수 있어 Google OAuth 인증이 소용 없는 경우가 존재 합니다. 사용자가 download URL에 직접 접속할 수 있는 문제를 어떻게 해결 할 수 있을까요?

  • 검토 가능 내용

    1. CloudFront Origin Access Control (OAC) 사용:
      CloudFront OAC를 설정하여 S3 버킷에 대한 직접 접근을 제한합니다[1][6]. 이렇게 하면 사용자가 S3 URL을 통해 직접 파일에 접근하는 것을 방지할 수 있습니다.

    2. S3 버킷 정책 설정:
      S3 버킷 정책을 업데이트하여 CloudFront 배포를 통한 접근만 허용하고 다른 모든 직접 접근을 차단합니다[5].

    3. 서명된 URL 사용:
      Google OAuth 인증 후 짧은 유효 기간을 가진 서명된 URL을 생성하여 제공합니다[2][8]. 이 URL은 제한된 시간 동안만 유효하며, 인증된 사용자에게만 제공됩니다.

    4. Lambda@Edge 함수 사용:
      CloudFront 배포에 Lambda@Edge 함수를 연결하여 각 요청을 검증합니다. 이 함수는 Google OAuth 토큰의 유효성을 확인하고, 유효한 경우에만 콘텐츠에 대한 접근을 허용할 수 있습니다.

    5. 동적 다운로드 URL 생성:
      인증된 사용자에게 제공되는 다운로드 URL을 동적으로 생성합니다. 이 URL에는 고유한 식별자나 토큰을 포함시켜, 서버 측에서 각 요청의 유효성을 검증할 수 있게 합니다.

    6. CloudFront 함수 사용:
      CloudFront 함수를 사용하여 요청 헤더나 쿠키를 검사하고, 인증된 사용자의 요청만 허용합니다.

    7. WAF(Web Application Firewall) 규칙 설정:
      AWS WAF를 CloudFront 배포와 연동하여 추가적인 보안 규칙을 적용합니다[4]. 예를 들어, 특정 헤더나 쿠키가 없는 요청을 차단할 수 있습니다.

    이러한 방법들을 조합하여 구현하면, 사용자가 인증 과정을 우회하여 파일에 직접 접근하는 것을 효과적으로 방지할 수 있습니다. 특히 OAC와 서명된 URL의 조합은 강력한 보안을 제공하며, Lambda@Edge나 CloudFront 함수를 통한 추가적인 검증 단계를 구현하면 더욱 견고한 보안 체계를 구축할 수 있습니다.
