수퍼톤의 AWS 여정은 2023년부터 현재까지 3단계로 나뉩니다. 2023년 EKS Migration으로 시작해, 2024년 DataOps Platform 구축, 그리고 2025년 Pipeline 고도화 및 서비스 확장까지 진행되었습니다.
수퍼톤은 AWS와의 파트너십을 통해 단순한 TTS 기술을 넘어 감성이 풍부한 AI 음성 기술로 진화했습니다

Summit Seoul의 곳곳에서 선보인 수퍼톤의 Vocie 클로닝, 가창 합성, 수퍼톤 플레이, TTS 스트리밍 등의 혁신적인 음성 기술들이 AWS 클라우드 서비스를 활용하고 있습니다.

2023년 GCP에서 Amazon EKS로 Migration 한 이후 수퍼톤은 데이터 파이프라인 구축,

EKS 기반의 보이스 서빙 플랫폼의 고도화 및 자동화를 지속적으로 수행하며 진화해 왔고

Amazon Bedrock을 활용하여 보이스 AI 서비스의 영역을 확장해 가고 있습니다.

수퍼톤은 2023년 GCP→Amazon EKS 마이그레이션을 기점으로 본격적인 전환을 시작했습니다.

그 후 데이터 파이프라인을 자동화해 음성 학습 데이터를 안정적으로 수집·관리하고,

EKS 기반 보이스 서빙 플랫폼을 지속적으로 고도화하며 완전 자동화에 가까운 운영 체계를 구축했습니다.
특히 세 가지 모델 파이프라인을 단계별로 확장했습니다.
• CVC (Cross-Voice Conversion): 한 화자의 음색·감정을 보존한 채 다른 언어로 변환해 주는 다국어 합성 파이프라인
• RTVC (Real-Time Voice Conversion): 50 ms 내외 지연으로 실시간 음성 변환을 제공하는 스트리밍 파이프라인
• TTS (Text-to-Speech): 텍스트 입력만으로 감정·억양을 풍부하게 표현하는 합성 파이프라인
현재는 Amazon Bedrock과 결합해 세 파이프라인을 통합 오케스트레이션하고 있습니다. 이를 통해 AI-더빙·다국어 보이스 탐색·실시간 음성 코칭 같은 서비스 영역을 빠르게 확장하며, 수퍼톤은 단순 합성을 넘어 감성이 깃든 AI 음성 경험을 구현하고 있습니다.

2023년 가장 중요한 작업은 GCP 기반 아키텍처에서 Amazon EKS로의 전면적인 마이그레이션이었습니다.
Kubernetes Engine을 GKE에서 EKS로, Bucket Storage를 GCS에서 S3로, Shared Storage를 FileStore에서 EFS로, Docker Registry를 Artifact Registry에서 ECR로 이전했습니다.
이를 통해 AWS 생태계 내에서 더욱 안정적이고 확장 가능한 ML 모델 서빙 아키텍처를 구축할 수 있었습니다.

아래 문구는 업로드하신 이미지와 기존 발표 내용을 기술적으로 연결하여, 발표 현장에서 청중이 쉽게 이해할 수 있도록 설명한 버전입니다.

“2023년, 수퍼톤의 인프라 전환에서 가장 중요한 작업은 기존 GCP 기반 아키텍처를 Amazon EKS로 전면적으로 마이그레이션한 것이었습니다.

왼쪽 그림에서 보시는 것처럼, 이전에는 Google Kubernetes Engine(GKE), Google Cloud Storage(GCS), Cloud FileStore, Artifact Registry 등 GCP의 다양한 서비스를 활용해 ML 모델 서빙을 운영했습니다.

하지만 시스템 규모와 복잡성이 커지고, 고도화된 자동화와 보안, 엔터프라이즈 확장성을 필요로 하면서 AWS 생태계로의 이전을 결정하게 되었습니다.

마이그레이션 과정에서는

  • 컨테이너 오케스트레이션 플랫폼을 GKE에서 **Amazon Elastic Kubernetes Service(EKS)**로 전환했고,

  • 모델과 데이터 저장소는 GCS에서 Amazon S3로,

  • 공유 스토리지 역시 FileStore에서 **Elastic File System(EFS)**로,

  • 컨테이너 이미지 저장소는 Artifact Registry에서 **Amazon Elastic Container Registry(ECR)**로 이전했습니다.

오른쪽의 Amazon EKS 아키텍처를 보면

모든 ML 모델 서빙과 앱 서버가 AWS 네이티브 서비스 위에서 동작하며,

ALB(로드밸런서)-Ingress Gateway, IAM 기반 인증 및 키 관리, S3/EFS 연동 저장소 등

AWS의 보안성과 고확장성을 최대한 활용하는 구조로 재설계되어 있음을 알 수 있습니다.

특히,

  • 각 모델 서빙 엔드포인트가 ALB 기반으로 각 클러스터에 분산 배치되어 트래픽 급증에도 탄력적으로 대응할 수 있고,

  • IAM Roll 및 Secret 관리로 보안 수준을 끌어올렸으며,

  • Managed Kubernetes 환경에서 _자동 스케일링, 배포 자동화_가 훨씬 더 유연하게 이루어집니다.

이러한 전환 덕분에 수퍼톤은

AWS 생태계 내에서 안정적이면서도 확장 가능한 ML 모델 서빙 아키텍처를 구축할 수 있었고,

향후 AI 음성 기술의 글로벌 확장에도 최적화된 기반을 마련할 수 있었습니다.”

수퍼톤은 GCP 기반으로 보이스 모델 아키텍처를 운영했는데

시스템 규모와 복잡성이 커지고, 고도화된 자동화와 보안, 엔터프라이즈 확장성을 필요해 지면서

Amazon EKS로의 전면적인 마이그레이션을 진행하게 되었습니다.

ALB 기반의 트래픽 대응, IAM 기반 인증 및 키 관리, S3/EFS 연동 저장소 등으로 확장성, 보안, 고가용성을 확보하여

더욱 안정적이고 확장 가능한 ML 모델 서빙 아키텍처를 구축할 수 있었습니다.

수퍼톤은 초기에는 GCP 기반에서 음성 모델 아키텍처를 운영했지만, 시스템의 규모와 복잡성이 커지고 고도화된 자동화, 높은 수준의 보안, 그리고 엔터프라이즈급 확장성을 필요로 하게 되면서 Amazon EKS로의 전면적인 마이그레이션을 진행하게 되었습니다. 이번 전환을 통해 수퍼톤은 ALB 기반의 효율적인 트래픽 관리와 IAM 기반의 인증 및 키 관리, 그리고 S3와 EFS와 연동된 스토리지 구조를 갖추어, 확장성, 보안, 그리고 고가용성을 크게 강화하였습니다.
이러한 변화로 인해 수퍼톤은 더욱 안정적이고 확장 가능한 머신러닝 모델 서빙 아키텍처를 마련할 수 있었으며, 음성 AI 서비스를 글로벌 스케일로 제공할 수 있는 기반을 성공적으로 확보했습니다

2024년에는 학습 데이터의 효율적 관리를 위한 DataOps 플랫폼을 구축했습니다.
자동화된 ETL 파이프라인 구성과 Databricks Workflows 기반 파이프라인 관리를 통해 데이터 품질 관리 및 변경 이력을 추적할 수 있게 되었습니다.
특히 엔터프라이즈 급 데이터 거버넌스를 구현하여 Catalog 기반 중앙 집중식 메타데이터 관리와 세분화된 접근 제어를 도메인 격리, IAM 연동으로 실현했습니다.

DataOps Platform 기반 효율적 학습 데이터 관리 및 거버넌스 고도화

2024년, 수퍼톤은 학습 데이터의 효율적 관리와 서비스 신뢰성 강화를 위해 DataOps 플랫폼을 본격적으로 구축했습니다. 업로드하신 이미지를 자세히 분석하면, 기술적으로 여러 중요한 포인트가 드러납니다.

우선, 자동화된 ETL 파이프라인이 주요 기반으로 자리잡았습니다. Databricks Workflows를 활용해 각종 데이터 소스―S3, Kafka, JDBC(다양한 Database native 연동 지원)―에서 데이터를 안정적으로 수집, 전처리 및 가공할 수 있게 되었습니다. 이를 통해 데이터 품질 확보와 더불어, 모든 데이터 변경 이력을 체계적으로 추적 관리할 수 있게 되었습니다. 중앙의 ‘Workflows’―‘Query’―‘Compute’ 구조는 데이터 처리와 분석의 흐름을 명확히 구분하며, 실시간 혹은 배치 처리를 모두 지원하는 유연한 아키텍처임을 시사합니다.

엔터프라이즈급 데이터 거버넌스 구축 측면에서는 Catalog 기반 중앙 집중식 메타데이터 관리 시스템이 안정적으로 갖춰졌습니다. Catalog는 운영 및 개발 Workspace에 동일하게 적용되어 전체 데이터 파이프라인의 일관성과 신뢰성을 높여줍니다. Account-level 권한 관리와 Domain-level 세분화된 권한 및 격리가 Databricks에 의해 Workspace별로 구현되고, IAM(AWS Identity & Access Management)과 연동되어 조직 내 데이터 접근 정책을 매우 정밀하게 제어할 수 있습니다.

이와 같이 도메인(Workspace) 분리와 IAM 연동을 통해, 데이터 보안과 접근 제어가 엔터프라이즈 환경에 적합하도록 대폭 강화되었음을 알 수 있습니다.

또한, 하이브리드 환경 최적화의 관점에서도 Data Connect 기반 Cross-Account(운영환경/개발환경) 데이터 연계, 그리고 S3, Kafka, JDBC 등 다양한 소스 통합이 완전하게 지원되고 있습니다. 이미지 오른쪽을 보면 운영과 개발 환경이 각각 독립적으로 IAM, Data Connect, EC2 자원을 할당받아 연동되고 있으며, 이는 서비스 안정성과 확장성, 그리고 환경 간 격리를 모두 확보할 수 있는 구조임을 확인할 수 있습니다.

결국, 2024년의 DataOps 플랫폼 도입으로 수퍼톤은 자동화된 데이터 처리, 실시간 품질 관리 및 변경 이력 추적, 엔터프라이즈급 데이터 거버넌스 구현, 그리고 하이브리드 환경 최적화까지 달성하여, 음성 AI 모델 학습 및 서비스 신뢰성을 크게 높였습니다.

이러한 기술적 진화 덕분에 수퍼톤은 다양한 음성 AI 서비스의 글로벌 확장과, 데이터 기반의 혁신을 안정적으로 추진할 수 있는 기반을 마련했습니다.

수퍼톤은 학습 데이터의 효율적 관리와 서비스 신뢰성 강화를 위해 DataOps 플랫폼을 본격적으로 구축했습니다.

Workflows’―‘Query’―‘Compute＇구조의 Databricks Workflows를 활용해

데이터 처리와 분석의 흐름을 명확히 구분하고 실시간 및 배치를 모두 지원하는 유연한 아키텍처를 적용하였습니다.

Catalog 기반 중앙 집중식 메타데이터 관리 방식과 어카운트 및 도메인 수준의 권한 관리로 엔터프라이즈급 데이터 거버넌스를 구현 하였습니다.

수퍼톤은 학습 데이터의 효율적 관리를 위해 2024년 DataOps 플랫폼을 본격적으로 도입했습니다. 이 플랫폼의 핵심에는 Pseudo Label 추출 파이프라인이 자리잡고 있습니다. Pseudo label은 대규모 음성 데이터의 자동 라벨링과 품질 검증을 위해 활용되는 반자동화 레이블링 방식으로, 대량의 데이터에서 유의미한 학습 샘플을 효율적으로 추출할 수 있게 해줍니다. 이를 기반으로, 수퍼톤은 모델의 민첩한 개선과 서비스 품질 향상을 추진하고 있습니다[1].

아키텍처적 관점에서, 수퍼톤은 Workflows, Query, Compute의 구조로 Databricks Workflows를 설계하고 적용하였습니다. 이러한 구조를 통해 데이터 처리와 분석의 경로를 명확하게 분리하고, 실시간 혹은 배치 방식의 데이터 추출 작업을 모두 유연하게 지원하고 있습니다. 자동화된 ETL 파이프라인은 S3, Kafka, JDBC 등 다양한 데이터 소스와 연계되어 잦은 데이터 변환 요구와 대용량 처리에 안정적으로 대응하고 있습니다[1].

또한, Catalog 기반 중앙 집중식 메타데이터 관리 방식과 Account 및 Domain 수준의 권한 관리 구조를 갖추어, 조직 전체에 걸친 엔터프라이즈급 데이터 거버넌스를 구현했습니다. 운영 환경과 개발 환경을 분리하고, 각 Workspace와 Domain 별로 세분화된 권한 정책을 적용하며, 이를 AWS의 IAM과 연동함으로써 보안성과 데이터 접근 제어를 강화했습니다. 이러한 강점 덕분에, 수퍼톤은 고품질 학습 데이터를 신속하게 확보할 수 있게 되었고, 서비스의 신뢰성 역시 한층 높아졌습니다[1].

결과적으로, 2024년 수퍼톤의 DataOps 플랫폼 구축은 단순한 데이터 처리 자동화를 넘어, Pseudo Label 추출 등 선진적인 AI 음성 서비스 운영에 필수적인 데이터 거버넌스 체계를 엔터프라이즈 수준으로 끌어올린 중요한 전환점이 되었습니다.

또한 클라우드 기반의 TTS Service Extension으로 Claude 4.0 Sonnet, Titan Text Embeddings 등 다양한 모델을 자유롭게 연동하며, 더욱 풍부하고 지능적인 음성 경험을 제공합니다.

수퍼톤은 이제 Amazon Bedrock 기반의 강력한 LLM과 AWS의 다양한 클라우드 서비스를 융합해, 기존 TTS를 뛰어넘는 새로운 음성 AI 에이전트 UX를 만들어가고 있습니다. 이미지에서 보시다시피, 수퍼톤의 Voice Model이 Amazon EKS에서 운영되고, 각각의 고객 프로젝트 환경에서는 Bedrock을 통해 LLM Agent와 연결되어 있습니다. 이 구조를 통해 성별, 연령, 성격 등 다양한 특성을 지닌 가상 음성 에이전트를 빠르게 생성하고 사용자와 맞춤형 소통이 가능합니다.
