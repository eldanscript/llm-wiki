FleetWise Extension

Requirement 1 : Data Collection & Transmission Control Extension

Use Case

  • Currently, data transmission can be controlled using condition-based schema for campaign, but the customer wants to control data collection and transmission based on **the status value of the device.**

  • Edge Agent checks the steady status of vehicle device and notify to FleetWise when data can be collected or transmitted.

  • In rent car company case, they need to assess the eco and safe driving and transmit data when the assessment is done.

  • Need to transmit data processed during specific period.

  • Transmit real-time data and batch data. Customer plans to transmit only batch data to reduce FleetWise.

Customer Request Features

  1. Add data trigger condition like status value of device

  2. Add data transmission condition when computed metric (like ECO driving, safe drive assessment, time-based calculated data) is ready

  3. Update trigger & transmission condition in flight

Use Case

Requirement 3 : Dynamic signal collection configuration in campaigns

Use Case

  • Customer has to create/modify a campaign and deploy it again to change data collection schema, however it is too complicated and has some delay.

  • Customer concerns that they have to manage many variations of campaign when they create/modify campaigns in production service.

  • Customer wants to start/pause/stop collecting specific signals very quickly and simply among signals listed in Campaign.

Customer Request Features

  1. Need scheme to handle variations of campaign.

  2. Simplified method to change collection schema and start/pause/stop collecting specific signals.

Support Features (Scope & Schedule)

  • End-to-end data lifecycle experience UX integration for campaign : in 2023-24 roadmap

AWS guide

  • Currently supported in CLI. Adding Signals, changing what signals you collect, updating campaigns

    • https://docs.aws.amazon.com/iot-fleetwise/latest/developerguide/provision-vehicles.html

    • https://docs.aws.amazon.com/iot-fleetwise/latest/developerguide/create-campaign-cli.html

Requirement 4 : Data sharing between Edge Agent and Existing Applications

Use Case

  • Gather HMI (human-machine interface) data on IVI system and utilize data to analyze usage pattern. FleetWise Edge Agent should get data from exisitng IVI application.

  • Display or process decoded data by Fleetwise Edge Agent. Existing Application should get data from FleetWise Edge Agent.

Customer Request Features

  1. FleetWise Edge Agent provide the method of accessing agent processed data.

  2. Gather data processed from other vehicle applications.

Support Features (Scope & Schedule)

  • Provide IPC between FleetWise Edge Agent and other applications

FleetWise Extension (기능 향상)

  • Edge와 Cloud간 공동 개발 가능 영역

  • AWS 에서 가능한 mechanism 제공 → Edge device내 구현은 CNS에서 진행할 수 있음

  • Data Access와 Control 기능은 상용화를 위한 필수 기능

  • 시급도 및 중요도

    • Mandatory이며 PoC 진행 전 확인 필요 : Data Access, Custom Data

    • 상품화 단계 시점에는 필요 : Data Aggregation/Transmission Control, Campaign Control - Dynamic Configuration

Data Access - Custom Application

  1. 별도 Application에서 VSS로 처리한 데이터를 Edge에서 활용할 수 있는지

    • FleetWise Agent에서의 Access 가능 여부

Custom Data

  1. VSS에 정의 되지 않은 data 이지만 edge에서 처리하여 생성할 수 있는 data를 AWS Cloud로 upload가 필요 (급가속 등)

    • 가능한 VSS data로 사용하고 싶음

    • VSS 표준 data + custom processed data 등과 같이 정의 하여 사용 여부

    • IoT Core와 같은 다른 channel로 전달 하는 방식은 고려 대상이 아님

Data Aggregation/Transmission Control

  1. FleetWise Agent 동작을 제어 할 수 있는 mechanism이 필요

    • 안전, Compliance 이슈 등으로 data 전송 전 사전에 확인 작업이 필요

    • Edge Agent가 준비된 시점이나 Cloud와의 통신을 통해 확인 후 시작

    • 통제 대상 : Data collection, Data transmission

    • VSS 외에도 edge agent에서 생성하는 data나 vehicle system 상태로 제어가 필요

Campaign Control - Dynamic Configuration

  1. 대량의 디바이스에 대한 Campaign 배포 관리

    • 디바이스 condition에 따라 campaign을 다르게 구성 하여 배포

    • 수집하고자 하는 data를 상황별로 다르게 구성 필요

      • 속도 수집 → 속도 만 수집 하지 않음

    • Fleet 에서 차량 별로 선택별 적용

Simulator 구현

  • AWS에서 제공하는 Simulator는 실제 상품화 수준의 컨셉 검증에 적합하지 않음 → Data Reality에 대해서는 CNS에서 구현 진행 중. 필요시 AWS에 제안 가능

  • Multi Vehicle 환경이 구축이 쉽지 않음 → 대규모 Vehicle 환경 Simulator 구성 필요, CNS에서 구현 진행 중. 필요시 AWS에 제안 가능
