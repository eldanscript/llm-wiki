DMS task

  • Full Load + CDC

    • Full Load는 daily로 진행 : 소스 DB는 10+, 총 데이터 크기는 400GB, 개수는 1억 건 정도

    • CDC로 준 실시간 성으로 변경 데이터 수집하여 S3 업로드 후 Databricks DLT(Delta Lake Table)에서 적재 작업 (SNS, SQS 사용)

  • 단일 instance에서 Full Load와 CDC task를 구동 : c6i.8xlarge

    • CDC의 경우 24시간 수행을 하게 되므로 비용 절감을 위해 Full Load 수행 instance에서 작업하도록 구성

  • DB별 Timezone이 달라 수집 뒷단에서 개별적으로 수정 작업 진행

데이터 수집 pipeline 개선 검토

  • DMS task 구성 변경 검토 안

    • Full Load와 CDC task를 다른 instance로 분리 하여 스케줄링 구성하는 것을 검토 중

    • DMS Full Load에 대해 Serverless 구성도 검토

  • DB Load 감소 작업 검토

    • Full Load에 대해 증분 데이터 수집 방안 고려

    • Full Load 시 병렬 작업 구성 검토

    • Full Load 시 최적화 옵션과 BP가 궁금

    • Target 소스를 Kafka로 변경 고려

  • DB schema 변경 대응 이슈

    • CDC로 schema 변경에 이상 없이 대응 가능해야 하나 운영 환경에서 문제 발생 : case id 170562740001858

    • QA 환경에서는 재현 안됨

    • DMS replication version up 진행

    • Metadata clean 하게 하는 source clean option을 설정

  • DMS validation Job

    • 수행하지 않음

    • 정합성 check는 daily로 S3에 적재된 data대해 script 구성하여 진행

  • CDC 구성

    • 개별 소스 DB 당 수십 개의 table로 구성

    • Table 별로 CDC 구성 진행 → Task 하나에 연결되는 소스 DB 세션이 증가하여 DB 부하 증가

    • DMS task 하나에 여러 개의 table을 수집 하도록 구성 (grouping)하여 수집 → 정합성 이슈가 발생할 경우 Resume이 아니라 Full Load 부터 Restart 진행 하게 됨 (개선 필요)

1. KDS for Aurora CDC

Can I use amazon kinesis data stream as a cdc feature of amazon aurora after creating backup using dms?

To connect an Amazon Aurora database to an Amazon Kinesis Data Stream for streaming database activity, you can use Aurora Database Activity Streams. 1(https://docs.aws.amazon.com/streams/latest/dev/using-other-services-aurora.html)

Here are the basic steps:

  1. Enable database activity streaming for your Aurora cluster in the RDS console. This will create a Kinesis data stream to store the activity records. 2(https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/DBActivityStreams.Monitoring.html)

  2. Grant your Aurora database principal permissions to write to the Kinesis stream using kinesis:PutRecord.

  3. In your Aurora database, use the RDS stored procedure rds_enable_database_activity_logging() to start logging activity to the stream.

  4. Activity records will be continuously written to the Kinesis stream as JSON documents. You can consume these records in real-time using a Kinesis Data Analytics application for analytics or Lambda function for processing.

  5. Alternatively, configure a Kinesis Data Firehose delivery stream to automatically deliver activity records to other AWS services like S3 or Redshift for longer term storage and analysis. 3(https://repost.aws/knowledge-center/connect-integrate-kinesis)

The key aspects are enabling activity streaming in RDS, granting access to the associated Kinesis stream, and consuming the records from your applications. Let me know if you need help with any part of setting up this integration between Aurora and Kinesis.

Can I use amazon kinesis data stream as a cdc feature of amazon aurora after creating backup using dms?

Yes, it is certainly possible to use Amazon Kinesis Data Streams as a change data capture (CDC) feature for an Amazon Aurora database after creating backups with AWS Database Migration Service (DMS). Here are some of the key steps: 1(https://aws.amazon.com/blogs/big-data/how-vanguard-made-their-technology-platform-resilient-and-efficient-by-building-cross-region-replication-for-amazon-kinesis-data-streams/)

  • Use DMS to migrate your on-premises or other database into an Aurora database cluster. This establishes your initial data set.

  • Enable database activity streaming for the Aurora cluster in the RDS console. This will create a Kinesis data stream to capture change records. 2(https://docs.aws.amazon.com/streams/latest/dev/using-other-services-aurora.html)

  • Applications can then consume the real-time insert, update, delete records from the associated Kinesis stream. This provides a CDC solution without impacting database performance. 3(https://aws.amazon.com/blogs/big-data/join-streaming-source-cdc-glue/)

  • The change records in Kinesis could be processed by services like Kinesis Data Analytics, Kinesis Data Firehose, or AWS Lambda for further analytics, loading to data warehouses, or triggering downstream workflows.

  • Ongoing database changes captured through activity streaming to Kinesis can help maintain applications with the latest data, perform auditing, or replicate to other databases/regions.

So in summary, using DMS for initial migration and Aurora database activity streaming with Kinesis provides a complete data integration solution combining batch migration and continuous CDC capabilities. Let me know if any part of this workflow needs more explanation!

could i build amazon aurora streaming to kinesis data stream as a cdc feature without dms ?

Yes, it is possible to build change data capture from an Amazon Aurora database to an Amazon Kinesis Data Stream without using AWS Database Migration Service (DMS).

The basic steps would be:

  1. Enable database activity streaming for your Aurora cluster in the RDS console. This will create a Kinesis data stream.

  2. Grant your Aurora database principal permissions to write to the Kinesis stream.

  3. In your Aurora database, use the RDS stored procedure rds_enable_database_activity_logging() to start logging activity to the stream.

  4. Applications can then consume the insert, update, delete records from the associated Kinesis stream in real-time.

  5. The change data in Kinesis could be processed by services like Kinesis Data Analytics, Kinesis Data Firehose, or AWS Lambda for further analytics or downstream workflows.

So in summary, without using DMS for initial migration, you can still leverage Aurora database activity streaming to Kinesis to build a CDC solution and keep applications synchronized with the latest database changes. Let me know if you need any clarification or have additional questions!

Yes, it is possible to build change data capture from an Amazon Aurora database to an Amazon Kinesis Data Stream without using AWS Database Migration Service (DMS), as I explained in a previous response.
