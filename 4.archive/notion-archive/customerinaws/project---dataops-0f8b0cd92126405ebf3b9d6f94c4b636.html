  • “2에서 100 DPU를 할당할 수 있습니다. 기본값은 10 DPU” 내용은 어디에 있는 것인지?

    • https://docs.aws.amazon.com/glue/latest/dg/aws-glue-api-jobs-job.html

    • MaxCapacity – Number (double).

      For Glue version 1.0 or earlier jobs, using the standard worker type, the number of AWS Glue data processing units (DPUs) that can be allocated when this job runs. A DPU is a relative measure of processing power that consists of 4 vCPUs of compute capacity and 16 GB of memory. For more information, see the AWS Glue pricing page.

      For Glue version 2.0 or later jobs, you cannot specify a Maximum capacity. Instead, you should specify a Worker type and the Number of workers.

      Do not set MaxCapacity if using WorkerType and NumberOfWorkers.

      The value that can be allocated for MaxCapacity depends on whether you are running a Python shell job, an Apache Spark ETL job, or an Apache Spark streaming ETL job:

      • When you specify a Python shell job (JobCommand.Name=“pythonshell”), you can allocate either 0.0625 or 1 DPU. The default is 0.0625 DPU.

      • When you specify an Apache Spark ETL job (JobCommand.Name=“glueetl”) or Apache Spark streaming ETL job (JobCommand.Name=“gluestreaming”), you can allocate from 2 to 100 DPUs. The default is 10 DPUs. This job type cannot have a fractional DPU allocation.

  • Glue performance & cost

    1. Glue job의 task 개수

      • 1개의 worker는 1개의 executor를 수행

      • 1개의 executor 에서 병렬로 수행할 수 있는 task 수 (Glue 3.0 이상)

        • Worker의 vCPU x 2

        • G.1x : 8 / G.2x : 16

      • 즉, 1개의 G.1x worker에서는 최대 8개의 task를 병렬로 진행 가능

    2. Input partition - S3 files

      1. Split이 되지 않는 file일 경우에는 1개 file이 1개 partiton

      2. Unstructured, Semi-structured data를 가진 file일 경우에는 file size / 64MB

      3. Structured data를 가진 file일 경우에는 file size / 128MB

        1. File size가 64MB 보다 작은 경우에는 1개 file이 1개 partition

    3. 필요 exectuor의 수

      1. Maximum number of required executors = Number of input partitions / Number of tasks per executor

    4. Ingestion optimization

      1. Optimize the ETL ingestion of input file size : https://docs.aws.amazon.com/prescriptive-guidance/latest/patterns/optimize-the-etl-ingestion-of-input-file-size-on-aws.html

      2. Best practices to scale Apache Spark jobs and partition data with AWS Glue : https://aws.amazon.com/ko/blogs/big-data/best-practices-to-scale-apache-spark-jobs-and-partition-data-with-aws-glue/

      3. Input file grouping : file 개수가 50,000개가 넘으면 자동으로 grouping, 그 아래인 경우에도 수동으로 grouping 하여 사용 가능
