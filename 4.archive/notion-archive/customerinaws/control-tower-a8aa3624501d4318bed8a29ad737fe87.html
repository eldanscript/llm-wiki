Control Tower

참석

  • AWS : 이종구 (ESM ProServe), 김민석 (Practice Manager), 한원탁 (Cloud Architect), 안경진 (Security Consultant)

ECSA

  • Security Epics

    • Identity

    • Detective Control

    • Infrastracture security

    • Data Protection

    • Incident Response (Remediation)

  • AWS native 보안 structure

AWS Control Tower

  • 권장되는 다중 계정 환경

Landing Zone (ALZ)

Feature

  • All-in migration 전 수행 권장

  • Account Vending Machinge (AVM) : 계정 생성 자동화

  • OU (Organization Unit) 생성 자동화

  • SCP를 통한 예방 가드레일 (Preventive Guardrails)

  • AWS Config 서비스를 통한 감지 가드레일 (Detective Guardrails)

  • AWS CF template을 활용한 자유로운 AWS 리소스 구성

New to Control Tower

  • 기존 계정 추가 지원

  • 대시보드

  • AWS SSO 기본 셋업

ALZ to CFCT Solution Mapping

  • Account Factory : AVM

  • OU 관리 : OU 생성 자동화

  • Preventive Guardrails

  • Detective Guardrails

  • CFCT Pipeline : custom reseource, AVM 확장 (CF template 활용)

CFCT Pipelin

  • Source → Build → SCP → CFn Resource

  • SCP 단계에서 회사 별 customization 추가

ALZ Project

  • Secure VPC 구축

  • PG, DG 협의 및 제언

  • AWS native security 도입 (Security Hub)

  • AWS SSO 설계 및 구축 (MS AD)

  • Hybrid DNS 설계 및 구축

  • 계정 구조 및 OU 구조 설계

  • Service Catalog 관리 체계 설계 및 구축

    • EC2 생성 시 naming rule이나 customization rule을 따르도록 생성 하게 할 수 있음 → Innotek EC2로 생성

Organization Unit 구성

  • Workload 중심으로 구축 : dev, test, stg 등의 단계별 하위 계정 생성

  • Shared Services Account

    • 공용 DB, CICD 등

Secure Zone (North Connectivity)

  • Internet 망 연결을 하나의 출구로 통합

CFCT 생성 시 기본적으로 추가되는 계정

  • Logging Account : Audit에 활용

  • 식별 → 보호 → 탐지 → 자동화 분석 → 대응 → 복구

GWLB + 3rd Party Security Solution

  • 기존 Architecture 단점 : 경로 설게

  • AWS GWLB 구성으로 간결한 Layer 구성, 통신 연계, 구축 및 운영 관리

  • GWLB와 Instance간에는 Geneve라고 하는 전용 Tunnel 사용하여 보안 검사

QnA

  • 계정의 결제 정보는 어떻게 입력 → Payer Account (Master Account)에서 지불

  • OU에서 분리를 하게 되면 결제 정보는 ? → unregistered account가 되며 수동으로 입력, 조직 관리에서 벗어나게 됨

  • 현재 5개 계정으로 운영하는데 기존 계정중 하나를 사용하면 되는지?

    • 별도의 Payer Account를 생성하여 구성하는 것을 권장

    • Payer Account는 초기에 Landing Zone을 deploy하고 이후에는 lock 시키는 것을 권장

  • 현재 Payer Account가 CNS 계정인데 어떻게 적용해야 하는지?

    • Payer Account의 민감 정보를 공개하지 않고 Control Tower deploy만 하도록 구성

    • LG U+에서도 동일한 케이스를 지원

      • Account Factory는 적용하지 않고 LG U+에서 Account를 만든 후 SCP를 적용하는 방식으로 진행

  • 이후 진행하게 된다면 기간은?

    • Phase 1 (ECSA 수행, 4주) → Phase 2 (네트워크 & 보안 고도화, 2 ~ 3 개월) → Phase 3 (AWS native 보안 & APN 솔루션 통합 확장, 3 ~ 4 개월)

    • 고객사와 Phase 구성에 대해 추가 협의 하여 일정 산정
