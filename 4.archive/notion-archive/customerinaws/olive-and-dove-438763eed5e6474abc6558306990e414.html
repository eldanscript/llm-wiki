Customer Request

  1. 회원 등록/관리
    회원관리 cognito 를 사용한 회원 가입 (ID/PW, email 및 SSO 등 지원)
    비밀번호 찾기 (email, SNS등을 cognito의 AWS SNS 등 활용)
    회원 관리 및 권한 관리 (cognito user group 과 identity pool 등을 활용)
    회원간 카메라 공유 기능 (가족 초대 기능, 현재는 아이디 공유방식이나 미국에서는 ID 초대 기능을 선호)

  2. 디바이스 관리
    공장에서 생산시 인증서 관리 (fleet provisioning 사용 예상)
    IoT core 를 사용하여 각 디바이스에 대한 인증서 배포 및 관리
    IoT core 디바이스 관리를 통한 펌웨어 업데이트 관리 (greengrass 적용 가능 여부)
    Message broker (MQTT) 를 사용한 디바이스와 통신
    MQTT에서 keepalive 주기 관리
    서버에서 디바이스에 대한 자산 관리 : ThingGroup 연동, App에서 CCTV 연결 시,

    앱에서 디바이스 설정 세팅 및 동기화
    연결이 끊긴 디바이스에 대한 관리
    배터리 잔량이 일정 수준 미만 (대략 20%)인 기기에 대한 관리

  3. 메시징 (디바이스 <=> 서버 <=> 앱)
    MQTT를 사용한 디바이스와 서버간의 통신 (이벤트 전송 등)
    서버와 스마트폰 앱과의 연동
    iOS와 android 에 대한 push 메시징 지원 (AWS SNS 사용)
    서버 및 디바이스 단에서 앱에 필요한 메시지 전송

  4. 스트리밍 및 미디어 관리
    KVS WebRTC를 사용한 스트리밍 (디바이스 <=> 앱)
    KVS를 사용한 디바이스에서 카메라 영상 녹화 화일 업로드
    KVS로 디바이스에 저장된 미디어 화일을 서버로 업로드할때 암호화 필요 (KVS 에 자체적으로 지원)
    영상 화일 자체에 대한 암호화 (KVS 에서 지원여부)

  5. 데이터 관리
    스트리밍 이벤트 및 영상등에 대한 관리 (앱에서 허가된 영상 리스팅 및 경찰등이 요청하는 경우 특정 디바이스의 특정 화일 찾아서 다운로드)
    S3를 사용하여 암호화된 형태로 화일 저장 (S3 지원)
    S3에 저장된 화일을 3rd party 업체에 전송하는 기능 (영상 분석 및 관리 업체등으로 전송)
    미디어 화일 다운로드시 비용 절감 및 속도 향상 (CDN 사용)
    임시로 pre-signed url 생성하여 다운로드 가능하는 기능 (CDN 사용)
    타업체와 보안채널로 연결 (VPN등으로 연결)

  6. 업체 /국가별 시스템 구성
    다양한 국가에 대한 서비스를 하나의 시스템으로 구성 (혹은 저렴한 구성으로)
    각 업체에 대한 고유 홈페이지와 권한을 설정 (추후 SaaS 화 혹은 저렴한 시스템 구성)
    docker 형태의 이미지를 사용하여 효율적인 관리 (ECS, EKS 등 사용)
    EC2를 최소화하고 lambda등을 사용한 구성 (Serverless 사용)
    MQTT, KVS / KVS WebRTC등을 사용하는 경우 Global Accelerator 사용 방안
    데이터 다운로드시 (CDN 활용)

  7. 시스템 관리
    시스템 운영시 관리자1/관리자2/관리자3에 대한 권한 설정 (예를 들어, 자사가 아닌 관리업체를 사용하는 경우)
    데이터에 대한 검색 및 관리를 하는 dash board 혹은 관리 페이지 (AWS에서 지원하는지 여부)
    모든 이벤트 및 미디어 화일에 대한 관리
    log 저장 및 관리 (ELK 활용)

  8. 과금 및 플랜 설정
    클라우드 스토리지를 플랜별로 판매 (고객에게 7일, 1달, 1년등의 클라우드 저장 서비스 판매)
    각 계정에 LTE SIM 카드 및 플랜 판매 (이런 서비스가 있는지?)

  9. 기타 시스템 연동
    Alexa 연동, apple homekit연동 : 스트리밍 및 notification
    IFTTT 연동
    AWS Rekognition 연동 가능 여부
    App 대신 Web을 viewer로 사용하는 방법 (Cogito와 KVS를 활용)

  10. 기존 시스템과 호환성
    신규 시스템과 기존 시스템 공존
    새로운 시스템으로의 마이그레이션 (기존 시스템을 cognito로 migration)

Customer Design

  • DB Schema

    1. 사용자 정보 : e-mail account, AWScognito의user id (36 byte)

    2. 주요 저장소 (DynamoDB, AWS RDS)

    3. 디바이스 정보 : MAC address, IoT core의 certificate id (64 byte)

    4. 주요 서비스 키 : device-id

    -message broker topic name

    -kinesisvideo의 signaling channel name

    -AWS SNS를 통한 Push notification을 위한 endpoint name(topic)
