WebRTC

💡

Open technology specification for enabling real-time communication (RTC) across browsers and mobile applications via simple APIs

  • 간단한 API를 사용하여 RTC 구현하기 위한 사양

  • Peer간 실시간 data 교환을 이용

  • IETF Protocol

    • ICE : Interactive Connectivity Establishment (상호 연결 설정)

    • TURN : Traversal Using Relay around NAT

      • NAT 주변의 릴레이를 사용한 순회를 의미하며 TURN 서버와의 연결을 열고 해당 서버를 통해 모든 정보를 중계하여 대칭 NAT 제한을 우회하는데 사용되는 프로토콜

      • NAT 또는 방화벽이 직접 연결(대칭 NAT 의 경우)을 허용하지 않는 경우 클라우드를 통해 미디어를 중계하는 Kinesis Video Streams TURN 엔트포인트에 연결

    • STUN : Session Traversal Utilities for NAT

      • NAT 용 세션 탐색 유틸리티를 의미하며 Public IP 를 검색하고 Peer 와의 직접 연결을 방해하는 라우터의 제한을 결정하는데 사용되는 프로토콜

      • 애플리케이션이 NAT 또는 방화벽 뒤에 위치한 경우 Kinesis Video Streams STUN 엔드포인트를 사용하여 Public 주소를 검색

  • Port

    • RTP : 5004

    • Signaling : 80/443

    • Discovery : 3478

    • P2P connection : random

KVS WebRTC

https://docs.aws.amazon.com/kinesisvideostreams-webrtc-dg/latest/devguide/what-is-kvswebrtc.html

💡

Provides a standards-compliant WebRTC implementation as a fully managed capability

  • Live stream media

  • Two-way audio/video interaction : IoT device나 WebRTC 호환 player

  • 완전 관리형 서비스 : WebRTC 관련 cloud infrastructure를 구축, 운영, 확장할 필요가 없음 (signaling media relay server 등)

Service Quotas

  • CreateSignalingChannel : Regione당 1000 channels per account (soft limit), Request 50 TPS

  • Signaling API

    • ConnectAsMaster : API 3 TPS (hard limit), 1 Master Connection per signaling channel (hard limit), 1h connection limit (hard limit), 10m connection timeout (hard limit)

    • ConnectAsViewer : API 3 TPS (hard limit), 10 Viewer Connection per signaling channel (hard limit), 1h connection limit (hard limit), 10m connection timeout (hard limit)
