Tech Guide - Advanced Shield & WAF

AWS WAF와 AWS Shield Advanced의 기능 차이 및 성능 개선 분석

AWS WAF와 AWS Shield Advanced는 모두 웹 애플리케이션을 보호하기 위한 AWS의 보안 서비스이지만, 그 기능과 접근 방식에는 중요한 차이가 있습니다. 특히 빠른 속도로 발생하는 이벤트에 대한 대응 능력 측면에서 두 서비스 간의 차이점을 이해하는 것이 중요합니다.

AWS WAF와 AWS Shield Advanced의 기본 비교

AWS WAF는 웹 애플리케이션을 다양한 위협으로부터 보호하기 위한 웹 애플리케이션 방화벽 서비스로, 웹 요청을 모니터링하고 사용자가 지정한 규칙에 따라 트래픽을 필터링합니다[3]. 반면 AWS Shield는 DDoS(분산 서비스 거부) 공격에 대한 보호를 제공하는 서비스로, 기본적인 Shield Standard와 고급 기능을 제공하는 Shield Advanced로 구분됩니다[9].

Shield Standard는 AWS 고객에게 추가 비용 없이 제공되는 기본 DDoS 보호 서비스로, 가장 흔한 네트워크 및 전송 계층(3-4계층) DDoS 공격으로부터 보호합니다[5]. 반면 Shield Advanced는 구독 기반 서비스로, 더 정교한 DDoS 공격에 대한 고급 보호 기능을 제공합니다[5][10].

RateLimit 규칙의 한계와 Shield Advanced의 개선점

현재 WAF의 RateLimit 규칙을 사용하고 있지만 순간적인 이벤트에 대한 차단이 효과적이지 않다는 문제에 대해, Shield Advanced는 다음과 같은 방식으로 이 문제를 개선할 수 있습니다:

1. 지능적인 트래픽 분석과 자동화된 대응

Shield Advanced는 시간 경과에 따른 트래픽을 분석하여 기준을 설정하고 DDoS 공격을 나타낼 수 있는 트래픽 패턴의 이상을 감지합니다[1]. 이는 단순한 속도 제한보다 더 지능적인 방식으로 공격을 식별할 수 있게 해줍니다. Shield Advanced가 공격을 감지하면 자동으로 AWS WAF 규칙을 생성하고 관리하여 대응할 수 있습니다[1][4].

2. 자동 애플리케이션 계층 DDoS 완화

Shield Advanced의 자동 애플리케이션 계층 DDoS 완화 기능은 애플리케이션 가용성에 영향을 미칠 수 있는 악의적인 웹 트래픽을 자동으로 완화합니다[5]. 이 기능은 고객을 대신하여 계층 7 DDoS 이벤트를 완화하기 위해 AWS WAF 규칙을 자동으로 생성, 테스트 및 배포합니다[5].

이 자동화된 접근법은 수동으로 WAF 규칙을 만들고 배포하는 것보다 공격에 더 빠르게 대응할 수 있게 해줍니다. Shield Advanced는 공격 서명을 식별하고 이를 AWS WAF 규칙에 구현하여 DDoS 공격과 관련된 트래픽만 차단합니다[4].

3. 선제적 대응 및 실시간 모니터링

Shield Advanced는 공격을 감지하기 전에 선제적으로 대응할 수 있는 기능을 갖추고 있어, 고도화된 DDoS 공격에 신속하게 대처할 수 있습니다[2]. 또한 CloudWatch와 통합되어 실시간으로 DDoS 공격을 모니터링하며, 이상 패턴이 감지되면 자동으로 방어를 개시합니다[2].

WAF 자체 성능 향상 여부

Shield Advanced가 WAF 자체의 성능을 직접적으로 향상시키는 것은 아닙니다. 대신, Shield Advanced는 WAF와 함께 작동하여 WAF의 기능을 보완하고 확장합니다. Shield Advanced는 다음과 같은 방식으로 전체 보안 체계를 강화합니다:

  1. 더 빠른 탐지와 대응: Shield Advanced는 WAF보다 더 빠르게 DDoS 공격을 탐지하고 자동으로 대응할 수 있습니다[4][11].

  2. 지능적인 규칙 생성: Shield Advanced는 공격 패턴을 분석하여 WAF에 더 효과적인 규칙을 자동으로 생성합니다[4].

  3. 글로벌 위협 인텔리전스 활용: Shield Advanced는 AWS의 글로벌 위협 인텔리전스를 활용하여 새로운 공격 패턴에 대한 보호 기능을 제공합니다[11].

  4. 실시간 모니터링 및 가시성: Shield Advanced는 DDoS 공격에 대한 실시간에 가까운 가시성을 제공하여 더 빠른 대응을 가능하게 합니다[5][8].

고급 속도 기반 규칙의 활용

2023년 5월에 AWS는 WAF 속도 기반 규칙 개선 사항을 발표했으며, 이를 통해 요청 속도 제한을 위해 추가 HTTP 요청 속성을 사용할 수 있게 되었습니다[7]. 이러한 개선 사항은 Shield Advanced와 함께 사용될 때 더욱 효과적일 수 있습니다. 예를 들어, 다양한 요청 속성(IP 주소, 헤더, 쿠키 등)을 기반으로 한 속도 제한을 설정할 수 있으며, 최대 5개의 복합 키를 매개변수로 결합하여 더욱 강력한 규칙을 구현할 수 있습니다[7].

결론

AWS Shield Advanced는 WAF 자체의 기본 성능을 직접적으로 향상시키지는 않지만, WAF와 통합되어 더 지능적이고 자동화된 DDoS 보호 기능을 제공합니다. 순간적으로 발생하는 대량의 이벤트에 대해 Shield Advanced는 자동 완화 기능을 통해 WAF보다 더 빠르고 효과적으로 대응할 수 있습니다[1][4][5].

따라서 RateLimit 규칙만으로는 순간적인 대량 이벤트를 효과적으로 차단하기 어려운 경우, Shield Advanced의 도입을 고려해볼 수 있습니다. Shield Advanced는 지능적인 트래픽 분석, 자동화된 규칙 생성 및 적용, 그리고 실시간 모니터링 기능을 통해 WAF의 한계를 보완하고 전반적인 DDoS 보호 능력을 향상시킬 수 있습니다[1][4][5][11].

AWS Shield Advanced 구독 시 고려사항

Shield Advanced 구독에는 Shield Advanced로 보호하는 리소스에 대한 표준 AWS WAF 기능 사용 비용이 포함됩니다[1][11]. 자동 애플리케이션 계층 DDoS 완화를 활성화하면 150개의 웹 ACL 용량 단위(WCU)를 사용하는 규칙 그룹이 웹 ACL에 추가됩니다[1][11]. 또한, DDoS 공격으로 인해 AWS 리소스 사용량이 급증할 경우, Shield Advanced는 추가 리소스 비용을 AWS에서 지원하여 고객의 비용 부담을 완화합니다[2].

AWS Shield Advanced와 AWS WAF의 공격 대응 순서 및 네트워크 흐름 분석

AWS Shield Advanced와 AWS WAF는 AWS의 주요 보안 서비스로, 각각 다른 계층에서 작동하면서도 통합된 보안 솔루션을 제공합니다. 공격이 발생할 때 이 두 서비스가 어떤 순서로 대응하는지 네트워크 흐름 관점에서 살펴보겠습니다.

각 서비스의 보호 계층 및 기본 동작

AWS Shield Advanced와 AWS WAF는 서로 다른 네트워크 계층에서 주로 작동하도록 설계되었습니다. 이것이 공격 대응 순서에 중요한 영향을 미칩니다.

Shield Advanced는 주로 네트워크 및 전송 계층(3-4계층)에서 DDoS 공격을 탐지하고 완화하는 데 중점을 둡니다. 반면 AWS WAF는 주로 애플리케이션 계층(7계층)에서 웹 애플리케이션 트래픽을 필터링하는 데 중점을 둡니다[6][12]. 그러나 Shield Advanced는 WAF와 통합하여 애플리케이션 계층 보호도 제공할 수 있습니다.

Shield Advanced의 주요 기능:

  • 네트워크 및 전송 계층(3-4계층) DDoS 공격 보호

  • 대규모 네트워크 공격 완화

  • 자동 탐지 및 대응 기능

  • 애플리케이션 계층 보호를 위한 WAF와의 통합[1][8]

AWS WAF의 주요 기능:

  • HTTP/HTTPS 요청 필터링

  • 웹 애플리케이션 취약점 보호

  • RateLimit 규칙을 통한 요청 제한

  • SQL 인젝션, XSS 등 웹 공격 방어[6]

네트워크 흐름 기준 대응 순서

네트워크 트래픽 흐름 관점에서 보면, AWS 인프라에 들어오는 공격은 일반적으로 다음과 같은 순서로 처리됩니다:

1. 네트워크 및 전송 계층(3-4계층) 공격의 경우:

Shield Advanced가 먼저 대응합니다. 이러한 유형의 공격(SYN/UDP Floods, 반사 공격 등)은 WAF가 검사하기 전에 Shield에 의해 식별되고 완화됩니다[5][12]. AWS Shield는 POP(Point of Presence)와 트랜짓 센터에서 트래픽을 실시간으로 분석하여 이러한 계층의 악성 트래픽을 우선적으로 차단합니다[11].

CloudFront나 Route 53과 같은 서비스에 대한 공격은 일반적으로 1초 이내에 완화되며, Elastic Load Balancing에 대한 공격은 5분 이내에 완화됩니다[5]. 이는 WAF가 개입하기 전에 Shield가 먼저 대응함을 의미합니다.

2. 애플리케이션 계층(7계층) 공격의 경우:

애플리케이션 계층 공격에 대한 대응은 더 복잡한 협력 모델을 따릅니다:

  1. Shield Advanced는 트래픽 패턴을 지속적으로 모니터링하고 분석하여 기준선을 설정합니다[1].

  2. 애플리케이션 계층 DDoS 공격이 감지되면, Shield Advanced는 자동으로 WAF 규칙을 생성하고 관리합니다[8].

  3. 이후 WAF가 이러한 규칙을 실행하여 악성 요청을 필터링합니다[1][8].

중요한 점은 애플리케이션 계층 보호를 위해 Shield Advanced는 WAF를 실행 메커니즘으로 활용한다는 것입니다. Shield Advanced의 자동 애플리케이션 계층 DDoS 완화 기능을 활성화하면, Shield Advanced는 DDoS 공격에 대응하여 사용자를 대신하여 웹 ACL 규칙을 자동으로 생성하고 관리합니다[7][8].

통합 작동 방식:

Shield Advanced의 자동 애플리케이션 계층 DDoS 완화 기능을 활성화하면, 150개의 웹 ACL 용량 단위(WCU)를 사용하는 규칙 그룹이 웹 ACL에 추가됩니다[1][8]. 이 규칙 그룹은 Shield Advanced가 DDoS 공격의 일부로 식별한 소스에서 오는 요청에 대해 속도 제한을 적용하고, 공격 패턴에 기반한 사용자 지정 WAF 규칙을 자동으로 생성합니다[8].

결론

네트워크 흐름 관점에서 볼 때, 공격 유형에 따라 대응 순서가 결정됩니다:

  1. 네트워크/전송 계층(3-4계층) 공격: Shield Advanced가 먼저 대응하며, WAF는 관여하지 않습니다.

  2. 애플리케이션 계층(7계층) 공격: Shield Advanced와 WAF가 통합되어 작동하는데, Shield가 공격을 탐지하고 WAF는 Shield의 지시에 따라 필터링 규칙을 구현합니다.

따라서 순서적으로는 Shield Advanced가 먼저 작동하지만, 애플리케이션 계층 공격의 경우 Shield Advanced는 WAF를 통해 방어 메커니즘을 구현하기 때문에 두 서비스가 긴밀하게 협력하는 모델이라고 볼 수 있습니다[1][7][8]. 이러한 통합된 접근 방식은 다양한 유형의 공격에 대해 더 효과적인 보호를 제공합니다.
