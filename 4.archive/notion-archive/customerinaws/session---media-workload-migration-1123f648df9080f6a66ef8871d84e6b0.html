Session - Media Workload Migration

Customer Meeting @October 2, 2024

Customer Status

  • NAS 음원 파일을 스트리밍 서비스를 위해 CDN으로 전송

  • 원 클릭 다운로드를 통해 client에서 파일을 다운로드

    • NAS에서 다운로드 (mp3, fla)

  • 수급 과정은 간단한 방식

  • 인코딩은 on-prem에서 작업

    • 7가지 종류

    • 수급하시는 음원별

    • DDEX를 통해 파일 정보를 획득

  • 스트리밍 HLS

  • DRM은

  • ALC 파일은 보관할 필요가 없으나

  • 파일의 규모는 1.3PB (원본 + 서비스 되는 파일)

  • 자동 프로비저닝

    • 자동 Provisioning

    • DDEX 가 없는 경우

    • ingest 구분은 수급사 별로 구분

  • 별도의 management system

    • 콘텐츠 메타 데이터 추출

  • 컨텐츠 입수량은 어느 정도

    • 일 최대 50TB (대략 2~3TB 수준)

    • 파일 개수는 20만개 정도

  • 수급 백엔드 구성

    • 웹서비스, SFTP → NAS Upload → Encoding (7~8종) → NAS → CDN

    • 웹 서버 → DDEX (AWS Upload)

  • 향후 계획

Customer Workload

음원 수급 파이프라인

업무 프로세스

  1. 음원 확보

    • 레이블, 기획사, 아티스트와의 계약 체결

    • 해외 음원 유통사와의 제휴

    • 인디 아티스트 발굴 및 계약

  2. 메타데이터 관리

    • 곡 정보, 아티스트 정보, 앨범 정보 등 상세 데이터 입력 및 관리

    • 장르 분류, 태그 작업

  3. 음질 관리

    • 고음질 마스터 파일 확보

    • 다양한 음질 옵션(일반/고음질/무손실 등) 변환 작업

  4. 저작권 관리

    • 저작권 정보 확인 및 등록

    • 저작권료 정산 시스템 구축

  5. 콘텐츠 큐레이션

    • 플레이리스트 제작

    • 추천 알고리즘 개발 및 적용

  6. 플랫폼 업로드

    • 음원 파일 및 메타데이터 업로드

    • 출시일 관리

  7. 품질 관리

    • 음질, 메타데이터 오류 체크

    • 사용자 피드백 모니터링 및 대응

  8. 정산 및 분배

    • 스트리밍 데이터 집계

    • 수익 정산 및 분배

회사별 특징

지니뮤직

  • KT 계열사로 통신사와의 제휴를 통한 가입자 확보에 강점

  • 실시간 차트, 뮤직비디오 서비스 등 다양한 부가 기능 제공

드림어스 컴퍼니(FLO)

  • SK텔레콤 계열사로 AI 기반 개인화 추천 시스템에 주력

  • 고음질 스트리밍 서비스 ‘FLO Hi-Fi’ 운영

멜론(카카오엔터테인먼트)

  • 국내 최대 음원 플랫폼으로 방대한 사용자 데이터 보유

  • 카카오톡 연동 등 카카오 생태계와의 시너지

스포티파이

  • 글로벌 서비스로 해외 음원 라이브러리가 풍부

  • 데이터 기반 개인화 추천 알고리즘에 강점

이들 회사는 공통적으로 음원 확보, 메타데이터 관리, 저작권 처리 등의 기본적인 프로세스를 갖추고 있습니다. 차별화 요소로는 AI 기술 활용, 고음질 서비스, 부가 기능(뮤직비디오, 가사 등), 통신사 제휴 등이 있으며, 각 회사의 강점을 살려 경쟁력을 확보하고 있습니다[1][2][3].

MEM (Media Event Manangement)

Migration Concept

Workload 구분

  1. 메타데이터 관리

    • 곡 정보, 아티스트 정보, 앨범 정보 등 상세 데이터 입력 및 관리

    • 장르 분류, 태그 작업

  2. 음질 관리

    • 고음질 마스터 파일 확보

    • 다양한 음질 옵션(일반/고음질/무손실 등) 변환 작업

  3. 콘텐츠 큐레이션

    • 플레이리스트 제작

    • 추천 알고리즘 개발 및 적용

  4. 플랫폼 업로드

    • 음원 파일 및 메타데이터 업로드

AWS 환경

  1. 음원 저장 및 관리

    • Amazon S3: 음원 파일과 메타데이터를 저장합니다1.

    • Amazon OpenSearch Service: 음원 메타데이터 검색 및 추천 엔진에 활용합니다2.

  2. 음원 변환 및 처리:

    • AWS Elemental MediaConvert: MP3 파일을 스트리밍에 적합한 형식(예: M3U8)으로 변환합니다1.

    • AWS Lambda: 간단한 음원 처리 작업을 수행합니다.

  3. 워크플로우 관리:

    • AWS Step Functions: 음원 수급, 변환, 배포 등의 전체 워크플로우를 오케스트레이션합니다3.

    • Amazon EventBridge: 특정 이벤트(예: 새 음원 업로드)를 감지하고 워크플로우를 트리거합니다3.

  4. 데이터 처리 및 분석:

    • Amazon EMR: 대규모 데이터 처리 및 분석 작업을 수행합니다2.

    • Amazon SageMaker: 음악 추천 모델 등 ML 모델을 훈련하고 배포합니다2.

  5. 스트리밍 서비스:

    • Amazon CloudFront: 전 세계 사용자에게 낮은 지연 시간으로 음원을 스트리밍 제공합니다.

  6. 보안 및 접근 제어:

    • AWS IAM: 리소스 접근 권한을 관리합니다.

    • AWS KMS: 음원 파일 암호화에 사용합니다.

Customer Case

DreamUS Company

입수 Pipeline 은 이렇게 구성이 되어 있구요.
음원의 경우는 DDEX (digital data exchange)라는 표준 xml format 으로 FTP 로 전달을 받아서 음질에 맞춰 다양한 bitrate 로Transcoding 하고 서비스를 하게 됩니다. podcast 등은 RSS 로 입수를 하고 있구요.
Transcoding 된 음원은 Direct Connect 를 통해서 SKB cdn 에 upload 되어서 서비스 됩니다.

실제로 입수 파이프라인에서 하는 일들이 참 많습니다.
Loudness normalization 라고 해서 음량 평준화를 위한 Lufs 추출, Music Recognition 이라고 음악을 통해 검색하기 위한 deep learning 기반의 embedding 추출, 간혹 타 레이블의 음원을 곡 변조 등을 통해 등록하는 경우도 있어서 음원의 유사성 비교를 통해 의심이 가는 음원 detection 하는 기능 등이 있으며

그리고 여기에는 CBF Embedding 으로 표시 되어 있는데 추천 컨텐츠 파이프라인으로 연결이 되며 mel-spectrogram 으로 변환해 embedding 을 추출하고 음원의 특징 피쳐 추출하는 등 CBF 추천을 위한 다양한 작업을 수행하고 있습니다.

또한 원래는 저희도 직접 트랜스코딩을 하다가 Mediaconvert 로 변환을 하였는데
MediaConvert 의 장점은 파일 사이즈에 상관없는 안정적인 트랜스코딩, ffmpeg 같은 3rd party 트랜스코딩 tool에 대한 관리 포인트 감소, 트랜스코딩 이슈 발생에 대한 스페셜리스트 지원 등이 있을 것 같습니다.

제공된 설명을 바탕으로 음원 입수 파이프라인의 아키텍처와 기술 요소를 다음과 같이 구성할 수 있습니다:

아키텍처 구성

  1. 입수 단계

    • FTP 서버: DDEX 형식의 XML 파일 수신

    • RSS 피드 수집기: 팟캐스트 등의 콘텐츠 수집

  2. 처리 단계

    • AWS MediaConvert: 다양한 비트레이트로 트랜스코딩

    • AWS Lambda: 각종 처리 작업 수행

    • Amazon S3: 원본 및 처리된 파일 저장

  3. 분석 및 특징 추출 단계

    • Amazon SageMaker: 딥러닝 기반 임베딩 추출

    • AWS Batch: 대규모 병렬 처리 작업

  4. 배포 단계

    • AWS Direct Connect: SKB CDN으로 파일 전송

  5. 메타데이터 관리

    • Amazon DynamoDB: 메타데이터 저장 및 관리

  6. 워크플로우 관리

    • AWS Step Functions: 전체 파이프라인 오케스트레이션

주요 기술 요소

  1. DDEX (Digital Data Exchange)

    • 음악 산업 표준 XML 포맷

    • 음원 메타데이터의 일관성 있는 교환 지원

  2. AWS MediaConvert

    • 다양한 비트레이트로 안정적인 트랜스코딩 수행

    • FFmpeg 등 서드파티 도구 관리 부담 감소

  3. Loudness Normalization

    • LUFS(Loudness Unit Full Scale) 추출

    • AWS Lambda를 사용하여 음량 평준화 작업 수행

  4. Music Recognition

    • 딥러닝 기반 임베딩 추출

    • Amazon SageMaker를 활용한 모델 훈련 및 추론

  5. 음원 유사성 비교

    • 의심되는 음원 탐지를 위한 알고리즘

    • AWS Batch를 사용한 대규모 비교 작업

  6. CBF (Content-Based Filtering) Embedding

    • Mel-spectrogram 변환 및 임베딩 추출

    • 추천 시스템을 위한 음원 특징 추출

    • Amazon SageMaker Feature Store를 활용한 특징 저장 및 관리

  7. AWS Direct Connect

    • SKB CDN으로의 안정적이고 빠른 파일 전송

    • 네트워크 지연 최소화 및 보안 강화

  8. AWS Step Functions

    • 복잡한 입수 파이프라인의 워크플로우 관리

    • 각 단계별 처리 상태 모니터링 및 오류 처리

이러한 아키텍처와 기술 요소를 통해 음원 데이터의 효율적인 입수, 처리, 분석, 그리고 배포가 가능해집니다. AWS의 관리형 서비스를 활용함으로써 인프라 관리 부담을 줄이고, 안정적이며 확장 가능한 시스템을 구축할 수 있습니다. 또한, 딥러닝 기반의 고급 분석 기능을 통해 음원의 품질 관리와 추천 시스템 개선이 가능해집니다.
