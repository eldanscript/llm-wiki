HTTP Chunked Mode

  • Elemental Live

  • https://docs.aws.amazon.com/elemental-live/latest/ug/video-ull.html

When you use AWS Elemental MediaLive and set the HTTP transfer mode to “NOT_CHUNKED”, it means that the video output will not be delivered in chunked encoding and transfer.

The key effects of using “NOT_CHUNKED” in the HTTP transfer mode are:

  1. The video output will be delivered as a complete segment, rather than being divided into smaller fragments.

  2. This can result in slower delivery to the downstream system, as the entire segment needs to be available before it can be delivered.

  3. The downstream system may need to wait longer to start processing the video, as it cannot start processing until the entire segment is received.

In contrast, when you enable “chunked encoding and transfer” by setting the HTTP transfer mode to “CHUNKED”, Elemental MediaLive will divide the video into smaller fragments and deliver these fragments more frequently. This can result in faster delivery and processing by the downstream system, as it can start processing the video without waiting for the entire segment to be available.

However, it’s important to discuss your specific requirements with the downstream system administrator to ensure they are prepared to accept the chunked output and can handle the increased frequency of fragment delivery.

For the most up-to-date information on Elemental MediaLive features, pricing, and other details, please refer to the AWS Documentation.

Output Groups - VOD

  • Where do save contents to S3 and the reason

    Based on the information provided in the search results, here is my recommendation on where to connect to save the live streaming file on S3:

    1. Connect to MediaLive to save the live streaming file on S3:

      • MediaLive supports live stream inputs, while MediaPackage does not.

      • The search results indicate that MediaLive can output the live stream directly to an S3 bucket as a file, whereas MediaPackage is designed for packaging and distributing live streams, not for storing the raw stream.

      • By connecting the live stream output directly from MediaLive to an S3 bucket, you can save the file for future use or processing, such as creating a video-on-demand (VOD) asset.

    2. Advantages of connecting to MediaLive:

      • MediaLive provides more flexibility and control over the live stream processing and output, including the ability to save the stream to S3.

      • MediaPackage is primarily focused on packaging and distributing the live stream to various playback formats and protocols, rather than storing the raw stream.

      • Connecting directly to MediaLive allows you to leverage its features for live stream processing, such as input redundancy, output options, and integration with other AWS services.

    Remember, the specific details and capabilities of AWS services may change over time, so it’s always best to refer to the latest AWS documentation for the most up-to-date information.

How to Reduce Latency

To reduce latency as much as possible for your HLS stream using AWS Elemental MediaLive, you can follow these steps:

  1. Coordinate with the operator of the AWS Elemental MediaPackage service to obtain the destination URL for your HLS output. This is required to configure the HLS output group in MediaLive.

  2. In the MediaLive channel, create an HLS output group and select MediaPackage v2 as the destination. This will allow you to leverage the Low-Latency HLS (LL-HLS) functionality provided by MediaPackage.

  3. When configuring the HLS output group, ensure that you follow the guidance provided in the AWS documentation for the “Fields for the output destination – sending to MediaPackage” section. This will help you properly set up the LL-HLS parameters.

  4. Additionally, you can leverage a content delivery network (CDN) like Amazon CloudFront to deliver your LL-HLS stream at scale to viewers. This can further help reduce the end-to-end latency.

  5. For the most up-to-date information on pricing, limits, availability, and other details related to AWS Elemental MediaLive and MediaPackage, please refer to the official AWS documentation.
