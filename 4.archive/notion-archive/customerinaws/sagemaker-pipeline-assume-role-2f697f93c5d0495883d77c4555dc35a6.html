Question 1

processor container 를 실행 할때 role 을 설정 해주는데, Sagemaker pipeline 이  설정된 Role 을 바로 사용하는것이 아니라 assume-role 을 해가지고 container 에 role 을 적용하는 것 같더라구요.container 실행할떄 role 은 (role=“arn:aws:iam::999254871570:role/UF-SAGEMAKER-ROLE-DEV”) 로 명시했음에도 불구하고

실제로, container 실행후에 반영된 role 을 찍어보면 아래처럼 assume-role 된 role 이더라구요.

‘Arn’: ‘arn:aws:sts::999254871570:assumed-role/UF-SAGEMAKER-ROLE-DEV/SageMaker’즉.. pipeline 내부적으로 명시된 role 을 assume 해서 적용하는 것 같은데.. 이것 좀 혹시 명시된 role 을 바로 processo container 에 적용할수 있게 하는 방법같은거 없나요?? (assume-role 된 role 이 아니라 인자로 넣은 role 자체가 반영이되게요)

Reference

In the pipeline definition, if you’re trying to access values in the file evaluation.json with a JsonGet expression in a condition expression or any downstream steps, the pipeline service will load the json file and fetch the value with the pipeline execution role. This doesn’t happen in your own computing environment (training,
processing instances) behind your own VPC. These values will eventually show via SageMaker’s list, describe APIs.

  • We don’t suggest that users put sensitive info in the files that they would like to use with a JsonGet.

  • To give pipeline execution role access to the bucket, users could create an exception for the role: https://docs.aws.amazon.com/sagemaker/latest/dg/build-and-manage-access.html#build-and-manage-scp

  • Don’t use the same role for training or data processing. For example:

sklearn_processor = SKLearnProcessor(
    ...
    role=sagemaker_processing_execution_role,
)
...
pipeline.upsert(role_arn = sagemaker_pipeline_execution_role)

We’re working on supporting Lambda function in pipeline. With this, users could run the Lambda function behind their VPC. They are able to access the evaluation.json and return a summary (e.g. True/False based on metric value) directly to the pipeline. Feel free to reach out to the team for more details.

Basically, pipeline service will assume the role, which is passed to the pipeline via Pipeline.upsert(role_arn=<>) call, to access the evaluation.json

Answers 1

pipeline service will assume the role, which is passed to the pipeline via Pipeline.upsert(role_arn=<>)

안녕하세요. 천현우 프로님. 말씀하신 대로 SageMaker Pipeline 서비스에서는 Pipeline.upsert(role_arn=<>)를 통해 전달 받은 Role을 Assume하여 사용하도록 되어 있습니다.

Assumed-Role 적용을 피하고자 하는 상황을 말씀해 주시면 다른 방법으로 검토해 볼 내용이 있을지 확인해 드리겠습니다. Pipeline Role에 대한 내용은 다음 링크를 참조 하시기 바랍니다.

Question 2

processor 내부에서 assume-role 을 수행해야 하는 케이스가 있는데 이미 processor 가 실행될때부터 assume-role 상태이기 때문에 내부적으로  chain-assume-role 로 인식이 되더라구요.

processor 안에서 assume-role 하면 아래에서 1번케이스가 되겟거니 생각했었는데 assume-role 된 role 이 또 다시 assume-role 하는 케이스로 인식이 되네요 (아래 2번케이스)이게 지금 문제가 되는게

  1. Role A 를 가지고 assume-role 을 수행하면 session timeout limitaion 을 최대 12시간까지 쓸수 잇는데 -> signle assume-role

  2. Role A 를 가지고 assume-role 한 role 가지고 또 assume-role 을 하면 session timeout limitation 이 max 1시간으로 픽스되는 것 같더라구요 → chain-assume-role

processor 밖에서 assume-role 을 해서 processor 의 실행인자로 넘겨 준다거나.. 하는식으로 우회하던지해야겠네요

Answer 2

role chaining 항목에 해당 설명을 확인할 수 있는데 파악하신 내용대로 AssumeRole에 대한 DurationSeconds 값은 최대 12시간 까지 설정할 수 있지만 ($aws iam update-role —role-name -max-session-duration 43200), role chaining에 대해서는 1시간으로 limit 되어 있습니다.

다음 Link에서 role chaining에 대한 대응 방법들을 guide하고 있는데 AssumeRole에 대해 추가 권한을 부여해서 role chaining이 발생하지 않도록 하는 방법도 가이드 하고 있습니다.

Role chaining이 발생하지 않도록 변경 하는 것이 쉽지 않으시면 이 방법에 대해 추가적으로 더 확인해 드리도록 하겠습니다.
