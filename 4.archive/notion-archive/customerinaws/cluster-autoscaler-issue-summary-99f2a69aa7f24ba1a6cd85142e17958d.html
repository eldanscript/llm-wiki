Cluster AutoScaler Issue Summary

Questions

  • 최근 deploy된 app의 cpu 할당량을 바꾸는 과정에서 scale up이 발생했습니다.

  • 그런데, 신규 생성된 worker node에 특정 label이 설정되지 않아 pod들이 올라가지 않는 현상을 확인했습니다.

  • 해당 pod들은 서비스용 pod로 nodeselector 옵션이 적용되어 있습니다.

  • 설정된 label은 cluster와 cluster-autoscaler가 구축된 뒤 각 노드에 설정되었으며,

  • application 의존성에 의해 label및 nodeselector 옵션을 해제할 수는 없는 상태입니다.

  • 이에 cluster-autoscaler github사이트 내 AWS 이용자용 readme 페이지에서 확인한 결과, auto scaling group에 tag를 설정하여 label을 설정할 수 있다는 내용을 확인했는데요,

  • (링크: https://github.com/kubernetes/autoscaler/blob/master/cluster-autoscaler/cloudprovider/aws/README.md#auto-discovery-setup)

  • 금일 해당 managed node group의 auto scaling group에 태그를 설정하고 테스트 한 결과 여전히 새 노드에 label이 설정되지 않았습니다. 추가로, 테스트 과정에서 cluster-autoscaler가 redeploy되었는데, 그 후에 autoscaler에 의해 생성된 새 노드에도 label은 설정되지 않았습니다.

  • cluster-autoscaler에 신규 생성 노드에 대해 label 적용을 하는 방법

Questions Arranged

  • kubectl label node {node name} kubernetes.io/nodetype=app 으로 수동 설정을 해 두면 CA로 scale out된 instance에 pod가 배포됨

  • label prefix에서 kubernetes.io를 제거하면 CA로 scale out된 instance에서는 pod 배포가 되지 않음

Target

  • worker node에 특정 label을 설정하여 pod가 올라가도록 하여야 함

  • 해결 방법으로 ASG에 tag를 설정해서 label을 설정하고자 하는데 worker node에 label 설정이 되지 않음
