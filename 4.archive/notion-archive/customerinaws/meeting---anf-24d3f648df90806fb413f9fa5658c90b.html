Meeting - ANF

Customer Request

  • 현재 AWS Network Firewall(NFW)을 활용하여 VPC 단위의 아웃바운드 트래픽을 화이트리스트 기반으로 제어하고자 합니다. 이와 관련하여, 다음과 같은 사항들의 방향성이 적절할지 자문이 필요하여 문의드립니다.

[질의 사항]

  • AWS에서 운영되는 관리형 서비스들이 내부적으로 호출하는 엔드포인트또는 도메인 목록을 제공받을 수 있을까요?

    • https://docs.aws.amazon.com/ko_kr/general/latest/gr/rande.html

  • 현재 로그 확인 시, VPC에서 wafv2m waf-regional, sts, ssmmessages, sheild 등 다양한 도메인을 질의 하는 것으로 확인됩니다.

  • 위와 같은 정책 적용 시 AWS 공식적으로 권장하는 접근 방식(예: 서비스별 Outbound Allow 정책 구성 방식, 관리형 서비스에 대한 예외 처리 방법)이 있다면 공유해주실 수 있을까요?

  • VPC 전체를 Drop 기반으로 구성할 경우, AWS 서비스 동작에 영향이 발생했을 때 문제를 진단할 수 있는 권장 절차나 도구가 있다면 안내 부탁드립니다.

  • 현재 OpenSearch에 로그를 적재하고 있으나, 개발자나 운영 담당자들이 Network Firewall에 의해서 차단되어 배포가 실패하거나, 정상 동작하지 않는 경우를 빠르게 식별할 수 있으면 좋겠습니다.

  • ANFW로 구성하면 CNP를 사용하지 않을 예정 (Pod나 Namespace 수준에서 차단) → DRIMAGE에서도 도입 (게임 서비스 적용)

보안 정책의 특징

화이트리스트 방식: 기본적으로 모든 트래픽을 차단하고, 필요한 AWS 서비스만 선별적으로 허용

세밀한 제어:

  • 일반 AWS 서비스는 허용하되

  • EC2 메타데이터와 ELB 직접 접근은 차단하여 보안 강화

SNI 기반 필터링: TLS 핸드셰이크 시 SNI 헤더를 검사하여 도메인 기반 접근 제어

이 구성은 제로 트러스트 네트워크 보안 모델을 구현하여, 필요한 AWS 서비스만 허용하고 나머지는 모두 차단하는 매우 엄격한 보안 정책입니다.
