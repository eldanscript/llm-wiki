Request History

2022/3/23

  1. Android 기능 중 work profile, 또는 managed profile 을 사용하실지 문의 드립니다.

이것은 애플리케이션이 할 수 있는 것과 할 수 없는 것을 제어할 수 있는 안드로이드의 enterprise management API를 사용합니다.

따라서, Greengrass가 설치된 프로필에 따라, 결국 Greengrass가 설치할 수 있는 것이 어떠한 것인지 영향을 받을 수 있습니다.

아래는 managed devices에 대한 안드로이드 개발자 문서의 내용입니다.

https://developer.android.com/work/dpc/dedicated-devices#managed_devices

Because dedicated devices might be left unattended or used in critical tasks, you need to secure the device. To prevent misuse, dedicated devices are fully managed and owned by an admin component (the admin component typically manages the users too).

  1. Android의 dedicated device features API인 Kiosk mode 사용하실지 문의 드립니다.

‘kiosk’ 모드는 앱의 실행이 제한되는 ‘lock task mode’라고도 불립니다. Greengrass가 device policy controller에서 허용하지 않는 앱을 설치하려고 하면 설치가 실패하기 때문에 문의 드립니다.

3) 만약 냉장고와 같은 가전제품에 Greengrass를 도입하신다면, 해당 냉장고는 LG 전자에서 제공하는 admin component에 의해서 managed device처럼 동작될 것인지 문의 드립니다.

device admin app은 장치에 보안 정책을 적용할 수 있기 때문에 문의 드립니다.

  1. Android에서 Nucleus가 설치되는 디바이스의 프로비저닝 방식에 대해서, 특별히 희망하시는 방식이 있는지 문의 드립니다.

우선, Android enterprise mobility management (EMM)은 장치 프로비저닝을 지원하여 관리되는 프로필을 생성하고 장치를 암호화하기 때문에, 이러한 EMM을 활용하실 예정이신지, 아니면 이것을 회피하여 사용하지 않으실 것인지 문의 드립니다.

또한, 잘 아시다시피 Greengrass는 (device 인증서 배포 과정을 포함하여) provisioning 과정이 필요합니다. 그래서 예를 들면, 이러한 과정이 end customer가 LG전자 가전제품을 구매하여 처음으로 power on했을 때 자동으로 실행되는 방식으로 구현하실 것인지 문의 드립니다 (예를 들면, Fleet Provisioning 방식을 활용하여).

공장에서 출하되는 가전 제품의 firmware image에 Greengrass만 preinstall 될 지, 아니면 Greengrass가 관리해야 할 app도 함께 preinstall될지 문의 드립니다.

2022/3/4

1. 추가되었으면 하는 aws-provided component

  •  공유해주신 것 이외에 더 추가되었으면 하는 것은 ML관련 컴포넌트들입니다.

해당 컴포넌트들은 초기에는 적용되지 못하더라도, 향후 적용계획이 있는지 문의 드립니다.

저희가 아직 ML컴포넌트를 적극적으로 활용해보지는 못하였으나 향후 활용할 가능성이 높은 컴포넌트 입니다.

[답변] 1) 고객님께서 ML 컴포넌트를 필요로 하신다는 내용을 GG 개발팀에 전달하였습니다**.** 하지만**,** 현재 Greengrass on Android의 필수적인 기능을 먼저 개발해야 하는 상황이어서, ML 컴포넌트는 timeline이 조금 뒤에 있게 될 것 같습니다.

2) 하지만, ML component****의 경우 저희가 미리 제작해서 드리는 AWS component****들 (Machine learning components) 외에 별도로 custom component로도 제작이 가능합니다.

Linux의 경우, 하기 워크샾을 참조하시면 Image Classification****을 위한 custom Greengrass component****를 직접 만드실 수가 있습니다 (영어로 되어 있지만 한국 AWS 직원들이 만든 워크샾입니다.).

https://main.d3pb4hy9eoxj40.amplifyapp.com/en/

3) Android OS****의 경우는 Linux****의 경우만큼 python활용이 유연하지 않기 때문에, Android OS****에서는 custom component****를 위해 ML Kit 을 활용해 볼 수 있을 것입니다**.**

하지만**,** 이 부분은 이후 Nucleus as a system service 버전이 릴리즈 후에 PoC가 필요할 것 같습니다.

  1. GG가 가전에 탑재되기 위해 필요한 지원 형태 및 보드 종류

  •  이부분은 회의에서 말씀드린 것 과 같이, 시스템 서비스 버전을 받게되면 저희가 검토한 후 사업부에 협의하려고 합니다.

따라서 우선 시스템 서비스를 받고 검토한 후에 다시 논의해야 할 것 같습니다.

[답변] 네 알겠습니다. 우선 저희는 AOSP의 공식 레퍼런스 보드인 Hi-key 960 기반으로 개발 진행하겠습니다**.**

3. 안드로이드상에서 구조 논의

  •  우선 저희가 기존에 개발한 컴포넌트들은 대부분 안드로이드에 맞추어 다시 개발해야할 것 같습니다.

다만 구조를 고민하다보니 몇가지 문의 사항이 있습니다.

1) 안드로이드에서는 시스템에 이미 gg가 포함되어 있는데, 기존 리눅스 버전에서 처럼, 별도의 설치과정이 있나요?

[답변] GG****가 AOSP의 일부로써 포함되어 있지만,

Linux****에서의 경우와 마찬가지로 Android****에서도 Greengrass****가 IoT Thing으로 등록되어야 하고, 인증서와 private kay등이 디바이스에 배포되어야 합니다.

그래서 이러한 provisioning 과정은 마찬가지로 필요합니다**.**

2) 안드로이드에서 기기 인증 방법은 어떻게 되나요? 저희가 라즈베리파이에서는 fleet provisiong을 적용해보려고 하는데,안드로이드 상에서는 어떤 인증 방법을 사용하게 되는지 궁금합니다.

[답변] Linux이던 안드로이드이던 인증 방식은 동일합니다. 동일하게 IoT Thing으로 등록되고, 디바이스 인증서와 private key를 활용하여 인증을 하게 되며,

TES (Token Exchange Service for providing AWS credentials to components) 도 동일하게 사용됩니다.

Fleet provisioning도 동일하게 사용 가능할 것으로 보입니다만, 역시 PoC는 필요합니다.

안드로이드에서 인증 절차를 공유해주시면, 해당 내용을 반영하여 구조를 잡은 후 공유드리겠습니다.

그리고 아마도 가능할 것이라고 생각되지만, kotlin기반의 앱도 지원 가능한지 확인 부탁드립니다.

[답변] Kotlin****은 초기에 제공해 드리는 Nucleus as a system service 버전에는 지원이 어렵습니다**.** 저희가 개발의 우선 순위를 Java로 포커싱하여 진행하고 있어서, Java 기반 앱만 초기에는 가능할 것 같습니다**.**
