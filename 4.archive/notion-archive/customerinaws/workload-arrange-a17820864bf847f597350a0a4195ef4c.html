Request Mail

이노텍에서 R&D 데이터플랫폼 추진 중으로, CNS 인원 투입되어 하기 아키텍처로 구축 예정입니다.

AWS 클라우드 아키텍처 설계 시 전체 아키텍처 구성 사항 및 Lambda, Glue(크롤링) 등 서비스에 조언을 주시면 어떨지 싶습니다.

저희 인원 투입 시기는 7월 중순 정도로 예상되고, 일정이 가능하시면 추후에 미팅 요청을 한번 드리도록 하겠습니다.

(데이터 크기에 따른 S3 처리 방법, Lambda à RDS DB화, Meta데이터/Raw데이터 분리 시 동일한 S3 내에서 버킷만 구분으로 가능할지 등등… 궁금한 사항이 있습니다.)

#R&D 데이터플랫폼 구축(InnoLAB)

프로젝트 개요: 측정/실험 데이터 수집/활용 플랫폼을 AWS 클라우드상에 구축함 / 추후 InnoDW 연계(‘23년)

업무 내용(CNS)

  • WEB/WAS 설치, RDS Table 생성 지원

  • L0/L1 데이터 이동 구성, Lambda 개발 영역 지원 및 표준 수립 / Glue 개발 표준 수립

아키텍처

QnA

  • 이노텍 RnD 데이터 및 장비의 Raw 데이터를 AWS 저장소에 저장

    • 데이터 크기

      • 원본 단일 파일 upload size 1GHz : 올해 월 단위 기준으로 20GB

      • Facotoba

        • Raw 데이터 파일 : tablular, CSV, png, jpg, 향후 video 파일도 존재 (1GHz)

        • Raw 데이터 파일을 (L0) 에서 L1으로 이동하고 이 데이터에 대한 meta 데이터를 생성 관리

      • Meta 파일 + 실험 데이터 파일 tar packaging 해서 Upload

      • 올해는 L0 → L1 이동에 대한 기능 테스트 : L2는 RDS에 구성

    • 데이터 용량

  • Meta 데이터를 활용해서 조회

  • Factoba와 DX로 AWS로 데이터를 업로드

  • Factoba에서 S3 bucket에 저장 (PDM)

    • 장비 History meta 정보 : 2개의 tar로 압축하여 업로드 (L0)

    • Lambda에서 tar 압축을 해제하고 메타데이터를 L1에 저장

    • 비정형 데이터 : CSV, Excel → Schema 정보 추출

    • CSV format이 비정형이 되어 있으며, 장비 ID와 Tablular 데이터에 대해 추출이 필요

  • Athena로 연계하여 query
