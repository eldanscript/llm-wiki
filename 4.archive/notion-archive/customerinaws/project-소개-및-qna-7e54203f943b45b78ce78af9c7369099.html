A) 화질은? Chime은 1080p 까지 제공 되며, 720p를 권장. 4명 정도는 1080p 는 문제 없을 것으로 판단되나 720p를 권장

A) Multi device (핸드폰, TV 등)를 사용한다면 인증을 어떻게 할 것인가? 두 기기간의 인증, 친구들간의 코드 공유, 삼성 어카운트를 사용할 것 인지? 삼성 어카운트를 SSO와 같이 인증에만 사용하고 친구 관계도나 커뮤니케이션은 다른 메커니즘을 구축할 것인지?

SS) 서비스 랩등에서는 관계도 포함하여 생각하고 있음. 이 기준으로 생각해야 할 것으로 보임. 현재는 모두 삼성 어카운트를 중심으로 이야기 되고 있음

A) Chime SDK의 경우 삼성 어카운트와 같은 다른 ID Provider와의 연동은 가능. Chime SDK가 제공하는 User management를 사용할 수 있고 혹은 따로 관리를 하기 위해서는 User management portal을 개발 하여야 함. 별도로 개발하게 되면 어려울 수 있어서 Chime SDK를 사용하면 삼성 어카운트와 인증을 맵핑 시켜서 IdP와 인증을 한 후 그 후에 친구 초대, 화상 통화 등은 차임을 사용하면 좋을 것으로 생각됨. 삼성 어카운트를 fully 사용한다면 개별 기능에서 어떻게 연동하여 사용해야 할지에 대해 고민 필요

SS) 모바일 연동은 복잡도를 높게 하고 있어 초창기의 기본적인 동작을 논의 하는 단계에서는 향후에 발생할 수 있는 것으로 생각하고 고려하였으면 함

A) 리모컨 컨트롤의 인풋을 voice command로 사용할 지 control을 사용할 지

SS) 빅스비 연동에 대해서는 내부적으로 control을 연결하는 것이어서 차후 요구 사항에 따라 가능하다고 봄. 앱 launching 정도의 연동은 현재 수준에서도 가능하며 상세 컨트롤을 보이스로 하는 것은 요구 사항이 발생하더라도 마지막에 검토하게 될 것 같음

A) 이전에 Watch Together 프로젝트를 통해서 Chime SDK 기능을 적용하고 검토한 부분이 있어 내부에서 검토하실 때 도움이 될 것 같다.

SS) 해외 연구소를 활용할 계획은 없으며 자체적으로 진행할 예정

SS) 내부 PoC를 진행하며 검토한 내용에 대한 질문.

STUN, TURN 등의 Signaling Server가 필요. AWS에서 제공하는 STUN 사용하여 (TURN은 미 사용) WebAPP으로 4인 영상 플레이 기능 확인.

Signaling 서버 필요 하다고 판단이 되었으며 KVS에서 제공하는 Signaling Server 가 아닌 별도로 구현한 서버를 사용하면 기본적인 요구 사항을 만족할 수 있겠다고 생각됨. KVS를 Chime으로 해서 저희가 TURN, STUN 사용 하고 Signaling을 별도로 구현 하는 것과 Chime SDK를 사용하여 구현하는 것의 차이를 이해하고 싶음. 아주 기본적인 요구 사항을 구현 하는 것의 차이는 ?

KVS를 사용하고 TURN, STUN도 사용하고 Signaling은 별도로 구현하거나, KVS에서도 Signaling을 지원하는 것 같은데 여기에 business loginc을 올린다고 했을 때 이것들에 대한 기술적인 차이나 비용적인 차이는?

A) KVS는 RTC 기반의 Pipeline 서비스. 용처가 다름. Chime의 경우 대부분의 기능이 구현되어 있어 API 형태로 사용. KVS는 Foundation 용도로 사용하는 서비스.Zoom 같은 서비스를 만들 때 Zoom의 다양한 서비스에 대해서는 자체 구현 하고 RTC Traffic Management에 대해서는 KVS를 사용할 수 있음. Zoom 같은 기능을 좀 더 빨리 만들어 보겠다고 할 때 Chime을 사용할 수 있음

KVS 서비스 구현의 가장 큰 허들은 RTC를 원할하게 안정적으로 제공할 수 있지만 나머지를 직접 다 개발해야 함. User 관리, Video Traffic 관리, Audio Mixing 등을 직접 해야 하는 단점이 있으며 기술 내제화가 중요, 프로젝트를 장기적으로 가져가도 괜찮고 서비스의 안정성이 중요하다고 하면 KVS를 사용할 수 있음

SS) 비용 차이는? KVS는 TURN에 대해 과금이 되고 Signaling 서버 까지 포함되어 사용되는 것으로 보이는 데 Signaling을 직접 구현하고 TURN과 STUN만 KVS를 사용하는 것도 가능한지?

A) 가능할 것으로 보이는데 확인이 필요함.

SS) Mesh 구조가 지원되는지? Master와 Viewer간 1:N 구조로 연결되는 것으로 보이는데 Mesh가 가능한지? Signaling 서버에 개설된 channel에 viewer간 연결은 되지 않는 것이 맞는가?

A) Viewer peer간 하나의 signaling 에서 연결이 가능하지 않음. 내가 송출하는 스트림에 하나의 엔드포인트가 형성되고 이 스트림 엔트포인트에 여러명의 viewer가 연결되는 구조. 4명이 있는 Room에서 peer to peer 연결을 하려고 하면 4명의 Master가 각각 3명의 Viewer에게 전송하는 형태가 되어야 함. 4개 채널을 생성 해야 함. KVS는 WebRTC pipeline을 안정적으로 사용할 수 있도록 제공되는 서비스 이며 conference 환경을 제공하는 서비스는 아님.

SS) 한달간 4인이 참여하는 room에서 평균적으로 60분 화상 통화를 하고 있고 한달 기준으로 100만 정도의 usage가 발생한다고 가정할 때 KVS를 사용하는 것과 Chime을 사용할 때 어느 정도 비용 차이가 있을지?

SS) 내년 RC (4월 이전) 정도로 예상. 이 경우에는 2월 까지 구현 완료

SS) 내년 초도로 진행 될 경우. 8월 까지 선행 완료. 상품화 완료 개발은 12월
