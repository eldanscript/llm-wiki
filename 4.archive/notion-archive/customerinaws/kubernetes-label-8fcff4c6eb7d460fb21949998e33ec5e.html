Hi Yejin,

Ricardo from AWS here.

I will try to answer the questions providing a few more information about the Cluster Autoscaler on each. However if you have any other follow up question, just let me know.

Question 1

After read the Node and Pod describe result I can see that the Node doesn’t have the labes required in the pod schedule. The Cluster Autoscaler will not work alone. The Kubernetes Scheduler [1] watches for created pods that have no Node assigned and becomes responsible for finding the best node for that pod. The Cluster Autoscaler will work to add new Nodes to the Cluster if there is not Node available to have the pods assigned.

The Cluster Autoscaler reads the nodes labels to identify node groups that have the same set of assigned labels. Thus, increasing a size of a node group will create a new Node that will be similar to these already in the cluster.

Also important to mention that the Cluster Autoscaler respects the maximum size of the Nodegroup. If reached the Maximum size the Cluster Autoscaler will not add more nodes.

Question 2

The Cluster Autoscaler will manage the AutoScaling Group based on Instance TAGs. It is important to note that you will have TAGs for the Node Instances and also Labels for nodes in the Kubernetes specs.

Pods are scheduled to Nodes using labels as Node selector.

Question 3

I would suggest to check if the Node selector match with the any Nodes labels, this is used to schedule pods to nodes. It is possible to check this describing the pending pods (observing the Node Selector [2] and also Taints and Tolerations) and the Nodes labels.

I would also recommend to take a look into the Cluster Autoscaler best practices [3] and understand how does the CA scale up and down [4].

If you have any further questions or need clarification on anything above, please feel free to reach out to me and I will be more than happy to assist you.

Answer

다음의 링크에서 ‘Edit a node group configuration’ 참조하셔서 Amazon EKS Console에서 node-group을 편집하여 label이나 tag를 추가하신 후 시험해 보시기 바랍니다.

문의 주신대로 kubernets.io label에 대해서는 제한이 걸려 있고 nodegroup 설정을 kubectl로 업데이트하는 방법으로 접근해야 할 것 같습니다.

https://github.com/kubernetes/cloud-provider-aws/issues/110

해당 이슈는 kubernetes에서 kubelet을 통해 update 할 수 있도록 allow 된 label이 제한되어 있어 EKS console로  업데이트가 어려운 것으로 판단 됩니다.

https://kubernetes.io/docs/reference/access-authn-authz/admission-controllers/#noderestriction
