Issue Support - NLB

NLB Operation

💡

https://w.amazon.com/bin/view/Elastic_Load_Balancing/Projects/ELB_Network_Load_Balancer/#HSetup

  • Network Load Balancers operate at the transport layer (Layer-4) and make routing decisions based on address information extracted from the **TCP packet header** and not from the packet content

  • Simply forward network packets to and from the upstream server without inspecting the content of the packets

  • Handle 1 million requests per second with very low latencies, while maintaining high-levels of performance

  • Connections are not terminated in the load balancer and only act as a pass through device except for address translation where applicable

Handle Failure

https://aws.amazon.com/ko/premiumsupport/knowledge-center/elb-capacity-troubleshooting/

  • a request just got to ELB

  • before ELB connected to backend, the backend failed → it’s showing as healthy because it has not crossed the unhealthy threshold

  • If the ELB tries to open a new connection (on TCP there are no pre-open connections) it goes to the surge queue until the backend responds.

  • This surge queue will get 1024 top surge connections.

  • After that it goes to Spillover. If the ELB is to able to get the connection after the timeout elapses it fails the request.

  • The ELB, once it chooses a backend tries to use that backend.

  • It won’t attempt to change the backend. Once the connection is in the surge queue, if the connection fails,the connection won’t success.

  • The process of passing the healthcheck is a separate agent so, it has to pass the whole threshold before marking it as unhealthy.
