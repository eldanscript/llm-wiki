준비 사항 논의

SDDC 구성

  • Single SDDC로 독립 배포 : VMWare 확인 (김상혁 전무, 오익준 상무)

  • 메가존에서 신규 구성 작업

  • LG 생건 에서만 액세스 가능

  • 테스트 대상 : 8개 워크로드

Network 구성

  • 현재 VPC구성 연결이 private VIF

  • LGNet에 VPC 연결 추가 문의

    • 인천 센터의 생건 IP 확인, VPC IP 대역 정보 → KO 미팅시 전달, C 클래스 4개 (254 * 4) 정도

  • 사용 기간 2주 : 사용 시점 확인 필요

  • 대역폭 100Mbps : 최소 요구 수준이지만 비용 고려하여 결정

Native AWS 계정

  • Native AWS 서비스와의 연동이 없으므로 개발 계정을 사용 하거나 account 정보 없이 구성 : Weekly 미팅에서 김동완 팀장과 확인

    • Account ID

    • Account 소유 VPC와 Subnet

  • Connected VPC 구성 시 account가 반드시 입력 하도록 최근 변경 → 임시 계정 확보 필요

  • IAM user 연동

    • 애플리케이션 level 접근은 Network I/F, routing으로 진행 됨

    • VMWare console 접근은 VMWare ID

    • Location은 AWS Infra에 구성 되지만 host 위의 애플리케이션 관리는 VMWare

    • Native AWS 서비스 연결은 AWS console로 가능

HCX (Hybrid Cloud eXtension)

  • On-prem에 virtual appliance 설치 필요

  • vCenter가 클러스터를 관리

    • vCenter당 IP 3개 필요

  • Appliance 구성 시 필요한 리소스

    • Storage

    • 방화벽 : on-prem과 VPC, PoC 기간 동안 on-prem appliance의 인증 URL 접속 허용 필요 (외부 인터넷 접속 허용)

  • vSphere 환경에 HCX appliance 구성 필요

  • HCX ver4.0 → on-prem vCenter 6.7 사용 가능

Migration 방법

  • 복제 VM 구성 작업 방식

  • Migration option

    • Cold Migration 방식

      • 기존 운영 중 prod VM을 clone 하여 migraion

      • 디스크 용량 확보 필요, SSID 급 성능 필요, 속도 빠름

      • 자원 여유, prod 영향 배제 시

    • Clone 방식

      • HCX의 DR 기능을 활용하여 clone을 DR로 진행

      • Test VM option 사용하여 동일 VM을 구성 후 VMC on AWS에 복제본 생성

      • 테스트시 동기화가 최대한 유지 되어야 할 경우

    • Application 형태에 의존적이며 Workload별 다르게 구성 가능

기타 논의

  • LB 구성 필요 여부 : 테스트 workload는 이중화 구조 필요 없는 상태

  • 쇼핑몰은 DB를 별도 Oracle 사용 : WEB + WAS

  • DB가 포함된 Workload가 존재

    • 보뗴 홈페이지 (Windows 서버) → 개발 DB 연결 혹은 VMWare에 포함 여부 확인

    • DB 포함 시 offline 상태에서 migration

    • DB 포함 시 workload 규모 재 산정 필요

Session

  • AWS Cloud에서 제공되는 주문형 VMware SDDC (Software Defined Data Center)

  • VMware 팀이 직접 vSphere 환경 유지 관리

  • vRealize Suite을 사용하여 Cloud 확장 구성 혹은 vRealize Suite SaaS를 Cloud와 연결

    • Cross ENI : data transfer 과금이 되지 않음

  • Relocation Migration

    • 동일한 vSphere 환경

    • Migration Cost Bubble 구간을 최소화 → 이익 실현 구간을 앞당김

  • Auto Scaler Service

    • Elastic DRS

    • Auto Remediation : 자동 조치 → 실패시 신규 instance (교체)

  • Migration

    • vMotion : L2 switch 이용 live migration

    • VMware HCX : migration 솔루션

  • DR

    • VMware Site Recovery : Hot DRaaS

      • 최소 node 배포 → 지속적으로 AWS Cloud로 백업 → 최소 5분 RPO

      • 최소한의 SDDC만 운영

      • 중요 workload에 대해서는 VSR로 replication

    • VCDR

      • 평상시에 VMC 배포를 하지 않고 Replication의 전용 S3에 저장 하였다가 장애가 발생할 때 SaaS 에서 로드 : 2시간 정도

  • Architecture

    • Baremetal → EC2

    • VMWare → VMC

  • Instance type

    • i3.metal, i3en.metal

  • Support

    • VMware

QnA

  • 고객이 Guest OS level 부터 관리해야 하는 것이 맞는지?

    • Yes. VSphere 환경에 대한 Managed Service 임

  • vRealize Suite 은 어떤 경우에 사용하는지?

    • 로그 취합, 사용자 VM 구성 배포, 특정 이벤트에 대한 자동화 프로세스 구성 등을 위한 component 제공

    • Governance, 장애 인지 및 proactive 대응, Automation → 운영 자동화

  • Migration의 장점이 무엇인지?

    • vMotion : 하나의 host에서 문제가 발생할 때 live migration이 가능하게 해 주는 기술

    • vMotion 기술을 사용하여 AWS Cloud로 migration을 제공하고 있음

    • Hypervisor를 그대로 이동하게 되기 때문에 VMware 상의 변경이 거의 없음 (수고가 거의 없음)

  • PoC

    • Single Host에 대해 한달 정도 PoC 테스트를 해 볼 수 있음

  • Rehost와 Relocate의 기간 차이는

    • Rehost의 40% 정도

  • 국내 사례는

    • 3 ~ 4개 정도

    • LG 화학 (Energy Solution) : 분사 3개월 직전에 시작, on-prem VMware에서 배터리 솔루션만 이전, workload 140여개

    • 삼성 물산 : MIS system

  • Setup 난이도는

    • 환경에 따라 차이 → 1개월 정도는 디자인 및 네트웍 기반 등의 셋업 (LG 화학)

  • 120대 정도 예상. 초기 Setup을 계속 활용 가능?

    • BackUp 본으로 migration 구성 후 DNS에서 switching

  • 기존의 License는 어떻게 되는지?

    • VMC에 license가 포함되어 있음

    • VMware를 통한 구매 혹은 AWS를 통한 구매 가능 : 할인 규모가 다름
