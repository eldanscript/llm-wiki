Auto Scaling - eksctl

You can create a cluster (or nodegroup in an existing cluster) with IAM role that will allow use of cluster autoscaler: eksctl create cluster —asg-access Once cluster is running, you will need to install cluster autoscaler itself. This flag also sets k8s.io/cluster-autoscaler/enabled and k8s.io/cluster-autoscaler/ tags, so nodegroup discovery should work.

https://eksctl.io/usage/autoscaling/

](https://eksctl.io/usage/autoscaling/)

Configuration file 사용 시

  • nodeGroup에 tag 설정
  • nodegroup discovery가 동작할 수 있도록 service discovery tag를 추가 하여야 한다

  • ‘—asg-access’ option 사용

Service Account에 대한 IAM Role 연결

  • AutoScalingGroup에 대한 IAM Role 정의
  • 정의한 IAM Role을 생성한다

  • 생성된 IAM Role을 Kubernetes의 Service Account에 Binding

    • cluster-autoscaler 이름을 가지는 Service Account는 rapid-cluster에서 IAM의 OIDC provider에게 발급받은 token을 통해 AWS ASG를 access 할 수 있는 k8s-asg-policy를 사용할 권한을 가진다.
  • cluster-autoscaler Service Account를 확인

Cluster Autoscaler

💡

Kubernetes cluster의 크기를 자동으로 조절하는 도구

[

kubernetes/autoscaler

Cluster Autoscaler is a tool that automatically adjusts the size of the Kubernetes cluster when one of the following conditions is true: there are pods that failed to run in the cluster due to insufficient resources. there are nodes in the cluster that have been underutilized for an extended period of time and their pods can be placed on other existing nodes.

https://github.com/kubernetes/autoscaler/tree/master/cluster-autoscaler

](https://github.com/kubernetes/autoscaler/tree/master/cluster-autoscaler)

  • Cluster size가 조절되는 case

    • 리소스 부족으로 pod 생성 fail

    • 오랜 기간 동안 이용할 수 없는 클러스터에 노드가 있으며 다른 기존 노드에 pod를 배치 할 수 있는 경우
