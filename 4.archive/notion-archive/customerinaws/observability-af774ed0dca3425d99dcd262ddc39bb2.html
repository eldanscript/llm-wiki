Observability

1. Private worker node의 Grafana Access

Subnet Auto Discovery

https://kubernetes-sigs.github.io/aws-load-balancer-controller/guide/controller/subnet_discovery/

  • AWS Load Balancer Controller는 기본적으로 ALB 또는 NLB 용 네트워크 서브넷을 자동으로 검색합니다. ALB는 가용성 영역에 적어도 두 개의 서브넷을 필요로하며 NLB에는 하나의 서브넷이 필요합니다. 서브넷은 자동 검색이 작동하려면 적절하게 태그가 지정되어야합니다. 컨트롤러는 각 가용 영역에서 하나의 서브넷을 선택합니다.

Load Balancer에서 Auto Subnet Discovery를 위한 Tag 지정

  • https://aws.amazon.com/ko/premiumsupport/knowledge-center/eks-vpc-subnet-discovery/

  • 추가 Tag : **kubernetes.io/cluster/: shared**

Step1 ) Add Tag to Subnet

  • Public Subnet descirption을 확인
  • Add Tag : kubernetes.io/cluster/rapid-cluster: shared
  • Check Tag

Setp2) Grafana Install

Install Configuration

https://github.com/grafana/helm-charts/tree/main/charts/grafana

  • Install via Helm chart
  • Check Grafana Service status

Access Grafana

  • LoadBalancer Ingress URL 접속 : http://a90aa04256dd7459391c87b41821b026-1983326853.ap-northeast-1.elb.amazonaws.com

Setp3) Create ALB to access Grafana

ALB Setup Guide

https://docs.aws.amazon.com/elasticloadbalancing/latest/application/create-application-load-balancer.html

Setup ALB

  • Listener 설정

    • HTTP 80 port로 입력되는 traffic을 Grafana instance 3000 port로 redirection

  • Target Group 설정

    • Port : 3000

    • Health Check Success Code : 302 (Health check simulation 결과 값 사용)

Access to Grafana

  • Open ALB URL

  • Default 계정 정보로 login : admin / admin

Associate Prometheus

  • DataSource에 Prometheus 추가

  • Server URL에 Prometheus의 LoadBalancer Ingress URL 입력
