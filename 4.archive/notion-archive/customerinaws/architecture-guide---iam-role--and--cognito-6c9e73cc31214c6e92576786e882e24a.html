Architecture Guide - IAM Role & Cognito

Question

  • 로그인이 완료된 사용자의 경우 jwtToken / refreshToken을 발급하여 앱으로 전달 하고 (토큰 발급과 관리는 cognito에서 하는건지 인증 서버를 따로 두어야 하는지도 궁금합니다) 이후 서버 통신에 대해서는 해당 토큰을 사용할 수 있을까요? 해당 토큰은 추후 ON HYBE 외 다른 시스템이 API gateway 이후에 붙는 경우 동일하게 사용될 수 있는지 궁금합니다

Answer

  1. 토큰 발급과 관리는 cognito에서 하는건지 인증 서버를 따로 두어야 하는지

    1. 따로 구성하실 필요가 없습니다. Cognito는 User Pool에 등록된 local user를 대상으로 token 발급과 갱신을 수행하는 standalone IdP 역활을 수행하며 동시에 3rd party IdP와 연동하여 federated user에 대해서도 token 발급과 갱신 역할을 수행하기 때문에 단일 token 발급, 갱신 서비스로 활용하실 수 있습니다. (https://docs.aws.amazon.com/cognito/latest/developerguide/what-is-amazon-cognito.html#what-is-amazon-cognito-features)

  2. 이후 서버 통신에 대해서는 해당 토큰을 사용할 수 있을까요?

    1. 동일한 Auth token을 사용하신다면 해당되는 서브 시스템의 인증 절차를 Cognito를 통해 진행하시는 방법을 선택할 수 있을 것 같습니다. 다음 링크에서 Cognito에서 발급한 JWT token validation을 구현하는 예를 참고 하시면 좋을 것 같습니다. (https://repost.aws/knowledge-center/decode-verify-cognito-json-token).

    2. 연동하실 서버의 구성등을 고려해야 하니 이 부분은 자세한 내용을 공유해 주시고 확인해 보아야 할 것 같습니다.

  3. 해당 토큰은 추후 ON HYBE 외 다른 시스템이 API gateway 이후에 붙는 경우 동일하게 사용될 수 있는지?

    1. API Gateway에서 Cognito를 이용한 인증 과정은 다음과 같은 flow로 진행 됩니다. Client가 API Gateway를 통해 접근하면 Cognito의 User Pool을 통해 사용자를 인증하고 access token을 발급합니다. Client는 해당 token으로 API에 접근하게 되는데 API Gateway에서는 해당 token에 대한 authorizer를 등록해 두고 발급한 token과 client가 access하는 token을 비교하여 authorization을 진행하게 됩니다. (동작 방식 안내 블로그 링크 : https://aws.amazon.com/blogs/architecture/web-application-access-control-patterns-using-aws-services/) 여러개의 API Gateway에서 동일한 auth token을 같이 사용하고 싶다면 각 API Gateway가 동일한 Authorizer를 사용하도록 구성하면 됩니다.

    2. 다른 방법으로는 인증을 위한 Single API Gateway를 구성하여 인증을 진행하고 routing 하는 방식으로 구성할 수 있을 것 같습니다.

Question

EKS가 아닌 외부 Self-hosted 쿠버네티스 클러스터내 pod에서 IAM Role 권한 호출이 필요하여 문의드립니다.

아래 2가지 방법이 있는걸로 확인되는데 권장되는 방법 또는 추가적으로 다른 방법이 있는지 확인 부탁드리겠습니다.

AccessKey 사용은 지양하고 있습니다.

    1. AWS IAM Roles Anywhere
    • https://aws.amazon.com/ko/blogs/security/extend-aws-iam-roles-to-workloads-outside-of-aws-with-iam-roles-anywhere/
    1. AWS IRSA(IAM Roles for Service Account)

    • https://github.com/aws/amazon-eks-pod-identity-webhook/blob/master/SELF_HOSTED_SETUP.md

    • https://github.com/smalltown/aws-irsa-example

추가적으로 1번 Anywhere 의 경우 private key 를 생성해야 하는데 AWS Private key의 경우 한달에 400불로 비용이 좀 비싼데,

External certificate bundle 로 사용 할 수 있는 인증서 생성 가이드가 있는지 추가 확인해주시면 감사하겠습니다.
