Guides from LLM

Prompt

💡

Amazon Bedrock Knowledge Base와 AWS Lambda를 사용하여 RAG 기반의 chatbot을 만들었습니다. 데이터 소스는 S3에 document를 업로드 하여 OpenSearch로 embedding vector를 생성하여 사용하고 있습니다. 여기에 Amazon Aurora MySQL 테이블을 데이터 소스로 추가하여 사용자 질의 중 Aurora에 저장되어 있는 데이터를 조회하는 기능을 Text-to-SQL을 사용하여 추가하려고 합니다. 다음의 기능들 동작을 위한 AWS Lambda 코드를 가이드하고 Infra에 추가 설정이 필요하면 알려 주세요. 코드 구성과 함께 프롬프트를 예를 들어 같이 가이드해 주세요.

  1. Amazon Aurora MySQL의 table schema 파악과 변경 발생에 대한 업데이트

  2. 사용자 질의에 대해 Aurora 조회 여부 판단

  3. Aurora용 쿼리 생성과 조회 결과에 대한 사용자 응답 생성

Cedric

안녕하세요. 여러분의 프로젝트에 대해 자세히 설명해 주셔서 감사합니다. 이 프로젝트에 대해 제가 가진 견해와 제안 사항을 말씀드리도록 하겠습니다.

  1. Aurora MySQL 테이블 스키마 파악 및 업데이트 방법:

    • AWS Management Console에서 Aurora 데이터베이스 클러스터에 연결할 수 있는 데이터베이스 클라이언트 도구(예: MySQL Workbench, AWS CLI 등)를 사용하여 데이터베이스에 연결할 수 있습니다.

    • 데이터베이스에 연결한 후 SHOW TABLES; 명령어로 테이블 목록을 확인하고, DESCRIBE <table_name>; 명령어로 각 테이블의 스키마를 확인할 수 있습니다.

    • 새로운 테이블이 추가되거나 기존 테이블의 스키마가 변경되는 경우, 이를 주기적으로 확인하고 애플리케이션 코드를 업데이트해야 합니다.

  2. 사용자 질의에 대한 Aurora와 Bedrock Knowledge Base 데이터 소스 선택 방법:

    • 사용자 질의의 특성에 따라 Aurora 데이터베이스와 Bedrock Knowledge Base 중 어느 데이터 소스를 사용할지 결정해야 합니다.

    • 사용자 질의가 구조화된 데이터(예: 제품 정보, 주문 내역 등)와 관련된 경우 Aurora 데이터베이스에서 데이터를 조회하는 것이 적합합니다.

    • 사용자 질의가 일반적인 지식이나 정보와 관련된 경우 Bedrock Knowledge Base에서 데이터를 조회하는 것이 적합합니다.

    • 필요에 따라 두 데이터 소스를 함께 활용할 수 있습니다. 예를 들어, Aurora 데이터베이스에서 관련 정보를 먼저 조회한 후 Bedrock Knowledge Base에서 추가 정보를 얻는 식으로 사용할 수 있습니다.

  3. Aurora 쿼리 생성 및 데이터 조회, 응답 생성:

    • 사용자 질의에 적합한 SQL 쿼리를 작성하여 Aurora 데이터베이스에서 데이터를 조회할 수 있습니다.

    • 조회된 데이터를 활용하여 사용자에게 적절한 응답을 생성할 수 있습니다. 이 때 RAG(Retriever-Annotator-Generator) 기반 chatbot 모델을 사용하면 좋습니다.

    • 예를 들어, 조회된 데이터를 Retriever 모듈에서 활용하고, Annotator 모듈에서 데이터를 처리하여 응답을 생성할 수 있습니다.

이 외에도 보안, 성능, 확장성 등 다양한 측면을 고려해야 할 것 같습니다. 예를 들어 Aurora 데이터베이스에 대한 안전한 액세스 권한 관리, 쿼리 최적화, 데이터 캐싱 등이 필요할 수 있습니다.

  • RAG 기반 chatbot 구현 예시: https://github.com/pytorch/fairseq/tree/main/examples/rag.

Perplexity

Amazon Aurora MySQL과 AWS Lambda를 활용한 RAG 기반 챗봇 확장 방안

AWS Bedrock Knowledge Base와 Lambda를 활용한 RAG(Retrieval-Augmented Generation) 시스템에 Amazon Aurora MySQL 통합을 위한 아키텍처 설계 및 구현 전략을 종합적으로 분석합니다. 본 보고서는 텍스트-to-SQL 변환 기술을 활용한 하이브리드 데이터 처리 모델의 기술적 구현 세부사항과 인프라 구성 요건을 체계적으로 제시합니다.

통합 아키텍처 개요

기존 S3-OpenSearch 기반 RAG 시스템에 Aurora MySQL 데이터 소스 추가 시 요구되는 핵심 구성 요소를 3계층 모델로 재구성합니다. 데이터 접근 계층에서는 Lambda 함수가 Bedrock의 GenerateQuery API와 연동하여 동적 SQL 생성을 수행하며, 이벤트 기반 트리거 메커니즘을 통해 스키마 변경 사항을 실시간 감지합니다.

Hybrid RAG Architecture

벡터 저장소(OpenSearch)와 관계형 저장소(Aurora MySQL) 간의 쿼리 라우팅 메커니즘은 사용자 의도 인식 모듈을 통해 구현됩니다. 자연어 처리 계층에서는 사용자 질의의 의미론적 분석을 수행하여 최적의 데이터 소스를 선택하는 지능형 라우팅 시스템을 구축합니다.

결론 및 향후 개선 방향

본 아키텍처는 하이브리드 데이터 소스 환경에서 RAG 시스템의 확장성을 입증하였습니다. 실제 구현 시 다음 요소들을 추가 고려해야 합니다

  1. 다중 데이터베이스 지원: PostgreSQL, Redshift 등 다른 관계형 시스템으로의 확장

  2. 자동 스키마 최적화: 생성된 쿼리 패턴 분석을 통한 데이터베이스 인덱스 자동 튜닝

  3. 프라이버시 보호: 동적 데이터 마스킹과 PII 탐지 기능 통합

  4. 비용 최적화: 쿼리 복잡도 기반 실행 경로 선택 알고리즘 구현

향후 생성형 AI의 발전에 따라 자연어-SQL 변환 정확도가 지속적으로 개선될 전망입니다. 사용자 피드백 루프를 구축하여 모델 성능을 지속적으로 진화시켜야 하며, MLOps 파이프라인과의 통합이 필수적입니다.
