Issue Support - Feature Request

Request Item

Request#1 : AWS IoT 인증서 발급에 사용된 CA 인증서 요청

  • 기기-서버 통신채널 다변화/효율화를 위해서 제품에서 MQTT 외에 다른 채널도 활용하고자 함 (그 중 하나의 후보군이 mTLS)

  • 이 경우 AWS IoT 인증서 발급에 사용된 CA 인증서로 인증을 하고자 하는데, 해당 인증서를 구할 방법이 없음.

  • 문제가 없다고 하면, 해당 인증서를 받고자 함

  • Internal Review

    • Public으로 오픈된 RootCA를 mTLS를 사용할 수 있는지에 대한 여부

Request #2 : subscribe, publish에 대한 combined protocol

  • 현재 AWS IoT Device SDK를 활용하고 있음.

  • SUBCRIBE, SUBOK, PUBLISH, PUBOK 순서로 sequence가 이루어지는데, 속도를 빠르게 하기 위해서 Subscribe, Publish를 진행한 결과 Subok가 오기 전에 보내지는 현상이 있으며, 간헐적으로 SUBOK 리턴이 느려서, 전체적인 성능이 늦어지는 케이스도 있었음.

  • Internal Review

    • SDK version은 어떻게 되는지? 사용하지 않는 것으로 연초에 얘기했었는데 현재 적용중 인지

    • Subscribe callback으로 처리가 되어 있는지?

Rejected Item

Request #3 : AWS IoT Feature Deployment

  • 현재 LG 전자 입장에서 Production 으로 운영되고 있는 인프라 팜에 Deployment가 진행되는데, 이 경우 ThinQ 서비스 장애가 발생할 수 있음 (최근에 있었음)

  • 요청은 LG 전자의 Staging 혹은 QA 인프라 팜에 먼저 Deployment 되는 것을 요청함. (인프라팜마다 계정 id는 다름..)

    • AWS TAM 응답은 ’ 런던이 대부분 Pre-deploy에 활용되는 것이어서 런던에 팜 구축에 대한 제안’을 했었음

    • 신규 팜을 만드는 것이라서 현실적이지 않아 보임

  • Internal Review

    • 고객의 환경을 AWS Test Phase에 넣을 수 없다

    • PDX의 QA workload로 옮기면 모니터링이 가능하지 않겠는가?

    • LG 계정에 포함된 device를 AWS test에 포함되도록 요청 → Side Effect에 대한 관리 요청

    • SW deployment의 영향을 최소화 할 수 있는 방안이 없는지?

    • Service team에서 deploy시 gradually하게 진행 하므로 초기에 영향을 발견하게 되면 최소화 할 수 없을지? → gradually deployment

    • Gradually deployment도 설정 변경에 대해서는 바로 영향을 받기 때문에 방법이 없음

    • Deployment 사전 공지가 예전에는 있었으나 최근 없음 → 확인 필요

    • Service Team에 Gradually deployment 진행 (Configuration 포함) → 영향 사전 대응
