Guide - China Expansion

Mail Guide @June 10, 2023

1. AWS China 현황 및 중국 규제

  1. AWS China Region 및 Service

  • AWS는 중국의 법률 및 규제 요구 사항에 따라 적합한 telecom 라이센스를 보유한 중국 현지 파트너사와 협력하여 Beijing 및Ningxia region에 리전을 구축하였습니다.

  • Beijing region(BJS, PEK) 은 2016년도에 시작되었으며Sinnet (Beijing Sinnet Technology Co. Ltd) 에서 Ningxia region (ZHY)은 2017년도에 시작되었고 NWCD (Ningxia Western Cloud Data Technology Co. Ltd) 에서 운영하고 있습니다. 각 region은 모두 3개의 AZ를 가지고 있습니다.

  • China region은 로컬 관리 콘솔과 계정 시스템을 사용하여 AWS Global과 유사한 GUI와 API를 서비스 하고 있으며 AWS Global과 동일한 수준의 성능과 보안을 제공 하고 있습니다. China 도메인은 www.amazonaws.cn 이고 China의 AWS 서비스에 대한 Endpoint는다음 링크에서 확인하시면 됩니다. (China Region Endpoint List)

  • China region에서 현재 111개의 서비스가 사용 가능하며 상세 리스트는 다음 링크를 통해 확인할 수 있습니다. (China Region Service Table) 구축을 검토하는 서비스와 Global과 연동하기 위한 서비스들을 리스트에서 확인해 보시면 될 것 같습니다.

  • China region에서 사용 가능한 Instance Type에 대해서는 다음 링크를 통해 확인할 수 있습니다. (China Region Instance Type)

  1. AWS China 제약 사항

  • AWS Networking – AWS global backbone과 직접 연결되어 있지 않고 Internet을 통해 연결이 됩니다. Global과 China region간의Network 지연 시간 감소를 위해서 중국 ISP와 협력하여AWS DX를 연결할 수 있습니다. 협력 가능한 중국 ISP는 China Mobile, China Telecom, China Union 이 있습니다.

  • Data Transfer – PIPL과 같은 중국 법률을 준수하여 데이터 전송 및 현지화를 구성해야 합니다.

  • AWS Account – China region에서는 root나 account의 개념이 없으며 모든 사용자는 IAM을 통해 user로 등록되어 사용합니다. 최초China region 등록 시 모든 권한을 가진 administrator IAM user를 생성하여 사용하게 됩니다. 사용자는 ICP recordal의 보유 여부에따라 권한이 다음과 같이 제한 됩니다.

    • Internal Access Account (ICP recordal / ICP license미 보유) – Internet을 통한 public access를 제한 합니다. EC2의 경우 port 22와3389을 제외하고 모든 internet port가block 됩니다. S3는 public anonymous access와 pre-signed URL 기능이 허용되지 않습니다.

    • Fully Access Account (ICP recordal / ICP license보유) – China region의 모든 AWS 기능을 사용할 수 있습니다.

  • AWS VPC (China region의 VPC 기능 안내)

    • Isolation – AWS China region의 VPC는 Global region과 격리가 되어 있어야 합니다.

    • VPN – AWS Site-to-Site VPN이 지원되지 않습니다. VPN 연결을 사용할 경우에는 EC2에 VPN 서비스를 직접 구축하여 가능 합니다.

    • VPC 간 연결 – VPC attachment나 VPC peering은 Transit Gateway를 통해서만 가능 합니다.

  • Amazon EC2 (China region의 EC2 기능 안내)

    • China region에서 사용 가능한 Instance Type에 대해서는 다음 링크를 통해 확인할 수 있습니다. (China Region Instance Type)

    • AMI에 대한 Cross-region copy 기능은 AWS China region으로 제한 됩니다. Global region과 China region간 copy는 지원되지 않습니다.

  • Amazon S3 (China region의 S3 기능 안내)

    • AWS Global과 AWS China간 cross-region replication이 허용되지 않습니다.

    • Static Website hosting과 Presigned URL 기능은 ICP license를 보유해야 사용할 수 있습니다.

  • Amazon ECR (China region ECR 기능 안내)

    • AWS Global과 AWS China간 cross-region replication이나 cross-account replication이 지원되지 않습니다.

  • Amazon CloudFormation (China region CloudFormation 기능 안내)

    • AWS Global과 AWS China의 AWS account나 credential은 분리되어 있음

    • Automation 작업 시 AWS Global과 AWS China의 Service Endpoint나 ARN의 차이를 고려해야 함 (arn:aws-cn, amazonaws.com.cn)

2. AWS Global****과 AWS China 인프라**,** 서비스 간 연동

  1. China region과 AWS Global 간의 Network 연결 Option

  1. Internet (Public Network) 을 통한 연결 (기본 구성)

    • 인터넷 경로 및 상황에 따라 속도 변화가 발생, 안정적인 연결 유지 어려움.

    • 데이터 전송 횟수가 적고 한번에 보내는 데이터 크기가 작은 경우 사용 가능. 추가 비용이 발생하지 않음

    • 서버의 TCP BBR (Bottleneck Bandwidth and RTT) 을 활성화 하여 전송 최적화. 데이터 송/수신 Instance에 Network 성능이 좋은 type 적용

  2. 통신 사업자가 제공하는 최적의 Link 사용

    • 인터넷 전송 대비 네트웍 혼잡이나 hop을 줄일 수 있지만 네트웍 상황에 따른 영향은 동일하게 발생

    • 데이터 전송 횟수가 적고 한번에 보내는 데이터 크기가 작은 경우 사용 가능. 추가 비용이 발생하지 않음

    • 서버의 TCP BBR 을 활성화 하여 전송 최적화. 데이터 송/수신 Instance에 Network 성능이 좋은 type 적용

  3. AWS Direct Connect 구축

    • AWS 파트너 사인 China Telecom, China Unicom 솔루션 활용 구축. 안정적이고 빠른 연결이 가능 하지만 DX 비용 발생 (Direct Connect AWS Partner 목록)

    • Target Global Region과 China Region간의 DX를 구성 하거나 China Region과 근접한 Region (Hong Kong, Singapore, Tokyo) 간에DX를 구성하여 AWS Global backbone 과 연결 구성 – 1Gbps 혹은 10Gbps 지원

    • China region과 AWS Global 간의 DX 구성을 통한 VPC 연결 구축 사용 예 (참조 블로그 링크)

  4. SDWAN 구축

    • AWS 파트너 사가 배포한 Global 네트워크 인프라 활용

    • 단기간 데이터 전송이나 DX 대비 적은 비용으로 유지가 필요할 경우

    • KINX의 China Direct Connect (서비스 소개 링크), ChinaDX-Asia (Marketplace 링크) 등

  1. Global region과 China region간 데이터 전송

  1. Server to Server 전송

    • SCP나 FTP를 이용하여 EC2 instance 간 데이터 전송

    • Open source file transfer tool 사용 전송 (tsunami-udp 등)

    • Commercial file transfer tool 사용 전송 (Raysync, CatonNet 등)

  2. Server to S3 전송

    • 데이터를 소스 region 의 EC2 인스턴스에서 대상 region의 EC2 인스턴스로 전송하고 EC2 인스턴스에서 S3로 업로드

  3. S3 to S3 전송

    • 소스 S3에 object 생성에 대한 trigger event 생성 후 Lambda를 호출하여 Lambda에서 대상 S3로 복사 진행

    • 소스 S3의 데이터를 동일 region EC2 인스턴스로 복사 후 EC2 인스턴스 간 데이터 전송. 대상 EC2 인스턴스에서 동일 region S3로 복사

    • 소스 S3의 데이터를 동일 region EC2 인스턴스로 복사 후 EC2 인스턴스에서 대상 region S3로 복사 (참조 블로그 링크)

  1. Global region과 연계한 CI/CD 구축

  1. CodePipeline을 이용하여AWS Global region에서 AWS China region으로 리소스 배포 (참조 블로그 링크)

  2. 솔루션 구축 과정

    1. China region에 배포할 리소스 (Lambda, Beanstalk, EC2, ECS, EKS 등)에 대한 권한을 가지는 Access Key를 생성

    2. Access Key를 암호화 한 후 Global region의 SSM Parameter 에 저장

    3. Global region의 CodePipeline은 SSM parameter의 Access Key를 사용하여 China region으로 리소스 배포
