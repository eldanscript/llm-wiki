Deck

Docker

Networking Mode

  • Reference Blog : https://bluese05.tistory.com/15

Container Runtime

  • Containerd

    • Docker에서 컨테이너 런타임 부분을 분라하여 만든 오픈 소스 컨테이너 관리 도구

    • Kubernetes 통신에 필요한 CRI 규격에 맞춰 구현한 plug-in 사용하여 kubernetes와 통합

  • CRI-O

    • RedHat에서 개발해 CNCF에 기부한 오픈 소스 프로젝트

    • Kubernetes 통합이 주목적으로 CRI 규격을 자체적으로 구현

  • Kata Container

Union File System

  • 복수의 파일시스템을 하나의 파일시스템으로 마운트하는 기능으로, 두 파일 시스템에서 동일한 파일이 있다면 나중에 마운트된 파일 시스템의 파일을 오버레이

  • 하위 파일시스템에 대한 쓰기 작업은 CoW(Copy On Write) 전략에 따라 복사본을 생성하여 수행하므로 원본 파일 시스템은 변하지 않는 것이 특징

Kubernetes

Basic Objects

  • Pod

    • 쿠버네티스 실행 최소 단위

    • 독립적인 공간과 사용 가능한 IP

  • Namespaces

    • 클러스터에 사용 되는 리소스 들을 구분해 관리하는 그룹

    • default, kube-system, metallb-system

  • Volume

    • 파드에서 사용할 수 있는 디렉토리를 제공

  • Service

    • 내/외부의 파드 접속을 안정적으로 유지

Object Spec

  • YAML 문법으로 작성

Service

  • 외부에서 클러스터에 접속하는 방법을 제공

  • NodePort

    • worker node의 특정 포트를 열고 여기로 오는 모든 요청을 NodePort 서비스로 전달

    • NodePort 서비스는 해당 요청을 처리할 수 있는 pod로 전달

    • 1개의 NodePort에 1개의 Deployment만 적용 (port 중복 사용이 안됨)

Ingress

Features

  • 여러 개의 Deoployment가 있을 때 그 수만큼 NodePort 구성 → Ingress를 사용

  • 고유한 주소를 제공해 사용 목적에 따라 다른 응답을 제공

  • Traffic에 대한 L4/L7 load balancer 및 보안 인증서 처리 기능 제공

Ingress

  • LoadBalancer + NodePort → Ingress object

  • Ingress Controller 서버와 함께 사용

    • NGINX Ingress Controller, Kong API gateway

    • Cloud 공급 업체 : ALB

DaemonSet

  • 노드 하나 당 한 개만 생성 : Replicas가 노드 수 만큼 정해지는 형태

  • 노드를 관리하는 pod는 DaemonSet으로 하는 것이 효율적

ConfigMap

  • Config를 목적으로 사용하는 오브젝트

  • 범용 설정으로 사용

PV & PVC

  • PV : 볼륨을 사용할 수 있게 준비

  • PVC : 준비된 볼륨에서 일정 공간을 할당받는 것

StatefulSet

  • 파드가 만들어지는 이름과 순서를 예측

  • 주로 Master-Slave 구조 시스템에서 필요

  • volumeClainTemplates를 이용해 자동으로 파드에 독립적인 스토리지를 할당 구성

  • 안정된, 고유한 네트워크 식별자, 지속적인 스토리지, 순차적인 배포 및 스케일링

RBAC

API Server 권한 인증

  • HTTP handler → Authentication → Authorization → Mutating Admission Controller → Validating Admission Controller

  • Auth : Service Account, OIDC (OAuth), Certificate

  • ~/.kube/config 파일에 저장한 인증서 키 쌍을 이용해 API 서버에서 인증

  • Cluster 내부에서 API 서버 접근

    • Pod 생성 시 Service Account의 시크릿을 pod 내부에 mount

    • API Server 접근 시 secret token을 HTTP 요청에 포함

Service Account

  • 체계적으로 권한을 관리하기 위한 Kubernetes 오브젝트

  • 한 명의 사용자나 애플리케이션에 해당

권한 부여

  • Role

    • Namespace에 속함

    • 예) 서비스 목록 조회, Deployment 생성, …

  • ClusterRole

    • Namespace에 속하지 않음

    • Cluster 단위의 권한을 정의

    • 예) PV 목록을 조회
