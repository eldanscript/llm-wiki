PySpark Config

Issue

PysparkProcessor의 spark configuration 셋팅 문제입니다. (Spark version 2.4)

spark configuration을 두 가지 방법으로 설정할 수 있습니다.

  1. code level

첫번째 방법(code level)로 설정할 시에 spark configuration이 제대로 변경되지 않는듯합니다. 

spark configuration을 출력해보면 정상적으로 반영된것으로 보이나, 셋팅이 제대로 되지 않아 결국 에러가 발생합니다.

  1. pysparkprocessor의 configuration 파라메터

동일한 configuration을 두번째 방법(pysparkprocessor configuration 파라메터)로 넘기면 코드가 정상동작합니다.

이슈가 되는 configuration은 ‘spark.driver.maxResultSize’, ‘-1’ 로 예상됩니다.

이유는 dataframe을 collect()하는 과정에서 문제가 되기 때문입니다.

Answer

안녕하세요. 김원균 프로님

기존 EMR 사용시 code level configuration이 적용되었다고 하셔서 확인이 더 필요할 수 있지만 Spark property 중 일부는 Driver Process및 SparkSession을 구성하기 위해 submit option이나 configuration file로 설정이 가능한 것으로 확인이 됩니다. Spark Properties 링크 에서 다음과 같이 안내하고 있습니다.

💡

Spark properties mainly can be divided into two kinds: one is related to deploy, like “spark.driver.memory”, “spark.executor.instances”, this kind of properties may not be affected when setting programmatically through SparkConf in runtime, or the behavior is depending on which cluster manager and deploy mode you choose, so it would be suggested to set through configuration file or spark-submit command line options; another is mainly related to Spark runtime control, like “spark.task.maxFailures”, this kind of properties can be set in either way

공유해 주신 pysparkprocessor configuraion에서만 적용이 된다고 하는 설정이 이런 property에 대한 것이 아닌지 확인해 주시면 감사하겠습니다.

Runtime에서 변경할 수 있는 property에 대해서는 아래와 같이 Spark Properties 링크에서 안내하고 있는데 Spark 구동시 설정하는 Property와 Code Level에서 적용하는 설정을 구분하여 적용하는게 맞는 것 같습니다.

https://spark.apache.org/docs/latest/configuration.html#runtime-environment

https://spark.apache.org/docs/latest/configuration.html#runtime-sql-configuration

maximizeResourceAllocation 설정은 Spark property가 아닌 Amazon EMR에서 사용되는 Spark config shortcut으로 EMR node에서 리소스를 최대로 사용하기 위해 spark.driver.memory나 spark.executor.memory, spark.executor.cores, spark.executor.instance등의 Spark property 값을 구성 합니다. (링크 참조)

spark-submit이나 configuration file로 설정이 되어야 하는 이유도 위에서 설명드린 대로 Spark 구동 시 적용되어야 하는 Spark property들이 사용되는 것이기 때문으로 보시면 되겠습니다.

maximizeResourceAllocation 설정에 대해서는 maximizeResourceAllocation = true 옵션으로 구성할 때는 maximizeResourceAllocation 설정에서 사용되는 property 등에 대해서는 추가로 설정하지 마시고

현재 구성하시는 설정들로 사용 하신다면 maximizeResourceAllocation 옵션은 적용하지 않는 방법으로 시험해 보시기 바랍니다.

Instance Size나 Spark Application에 따라 maximizeResourceAllocation 설정의 효과가 다를 수 있으니 비교해 보시고 적용 여부를 결정하시면 좋을 것 같습니다.
