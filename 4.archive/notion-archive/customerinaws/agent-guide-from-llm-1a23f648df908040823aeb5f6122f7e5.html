Agent Guide from LLM

Orchestration Default Process

Amazon Bedrock Agents의 기본 orchestration process에 대해 설명드리겠습니다. 이 프로세스는 사용자 입력을 처리하고 적절한 응답을 생성하는 일련의 단계로 구성됩니다.

  1. 사용자 입력 수신:

    • 프로세스는 사용자로부터 텍스트 입력을 받는 것으로 시작합니다.

  2. 입력 분석:

    • 에이전트는 자연어 처리 모델을 사용하여 사용자 입력을 분석합니다.

    • 이 단계에서 사용자의 의도와 요청의 주요 요소를 식별합니다.

  3. 작업 결정:

    • 분석 결과를 바탕으로 에이전트는 다음 작업을 결정합니다.

    • 이는 직접 응답, 추가 정보 요청, 또는 특정 도구 사용 등일 수 있습니다.

  4. 모델 호출:

    • 필요한 경우, 에이전트는 기본 언어 모델을 호출하여 응답을 생성하거나 추가 분석을 수행합니다.

  5. 도구 사용:

    • 작업 수행을 위해 필요한 경우, 에이전트는 정의된 도구(예: API 호출, 데이터베이스 쿼리)를 사용합니다.

  6. 지식 베이스 참조:

    • 관련 정보가 필요한 경우, 에이전트는 연결된 지식 베이스를 참조합니다.

  7. 응답 생성:

    • 수집된 정보와 처리 결과를 바탕으로 최종 응답을 생성합니다.

  8. 가드레일 적용:

    • 생성된 응답에 대해 정의된 가드레일을 적용하여 안전성과 적절성을 확인합니다.

  9. 사용자에게 응답 전달:

    • 최종 처리된 응답을 사용자에게 전달합니다.

  10. 컨텍스트 유지:

    • 대화의 컨텍스트를 유지하여 후속 상호작용에 활용합니다.

  11. 반복:

    • 사용자의 새로운 입력이 있을 경우 프로세스를 반복합니다.

이 기본 orchestration process는 대부분의 일반적인 사용 사례에 적합하도록 설계되었습니다. 그러나 더 복잡하거나 특수한 요구사항이 있는 경우, custom orchestration을 통해 이 프로세스를 수정하거나 확장할 수 있습니다.

Custom Orchestration

귀하의 질문은 매우 통찰력 있습니다. Amazon Bedrock Agents의 custom orchestration 기능과 일반적인 Lambda 사용의 차이점을 명확히 하는 것이 중요합니다. 이에 대해 설명드리겠습니다:

  1. 기본 에이전트 동작:
    기본적으로 Amazon Bedrock Agents는 사전 정의된 오케스트레이션 로직을 사용합니다. 이는 대부분의 일반적인 사용 사례에 적합하도록 설계되었습니다.

  2. Lambda의 일반적인 사용:
    에이전트는 indeed Lambda 함수를 사용하여 특정 작업을 수행할 수 있습니다. 그러나 이는 주로 개별 작업이나 도구 호출에 사용되며, 전체 대화 흐름을 제어하지는 않습니다.

  3. Custom Orchestration의 차별점:

    • 전체 대화 흐름 제어: Custom orchestration을 사용하면 개발자가 전체 대화 프로세스를 세밀하게 제어할 수 있습니다.

    • 복잡한 의사결정: 모델 호출, 도구 사용, 가드레일 적용 등의 시점과 방법을 정확히 결정할 수 있습니다.

    • 상태 관리: 대화의 각 단계에서 상태를 추적하고 관리할 수 있습니다.

    • 유연한 워크플로우: 특정 비즈니스 로직이나 복잡한 추론 과정을 구현할 수 있습니다.

  4. 별도 기능으로 지원되는 이유:

    • 최적화: Amazon Bedrock이 제공하는 custom orchestration은 에이전트 시스템과 더 깊이 통합되어 있어, 성능과 확장성 면에서 이점이 있습니다.

    • 간소화: 개발자가 전체 대화 로직을 처음부터 구현할 필요 없이, Bedrock의 기존 기능을 활용하면서 커스터마이징할 수 있습니다.

    • 표준화: Custom orchestration API를 통해 일관된 방식으로 복잡한 대화 로직을 구현할 수 있습니다.

즉, custom orchestration은 단순히 Lambda를 사용하는 것보다 더 강력하고 유연한 제어를 제공하며, Amazon Bedrock 에코시스템과 더 긴밀하게 통합됩니다. 이는 복잡한 AI 에이전트 애플리케이션을 개발할 때 큰 이점을 제공합니다.

CoT Orchestration Process

Chain of Thought 오케스트레이션 코드는 Amazon Bedrock Agents의 custom orchestration의 좋은 예시입니다. 이 접근 방식이 custom orchestration의 예인 이유와 함께 코드에 대해 설명드리겠습니다.

Chain of Thought 오케스트레이션 코드 예시:

이 코드가 custom orchestration의 예인 이유:

  1. 상태 기반 로직:

    • 코드는 ‘START’, ‘MODEL_INVOKED’, ‘TOOL_INVOKED’ 등 다양한 상태를 처리합니다.

    • 각 상태에 따라 다른 액션을 취하므로, 개발자가 전체 대화 흐름을 세밀하게 제어할 수 있습니다.

  2. 모델 호출 제어:

    • ‘INVOKE_MODEL’ 이벤트를 통해 언제 모델을 호출할지 직접 결정합니다.

    • 이는 기본 orchestration과 달리, 모델 사용을 더 정밀하게 제어할 수 있음을 보여줍니다.

  3. 도구 사용 결정:

    • 모델의 출력을 바탕으로 도구 사용 여부를 결정합니다(‘tool_use’ stopReason).

    • 이를 통해 도구 사용의 타이밍과 방법을 커스터마이즈할 수 있습니다.

  4. 반복적 추론:

    • 도구 호출 후 다시 모델을 호출하여 다음 단계를 결정합니다.

    • 이는 Chain of Thought 방식의 핵심으로, 복잡한 추론 과정을 구현할 수 있게 합니다.

  5. 유연한 종료 조건:

    • ‘end_turn’ stopReason을 통해 대화 종료 시점을 유연하게 결정합니다.

  6. 커스텀 페이로드 생성:

    • 각 단계마다 필요한 페이로드를 커스텀하게 생성합니다.

이러한 특징들로 인해 이 코드는 단순히 사전 정의된 흐름을 따르는 것이 아니라, 개발자가 에이전트의 행동을 세밀하게 제어하고 복잡한 추론 과정을 구현할 수 있게 해주는 custom orchestration의 좋은 예시입니다.
