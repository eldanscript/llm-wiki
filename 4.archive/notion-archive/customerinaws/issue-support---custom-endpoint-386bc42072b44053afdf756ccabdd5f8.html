Compare symantec and custom endpoint

  • 동일 region에서 symantec과 custom endpoint는 동일한 identity 서비스와 talk

    • either registration did not reach the connection process → 등록 절차가 connection 단계까지 가지 못하거나

    • the connection did not go to AWS IoT Core service → connection이 IoT Core 서비스에 가지 못한 것이 아닌지

  • Difference

    • Symantec endpoint는 여전히 이전 TLS stack에 hosting 되고 있으며 custom domain을 지원하지 않음

    • Custom domain endpoint는 새로운 TLS stack에서 서비스 되는 listener를 지정 (point)

MQTT Connection Workflow

  • Device can pass credentials through the username and password fields of MQTT message → Authorizer

  • Custom authentication connect on port 443

  • Pass ALPN (Application Layer Protocol Negotiation) TLS extenstion

  • Pass SNI (Server Name Indication) extension with the host name of IoT Core data endpoint

Configurable endpoints

💡

Configurable Endpoint just provides and alternative “facade” for devices to access the AWS IoT Core account, see it as simply an alias of your AWS IoT Core Endpoint

[

Configurable endpoints

Learn about configurable endpoints and how they relate to custom domains for AWS IoT.

https://docs.aws.amazon.com/iot/latest/developerguide/iot-custom-endpoints-configurable.html

](https://docs.aws.amazon.com/iot/latest/developerguide/iot-custom-endpoints-configurable.html)

  • Domain configuration : Configure & manage the behaviors of data endpoint

    • Can generate multiple data endpoint and customzie with own FQDN

  • IoT Core use the SNI (server name indication) TLS extension to apply domain configuration

    • Device pass a server name that is specified in the domain configuration

    • Use IoT Device SDK v2 for testing

    • Certificates limit : 4 domain names per certificate

  • Why use?

    • Migrate devices to AWS IoT

    • Support heterogeneous device fleets : separate domain configurations for separate device types

    • Maintain brand identity through domain name while migration infra to AWS IoT

  • How to create an AWS managed domain

    • Using API : CreateDomainConfiguration

      • customer authroizer

      • whether devices can override the default authorizer in HTTP header

      • service type

        • Data, Credential Provider, Jobs

        • Support only Data type → IoT Core returns an endpoint with type of iot:Data-ATS

  • How to create custom domain

    • Specify FQDN to connect to AWS IoT

    • Manage own server certificate in detail : root CA, chain depth, signature algorithm, lifecycle of the certificate

    • Register server certificate chain to ACM

      • Use one certificate to multiple subdomians : use wildcard domain in CN or SAN (*.iot.example.com)

    • Create a domain configuration

      • Use CreateDomainConfiguration API

        • domain name, server certificate ARN, Authorizer Name, Authorizer override, Service Type

        • Support only DATA type

    • Create DNS records

      • Let custom domain points to an AWS IoT domain

      • DNS record point to an AWS IoT endpoint of type : Data-ATS
