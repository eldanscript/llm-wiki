AI 기능 Review - AWS Support

AWS 솔루션에서 지원하고 있는 부분은 다음과 같습니다. AWS 솔루션을 사용하더라도 고객의 요구 사항에 따라 추가 개발이나 솔루션의 일부 차용 적용이 되어야 할 것으로 보이며 이에 따른 개발 주체 및 리소스 확보에 대한 준비가 필요할 것으로 보입니다.

  1. 영상 콘텐츠에 대한 메타데이터 추출 및 검색 서비스

  • 관련 RFP

    • AI 기능을 기반으로 영상 콘텐츠 메타정보(아티스트 등) 자동 추출 및 입력 기능

    • AI 기능을 기반으로 LLM 활용을 통한 검색서비스 제공 (물리장비 및 클라우드 스토리지를 포함한 통합 검색)

    • AI 기능을 기반으로 시각적 검색서비스 제공(이미지/영상으로 검색)

    👠Contents Search by Image or Video

  • AWS 솔루션

    • Semantic Video Search on AWS (https://aws.amazon.com/solutions/guidance/semantic-video-search-on-aws/)

    • Media2Cloud on AWS (https://aws.amazon.com/ko/solutions/guidance/media2cloud-on-aws/)

    • S3에 업로드 되는 콘텐츠에 대한 메타 정보를 Amazon Rekognition을 통해 장면, 텍스트, 인물, 신 정보 등에 대해 추출하여 LLM으로 임베딩하여 OpenSearch에 데이터로 저장하고 LLM을 사용하요 semantic 검색을 할 수 있는 기능 입니다.

  • 추가 검토 사항

    • S3로 업로드 되는 콘텐츠를 기준으로 제공하고 있으며 On-prem의 물리 장비에 있는 콘텐츠에 대해서는 지원되지 않아 고객사와 협의가 필요 합니다.

Architecture 정리

요약 prompt

웹페이지의 내용을 기반으로 AWS AI 기능을 기반으로 한 자동 자막 생성 서비스에 대한 아키텍처 및 기능 설명을 3가지 키워드로 분류하고 각 키워드 별로 하위 설명 내용을 3~4가지로 작성해 주세요. 내용은 모두 한글로 만들어 주세요.

3가지 키워드와 각 키워드에 대한 하위 설명은 다음과 같습니다.

  1. 자동화 및 효율성

  • 수동 프로세스의 자동화: 복잡하고 노동 집약적인 자막 생성 작업을 자동화할 수 있습니다.

  • 최종 결과물 제어: 생성된 자막을 검토하고 수정할 수 있으며, 수정된 입력으로 워크플로를 재실행하여 결과를 재생성할 수 있습니다.

  • 간편한 웹 기반 인터페이스: 동영상 업로드, 분석, 자동 생성된 자막 작업 등을 간단한 웹 인터페이스에서 처리할 수 있습니다.

  • 비용 절감: 수동 프로세스를 자동화함으로써 인력 투입을 줄일 수 있어 비용을 절감할 수 있습니다.

  1. 정확도 및 품질 향상

  • AWS AI 서비스 활용: Amazon Transcribe, Amazon Translate, Amazon Polly 등의 AWS AI 서비스를 활용하여 자막 생성 품질을 높일 수 있습니다.

  • 사용자 지정 어휘 및 용어: 수정한 자막을 토대로 사용자 지정 어휘와 용어를 생성하여 더 정확한 결과를 얻을 수 있습니다.

  • 다국어 자막 생성: 다국어 자막 생성을 통해 글로벌 시청자 층을 확대할 수 있습니다.

  • 실시간 피드백 및 결과 개선: 생성된 자막을 검토하고 수정하여 결과를 지속적으로 개선할 수 있습니다.

  1. 확장성 및 통합성

  • 서버리스 아키텍처: AWS 클라우드 서비스를 활용한 서버리스 아키텍처로 구현되어 확장성이 뛰어납니다.

  • 데이터 파이프라인 및 분석: Media Insights on AWS 데이터 파이프라인을 통해 미디어 메타데이터를 추출, 변환, 저장하고 분석할 수 있습니다.

  • API 및 워크플로 통합: API Gateway, AWS Step Functions 등을 활용하여 다양한 서비스와 통합할 수 있습니다.

  • 사용자 인증 및 권한 관리: Amazon Cognito를 통해 사용자 인증 및 권한 관리를 제공하여 보안을 강화할 수 있습니다.

알겠습니다. AWS AI 기능을 기반으로 한 자동 자막 생성 서비스에 대한 아키텍처 및 기능을 3가지 키워드로 분류하고 각 키워드별 하위 설명을 작성하겠습니다.

  1. 음성 인식 및 자막 생성

  • Amazon Transcribe: 음성을 텍스트로 변환하는 자동 음성 인식 기능을 제공합니다.

  • Toxicity Detection: 음성 메시지에서 유해한 내용을 자동으로 감지하는 기능을 제공합니다.

  • 실시간 자막 생성: 실시간으로 자막을 생성하여 사용자에게 제공합니다.

  1. 정책 기반 컨텐츠 검열

  • Amazon Bedrock: 대규모 언어 모델(LLM)을 활용하여 사용자 맞춤형 정책에 따른 컨텐츠 검열을 수행합니다.

  • 정책 문서 관리: Amazon OpenSearch Service를 통해 정책 문서를 관리하고 관련 문서를 효율적으로 검색합니다.

  • 컨텐츠 평가 리포트: 정책 위반 여부와 그 이유를 모니터에게 제공하는 상세한 리포트를 생성합니다.

  1. 확장성 및 통합성

  • 서버리스 아키텍처: AWS 클라우드 서비스를 활용하여 확장성 있는 아키텍처를 구현합니다.

  • 데이터 파이프라인: Media Insights on AWS 데이터 파이프라인을 통해 미디어 메타데이터를 수집, 변환, 저장합니다.

  • 타 서비스와의 통합: API Gateway 및 AWS Step Functions을 활용하여 다른 서비스와의 통합을 지원합니다.

  • 사용자 인증 및 권한 관리: Amazon Cognito를 통해 사용자 인증 및 권한 관리 기능을 제공합니다.

알겠습니다. AWS AI 기능을 기반으로 한 자동 자막 생성 서비스의 아키텍처 및 기능을 3가지 키워드로 분류하고 각 키워드별 하위 설명을 작성하겠습니다.

  1. 자막 생성 및 번역

  • Amazon Transcribe: 영상의 오디오를 텍스트로 변환하여 자막을 생성합니다.

  • Amazon Translate: 생성된 자막 텍스트를 다국어로 번역합니다.

  • 파일 포맷 변환: WebVTT 등 다양한 자막 파일 형식을 지원합니다.

  1. 자막 품질 향상

  • 문장 분리 및 정제: 자막 텍스트를 의미 단위로 분리하고 정제하여 번역 품질을 높입니다.

  • 사용자 정의 용어: 고객이 정의한 특정 용어 및 어휘를 활용하여 자막을 생성합니다.

이제 AWS Clean Rooms의 특징과 장점에 대해 더 자세히 살펴보겠습니다.

1., AWS Clean Rooms의 편의성에 대해 말씀드리겠습니다.
기존의 클린룸 구축은 복잡한 개인정보 보호 제어, 각 참여자의 데이터를 보호하기 위한 특수 도구, 그리고 분석 도구를 커스터마이징하는 데 몇 달이나 걸리는 개발 시간이 필요했습니다. 하지만 AWS Clean Rooms를 사용하면 몇 번의 클릭만으로 자체 클린룸을 쉽게 만들고, 참여자를 추가하고, 협업을 시작할 수 있습니다. 이는 시간과 비용을 크게 절약해줍니다.

2다음으로, 데이터 보안과 협업의 균형에 대해 말씀드리겠습니다.
다른 솔루션들은 협업을 위해 데이터를 반복적으로 복사하고 외부 저장 환경에 업로드해야 하는 경우가 많았습니다.
하지만 AWS Clean Rooms를 사용하면 기본 데이터를 공유하거나 노출하지 않고도 데이터 보안을 크게 향상시킵니다.

3.AWS Clean Rooms는 또한 광범위한 구성 가능한 데이터 액세스 제어 기능을 제공합니다.
쿼리 제어, 쿼리 출력 제한, 쿼리 로깅 등을 포함하여 각 클린룸 참여자가 실행하는 쿼리에 대한 제한을 사용자 지정할 수 있습니다. 이를 통해 데이터 협업의 범위와 깊이를 정밀하게 조정할 수 있습니다.

마지막으로 내장된 유연한 분석 규칙을 사용하여 특정 비즈니스 요구에 맞게 쿼리를 조정할 수 있습니다.
이는 각 기업의 고유한 니즈에 맞는 데이터 협업을 가능케 합니다. 또한 AWS Entity Resolution 기능을 사용하여 집단 데이터셋 간의 데이터 매칭을 개선하거나 기계학습을 활용하여 지정한 유저 모집군에서에서 패턴이 유사한 유저의 데모그래픽을 확보할 수 있습니다.이를 통해 더욱 정확하고 의미 있는 인사이트를 얻을 수 있습니다.

다음은 클린룸에서 수행할 수 있는 분석 유형에 대해 말씀드리겠습니다.

AWS Clean Rooms는 SQL 쿼리와, 머신러닝 두 가지 유형의 분석을 제공합니다.

먼저, SQL 쿼리에 대해 말씀드리겠습니다.
AWS Clean Rooms는 광범위한 SQL 프라이버시 강화 제어 기능을 제공합니다. 이는 쿼리 제어, 쿼리 출력 제한, 쿼리 로깅을 포함합니다. 이를 통해 각 클린룸 참여자가 실행하는 쿼리에 대한 제한을 사용자 지정할 수 있습니다. 즉, 데이터 협업의 범위와 깊이를 정밀하게 조정할 수 있다는 것이고 예를 들어 특정 열에 대해서는 count만 실행가능하게 한다든지 select를 못하게 한다든지와 같은 기능입니다.

더 나아가, AWS Clean Rooms는 차등 프라이버시(Differential Privacy)를 제공합니다. 차등 프라이버시를 처음 들으시는 분들을 위해 간략히만 말씀드리면 데이터 분석 결과를 공유할 때 개인의 정보를 보호하기 위해 약간의 ‘노이즈’(무작위 변동)를 추가하여 누군가를 특정하는 것을 방지하는 기능입니다.
이 기능은 수학적으로 뒷받침된 직관적인 제어 기능을 사용하며 데이터의 유용성을 유지하면서도 개인의 프라이버시를 보호하는 강력한 방법입니다. 뒷장에서 더 자세히 설명드리겠습니다.

또한, 클린룸을 위한 암호화 컴퓨팅(C3R)은 협업 과정에서 민감한 데이터를 암호화된 상태로 유지하는 데 도움을 줍니다. 클라이언트측에서 데이터를 암호화여 데이터셋으로 구성함으로써 데이터가 협업되는 과정에도 모든 데이터가 암호화되는 것을 보장할 수 있고 복호화과정없이 분석을 할 수 있습니다.
이는 데이터 보안을 한 단계 더 강화하는 중요한 기능입니다.

다음으로, AWS Clean Rooms ML은 고객이 프라이버시 강화 머신러닝(ML)을 적용하여 기본 데이터를 서로 공유하지 않고도 예측 인사이트를 생성할 수 있게 해줍니다. 유사 고객 세그먼트를 생성하여 마케팅에 활용하거나 잠재고객을 식별하는데 사용할 수 있습니다. 이 기능도 이어지는 장에서 자세히 말씀드리겠습니다.

이어서 AWS Clean Rooms의 전체적인 워크플로우에 대해 설명드리겠습니다.

첫째, 공동작업 생성 단계입니다.
먼저 파트너사를 통해 데이터를 공유받고 분석할 사용자는 공동 작업(Collaboration)을 생성합니다. 그 후 계정 ID를 통해 한 명 이상의 멤버를 초대합니다. 이 때, 쿼리를 실행할 수 있는 멤버나 쿼리 결과를 받을 수 있는 멤버 등 각 멤버의 권한을 지정합니다. 이를 통해 공동 작업의 구조와 각 참여자의 역할이 명확히 정의됩니다.

둘째, 멤버 참여 단계입니다.
초대받은 멤버들은 멤버십에 사용할 구성 테이블을 생성 및 연결합니다. 이때 사용할 데이터로 AWS Glue 테이블을 AWS Clean Rooms에서 사용할 수 있도록 구성합니다. 이 단계는 공동 작업에 참여하기 전에 수행해도 되고 언제든지 추가할 수도 있습니다. 또한, 멤버들은 선택적으로 테이블을 구성하기 전에 데이터를 미리 암호화할 수 있습니다. 이는 데이터 보안을 한층 강화합니다.

셋째, 분석 규칙 추가 단계입니다.
초대받은 멤버들은 구성된 테이블에 분석 규칙(집계 또는 목록)을 추가합니다. 예를 들어 특정 컬럼에 대해 count를 할지, List를 보여줄지등을 결정하고 join이나 group by연산에 사용할 컬럼들을 지정하여 테이블에서 실행할 수 있는 분석 규칙을 세세하게 제어합니다. 이는 데이터 사용의 범위와 방식을 정밀하게 관리할 수 있게 해줍니다.

넷째, 서비스 역할 부여 단계입니다.
초대받은 멤버들은 AWS Clean Rooms에 AWS Glue 테이블에 접근할 수 있는 서비스 역할을 부여합니다. 이 역할은 테이블에 대한 권한을 가지며, 오직 AWS Clean Rooms만이 쿼리를 실행하고 결과를 받을 수 있는 멤버를 대신하여 허용된 쿼리를 실행하기 위해 이 역할을 맡을 수 있습니다. 중요한 점은, 데이터 소유자를 제외한 어떤 협업 멤버도 협업의 기본 테이블에 접근할 수 없다는 것입니다.

마지막으로, 쿼리 실행 단계입니다.
쿼리를 실행하고 결과를 받을 수 있는 권한을 가진 멤버는 구성된 테이블에서 SQL 쿼리를 실행할 수 있습니다. 이 때, 분석 규칙과 출력 제약 조건이 자동으로 적용됩니다. AWS Clean Rooms는 정의된 분석 규칙을 준수하는 결과만을 반환합니다.

이러한 워크플로우를 통해 AWS Clean Rooms는 데이터의 안전성을 보장하면서도 효과적인 협업을 가능하게 합니다. 각 단계마다 데이터 보안과 프라이버시가 고려되어 있어, 안심하고 데이터 협업을 진행할 수 있습니다.

분석 규칙에 추가적으로 더 말씀을 드리면 분석 규칙을 사용하게 되면 여러분의 데이터가 어떻게 분석될 수 있는지를 제어할 수가 있습니다.. AWS Clean Rooms는 세 가지 유형의 분석 규칙을 지원합니다.집계, 목록, 그리고 사용자 지정 규칙입니다.

먼저, 집계 분석 규칙에 대해 설명드리겠습니다.
집계 분석 규칙을 사용하면 두 데이터셋의 교집합 크기와 같은 집계 통계를 생성하는 쿼리를 실행할 수 있습니다. 이 규칙을 사용할 때, 여러분은 오직 집계 쿼리만 데이터에 대해 실행되도록 강제할 수 있습니다. 또한, 블라인드 매치에만 사용되어야 하는 열과 합계, 개수, 평균 등의 집계에 사용될 수 있는 열을 지정할 수 있습니다. 출력의 최소 집계 제약 조건도 제어할 수 있습니다. 이를 통해 데이터의 세부 정보를 노출하지 않으면서도 유용한 통계 정보를 얻을 수 있습니다.

다음으로, 목록 분석 규칙입니다.
리스트 분석 규칙을 사용하면 여러 데이터셋의 교집합에 대한 행 수준 리스트를 추출하는 쿼리를 실행할 수 있습니다. 이 규칙을 사용할 때, 오직 리스트 쿼리만 데이터에 대해 실행되도록 강제할 수 있으며, 블라인드 매치에만 사용되어야 하는 열과 출력에서 리스트로 출력될 수 있는 열을 지정할 수 있습니다. 이는 특정 조건을 만족하는 데이터 항목을 식별하는 데 유용합니다.

마지막으로, 사용자 지정 분석 규칙입니다.
사용자 지정 분석 규칙을 사용하면 ANSI 표준 SQL의 대부분을 사용하여 사용자 지정 쿼리를 생성할 수 있습니다. 여기에는 공통 테이블 식(CTE)과 윈도우 함수 등이 포함됩니다. 또한 협업 파트너가 쿼리를 실행하기 전에 검토하고 허용할 수 있으며, 다른 협업자의 쿼리가 여러분의 테이블에서 실행되기 전에 검토할 수 있습니다. 이 규칙을 사용하면 분석이 완료된 후 쿼리 로그에 의존하는 대신, 사전에 기본 데이터가 어떻게 분석될 수 있는지를 결정하거나 제한할 수 있습니다. 또한 분석 템플릿을 만들거나 사용하여 매개변수가 있는 사용자 지정 쿼리를 협업에 저장할 수 있습니다. 이는 협업에서 재사용 가능한 분석을 용이하게 합니다.

이러한 분석 규칙들을 통해 AWS Clean Rooms는 데이터 소유자에게 강력한 제어 기능을 제공하면서도, 협업 파트너들에게 유연한 분석 옵션을 제공합니다. 이는 데이터 프라이버시와 분석의 유용성 사이의 균형을 맞추는 데 큰 도움이 됩니다
