MAP - Image Generation Unit

Project Overview

Project Description

  • DreamUs identity를 반영한 GenAI 기반 Image 생성 모델 개발 및 Marketing과 Designer 업무용 image 생성 기능 구축

Requirements

  • DreamUs 고유 image style 반영

  • 기존 업무용 Image 생성 프로세스 및 시스템에 결합

Risk or Challenge

  • 인력 리소스 및 경험치 부족

  • Image에 대한 정성적 평가 대응

  • 회사 Image Style은 6개월, 1년 단위로 변경 되며 제작하는 image 개수가 제한 됨

Goal

  • DreamUs 고유 style의 Image generation model 개발

  • Prompt 입력을 바탕으로 music album background image 변경 : Marketing Unit

  • Prompt 입력을 바탕으로 design 작업에 필요한 image asset 생성 : Creative Unit

Executive Summary:

DreamUs aims to develop a GenAI-based image generation model that reflects its unique identity, enhancing marketing and design workflows. The project seeks to create a proprietary image style, integrate with existing systems, and overcome resource limitations. Key objectives include developing a DreamUs-specific image generation model, enabling prompt-based music album background image creation for marketing, and generating design assets for the creative team. This initiative will streamline image production processes, maintain brand consistency, and leverage AWS cloud capabilities to address technical challenges and scalability requirements.

Based on the project overview and the requirements for success criteria, here’s a bulleted list of quantitative and measurable objectives for the “Image Generation Unit” project:

  • Develop a GenAI image model that accurately reflects DreamUs’ unique style, with 90% consistency in generated images.
    • Reduce image creation time for marketing by 50% using the new prompt-based system.
    • Achieve 80% designer satisfaction with the quality of AI-generated image assets.
    • Integrate the new image generation system with existing workflows, resulting in a 30% increase in overall productivity.
    • Maintain brand consistency across 95% of generated images, even with style changes every 6-12 months.

For the Image Generation Unit project, we assume that DreamUs has access to a substantial dataset of their proprietary images, sufficient to train a GenAI model that accurately captures their unique style. This dataset is expected to contain at least 10,000 high-quality images representing various DreamUs style iterations over the past 3-5 years. We also assume that the company has the necessary computational resources, including high-performance GPUs, to train and deploy the image generation model efficiently. It is anticipated that the model will require at least 100 hours of training time on a cluster of 8 NVIDIA V100 GPUs to achieve the desired quality and style consistency.

Furthermore, we assume that the marketing and creative teams will generate approximately 500 new images per month using the AI system, with an average processing time of 2 minutes per image. This volume is expected to cover 80% of their image creation needs, significantly reducing the workload on human designers. The system is assumed to integrate seamlessly with DreamUs’ existing digital asset management system, which currently houses over 100,000 images and handles an average of 1,000 daily queries from various departments. Lastly, we assume that DreamUs has the necessary legal clearances to use AI-generated images for commercial purposes and that the company’s bi-annual style updates can be accommodated by fine-tuning the model with approximately 1,000 new images per update cycle.

Project Info

Image 생성 model tuning

  • 현재 250여 장의 학습용 image 준비

  • Image Data Augmentation을 통해 학습용 data 증가 필요

  • Image prompt는 vit로 생성 (소품 클릭)

  • 회사 Image Style은 보통 6개월 혹은 1~2년 주기로 변경

  • LoRA, LoCon 으로 진행

    • LoRA model은 700 MB 정도

    • Script로 Tuning 수동 반복 작업 진행

  • Core Trainer load 후 Full Tuning 진행 하며 LoRA, LoCon 제외 시킴

Layer Diffusion Model

  • Design team에서 image component들을 각각 만들고 조합하여 사용할 수 있도록 제공해야 함

  • 개별 asset은 SVG format을 희망

Image asset 생성 작업 : Creative Unit

  • Design team의 asset 제작과 조합 생성 업무에 적용

  • 요구 사항

    • Keyword 중심의 asset 생성과 이를 기반으로 여러 가지 variation 추가 생성

    • image variation : 3D rotation 등

Album Image 생성 작업 : Marketing Unit

  • Artist album image에 대해 배경 변경 생성

요구 사항에 따른 AWS 관련 기능 안내

  • Titan Image Model Fine Tuning

    • image file과 pair prompt를 S3에 upload 후 tuning 작업 진행

    • Batch 크기, Learning rate 설정 등 세부 조정 가능

    • 최소 Image 개수는 25장 이상 이지만 학습 image가 많을 수록 model quality 향상

  • Titan Image Generator

    • Input image에 대한 variation 생성 기능 제공 : human position 변경 등

  • Model tuning pipeline

    • 생성된 Image 중 quality 높은 image는 선별 후 재 학습에 사용하여 model 성능 향상

    • 최초 학습 시 hyper-parameter 조정으로 variation을 높이고 생성된 data를 다시 학습에 활용하는 pipeline 구성

    • Bedrock에서 no-label data에 대해 학습이 가능 하기 때문에 최초 생성 data를 재 학습에 사용

  • Prompt 생성

    • AWS 별도 서비스는 없으며 일반적으로 학습 진행 시 CLIP interrogator 혹은 BLIP 사용

    • 수동 prompt가 Image quality 향상에 좋음

    • BLIP 등으로 prompt 추출 시 후 처리를 통해 불필요한 text 제거 작업을 진행

  • Amazon SageMaker Jumpstart

    • Amazon Bedrock 제공 model이 아닌 3P model 사용 시 Jumpstart를 통해 간단히 구축 가능

    • Jumpstart로 생성한 serving endpoint 사용

  • Layer Diffusion Model 대체 작업

    • Image Generator를 통해 생성한 asset을 4 channel PNG type으로 저장하고 alpha 값을 조정하여 transparent한 image로 layer에 적용 (OpenCV 등 사용)

    • SVG file 대응은 해상도 높은 PNG file을 생성하여 대응 가능 : image 크기 증가

    • Image asset 생성 pipeline 구성

      • Lambda 혹은 step function 등의 workflow 서비스로 전처리 → 이미지 생성 → 후처리 process 구성

  • Album Image 생성 작업

    • 일반적인 Background 변경 작업

      • Image split → Background generation과 Foreground generation 작업 → 이미지 후처리

      • 후처리 : OpenCV, ControlNet, Depth estimation model 사용하여 overlay 작업 (gradation 이용 병합)

    • Album 생성 작업 pipeline 구성

      • Masking 작업으로 Artist 분리 → Background Image 생성 → Masking image와 Background Image overlay

        • Masking 작업 : Segmentation model 사용

      • Amazon Bedrock의 outpainting 기능 사용

        • Masking 한 Image를 사용

  • HyperPaarameter Tuning 및 Evaluation

    • Repeat과 Epoch을 조정

      • Repeat x Epoch : 일반적으로 1500 ~ 2000 정도를 유지

      • Style 구성 같은 경우 7000 이상을 사용

    • Learning Rate, Text Encoder Learning Rate, Unit Learning Rate

      • Learning Rate 값만 조정, 나머지는 대게 무시

      • Batch size가 커지면 Learning Rate는 x2

    • 학습 시 BP16 사용할 경우 성능 향상

    • 공유 memory는 사용하지 않고 GPU memory만 쓰도록 설정
