ML on AWS IoT Greengrass

QnA 1

다만, AWS 에서 Greengrass 를 소개한 아래 Usage와 비슷하다 보셔도 무방합니다.

https://aws.amazon.com/ko/greengrass/ml/

IoT Greengrass를 통해 두 가지 측면의 장점을 모두 누릴 수 있습니다. 클라우드에서 개발과 트레이닝을 거쳐 최적화된 기계 학습 모델을 사용하여 디바이스의 로컬에서 추론을 실행합니다. 예를 들어 장면 탐지 분석을 위한 SageMaker에서 예측 모델을 개발하여 카메라에서 실행하도록 최적화한 후 의심스러운 활동을 예측해 알림 메시지를 전송할 목적으로 배포할 수 있습니다. IoT Greengrass에서 추론을 실행하여 수집된 데이터는 다시 SageMaker로 전송되고, 여기에서 태깅을 통해 기계 학습 모델의 품질을 계속해서 높이는 데 사용됩니다.

요점은, “IoT 환경, Android Edge에서 ML Inference &application 실행(로컬 람다) + 클라우드에서 학습 및 모델 최적화 -> 클라우드에서 edge로 신규 ML 모델 배포” 가 되겠습니다.

조사 중 몇 가지 문의드리고 싶은 사항들이 생겼는데…

바쁘시겠지만 도움을 부탁드릴 수 있을까요?

  1. Roadmap

만약 말씀 가능하시다면, Android for greengrass 지원 시기를 알 수 있을까요?

시기는 확정인지 변경 가능인지도 궁금합니다.

  • 지원 시점은 아직 확정되어 안내 되지 않은 상태입니다. 추후 확인되면 다시 안내 드리도록 하겠습니다.
  1. v1, v2 기능 차이

https://docs.aws.amazon.com/greengrass/v2/developerguide/greengrass-v2-whats-new.html

위 문서로 봐서는, v2는 1) 모듈화 2) 오픈소스 3) tool 4) deployment 개선으로 보입니다.

v1, v2 지원되는 기능 피처 자체는 같은지요?

예를 들어 connector(v1)/component(v2), 보안 등의 모든 피처들은 동일한 지…

향후 v2 에 추가되는 피처는 v1에도 추가되는지 궁금합니다.

즉, v1을 사용해도 ML 등 기능상 큰 불이익은 없을지 궁금합니다.

  • V1과 V2 기능 차이

    확인하신 부분은 V2에 새롭게 추가된 기능이며 말씀하신 부분이 맞습니다.

    V2는 메이저 버전 업그레이드로 많은 변경이 있습니다. V1과 V2가 Greengrass의 기능인 엣지 런타임과 클라우드 서비스의 사용을 지원하는 의미로는 동일하지만 이런 기능을 구동하는 방식에 변화가 있습니다.

    V1에서는 Lambda와 같은 serverless 서비스를 AWS cloud에서 작성하고 이것을 edge(greengrass가 설치된 디바이스)에 배포하는 방식으로 이루어 졌습니다.

    V2에서는 AWS cloud와 관계없이 edge에서 개발과 디버깅을 진행하고 이것을 다른 디바이스에 재 배포, 재 사용을 하기 위해 component화 하고 AWS Cloud에 연결하여 다른 디바이스로 배포 사용하는 concept으로 변경 되었습니다. 이에 따라 V2에서 실행되는 소프트웨어는 component 개념으로 module화 되어 배포가 되고 있습니다. Greengrass V2를 설치하면 nucleus라는 가장 기본이 되는 component가 배포되고 이후 필요에 따라 component를 개발, 추가하여 사용하시게 됩니다. nucleus 외에 AWS 서비스를 사용하기 위한 pre-built된 component 들도 open source로 배포되어 그대로 사용하시거나 customizing 하셔서 사용하실 수 있습니다.

    V1과 V2에서는 구현하는 소프트웨어의 기능의 차이 보다는 이러한 구동 방식 개념의 차이가 있고 이에 따라 소프트웨어 패키징과 배포가 다르고 이에 따라 구성 소프트웨어에 차이가 발생한다고 됩니다.

    ML 기능을 구현 한다고 할 때 V1에서는 모델 배포와 추론을 수행할 소프트웨어가 Lambda 패키지 - Connector를 사용하여 배포 이용한다고 하면 V2에서는 ML 컴포넌트로 배포 사용한다고 보시면 될 것 같습니다. ML 기능의 사용은 동일하지만 구동 환경과 방식에 차이가 있다고 생각하시면 됩니다.

    V1과 V2 기능 차이에 대한 세부 내용은 다음 링크 내용을 확인해 보시기 바랍니다. https://docs.aws.amazon.com/ko_kr/greengrass/v2/developerguide/move-from-v1.html

    Lambda를 edge에서 구동 시키기 위해 Greengrass core 소프트웨어를 통해 runtime을 구성하는 역할을 하였습니다. 통상적으로 Linux OS에서 많이 사용되었고 MacOS나 Windows는 docker를 설치하고 Greengrass core를 container로 실행하여 사용하는 방식으로 이용되었습니다.

    Core 디바이스, 구성 소프트웨어, 연결할 thing 등을 Greengrass Group으로 정의하고 단일 소프트웨어 패키지로 배포하지만 V2에서는 Core 디바이스, 소프트웨어, Things 구성을 Deployment를 통해 분리하여

    V1에서 구현한 애플리케이션을 V2에서 실행할 수 있지만 배포 방식과 구동 방식이 차이가 있기 때문에 수정이 필요하며 일부 기능은 제한이 있습니다.

    ML 관련하여서

  1. Docker 지원

우선은 Core 부터 안드로이드에 설치해 보려 하는데…

아무래도 Android 에는 필요 toolchain이나 openjdk 도 없는 등, 환경 상 한계점이 있습니다.

하여, docker로 돌릴 수 있을지도 검토를 해 보려 합니다.

그런데 Docker로 동작시킬 경우, “No container mode:No” 인 connector는 엣지에서 실행 불가로 이해됩니다.

즉, “ML Image classification” 같은 ML inference는 지원 불가로 이해했는데 맞는지요?

https://docs.aws.amazon.com/greengrass/v1/developerguide/run-gg-in-docker-container.html

https://docs.aws.amazon.com/greengrass/v1/developerguide/connectors-list.html

UntitledThe following features aren’t supported when you run AWS IoT Greengrass in a Docker container:

To find connectors that support No container mode, see AWS-provided Greengrass connectors. Some of these connectors have an isolation mode parameter that you must set to No container.

v1은 GG Core가 포함되어 있는 docker image를 명시하고 있습니다.

https://docs.aws.amazon.com/greengrass/v1/developerguide/run-gg-in-docker-container.html

그런데 v2에서는 core device, 즉 nucleus 가 포함된 docker image가 없는 것 같습니다. 맞나요?

https://docs.aws.amazon.com/greengrass/v2/developerguide/run-docker-container.html

  • Docker image는 V1의 Greengrass Core 소프트웨어가 Linux 환경이 아닌 MacOS, Windows 환경에서 구동하기 위해 주로 사용되고 있으며 Linux, MacOS, Windows용 container image가 지원됩니다. V2용은 아직 container image로는 제공되고 있지 않습니다.

  • Docker 구동 시 Lambda runtime 환경을 No container mode로 설정하는 것은 다음과 같이 생각하시면 됩니다. V1에서 Greengrass core는 기본적으로 docker container image가 아닌 소프트웨어 패키지를 설치하여 Lambda를 구동하게 됩니다. 이 때 Lambda의 구동은 container image화 되어 실행되기 때문에 Lambda 패키지 배포 시 container화 설정을 필요로 합니다. 하지만 Docker image를 사용하여 Greengrass Core를 실행한다면 container runtime 환경이 이미 구동이 되어 있기 때문에 No container mode로 배포를 하게 되는 것입니다.

  • 확인 하신대로 ML 이미지 분류는 No Container mode를 지원하지 않기 때문에 Greengrass Core를 Docker image로 실행한다면 구동이 안된다고 보시면 됩니다.

  • V2에서는 ML 이미지 분류를 component로 제공하고 있습니다. 다음의 link를 참조 하시기 바랍니다.

    V2 ML 구성 요소 : https://docs.aws.amazon.com/ko_kr/greengrass/v2/developerguide/ml-components.html

    V2 이미지 분류 작업 안내 : https://docs.aws.amazon.com/ko_kr/greengrass/v2/developerguide/ml-tutorial-image-classification.html

    V2 객체 감수 작업 안내 :

    https://docs.aws.amazon.com/ko_kr/greengrass/v2/developerguide/ml-tutorial-object-detection.html

  1. v1,v2 어느 쪽이든 안드로이드에서 쉽게 구동시킬 수 있는 방법 있을까요?

말씀하신 것과 같이, v1 코드를 안드로이드에 맞게 변경하는 것은 비공식적 업무로는 로드가 너무 심하고…

뭔가 다른 방법 없을지요?

  • Termux나 시중 존재하는 linux emulator는 사용할 수 없는 상황입니다. 만약 상품화한다면 포함시킬 수가 없으니까요.

이외 어떤 방법이든 괜찮으니, 생각나시는 것이 있다면 무엇이든 조언 부탁드립니다.

  • Greengrass에서 사용하시는 기능에 대해 문의 드린 이유가 Android에서 Greengrass를 포팅하여 사용하기가 어렵기 때문이었습니다. Edge에서 ML Image detection이나 classification 구현 기능으로만 필요하시다고 하면 2020 re:Invent에서 새로 발표된 Amazon SageMaker Edge Manager도 적합한지 검토해 보셨으면 합니다. https://aws.amazon.com/ko/sagemaker/edge-manager/

  • 지원되는 디바이스와 Android 아키텍쳐에 대해서는 다음의 링크에서 확인해 보시면 됩니다. https://docs.aws.amazon.com/ko_kr/sagemaker/latest/dg/neo-supported-devices-edge.html

QnA 2

  • edge가 offline 상태에서 inference 가능 여부

    모델 생성하여 배포가 되면 Offline 상태에서도 inference가 가능합니다.

    다만 Offline 상태에서는 배포 모델의 관리 및 데이터 수집 등의

    다음의 예제를 통해 Android에서 DLR을 이용한 Image Detection 기능을 돌려 보시면 파악에 더 도움이 되실 것 같습니다.

    https://github.com/neo-ai/neo-ai-dlr/tree/main/examples/android/image_classification

Neo는 Deep Learning 모델의 실행을 위한 Runtime 제공이 주 목적이라고 한다면 Edge Manager는 대규모 프로덕션 배포를 위한 기능이 추가된 것으로 다양한 Edge 디바이스에서의 모델 관리 및 모델 피처 제어를 사용할 수 있도록 지원 합니다. Edge Manager는 대규모 디바이스에 모델 패키지 배포, 수집되는 데이터 및 추론 데이터 모니터링, 디바이스 상태 모니터링을 할 수 있다고 보시면 될 것 같습니다.

Offline 상태에서 Neo 및 Edge Manager 모두 추론이 가능하며 제약이 있다면 디바이스 상태 관리, 모델 배포 관리 등의 기능을 활용하지 못하는 것으로 보시면 될 것 같습니다.

Neo를 사용하더라도 IoT Device SDK를 사용하여 수집 데이터를 IoT Core에 배포하고 Inference Model을 지속적으로 개선하고 Edge 에 배포하는 작업을 구현할 수 있지만 Edge Manager에서는 이런 작업을 쉽게 할 수 있도록 SDK로 배포하고 있다고 보시면 될 것 같습니다.

Neo DLR을 이용하여 Android에서 Image detection을 수행하는 예제 링크를 전달 드리니 참고해 보시기 바랍니다.

https://github.com/neo-ai/neo-ai-dlr/tree/main/examples/android/image_classification
