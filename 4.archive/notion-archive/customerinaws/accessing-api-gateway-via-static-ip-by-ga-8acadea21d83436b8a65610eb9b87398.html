Monitoring & Logging 구성

1. Global Accelerator

CloudWatch Metric

https://docs.aws.amazon.com/global-accelerator/latest/dg/cloudwatch-monitoring.html

  • CloudWatch → Metrics → All metrics 메뉴에서 GlobalAccelerator 선택

    • CloudWatch는 Regional service 이므로 GlobalAccelerator 생성 Region에서 확인해야 함

Flow Log

https://docs.aws.amazon.com/global-accelerator/latest/dg/monitoring-global-accelerator.flow-logs.html

  • Log 파일 저장을 위한 S3 bucket 생성 또는 생성해둔 bucket을 사용

    • Log 파일은 다음과 같은 위치에 저장 된다 : s3-bucket_name/s3-bucket-prefix/AWSLogs/aws_account_id/globalaccelerator/region/yyyy/mm/dd/

    • Log 파일명은 다음의 형으로 생성 된다 : aws_account_id_globalaccelerator_accelerator_id_flow_log_id_timestamp_hash.log.gz

  • AWS CLI를 사용하여 Flow Log를 S3 bucket에 저장되도록 설정

  • Flow Log

2. ALB

CloudWatch Metric

  • Load balancer의 Monitoring tab에서 기본 설정된 metric 항목 monitoring 가능

  • CloudWatch → Metrics → All metrics에서 ApplicationELB 선택하여 구성 가능

Access Logs

https://docs.aws.amazon.com/ko_kr/elasticloadbalancing/latest/application/load-balancer-access-logs.html

  • Log 파일 저장을 위한 S3 bucket 생성 또는 생성해둔 bucket을 사용

    • Log 파일은 다음과 같은 위치에 저장 된다 : s3-bucket_name/s3-bucket-prefix/AWSLogs/aws_account_id/elasticloadbalancing/region/yyyy/mm/dd/

    • Log 파일명은 다음의 형으로 생성 된다 : aws_account_id_elasticloadbalancing_region_load-balancer-id_end-time_ip-address_random-string.log.gz

  • Load balancer Description tab에서 Atrributes 항목을 편집

  • Access logs 항목을 Enbale 하고 S3 location을 지정

  • Access Log

3. API Gateway

CloudWatch Metric

  • Amazon API Gateway 콘솔에서 API의 Dashboard 메뉴에서 확인 가능

  • CloudWatch → Metrics → All metrics에서 ApiGateway 선택하여 구성 가능

CloudWatch Log

https://aws.amazon.com/premiumsupport/knowledge-center/api-gateway-cloudwatch-logs/

  • CloudWatch에 Logging 할 수 있는 IAM role을 생성한다
  • 생성된 IAM role의 ARN을 API Gateway의 Settings의 CloudWatch log role ARN에 입력하고 저장한다

  • 생성한 API의 Stages Editor 화면에서 Logs/Trace tab을 선택하여 CloudWatch Logs를 Enable 한다

  • CloudWatch → Log groups에 log group이 생성된다 : API-Gateway-Execution-Logs_apIId/stageName

Custom Access Logging

  • 기본 Log format 외에 필요한 항목들을 직접 구성하여 Log를 저장할 수 있다

  • 저장할 Log group을 CloudWatch → Log groups에서 생성한다

  • 생성된 Log group의 ARN을 복사한다 : arn:aws:logs:ap-northeast-2:872943583326:log-group:API-Gateway-Demo-AccessLog

  • 생성한 API의 Stages Editor 화면에서 Logs/Trace tab을 선택하고 Custom Access Logging을 편집한다

  • Access Log Destination ARN에 복사한 ARN을 입력한다

  • Log Format에 Logging 할 항목들을 지정한다

  • Log Format은 다음 페이지에서 확인할 수 있다 : https://docs.aws.amazon.com/apigateway/latest/developerguide/set-up-logging.html

  • Custom Access Log

DNS name 구성

  • REST API URL Access : https://apidemo.jawslab.link/resource

  • Route53에 등록된 Domain Name의 Alias를 조회 → Global Accelerator의 DNS name을 route

  • Global Accelerator는 DNS name과 mapping된 static IP를 가지고 있고 REST API URL에 대한 DNS lookup 결과를 이 IP를 return 한다

  • Global Accelerator의 IP로 접속하면 Global Accelerator에 설정된 Endpoint로 routing 하게 된다

  • Routing할 IP는 ALB의 DNS name을 통해 가져오게 된다

  • ALB의 target group으로 private API Gateway와 SSL Certificate이 등록되어 있다. ALB에서는 target group으로 routing 하기 때문에 SSL Certificate이 의미를 가지지는 않는다

  • Target group은 VPC Endpoint로 설정되어 있기 때문에 ALB는 VPC Endpoint의 ENI IP를 전달하게 된다

  • VPC Endpoint는 서비스와 연결된 DNS name을 생성하는데 Public DNS name과 Private DNS name을 제공한다. DNS name을 lookup 하면 VPC Endpoint의 ENI IP가 확인된다

  • REST API URL이 Private API Gateway에 연결된 VPC ENI IP로 access 할 수 있게 된다

  • Private API Gateway에서는 REST API URL이 custom domain name으로 등록되어 있어야 한다. 여기에 등록된 Certificate을 통해 인증하게 되는데 이 인증서에 등록된 Server URL이 REST API URL과 matching 되어야 한다
