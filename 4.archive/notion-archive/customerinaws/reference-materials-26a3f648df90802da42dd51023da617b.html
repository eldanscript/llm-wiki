[슬라이드 3] 한국일보 소개 및 시스템 개요

  • 한국일보: 70년 이상의 역사와 저널리즘 가치를 지켜온 대한민국 대표 언론사

    • 생성형 AI 및 클라우드 기반 기술 선도적 도입

    • 데이터 기반 뉴스 생산 및 독자 맞춤형 서비스 혁신

  • ‘FACT’ 시스템 개요

    • 목표: 언론사의 오랜 과제였던 인물 사진 자동 분류 및 AI 검색 시스템 구축

    • 핵심 기술: Amazon Rekognition (얼굴 인식) + Amazon Bedrock (생성형 AI)

    • 주요 기능:

      • 매일 수백 장의 보도 사진 자동 분류

      • “웃고 있는 지드래곤”, “넘어진 손흥민”과 같은 자연어 기반 맥락 검색

    • 혁신: 기존 수작업 태깅의 한계를 극복하고 기자 업무 효율성 획기적 개선

[슬라이드 4] 기존 인물 사진 관리의 과제

  • 현실적인 업무 환경: 매일 수천 장의 보도 사진 처리, 신속성 및 정확성 요구

  • 기존 시스템의 한계

    • 수동 태깅의 한계:

      • 기자들이 이미지 등록 시 인물 정보 수기로 작성, 시간 소요 및 일관성 부족

      • 자체/외신 사진 간 일관성 유지 어려움

    • 복합적인 기술적 과제:

      • 유명 인물 식별 오류, 다중 인물 구분, 저화질 이미지 필터링

      • 편집자가 매일 수백 장 사진 직접 확인 및 보정 부담

    • 검색 효율성 문제:

      • 단순 파일명/메타데이터 의존, “웃고 있는 대통령 사진” 등 구체적 검색 불가능

      • 인물 사진 분류 자체가 불가능한 상황 (전담 인력 부재)

[슬라이드 5] ‘PersonaDB’ 핵심 아이디어 및 ‘FACT’ 시스템의 구현

  • PersonaDB: 한국일보의 과제 해결을 위한 GenAI 기반 인물 데이터베이스 데모 애플리케이션

  • 핵심 아이디어 4가지

[슬라이드 6] 유명인 자동 인식 및 유사 얼굴 검색

  • 1. Auto Name Labeling (유명인 자동 인식)

    • 기술: Amazon Rekognition의 유명인사 API

    • 기능: 사진 속 유명인 (예: 유재석)을 자동으로 식별하여 인물명 반환

    • 효과: 수작업 인물 라벨링 전처리 및 부담 감소

  • 2. Classification (유사 얼굴 검색)

    • 기술: Amazon Rekognition의 유사한 얼굴 검색 기능

    • 기능: 이전에 분석된 얼굴 벡터 정보를 Collection에 저장, 신규 사진과 유사도 점수 비교

    • 효과: 유사도 높은 경우 동일 인물로 판단, 기존 태깅 활용 및 일관된 태깅 자동 적용

[슬라이드 7] 미인식 유명인 처리: 텍스트 데이터 기반 인물명 추론

  • 3. Name Inference (텍스트 데이터 기반 인물명 추론)

    • 문제: Amazon Rekognition 유명인사 API로 식별되지 않는 인물 존재

    • 해결책: 신문기사 텍스트 데이터 활용 (Amazon Bedrock 기반 LLM)

    • 상세 과정:

      1. 초기 임시 라벨링: Rekognition으로 조회되지 않는 인물은 **‘Unknown’**으로 임시 라벨링 되거나, 신규/중요도 낮은 인물은 **‘ETC’**로 분류되어 얼굴 데이터가 DynamoDB에 추가.

      2. 기사 텍스트 인물명 추출: Amazon Bedrock에 “기사 내용에서 인물명만 추출해줘” 요청, 기사 내 인물명(예: 김철수, 김영희) 추출.

      3. 데이터 축적 및 빈도수 분석: 동일 인물이 여러 기사에 반복 등장 시, 해당 기사들에서 인물명 지속 수집 (예: “김철수 대표”, “김철수 CEO”).

      4. 인물명 추론 및 자동 확정: 가장 많이 등장하는 이름을 찾아 해당 인물의 이름으로 추론. 관리자가 ‘이름 자동확정’ 버튼 클릭 시, 가장 빈도가 높은 인물명으로 해당 인물의 모든 사진에 일괄 라벨링.

      5. 지속적 활용: 이후 동일 인물 사진 입력 시, 유사 얼굴 검색으로 Collection에서 얼굴을 찾고 매핑된 이름을 참고하여 이름 부여.

    • 효과: 수작업 없이 미인식 인물에 대한 자동 라벨링 및 검색 가능성 확보

[슬라이드 8] 인물 행동 분석

  • 4. Behavior (인물 행동 분석)

    • 기술: Amazon Bedrock (Claude Sonnet 4)

    • 기능: “사진 속 인물의 행위를 묘사해줘” 요청 시, “해당 인물은 넘어져 있습니다”와 같은 구체적인 행동 설명 제공

    • 프롬프트 예시:

      • System Role: 이미지 분석 전문가, 인물 행동 정확하고 간결하게 분석

      • User Role: “이 이미지에서 {celebrity_name}이(가) 무엇을 하고 있는지 간단하고 명확하게 한국어로 설명해주세요.”

    • 효과: 단순 인물 식별 넘어 상황과 맥락까지 파악, “넘어진 손흥민”, “웃고 있는 유재석” 등 세밀한 검색 가능

[슬라이드 9] ‘FACT’ 시스템 아키텍처

  • PersonaDB 아키텍처 기반

  • 3가지 핵심 기능 분리: 이미지 처리, 데이터 저장, 검색

    • 이미지 처리 (Amazon Rekognition):

      • 업로드된 이미지 품질 검증 (DetectFaces)

      • 유사 얼굴 검색 (SearchFacesByImage)

      • 유명인사 식별 (RecognizeCelebrities)

      • 얼굴 벡터 생성 및 Face Collection 저장

      • 인물 행동 분석 (Amazon Bedrock)

    • 데이터 저장:

      • Amazon S3: 원본 이미지 파일 저장

      • Amazon DynamoDB: 인물명, Face ID, 행동 설명, 이미지 경로 등 메타데이터 저장

      • Amazon Rekognition Face Collection: 얼굴 벡터 데이터 저장

    • 검색 시스템 (Amazon OpenSearch):

      • 사용자 검색 요청 처리

      • 인물명 검색 (“유재석”)부터 복합 검색 (“웃고 있는 유재석”)까지 지원

      • DynamoDB 메타데이터 연동하여 관련 이미지 반환

[슬라이드 10] ‘FACT’ 시스템 워크플로우 (AWS Step Functions 기반)

  • AWS Step Functions를 통한 워크플로우 체계화

    • 병렬 처리 최적화 (Map State)

    • 모니터링 및 추적

    • 확장성 보장 (자동 스케일링)

  • 주요 워크플로우 단계

    1. 이미지 업로드: S3 temp 폴더 업로드 시 Lambda가 Step Functions 호출

      • 품질 필터링: DetectFaces API로 얼굴 감지 및 퀄리티 점수(30 미만 저화질 제외) 검증

    2. 기존 인물 감지: SearchFacesByImage API로 Collection에서 매칭 인물 검색

      • 기존 인물 시 S3 경로 복사, DynamoDB 업데이트

      • ‘ETC’ 라벨: 기존 인물이 ‘ETC’인 경우, Collection에서 제외하여 메모리 낭비 방지

    3. 유명 인물 감지: RecognizeCelebrities API로 유명인 분류, Bedrock으로 행동/특징 파악 및 이미지 요약 생성

      • ‘Celebrity’ 카테고리로 S3 이동, 모든 정보 DynamoDB 저장

    4. 신규 인물 색인: 기존/유명인 아닌 경우, **‘ETC’**로 분류 후 ETC S3 경로에 복사, Rekognition 분석 데이터 DynamoDB 추가

      • Saltware 제안으로 최적화: “기존 인물 감지 → 유명 인물 감지” 순서 변경으로 성능/비용 효율성 개선

[슬라이드 11] 구축 결과 및 기대 효과

  • 효율성 증대

    • 평균 10초 이내 비동기적 자동 태깅 완료

    • 기자들의 기사 작성 시 관련 이미지 검색 시간 단축

    • 수작업 태깅 부담 획기적 감소

    • 기자들이 취재 및 기사 작성에 집중할 수 있는 환경 조성

  • 검색 경험 혁신

    • “웃고 있는 지드래곤”처럼 맥락 중심 키워드로 즉시 이미지 검색 가능

    • 인물 행동과 결합된 복합 검색 지원 (“넘어진 손흥민”)

    • 자연어 기반의 사용자 경험 획기적 개선

  • 기술적 이점 및 확장성

    • 정확성 향상: Rekognition의 인물 식별과 Bedrock의 맥락 이해 결합

    • 확장성 및 효율성: 서버리스 아키텍처 기반 자동 스케일링, 사용한 만큼만 비용 지불

    • 지속적인 학습: 새로운 인물과 상황 축적으로 인식 정확도 및 검색 품질 지속 향상

    • 다양한 미디어 유즈케이스 확장 가능성: 영화, 자동차, 스포츠 산업 등으로 유사 DB 구축 가능

[슬라이드 12] 결론 및 향후 계획

  • 결론

    • 한국일보는 ‘FACT’ 시스템 도입을 통해 기존에 불가능했던 인물 사진 분류 및 검색의 근본적인 문제 해결

    • AWS와의 긴밀한 파트너십으로 클라우드 기반 AI 워크플로의 효율성 및 확장성 입증

    • 언론사가 AI와 클라우드 기술을 결합하여 새로운 가치를 창출할 수 있음을 증명한 사례

  • 향후 계획

    • ‘FACT’ 시스템을 영상 및 실시간 스트리밍 영역으로 확장하여 더욱 고도화할 계획
