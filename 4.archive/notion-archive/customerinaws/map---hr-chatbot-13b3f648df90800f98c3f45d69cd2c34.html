MAP - HR Chatbot

Executive Summary

DreamUs Company aims to develop an HR RAG chatbot using Amazon Bedrock, leveraging Claude 3.5 LLM and Titan Embedding. The project will integrate with Slack, utilizing AWS services like API Gateway, Lambda, and DynamoDB. The phased approach includes basic RAG implementation, performance optimization with OpenSearch, quality improvement through reranking, and the addition of agent functionalities for enhanced HR operations. This initiative seeks to streamline HR processes and improve employee access to information through cloud-based AI technologies.

Success Criteria

The HR RAG Chatbot project’s success will be measured by achieving a 95% accuracy rate in answering HR-related queries, reducing response time to under 5 seconds for 90% of inquiries, and increasing employee satisfaction with HR services by 30%. Technical objectives include seamless integration with Slack, achieving 99.9% uptime for the chatbot service, and successfully implementing all planned phases, including reranking and agent functionalities. The system should handle a minimum of 1,000 concurrent users and demonstrate a 50% reduction in HR staff workload for routine inquiries within the first three months of deployment.

Assumptions

For the HR RAG Chatbot project, we assume that DreamUs Company has a comprehensive set of HR documents totaling approximately 5,000 pages, which will be sufficient to train the RAG system effectively. These documents are assumed to be in digital format, primarily PDF and Word files, and will be easily convertible for ingestion into Amazon S3. We anticipate processing about 100 MB of text data, which should be manageable for the initial Amazon Bedrock Knowledge Base setup. The use of Amazon Bedrock with Claude 3.5 is justified by the need for a high-quality, pre-trained language model capable of understanding complex HR queries and generating accurate responses.

We assume that the company’s Slack workspace has at least 1,000 active users, with an estimated 200 HR-related queries per day. This volume justifies the use of Amazon API Gateway and AWS Lambda for scalable, serverless architecture. The DynamoDB usage is based on the assumption of storing approximately 50,000 query-response pairs per month, with each record averaging 5 KB in size. For the OpenSearch implementation, we assume a need for indexing up to 1 million embeddings, justifying its use for improved search capabilities. The project also assumes that DreamUs has the necessary Slack API permissions and that all employees have Slack accounts, which is critical for the chatbot’s accessibility and user authentication process.

For the HR RAG Chatbot project, we assume that DreamUs Company has a substantial corpus of HR documents totaling approximately 10 TB, which will be used to train and populate the RAG system. This volume of data justifies the use of Amazon S3 for storage and Amazon Bedrock for efficient processing and indexing. The documents are assumed to be in various digital formats, primarily PDF, Word, and HTML files, which will require preprocessing before ingestion. We anticipate that this large dataset will provide comprehensive coverage of HR policies, procedures, and historical cases, enabling the chatbot to handle a wide range of queries accurately.

We assume a Monthly Active User (MAU) base of 2,000 employees, with each user averaging 100 queries per month. This translates to approximately 200,000 HR-related queries per month, justifying the use of Amazon API Gateway and AWS Lambda for scalable, serverless architecture. The average input size of 5,000 tokens and output size of 1,000 tokens per query aligns with the capabilities of Claude 3.5 on Amazon Bedrock, supporting the choice of this LLM for generating accurate and detailed responses. DynamoDB usage is based on storing these query-response pairs, estimating about 1.2 GB of data per month (assuming 1 token ≈ 4 bytes). This volume of interactions and data storage justifies the use of DynamoDB for its scalability and performance characteristics. The project also assumes that all 2,000 employees have Slack accounts and necessary access permissions, which is critical for the chatbot’s widespread adoption and effectiveness in streamlining HR operations.

Milestones & Deliverables

Based on the HR RAG Chatbot project overview and the given timeline, here’s a breakdown of the project into four phases with their respective completion dates and deliverables:

Phase 1: Project Initiation and Basic RAG Implementation
Completion Date: May 31, 2024
Deliverables:
• Project charter and detailed project plan
• Initial AWS environment setup (S3, Bedrock, API Gateway, Lambda, DynamoDB)
• Basic RAG system using Amazon Bedrock Knowledge Base
• Prototype Slack App integration
• Initial set of HR documents processed and ingested into the system
• Preliminary performance metrics report

Phase 2: Performance Optimization and OpenSearch Integration
Completion Date: July 15, 2024
Deliverables:
• Optimized RAG system with improved response times
• OpenSearch implementation for enhanced Lexical and Semantic search capabilities
• S3 to OpenSearch synchronization pipeline
• Updated Slack App with improved query handling
• Performance comparison report: Basic RAG vs. Optimized system
• User acceptance testing (UAT) results from a pilot group

Phase 3: Quality Improvement with Reranking
Completion Date: August 15, 2024
Deliverables:
• Implemented reranking model for improved search result quality
• Updated RAG pipeline incorporating reranking
• Comprehensive evaluation report on response accuracy and relevance
• Fine-tuned prompts for common HR scenarios
• Updated user guide and system documentation
• Training materials for HR staff on system capabilities

Phase 4: Agent Implementation and Final Optimization
Completion Date: September 30, 2024
Deliverables:
• Implemented agent functionality for automated notifications
• Integration with SMS and email systems for critical HR communications
• Final performance optimization report
• Complete system architecture documentation
• User satisfaction survey results
• Final project presentation and handover documentation
• Recommendations for full-scale deployment and future enhancements
