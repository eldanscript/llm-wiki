GA vs API Regional vs API Edge Optimized

API Edge Optimized

  1. The clients connect to a nearby POP and from there the traffic traverses AWS’s managed network, which will probably have better performance compared to the internet.

  2. The HTTPS handshake negotiation happens against the local POP which reduces the round trip time required for the handshake.

FSx for Lustre와 S3간 DataSync

  • FSx for Lustre는 ML, HPC 등의 고성능 computing을 필요로 하는 workload를 위한 고성능 파일 시스템

  • 기본적으로 Amazon S3와 함께 작동하므로 고성능 파일 시스템으로 클라우드 데이터 세트를 쉽게 처리 할 수 있음.

  • Amazon S3의 대규모 data를 FSx file system으로 import 하거나 (S3 linked file system으로 구성) S3를 File System BackUp (Data Repository) 용도로 사용 (예제 Link)

  • S3-linked file system : S3 bucket을 FSx for Luster file system과 연동시켜 S3에 file을 Upload 등의 변경을 FSx file system에서 감지하거나 (안내 Link), S3를 data repository로 구성하여 FSx file system의 변동을 S3로 동기화 (안내 Link)

  • Canned Policy : https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-creating-signed-url-canned-policy.html

    • 여러 개의 파일 사용을 제한

    • Policy 내용이 URL에 포함

  • Policy 선택 : Custom or Canned

CloudFront Security

https://docs.aws.amazon.com/whitepapers/latest/secure-content-delivery-amazon-cloudfront/how-cloudfront-can-help-you-ensure-security-in-the-cloud.html

CloudFront 서비스를 사용하는 애플리케이션의 Security를 강화를 위한 권장하는 내용은 다음과 같습니다.

  1. HTTPS를 사용하여 인터넷으로 전송되는 data를 보호
  • HTTPS 연결은 Viewer와 CloudFront간, CloudFront와 Origin간에 적용
  1. CloudFront Contents에 대한 접근 권한을 제한

  • Geo-based access를 사용

  • Signed URL, Signed cookies를 사용하여 접근 권한을 부여

  • 민감한 데이터는 encryption

  1. Origin 접근 보호

  • S3 접근 권한을 CloudFront URL을 통한 access로 제한

  • CloufFront에서 origin으로 전달하는 http 패킷에 secret value를 custom header로 추가

  • CloudFront IP 대역에 대한 Firewall, Security Group 설정

  1. 외부 공격으로 부터 보호

  • AWS Shield

  • AWS WAF
