Migration Issue

  1. AWS에서 AIX를 지원하지 않기 때문에 RHEL 사용해야 함

  2. RHEL migration 시 endian 차이 때문에 on-prem database를 backup하고 restore 할 수 없음

  3. Migration 과정

    1. 3rd party tool을 사용하여 replication을 setup

      1. AWS DMS에서는 DB2를 destination으로 지원하지 않음

      2. SAP의 경우 U2L conversion tool 제공

    2. 소스의 모든 Table data를 fiat file로 export 한 후 destination에서 flat file을 load 하는 방식

DB2 to RDS/Aurora

AWS 개발 진행 프로세스 (Fixed DMA)

  • 현재는 Oracle/MSSQL 만 공식적으로 지원 → DB2 Migration에 대해서는 Fixed DMA와 사전 협의가 필요

  • Fixed DMA에서 제공하는 S3 에 고객이 SCT Report Output (PDF 포함 csv 파일 전체)와 App 소스 코드 로딩

  • 2-3 일동안 Fixed DMA이 분석하여 Category를 정하고 고객의 동의 하에 계약 프로세스가 시작

  • Price와 일정

    • Cat 1 – USD $60K, 8~9 주

      • 고객의 Account 내에 Sandbox (EC2)를 마련하여, Application 및 DB2 설치 후 샘플 데이터를 넣고

      • Fixed DMA 팀이 로그인하여 App/DB 코드를 Target DB에 맞게 변환

      • 고객이 직접 Functional Test를 수행하여 완료 : Functional Test 범위에 대한 사전 협의가 우선

      • Deliverable : Conversion완료된 코드에 대한 Migration Runbook

    • Cat 2 - $185K

    • Cat 3 - $370K

Case - Internal Guide

  • ProServce : Divaker Goal

Condition

  • Source : DB2 License Community Edition V11.5, 4 core, 16GB RAM, 100GB database

  • Target : RHEL 7.7, m5.xlarge (2 vCPU, 16GB)

Procedure

  1. Root 계정으로 EC2 인스턴스에 DB2 설치

  2. DB2 Instance 생성

    1. OS Users 생성

    2. Port 할당 및 Configuration

  3. Database 생성

  4. Data Migration (다운타임 발생)

    1. Source DB : QUIESCE mode 진입

    2. Extract DDL, foreign key : db2look 명령어 사용

    3. Export Data : db2move 명령어 사용

    4. Copy Data & DDL to EC2 instance

    5. Import Data on EC2 : db2move 명령어 사용

  5. HA 구성
