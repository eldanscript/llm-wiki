Data (File) Info

  • Objects(Files) 개수/크기/유형(사진,영상 등)

    • 4PB의 경우에는 각각의 제작부서에 불출된 후, 사용하는 외장하드 수를 기준으로 집계한 내역, 외장하드에 보관된 구체적인 Objects의 수 미 파악

    • 외장하드의 수는 700개 이상이나, 해당 내역 중 제작에 사용되는 일부 장비를 제외하면 약 600개 내외가 될 것으로 추측

    • 사진, 영상이 모두 산입되어 있을 가능성이 높습니다.

  • On-premise storage(SAN or NAS or DAS) 타입

    • HYBE 본사 내 위치

  • 파일명 구성 현황 (한국어 or 기타 언어 혹은 특수문자 포함여부)

    • 일반적으로 제작부서에서 사용하는 파일명의 경우 특수문자가 포함된 경우가많습니다. 또한 한글도 사용하고 있을 가능성이 매우 높습니다.

    • 파일명의 경우 실제적으로 작업계획에 따라서 현업에 수정을 요청하거나, 추가적인 치환 작업이 필요해 보입니다

Cost Estimation - 50TB

  • AWS DataSync

    • 데이터 전송 비용은 서울리전 기준 GB당 0.0125로서52,428가 예상

    • S3 API Call 비용은 각 항목당 $0.0045(건수)의 비용 발생

      • CompleteMultipartUpload/InitiateMultipartUpload/ListMultipartUploads

  • AWS Snowball

    • 1대당 storage capacity가 80TB (Storage Optimized)

    • 10일 기준(400/최소요금),하루초과될때마다40의 요금이 추가 됩니다.(+Snowball 장비 운송비)

Discussion

50TB Case

  • DataSync로 진행 중

  • 비용 효율 적으로 진행할 수 있는 방안은?

  • Megazone(조용욱)에서 검토 중

  • Storage Gateway 검토 하였음

    • 비용 문제로 잠정 중단

    • On-prem appliance 비용 : 이중화로 인한 Storage Gateway 비용이 크게 산정

  • 기존에도 DataSync나 Snowball 모두 사용 하였음

    • Snowball로 가격이 잇점이 있으나 전체 Process가 오래 걸림

    • 50TB와 같은 규모의 Data BackUp이 반복적으로 발생하는 데 이에 대한 효율적인 solution 검토가 필요

    • Network 구성은 DX (10G bps)이며 DataSync 사용 가능

  • 업무 특성

    • 컨텐츠 제작 일정이 고정적 이지 않기 때문에 Snowball로 대응이 쉽지 않음

    • 분기별로 기본적 데이터 BackUp은 Snowball 사용

      • point 기준 backup

      • 사전 Edge Storage 확보 필요

    • 긴급건에 대해서는 DataSync 사용 : In-time sync

4PB Case

  • 비용 및 소요 시간 확인 필요 : Megazone 통해 비용 전달

  • 외장 하드 700개

  • CMS에서 사용하는 Case는?

    • HP, Dell 등 에서는 3rd party appliance 사용하여 Cloud와 연동 가능

    • 사용중인 HW vendor는 화웨이 외에 다양한 vendor사 적용

    • 전체 Pipeline이 구성된 적용 사례가 궁금

AWS advice

  • Online vs Offline

    • Snowball : Read I/O에 의존 적, 외장 하드 성능

    • DataSync : Network I/O, On-prem과 AWS간 network connection

  • 대다수 엔터사 및 미디어 사에서 Offline 방식 (Snowball) 이용

  • 4 Core Server 3대로 Storage Server 구축 후 외장 하드 연결

  • Hybrid 방식도 고려 가능

    • 대용량 데이터는 Bulk로 Snowball 사용

    • DataSync로 부가적 작업을 진행

  • Best Solution

    • 기술적, 편리함 : DataSync

    • 가격, 일정 허용 : Snowball

  • DataSync

    • Storage I/O 성능이 Network I/O 성능에 meet 해야 best가 나옴

    • File Sync 방식

      • S3 versioning을 활성화 하여 동일 파일 loss 발생 방지

      • File 변경 정보를 취합하여 Incremental copy 수행

    • File Validation

      • Checksum 확인 하여 이상 파일 목록 제공

      • Snowball도 동일

  • Snowball

    • 신청 후 배송에 1주일 소요

  • 4PB 대응

    • Migration plan 수립 하여 진행

    • Data archiving시 meta data 생성 계획도 고려

  • 타사 Case

    • 방송사 : DCM Storage에 대한 Snowball backup 많이 활용

  • CMS 연동

    • CMS 케이스 확인 후 공유 (public case 여부)

    • CMS solution이 Cloud와 연동 필요

      • Cloud vendor 연동성 활용 : 전송된 데이터에 대한 관리, 서비스 연결도 필요

      • HW vendor 연동성 활용 : 데이터 전송 부분으로 한계
