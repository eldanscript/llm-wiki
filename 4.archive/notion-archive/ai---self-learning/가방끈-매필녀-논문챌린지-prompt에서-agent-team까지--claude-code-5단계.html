가방끈 매필녀 논문챌린지 Prompt에서 Agent Team까지- Claude Code 5단계

2026년 6월 06일15 min read

99%는 Claude Code를 잘못 쓰고 있습니다.

같은 Claude Code인데 생산성 50배 차이 나는 이유?

Claude Code의 5단계

Important

1단계: Prompt (2배)

무엇을 하는 단계인가?

Claude에게 일회성 작업을 요청합니다. Claude는 생각하고, 필요한 경우 확인 질문을 하고, 결과를 전달합니다.

왜 중요한가?

대부분의 사람들은 여기서 멈춥니다. 하지만 이 단계만으로도 이미 강력합니다. 잘 만든 프롬프트 하나가 수작업으로 30분 걸리던 조사, 필터링, 비교, 랭킹 작업을 대체할 수 있습니다. 중요한 점은 Claude가 단순히 질문에 답만 하는 것이 아니라, 문제를 잘게 나누고, 후보를 걸러내고, 점수를 매기고, 순위를 정리해준다는 것입니다. 즉, 사용자는 곧바로 의사결정 단계로 넘어갈 수 있습니다.

결과

30분 걸리던 작업이 15분으로 줄어듭니다.

이럴 때 사용하면 좋습니다

  • 한 번만 하면 되는 조사 작업 (도구, 벤더, 프레임워크 비교)

  • 특정 기준으로 여러 옵션을 평가해야 할 때

  • 선택지가 너무 많아 점수화와 순위화가 필요할 때

  • 다음 주에 다시 반복하지 않을 작업

예시

사용자:

“Next.js 앱에 사용할 headless CMS가 필요해. 무료 플랜이 있어야 하고, GraphQL API를 지원해야 하며, TypeScript 지원도 좋아야 해. 상위 5개 옵션을 이 기준으로 점수화해서 순위까지 매겨줘.”

Claude:

2개의 확인 질문을 한 뒤, 장단점과 함께 점수표 및 최종 추천안을 제시함

Important

2단계: Skill (5배)

무엇을 하는 단계인가?

재사용 가능한 워크플로를 SKILL.md 파일로 정의합니다. 그러면 Claude가 /skill-name 형태로 항상 같은 방식으로 실행합니다.

왜 중요한가?

프롬프트는 일회성 작업에는 좋지만, 실제로는 반복하는 작업이 많습니다. 예를 들어 리드 검증, 변경 로그 작성, SEO 점검 같은 일들입니다. Skill은 여러분이 가장 잘 만든 프롬프트를 반복 가능한 실행 매뉴얼로 바꿔줍니다. 한 번만 지침을 적어두면 Claude가 그 과정을 그대로 따라갑니다. 다시 설명할 필요도 없고, 품질이 흔들리지도 않으며, 중간 단계를 빼먹을 일도 줄어듭니다. 월요일 아침이든 금요일 자정이든 같은 품질을 유지할 수 있습니다.

결과

반복 작업은 10분 동안 프롬프트를 다듬는 일에서 2분짜리 실행 작업으로 줄어듭니다.

이럴 때 사용하면 좋습니다

  • 일주일에 두 번 이상 반복하는 작업

  • 일관성이 중요한 프로세스 (아웃리치, 리포팅, 감사, 점검)

  • 원래 SOP로 문서화할 만한 워크플로

  • 지금은 주니어 팀원에게 맡기고 있는 작업

예시 파일

Claude:

전체 플레이북을 실행한 뒤 구조화된 검증 결과를 반환함

Important

3단계: Skill Chain (10배)

무엇을 하는 단계인가?

여러 개의 Skill을 순차적으로 실행합니다. 하나의 출력이 다음 단계의 입력이 됩니다.

왜 중요한가?

실제 업무는 한 단계로 끝나지 않습니다. 예를 들어 리드를 찾고, 정보를 보강하고, 점수를 매기고, CRM에 넣는 식의 파이프라인 구조입니다. 각 단계를 개별적으로 수행하면, Skill을 쓰더라도 결국 사람인 여러분이 중간에서 연결자 역할을 해야 합니다. Skill Chain은 그 병목을 없애줍니다. Claude가 처음부터 끝까지 전체 파이프라인을 이어서 처리하므로, 사용자는 시작만 걸고 완성된 결과를 받으면 됩니다.

결과

원래 1시간 걸리던 다단계 작업이, 수동 인계 없이 몇 분 만에 끝납니다.

이럴 때 사용하면 좋습니다

  • 3단계 이상의 순차 워크플로

  • 툴 간 결과를 복사해서 붙여넣고 있는 작업

  • 조사 → 보강 → CRM 입력처럼 여러 시스템이 연결된 파이프라인

  • 매주 반복하는 배치성 업무 (콘텐츠 재가공, 리포팅 등)

예시

사용자:

“이 웨비나 참석자 리스트에 대해 전체 리드 파이프라인을 실행해줘.”

Claude:

  1. /find-webinar-leads — CSV에서 참석자 47명 추출

  2. /enrich-leads — 회사 규모, 직무, LinkedIn URL 추가

  3. /score-leads — ICP 적합도를 1~10점으로 평가

  4. /push-to-crm — 7점 이상 리드를 HubSpot에 등록

결과

23명의 적격 리드가 전체 맥락 정보와 함께 CRM에 등록됨. 수동 작업은 0.

Important

4단계: Agent (20배)

무엇을 하는 단계인가?

Claude가 대규모 데이터셋에 대해 백그라운드에서 자율적으로 작업합니다. 오류를 처리하고, 실패를 재시도하며, 중단된 지점부터 다시 이어서 실행할 수 있습니다.

왜 중요한가?

Skill과 Skill Chain은 소규모 배치에는 잘 맞습니다. 하지만 3,000개 레코드, 10,000개 행, 몇 시간씩 걸리는 작업은 어떨까요? 여기서 --background 플래그가 결정적인 차이를 만듭니다. Agent를 실행해두면 사용자는 노트북을 닫아도 되고, Claude는 계속 일합니다. 레이트 리밋에 걸리면 기다렸다가 재시도하고, 어떤 레코드가 실패하면 에러를 기록한 뒤 다음 항목으로 넘어갑니다. 사용자는 나중에 돌아와 완성된 결과물과 에러 리포트를 확인하면 됩니다.

결과

원래 며칠 걸리던 대규모 데이터 작업이 밤새 자동으로 처리됩니다.

이럴 때 사용하면 좋습니다

  • 500개 이상 레코드를 처리하는 작업

  • 완료까지 15분 이상 걸리는 작업

  • 오류 처리와 재시도 로직이 필요한 작업

  • 원래라면 VA를 고용해 수작업으로 시킬 업무

예시

사용자는 노트북을 닫고, 운동하러 갔다가, 다시 돌아옵니다.

Claude:

“완료했습니다. 2,847개 회사 정보 보강 완료.

153개는 errors.csv에 기록했습니다.

(사이트 다운 92건, LinkedIn 미발견 41건, 레이트 리밋 20건 — 재시도 예정)

결과는 enriched-companies.csv에 저장했습니다.”

Important

5단계: Agent Team (50배)

무엇을 하는 단계인가?

여러 Agent가 병렬로 실행되며, 각각 서로 다른 역할을 동시에 수행합니다.

왜 중요한가?

단일 Agent도 강력하지만 기본적으로는 순차적입니다. 반면 Agent Team은 병렬입니다. 예를 들어 Agent 1이 리드를 찾고 보강하는 동안, Agent 2는 들어오는 데이터를 점수화하고 맞춤형 아웃리치를 작성할 수 있습니다. Agent 3는 실시간으로 답장을 모니터링하고, Agent 4는 구매 의도가 감지되면 바로 미팅 일정을 잡습니다. 즉, 여러 역할이 동시에 돌아가는 작은 운영팀처럼 작동합니다. 이것은 단순 자동화를 넘어, 규모 있는 위임에 가깝습니다.

결과

원래 4~5명 팀이 필요했던 병렬 운영이, 추가 인력 없이 돌아갑니다.

이럴 때 사용하면 좋습니다

  • 속도가 중요한 운영 작업 (시의성이 중요한 캠페인)

  • 서로 독립적인 병렬 트랙이 있는 워크플로

  • 배치 처리와 실시간 모니터링이 동시에 필요한 프로세스

  • 지금 기준으로는 별도 팀을 꾸려야 할 만한 작업

예시

사용자:

“SaaS-100 리스트를 대상으로 전체 아웃바운드 캠페인을 시작해줘.”

Agent 1 (Researcher): 100개 회사를 병렬로 찾고 정보 보강

Agent 2 (Writer): Agent 1이 넘겨주는 리드를 점수화하고 개인화 아웃리치 작성

Agent 3 (Monitor): 받은 편지함을 모니터링하며 답장을 분류

(관심 있음 / 이의 제기 / 나중에 연락)

Agent 4 (Closer): 긍정 신호가 보이면 자동 응답 후 캘린더 링크 전송 및 콜 예약

네 개의 Agent가 동시에 돌아가며, 사용자는 하루 한 번 정도만 확인하면 됩니다.
