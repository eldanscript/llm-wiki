작성자: 稲田大陸 (이나다 타이리쿠) | 2025년 1월 24일

여러분, 안녕하세요. 이나리쿠입니다.

새해 복 많이 받으세요. 여러분 Kiro 라이프를 어떻게 보내고 계신가요? Kiro CLI 1.24.0에서는 대규모 문서 세트의 단계적 읽기를 가능하게 하는 Skills, 커스텀 Diff 툴, 18개 언어에 대응한 내장 코드 인텔리전스, 리모트 인증, web_fetch 툴의 상세한 권한 관리, 장시간 세션을 원활하게 유지하는 회화 압축의 상세한 컨트롤이 도입되었습니다. 이러한 업데이트가 저의 Kiro 라이프를 더욱 쾌적하게 해주었기 때문에, 이번에는 이러한 추가된 기능을 깊이 파고들어 소개하겠습니다. Kiro가 뭐냐고요? 라는 분은 「Kiroweeeeeeek in Japan 개최 안내」를 읽어주시면 Kiro의 전체상을 파악하실 수 있을 것입니다. 궁금한 업데이트 섹션 및 이행 가이드만 읽어주셔도 문제없습니다. Kiro CLI의 v.1.21.0부터 v.1.23.0까지의 업데이트에 관해서는 「Kiro CLI 신기능 정리 : v1.21.0부터 v1.23.0」을 꼭 읽어주세요.

업데이트 1 : Skills에 의한 단계적 컨텍스트 읽기

Skills는 기동 시에는 메타데이터(이름과 설명)만 읽어들이고, 에이전트가 필요하다고 판단했을 때만 완전한 콘텐츠가 읽어들여집니다. 이를 통해 컨텍스트 윈도우를 효율적으로 관리하면서 광범위한 문서에 대한 액세스를 제공할 수 있습니다.

Skills의 구조

기존의 Steering 파일은 에이전트 기동 시에 모든 콘텐츠를 컨텍스트 윈도우에 읽어들입니다. 이는 소규모 파일에는 적합하지만, 대규모 문서 세트에서는 컨텍스트 윈도우를 압박해버립니다.

Skills는 다음과 같은 접근 방식을 채택하고 있습니다.

  • 기동 시: 이름과 설명만 읽어들임

  • 실행 시: 에이전트가 관련성을 판단하고, 필요에 따라 완전한 콘텐츠를 읽어들임

  • 효율성: 사용되지 않는 문서는 컨텍스트를 소비하지 않음

Skills 파일의 작성

Skills 파일에는 YAML 프론트매터로 기술된 설명적인 메타데이터가 필요합니다. 에이전트가 완전한 콘텐츠를 읽어들이는 타이밍을 확실히 판단할 수 있도록 구체적인 설명을 기술해주세요.

Skills와 Steering의 사용 구분

Skills를 사용하는 경우:

  • 대규모 문서 세트(API 레퍼런스, 아키텍처 가이드 등)

  • 특정 태스크에서만 필요한 전문 지식

  • 컨텍스트 윈도우의 효율적인 관리가 필요한 경우

  • 복수의 토픽으로 나뉜 참조 문서

Steering을 사용하는 경우:

  • 모든 회화에서 항상 필요한 소규모 파일(README, 설정 파일 등)

  • 프로젝트의 기본 정보나 컨텍스트

  • 에이전트의 동작을 항상 제어하고 싶은 코딩 규약이나 스타일 가이드

커스텀 에이전트 설정에서의 Steering/Skills 사용

커스텀 에이전트에서는 Skills/Steering 파일이 자동으로 읽어들여지지 않으며, 커스텀 에이전트 설정 파일의 resources 필드에서 명시적으로 지정할 필요가 있습니다. Glob 패턴을 사용하면 복수의 Skill 파일을 한 번에 포함할 수 있습니다. 에이전트는 각 Skills의 메타데이터를 읽어들이고, 회화의 문맥에 기초하여 관련된 Skill을 자동적으로 읽어들입니다.

다음 예에서는 README.md와 Steering 파일(coding-standards.md, project-rules.md)은 커스텀 에이전트에서 항상 읽어들여지고, Skills로서 api-reference.md, architecture-guide.md, deployment-guide.md가 필요할 때만 읽어들여집니다.

자세한 내용은 Skills 리소스의 문서를 참조해주세요.

업데이트 2 : 커스텀 Diff 툴

Kiro가 파일의 변경을 제안할 때, 기본적으로는 내장 Diff 툴을 사용하여 변경 내용을 표시합니다. 1.24.0에서는 외부 Diff 툴을 설정할 수 있게 되어, 신택스 하이라이트, 사이드바이사이드 표시, 좋아하는 GUI 툴 등 선호하는 Diff 표시 방법을 선택할 수 있습니다.

설정 방법

chat.diffTool 설정에서 선호하는 Diff 툴을 지정합니다.

내장 Diff로는 다음 명령으로 되돌릴 수 있습니다.

터미널 툴

터미널에서 직접 Diff를 표시하는 툴은 워크플로우를 중단시키지 않습니다.

  • delta: Git 유저 향한 신택스 하이라이트와 행 번호 표시

  • difftastic: 포맷의 차이를 무시하는 언어 대응 구조적 Diff

  • icdiff: 빠른 사이드바이사이드 컬러 비교

  • diff-so-fancy: 깔끔하고 인간이 읽기 쉬운 출력

  • colordiff: 심플한 컬러 표시의 Diff

  • bat: Git 통합을 갖춘 신택스 하이라이트

GUI 툴

변경 내용을 별도 윈도우에서 확인할 수 있는 GUI 툴도 지원하고 있습니다:

  • VS Code: code

  • Meld: meld

  • KDiff3: kdiff3

  • FileMerge (macOS): opendiff

  • Vim: vimdiff

  • Neovim: nvim

주의: GUI Diff 툴은 표시 전용 임시 파일을 엽니다. GUI 툴에서 행한 편집은 저장되지 않으며, Kiro가 제안한 변경에는 적용되지 않습니다.

커스텀 인수의 사용

인용부호로 둘러싸면 툴의 동작을 커스터마이즈할 수 있습니다.

자세한 내용은 커스텀 Diff 툴의 문서를 참조해주세요.

업데이트 3 : AST 패턴 툴에 의한 정확한 리팩토링

새로운 pattern-search와 pattern-rewrite 툴에 의해, 에이전트는 텍스트의 정규표현이 아니라 구문목 패턴을 사용하여 코드를 검색 및 변환할 수 있습니다. 이를 통해 문자열 리터럴이나 코멘트 내의 오검출이 없어집니다.

pattern-search의 사용 예

pattern-rewrite의 사용 예

메타변수를 사용하여 패턴을 정의합니다.

  • $VAR: 단일 노드(식별자, 식)에 매치

  • $$$: 제로개 이상의 노드(문, 파라미터)에 매치

이러한 툴은 코드의 구조를 이해하기 때문에, 텍스트 베이스의 검색 치환보다도 정확하고 안전한 리팩토링이 가능합니다.

업데이트 4 : 개선된 코드 인텔리전스

Kiro CLI는 셋업 불요로 18개 언어에 대응한 내장 코드 인텔리전스를 제공합니다. 에이전트는 심볼 검색, 정의로의 네비게이션, 구조적인 코드 검색을 즉시 실행할 수 있습니다.

대응 언어

Bash, C, C++, C#, Elixir, Go, Java, JavaScript, Kotlin, Lua, PHP, Python, Ruby, Rust, Scala, Swift, TSX, TypeScript

내장 기능

  • 심볼 검색: 코드베이스 전체에서 함수, 클래스, 변수를 검색

  • 문서 심볼: 파일 내의 모든 심볼을 리스트 표시

  • 심볼 룩업: 정의로 즉시 점프

  • 패턴 검색: AST 베이스의 구조적 코드 검색

  • 패턴 재작성: AST 패턴을 사용한 자동 코드 변환

  • 코드베이스 맵: 디렉토리 구조의 탐색과 코드 구성의 이해

코드베이스 개요

임의의 워크스페이스의 개요를 빠르게 취득할 수 있습니다.

깔끔한 출력에는 —silent를 사용합니다.

이것은 다음의 경우에 편리합니다:

  • 새로운 코드베이스로의 온보딩

  • 프로젝트 구조에 관한 Q&A 세션

  • 미지의 패키지를 빠르게 이해

LSP 통합(옵션)

참조의 검색, 호버 문서, 리팩토링의 리네임 등의 확장 기능을 사용하려면 LSP 통합을 유효하게 할 수 있습니다. 프로젝트 루트에서 다음 명령을 실행하면 .kiro/settings/lsp.json 설정이 작성되고, 언어 서버가 기동합니다.

사용 예

자세한 내용은 코드 인텔리전스의 문서를 참조해주세요.

업데이트 5 : 회화 압축의 상세한 컨트롤

/compact 명령을 이용하면 회화 이력을 요약하고, 중요한 정보를 보유하면서 컨텍스트 스페이스를 해방할 수 있습니다. 이번 업데이트에서는 보유하는 메시지와 최소 컨텍스트 윈도우의 비율을 지정할 수 있게 되었습니다.

압축의 구조

압축은 오래된 메시지를 요약하면서 최근의 메시지를 보유합니다. 이를 통해 회화의 문맥을 유지하면서 컨텍스트 윈도우를 효율적으로 사용할 수 있습니다.

  • 수동 압축: /compact 명령을 실행

  • 자동 압축: 컨텍스트 윈도우가 오버플로우하면 자동적으로 트리거

설정

보유하는 메시지의 양을 설정할 수 있습니다.

  • compaction.excludeMessages(기본값: 2): 보유하는 최소 메시지 페어 수

  • compaction.excludeContextWindowPercent(기본값: 2): 보유하는 최소 컨텍스트 윈도우의 비율

양쪽 설정이 평가되고, 보다 보수적인(큰) 값이 우선됩니다.

압축 후의 조작

자세한 내용은 회화의 압축 문서를 참조해주세요.

업데이트 6 : web_fetch 툴의 상세한 URL 권한 관리

에이전트 설정을 통해 에이전트가 액세스할 수 있는 URL을 제어할 수 있게 되었습니다. 정규표현 패턴을 사용하여 신뢰할 수 있는 도메인을 자동적으로 허가하거나 특정 사이트를 블록할 수 있습니다.

설정 방법

에이전트 설정 파일의 toolsSettings에서 URL 베이스의 권한을 설정합니다.

패턴의 동작

  • 패턴은 정규표현으로, 자동적으로 ^와 $로 앵커됩니다

  • blocked는 trusted보다도 우선됩니다

  • blocked의 무효한 정규표현은 모든 URL을 거부합니다(페일세이프)

  • trusted의 무효한 정규표현은 스킵됩니다

  • 신뢰된 패턴에 일치하지 않는 URL은 승인을 요구하는 프롬프트가 표시됩니다

사용 예

이 설정에 의해 AWS 문서, 조직의 GitHub 리포지토리, Stack Overflow로의 자동 액세스가 허가되고, 특정 사이트가 블록됩니다.

자세한 내용은 web_fetch 툴의 문서를 참조해주세요.

업데이트 7 : 리모트 인증

리모트 머신(SSH, SSM, 컨테이너 경유)에서 Kiro CLI를 실행할 때, Google 또는 GitHub로 사인인할 수 있게 되었습니다. 포트 포워딩에 의해 인증이 기능합니다.

Builder ID와 IAM Identity Center

Builder ID와 IAM Identity Center의 경우, 디바이스 코드 인증이 그대로 기능합니다. URL과 코드를 로컬 브라우저에 입력하기만 하면 됩니다.

소셜 로그인(Google 또는 GitHub)

소셜 로그인의 경우, CLI는 PKCE 인증을 사용하고, 포트 포워딩이 필요합니다. OAuth 콜백은 localhost로 리다이렉트되기 때문에, 터널 없이는 리모트 CLI에 도달할 수 없습니다.

리모트 머신에서의 사인인 순서

  1. kiro-cli login을 실행하고, 「Use for Free with Google or GitHub」를 선택

  2. 표시된 포트 번호를 메모(매번 다릅니다. 예: 49153)

  3. 로컬 머신의 새로운 터미널에서 포트 포워딩을 설정:

를 스텝 2의 포트로, user@remote-host를 리모트 인증 정보로 치환합니다.

  1. CLI에서 Enter 키를 누르고, 로컬 브라우저에서 URL을 엽니다

  2. 인증을 완료하면 콜백이 터널 경유로 CLI에 도달합니다

SSH 포트 포워딩의 예

정리

Kiro CLI 1.24.0은 개발자의 생산성을 향상시키는 많은 신기능을 제공합니다. Skills에 의한 효율적인 컨텍스트 관리, 커스텀 Diff 툴에 의한 유연한 변경 리뷰, 18개 언어에 대응한 내장 코드 인텔리전스, 회화의 압축에 의한 장시간 세션의 서포트, 상세한 URL 권한 관리, 리모트 인증의 서포트 등, 개발 워크플로우를 강화하는 기능이 만재입니다.

지금 바로 Kiro CLI 1.24.0으로 업그레이드 혹은 인스톨하여 이러한 신기능을 시험해보세요! 여러분의 Kiro 라이프가 보다 쾌적해지기를 바랍니다!

개요

Kiro CLI 1.24.0 버전은 개발자 생산성을 향상시키는 7가지 주요 기능을 제공합니다. 이 문서는 AWS 블로그에 게시된 업데이트 내용을 한글로 정리한 것입니다.

1. Skills - 단계적 컨텍스트 로딩

개념

  • 대규모 문서 세트를 효율적으로 관리하는 새로운 방식

  • 시작 시에는 메타데이터(이름과 설명)만 로드

  • 에이전트가 필요하다고 판단할 때만 전체 콘텐츠를 로드

  • 컨텍스트 윈도우를 효율적으로 관리하면서 광범위한 문서에 접근 가능

Skills 파일 작성 방법

  • YAML 프론트매터로 설명적인 메타데이터 작성 필요

  • 에이전트가 전체 콘텐츠를 로드할 타이밍을 정확히 판단할 수 있도록 구체적인 설명 작성

Steering과 Skills 사용 구분

Skills 사용 권장:

  • 대규모 문서 세트(API 레퍼런스, 아키텍처 가이드 등)

  • 특정 태스크에서만 필요한 전문 지식

Steering 사용 권장:

  • 모든 대화에서 항상 필요한 소규모 파일(README, 설정 파일 등)

  • 코딩 규약이나 스타일 가이드

새로운 도구

  • pattern-search: 구문 트리 패턴을 사용한 코드 검색

  • pattern-rewrite: AST 패턴을 사용한 자동 코드 변환

메타변수

  • $VAR: 단일 노드(식별자, 표현식)에 매치

  • $$$: 0개 이상의 노드(문, 파라미터)에 매치

5. 대화 압축의 세밀한 컨트롤

기능

  • /compact 명령으로 대화 이력을 요약하여 컨텍스트 스페이스 확보

  • 중요한 정보는 유지하면서 오래된 메시지를 요약

압축 방식

  • 수동 압축: /compact 명령 실행

  • 자동 압축: 컨텍스트 윈도우가 오버플로우되면 자동 트리거

설정

  • compaction.excludeMessages (기본값: 2): 유지할 최소 메시지 쌍 수

  • compaction.excludeContextWindowPercent (기본값: 2): 유지할 최소 컨텍스트 윈도우 비율

압축 후 조작

6. web_fetch 도구의 세밀한 URL 권한 관리

기능

  • 에이전트 설정을 통해 에이전트가 접근할 수 있는 URL 제어

  • 정규표현식 패턴으로 신뢰할 수 있는 도메인 자동 허용 또는 특정 사이트 차단

설정 예시

패턴 동작

  • 패턴은 정규표현식이며 자동으로 ^와 $로 앵커됨

  • blocked가 trusted보다 우선순위가 높음

  • 신뢰된 패턴에 일치하지 않는 URL은 승인 프롬프트 표시

7. 리모트 인증

기능

  • 리모트 머신(SSH, SSM, 컨테이너 경유)에서 Kiro CLI 실행 시 Google 또는 GitHub으로 로그인 가능

  • 포트 포워딩을 통해 인증 작동

Builder ID와 IAM Identity Center

  • 디바이스 코드 인증이 그대로 작동

  • URL과 코드를 로컬 브라우저에 입력

소셜 로그인 (Google/GitHub)

  • PKCE 인증 사용, 포트 포워딩 필요

  • OAuth 콜백이 localhost로 리다이렉트되므로 터널 없이는 리모트 CLI에 도달 불가

리모트 머신 로그인 절차

  1. kiro-cli login 실행, “Use for Free with Google or GitHub” 선택

  2. 표시된 포트 번호 메모 (예: 49153)

  3. 로컬 머신의 새 터미널에서 포트 포워딩 설정:

  1. CLI에서 Enter 키를 누르고 로컬 브라우저에서 URL 열기

  2. 인증 완료 시 콜백이 터널 경유로 CLI에 도달
