LLM Wiki Pattern — Karpathy의 지식 자동 합성 아키텍처

Andrej Karpathy가 제시한 LLM이 Raw 소스를 읽어 합성 지식 페이지를 자동 생성·관리하는 아키텍처.
Obsidian Vault + Quartz v5 + GitHub Actions로 실제 구현한 사례.
Raw Sources는 불변, Wiki는 LLM이 자동 관리, 배포는 자동화.
구축 사례: Obsidian-Wiki-Agent

관련: Multi-Agent-System · Obsidian-Wiki-Agent · Agentic-AI

핵심 개념

3-Layer 구조

  • Layer 1 (Raw Sources): 원본 노트들 — LLM은 읽기만 수행, 절대 수정 금지
  • Layer 2 (Wiki): LLM이 생성·관리하는 합성 지식 페이지
  • Layer 3 (배포): 정적 사이트(Quartz) 또는 공개 플랫폼

핵심 원칙

  • Raw Sources 불변성: 0.Slip-box, 1.Projects, 2.Areas, 3.Resources, 4.Archive, 5.Periodic Notes는 읽기 전용
  • Wiki 자동화: 6.Wiki/ 디렉토리는 LLM의 전담 영역
  • 자동 배포: Git push → GitHub Actions → 정적 사이트 자동 생성·배포

Obsidian Vault 구현

디렉토리 구조

6.Wiki/
  WIKI_SCHEMA.md      ← 운영 규칙 및 Raw Source → Wiki 매핑
  index.md            ← 카탈로그 (자동 관리)
  log.md              ← append-only 작업 이력
  Concepts/           ← 추상 개념 (Agentic AI, LLM 등)
  Entities/
    Companies/        ← 기업 (Anthropic, AWS, FuriosaAI 등)
    Models/           ← AI 모델
    Tools/            ← 소프트웨어 도구
  Projects/           ← 프로젝트 요약
  Topics/             ← 주제별 교차 분석 페이지

페이지 형식

모든 Wiki 페이지는 표준 frontmatter 사용:

페이지 구조

  1. 한 줄 정의
  2. 핵심 내용 (3~7개 bullet)
  3. 관련 노트 ([[링크]])
  4. 출처

자동 배포 파이프라인

Vault push (6.Wiki/ 변경)
  ↓
obsidian-vault/trigger-wiki.yml
  (repository_dispatch: wiki-updated)
  ↓
llm-wiki/deploy.yml
  ① Clone obsidian-vault (VAULT_ACCESS_TOKEN)
  ② rsync 6.Wiki/ → content/
  ③ npm ci + quartz build
  ④ Deploy to gh-pages
  ↓
https://eldanscript.github.io/llm-wiki (자동 배포 완료)

GitHub Secrets 필수

  • obsidian-vault repo: WIKI_DEPLOY_TOKEN (llm-wiki dispatch 인증)
  • llm-wiki repo: VAULT_ACCESS_TOKEN (private vault clone 인증)

Multi-Agent 협업

4개 에이전트가 tmux 4-pane에서 병렬 작동:

Agent역할담당 소스
Orchestrator팀 지휘, 스켈레톤 생성1.Projects/
BackendAgentic AI, 지식 관리 개념2.Areas/AgenticAI/, KnowledgeBase/
Frontend기업·기술 블로그 인제스트3.Resources/Tech Report/
ReviewerAWS, AI 칩 랜드스케이프, index 완성2.Areas/AWS/, FuriosaAI/

각 에이전트의 /CLAUDE.md (직무기술서)에 Wiki 인제스트 모드 포함.

운영 Workflow

Ingest (새 소스 추가)

  1. Raw source를 읽음
  2. 새 개념/엔티티 → Wiki 페이지 생성 또는 업데이트
  3. index.md 항목 추가
  4. log.md에 기록: [YYYY-MM-DD] INGEST: <소스> → <생성/수정 페이지들>

Query (질의 응답)

  1. 질문과 관련된 Wiki 페이지 읽음
  2. 답변 생성
  3. 새로운 인사이트는 적절한 Wiki 페이지에 반영
  4. 중요한 Q&A는 Topics/ 페이지로 저장

Lint (품질 점검)

  • 고아 페이지 (index.md에 없는 페이지)
  • 깨진 [[링크]]
  • sources 필드 누락
  • 6개월 이상 미업데이트 페이지
