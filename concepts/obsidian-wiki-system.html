Obsidian Vault + LLM Wiki 시스템

Private 지식 관리 기반 인프라. Agent가 Raw Sources(1-5 폴더)에 기록하면 GitHub Actions가 자동으로 인제스트해 6.Wiki 페이지를 생성·관리한다.

핵심 구성

  • 3-Layer Architecture: Raw Sources(0-5) → Wiki(6) → Public(llm-wiki)
  • GitHub Actions 자동화: trigger-wiki.yml이 0-5 폴더 변경 감지 → wiki_ingest.py 실행 → 6.Wiki 생성·업데이트
  • Claude API 기반 인제스트: Haiku 4.5 모델로 변경된 소스 파일을 분석하여 Wiki 페이지 생성
  • 토큰 예산 관리: MAX_FILE_CHARS=8,000, MAX_EXISTING_WIKI_CHARS=5,000으로 출력 한도(8,192) 초과 방지
  • 자동 배포: Wiki 변경 후 repository_dispatch로 llm-wiki 정적 사이트 갱신

운영 원칙

  • Raw Sources 불변: 0-5 폴더는 Agent가 자유롭게 읽기·쓰기 가능
  • Wiki 자동 생성: 6.Wiki는 GitHub Actions + Claude API가 관리 → 수동 편집 금지
  • 배치 처리: 상위 2단계 폴더(예: 1.Projects/Raingent) 기준 그룹핑, 그룹당 최대 5파일 처리
  • 부분 실패 복구: JSON 출력이 한도 초과 시 역방향 } 탐색으로 부분 파싱 재시도

Agent 작업 규칙

✅ 할 수 있는 것

  • 6.Wiki 직접 읽기 (지식 조회)
  • 1.Projects, 2.Areas, 3.Resources 등에 문서 작성
  • Vault commit & push

❌ 하면 안 되는 것

  • 6.Wiki 직접 편집 (자동화 파이프라인과 충돌)
  • scripts/wiki_ingest.py 수동 실행 (CI에서만 실행)
