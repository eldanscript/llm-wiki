텐서 컨트랙션 프로세서 (TCP)

딥러닝의 핵심 연산인 텐서 컨트랙션을 하드웨어 기본 요소로 사용하여, 메모리 이동을 최소화하고 시간·공간 축 병렬성을 극대화함으로써 높은 성능과 에너지 효율성을 동시에 달성하는 AI 칩 아키텍처.

핵심 내용

  • 텐서 컨트랙션의 중요성: 딥러닝 모델(Transformer, FFN, Attention)의 FLOPS 99%를 차지하는 기본 연산. 행렬 곱셈의 다차원 버전
  • 기존 가속기와의 차별점: GPU는 메모리 명령어를 기본 요소로 사용 vs TCP는 전체 텐서 컨트랙션 연산을 기본 요소로 가속화
  • 하드웨어-소프트웨어 공설계: 아인슈타인 표기법 → 저수준 중간 표기법(ISA) → 명시적 메모리 레이아웃·스케줄링으로 변환
  • 시간·공간 축 가속화: SRAM에서 읽은 데이터를 멀티캐스트하고, 시간 파이프라이닝으로 compute unit을 지속 활용
  • 슬라이스 구조: SRAM + Compute Unit 한 쌍을 “슬라이스”로 정의. VET(Vector Engine), VCH Network, Contraction Engine 포함
  • 컴파일러 최적화: 전술 공간(Tactic Space)에서 AI축의 순열로 최적 스케줄링 선택. End-to-end 모델 레벨 메모리 레이아웃 최적화
  • 동적 형태 지원: 배치 크기, 시퀀스 길이 등 런타임 파라미터 변화에 동적으로 대응. 추론 워크로드 최적화

아키텍처 주요 컴포넌트

슬라이스 내부

  • VET (Vector/Transpose Engine): 다차원 데이터 접근, 간접·이중 간접 접근, 테이블 룩업 지원
  • VCH Network: 회로 스위칭 기반 페치 네트워크. 특정 토폴로지로 구성되어 텐서를 여러 연산 유닛에 멀티캐스트
  • Contraction Engine: Feed Unit → T Product Engine → Register File → Accumulation Unit
  • DPS (Dot Product Slice): 내적 엔진과 누적기 관리. 시간/공간 내적 선택 가능

메모리 계층

  • 온칩 SRAM: 슬라이스별 로컬 메모리. 여러 compute unit에서 데이터 재사용 극대화
  • 메모리 레이아웃 최적화: 행 우선(row-major) vs 열 우선(column-major) 선택에 따라 SRAM 대역폭 영향. 연산자 간 출력-입력 텐서 메모리 일치로 데이터 이동 제거

제어 및 스케줄링

  • Arm 코어: 텐서 유닛 명령 큐에 비동기적으로 명령 푸시 (Load, Execute, DMA, Wait)
  • 텐서 DMA: DRAM → SRAM으로 최적화된 메모리 레이아웃으로 전송
  • 시간 파이프라이닝: 연속적 사이클 동안 입력 데이터 재사용. 명령 큐 유휴 상태 방지

텐서 컨트랙션 처리 과정

  1. 선언적 표현: 아인슈타인 표기법으로 수학적 정의 (명시적 스케줄링·메모리 없음)
  2. 컴파일러 저수준 변환: 저수준 ISA로 변환 → 명시적 메모리 레이아웃·스케줄링 추가
  3. 공간 분산: 행렬 연산을 여러 SRAM·compute unit에 분할
  4. 시간 파이프라이닝: 병렬 축(AI)으로 멀티캐스트, 가장 안쪽 루프 매 사이클 실행
  5. 하드웨어 실행: 슬라이스가 페치 → 멀티캐스트 → 컨트랙션 → 누적

RENEGADE 구현 (FuriosaAI 2세대 칩)

  • 구성: 8개의 P(프로세서), 각 64 TOPS + 2MB SRAM
  • 텐서 유닛: P당 64개 슬라이스
  • 제어: Arm 코어 → 텐서 유닛 비동기 구동 (DMA·연산 병렬화)
  • 데이터 타입: FP8, BF16, MX FP4, MVFP4 소프트웨어 지원
  • 성능: X41.032B 모델 기준 배치 512에서 12,000 토큰/초

장점 및 제한

장점

  • 에너지 효율성: GPU 대비 3배 와트당 처리량 (NVIDIA RTX Pro 6000 동등 성능을 180W vs 600W)
  • 메모리 효율성: 데이터 이동 최소화로 메모리 대역폭 활용 극대화
  • 범용성: 모든 딥러닝 모델 유연 지원 (Transformer, CNN, RNN 등)
  • 추론 최적화: 동적 배치 크기·시퀀스 길이 대응

설계 고려사항

  • 컴파일러 복잡도: 전술 공간 탐색·메모리 레이아웃 최적화 비용 증가
  • 스칼라 처리: 텐서 연산 외 스칼라 처리·제어 흐름은 Arm 코어 담당 (오버헤드)
  • 시퀀스 길이: 동적 형태 처리로 성능 예측 복잡화
